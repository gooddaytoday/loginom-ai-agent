# Измерение связности форка с upstream

Скрипты воспроизводят метрику LAB-198: число путей в unmerged-состоянии после чистого пробного слияния
upstream (OpenCode) в форк. Они ничего не меняют в рабочей ветке и ничего не публикуют: слияние идёт в
отдельной временной рабочей копии (`git worktree`), которая удаляется после измерения.

| Файл | Назначение |
|---|---|
| `measure-conflicts.sh` | Базовое измерение: пробное слияние, список путей, типы конфликтов, сводка. |
| `counterfactual-names.py` | Строит синтетический дочерний коммит форка с возвращёнными именами upstream (для прогноза). |
| `forecast-conflicts.sh` | Для набора комбинаций классов переименований строит контрфактический коммит и измеряет на нём то же слияние. |
| `reference/` | Эталонный вывод для исходной точки (форк `2e6f66a9`, upstream `v1.19.4` = `148842ef`). |

## Быстрый запуск

```bash
# базовое измерение в чистом клоне; сверка со списком из reference/
scripts/upstream-sync/measure-conflicts.sh --out /tmp/sync-out \
  --compare scripts/upstream-sync/reference/baseline-unmerged-paths.txt

# прогноз по классам переименований (нужен клон, где есть оба коммита; его создаёт предыдущая команда)
scripts/upstream-sync/forecast-conflicts.sh --repo /tmp/sync-out/clone --out /tmp/sync-forecast
```

Нужны `git` ≥ 2.43, `bash`, `awk`, `sort`, `sha256sum`; для прогноза — `python3` (стандартная библиотека).
Другая исходная точка задаётся переменными `FORK_SHA`, `UPSTREAM_SHA`, `UPSTREAM_TAG`, `FORK_URL`, `UPSTREAM_URL`
(всегда полные SHA, а не имена веток и тегов).

## Что зафиксировано и почему

- Метрика — `git diff --name-only --diff-filter=U` после `git merge --no-commit --no-ff -s ort <UPSTREAM_SHA>`.
- Изоляция: `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, фиксированная личность, `rerere` выключен — сохранённые
  решения конфликтов не занижают число.
- `merge.directoryRenames=conflict`: значения `true`/`false` скрывают 6 конфликтов «file location» (число становится 63).
  Это артефакт переименования каталога, а не повод менять настройку: её фиксирует скрипт.
- В git 2.43.0 стратегия `ort` игнорирует `-X no-renames` и `merge.renames=false` (проверено на синтетическом репозитории,
  стратегия `recursive` их учитывает), поэтому метрика на них не опирается; версию git скрипт печатает.
- Недействительное измерение — отказ, а не «0 конфликтов»: код возврата `merge` не 0/1, нет `MERGE_HEAD`, предупреждение о лимите
  переименований, атрибут `merge=` в `.gitattributes` форка.
- Строк `CONFLICT` больше, чем путей, на число путей rename/delete: каждый такой путь даёт две строки.

## Ограничения прогноза

`forecast-conflicts.sh` — нижняя оценка для одной дельты upstream: контрфактический коммит возвращает имена, но не переносит
содержательные правки и не проверяет, что продукт собирается. Возврат внешних имён (переменные окружения, файлы настройки
пользователя) требует адаптера идентичности; комбинации, где он нужен, помечены в таблице.
