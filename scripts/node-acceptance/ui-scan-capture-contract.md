# Internal controls/time collector and capture contract

This is an offline diagnostic instrument, not a latency fix or public runtime capability. It does not create a browser, authenticate, acquire/release a host or authorize a mutation. Production `workspace-ui.mjs` and its admission/output contracts remain unchanged.

## Exact observer and measurements

`collectUiScan(page, options, executeSerialized, {expectedObserverSha256})` delegates the exact `makeWorkspaceUiCode(options)` to the caller's executor. The executor must execute that source once on that Page; it must not substitute an observer or replay an uncertain mutation. Pin the reviewed observer function SHA256 explicitly: `e0e045f97840e18e68a22154a3035007be2915497c7fc68bb1bade572fcc3238` for the receiving LAB-69 observer retained from `d04a64c7972d973dbd73e7d389396e3b275e1192` (source collector pin `6dceec2e2eb910d5e3e2b3d521c325883cbcce4e56152213ac0127d166e70eae` is a different observer and is not accepted here). Do not discover and automatically accept a changed hash at capture time. The harness verifies exact callback identity and unique instrumentation anchors before executing it. Changed code requires review and a new pin.

The Page facade wraps only the native observer callback. It preserves filter order, in-place sort, the 240 selection cap, arguments/receivers/returns of geometry/style/hit-test calls, original Date reads, work charges, and effective budgets. It adds temporary local aggregate measurements with `performance.now`; those calls do add observer overhead. Instrumented wall times are therefore diagnostic measurements, not an uninstrumented latency claim. The controlled artificial Date-overrun test must be reported separately from measured performance time.

Each retained scan has collect, metadata, output/import definitions, filter, sort, controls setup, render and data-view segments when reached; unreachable segments are absent. Each segment has measured milliseconds and native work/visited entry/exit counters. Geometry/style/hit-test aggregates contain only call counts and measured milliseconds. Candidate/filtered counts are null if the corresponding boundary was never reached. Returned count is the actual issued UI count, zero on failed scans, not partial rendering progress. The final numeric scan counters/effective limits and root/document epoch are retained. Original failure trace supplies Date-based elapsed and its failure stage. At most eight scans are retained; additional scans still execute normally and are counted as omitted. No scalar input values, text/credentials, full HTML, partial UI, action refs from incomplete scans or DOM objects are persisted in the report. Normal native receipts remain internal to the executor.

## Minimal future Amount capture

A future separately authorized capture must bind one fresh equivalent Amount/index=1/type state, not repeat `import-null-empty-001` or infer its historical cleanup. Its manifest must include exact code/build/serialized/collector SHA256, operation and receipt IDs, native document/workflow/node IDs, wizard and selected-root identity, account/connection/package binding, phase, monotonic clock origin, CPU/runtime/browser versions and concurrent load description. Account binding may be hashed; credentials must never be included.

Capture the selected root and required fixed guards only, preserving traversal order, parent indices, subtree size distribution and omission boundaries. Bound the inventory to the observer's existing limits; truncation must be explicit and cannot count as a complete fixture. Required structural fields: tags, exact allowlisted TIDs, classes affecting visibility/identity/layout, parent paths, rectangles, viewport/scroll dimensions, visibility/transform/overflow flags and native record binding IDs/indexes. Allowlist Amount's technical name/index/type/kind and its editor/control owner; omit input values, unrelated text, CSV data and credentials. No full-page HTML or screenshots containing arbitrary input values.

Native layout must bind the real definition grid/view/store/controller to the same document/workflow/node/root; record cached local row/record IDs/indexes, store completeness/loading/filter flags, selected field and actual editor/root, row-parent relationships and geometry. Never load ranges, invoke getters that retrieve backend/data values or inspect unrelated stores. The fixture must distinguish failed-root discovery, pregesture revalidation and postgesture observation, with candidate/filtered/returned counts, stages, budgets and work/visited/timing from each scan. Preserve AMBIGUOUS, parent pending, original journal, effects and deadlines; no automatic retry.

## Controlled owner/Page caller gate

Before live capture, separately prove that the caller retains the actual authenticated owned Page through the exact Amount editor route: account, connection, personal package/path, document/workflow/node/root and native grid/editor identity. A bounded LAB-68 owner/Page PASS or Calculator admission is insufficient by itself. Show actual product-host/private owner binding, receipt provenance, lease ownership, cancellation/deadline/unsettled behavior and no second Page/browser substitution. Prove pregesture foreign owner/document/root/field rejection and postgesture unknown-effect retention without replay on that composition SHA. A new SHA needs its own clean build and corresponding affected-path checks.

Fresh resource evidence and explicit authorization are required for the new equivalent diagnostic operation. Keep the original live Page while confirming save/dirty/running/unsettled guards and exact owned package cleanup; then release transport/lease through the checked shutdown route. PID/socket disappearance is not resource handoff or logout proof. Never touch foreign or unknown resources, discard changes, overwrite the historical package, or blindly repeat its mutation. If cleanup is rejected, preserve owner/Page and report the exact bound receipt/limit. This contract grants no live authorization; the current assignment ends at offline tool review.
