# Original admitted execution: producer component

This is the SOURCE67 claim/birth component. Private RunCommand delivery remains
UNAVAILABLE, SDK/native authority false. No receipt or environment label is a
borrowable caller scope. Existing CLI/PromptInput/tools remain unchanged.

The hash-pinned private requirements must explicitly contain
`business_execution_seconds`, an integer from 1 through the unchanged ceiling
7200. This is a reviewed business lifetime accepted by the original launch
decision, not evidence.checked_at, binding expiry, or a downstream timeout.
Missing lifetime refuses new production; historical receipts are neither migrated
nor invalidated. Required fixes, model, case wording and freshness remain intact.

`admission_decision` exclusively creates the original mode0600 receipt, validates
all business inputs, takes the existing profile lock and validates again. Before
spawn, it retains the exact manifest bytes/argv and commits execution_origin under
that same open inode, file fsync plus directory fsync. The original decision
captures one wall-clock birth and one monotonic bound. The absolute deadline is
birth plus the admitted lifetime, minted here once, never after a queue/await.
Both clocks bound producer dispatch; clock rollback cannot extend the original
monotonic budget. Validation consumes that budget. Replacement, copies, additional
hardlinks, changed bytes/inputs and disposed decisions refuse; same claim retries
cannot create a second origin. `consume_birth` is once-only. Failure after the
launching commit preserves the original claim/UNKNOWN boundary and raw exception.
No second spawn, receipt repair or native operation is attempted.

The durable record pins producer SHA256, original claim path/device/inode/uid/pid,
manifest bytes and exact issue/case/task/inputs/candidate/requirements/evidence/
profile/config/cwd/model binding, lifetime/birth/deadline. UID/PID and these bytes
are provenance, not Multica identity, raw caller signal or authority. External
immutable source/catalog validation is mandatory before any compatible reader.
A local privileged process can edit files; this is not a sandbox or authentication
protocol. Python Error/falsy rejection channels differ from SDK boxed rejections:
this component preserves Python exceptions; it does not manufacture SDK reasons.

## Exact unsupported seam and receiving contract

Production birth is `admit.launch -> admission_decision -> consume_birth ->
subprocess.run(argv,cwd,env,stdin=DEVNULL)`. No pass_fds/private reader/typed origin
handoff currently exists. This cut deliberately adds no serialized origin to argv,
model attachments/environment or public CLI. Child RunCommand currently cannot
consume this claim as genuine admitted execution scope.

Creator68 owns run.ts command/prompt sender, private prompt/context and SDK
ToolExecutionOptions.experimental_context. Its existing SOURCE e423 and task
01a13797-9b18 identify the missing birth reader. Registry must sequence a reviewed,
fixed private producer-to-RunCommand birth channel and compatible source pins.
The reader must bind the live original producer claim/launch, same child and exact
validated binding, retain the producer absolute deadline without remint, reject
missing/legacy/copied/foreign/late/expired/UNKNOWN state and consume once before
RunCommand awaits. JSON/FD number/PID/env label alone does not satisfy that binding.
No proposed delivery transport is asserted supported by this component.

Creator68 separately captures genuine RunCommand request/purpose/raw signal and
later SDK creation/options/toolCallId/raw signal references before their first
await, in the original process/realm. Serialized receipt provenance cannot recreate
those refs, and RunCommand signal is not a replacement SDK signal. Original
terminal, Import and Union purposes require their own qualified creation; startup
or readiness does not supply them. A compatible reviewed publisher/reader is
required before carrier67 and terminal70/Import71 receiving; no waiting run or
second SDK author is created here.
