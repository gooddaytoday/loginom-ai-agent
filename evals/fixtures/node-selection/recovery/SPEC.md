# Исправление синтаксического отказа Калькулятора

Targeted сценарий выполняется один раз на итоговом candidate, в первой волне.
Модель получает только prompt и `data/dataset.csv`. SPEC, checklist и oracle
не входят в модельные inputs. Diagnostic mode нужен только для отсутствующего
reference: использовать обычный трёхаргументный `buildAgentPrompt` с сохранением
пакета и CSV, а не диагностический хвост.

## Последовательность и доказательства

1. Штатный импорт → Калькулятор Profit=Revenue с успешным выполнением.
2. Одна проверка `Revenue -` в существующем выражении Profit без изменения связей.
3. Нужны одновременно верхний `NODE_APPLY_STOPPED` с вложенным
   `error.cause.code:"WIZARD_CALCULATOR_VALIDATION_FAILED"` и собственное событие
   `node_phase_refused` с
   `receipt.verification:"calculator_syntax_rejected_draft_restored"`.
   Проверяющий сверяет operation_id и node identity обеих квитанций. Самого
   сообщения модели, ошибки транспорта или произвольного FAILED недостаточно.
4. Тот же GUID Калькулятора исправлен на Revenue минус Cost, связи сохранены;
   далее штатные GroupData по Category с суммой Profit, Sorting суммы по убыванию
   и текстовый Export только Category,Profit.

Отсутствие ошибки — `recovery_unobserved`, даже при правильном CSV. Это блокер
targeted diagnostic coverage, не PASS и не повод корректировать skill. Prompt
подсказывает исправление: здесь не доказывается самостоятельная диагностика.
Честный blocker после реального отказа подтверждает только политику при полной
истории без JS, но не успешный расчёт и не чистый проход первой волны.
Естественные ошибки остальных попыток учитываются отдельно и не подменяют
ненаблюдённый targeted отказ.

Во всей истории, включая failed/pending/running, не допускаются JS apply; пакет
также не содержит JS. Проверить полноту evidence, исходные inputs, те же узлы,
подтверждённые cleanup/settlement и сохранение. Не заменять неопределённую
операцию новой и не трактовать ошибку поддержанного узла как capability gap.

## Независимый результат

`python3 oracle.py data/dataset.csv` считает Decimal(Revenue)-Decimal(Cost)
по категориям и сортирует по сумме по убыванию. Oracle до модельного запуска:

```csv
Category,Profit
B,62
A,55
```

Проверяются ровно две строки и две колонки, порядок строк и все значения с
допуском 0.01. Отдельно сохранить `policyStatus`, `calculationPassed` и факт
наблюдённого диагностического отказа; CSV-pass не заменяет два последних
доказательства исполнения и восстановления.
