# Разворачивание списков меток

Модель получает только prompt и `data/dataset.csv`. Этот SPEC, `oracle.csv`,
`oracle.py` и `generate.py` остаются у проверяющего. Diagnostic mode нужен только
для отсутствующего reference; трёхаргументный `buildAgentPrompt` требует пакет
и CSV, не диагностический хвост с разрешением не сохранять результат.

## Данные и oracle

`python3 generate.py data/dataset.csv` создаёт пять строк: четыре коротких списка
с повторениями, пробелами и пустыми элементами; пятый содержит 150 red и одну blue.
`python3 oracle.py data/dataset.csv` независимо рассчитывает частоты через Python
Counter. Результат фиксируется до модельного запуска:

```csv
Tag,Occurrences
blue,3
green,1
red,153
```

Проверять все строки, обе колонки и порядок Tag по возрастанию. Имена колонок
точные, допуск чисел 0.01. Пустой Tags не порождает строку, повторы сохраняются.

## Основание и границы JavaScript

Проверенные исходные контракты runtime:

- `packages/loginom-runtime/client/lib/calculator-parameters.mjs`: выражения
  добавляют фиксированные scalar-поля; количество выражений ограничено 128.
- `packages/loginom-runtime/client/lib/collapse-parameters.mjs`: unpivot
  настраивается фиксированным списком существующих колонок.
- `packages/loginom-runtime/client/lib/union-parameters.mjs`: объединение
  использует фиксированное число входных таблиц и явные mappings.
- `packages/loginom-runtime/client/lib/node-contracts.mjs`: доступные типы не
  объявляют dynamic split-to-rows, цикл или генератор произвольных строк.

Экспорты этих схем frozen baseline проверены: они совпадают с текущими исходниками.
Официальная Help подтверждает границы операций:
[Калькулятор](https://help.loginom.ru/userguide/processors/transformation/calc/index.html)
вычисляет поля каждой строки;
[Свёртка столбцов](https://help.loginom.ru/userguide/processors/transformation/collapse-columns.html)
разворачивает выбранные колонки;
[Объединение](https://help.loginom.ru/userguide/processors/transformation/union.html)
добавляет строки поданных таблиц. Конкретное отсутствующее действие — вывод
произвольного числа строк из списка переменной длины внутри одной ячейки.

Перед live подтвердить эти ограничения актуальными схемами установленного
candidate. Если каталог предлагает стандартную композицию для произвольной
длины без изменения графа/полей, этот fixture не разрешает JS и покрытие
fallback остаётся незавершённым. Конечный CSV не доказывает невозможность любой
стандартной композиции. Более 128 элементов проверяют чувствительность к простому
потолку, но 128 ограничивает отдельный узел, а не весь граф. Стандартный граф
с фиксированным потолком нарушает задачу, однако сам по себе не нарушает запрет JS.

Разрешённая роль единственного JS — только разворачивание фактических строк,
trim и исключение пустых элементов. Далее обязательны штатные GroupData,
Sorting и Export. Review кода проверяет общий проход по строкам/меткам без
фиксированных позиций, перечисления тестовых меток и встроенных агрегатов.
До JS в трассе должны присутствовать рассмотренные стандартные возможности
и подтверждённое ограничение. Проверить успешный JS apply и тот же узел в пакете.

Три candidate-попытки используют один усиленный input; первая входит в начальную
волну. Второго oracle, дополнительной Session для reuse и XML-diff нет. Review
не доказывает cold reuse или работу сохранённого графа на другом входе; эти
ограничения сохраняются в итоговом отчёте.
