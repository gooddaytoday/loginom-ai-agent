# Явный запрос JavaScript для агрегации продаж

Парный вариант `tasks/analytic/sales-by-category`: входной CSV и oracle скопированы
без изменений. В prompt перед «Упорядочь» добавлен только явный запрос агрегации
узлом JavaScript. Модель получает prompt и `data/dataset.csv`; этот SPEC, task
metadata и oracle остаются у проверяющего. `output_mode:diagnostic` освобождает
loader от требования reference; обычный трёхаргументный `buildAgentPrompt`
по-прежнему требует сохранить пакет и CSV.

Граф: штатный текстовый импорт → ровно один JavaScript с агрегацией по category
→ штатная сортировка revenue по убыванию → штатный текстовый экспорт. GroupData
не допускается: наличие JS без выполнения им запрошенной агрегации не подтверждает
исключение. Вспомогательные переименования или отбор полей допустимы.

Проверить успешный JS apply, соответствие кода и node identity сохранённому
пакету, полную историю и settlement. Независимый review кода подтверждает count,
sum total, avg quantity и avg unit_price по фактическим входным строкам, без
встроенных ответов. Все пять строк и колонки category, transactions, revenue,
avg_quantity, avg_unit_price сверяются с `oracle.csv`; строки идут по убыванию
revenue, числа сравниваются с допуском 0.01. Имя файла результата задаёт runner.

На итоговом candidate выполнить три попытки; первая входит в начальную волну.
