# Погодный риск по городам

Источник: `analitic-tasks/task58-openweather`. Единственный фиксированный вход — `data/dataset.csv`, все 300 наблюдений. Не используются timestamp, season и feels_like; исходные метки погоды не исправляются.

## Фактический сохранённый граф

В `reference.lgp` восемь стандартных узлов, соединённых семью связями одного линейного пути:

1. Импорт CSV с заголовком, UTF-8, запятой и десятичной точкой.
2. Калькулятор создаёт целый `adverse_flag` выражением `IF(RegExMatch("(?-i)^(Rain|Snow|Mist)$", weather_main) AND (Count(weather_main)=4),1,0)`. Оно задаёт точное множество Rain/Snow/Mist с учётом регистра и дополнительной проверкой длины четыре; остальные наблюдения получают ноль.
3. Группировка по `city`: Count(adverse_flag) → `observations`, Sum(adverse_flag) → `adverse_count`, обычные средние `temperature`, `wind_speed`, `cloudiness`. Флаг определён для каждой строки, поэтому Count равен числу всех наблюдений города.
4. Калькулятор считает сырой `adverse_weather_pct=100.0*adverse_count/observations`.
5. Сортировка до округления: `adverse_weather_pct` по убыванию, `mean_wind_speed` по убыванию, `city` по возрастанию; LocaleAware=false.
6. Калькулятор явно округляет четыре вещественных результата через `Round(показатель,6)`, заменяя поля без потери знака. До этого шага округления нет.
7. Параметры полей исключают служебный `adverse_count`, оставляя шесть итоговых колонок.
8. Единственный экспорт UTF-8 CSV с заголовками по именам, запятой и десятичной точкой: `/user/analytic-evals-city-weather-risk-1.result.csv`.

JavaScript, дополнительные ветки и вручную заданные итоговые строки отсутствуют. Пакет создан CLI 0.2.2 на `openai/gpt-6.1-sol/xhigh`, primary-попытка 1 без подсказки. Один таймаут выходного сопоставления финального узла штатно разрешён через inspect → release after proof → повторную полную настройку существующего узла. Аналитика не менялась и не упрощалась.

## Результат и проверка

Ровно 15 строк, колонки `city,observations,mean_temperature,mean_wind_speed,mean_cloudiness,adverse_weather_pct`. Счётчик целый; вещественные результаты округлены до шести знаков. Полный ожидаемый CSV — `oracle.csv`, абсолютный допуск `1e-6`. Oracle на стандартной библиотеке Python подтверждён независимым слепым SQL-расчётом.

Проверены SHA256 входа, фактические формулы и связность графа, сортировка до явного округления, единственный экспорт и полный CSV после CLI. После завершения CLI сохранённый пакет отдельно открыт в браузере, выполнен целиком и закрыт без сохранения; новый CSV снова совпал со всеми строками и колонками oracle. Пути доказательств, включая проверку погодного флага, и модельные параметры находятся в `provenance.json`.
