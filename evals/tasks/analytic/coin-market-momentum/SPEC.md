# Рыночные наблюдения и изменения по монетам

Источник: `analitic-tasks/task60-coingecko`. Фиксированный вход — `data/dataset.csv`, все 200 строк. Исходные 24h_change и 7d_change уже заданы в процентах, сохраняют знак и повторно на 100 не умножаются. High/low, ATH и даты не участвуют.

## Фактический сохранённый граф

В `reference.lgp` семь стандартных узлов, соединённых шестью связями одного линейного пути:

1. Импорт CSV с заголовком, UTF-8, запятой и десятичной точкой. Технические имена двух полей — `change_24h`, `change_7d`, с исходными отображаемыми именами `24h_change`, `7d_change`. Значения и исходный файл не изменены.
2. Калькулятор: целый `row_marker=1` и `positive_24h_flag=IFF(change_24h>0,1,0)`. Ноль не считается положительным.
3. Группировка по `coin`: Count(row_marker) → `observations`, обычные средние `current_price_usd`, `market_cap`, `volume_24h`, `change_24h`, `change_7d`; Sum(positive_24h_flag) → `positive_24h_count`. Маркер определён для каждой строки, Count равен числу всех наблюдений.
4. Сортировка по сырому `mean_change_7d_pct` по убыванию, затем `coin` по возрастанию; LocaleAware=false.
5. Калькулятор «Итоговые показатели» после сортировки формирует шесть десятичных знаков пяти средних и `positive_24h_pct=100*positive_24h_count/observations`. Для средних знак возвращается условием `IF(x<0,"-","")`; целая часть берётся через `Int(Abs(x))`, округляется только дробная часть `Round(Frac(Abs(x))*1000000)`. Перенос округлённой дробной части 1000000 в целую учтён через `IFF`, дробь выводится через `StrZero` и `Right(...,6)`. Весь большой показатель на миллион не умножается. Аналитические средние и знак исходных изменений не искажаются. В том же узле сохранён служебный `Expr1=positive_24h_count`.
6. Параметры полей исключают `Expr1` и `positive_24h_count`, оставляя только восемь итоговых колонок. `observations` остаётся целым.
7. Единственный экспорт UTF-8 CSV с заголовками по именам, запятой и десятичной точкой: `/user/analytic-evals-coin-market-momentum-2.result.csv`.

JavaScript, дополнительные ветки и вручную подставленные итоговые строки отсутствуют. Пакет создан CLI 0.2.2 на `openai/gpt-6.1-sol/xhigh`, primary-попытка 2 без подсказки. Первая попытка завершилась кодом 0, но сохранила только частичный сценарий без экспорта после технических отказов финального мастера; она не принята, квитанции и штатное закрытие сохранены. Вторая попытка штатно освобождала остановленные операции и довела финальный узел и выгрузку до успешного выполнения. Аналитика не менялась и не упрощалась; подготовленные гипотезы технической подсказки модели не передавались.

## Результат и проверка

Ровно десять строк, колонки `coin,observations,mean_price_usd,mean_market_cap,mean_volume_24h,mean_change_24h_pct,mean_change_7d_pct,positive_24h_pct`. Полный ожидаемый CSV — `oracle.csv`, абсолютный допуск `1e-6`. Oracle на стандартной библиотеке Python подтверждён независимым слепым SQL-расчётом.

Проверены SHA256 входа, фактические средние и строгий порог положительного изменения, сортировка до округления, связность графа, единственный экспорт и полный CSV после CLI. Сохранённый пакет отдельно открыт в браузере после завершения CLI, выполнен целиком и закрыт без сохранения; новый CSV прошёл повторное сравнение всех строк и колонок. Для крупных значений оба CSV дополнительно прошли строгую Decimal-сверку с абсолютным допуском 1e-6 без расширения по масштабу; пять средних совпали с точным десятичным расчётом. Пути доказательств и история попыток — в `provenance.json`.
