# Доля убыточных кампаний по типу и региону

Источник: `analitic-tasks/task54-yandex-direct`. Фиксированный вход — `data/dataset.csv`, все 250 исходных строк. Используется предоставленный `roi`; он не пересчитывается из других полей и его среднее повторно не умножается на 100. Строка с roi=0 не считается убыточной.

## Фактический сохранённый граф

В `reference.lgp` семь стандартных узлов и шесть связей одного линейного пути, без дополнительных веток:

1. Импорт CSV с заголовком, UTF-8, запятой и десятичной точкой.
2. Калькулятор: `negative_roi_flag=IF(roi<0,1,0)` и `campaign_row=1`.
3. Группировка по `campaign_type` и `region`: сумма `campaign_row` → `campaigns`, сумма флага → `negative_roi_count`, суммы `cost` → `total_cost` и `conversions` → `total_conversions`, простое среднее исходного `roi` → `mean_roi`.
4. Калькулятор приводит три счётчика к целому через `Int`, считает сырые `negative_roi_pct=100.0*negative_roi_count/campaigns` и `cpa=total_cost/total_conversions`. Выходное сопоставление оставляет девять заданных колонок.
5. Сортировка сырых чисел: `negative_roi_pct` по убыванию, `total_cost` по убыванию, затем `campaign_type` и `region` по возрастанию; LocaleAware=false.
6. Калькулятор после сортировки заменяет четыре вещественных показателя строковым CSV-представлением: `Round(x*1000000,0)`, затем целая часть и шестизначная дробная часть через `Int`, `Abs`, `Mod`, `Str`, `StrZero`, `Concat`. Знак отдельно возвращается условием `IF(x<0,"-","")`; `Abs` используется только при форматировании модуля, отрицательный ROI в аналитике не обрезается. Счётчики остаются целыми.
7. Единственный экспорт UTF-8 CSV с заголовками по именам, запятой и десятичной точкой: `/user/analytic-evals-campaign-region-loss-share-1.result.csv`.

JavaScript и вручную введённые итоговые строки отсутствуют. Пакет построен CLI 0.2.2 на `openai/gpt-6.1-sol/xhigh`, primary-попытка 1 без подсказки. Один запрос создания узла был отклонён из-за неподдерживаемого имени до изменений; агент исправил имя и продолжил ту же попытку. Аналитика не менялась и не упрощалась.

## Результат и проверка

Ровно 16 строк, колонки: `campaign_type,region,campaigns,negative_roi_count,negative_roi_pct,total_cost,total_conversions,cpa,mean_roi`. Полный ожидаемый CSV — `oracle.csv`; абсолютный допуск `1e-6`. Oracle на стандартной библиотеке Python подтверждён отдельным слепым SQL-расчётом.

Проверены побайтовый SHA256 исходного CSV, связность и фактические формулы пакета, порядок сортировки перед округлением, единственный экспорт и весь CSV после CLI. После завершения CLI сохранённый пакет отдельно открыт в браузере, выполнен целиком и закрыт без сохранения; новый CSV снова прошёл сравнение всех строк и колонок. Пути доказательств и модельные параметры находятся в `provenance.json`.
