# Обработка услуг по исходному цифровому признаку

Источник: `analitic-tasks/task53-gosuslugi`. Единственный фиксированный вход — `data/dataset.csv`, все 100 исходных строк. `is_digital` используется как предоставлен, независимо от `submission_method`; противоречия не исправляются.

## Фактический сохранённый граф

В `reference.lgp` восемь стандартных узлов, соединённых одним линейным путём без дополнительных веток:

1. Импорт CSV с заголовком, UTF-8, запятой и десятичной точкой; `is_digital` читается как целое число.
2. Калькулятор добавляет `row_unit=1` и `approved_flag=IF(status="Approved",1,0)`.
3. Группировка по `service` и исходному `is_digital`: сумма `row_unit` → `applications`, средние `processing_days` и `satisfaction`, сумма флага → `approved_count`. Все строки участвуют в средних и знаменателе.
4. Калькулятор приводит `applications` к целому через `Int(applications)` и вычисляет неокруглённый `approved_pct=100.0*approved_count/applications`.
5. Сортировка: `service` по возрастанию, затем числовой `is_digital` по возрастанию; LocaleAware=false.
6. После сортировки калькулятор округляет три результата через `Round(x*1000000)` и формирует строковое представление с точкой и ровно шестью десятичными знаками через `Str`, `Int`, `Mod`, `StrZero`, `Concat`. На фиксированном входе средние и процент неотрицательны. Округление не участвует в аналитических расчётах.
7. Параметры полей исключают `approved_count` и оставляют шесть заданных колонок в требуемом порядке.
8. Единственный экспорт CSV: UTF-8, заголовки по именам, запятая и десятичная точка. Выход `/user/analytic-evals-service-digital-processing-1.result.csv`.

JavaScript и вручную введённые итоговые строки отсутствуют. Пакет создан CLI 0.2.2 на `openai/gpt-6.1-sol/xhigh`, primary-попытка 1 без подсказки. Внутри попытки один технический таймаут выходного сопоставления штатно разрешён через inspect → release after proof → полная повторная настройка существующего узла; аналитика не менялась и не упрощалась.

## Результат и проверка

Ровно 12 строк, колонки: `service,is_digital,applications,mean_processing_days,mean_satisfaction,approved_pct`. `applications` и `is_digital` выгружаются целыми, прочие числовые значения — с шестью знаками. Полный ожидаемый результат — `oracle.csv`, абсолютный допуск `1e-6`; oracle реализован на стандартной библиотеке Python и подтверждён независимым слепым SQL-расчётом.

Проверены SHA256 входа, связность и реальные формулы графа, полный CSV после CLI. После завершения CLI пакет заново открыт в браузере, выполнен целиком, закрыт без сохранения; новый CSV повторно прошёл сравнение всех строк и колонок. Детальные пути доказательств и модельные параметры находятся в `provenance.json`.
