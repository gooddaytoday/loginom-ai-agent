# Проверка выбросов по генеральным z-оценкам

Источник: analitic-tasks/task12-anomaly-detection, 500 строк data/dataset.csv. Исходный CSV сохранён побайтово. Для трёх метрик используются общие mean и генеральные std по всем строкам. is_anomaly служит только истинной меткой для сравнения с предсказанием.

## Фактический граф

Описание проверено по Unit_0/Unit.xml принятого пакета. Используются 13 стандартных узлов, JavaScript отсутствует. Ветка общих статистик соединяется с веткой всех исходных строк.

1. «dataset.csv — все исходные строки» — импорт UTF-8, запятая и десятичная точка. Загруженная копия совпадает с источником по SHA256.
2. «Квадраты метрик и общий ключ» — Калькулятор: all_rows=1, sq_k=metric_k*metric_k для k=1,2,3. Отсюда исходные строки идут и в группировку, и напрямую в соединение.
3. «Все строки: n, суммы и суммы квадратов» — Группировка по all_rows: COUNT(record_id) → n и суммы metric_k/sq_k → sum_k/sumsq_k. Все record_id заполнены, n=500. is_anomaly не участвует в статистике.
4. «Mean и генеральное std без округления» — Калькулятор: mean_k=sum_k/n; std_k=Sqrt(sumsq_k/n−mean_k*mean_k). Значения не округляются.
5. «Статистика для присоединения ко всем строкам» — Параметры полей оставляют all_rows, три mean и три std; исключают суммы, n и пустой служебный Expr1.
6. «Глобальные mean и std к каждой исходной строке» — Слияние по all_rows с двух веток; единственная строка статистик присоединяется к каждой из 500 исходных строк.
7. «z и матрица ошибок при строгом пороге 3» — Калькулятор: z_k=(metric_k−mean_k)/std_k; predicted=IF(Abs(z_1)>3 or Abs(z_2)>3 or Abs(z_3)>3,1,0). tp_row/fp_row/fn_row/tn_row проверяют соответствующие сочетания predicted и исходного is_anomaly. Строгое сравнение не включает ровно 3.
8. «Итоговые целочисленные tp fp fn tn» — Группировка по all_rows и суммы четырёх индикаторов → tp,fp,fn,tn.
9. «Целые счетчики и проценты без округления» — Калькулятор переводит счётчики через Int(...); precision=IF(tp+fp=0,0,100.0*tp/(tp+fp)); recall=IF(tp+fn=0,0,100.0*tp/(tp+fn)). Обе формулы с множителем 100 и защитой нулевого знаменателя проверены непосредственно в сохранённом XML.
10. «Сортировка по неокругленным процентам» — precision и recall по убыванию до округления; на одну строку порядок не влияет.
11. «Финальное округление процентов до 6 знаков» — Калькулятор заменяет precision/recall через Round(...,6); четыре счётчика сохраняет целыми.
12. «Одна строка - шесть требуемых колонок» — Параметры полей исключают служебный all_rows, оставляют только требуемые поля.
13. «CSV результат» — единственная выгрузка UTF-8, заголовки из имён колонок, запятая и десятичная точка.

## Результат и проверка

Колонки: tp,fp,fn,tn,precision,recall. Одна строка 0,20,20,460,0,0. Оба процента на фиксированном CSV равны нулю; правильные единицы отдельно доказаны формулами графа. До модельного построения primary-v2 oracle прошёл RED→GREEN на ненулевом fixture с precision=recall=50 процентов и новую независимую слепую сверку. Oracle и fixture модели не передавались. Полный oracle находится в oracle.csv, числовой допуск 1e-6.

CLI 0.2.2, openai/gpt-6.1-sol/xhigh, primary-v2 попытка 1 без подсказки. Primary-v2 исправляет единицы авторской спецификации до первого модельного запуска; аналитика не упрощалась. Модель самостоятельно восстановила локальные UI-остановки открытия и выходного сопоставления калькуляторов; пакет сохранён с exit=0.

Официальная проверка графа и полного CSV прошла. Сохранённый пакет заново открыт через меню и выполнен целиком: 13 узлов активны, ошибок нет. Новый CSV полностью совпал с oracle; пакет закрыт без сохранения изменений браузерной сессии. Версии, SHA256, свежая независимая слепая сверка primary-v2 и formula-proof приведены в provenance.
