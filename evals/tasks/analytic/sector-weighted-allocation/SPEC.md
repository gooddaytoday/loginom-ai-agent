# Веса и взвешенные показатели секторов

Источник: `analitic-tasks/task41-portfolio-analysis`, 200 строк `data/dataset.csv`. Исходный файл сохранён побайтово; сумма исходных весов равна 101 и не нормализуется.

## Фактический граф

Описание проверено по `Unit_0/Unit.xml` принятого пакета. Используются десять стандартных узлов, JavaScript отсутствует.

| Узел | Компонент | Настройка |
|:--|:--|:--|
| Исходные активы — dataset.csv | Импорт текстового файла | UTF-8, запятая, десятичная точка; загруженная копия dataset.csv в `/user/` совпадает с исходником по SHA256. |
| Взвешенные слагаемые без округления | Калькулятор | `return_component=allocation_percent*annual_return`, `dividend_component=allocation_percent*dividend_yield`, служебный `audit_group=1`. |
| Секторы — число активов и суммы весов | Группировка | Ключ `sector`; `COUNT(portfolio_id)` → assets, суммы allocation_percent → allocation_weight, return_component → return_sum, dividend_component → dividend_sum. Все portfolio_id заполнены. |
| Контроль исходных данных — 200 строк, вес 101 | Группировка | Отдельная контрольная ветка по audit_group: считает portfolio_id и суммирует исходные allocation_percent, без нормализации. В выгрузку не входит. |
| Взвешенные проценты внутри сектора | Калькулятор | `weighted_return_pct=100*return_sum/allocation_weight`, `weighted_dividend_pct=100*dividend_sum/allocation_weight`. |
| Пять итоговых колонок | Параметры полей | Оставляет sector, assets, allocation_weight и два взвешенных процента; исключает return_sum/dividend_sum. |
| Сортировка — вес ↓, сектор ↑, до округления | Сортировка | allocation_weight по убыванию, затем sector по возрастанию; LocaleAware=false. |
| Округление | Калькулятор | Заменяет три вещественных итоговых поля через Round(...,6). Сохранившееся служебное Expr1=0 исключается следующим узлом и не влияет на расчёт. |
| Итоговая таблица | Параметры полей | Исключает Expr1, сохраняя пять требуемых колонок. |
| Итоговый CSV | Экспорт текстового файла | Одна выгрузка, UTF-8, заголовки из имён колонок, запятая и десятичная точка. |

Основной путь: импорт → калькулятор слагаемых → группировка секторов → калькулятор процентов → отбор полей → сортировка → округление → итоговая таблица → экспорт. От калькулятора слагаемых отходит связанная контрольная ветка общей суммы весов. Взвешенные показатели делятся на вес собственного сектора; простые средние и общая нормировка до 100 не применяются.

## Результат и проверка

CSV содержит `sector, assets, allocation_weight, weighted_return_pct, weighted_dividend_pct`, ровно пять строк. Сортировка выполняется до округления; счётчики целые. Полный oracle — `oracle.csv`, допуск всех числовых ячеек `1e-6`.

CLI 0.2.2, `openai/gpt-6.1-sol/xhigh`, primary-попытка 1 без внешней подсказки. Модель самостоятельно восстановилась после локальных остановок UI при настройке калькуляторов; итоговый пакет сохранён с exit=0. Официальная проверка графа и всего CSV прошла. Пакет заново открыт через меню, выполнены все десять узлов: зелёные рамки, ошибок нет. Новый CSV полностью совпал с oracle; пакет закрыт без сохранения изменений браузерной сессии. Версии, SHA256 и независимая слепая сверка — в provenance.
