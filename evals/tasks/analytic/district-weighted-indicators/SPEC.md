# Взвешенные показатели округов

Источник: `analitic-tasks/task55-rosstat`. Фиксированный вход — `data/dataset.csv`, все 50 строк. Веса — исходное `population` внутри каждого `region`; межрегиональная нормировка не применяется. Безработица и рост доходов уже заданы в процентах, дополнительный множитель 100 не используется.

## Фактический сохранённый граф

В `reference.lgp` восемь стандартных узлов, соединённых семью связями одного линейного пути:

1. Импорт CSV с заголовком, UTF-8, запятой и десятичной точкой.
2. Калькулятор добавляет `pop_gdp=population*gdp_per_capita`, `pop_salary=population*average_salary`, `pop_unemployment=population*unemployment_rate`, `pop_income_growth=population*real_income_growth`. Исходные отрицательные изменения сохраняются.
3. Группировка по `region`: Count(region_id) → `observations`, Sum(population) → `total_population`, суммы четырёх произведений. `region_id` заполнен во всех 50 строках, поэтому Count равен числу наблюдений.
4. Калькулятор делит каждую сумму произведений на `total_population`, получая четыре взвешенных средних. `total_population` приводится к целому через `Int`; простые средние и межрегиональные веса не используются.
5. Параметры полей оставляют семь заданных колонок и исключают служебные суммы произведений.
6. Сортировка неокруглённого `weighted_real_income_growth` по убыванию, затем `region` по возрастанию; LocaleAware=false.
7. Калькулятор после сортировки округляет четыре средних через `Round(Abs(x)*1000000)`, выделяет целую и шестизначную дробную части через `Int`, `Div`, `Mod`, `Str`, `StrZero`, `Concat`. Знак возвращается `IF(x<0,"-","")`; `Abs` служит только форматированию модуля. Число наблюдений и сумма населения остаются целыми.
8. Единственный экспорт UTF-8 CSV с заголовками по именам, запятой и десятичной точкой: `/user/analytic-evals-district-weighted-indicators-2.result.csv`.

JavaScript, дополнительные ветки и вручную введённые итоговые строки отсутствуют. Пакет создан CLI 0.2.2 на `openai/gpt-6.1-sol/xhigh`, primary-попытка 2 без подсказки. Первая попытка завершилась техническим отказом входного сопоставления; её квитанции и подтверждённая очистка сохранены. Вторая попытка штатно восстановила один таймаут выходного сопоставления через inspect → release after proof → повторную настройку существующего узла. Аналитика не менялась и не упрощалась.

## Результат и проверка

Ровно восемь строк, колонки `region,observations,total_population,weighted_gdp_per_capita,weighted_average_salary,weighted_unemployment_rate,weighted_real_income_growth`. Полный ожидаемый CSV — `oracle.csv`, абсолютный допуск `1e-6`. Oracle на стандартной библиотеке Python подтверждён независимым слепым SQL-расчётом.

Проверены побайтовый SHA256 входа, реальные формулы и связность графа, сортировка перед округлением, полный CSV после CLI. После завершения CLI сохранённый пакет отдельно открыт в браузере, выполнен целиком и закрыт без сохранения; новый CSV прошёл повторное сравнение всех строк и колонок. Пути доказательств, параметры модели и история попыток находятся в `provenance.json`.
