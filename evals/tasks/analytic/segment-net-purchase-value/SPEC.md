# Покупки с учётом возвратов по готовым сегментам

Источник: analitic-tasks/task29-customer-segmentation-clv, 400 строк data/dataset.csv. Исходный CSV сохранён побайтово. Используется готовый segment без повторной сегментации; net_purchase_value — показатель покупки с учётом возвратов, не оценка CLV.

## Фактический граф

Описание проверено по Unit_0/Unit.xml принятого пакета. Шесть стандартных узлов образуют один линейный путь; JavaScript и обучение моделей отсутствуют.

1. «dataset.csv — все клиенты» — импорт UTF-8 с запятой и десятичной точкой. Загруженный CSV совпадает с источником по SHA256; фильтра нет.
2. «net_purchase_value для каждого клиента» — Калькулятор: net_purchase_value=avg_order_value*frequency*(1-return_rate). Произведение вычисляется на исходной строке клиента.
3. «По segment: число клиентов и средние» — единственный ключ исходный segment; Count(customer_id)→customers, Avg(recency_days)→mean_recency_days, Avg(frequency)→mean_frequency, Avg(monetary_value)→mean_monetary_value, Avg(net_purchase_value)→mean_net_purchase_value. Все 400 customer_id заполнены, поэтому count соответствует числу строк. Усредняется построчное произведение, а не перемножаются групповые средние.
4. «mean_net_purchase_value ↓, segment ↑ — до округления» — Сортировка неокруглённого mean_net_purchase_value DESC, segment ASC, LocaleAware=false.
5. «Финальный формат CSV: шесть знаков после точки» — четыре средних заменяются на строки. Для каждого x сначала Round(x*1000000) округляет до целого, StrZero(...,7) даёт не менее семи цифр, затем Stuff вставляет точку перед шестью последними цифрами. Так окончательное округление до шести знаков выполняется после сортировки. Все эти средние неотрицательны на фиксированном входе. Выходное сопоставление оставляет ровно шесть требуемых колонок; customers сохраняет целый тип.
6. «Итоговый CSV по сегментам» — единственная выгрузка UTF-8 с заголовками из имён колонок, запятой и десятичной точкой.

## Результат и проверка

Колонки: segment,customers,mean_recency_days,mean_frequency,mean_monetary_value,mean_net_purchase_value. Четыре строки: high_value, mid_value, low_value, at_risk. Полный oracle находится в oracle.csv, числовой допуск 1e-6.

CLI 0.2.2, openai/gpt-6.1-sol/xhigh, primary-попытка 1 без внешней подсказки, exit=0. Упрощение не применялось.

Официальная проверка графа и полного CSV прошла. Сохранённый пакет отдельно открыт через меню браузера и выполнен целиком: шесть узлов активны, ошибок нет. Новый CSV полностью совпал с oracle; пакет закрыт без сохранения браузерных изменений. Версии, SHA256 и независимая слепая сверка приведены в provenance.
