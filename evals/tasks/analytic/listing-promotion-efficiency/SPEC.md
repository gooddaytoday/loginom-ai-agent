# Эффективность продвижения объявлений

Источник: `analitic-tasks/task57-avito-analytics`. Фиксированный вход — `data/dataset.csv`, все 200 объявлений; исходный `is_top` не пересоздаётся.

## Фактический сохранённый граф

В `reference.lgp` девять стандартных узлов. Итоговый CSV создаётся связным путём из шести узлов:

1. Импорт CSV с заголовком, UTF-8, запятой и десятичной точкой; `is_top` — целое дискретное поле.
2. Группировка по `category` и исходному `is_top`: Count(listing_id) → `listings`, суммы `views`, `days_active`, `favorites`, простое среднее `response_rate`. `listing_id` заполнен во всех 200 строках, поэтому Count равен числу объявлений.
3. Калькулятор «Показатели и финальный формат CSV» считает сырые `views_per_active_day=sum_views/sum_days_active`, `favorites_pct=100*sum_favorites/sum_views`, `mean_response_pct=100*avg_response_rate`. Отдельные поля с суффиксом `_csv` вычисляют те же итоговые показатели и округляют их через `Round(x*1000000)`, затем `Int`, `Div`, `Mod`, `Str`, `StrZero`, `Concat` формируют точку и шесть знаков. Все участвующие исходные просмотры, дни, избранное и response_rate на фиксированном входе неотрицательны.
4. Параметры полей «Итоговые колонки CSV» исключают сырые показатели, суммы и среднее, переименовывают три `_csv`-поля в итоговые имена. Ключи группы и целый `listings` проходят без изменения.
5. Сортировка «Порядок строк CSV»: `category` по возрастанию, затем целый `is_top` по возрастанию; LocaleAware=false. Округление сделано после всех числовых расчётов, перед сортировкой только по ключам группы. Сортировки по расчётным величинам здесь нет, на порядок строк округление не влияет.
6. Единственный экспорт UTF-8 CSV с заголовками по именам, запятой и десятичной точкой: `/user/analytic-evals-listing-promotion-efficiency-2.result.csv`.

От калькулятора метрик также сохранена отдельная служебная ветка из трёх узлов: «Шесть итоговых полей» → «category ASC, is_top ASC — до округления» → «Округление 6 знаков». Последний узел содержит оставшееся пустое `Expr1` и три заменяющих выражения форматирования. Эта ветка не соединена с итоговым экспортом, её `Expr1` в CSV не попадает. В браузерной проверке выполнен весь пакет, включая эту ветку: все девять узлов активны, ошибок нет.

JavaScript и вручную введённые итоговые строки отсутствуют. Пакет создан CLI 0.2.2 на `openai/gpt-6.1-sol/xhigh`, primary-попытка 2 без подсказки. Первая попытка завершилась техническим отказом подтверждения входного сопоставления экспорта; квитанции и безопасная очистка сохранены. Во второй попытке агент штатно освобождал остановленные настройки, исправлял сопоставление и построил действующий экспортный путь. Аналитика не менялась и не упрощалась.

## Результат и проверка

Ровно 12 строк, колонки `category,is_top,listings,views_per_active_day,favorites_pct,mean_response_pct`. Счётчики и `is_top` целые; три показателя имеют шесть десятичных знаков. Полный ожидаемый CSV — `oracle.csv`, абсолютный допуск `1e-6`. Oracle на стандартной библиотеке Python подтверждён независимым слепым SQL-расчётом.

Проверены SHA256 входа, реальные отношения сумм и среднее response_rate×100, действующий путь графа, единственный экспорт и весь CSV после CLI. Сохранённый пакет отдельно открыт в браузере после завершения CLI, выполнен целиком и закрыт без сохранения; новый CSV снова совпал со всеми строками и колонками oracle. История попыток и пути доказательств — в `provenance.json`.
