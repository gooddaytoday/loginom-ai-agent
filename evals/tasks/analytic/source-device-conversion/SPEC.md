# Конверсия по источнику и устройству

Источник: analitic-tasks/task51-yandex-metrica, 200 строк data/dataset.csv. Исходный CSV сохранён побайтово. Каждая строка — одна сессия; visits не служит весом или фильтром. Все 13 строк с visits=0 включены.

## Фактический граф

Описание проверено по Unit_0/Unit.xml принятого пакета. Шесть стандартных узлов образуют один линейный путь без вспомогательных веток; JavaScript отсутствует.

1. «dataset.csv — все строки» — импорт UTF-8 с запятой и десятичной точкой. Загруженный CSV совпадает с источником по SHA256; фильтра нет.
2. «Сессии, цели, длительность и выручка» — только два ключа source,device. Count(session_id)→sessions, Sum(goal_reached)→goals, Avg(visit_duration_sec)→mean_duration_sec, Sum(revenue)→revenue_total. Все 200 session_id заполнены, поэтому count соответствует числу строк. Поле visits не участвует в агрегации.
3. «Показатели и формат CSV — 6 знаков» — Калькулятор сохраняет числовые conversion_pct=100.0*goals/sessions и revenue_per_session=revenue_total/sessions. Отдельные conversion_csv, duration_csv, revenue_csv представляют окончательные значения с шестью знаками: округляется Abs(x)*1000000, выделяются целая и шестизначная дробная части, добавляются точка и знак по условию x<0. Abs используется только для цифр строкового представления, исходные числовые показатели не заменяются модулем. Ссылки Expr.conversion_pct и Expr.revenue_per_session берут вычисленные в том же узле числовые результаты. Округление выполняется после всех числовых расчётов.
4. «source ASC, device ASC» — Сортировка двух исходных текстовых ключей ASC, LocaleAware=false. Она идёт после форматирования, но округлённые показатели в сортировке не участвуют; порядок строк от округления не зависит. Сортировки по расчётным величинам в этом кейсе нет.
5. «Итоговые 7 колонок CSV» — Параметры полей исключают сырые вычисленные показатели и revenue_total, переименовывают conversion_csv→conversion_pct, duration_csv→mean_duration_sec, revenue_csv→revenue_per_session. Goals приводится к dtInteger, sessions уже целое. Сохраняются ровно семь требуемых колонок.
6. «analytic-evals-source-device-conversion-3.result.csv» — единственная выгрузка UTF-8 с заголовками из имён колонок, запятой и десятичной точкой.

## Результат и проверка

Колонки: source,device,sessions,goals,conversion_pct,mean_duration_sec,revenue_per_session. Восемнадцать строк в порядке source ASC,device ASC. Полный oracle находится в oracle.csv, числовой допуск 1e-6.

CLI 0.2.2, openai/gpt-6.1-sol/xhigh, primary-попытка 3 с технической подсказкой. Подсказка касается повторной настройки существующих выражений, обязательных полей, положения существующих узлов и сохранения числовых типов при создании отдельных CSV-представлений; oracle и готовые ответы модели не передавались. Попытки 1–2 закончились техническими UI-отказами без пакета и CSV. Их квитанции, классификация и подтверждённое штатное освобождение профиля сохранены. Аналитика не упрощалась.

Официальная проверка графа и полного CSV прошла. В свежем браузерном контексте сохранённый пакет открыт через меню и выполнен целиком: шесть узлов активны, ошибок нет. Новый CSV полностью совпал с oracle; пакет закрыт без сохранения браузерных изменений. Версии, SHA256, история попыток и независимая слепая сверка приведены в provenance.
