Маржинальная тарификация общего потребления

Сценарий рассчитывает ведомость по всем счетам реестра. Записи расхода сначала суммируются по счёту, затем общий расход распределяется по маржинальным тарифным ступеням его плана. Фиксированная плата начисляется один раз, включая счета без записей и с нулевым расходом. Данные полностью синтетические.

Входы

- `tier_accounts.csv`: 9 счетов, поля account_id,plan_id,fixed_fee.
- `tier_readings.csv`: 12 записей, поля reading_id,account_id,quantity. A01 не имеет записей; A08 имеет нулевую запись. Несколько записей есть у A02, A04, A05, A09.
- `tier_rates.csv`: 6 ступеней двух планов, поля plan_id,lower_qty,upper_qty,unit_rate. Ступени непрерывно покрывают 0..500; порядок строк произвольный.

Все входы UTF-8, первая строка — технические имена, разделитель запятая, десятичная точка. Ключи строковые, quantity/fixed_fee/границы/ставки числовые. Пустых значений во входах нет.

Фактический reference

| Узел | Native-компонент | Существенная настройка |
| --- | --- | --- |
| Реестр счетов | Импорт текстового файла | tier_accounts.csv, явные типы трёх полей |
| Записи расхода | Импорт текстового файла | tier_readings.csv, reading_id/account_id — строки, quantity — число |
| Тарифные ступени | Импорт текстового файла | tier_rates.csv, plan_id — строка, остальные поля числовые |
| Расход за период по счёту | Группировка | account_id, SUM(quantity), выходное имя quantity |
| Все счета и суммарный расход | Слияние | Left Join полного реестра со сводкой по account_id |
| Нет записей означает нулевой расход | Пропуски | Отсутствующая quantity заменяется константой 0 |
| Разворот счетов на ступени плана | Слияние | Inner equijoin по plan_id, три строки на счёт |
| Маржинальный расход и стоимость ступени | Калькулятор | Ограничение расхода шириной своей ступени; tier_charge=tier_quantity*unit_rate |
| Стоимость расхода по счёту | Группировка | Ключи account_id,quantity,fixed_fee; SUM(tier_charge) → variable_charge |
| Фиксированная плата один раз и итог | Калькулятор | total_charge=Round(variable_charge+fixed_fee,6); финальное округление остальных числовых колонок |
| Итоговая ведомость по account_id | Сортировка | account_id по возрастанию; только пять итоговых колонок |
| Итоговый CSV начислений | Экспорт текстового файла | UTF-8, технический заголовок, запятая, десятичная точка |

Связи: реестр и сводка расхода сходятся в левом слиянии; после восстановления нуля результат соединяется со справочником ступеней; последовательно идут построчная стоимость, итоговая группировка, итоговые суммы, сортировка и экспорт. Все 12 узлов связаны; независимые ветви включают три исходных импорта. Граф не содержит JavaScript.

Сохранённая формула количества внутри ступени:

`IFF(quantity <= lower_qty, 0, IFF(quantity >= upper_qty, upper_qty-lower_qty, quantity-lower_qty))`.

Границы не добавляют отдельную единицу расхода; при нуле ни одна ступень не создаёт стоимости. Группировка после разворота не суммирует fixed_fee: она входит в ключ счёта и прибавляется после суммы переменной стоимости.

Независимая проверка

`oracle.py` читает исходные CSV и выполняет прямой Decimal-расчёт каждого счёта, не используя граф или экспорт Loginom. Дополнительная независимая ручная таблица подтвердила все 9 строк × 5 колонок. В частности, A04 имеет расход 150+130=280 и variable_charge=365, total_charge=372. Тарификация каждой записи отдельно дала бы иную сумму; ставка последней ступени для всего расхода дала бы total_charge=147, повторная плата трёх ступеней — 386. A01 сохраняется с расходом 0 и платой 7.

Reference создан первой started CLI-попыткой, фактическая модель openai/gpt-6.1-sol/xhigh подтверждена в БД сессии. Exit 0; все три доставленных входа совпали с исходными байтами, полный CSV совпал с oracle при допуске 0.000001. Подсказок не было. Проверка пакета принимает эквивалентные native-композиции и не требует именно этих имён или числа узлов.

Cold: в отдельной браузерной сессии открыт сохранённый пакет и выполнены все 12 узлов без открытия настроек и Save. Прежний CSV припаркован, новый полный CSV совпал с oracle. SHA256 серверного LGP до/после одинаков. Закрытие пакета и logout подтверждены. Приватные receipts, исходная история и авторская среда сохраняются вне Git.

Выход

Ровно 9 строк, порядок account_id; колонки account_id,quantity,variable_charge,fixed_fee,total_charge. Полный ожидаемый результат хранится в `oracle.csv` и дословно включён в единственный пункт rubric `result-rows`. Обе формы используют одни данные, определения, oracle, rubric и общий reference; business не приписывается отдельная авторская CLI-попытка.
