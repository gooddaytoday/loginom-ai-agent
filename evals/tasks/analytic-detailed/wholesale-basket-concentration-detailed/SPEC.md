# Концентрация закупочной корзины: фактический reference

## Данные и общий контракт

Использованы все 440 строк UCI Wholesale Customers (Margarida Cardoso, DOI 10.24432/C5030X, CC BY 4.0) в исходном порядке. Восемь исходных полей сохранены; добавлен строковый технический customer_id=C001…C440 по номеру строки исходного снимка. Это ключ снимка, не исходная идентичность клиента. Изменена только CSV-сериализация: UTF-8, разделитель `;`, десятичная точка, заголовок, LF. Полная атрибуция, лицензия, происхождение и изменения приведены в provenance.json:source_dataset.

Расходы: Fresh, Milk, Grocery, Frozen, Detergents_Paper, Delicassen. Channel и Region — категориальные коды, в расходы и зерно результата не входят. Денежные единицы исходного набора сохраняются; валюта и масштаб проверенными сведениями не установлены. Все суммы клиента положительны. Нулевых расходов в этом реальном снимке нет; проверка отдельного zero-expense witness не заявляется, синтетические наблюдения не добавлялись.

## Фактический граф

В принятом reference семь native узлов и шесть связей одной последовательной цепочки. Это описание reference; rubric допускает эквивалентные native решения без совпадения имён и количества узлов.

1. **«Исходные клиенты» — импорт текста.** Читает доставленный wholesale-customers.csv, UTF-8/65001, `;`, decimal dot. customer_id имеет строковый тип; Channel/Region — категориальные целые, шесть расходов — целые числа. Доставленный файл побайтно совпал с закреплённым входом.
2. **«Концентрация корзины» — Калькулятор.** total_spend складывает шесть расходов текущей строки. Каждая category_share равна расходу категории, делённому на total_spend того же клиента. hhi — сумма квадратов всех шести долей; effective_categories=1/hhi; max_category_share — Max шести долей. Итоговые вычисления имеют вещественный тип, промежуточного округления нет. Глобальных, групповых или рыночных знаменателей нет.
3. **«Пять показателей» — Параметры полей.** Исключает Channel/Region, исходные расходы и промежуточные доли, сохраняя customer_id, total_spend и три показателя. Группировки/фильтрации клиентов нет.
4. **«По номеру клиента» — Сортировка.** customer_id как string по возрастанию, binary, LocaleAware=false; ASC подтверждён actual readback и полным CSV, не выведен из отсутствующего XML-атрибута.
5. **«Сумма с двумя знаками» — Калькулятор.** Создаёт строковый spend_csv выражением `Concat(Str(Int(total_spend)), ".00")`. Сумма шести frozen integer расходов здесь целая и точно представима; Int не теряет дробную денежную информацию этого снимка. Это форматирование только total_spend, не округление трёх metrics.
6. **«Поля итогового CSV» — Параметры полей.** Исключает прежний real total_spend, сохраняет spend_csv с display label total_spend и остальные четыре колонки.
7. **«Итоговый CSV» — экспорт текста.** Один UTF-8/65001 CSV, `;`, decimal dot, квалификатор двойная кавычка, BOM=false, заголовок из labels (`header=2`). В итоговом файле денежная колонка называется total_spend; все 440 её ячеек имеют не менее двух десятичных знаков.

JavaScript, внешний расчёт или подстановка готового gold в графе не используются. Независимый oracle.py читает только data/wholesale-customers.csv, вычисляет рациональные доли/HHI через Fraction и сериализует metrics через Decimal с точностью, достаточной для допуска.

## Полная сдача

Ровно 440 строк данных и пять колонок: customer_id, total_spend, hhi, effective_categories, max_category_share. Все C001…C440 уникальны, идут как строки по возрастанию. Проверяется весь CSV; порядок колонок сопоставляется по именам. Абсолютный numeric tolerance=1e-8; total_spend обязан иметь минимум два знака после точки. У metrics отдельного минимального числа знаков нет — требуется численная точность. Эссе или дополнительные артефакты не требуются.

## Происхождение и выполненные проверки

Reference построен detailed CLI attempt 1/3, modelConfirmed openai/gpt-6-sol/xhigh, с одним raw input. Check полного CSV и совпадение доставленного входа прошли. Сохранённый package после Save и собственное native закрытие подтверждены. Business использует тот же принятый reference; отдельный business build не заявляется.

Cold D1 выполнен root, знающим oracle, и не называется blind: точный пакет вновь открыт в браузере, все семь BODY→F9 исполнены без Configure/Save; после экспорта Home→Logout→«Выйти без сохранения», закрыта собственная вкладка. После парковки старого результата создан новый полный 440×5 CSV; check-rerun PASS, IDs/порядок/все440 денежных форматов подтверждены. Фактический server LGP до/после совпал; максимальные ошибки трёх metrics менее 5e-11 при допуске1e-8.

Наличие этого reference/D1 и offline corpus preparation не подтверждает live judge calibration либо результаты будущих измерений. Они остаются pending до отдельных фактических запусков root.
