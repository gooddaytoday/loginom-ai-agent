Коррекция готовых p-value Benjamini–Hochberg внутри полных семей, с решением по неокруглённому adjusted p и alpha своей семьи. Данные синтетические. Native reference получен отдельной чистой B-попыткой только с B+inputs; D использует тот же пакет с честным source_task, без вымышленного D-запуска.

|---|---|---|
| Исходные гипотезы | Импорт текста | bh_tests.csv: family_id,hypothesis_id,p_value |

| Размеры и позиции | Внутреннее соединение | Строки и сводка по family_id |
| Ранги и кандидаты BH | Калькулятор | bh_rank=position-first_position+1; candidate_q=Min(1,m*p_value/(position-first_position+1)) |
| Кандидаты хвостового минимума | Производные поля | Правая копия family_id,rank_j,q_j для ранга и кандидата |

Начальная сортировка делает позиции каждой семьи смежными, поэтому вычитание её минимальной позиции даёт локальные ранги 1..m. Внутренний cap каждого candidate_q эквивалентен cap после хвостового минимума. Ни большие p, ни крайние p=0/1 не удалены. Self-equijoin ограничен family_id; рассчитанный boolean-флаг позволяет штатному Filter использовать константу, а не field-to-field operand. Ни JavaScript, ни новый ranking-handler не используются. Эквивалентные native-композиции принимаются, имена и количество узлов не являются требованиями rubric.

Oracle независим от XML/экспорта: Fraction по исходным CSV, сортировка внутри каждой семьи и обратный проход со скользящим минимумом. F01 даёт adjusted p 0.006/0.042/0.042/0.0735/0.96/1. F02 содержит ничью p=0.02: точное adjusted=2/75 меньше alpha=0.0266668, поэтому обе гипотезы отклоняются, хотя вывод 0.026667 больше alpha. Округление до решения меняет флаг и должно провалить полный oracle. В F03 adjusted=0.5 в точности равно alpha=0.5: строгое < неверно теряет H01. Разные размеры/alpha семей отличают pooling и подмену порога.
