Точное целочисленное распределение неделимых единиц по наибольшим остаткам, отдельно по pool_id. Native reference читает apportion_pools.csv и apportion_weights.csv; все данные синтетические.

| Узел | Компонент | Фактическая настройка |
|---|---|---|
| Исходные пулы | Импорт текста | pool_id,units, целые неотрицательные units |
| Исходные веса | Импорт текста | pool_id,recipient_id,weight, включая нулевые веса |
| Суммы весов по пулам | Группировка | pool_id; SUM(weight) как total_weight |
| Получатели и сумма весов | Внутреннее соединение | Исходные получатели и total_weight по pool_id |
| Присоединение числа единиц | Внутреннее соединение | units своего pool_id |
| Квоты и неокругленные остатки | Калькулятор | quota=units*weight/total_weight; base_units=Int(quota); remainder=quota-base_units |
| Базовое распределение по пулам | Группировка | pool_id; сумма base_units и сохранённое число units |
| Оставшиеся единицы | Калькулятор | leftover=pool_units-sum_base |
| Правая копия получателей | Производные поля | pool_id, recipient_id_j и remainder_j; исключение ненужных правых полей |
| Все пары получателей внутри пула | Внутреннее соединение | Квоты и правая копия по pool_id |
| Флаг строгого опережения | Калькулятор | better=1 при большем remainder_j либо равном остатке и меньшем recipient_id_j, иначе 0 |
| Число опережающих получателей | Группировка | Ключ получателя i с его исходными метриками; SUM(better) как ahead_count |
| Приоритеты и оставшиеся единицы | Соединение | Подключить leftover по pool_id |
| Распределение и выходная точность | Калькулятор | extra_unit=If(ahead_count<leftover,1,0); allocated_units=base_units+extra_unit; только теперь Round(quota,6) |
| Точные итоговые поля | Производные поля | Ровно шесть требуемых полей, без служебных величин |
| Итог по пулу и получателю | Сортировка | pool_id,recipient_id по возрастанию |
| Контроль сохранения единиц | Группировка | Дополнительная сводка сумм allocated_units по пулам для проверки; не отдельный экспорт |
| Итоговый CSV | Экспорт текста | Единственный CSV UTF-8 с заголовком, запятой и десятичной точкой |

Исходная ветвь квот питает подсчёт базовых сумм и pairwise-ранжирование. Остатки сравниваются до округления, равенство разрешает recipient_id, а не входной порядок. Нулевые веса и units=0 проходят все ветви; при leftover=0 extra_unit=0. Сводка контроля и экспорт являются разными исполняемыми ветвями; cold исполнил обе.

Для неотрицательных квот Int равна целой части вниз. Функция проверена до reference по [Loginom Help](https://help.loginom.ru/userguide/processors/func/calc-func/mathematical.html). Допустимы эквивалентные native-композиции, без JavaScript. Имена и число узлов не являются требованиями rubric.

Независимый oracle использует Fraction, целочисленное деление числителя на знаменатель и сортировку остатков/ID, без native self-join. P01 (5 единиц; веса 5/3/2/0) даёт 3/1/1/0; P02 (2 единицы; равные A/B/C) даёт 1/1/0 вопреки обратному входному порядку. P03 сохраняет все три нулевые строки. P04 также имеет units=2, но веса 1/2/4 и итог 0/1/1; это отличает ранжирование внутри pool от смешения пулов с одинаковым units. Итоги четырёх пулов 5/2/0/2.
