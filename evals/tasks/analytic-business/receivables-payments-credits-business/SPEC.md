# P01. Дебиторская задолженность с частичными платежами

> Сведения о локальном окружении обезличены. Приватные подтверждения, упомянутые в документе, не включены в репозиторий.

Назначение: получить задолженность каждого клиента полного реестра счетов с учётом только проведённых платежей и кредит-нот, сохранив неоплаченные счета и отрицательную переплату.

## Происхождение и границы

Обе формы используют общее описание одного reference, созданного первой CLI-попыткой detailed (D). Отдельная CLI-сборка business (B) не выполнялась. Основа этого SPEC — фактически сохранённый `package.lgp`, единственный `Unit_0/Unit.xml`, а не предполагаемый граф. CLI/reference и D1 подтверждены: отдельная браузерная сессия выполнила все 14 узлов, серверный LGP не изменился, новый полный CSV совпал с независимым oracle. Калибровка и измерения учитываются отдельно в карточке P01; SPEC их не подменяет.

Это один допустимый native-путь без JavaScript. При оценке принимаются эквивалентные native-композиции: имена, число и состав узлов reference не являются требованиями к решению. Имена пакета и файла результата задаёт harness и в оценке не учитываются.

## Входы

Все три файла из `data/` — CSV UTF-8 с заголовком, разделителем `;` и десятичной точкой. В сохранённых импортах стоят `CodePage=65001`, `DelimiterChar=;`, `DecimalSeparator=.`, пустой `ValueNull`; пути `PRIVATE_STORAGE` оканчиваются соответствующим basename.

- `invoices.csv`: `invoice_id`, `customer_id` — `dtString`; `invoice_amount` — `dtFloat`. `invoice_id` уникален; это полный реестр счетов.
- `payments.csv`: `payment_id`, `invoice_id`, `status` — `dtString`; `amount` — `dtFloat`. `payment_id` уникален.
- `credit_notes.csv`: `credit_id`, `invoice_id`, `status` — `dtString`; `amount` — `dtFloat`. `credit_id` уникален.

Каждая операция относится к существующему счёту; суммы операций неотрицательны. Только точное `status=posted` означает проведённую операцию. Денежная единица общая, без налогов и дополнительных сборов.

## Сохранённые узлы и настройки

| Узел | Реальный компонент (`xsi:type` Engine) | Настройки и формулы |
| --- | --- | --- |
| Полный реестр счетов | `TBGImportTextFile` | `invoices.csv`; схема и формат выше. |
| Платежи | `TBGImportTextFile` | `payments.csv`; схема и формат выше. |
| Проведенные платежи | `TBGFilterDataEngine` | `status`, `frtEqual`, `CaseSensitive=true`, строковое значение `posted`. |
| Оплаты по счету | `TBGGroupDataEngine` | Группа `invoice_id`; `amount`: `gdSum`; выход `amount_Sum` переименован в `paid`. |
| Кредит-ноты | `TBGImportTextFile` | `credit_notes.csv`; схема и формат выше. |
| Проведенные кредит-ноты | `TBGFilterDataEngine` | `status`, `frtEqual`, `CaseSensitive=true`, строковое значение `posted`. |
| Кредит-ноты по счету | `TBGGroupDataEngine` | Группа `invoice_id`; `amount`: `gdSum`; выход `amount_Sum` переименован в `credited`. |
| Все счета и оплаты | `TBGJoinDataEngine` | Главная таблица — реестр счетов, присоединяемая — сводка оплат; `Left invoice_id = Right invoice_id`. Отдельный атрибут режима соединения в XML отсутствует. |
| Все счета и кредит-ноты | `TBGJoinDataEngine` | Главная таблица — предыдущий результат, присоединяемая — сводка кредит-нот; `Left invoice_id = Right invoice_id`. Отдельный атрибут режима соединения в XML отсутствует. |
| Нули и остаток по счету | `TBGCalcData` | Замена `paid=NVLF(paid, 0)`, `credited=NVLF(credited, 0)`; новый `balance=invoice_amount - NVLF(paid, 0) - NVLF(credited, 0)`; все три поля `dtFloat`. |
| Задолженность клиентов | `TBGGroupDataEngine` | Группа `customer_id`; `invoice_id`: `gdCount` → `invoices`; `invoice_amount`, `paid`, `credited`, `balance`: `gdSum` → `invoiced`, `paid`, `credited`, `balance`. |
| Итог по customer_id | `TBGSortingEngine` | Ключ `customer_id`, `LocaleAware=false`; в XML нет отдельного атрибута направления, контракт требует возрастание. |
| Денежный формат CSV | `TBGCalcData` | Заменяет `invoiced`, `paid`, `credited`, `balance` на `dtString` по формуле ниже; только финальное форматирование после суммирования. |
| Итоговый CSV | `TBGExportTextFile` | `CodePage=65001`, `CaptionType=ctUseColumnNames`, `DelimiterChar=;`, `DecimalSeparator=.`, пустой `ValueNull`; один файл результата. |

Для каждого из четырёх денежных полей сохранено одно и то же выражение с подстановкой имени поля вместо `x` (это обозначение в SPEC, не переменная пакета):

```text
Concat(IF(x < 0, "-", ""), Str(Int(Abs(Round(x, 2)))), ".", StrZero(Round(Frac(Abs(Round(x, 2))) * 100), 2))
```

## Связи

`Платежи → Проведенные платежи → Оплаты по счету` и `Кредит-ноты → Проведенные кредит-ноты → Кредит-ноты по счету` — две независимые ветви. Реестр поступает в главный вход «Все счета и оплаты», сводка оплат — в присоединяемый; этот результат поступает в главный вход «Все счета и кредит-ноты», сводка кредит-нот — в присоединяемый. Далее: `Нули и остаток по счету → Задолженность клиентов → Итог по customer_id → Денежный формат CSV → Итоговый CSV`.

Смысл соединений — сохранить полный реестр, включая счета без проведённых операций. Агрегация независимых журналов до соединения исключает перемножение платежей и кредит-нот одного счёта. Это предметные свойства результата, а не требование повторить внутренний граф reference.

## Ожидаемый результат

Одна строка на каждый `customer_id` полного реестра, ключ уникален, строки по `customer_id` по возрастанию с учётом регистра без локали. Ровно колонки `customer_id, invoices, invoiced, paid, credited, balance`; порядок колонок не оценивается. `customer_id` строковый, `invoices` — целое число счетов реестра; `invoiced` — сумма выставленных счетов клиента, `paid` — сумма его проведённых платежей, `credited` — сумма его проведённых кредит-нот, `balance=invoiced-paid-credited`. Отсутствующие оплаты и кредит-ноты равны нулю, положительные кредит-ноты уменьшают долг; отрицательный остаток не обрезается. Остальные статусы не участвуют в суммах и не увеличивают число счетов.

Один CSV UTF-8 с заголовком, разделителем `;`, десятичной точкой, без разделителей тысяч, строковый квалификатор `"`. Промежуточного округления нет; денежные суммы экспортируются не менее чем с двумя знаками после точки, в reference финальные строки имеют два знака. Источник полного состава строк и всех численных значений — соседний `oracle.csv`; значения здесь не дублируются. Сверяются все строки и колонки: точные имена колонок и текст, точный состав и порядок строк, числа с абсолютным допуском `0.001`, одинаковым для D/B. Лишние, пропущенные или повторяющиеся колонки и лишние/пропущенные строки недопустимы.
