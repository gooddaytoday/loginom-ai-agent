## Qualification and launch

Run from `evals/` with the role's pinned Bun. `R` is the private evalrun runtime;
`ISSUE` and `TASK` must identify the assigned LAB-77 issue and current native task.
Do not print the private environment or runtime configuration.

Before preparing any series, install the official clean build in a separate
immutable directory. Qualify its exact Chromium path under AppArmor, retain the
previous CLI, and change only EvalRunner's pins. Record successful full tests and
typecheck, sandbox/native cleanup, corpus and installed manifest hashes, and the
documented recovery of EvalRunner's historical resource in a private versioned
`evalrunner-nonmodel-qualification` receipt. The receipt is pinned by SHA256 in
the role config. A dead PID never authorizes historical lease retirement.

Perform real OpenViking health and actor-find calls with automatic Git peer and
record only their names, time and success. Confirm the dedicated container ID,
image, absence of host mounts, clean profile/storage and exclusive endpoint.
No unit fixtures may run concurrently with live measurements.

```sh
"$R/bin/bun" script/run-evalrunner.ts prepare --config "$R/roles/evalrunner/runtime.json"
"$R/bin/bun" script/run-evalrunner.ts prepare-series --config "$R/roles/evalrunner/runtime.json" --issue "$ISSUE" --task "$TASK" --scope readiness-calc
"$R/bin/bun" script/run-evalrunner.ts start-series --config "$R/roles/evalrunner/runtime.json" --series "$R/roles/evalrunner/results/v02-readiness-calc-$ISSUE" --task "$TASK"
```

Independently `check-series` after release. Then prepare and start
`readiness-node` in its separate canonical directory. After both one-slot
readiness series are confirmed RELEASED, prepare and start `full` at
`R/roles/evalrunner/results/v02-full-ISSUE`. Readiness IDs never consume main
slots and never reuse LAB-76 IDs. A completed quality FAIL is retained and can
qualify technically; infrastructure, judge error and uncertain cleanup cannot.

The main manifest contains exactly 144 unique `(collection, case, round)` slots:
three rounds of regular, analytic, node, case IDs alphabetical within each
collection. Each has repeat 1, infrastructure retries 0, product timeout 30 min,
judge timeout 5 min and management timeout 10 min. Product is
`openai/gpt-6.1-sol/medium`; regular/analytic judge is `gpt-6-sol/xhigh`, threshold
70; node uses the existing code validator only. The shared executor retains the
`evalrunner-v1` execution-policy selector that enables strict recovery and
disables external/Claude skills; it is not a configuration-version selector.

## Persistence, interruption and recovery

The issue/scope reservation and each slot admission live outside results under
`operations/`. Fsynced complete documents become visible by atomic no-replace
link before dispatch. Changing task ID, directory or controller never creates a
fresh attempt for an admitted slot. One executor lock excludes concurrent
start/resume; one logical series lease remains held through all slots.

| Interruption | Required behavior |
| --- | --- |
| Reservation exists, local preparation incomplete | BLOCKED; preserve the reservation and inspect original preparation evidence. |
| Admission exists, dispatch/outcome not proven | BLOCKED; no product redispatch, including after a child exits. |
| Child release exists, controller model/completion receipt absent | Resume verifies the existing sealed artifact and closed history, writes only the missing proof, and skips inference. |
| Completion exists | Verify pins, raw evidence, model proof and original outcome, then skip it. |
| Executor owner is dead, altered or foreign | BLOCKED; do not infer permission to remove its lock. |
| Finalization was admitted without parent release | BLOCKED; preserve evidence for explicit ownership/cleanup recovery. |
| 143 main completions | Cannot release or report COMPLETE. |
| Provider/infra error, recovery, UNKNOWN, judge error or unconfirmed cleanup | Stop dispatch and retain the logical lease and admission. |

`resume-series` uses the original canonical manifest and the same global
admissions. It does not automatically remove stale locks, replay an unproven
dispatch or repair a failed judge. A judge incident must preserve the original
summary, artifact, logs and product/model facts; any adjudication recovery must
use the existing artifact through the judge-only path, never another product
attempt. A scored quality FAIL is not a judge-recovery candidate. Releasing a
recovered incident requires independently verified evidence and documented
ownership/cleanup; absent that proof the series stays BLOCKED.

Each release verifies native process capture, no UNKNOWN identities, two empty
process observations, writer/ready/diagnostic cleanup, closed profile history and
empty isolated storage. Actual provider/model/variant are read only from a
private copy of the closed SQLite plus sidecars; source hashes must remain
unchanged. All assistant messages, including delegated sessions, must use the
pinned model and variant. The controller checks saved rubric/oracle judgment
and reruns node code validation independently.

## Pinned catalog and the authorized pre-inference recovery

The LAB-77 operator independently proved that the original readiness-calc
failed with `ProviderModelNotFoundError` before any Session, message or inference.
Its BLOCKED result, manifest, reservation, admission and evidence remain immutable.
The installed product sources remain at d87991c94; a harness-only change does
not require rebuilding that product or changing its recorded source pin.

Version 2 now pins `catalog.path` and `catalog.sha256`. Only the public catalog
file is mounted read-only; its directory and siblings stay hidden. Agent and
sandbox explicitly allow `LOGINOM_AI_AGENT_MODELS_PATH` and
`LOGINOM_AI_AGENT_DISABLE_MODELS_FETCH=1`. Qualification verifies bytes, exact
target and medium reasoning, then executes `models openai` with the same product
flags, auth and mounts in a probe profile without history. Dispatch repeats that offline check
before admission. Catalog recognition is not evidence of inference availability.

Only this exact issue's original readiness-calc can use `recover-readiness`:

```sh
"$R/bin/bun" script/run-evalrunner.ts recover-readiness --config "$R/roles/evalrunner/runtime.json" --series "$R/roles/evalrunner/results/v02-readiness-calc-$ISSUE" --task "$TASK" --proof-sha256 "$OPERATOR_PROOF_SHA256"
```

The command independently checks the pinned operator proof, the 33-file original
seal, both admission copies, exact lease owner, error-only events, zero tokens,
tools and judge calls, complete process capture with UNKNOWN=0 and two empty
observations. It copies the closed SQLite with sidecars, verifies zero sessions
and messages and unchanged source hashes, and rechecks current profile/storage.
New tests, qualification, harness/catalog/env pins must be fixed before recovery.

One durable recovery request is spent before retiring the exact lease directory
intact into `operations/series-recovery/ISSUE-readiness-calc/`. An append-only
receipt links every original file and the new pins to the sole `-g1` readiness

receipt. The node/full readiness gate follows this receipt and still requires
confirmed model, judgment, history, cleanup and RELEASED for generation 1.
No original RELEASED is manufactured. Any crash after request, repeated request,
Session/message/inference, unknown process, incomplete cleanup, pin drift or
attempt to recover node/full scope fails closed. There is no automatic rollback,
retry or second generation; investigate the retained journal instead.
