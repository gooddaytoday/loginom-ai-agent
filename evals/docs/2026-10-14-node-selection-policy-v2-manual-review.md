## Наблюдаемая необходимость

Claims/2 завершился с CLI0, oracle true, calculation true, policy passed, JS0
и подтверждённым normal close. Однако история содержит аномалию; исходный
runner правильно остановился с `MANUAL_REVIEW_REQUIRED`. Отдельное обязательное
ревью ещё нужно. Его обычный путь требует обновить поле reviewStatus в исходном
`selection-audit.json`. Для сохранения исходного машинного вердикта нужен узкий
путь v2, который учитывает новый review только в памяти.

Исходный audit SHA
`3b392b575993f2cc34a584fae4d69190083b6fae93ef0b6d4783b07743bd6c76`
остаётся неизменным. Дополнительная readonly копия сохранена отдельно;
attempt, closure, результат и исходный stopped ledger также не переписываются.
Источники предыдущего execution-r2 сохранены отдельными readonly копиями;
индекс SHA `47b10529a460217e612f7a3fad20832367e1452e4f57b7863753f3f865aeb667`.

## Узкий новый допуск

Только при explicit v2 context и стандартном сценарии, где исходные policy,
oracle и calculation уже положительны, новый самостоятельный graph review
может подтвердить завершение ревью. Он должен иметь положительный вердикт,
совпадающие Session и package SHA и существующие связанные evidence.
Неполный, отрицательный или чужой review не разрешает продолжение.

Runner использует подтверждённый reviewStatus в памяти для проверки следующего
слота; исходный audit не меняется. Все проверки original closure/protected hashes,
политики и strict release сохраняются. Другие аналитические статусы, поля policy
и runtime не подменяются. Этот путь не допускает oracle false или functional FAIL
и не предназначен для общего продолжения аналитически неуспешных попыток.
Старое поведение без opt-in остаётся прежним.

## Проверка и версия

Разработка по TDD через публичный runner API: положительный связанный review,
неизменность исходного audit, старый v1 refresh, отрицательные и неполные review,
чужая Session/package, исходные отрицательные policy/oracle/calculation.
После GREEN/typecheck и независимого review будет отдельный immutable
execution-lock-r3 с обновлёнными SHA тех же четырёх разрешённых evaluator файлов.
Предыдущий r2 lock и его запущенные attempts остаются неизменными.
Runtime не пересобирается, обработчики узлов не меняются.

До фактического допуска следующая модель не запускается. Next — candidate ROI/2;
успешный Claims/2 повторно не исполняется и не пересчитывается.
