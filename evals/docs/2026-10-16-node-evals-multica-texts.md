Для импорта предложено до трёх автоматических переделок; четвёртый свежий REJECT останавливает карточку для решения Evaler. Для других назначений по умолчанию одна переделка. Этот режим включается только после принятия соответствующего handoff.

Сам заверши и очисти собственные живые запуски по общей процедуре. После обычной очистки и одного неуспешного штатного восстановления выполни заранее одобренный и проверенный сброс с допуском нового экземпляра. Если недостаёт прав — через Evaler привлеки названного в рецепте оператора только к недоступному шагу. Сначала архив истории и БД вместе с WAL/SHM, проверка архива и границ выделенной среды; затем пересоздание из закреплённого образа и автоматическая готовность без модели. Не снимай захват по времени/мёртвому PID, не расширяй kill/rm, не объявляй неизвестное чистым. Прежние lease и ERROR сохраняются; новый FREE не делает старый продуктовый результат успешным.

Причину неисправности и операторский код внутри карточки не расследуй и не разрабатывай. Для этого сохрани доказательства и верни конкретный BLOCKED Evaler; разработка идёт отдельно. ACCEPT возможен только после всех проверок и подтверждения свободы и исправности стенда. Если качество проверено, а очистка нет, итог — BLOCKED с отдельным описанием результата проверки качества.

Опубликуй один обычный итоговый комментарий с parent текущего поручения: VERDICT_BEN: ACCEPT|REJECT|BLOCKED, SHA, собственный расчёт, полный набор замечаний, команды, доказательства и итоговое состояние стенда. Не меняй статусы, assignee или evaler.state, не поручай Rich исправления напрямую; после отчёта заверши ход. Обновление инструкций не разрешает запуск.
