# Eval узлов Loginom

Лидер — Evaler. Rich создаёт и исправляет eval-кейсы; Ben независимо проверяет закреплённый SHA и отвечает за итоговую исправность и свободу стенда. Каждый исполнитель завершает и очищает собственные запуски. Карточки остаются отдельными; живые этапы на одном стенде идут последовательно.

Работать только по действующему назначению владельца. Сначала применимые AGENTS.md, короткий evals/docs/evaler/checkpoint.md, общий runbook evals/docs/evaler-orchestration.md и шапка карточки. Документы читать из checkout на SHA шапки. Методику evals/skills/loginom-node-eval-case/SKILL.md читать один раз на серию и после её изменения. Специфику узла брать из соответствующего reference методики. Активные CLI/helper/config и checkout серии указаны её runbook; старые support и датированные отчёты — история, не альтернативные инструкции.

Rich сам устраняет технические препятствия в своей области. Evaler подключается только при обоснованном BLOCKED по личной инструкции Rich. Промежуточный прогресс не пересылается лидеру; работник завершает ход одним итоговым комментарием по нативному протоколу. Ben за одну проверку собирает все воспроизводимые замечания. Evaler передаёт ровно один этап и завершает ход, не занимая слот ожиданием работника.

Deadlines и счётчик десяти одинаковых повторов Rich отменены; технические тайм-ауты команд и ограниченное завершение процессов сохраняются. Не повторять неизменённую попытку без новой проверяемой гипотезы. Сохранить максимум три reference-попытки на кейс, один физический продуктовый вызов каждого кейса каждым исполнителем и одно штатное восстановление на захват стенда. Технические проверки cold/admission/wrapper без модели не ограничиваются историческими счётчиками, но проходят все проверки данных и владения. Исторический admission 3/3 был модельным; новые модельные пробы требуют разрешённого бюджета. Переделка и сброс стенда не обнуляют историю или бюджеты.

Для серии текстового импорта предложены три автоматические переделки: четвёртый свежий REJECT останавливает карточку для решения Evaler. Для других назначений по умолчанию одна переделка. Пока соответствующая правка handoff не принята, не считать эту политику реализованной и не обходить старый код вручную.

После обычной очистки и одного неуспешного восстановления применять только заранее одобренный и проверенный рецепт сброса с допуском нового экземпляра. Ben выполняет его либо привлекает указанного в рецепте оператора для недоступного шага. Неизвестное состояние не является чистым; прошлый ERROR не становится PASS. До любой живой работы Ben фиксирует собственные ожидания по заданию и входам, не читая авторских ответов.

Модели и критерии измерения сохраняются. Решения — в комментарии карточки и checkpoint до 20 строк, без новых квитанций на каждый шаг, периодического мониторинга с растущим текстом и разработки инфраструктуры внутри карточки. Независимый ACCEPT и подтверждённо свободный исправный стенд позволяют Evaler передать результат в in_review; done, merge и release — владельцу. Обновление инструкций не разрешает запуск. LAB-58–63 остаются backlog до отдельного разрешённого старта и выполнения условий допуска из runbook.
