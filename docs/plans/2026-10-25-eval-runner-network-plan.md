# Устойчивый вход на runner3 после простоя

**Результат:** EvalOps входит на прежний runner3 из своего runtime после простоя, устанавливает уже принятый harness и продолжает LAB-170 штатными командами. Результаты, leases, pins, бюджет и срок сохраняются. Полная автономность исходной LAB-170 этим ремонтом не подтверждается.

**Основание:** native SSH неоднократно отказывает до remote dispatch; проверки через отдельный исходящий SSH с host на runner2 проходят. На host runner3 маршрут к runner2 идёт через `wg0`; единственный существующий peer имеет выключенный persistent keepalive и в live state, и в `/etc/wireguard/wg0.conf`. После простоя handshake старше десяти минут. Потеря NAT mapping — проверяемая гипотеза, не установленная причина. Предыдущий capture не пересёкся с native подключением и ничего о месте потери не доказал. Материалы — private `preparation-accounting/host-wg-*-readonly.json` и `native-ssh-correlated-assessment.json`.

WireGuard [рекомендует keepalive для входящих соединений за NAT после простоя](https://www.wireguard.com/quickstart/#nat-and-firewall-traversal-persistence); штатный интервал — 25 секунд. Это свойство существующего client peer, без нового туннеля, службы или изменения удалённого VPN-сервера. Цена — служебные пакеты во время простоя; расходов измерений нет.

**Область:** client peer на host выделенной runner3 VM, один параметр в существующем config и live state; этот план и краткий owning checkpoint. Оценка: 3 файла, около 45 изменённых строк с документацией. До изменения проверить владельца config и самостоятельность этой настройки. Общие маршруты, ключи, endpoint, allowed IPs, SSH auth/host-key и чужие процессы не меняются; интерфейс не опускается и службы не перезапускаются. Если для ремонта необходимы изменения чужой инфраструктуры или текущих сетевых контрактов, это отдельное решение владельца.

1. [x] **Сопоставить отказ и исходящий трафик.** Использовать уже сохранённый native timeout как исходный отказ; независимая штатная read-only сверка runner2 создаёт исходящий WireGuard-трафик. Сверить время и свежий native вход, не называя единичный успех доказательством причины. Проверяемый результат — конкретные UTC/исходы и актуальный владелец config; если keepalive уже включён, не менять его.
2. [x] **Применить одну штатную настройку после независимого ревью.** Сохранить root-private точную копию config. Для того же peer включить `PersistentKeepalive = 25` в config и live `wg set`, без restart/down/up. Сверить отсутствие иных изменений, права/владельца config и live значение 25. При ошибке восстановить исходный config и прежнее значение, не трогая маршруты. Проверяемый результат — только один изменённый параметр либо точный rollback.
3. Здоровый batch принять под управление. Не повторять неизвестный исход команды и готовые измерения. Первый результат — подтверждённый native вход и новые admissions только missing либо точный следующий блокер.
4. [ ] **Проверить сохранение доступа после простоя.** Следующее штатное пробуждение EvalOps должно войти без исходящего SSH/пробы Codex между проверками; использовать существующие события. Сверить прежние результаты и срок, записать итог в checkpoint. Если отказ сохраняется, гипотезу не считать подтверждённой; не строить fallback/монитор и не менять соседние настройки. Отдельно решить по evidence, сохранять ли25 для требуемого входящего доступа или вернуть исходное значение.
