# Rebase autonomous-evals на текущий loginom

**Результат:** локальная ветка `autonomous-evals` основана на зафиксированном текущем `loginom`; её нужные изменения сохранены, конфликты разрешены по действующим контрактам, проверки evals проходят. Push и поставка на серверы не входят в задачу.

**Сохранность:** завершить уже подготовленный checkpoint отдельным commit; сохранить старый tip в отдельном backup ref. Старые принятые SHA, pins и исторические доказательства не переписывать: развёрнутые runner checkout остаются на своих SHA. Нативные задачи Multica продолжаются независимо; Git-операция не управляет их сессиями или процессами.

**Первый проверяемый результат:** clean worktree, backup ref совпадает со старым tip и зафиксирован точный target loginom. Есть значительное пересечение evals с upstream. Patch-equivalent commits сначала различить через git cherry, а не считать потерянными.

**Размер:** этот документ≈15строк; существующие изменения переносятся Git. Конфликты пока неизвестны; ориентир≤10файлов/200строк ручного разрешения. При существенно большем объёме пересмотреть способ, сохранив требование rebase. Новые production-механизмы, тестовые frameworks и изменения эксперимента исключены.

1. [ ] Независимо проверить этот короткий план; сохранить checkpoint, pinned target и backup ref. Результат — восстановимая исходная ветка без незакоммиченных изменений.
2. [ ] Выполнить обычный rebase на pinned loginom. До первого разрешения прочитать target AGENTS/owning contracts; конфликты сравнивать с обеими исходными версиями, сохранять нужные upstream и autonomous изменения. Не использовать массовое ours/theirs. Результат — завершённый rebase без unmerged entries.
3. [ ] Проверить ancestor, clean status, range-diff/patch-equivalence и итоговый diff на потерянные изменения. Прочитать изменившиеся применимые AGENTS. Из evals выполнить bun typecheck и штатный test script с прежними Bun/Node; live/proc-denial флаги не включать. Независимо проверить разрешённые конфликты, если они были. Результат — прошедшие проверки либо конкретный воспроизводимый блокер; принятые deployment SHA остаются доступны через backup.

Checkpoint: план подготовлен, rebase не начат. Точные refs и результаты будут в private rebase evidence; сведения, доступные из Git, здесь не дублируются.
