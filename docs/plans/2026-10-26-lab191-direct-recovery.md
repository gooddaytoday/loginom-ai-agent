Прямое вмешательство не доказывает автономность EvalOps. Этот план заменяет ближайший recovery-шаг прежнего плана, не меняя эксперимент.

**Результат этапа:** настоящий batch начал измерения в N=6, служба кампании продолжает работу; опубликованы время старта, batch ID, число активных слотов и состояние результатов. Отдельные модули, SHA и тесты этим результатом не являются.

**Границы:** официальный CLI0.3.3, все78 keys, `openai/gpt-6.1-sol/medium`, judge `gpt-6-sol/xhigh`, бюджеты и исходный clock сохраняются. Старые кампании, их ресурсы, агенты/runtime и выключенный VPN не меняются. Перезагрузка хоста не разрешена. Готовые измерения, включая quality FAIL, повторять нельзя.

1. **Единственный оператор.** Отменить только running/queued задачи LAB-191, временно выключить его два wakeup, проверить терминальные состояния и отсутствие конкурирующих процессов. Прочитать server/config/manifest/journal/claims. Проверяемый результат: batches/attempts0, служба не работает, семь новых retained и семь старых сохранены; нет конкурирующего ремонта.
2. **Подтверждённая очистка.** Штатный `reconcileEnvironment` не принимает failed standalone management без первоначального unitBinding. Исчезновение PID не заменяет proof. Использовать подходящие части сохранённого draft для разового root-наблюдения и узкого native consumer: подлинный root-owned proof, точные исходные bytes/owner/boot, controller lock и прежние matching leases. Затем существующие archive/session/storage/release. Исходные receipts не переписывать; флаги/блокировки вручную не снимать. Проверяемый результат: новые native cleanup/release receipts подтверждены, исходные failed bytes и старые retained неизменны.
   Перед кодом проверить достижимость наблюдения на фактическом host state. В draft отказ по всем post-cutoff TGID затрагивает новые kernel threads: их следует отличать по достоверному kernel flag, а не UID/имени. Старые userspace lineage и неоднозначные записи по-прежнему дают отказ. Запуск observer — отдельный root systemd oneshot после закрытия SSH; его исключение связано с этим invocation, а не с ancestry вызывающего процесса.
   Не добавлять новый scheduler, постоянный supervisor, универсальный repair API или новые политики. Не включать draft-ветки для других видов отказов: текущие admin connection receipts уже confirmed; неисправен management cleanup слота a. Обычный prepare не должен автоматически доверять административному proof.
3. **Минимальный исправленный кандидат.** Реализацию делает Codex. RED→GREEN для фактического блокера/изменений, typecheck и затронутые regression tests из evals; уже действующие результаты baseline переиспользовать. Отдельно проверить родные режимы файлов: не чинить production privacy из-за fixture/umask. Одно независимое ревью полного кода и конкретной поставки до применения. Проверяемый результат: принятый кандидат с известным diff; никакой подделки continuous observation, writer или прежнего unitBinding.
4. **N6 и запуск.** Самостоятельно поставить принятый harness, выполнить разовую процедуру и проверить release. Установить уже полученный OAuth seed только после cleanup, сохранив principal. Затем штатно запустить постоянную службу кампании. Проверяемый результат: measurement admission, перекрывающаяся работа шести слотов, batch ID и время; нет дублирующего запуска.
5. **Штатный цикл под контролем Codex.** Лично проверить journal/results, процессы и службу, сохранить краткий checkpoint. Будильники LAB-191 остаются выключенными при прямом владении Codex; другим агентам допускается только независимое ревью. Проверяемый результат: служба работает и выбирает missing, управляющие процессы не конкурируют. Ближайший этап не заменяет полное завершение78 в активной цели.
