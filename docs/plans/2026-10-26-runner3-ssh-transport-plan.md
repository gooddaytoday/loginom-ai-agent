# Штатный SSH-доступ к runner3 через runner2

**Цель:** вернуть EvalOps устойчивый доступ к прежней VM, чтобы закончить очистку и продолжить LAB-170 только по missing. Runtime, сервер кампании, experiment pins, Results/history и срок не меняются. Внешнее восстановление не доказывает автономность исходной LAB-170.

**Почему нужен ремонт:** многократные native TCP timeout происходят до dispatch; последний подтверждён06:13UTC. Прямой host→runner2 SSH работает, в том числе непрерывно20мин. По paired capture место потери не установлено; доказанной адресной правки route/firewall нет. Новые захваты, повторы keepalive-гипотезы и изменения общего VPN не нужны.

**Новая среда и решение владельца:** с26.10 host в офисной LAN10.150.1.230/22, прямой routeR2 через10.150.0.1; wg0 отсутствует. Владелец указал оставить VPN выключенным. QEMU всё ещё слушает собственный прежний172.16.0.29:2223, но адрес больше не local. До forwarding нужен только этот /32 на host loopback (`ip address replace 172.16.0.29/32 dev lo`); это локальная принадлежность прежнего адреса, не WireGuard, peer или маршрут офисной подсети. Его ownership подтверждён прежним собственным wg0 config и live QEMU listener. Никакие другие адреса, VPN/config/keys/routes не меняются.

**Выбор:** стандартный reverse forwarding OpenSSH: host VM устанавливает SSH на runner2 и слушает там **только127.0.0.1:2224**, перенаправляя байты к существующему `172.16.0.29:2223` на host. Это прежний SSH гостя с прежним host key и auth, без proxy application, переноса batch или runtime. Подтверждены AllowTcpForwarding=yes, GatewayPorts=no и свободный порт2224; исходный alias `eval-runner-3` имеет собственный HostKeyAlias/known_hosts. Неизвестная занятость перед effect означает STOP.

**Механизм / цена:** сначала один временный SSH с timeout120с, без смены alias. Только при успешном настоящем SSH гостя — один systemd unit для того же OpenSSH с Restart=always/RestartSec30, ServerAliveInterval15/CountMax3 и ExitOnForwardFailure=yes. Это восстановление одного нужного транспорта; scheduler, port discovery, watchdog и retry framework не добавляются. Пароль только в root-private credential вне Git и через systemd LoadCredential/sshpass -f; не argv/env/log. Host key runner2 проверяется существующим known_hosts. На runner2 меняются только HostName/Port одного собственного alias; HostKeyAlias, user и known_hosts прежние.

**Изменения:** новый transport template≈24строки, VM template≈3строки, этот план≈35строк и два owning checkpoint≈4строки; ожидаемо5файлов/~75строк по git diff --stat. Из собственного VM unit убрать зависимость Wants/After от wg0; idempotent root ExecStartPre добавляет только собственный /32 наlo **до QEMU bind**. Transport имеет After/Wants VM. Для уже работающей VM при первой поставке тот же /32 добавляется отдельно, без restart/PID change; дальнейший start VM использует ExecStartPre. Вне Git — transport unit/credential и собственный loopback /32 на host, dependency-only обновление VM unit и две строки alias на runner2. Новая VM, пользователь, SSH key, grant, sshd policy и firewall не нужны.

## Остановка и откат
- Listener collision, host-key mismatch, foreign alias drift или неизвестный active job — STOP без kill чужих процессов/обхода проверки. `ExitOnForwardFailure` означает только успех привязки, не готовность гостя; её доказывает шаг2/штатная команда.
- При отказе постоянной поставки вернуть exact исходные две строки alias при совпадении own installed hash, disable/stop только свой unit и удалить только собственный добавленный loopback /32; private credential удалить только после остановки своего процесса. VM, кампанию, ресурсы и Results не трогать.
- После потери сети старый remote listener может жить до TCP/sshd cleanup; фиксированный порт намеренно не обходится новым портом и чужой listener не убивается. Зафиксировать ограничение и ждать штатного освобождения в прежний срок; не выдавать local process restart за полную сетевую аварийную приёмку.
- Завершение плана — native доступ через поддерживаемый systemd транспорт и его ограниченный restart proof. Это не cleanup, не финал234 и не доказательство причины прежней сетевой потери. Срок и partial policy LAB-170 прежние.

Checkpoint: первоначальный reverseSSH план ACCEPT, но после фактической смены среды выявлен отсутствующий local target. Владелец подтвердил VPN OFF; офисная поправка /32+VM dependency независимо ACCEPT (`runner3-ssh-transport-plan-v2-independent-review.json`). Effects не начаты; следующий шаг — fresh no-conflict guard и один E2E. Read-only preflight — private `preparation-accounting/reverse-ssh-preflight-r2-readonly.json`; прежняя trace — `2026-10-26-eval-runner-packet-path-plan.md`. Остальное восстановление принадлежит EvalOps и адресному плану c3.
