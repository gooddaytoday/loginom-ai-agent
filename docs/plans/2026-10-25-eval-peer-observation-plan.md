# Независимая очистка здорового слота при недоступном peer

> Исполнение по `executing-plans` и TDD: один публичный RED → минимальная правка → GREEN. До изменения кода — независимое ревью плана.

**Цель:** недоступный процесс слота B с читаемой чужой ancestry не мешает подтверждённой очистке здорового A. Недоступный собственный процесс B по-прежнему оставляет B в карантине.

**Основание:** пп.21–24 `evals/docs/parallel-users-contract.md` и обязательное P2 итогового независимого native review, `/home/george/.codex/tmp/preparation-accounting/final-native-review.json`. Существующий opt-in тест ошибочно требует failed у обоих слотов; это не новое правило эксперимента.

**Причина:** `scan` передаёт в `snapshot` origin entries всех `liveSupervisors`. При EACCES/EPERM `hasOwnedAncestry` поэтому считает процесс B своим также для A. Сам kernel ancestry читается и однозначно отличает B от A.

**Правка:** передавать в проверку недоступности только собственные origin entries `ledger`. Общий registry остаётся для исключения читаемых peers; недоступный peer не получает свежий claim. Не менять snapshot/ancestry алгоритм, signal authority, treatment неизвестной ancestry, бюджеты teardown, профильные или native lease guards. Нового механизма нет.

**Область и стоимость:** `evals/src/process-supervisor.ts`, существующий тест `evals/test/process-supervisor.test.ts`, этот план и краткий owning checkpoint. Около5 файлов/50 изменённых строк, включая документацию. Все callers `snapshot` прочитаны: startup baseline, native post-exit и scan; меняется только scan. Результаты/manifest/pins/failed receipts/runtime/агенты/серверы не меняются в этой локальной правке.
