# Branch Cleaner

Branch Cleaner очищает заданную ветку и пересобирает её локальную историю в
логические коммиты. Он сохраняет причины действующих решений, ограничения,
полезные тесты и свидетельства реально проведённых проверок. Старая история
остаётся в резервной ссылке и проверенном bundle вне репозитория.

## Вызов

Codex:

```text
$branch-cleaner Очисти ветку feature относительно origin/dev в текущем репозитории.
```

Claude Code:

```text
/branch-cleaner Очисти ветку feature относительно origin/dev в текущем репозитории.
```

Для проверки без изменений добавьте «только аудит». База в примерах искусственная:
указывайте реальную базу нужной ветки. Если ветка не опубликована, удалённый агент
Multica должен сначала получить доступ к её Git-объектам через разрешённый
checkout или bundle; локальная ветка компьютера не появляется на runtime сама.

Команда запускает отдельного подагента. В Codex родитель передаёт только задание,
важные ограничения и путь к роли; историю разговора не копирует. Claude запускает
команду в собственном контексте через `context: fork`. Внутренние навыки читаются
только на нужном этапе; их полные тексты не входят в обычный контекст.

Агент фиксирует базу и исходный tip, работает в отдельном worktree и проверяет
очищенное дерево до реконструкции истории. Новая история линейная; полезные
merge resolutions и авторский вклад сохраняются. Проверяются все новые коммиты,
а не только итоговый diff. После проверок заменяется локальная исходная ветка.
Отправка в remote требует отдельного поручения.

При грязном рабочем каталоге, изменившейся ветке или конфликте переключения агент
сохраняет подготовленный результат и сообщает, как продолжить или восстановиться.
Он не прячет чужие изменения через stash и не сбрасывает их принудительно.

## Проектная и глобальная копии

Коллегам достаточно checkout с проектными командами и комплектом
`.agents/branch-cleaner/`. В уже открытой сессии может потребоваться перезапуск
для перечитывания каталога навыков. Проектный комплект имеет приоритет перед
глобальным даже при вызове глобальной команды из подкаталога проекта.

Для персональной установки скопируйте из корня этого checkout три каталога:

```sh
mkdir -p "$HOME/.agents/branch-cleaner" "$HOME/.agents/skills/branch-cleaner" \
  "$HOME/.claude/skills/branch-cleaner"
cp -R .agents/branch-cleaner/. "$HOME/.agents/branch-cleaner/"
cp -R .agents/skills/branch-cleaner/. "$HOME/.agents/skills/branch-cleaner/"
cp -R .claude/skills/branch-cleaner/. "$HOME/.claude/skills/branch-cleaner/"
```

При обновлении заменяйте эти же три копии целиком содержимым одного checkout;
не смешивайте версии роли и навыков. Общую конфигурацию Codex/Claude и другие
установленные навыки менять не требуется. Автоматического обновления нет.

Внутри комплекта находятся `AGENT.md` и три навыка: `design-cleanup`,
`harmonize-docs`, `branch-history-rewrite`. Прежние отдельные команды первых двух
навыков перенесены внутрь агента. Guide для архитектурной документации сохранён
рядом с `harmonize-docs` и читается только при работе с такой документацией.

## Multica

Агент создаётся на явно выбранном пользователем runtime после проверки права
его использования. Ему назначаются копии тех же трёх навыков вместе с используемыми
ресурсами, ограничение одной задачи и приватный доступ. Полные тексты навыков не
вклеиваются в роль. Правила, расписания и squad для запуска не создаются.

Рабочий каталог каждой задачи отделён от eval-процессов. Поручение задаёт
репозиторий, ветку и базу; отсутствие объектов или доступа останавливает работу
с конкретной причиной, без подмены ветки или runtime.

Фактические проверки установки и ограничения записаны в
[плане реализации](superpowers/plans/2026-11-16-branch-cleaner.md).
