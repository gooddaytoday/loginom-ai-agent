# Разработка узлов Loginom AI Agent

Актуальные технические требования: [RUNBOOK](RUNBOOK.md). Этот каталог содержит подпланы, данные и независимые ожидания, техническую приёмку и подтверждённую историю клиента. Управление задачами и настройка среды находятся в операционном репозитории.

- [Реестр](registry.json) и [обзор](inventory.md) описывают реализацию и точные пределы готовности.
- [Подпланы](workflow/new-node-plan.md) определяют отдельные режимы; наличие плана не назначает повторную разработку.
- [Полная очередь](roadmap.md) связывает 78 узлов с этапами, зависимостями и условиями среды.
- [Карта покрытия](coverage-map.json) сопоставляет документированные возможности с подпланами и проверками; она отделена от готовности runtime.
- [Параллельная работа в Multica](workflow/multica-parallel.md) и [карта назначений](parallel-execution.json) разделяют независимую разработку, общие контракты, интеграцию и приёмку. Предлагаемые лимиты не означают, что сервер настроен.
- [Проверки документации](validation.md) и [точка продолжения](coverage-checkpoint.md) фиксируют результат подготовки полного покрытия.
- [CLI-приёмка](workflow/acceptance-cli.md) проверяет сохранённый пакет независимым oracle.
- [История](history/README.md) и [происхождение](provenance.json) сохраняют источники и SHA.

Назначение владельца, текущий код и наблюдаемое состояние имеют приоритет над историей. Нельзя переносить PASS на другой SHA, платформу или режим. `source_commit` означает ревизию исходников; checksum документа не доказывает выполнение теста.

Эксплуатационные инструкции Paperclip перенесены в исторический раздел операционного репозитория `swarm` (`ops/loginom-multica/history/paperclip`). Они не являются текущими техническими требованиями.
