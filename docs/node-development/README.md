# Разработка узлов Loginom AI Agent

Актуальный регламент на 24 сентября 2026. Он заменяет инструкции запуска потоков
через Hermes и плагины Codex из исторического Dock. Разработчик может работать
в Codex; сценарий при автономной приёмке строит **standalone CLI Loginom AI Agent**.
Слово «обучение узла» здесь означает разработку и проверку обработчика интерфейса.
Обучение статистической модели внутри Loginom — отдельное свойство конкретного узла.

## Что считается источником истины

Общие правила находятся в `workflow/`. Для каждого документированного узла
`nodes/<slug>/README.md` показывает готовность и ограничения, а соседний `plan.md`
содержит предметный подплан. Подпланы готовых режимов служат основой сопровождения;
само наличие документа не назначает повторную разработку. Кросс-таблица имеет
отдельный подплан со статусом исследования. Остальным компонентам подпланы
создаются по мере назначения.

1. Текущее назначение пользователя и правила активного репозитория.
2. Наблюдаемое состояние и код закреплённого candidate.
3. Подтверждения реестра с версиями, платформой и границами проверки.
4. Исторические подпланы и память как справочные материалы.

`registry.json` — единственный источник сводных чисел и состояний готовности в этом
комплекте; `inventory.md` генерируется. Реестр не управляет процессами. Очередь,
владельцы, события и занятые ресурсы находятся в приватном состоянии кампании.
Смена parallel/sequential не меняет готовность обработчика.

В доказательствах `source_commit` означает Git-ревизию, `runtime` — закреплённую
версию или hash проверенного исполнения, `sha256` — hash документа по текущей
ссылке. Для адаптированной истории `source_sha256` закрепляет оригинал из ZIP,
а `adapted_sha256` в provenance — новую навигационную копию. Отсутствующее значение не означает проверку на текущем HEAD: для
исторического документа ревизия могла не сохраниться, а для каталога платформа
не применима. Точные пределы указаны в `scope` и самом источнике.

Каталог компонентов — исторический снимок, а не повторный осмотр всех редакций
Loginom. У нового клиента имеются технические Desktop-проверки; они не объявляются
проверкой аналитической правильности и не заменяют целевую CLI-приёмку.

## Принятые настройки

- База кампании — проверенный commit продуктовой ветки `loginom`, не автоматически текущий HEAD.
- До четырёх разработчиков Astra medium; один итоговый CLI-прогон Sol low через имеющуюся подписку ChatGPT.
- Одна задача/worktree/ветка на узел. Продолжение только внутри разрешённой очереди;
  single заканчивается на одном узле. Слияние и публикация — отдельно.
- Один этап ревью в задаче разработчика, один раунд исправлений и адресная проверка;
  это не независимое ревью другим агентом.
- Для будущих worktrees установлен [механизм регистрации нового проекта](../../services/loginom-ai/tools/project-memory/CURRENT.md)
  поколения `20260924.1`. **[Полный цикл чтения и записи проверен](workflow/shared-memory.md).**
  Каждый worktree получает отдельный допуск; исходники механизма не заменяют
  [проверку фактического доступа](workflow/lifecycle.md).
- Этот комплект сам по себе **не запускает очередь** и не меняет установленные клиенты.

## Проверка и архивирование

Из корня `loginom-ai-agent`:

```sh
python3 docs/node-development/tools/validate.py --render
python3 docs/node-development/tools/validate.py
python3 docs/node-development/tools/package.py
```

Последняя команда создаёт новый ZIP, manifest/SHA256 и проверенную распакованную
копию в `~/Backups/loginom-node-development/`; существующие архивы не заменяет.
Неизменённые оригиналы сохраняются в исходном ZIP вне Git; его имя и SHA256 есть
в [provenance.json](provenance.json). Для их повторной проверки передать
`validate.py --source-archive <путь к исходному ZIP>`. История в репозитории
адаптирована для навигации: уже перенесённые материалы переиспользуются,
отличающиеся версии находятся в `history/supplements/`. Исторические JSON
ссылаются на [исходные идентичности](history/references.json), чтобы прежний hash
не приписывался текущему коду. [Неперенесённые материалы](history/unavailable.md)
обозначены явно. Код и внешние доказательства,
не входящие в документационный архив, перечисляются отдельно. Это архив знаний,
а не установочный комплект или резервная копия runtime.
