`acceptance/proposed-reference.md` — проект замены существующего файла узла.

Для воспроизведения: импортировать `node-api.mjs`, `node-contracts.mjs` и
`filter-node.mjs` закреплённым Node из существующего cache run-check, без
сборки. Размер базы — `Buffer.byteLength(JSON.stringify(value))`; файлы —
`readFile`/stat. Карточка предложения — JSON из приложенного файла.
В full/apply подставить её `parameter_schema.properties.groups`, сохраняя
остальные поля базы. Для published менять только `value`/`values` на anyOf
старого literal и variable; variable.name использует существующий
`#/$defs/text128`. Description условия берётся из proposal без изменений.
Навык — замена одной строки, без добавления второй маршрутизации фильтра.

## Реализация после решения владельца

Оценка — **2 цикла + 1 резервный**, после принятого W1. Узловой production
дифф 180–280 строк, tests 100–160; это прогноз, а не лимит/готовый результат.
Общая разработка W1, сокращение схемы, её приёмка и независимые 2/3
не включены в узловую оценку. Первая стадия не меняет handler.

Срез небольшой по семантике: выбор scalar-переменной и string-переменной
списка вместо literal. Главный технический риск — восстановить точную
сохранённую ссылку после reopen, когда store показывает имя вместе с текущим
значением. При невозможности решить это аддитивно в filter-ветке остановиться
до общей правки. Решение включить в 0.4.0 принимает владелец по этому предложению.
