# Предложение контракта этапа 1

LAB-822, база `v040@aa49dc7d88b79917b1ba93d721880b155c4f19c9`.
Критерии требуют утверждения; общий контракт W1 здесь не реализуется.

## Калькулятор

`variables.calculator`, режим `expression`, компонент назначения
`component.variables.Calculator`. Создаёт переменные без обязательного входа.
Опциональный вход переменных и выход переменных 0 относятся к W1.
Табличный вход не подставлять вместо переменных.

Новый узел получает 1–32 выражения. Каждое явно задаёт техническое имя,
метку, `integer|real|string|boolean`, native-формулу; описание необязательно.
При обновлении адресовать сохранённое выражение его исходным именем;
пропущенные свойства и неуказанные выражения сохраняются. Безопасно удалить
начальное пустое `Expr1` только при создании полного заданного набора.
Имена ASCII, до 128 символов; неоднозначность/коллизия — отказ до изменения.
Ссылка `Expr.limit` допустима на предыдущее выражение. Перестановка,
замена входных переменных, промежуточные выражения, кэширование, datetime,
Variant и JavaScript исключены из этого этапа.

`NULL` означает типизированное отсутствие, `""` — пустую строку; `0` и FALSE
самостоятельные значения. В схеме присутствует и NULL-переменная.
На выходе сохраняются имена, метки, типы и порядок выражений. При наличии
входа сохранение и положение унаследованных переменных определяет W1;
приёмочный сценарий этапа 1 не требует входного источника переменных.

## Таблица в переменные

`variables.from_table`, режим `aggregate`, компонент назначения
`component.variables.DataToVar`. Один обязательный вход таблицы 0, выход
переменных 0. Это агрегаты, а не автоматический выбор первой строки.

Полное упорядоченное описание 1–16 числовых полей и функций:
`sum|count|min|max|avg`. Внутри поля native-порядок функций фиксирован:
sum, count, min, max, avg; последовательность щелчков его не задаёт.
Порядок нескольких полей ещё требует адресной проверки этапа 1.
`count` включает строки с NULL; прочие функции пропускают NULL.
`sum` и `avg` дают real, `count` — integer, `min/max` сохраняют числовой
тип источника. Один агрегат: имя исходного поля; несколько: наблюдённые
суффиксы `_Sum`, `_Count`, `_Min`, `_Max`, `_Avg`. Метки для fixture X:
`X|Сумма`, `X|Количество`, `X|Минимум`, `X|Максимум`, `X|Среднее`.
Один агрегат, пустой вход и все NULL проверяются отдельными случаями;
их наблюдения и границы приведены в discovery второго узла.
Другие функции, строковые/логические/датовые агрегаты — вне этапа 1.

## Точность и readback

Вещественные значения сравнивать с `abs=1e-12, rel=1e-12`:
`|actual-expected| <= max(abs, rel*|expected|)`. Integer, Boolean, строки,
NULL, имена, типы и порядок — точно. Приёмочные целые лежат внутри
`[-(2^53-1),2^53-1]`; точность больших Int64 этим комплектом не заявляется.
В typed reader W1 нельзя округлять данные по тексту DOM: 0.125 отображается
как 0.13. Неподтверждённое точное чтение должно давать явный отказ.

Компактный configuration readback: `mode`, ordered `expressions` с
name/label/type/formula/description или `fields` с field/aggregations;
identity узла и реальные typed-связи — через принятый контракт W1.
Выход: упорядоченные name/label/type/value, отдельно от настроек.
NULL передаётся JSON null; пустая строка — JSON string длины 0.
Раздельно сообщать сохранение настроек, Execute и чтение значений.
Обучения и обученной модели у обоих узлов в исследованном сценарии нет.

## Приёмка и зависимости

`acceptance/task.md`, `fixtures/`, независимый `acceptance/oracle.py` и
сгенерированный `expected.json` — предложение до модельных прогонов.
У expected явно заданы `port_kind:variables`, `output_port:0`, `ordered:true`
и вещественные tolerance. Это проект данных W1, **не поддерживаемая на базе
схема cold-check**. Не удалять port_kind ради прохождения табличного reader.
Формат expected согласовать с принятым W1 до run-check; механизм проверки
в этой карточке не добавляется. Oracle не использует Loginom или runtime.

Для этапа 1 нужны: typed refs/связи/read/context/cold W1 и его утверждённый
формат expected; затем аддитивная регистрация обоих типов, собственные
обработчики/тесты, разделы навыка, два сценария run-check. Общие правки сверх
согласованного W1 сейчас не обоснованы наблюдённым отказом. Если они
потребуются при реализации, остановиться по условию назначения.

В базе `workspace-ui.mjs` распознаёт `CalcDataWizard`, но не
`CalcVariablesWizard`/`DataToVariablesWizard`. Поэтому табличный калькулятор
нельзя переиспользовать одной заменой type. Планировать собственные
узловые UI-процедуры с проверкой владельца/стадии/элементов и лишь
аддитивные точки подключения. Изменение поведения общей UI-процедуры
этим документом не разрешается. При невозможности локальной реализации
без общей правки — остановка и вопрос до кода.

## Размеры предложения

Счёт — UTF-8, компактный JSON без пробелов; размеры файлов — как в Git.
Тела предложений карточек: Калькулятор 2712 Б, Таблица в переменные 2167 Б,
против лимита 12000 Б. Это содержимое предложения, **не реальный wire-ответ
dock_action_describe**: сессионный envelope/handler metadata добавятся на
этапе 1 и должны быть измерены повторно. Schema не регистрируется на этапе 0.

Файлы разделов навыка: 2041/1857 Б против 6000 Б. Две строки маршрутизации:
120/126 Б; SKILL.md базы 39686 Б, после их добавления 39932 Б против 40000 Б
(запас 68 Б). При добавлении маршрутов не дублировать весь текст карточки.

Текущая полная `nodeApplyInputSchema` — 58948 Б, опубликованная с `$defs`
(`nodeApiTools`, dock_node_apply.inputSchema) — **50099 Б**, превышение
лимита 20000 Б уже на базе на 30099 Б. Замер выполнен импортом модулей базы,
без сборки CLI. Это не gzip; модель видит JSON. Дельта регистрации новых
типов ещё не измерена и общий бюджет здесь не меняется. По назначению
превышение сообщается и не останавливает этап 0.

Критерий этапа 1: сохранённый пакет повторно выполняется в новом профиле;
каждая переменная, её тип, порядок и порт совпадают с независимым oracle;
смена значения/таблицы сохраняет остальные настройки; закрытие и logout
подтверждены. По регламенту: не менее 2 PASS из 3 на одном SHA у исполнителя
и отдельно 2/3 при независимой проверке. Этап 0 таких PASS не заявляет.

Оценка после готового W1: 2–3 цикла на Калькулятор и 2–3 на Таблицу в
переменные, затем самостоятельная приёмка. Не включает разработку W1.
