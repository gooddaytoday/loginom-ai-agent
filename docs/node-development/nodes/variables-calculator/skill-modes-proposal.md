# variables.calculator / expression — предложение LAB-1031

Изменения ниже требуют утверждения критериев и реализации обработчика.
Текущий runtime их не поддерживает. Строка маршрутизации SKILL.md сохраняется.

Для параметров сценария используй variables.calculator, mode=expression;
вход и выход — переменные 0. parameters.expressions задаёт новые выражения
через target:{kind:"new"}, name,label,type,formula. Для обновления используй
target:{kind:"existing",name:"сохранённое_имя"}; пропущенные выражения и
свойства сохраняются. На новом узле замени пустое Expr1 первым выражением.

Типы: integer, real, string, boolean, datetime, variant. Формула — язык
Loginom: TRUE/FALSE, NULL, строки в кавычках. Обращайся к предыдущему
выражению по имени: base+1. Префиксы Expr. и Field. в Loginom 7.4.2
не поддерживаются. Календарная дата с миллисекундами:
EncodeDateTime(2026,11,7,23,59,58,123). Не добавляй UTC-суффикс к civil datetime.
variant сохраняет тип значения; объявленный Variant с целым 7 остаётся Variant,
его значение имеет подтип integer.

intermediate=true оставляет выражение доступным зависимым выражениям,
но исключает его из выходного порта. Предпросмотр показывает промежуточные
выражения тоже: он не доказывает состав выхода. finish=execute, затем
read:{ports:[],variable_ports:[0]}; проверяй полный typed-выход.
NULL, пустая строка, false и 0 различаются; datetime сравнивается с миллисекундами.
Обнови нужное выражение, выполни узел и отдельно сохрани пакет.

Кэш и JavaScript в мастере переменных не обнаружены. Замена входных
переменных и перестановка пока не проверены; не заявляй их поддержку.
