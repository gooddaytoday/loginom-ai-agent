## Значения, порядок, NULL и точность — наблюдено

Созданы восемь выражений в следующем порядке. Первое состояние подтверждено
предпросмотром и выходом переменных после Execute. Обновлённое состояние
подтверждено предпросмотром, затем выполнено и сохранено; отдельное чтение
выхода после второго Execute не проводилось. Native типы из локального store
VariablesForm: 4 integer, 5 string, 1 boolean, 3 real.

| Имя / метка | Тип | Формула | Первое значение | После изменения limit |
|---|---|---|---|---|
| limit / Лимит | integer | `100`, затем `120` | 100 | 120 |
| skip / Пропуск | integer | `0` | 0 | 0 |
| remaining / Осталось | integer | `Expr.limit-Expr.skip` | 100 | 120 |
| title / Заголовок | string | `"Страница"` | Страница | Страница |
| enabled / Включено | boolean | `TRUE` | true | true |
| ratio / Доля | real | `1/8` | 0.125 | 0.125 |
| empty / Пустая строка | string | `""` | пустая строка | пустая строка |
| missing / Нет значения | integer | `NULL` | NULL | NULL |

Непустое выражение можно изменить без перенастройки зависимого выражения.
Порядок ровно совпал с порядком добавления; в данном случае входных
переменных нет. В `CalcVariablesPreviewForm;grdVars` локальные поля
0/1/2/3 — имя, метка, значение, тип. У `ratio` число 0.125, хотя DOM
`headercontainer;2_5` показывает **0.13**. У `empty` значение `""`, у
`missing` — null, хотя обе клетки DOM пустые.

После Execute прямой двойной щелчок по `Output_Var-0` открывает
`ModelForm;PreviewWindow;PreviewForm;VariablesForm;grdValuePreview`.
Его локальный store содержит Name/DisplayName/DataType/ValueVariant;
чтение привязывать к конкретному своему узлу/порту и полной коллекции.
Это наблюдение поверхности будущего W1; собственный typed reader не добавлен.

## Отказ и lifecycle — наблюдено

Для `100+` переход «Далее» показал `WizrdMCF;btnError` («Подробнее…»).
Причина в `msgbox;cnt;cnt;MessagesView`:
«Ошибка разбора выражения \"Лимит\" / 1. Неправильное выражение: \"100+\"».
После исправления на `100` переход и предпросмотр успешны. Мастер допускает
«Всё равно далее» — обработчик не должен обходить выявленную ошибку.

Done сохраняет настройки узла; Execute вычисляет значения. При повторной
настройке активного узла появляется подтверждение его деактивации.
Обученная модель для исследованного сценария не требуется; отдельный
режим train/apply не предлагается. Пакет сохранён штатными Save As/Save.
Штатный cleanup подтвердил `package_closed=true`, `logged_out=true`;
контекст браузера закрыт. Пакет исследования оставлен в собственном каталоге.
