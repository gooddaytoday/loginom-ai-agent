## 0. Назначение

Только назначенная карточка и её пара аккаунтов; отчёт одним комментарием.
Стенд — `https://app.loginom.ai/app/?testable=true`, действия по data-tid.
Модель будущей приёмки `openai/gpt-6.1-sol`, medium, 1800 с; прогоны только
через run-check start/wait. Этап 0 выполняется без сборки CLI и без runtime-кода.

Стоп по карточке: компонента нет; нужна несогласованная общая правка;
нужен режим вне объёма либо критерий сверх назначения. Превышение измеренных
model-visible бюджетов в этапе 0 фиксируется в отчёте, не меняет лимиты.

## 1. Подтверждённый результат этапа 0

Компонент присутствует. Fulltype Engine `TBGCalcVariables`; мастер
CalcVariablesWizard и DoneWizard; необязательный вход переменных,
выход переменных 0. Без входа созданы типизированные константы и выражения.
Порядок восьми переменных сохранён, `NULL` и пустая строка различаются.
`Expr.limit-Expr.skip` пересчиталось 100→120 при смене limit 100→120.
Вещественное значение 0.125 форматируется UI как 0.13 — требуется typed W1.
Отказ синтаксиса прочитан через btnError; исправленная формула успешна.
Сохранение собственного пакета подтверждено; cold-приёмка не проводилась.

## 2. Предлагаемый этап 1 — параметры сценария

- `r01`: создать ordered-набор integer/string/boolean/real с именем,
  меткой, формулой и необязательным описанием без обязательного источника.
- `r02`: изменить существующий limit, сохранить прочие выражения/порядок,
  пересчитать зависимое remaining и прочитать полный исходный выход переменных.
- `r03`: сохранить пакет и подтвердить свежий результат при холодном открытии
  по принятому W1; NULL/пустая строка/false/0 не смешиваются.

Приёмочный набор: limit=100, skip=0, remaining=100, title=Страница,
enabled=true, ratio=0.125, empty="", missing=NULL; после изменения
limit=120, remaining=120. Типы и метки заданы в expected.
Порядок точный; real abs/rel=1e-12; остальные значения точные.

Новый node handler, параметры/процедура/context/readback и адресные тесты;
аддитивная регистрация, собственный раздел навыка и сценарий run-check.
Образцы: `calculator-node.mjs`, `calculator-parameters.mjs`,
`crosstable-variables.mjs`; табличные связи из образца не переносить.
Описание каждого поля и semantics подготовлены в node-card-proposal.json.
Реальная карточка и compact apply повторно измеряются после регистрации.

## 3. W1 и пределы

W1 — typed refs/связи/чтение переменных и независимая cold-приёмка именно
исходного порта. Формат expected с port_kind:variables — предложение,
не принимается текущим табличным cold-check. Согласовать с W1 до запуска;
новый механизм проверки в этом подплане не реализуется.

Непроверенные/последующие возможности: входные переменные и коллизии,
перестановка, промежуточные и заменяющие выражения, lazy-вычисление,
полный редактор функций, datetime/Variant, точный Int64 около 2^53.
Не включать их неявно в раннее назначение.

## 4. Проверки и продолжение

Oracle независим от Loginom: `python3 acceptance/oracle.py --check`
из каталога узла. Значения oracle/expected не передавать модели.
По изменённым путям этапа 1 — required-checks list/verify; клиентские
изменения требуют полного client с закреплённым Chromium под nice -n 19.
Сначала наблюдение, затем red→green в production-ветке, далее run-check.
Условие приёмки: ≥2/3 PASS на одном SHA и отдельно ≥2/3 независимой проверки,
Save/cold/close/logout и точные значения/типы/порт по W1.

На этапе 0 проверяются документы, JSON, воспроизводимость oracle и бюджет.
Модельные прогоны, runtime red→green и cold — not_checked, до этапа 1.
Оценка реализации после W1: 2–3 цикла плюс самостоятельная приёмка.
