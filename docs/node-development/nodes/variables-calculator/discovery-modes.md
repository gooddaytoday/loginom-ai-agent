## Стоп-условие и состояние комплекта

В `CalcVariablesWizard` не обнаружен переключатель JavaScript; в
`ExprEditForm` отсутствует настройка кэша. В локальных записях выражений
присутствуют Intermediate, Replaced, Active, но нет Cached.
В наблюдённом диалоге свойств есть только имя, метка, тип данных,
«Промежуточное» и описание. btnCalcMode и chbCached, известные для
табличного Калькулятора, не являются наблюдёнными элементами этого мастера.
Это ограниченный вывод о поверхности UI данной версии, не доказательство
отсутствия возможностей в других версиях или компонентах.

По условию карточки «режима нет в UI» исследование остановлено, статус blocked.
Нужно решение владельца об исключении кэша/JavaScript из матрицы этого узла
и продолжении оставшегося объёма. Новые критерии ещё не утверждены.
Ни один из дополнительных режимов не объявляется поддержанным runtime.

## Предпросмотр и исходный выход после Execute

Fixture создан до проверки значений. В предпросмотре четыре выражения:
report_date, mixed, base, total. После Execute открыт исходный Output_Var-0,
`ModelForm;PreviewWindow;PreviewForm;VariablesForm;grdValuePreview`.
Локальный store содержит ровно три переменные в таком порядке:

| Имя / метка | Native тип | ValueVariant |
|---|---:|---|
| report_date / Дата отчёта | 2 (datetime) | civil `2026-11-07T23:59:58.123` |
| mixed / Разное | 6 (variant) | число 7 |
| total / Итого | 4 (integer) | число 3 |

base имеет Intermediate=true и участвует в формуле, но отсутствует в выходе.
Это отличие от предпросмотра; полнота выхода не доказывается списком preview.
Дата в UI форматируется без секунд; Date в браузере сериализуется как
`2026-11-08T04:59:58.123Z` при локальном UTC−05. Для ожидания нужна исходная
календарная дата с миллисекундами, без часового преобразования.
Variant с числом 7 не превращается в объявленный integer. Другие подтипы
Variant, NULL и смена подтипа в этом исследовании не проверялись.

Пакет сохранён штатным package.save_as, действие подтвердило reopen и
совпадение графа. Guarded cleanup подтвердил package_closed=true,
logged_out=true, modified_before_close=false, unsaved_changes_discarded=false.
Браузер закрыт. Это Save/reopen исследования, не cold-приёмка run-check.

## Предложение приёмки и оценка продолжения

[Задание](acceptance/task-datetime-variant-intermediate.md),
[fixture](fixtures/modes.json), [oracle](acceptance/modes/oracle.py),
[expected](acceptance/modes/expected.json) — предложение, не утверждённая
регистрация сценария. Python datetime формирует civil дату; целочисленная
арифметика считает total, промежуточный base исключается из списка результата.
Loginom, runtime, парсер формул и значения UI oracle не использует.

Предлагается полный ordered typed-выход 0 с точными именами, метками и типами;
datetime до миллисекунд, Variant с integer-подтипом и total=3. Затем patch
только base=4 в том же узле, total=5, остальные переменные без изменений.
Второе состояние пока рассчитано только oracle, живой patch не выполнялся.
Стандартные Save/cold/cleanup и 2/3 + независимые 2/3 на одном SHA сохраняются.
Модель получает только задание и fixture; oracle/expected остаются приватны.
Новый механизм верификации не предлагается; адаптация в штатный W1 expected
и сценарий run-check относятся к отдельно назначенному этапу 1.

Для подтверждённого среза оценка — 2 цикла правки + 1 резервный:
schema/parameters/context/readback для datetime/Variant; затем UI-параметр
intermediate и сохранение пропущенных свойств. Возможные файлы:
`variables-calculator-{schema,parameters,context,procedure,readback}.mjs`,
`variables-calculator-node.mjs`, узловые тесты, декларация типа и reference навыка.
Сейчас это оценка, production red→green не выполнялся. Общая логика W1
по наблюдению не требует правки, но совместимость typed/cold ещё не доказана;
если нужна общая неаддитивная правка, повторно действует стоп.
