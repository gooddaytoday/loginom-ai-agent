## Ограничения платформы и состояние комплекта

В `CalcVariablesWizard` не обнаружен переключатель JavaScript; в
`ExprEditForm` отсутствует настройка кэша. В локальных записях выражений
присутствуют Intermediate, Replaced, Active, но нет Cached.
В наблюдённом диалоге свойств есть только имя, метка, тип данных,
«Промежуточное» и описание. btnCalcMode и chbCached, известные для
табличного Калькулятора, не являются наблюдёнными элементами этого мастера.
Это ограниченный вывод о поверхности UI данной версии, не доказательство
отсутствия возможностей в других версиях или компонентах.

Владелец подтвердил: кэш и JavaScript исключены из матрицы узла 7.4.2.
В карточке типа и предложении справки этих параметров нет. Доказательства
сохранены во вложении `discovery.jsonl`, строки 12, 14, 21, в исходном отчёте
LAB-1031. Сырые снимки не коммитятся по регламенту сквада.
Исследование продолжено по этому решению; текущий blocker — разрывы связи,
описанные ниже. Новые критерии ещё не утверждены, runtime не менялся.

## Предпросмотр и исходный выход после Execute

Fixture создан до проверки значений. В предпросмотре четыре выражения:
report_date, mixed, base, total. После Execute открыт исходный Output_Var-0,
`ModelForm;PreviewWindow;PreviewForm;VariablesForm;grdValuePreview`.
Локальный store содержит ровно три переменные в таком порядке:

| Имя / метка | Native тип | ValueVariant |
|---|---:|---|
| report_date / Дата отчёта | 2 (datetime) | civil `2026-11-07T23:59:58.123` |
| mixed / Разное | 6 (variant) | число 7 |
| total / Итого | 4 (integer) | число 3 |

base имеет Intermediate=true и участвует в формуле, но отсутствует в выходе.
Это отличие от предпросмотра; полнота выхода не доказывается списком preview.
Дата в UI форматируется без секунд; Date в браузере сериализуется как
`2026-11-08T04:59:58.123Z` при локальном UTC−05. Для ожидания нужна исходная
календарная дата с миллисекундами, без часового преобразования.
Variant с числом 7 не превращается в объявленный integer. Другие подтипы
Variant, NULL и смена подтипа в этом исследовании не проверялись.

Пакет сохранён штатным package.save_as, действие подтвердило reopen и
совпадение графа. Guarded cleanup подтвердил package_closed=true,
logged_out=true, modified_before_close=false, unsaved_changes_discarded=false.
Браузер закрыт. Это Save/reopen исследования, не cold-приёмка run-check.

## Предложение приёмки и оценка продолжения

[Задание](acceptance/task-datetime-variant-intermediate.md),
[fixture](fixtures/modes.json), [oracle](acceptance/modes/oracle.py),
[expected](acceptance/modes/expected.json) — предложение, не утверждённая
регистрация сценария. Python datetime формирует civil дату; целочисленная
арифметика считает total, промежуточный base исключается из списка результата.
Loginom, runtime, парсер формул и значения UI oracle не использует.

Предлагается полный ordered typed-выход 0 с точными именами, метками и типами;
datetime до миллисекунд, Variant с integer-подтипом и total=3. Затем patch
только base=4 в том же узле, total=5, остальные переменные без изменений.
Второе состояние подтверждено живым выполнением при продолжении исследования.
Стандартные Save/cold/cleanup и 2/3 + независимые 2/3 на одном SHA сохраняются.
Модель получает только задание и fixture; oracle/expected остаются приватны.
Новый механизм верификации не предлагается; адаптация в штатный W1 expected
и сценарий run-check относятся к отдельно назначенному этапу 1.

Для подтверждённого среза оценка — 3 цикла правки + 1 резервный:
schema/parameters/context/readback для datetime/Variant; UI-параметр
intermediate и сохранение пропущенных свойств; замена входа и независимый
порядок выражений/выхода. Возможные файлы:
`variables-calculator-{schema,parameters,context,procedure,readback}.mjs`,
`variables-calculator-node.mjs`, узловые тесты, декларация типа и reference навыка.
Сейчас это оценка, production red→green не выполнялся. Общая логика W1
по наблюдению не требует правки, но совместимость typed/cold ещё не доказана;
если нужна общая неаддитивная правка, повторно действует стоп.

## Продолжение по решению владельца: замена входа и перестановка

Новый журнал `discovery2.jsonl` приложен к отчёту продолжения. Все данные —
собственного пакета и назначенной пары. Исходный `discovery.jsonl` сохранён.

| Режим | Статус и доказательство |
|---|---|
| datetime с миллисекундами | Наблюдено: первоначальный журнал:24 и новый:4; тип 2, civil дата без изменений |
| Variant с целым значением | Наблюдено: новый журнал:4; тип 6, число 7; другие подтипы not_checked |
| Промежуточное выражение | Наблюдено: новый журнал:3–4; base=4, Intermediate=true, в выход не входит |
| Patch base=4 → total=5 | Наблюдено: `CalcVariablesWizard;colExpressionName_base` и `cmpExpression`, новый журнал:2–4 |
| Перестановка вверх | Наблюдено: `CalcVariablesWizard;btnExprUp`, новый журнал:6–7 |
| Перестановка вниз/зависимого выражения | not_checked: остановка по лимиту переподключений; видим btnExprDown |
| Замена входной переменной | Наблюдено: `CalcVariablesWizard;btnReplaceField`, новый журнал:28–30,34 |
| Кэш | Нет в UI 7.4.2: `ExprEditForm` и исходный журнал:14,21; исключён владельцем |
| Переключатель JavaScript | Нет в UI 7.4.2: `CalcVariablesWizard`, исходный журнал:12; исключён владельцем |

После изменения base выход 0 сохранил report_date/mixed/total и дал total=5.
Перенос mixed перед report_date поменял порядок локального store выражений
и автоподпись, но исходный выход сохранил report_date/mixed/total. Поле Index
в записи выражения после переноса ещё содержит прежнее значение; порядок
нельзя выводить только из него. В предложении переставляется список выражений,
а существующее соответствие выходных переменных сохраняется.

Для замены входа создан второй Калькулятор, связанный variables-портами 0.
К источнику добавлены пять констант из [consumer.json](fixtures/consumer.json).
В потребителе выражение total, метка «Скорректировано», integer,
формула `total+10`, Replaced=true. Пока Replaced=true, `ExprEditForm;edtName`
disabled, а `chbIntermediate` недоступен. Переименование выполнялось до включения.
Предпросмотр показал total=15 и исходное total=5 с меткой «Итого (до)».
Полный исходный выход содержит восемь переменных в прежнем порядке:
report_date, mixed, total, Color, Code, Amount, TextNum, Other. Только total
изменился на 15 и получил метку выражения; остальные значения и типы сохранены.
Это свежий native Execute, не PASS модели или cold.

[Дополнительное задание](acceptance/task-replace-reorder.md), fixture consumer
и расширенный независимый oracle/expected фиксируют оба порядка и все восемь
значений. Профили, журналы и недосохранённое состояние не отбрасывались.
