Утверждённый второй сценарий LAB-770: JSON→дерево→JSON, отдельный новый пакет.
Модели — `task.md` и `../fixtures/documents.csv`. Остальные файлы приватны для
расчёта ожиданий. Входная Document содержит один object с одной ветвью items.
Это собственная копия значений принятого ограниченного случая v0.3.9;
файл `document.json` нужен независимому oracle, а не импорту модели.

Общий oracle и команды: [trees-datatotree/acceptance](../../trees-datatotree/acceptance/README.md).
`oracle.py --scenario json --check` сверяет этот expected; с `--actual-json`
проверяет один полный сериализованный документ, сохраняя точный Int64.

Отсутствующая note четвёртой позиции нормализуется в NULL на JSON→дерево,
согласно принятому контракту v0.3.9. Результат должен содержать note:null;
байтовый roundtrip исходного документа не требуется. Критерий — JSON values
и полное типизированное дерево, включая 4 позиции и 24 экземпляра, с порядком.

Критерии и W040 утверждены в LAB-770; модельный/cold PASS не заявлен.
Новые типы, JSON comparator и сценарии run-check ещё не зарегистрированы.
Реализация и прогоны назначаются отдельной карточкой этапа 1, первым шагом
которого является native-подтверждение массива без группировки и исключения Root.
