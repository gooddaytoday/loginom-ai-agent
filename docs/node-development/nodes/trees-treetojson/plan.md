## Предлагаемое разбиение на этапы

Разбиение — гипотеза до этапа 0. Каждый этап должен приниматься самостоятельно; общие изменения, нужные этапу, входят в его же карточку.

- `trees-treetojson:s1` — Структурная сериализация и корневой массив. Требования: `trees-treetojson:r01`, `trees-treetojson:r02`.
- `trees-treetojson:s2` — Метки, даты, форматирование и переменные. Требования: `trees-treetojson:r03`, `trees-treetojson:r04`, `trees-treetojson:r05`. После: `trees-treetojson:s1`.

## Заметки черновика

Вход — типизированное дерево, выход — таблица JSON-строк. Корневой массив может дать по строке на элемент либо одну сериализацию; это выбирается флагом. JSON не имеет native datetime: даты становятся строками. Числа, Boolean, строки, null и отсутствующие container/array сохраняют разные значения. Все настройки Help допускает задавать управляющими переменными.

Самостоятельное дерево с root container, вложенным массивом из двух элементов, true/false, NULL, Unicode и числом 9007199254740993; отдельно корневой массив пустой/непустой. Oracle сравнивает семантическое JSON дерево, отдельно обязательные raw формат/escape/date требования. JSON object order не использовать как смысл, array order сравнивать точно. Контрольная дата 2026-01-02 03:04:05.006 при ISO сохраняет секунды/миллисекунды согласно заранее наблюдённой точности и не получает суффикс Z. Даты по ручным шаблонам проверяются независимым formatter.

Узловые отказы: Несовместимый template/variable type, совпадающие labels, unsupported variant; экспорт в JSON не считать принятым после обратного импорта тем же ещё не проверенным handler.
