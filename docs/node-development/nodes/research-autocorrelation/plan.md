## 2. Этап 1 — одна серия и временная АКФ

`research-autocorrelation:r01`: одна числовая серия integer/real, используемая
роль, число отсчётов и временная область. `r02`: полный выход с ошибкой и
Boolean значимостью. Создание/изменение существующего узла, readback, full read,
CSV, Save и независимое новое открытие сохранённого пакета.

Предлагаемый положительный критерий: ≥2 конечных значений без NULL и
с положительной дисперсией. Число отсчётов включает 0; матрица 1/4/8 при N=8.
Native ограничивает результат длиной входа. Ноль/пустой редактор, константы,
пустой/одноэлементный вход и несколько серий не входят в положительный критерий.
NULL даёт читаемый отказ, не синтезированный или устаревший результат.

### Параметры и semantics

`parameters.autocorrelation`:

- `field`: одно точное техническое имя integer/real поля; полностью заменяет
  используемые роли, остальные поля в расчёт не входят.
- `lag_count`: целое 1..9007199254740991, включая лаг 0.

Новый узел требует оба свойства. Для существующего пропуск сохраняет
поддержанную настройку; пустой patch не меняет молча неизвестный сохранённый
режим. `mode:"time_domain"` — строковый enum: временная область и ЧАКФ off.
Native numeric enum наружу не передаётся. Полная схема с description каждого
свойства — `fixtures/parameter-schema.json`; NODE_TYPES.semantics — в discovery.

Недопустимые режимы, типы, несколько серий, неизвестные поля параметров,
нулевой/дробный lag_count и mapping overrides отклоняются до мутации.
Разрешённый вход берётся в порядке записей, без скрытой сортировки.
Нельзя подменять native АКФ расчётом через JavaScript или Pearson сдвинутых колонок.

Компактный readback: идентичности узла/источника и source port, mode, field,
lag_count, domain=time, pacf=false, output_port=0, фактическое число строк и
схема выхода. Служебные квитанции модели не добавляются.

### Выход и численная проверка

| Имя | Native метка для X | Тип |
|---|---|---|
| Lag | Лаг | integer |
| X_ACF | X: АКФ | real |
| X_StdErr | X: Ошибка | real |
| X_Significant | X: Значимость | boolean |

Порядок колонок точный, строки — возрастающий лаг. Для другого поля читать
native схему, не угадывать имена. Исходные поля на выход не проходят.
`ordered:true`, `column_order:"exact"`, `output_port:0`; имена/типы/Boolean/NULL
точны. Пользовательские метки не заданы: `label_any:true`. Только два real-поля
имеют abs=1e-8, без относительного допуска.

Oracle: Python stdlib, точные Fraction-суммы центрированных произведений
с общим знаменателем, Decimal sqrt (precision 50) для ошибки Бартлетта.
Все ячейки/значимость в expected подготовлены до модельных прогонов.
Для фиксированных рядов significance=|АКФ|>ошибка, без 95%-множителя;
равенство на границе отдельно не исследовано и в матрицу не входит.

| Сценарий | Данные | Проверка |
|---|---|---|
| acf-series | series.csv | 4 лага, expected-series-4.json |
| acf-update | series.csv → update.csv на том же узле | Финальные 4 лага, expected.json; GUID и связи сохраняются |
| acf-one | series.csv | Ровно лаг 0: 1, 0, true |
| acf-eight | series.csv | Все 8 строк, expected-series-8.json |

Каждый сценарий экспортирует один финальный CSV и сохраняет свой пакет.
run-check сравнивает CSV и cold выход одного свежего исполнения существующим
проверяющим кодом. Нужны собственные записи сценариев с expected_name,
input_files и соответствующими task.md; новые механизмы проверки не требуются.

### Реализация и бюджет схемы

Собственные `auto-correlation-{node,parameters,procedure,context,readback,output}.mjs`
и адресные тесты client; аддитивные регистрации NODE_TYPES/NodeType, node-support,
node-api, node-procedure, node-result-schema/user-results и readback;
свой раздел `packages/product/skills/loginom-automation`; четыре сценария run-check.
Образцы — research.corr_analysis и transform.sliding_window.
Семантика пропусков Pearson на АКФ не переносится.

AutoCorrelationWizard требует дождаться загруженного значения, не только
visible корня: ранний ввод перезаписывался загрузкой. Собственный reader должен
подтверждать поле/lag_count/область/ЧАКФ до и после Next.

Полная dock_node_apply на базе: **43 329 Б**; тип добавляет **690 Б**
(42 enum + 648 parameters), итого **44 019 Б**, остаток **1981 Б**.
Измерение: `fixtures/schema-size.mjs`, тот же объект полной схемы, что использует
`node-caption-schema.test.mjs`. Приращение ≤1050 Б; регистрация — этап 1.
Общих изменений сверх регистраций не выявлено. W2/W3 уже реализованы:
expected поддерживает tolerance, ordered и output_port.

Оценка этапа 1 — **2–3 цикла**: реализация/адресные тесты, живые full/cold
сценарии, цикл исправления при наблюдённом отказе. Независимая приёмка того же
SHA отдельно по действующему регламенту.
