быстрый просмотр — только 2 знака после запятой. Preview не заменяет точный
Table/full read и CSV в будущей приёмке.
Максимальное расхождение прочитанных Table-значений series-8 и update-4
с независимым oracle — менее 4.86e-11; типы, лаги и Boolean совпали точно.

|АКФ| > ошибка, без 1.96; точное равенство на границе не исследовано.
Предложение: abs=1e-8 только для двух real-полей, остальные типы/NULL точны;
`ordered:true`, `column_order:"exact"`, `output_port:0`, `label_any:true`.

## NULL и особые входы — наблюдено / граница

В `null.csv` третье значение X — NULL, маркер импорта `?`. Обычное выполнение
АКФ отказало, выход не активировался. Причина через `Graph;Автокорр.:_X;Status`
→ `msgbox-1;cnt;cnt;MessagesView`: **«Данные содержат пустые значения»**.
Мастер при этом не отказывал; это ошибка исполнения. Нет автоматического
удаления пропусков или заполнения нулём. Старые числа не выдавались как свежие.

На `constant.csv` (восемь X=2) native выполнился: АКФ=1 для всех лагов 0–7,
ошибки в Preview 0 / 0.35 / 0.61 / 0.79 / 0.94 / 1.06 / 1.17 / 1.27,
значимость true на 0–4 и false на 5–7. Это native соглашение при нулевой
дисперсии; математический oracle с D=0 его не определяет. Константы не входят
в предлагаемый положительный критерий этапа 1. empty/one/types fixtures
подготовлены, но их выполнение не проверено; они остаются последующим срезом.

Импорт должен явно задавать RowID=integer и X=real: при первом автоматическом
определении `1.0` было распознано как дата. После явного типа полей X назначение
«Используемое» доступно и результаты соответствуют числовому oracle.

## Выполнение и сохранение

Создание, повторная настройка и замена файла существующего импорта проверены
в одном пакете. Для update.csv=[1,8,2,7,3,6,4,5] тот же узел без обучения дал
новые числа из таблицы. Разворот исходного ряда намеренно не используется:
его АКФ совпадает с исходной и не проверяет обновление.

Обычный Execute достаточен для исследованных конфигураций. В контекстном меню
есть команда обучения, но она не вызывалась; искусственный Train для нового
обработчика не предлагается. Saved-model apply отдельно не исследовался
и не входит в этап 1. Пакет с update.csv, LagCount=4 и dcTime сохранён.

После штатного закрытия пакета и logout он открыт под тем же аккаунтом в
новом браузерном профиле. Без ввода параметров прочитаны сохранённые
LagCount=4, область «Временная» и PACF=false; обычный Execute и Table снова
дали четыре строки update из таблицы. Это UI-проверка сохранения/повторного
расчёта, не модельный прогон и не запуск `cold-check.mjs`.

## Предлагаемый контракт и объём реализации

`fixtures/parameter-schema.json`: `parameters.autocorrelation.field` — одно
точное техническое имя integer/real, `lag_count` — число отсчётов ≥1.
Оба обязательны для нового узла; пропуск на существующем сохраняет настройку.
Явный field полностью заменяет роли используемых полей; RowID и остальные
снимаются. mode=`time_domain` включает временную область и выключает ЧАКФ.
Недопустимые типы, режимы, нулевой/дробный lag_count, несколько серий,
нестандартные mappings и непредусмотренные поля запроса отклонять до мутации.
Сохранённый узел из отложенного режима не менять молча при пустом patch.

Предлагаемый `NODE_TYPES.semantics`:

```text
Time-domain autocorrelation of one numeric field in input row order.
Set parameters.autocorrelation.field and lag_count; both required for new nodes,
existing omission preserves. Count includes lag 0 and is capped by input length.
Output 0: Lag, <field>_ACF, <field>_StdErr, <field>_Significant, increasing lag order.
Execute recomputes current input without training. Supported acceptance input:
at least two finite nonmissing values with positive variance. NULL input fails;
do not replace it with zero or reuse previous output. PACF, multiple fields,
frequency/auto and saved-model apply are outside this stage.
```

Компактный readback: type/mode, существующая идентичность узла, `field`,
`lag_count`, `domain:"time"`, `pacf:false`, source node/port, output_port=0,
имена/типы/порядок выходных полей и фактическое число строк. Полные UI-деревья
и служебные квитанции модели не нужны. У каждого свойства схемы есть description;
native числовые enum наружу не передаются.

План: собственные auto-correlation-{node,parameters,procedure,context,readback,output}
и адресные тесты; аддитивные регистрации типа/режима/схемы/диспетчеров и своего
readback; свой раздел навыка; четыре сценария run-check. Образцы —
research.corr_analysis и transform.sliding_window. Проверка готовности
AutoCorrelationWizard относится к собственному reader/procedure.

**Общих изменений сверх этих регистраций не выявлено.** Формат expected базы
уже содержит ordered, output_port и tolerance; W2/W3 не требуются.
Код runtime, общий runner и сборки CLI на этапе 0 не менялись.
