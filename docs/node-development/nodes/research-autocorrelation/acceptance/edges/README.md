## Наблюдение, не заявляется

Одна строка (`task-one.md`, series → one) однажды дала `[0,1,0,true]`.
Это наблюдение одного прогона, а не результат oracle или утверждённое соглашение.
Оно хранится в `observations_not_claimed.one` без положительного output-объекта.
По решению владельца от 08.11 singleton исключён из положительной приёмки:
в цикле 1 его сценарий не регистрируется и не запускается; обработчик N=1
специально не меняется. Математический коэффициент при N=1 не определён.

Положительные output-объекты используют штатные `output_port:0`, `ordered:true`,
`column_order:"exact"`, `label_any:true`; abs=1e-8/rel=1e-10 только для Real.
Integer/Boolean/NULL и порядок точны. При регистрации сценариев этапа 1 эти
объекты вкладываются в обычный `outputs`, с imports.text → research.auto_correlation
→ exports.text. `series.count4/count8` — oracle для проверки сохранения count;
в этом этапе живое численное сравнение сделано для count12 (0…7).

После утверждения: ≥2 PASS из 3 и независимые 2/3 на одном SHA; полный typed
выход, скачанный CSV, Save, cold Execute без перенастройки, cleanup. NULL использует
существующий стандарт отрицательного сценария: исходная причина, без экспорта
и stale output, Save/cleanup. У пустого входа отсутствует положительный oracle
платформы; защита до Execute — отдельное предложение владельцу, не ослабление
приёмки до «Access violation считается PASS».

Ни один из этих новых сценариев пока не зарегистрирован в run-check;
модельные PASS, CSV/cold и готовность runtime не заявляются.
