## Сценарий

`task.md` использует `data/series.csv`, затем `data/update.csv` на том же импорте
и том же узле. Один X типа real, RowID типа integer не участвует в расчёте.
Четыре отсчёта, временная область, ЧАКФ выключена. Сначала прочитать исходный
результат, затем обновить данные, прочитать полный новый выход, экспортировать
его в CSV и Save. `expected.json` проверяет финальный выход update.csv при
новом открытии сохранённого пакета.

| Сценарий этапа 1 | Задание | Expected | Входы |
|---|---|---|---|
| acf-series | task-series.md | expected-series-4.json | series.csv |
| acf-update | task.md | expected.json | series.csv, update.csv |
| acf-one | task-one.md | expected-series-1.json | series.csv |
| acf-eight | task-eight.md | expected-series-8.json | series.csv |

Каждый сценарий имеет один финальный CSV и свой сохранённый пакет. Это
соответствует существующему сопоставлению свежего результата одного node/port
в cold-check и не требует механизма проверки исторических снимков одного порта.

Модель получает только `task.md` и два файла из `data/`. Oracle, expected,
manifest и discovery остаются вне её workspace. `{{PACKAGE_PATH}}` перед стартом
заменяется новым путём внутри назначенного аккаунта.

`expected-series-1.json`, `expected-series-8.json`, `expected-update-1.json` и
`expected-update-8.json` задают дополнительные проверки числа отсчётов.
Сценарии для этих границ регистрируются в этапе 1; численные ожидания уже готовы.

## Предлагаемые критерии

| Предмет | Критерий |
|---|---|
| Область | Одна числовая серия integer/real, не менее двух непустых конечных значений, положительная дисперсия; без ЧАКФ |
| Лаги | Число отсчётов включает 0; 1/4/8 дают 1/4/8 строк на входе длины 8; порядок Lag по возрастанию |
| Порты | Один табличный вход 0, один табличный выход 0; `output_port:0` |
| Поля | `Lag`, `X_ACF`, `X_StdErr`, `X_Significant`; точные имена, типы и порядок |
| Точность | `X_ACF`, `X_StdErr`: только abs=1e-8, без relative tolerance; integer/boolean/NULL точны |
| Метки | Пользователь не задаёт метки: `label_any:true`; имена узлов также не фиксируются |
| Порядок | `ordered:true`, `column_order:"exact"`; порядок входа задаётся записями файла, без скрытой сортировки |
| Изменение | Сохраняются GUID импорта и АКФ, связи и незапрошенные настройки; обновлённые числа совпадают с oracle |
| Жизненный цикл | Обычный Execute на текущем входе; искусственное обучение и режим saved-model apply не требуются |
| Сохранение | Save, новое открытие, Execute и полный cold-check финальных четырёх строк; штатное закрытие и logout |
| Приёмка | Один опубликованный SHA; worker ≥2 PASS из 3 и независимая проверка 2/3 на другом аккаунте, по регламенту сквада |

Непустое значение `lag_count` ≥1; native ограничивает число возвращаемых строк
длиной входа. Для этапа 1 обязательная численная матрица — 1/4/8 при N=8.
Ноль и пустой редактор native принимает как 0, но их вычислительная семантика
не проверялась и не предлагается для API этого этапа.

## Независимый oracle

`oracle.py` использует только стандартную библиотеку Python 3: Fraction для
точного среднего и сумм центрированных произведений, Decimal sqrt с точностью 50.
Вход — самостоятельные CSV. Oracle не читает Loginom, runtime или результаты UI.

Для x длины N и среднего m:

```text
D = sum((x[t]-m)^2, t=0..N-1)
r[k] = sum((x[t]-m)*(x[t+k]-m), t=0..N-k-1) / D
SE[0] = 0
SE[k] = sqrt((1 + 2*sum(r[j]^2, j=1..k-1)) / N), k>0
significant[k] = r[k]^2 > SE[k]^2
```

Это смещённая АКФ с общим знаменателем D, не Pearson двух укороченных рядов
и не нормировка на N-k. Уровень 95% и множитель 1.96 не вводятся.
На фиксированных рядах сравнение не попадает на границу равенства; поведение
native при точном равенстве требует отдельного исследования.

```sh
python3 docs/node-development/nodes/research-autocorrelation/acceptance/oracle.py --check
```

`--check` сверяет все шесть expected, reference и manifest; `--write` создаёт их
перед прогоном. После публикации кандидата ожидания не менять для обхода FAIL.
Oracle также проверяет известную АКФ чередующегося ряда и инварианты сдвига,
масштаба и разворота. Поэтому update.csv — другая перестановка, не разворот.

## Границы и этап 1

`fixtures/null.csv` вызывает native отказ «Данные содержат пустые значения».
NULL не заменяется нулём и строки не удаляются автоматически. Выбранный ряд
должен быть без NULL; отрицательный случай требует читаемой причины и отсутствия
заявления о свежем результате. Для константы native показывает АКФ=1 на всех
лагах; математический oracle с D=0 её не определяет. Этот native special case,
пустой/одноэлементный вход, несколько серий, частотная/автоматическая область и
ЧАКФ остаются последующим срезом. `empty.csv`, `one.csv`, `types.csv` — запас
для исследования, без численного PASS или новых механизмов проверки.

Существующий формат expected уже поддерживает tolerance, ordered и output_port;
W2/W3 не нужны для одного табличного выхода. В этапе 1 добавить перечисленные
сценарии `run-check` с явными `expected_name` и `input_files`, одним финальным CSV
и существующим проверяющим CSV-кодом. Общий runner сейчас не меняется. Затем запускать только
`run-check start` + foreground `wait`: openai/gpt-6.1-sol, medium, 1800 с,
новые профиль/основа/чат и назначенная пара.
