# Автокорреляция (`research.auto_correlation`)

Предложение LAB-1022; установленный skill и обработчик не меняются.

Прочитай карточку типа. Используй time_domain или frequency_domain,
parameters.autocorrelation: fields — полный набор непрерывных Integer/Real
серий в порядке входных полей, lag_count — число отсчётов с нулевым лагом,
pacf — нужен ли расчёт ЧАКФ. Старое field сохраняется для одной серии;
не передавай field и fields вместе. Пропуски существующих настроек сохраняют
поддержанные значения. Переменные не входят.

Сохраняй порядок строк входа: скрытой сортировки нет. Выбирай серии явно;
RowID и служебные поля не включай. Число отсчётов ограничивается длиной входа.
Положительный срез — не менее двух конечных значений с ненулевой дисперсией.
NULL в выбранной серии вызывает читаемый отказ «Данные содержат пустые значения»;
не заполняй пропуск, не удаляй строку и не выдавай старую таблицу.

ЧАКФ native — частная корреляция концов окна после регрессии на константу
и промежуточные лаги, по N−k строкам. Не заменяй её Yule-Walker estimator.
Частотная АКФ в исследованном срезе совпадает с временными прямыми суммами;
не подменяй native вычислением через JavaScript.

Табличный вход 0 и выход 0, обучения нет. Execute пересчитывает текущий вход.
Полный выход: Lag Integer, затем для каждой серии <field>_ACF Real,
<field>_StdErr Real, <field>_Significant Boolean; после всех блоков идут
<field>_PACF Real в том же порядке серий, если ЧАКФ включена.
Отдельных PACF StdErr/Significant нет. Проверяй фактическую схему после
смены набора или флажка, не предполагай четыре поля для нескольких серий.

Читай все строки и поля, сохраняй native NULL/Boolean и точные типы,
выгрузи таблицу в CSV и сохрани пакет. Oracle и expected модели не передаются.
