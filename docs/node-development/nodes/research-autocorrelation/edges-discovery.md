## Числа на краях ряда

Независимый `acceptance/edges/oracle.py` подготовлен до численного чтения.
Исходный X=[1,2,4,3,6,5,8,7], N=8, среднее 4.5, сумма квадратов отклонений 42.
Для lag k: сумма (X[t]−mean)(X[t+k]−mean) по t=0…N−k−1 делится на **42**.
Среднее и знаменатель общие, не пересчитываются по двум перекрытым срезам;
нет умножения на N/(N−k), дополнения нулями или циклического замыкания.
Ошибка при k>0: sqrt((1+2·sum(r[j]²,j=1…k−1))/N), при k=0 — 0.
Для этой fixture значимость совпала с r[k]² > variance; граничное равенство
отдельно не исследовано. Это не порог 1.96 стандартной ошибки.

| Lag | Пар | АКФ native | Ошибка native | Значимость |
|---|---:|---:|---:|---|
| 0 | 8 | 1 | 0 | true |
| 1 | 7 | 0.47023809523809523 | 0.35355339059327373 | true |
| 2 | 6 | 0.25 | 0.42459506185692736 | false |
| 3 | 5 | −0.005952380952380952 | 0.4426126597300262 | false |
| 4 | 4 | −0.2857142857142857 | 0.4426226657809545 | false |
| 5 | 3 | −0.27976190476190477 | 0.4651053509994748 | false |
| 6 | 2 | −0.44047619047619047 | 0.485684741748541 | false |
| 7 | 1 | −0.20833333333333331 | 0.5332864961364119 | false |

Полные 8×4 совпали с oracle: максимальная абсолютная разница
5.551115123125783e-17; Integer/Boolean точны. На lag6 Pearson двух срезов
равен −1, native АКФ — −37/84. На lag7 одна пара даёт −5/24; Pearson по одной
паре не определён. Эти края различают методы независимо от округления.

Числа прочитаны из уже загруженного кэша **того же видимого** DataSetForm:
FColumnInfosStore и FDataTable.FDataSourceStore.data.map; total=8 и 8 cached
rows, затем total=1 и 1 row для одной строки. Внутренний JS не перехватывался,
не подменялся; методов RPC/вычислений Loginom не вызывали. Это исследовательское
чтение, не новый runtime decoder или механизм верификации. Видимые ячейки
Preview показывают только 2 знака; они сами по себе не доказывают точность.

## Одна строка, пустой вход и NULL

Файл менялся у того же импорта с сохранением RowID Integer / X Real;
повторно выполнялся тот же узел АКФ, count12/time/PACF off. Имена файлов
подтверждались после загрузки и blur: ранний ввод может быть перезаписан
поздним readback. На пустом файле не запускалось повторное автоопределение типов.

| Вход | Native наблюдение | Предложение |
|---|---|---|
| one: X=[5] | total=1; [0,1,0,true], прежние восемь строк исчезли, типы те же | положительный singleton-case после утверждения |
| empty: только заголовок | вход total=0, схема RowID/X сохранена; после Launch Access violation | ограничение платформы; успешного empty-case нет |
| null: X[2]=NULL | вход total=8, ровно один NULL; Execute отказал | исходная ошибка без импутации/удаления/stale output |

Для one коэффициент по математическому oracle не определён (D=0).
Native [0,1,0,true] записан в expected как отдельное соглашение платформы.
Для empty ошибка прочитана в `msgbox-1;cnt;cnt;MessagesView`:
«Access violation at address 0000000001A312DD. Read of address 0000000000000000».
После ошибки попытка просмотра выхода АКФ дала несогласованный кэш:
FTotalRowCount=12, 0 cached rows; это **не** пустая успешная таблица.
Соседний просмотр входа подтвердил total=0 и RowID Integer / X Real.
Адрес ошибки — доказательство этого наблюдения, не устойчивый критерий matcher.
Воспроизводимость AV отдельным новым пакетом не установлена, PASS не заявляется.

NULL: `Graph;Автокорр.:_X;Status` → `msgbox-1;cnt;cnt;MessagesView`:
**«Данные содержат пустые значения»**. Входной кэш содержал восемь исходных
значений с NULL в третьей строке; новая таблица не засчитывалась.

## Границы этапа 1 и оценка

Нативных start/step/list нет: **0 циклов реализации native режима**; требуется
решение владельца о закрытии этой возможности как ограничения либо об отдельном
преобразовании результата. Новые параметры/mode в этом PR не предложены.
Обычные ненулевые лаги и ограничение count длиной уже есть в time_domain:
**1 цикл** закрепления полного края через run-check/CSV/Save/cold.
Singleton: **1–2 цикла** приёмки/своей правки по наблюдённому отказу.
NULL: **1 цикл** отрицательного сценария со штатным matcher, собственная правка
только если модель/handler нарушит исходный отказ. Empty: **1–2 цикла** защиты
до Execute, только после утверждения владельцем; успешный native расчёт обещать нельзя.
Итого для доступного среза и защиты: ориентир **4–6 циклов**, не выполненные циклы.

Адресные production-файлы: `client/lib/auto-correlation-node.mjs` (own preflight),
`auto-correlation-procedure.mjs` (готовность/readback при необходимости),
`auto-correlation-output.mjs` (свежие строки/типы, singleton),
`auto-correlation-readback.mjs` (сохранённые настройки). Схема параметров
`auto-correlation-parameters.mjs` уже допускает count≥1; output уже допускает
row_count≥1. Нельзя просто ослабить его до нуля: empty наблюдение неуспешно.
`auto-correlation-context.mjs` не требует расширения контролов; тип найден
в `node-contracts.mjs`, обработчик указан выше. В knowledge меняются только
semantics карточки и свой reference. Сценарии добавляются аддитивно в run-check.

Общая правка не обоснована. Текущий общий preflight проверяет схему, а не
валидность пустого ряда; способ безопасного собственного guard надо подтвердить
в этапе 1. Если для него потребуется изменение общего контракта/reader,
остановиться и запросить решение. Публичные параметры и общий код здесь не меняются.
