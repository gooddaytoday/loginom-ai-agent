Предлагаемая матрица последовательного режима; утверждение владельца перед
этапом 1. `oracle.py --case CASE` строит соответствующий expected независимо.

| CASE | Вход | Размеры first / last | Ожидание |
|---|---|---|---|
| rows | 20 строк, integer/string/integer | 5 / 5 | 1..5 / 16..20, исходные поля и порядок |
| update | тот же состав полей, RowID +100 и Value +1000 | 5 / 5 | 101..105 / 116..120; обновление тех же узлов |
| null | 3 строки, integer/string/real/boolean/datetime | 3 / 2 | все строки / строки 2,3; NULL не равен пустой строке или false |
| empty | только заголовок5 полей | 0 / 0 | ноль строк, прежняя явная схема |

Поля в исходном порядке; ordered=true, output_port=0; real abs=0/rel=0.
Пользовательские подписи узлов основного task фиксированы, метки входных полей
не фиксированы (`label_any`). До модели доходят только task и нужные CSV.
Изменение узла проверяется вместе с новым source identity и последующим Save.
Случайный, равномерный случайный, стратифицированный и biased режимы исключены.

Живое native discovery подтвердило только rows. **NULL/empty — проверяется
на этапе 1 по oracle**, по решению LAB-533; сейчас NOT_CHECKED. Update — NOT_RUN.
Статус ready_for_development относится к подплану; ожидания не являются PASS.
