Комплект для этапа 0 подплана. Модель получает только `task.md` с подставленным новым путём пакета и файлы из `data/`. Этот README, oracle, manifest, ожидаемые значения и история ошибок остаются вне её контекста и рабочего каталога.

`cleanup.csv` и `scalar-matrix.csv` — побайтовые копии прежних входов. Размеры, SHA256, формат и порядок полей фиксирует `manifest.json`. `fixtures/scalar-matrix.historical.json` сохраняет прежние наблюдения с исходной provenance; это диагностический материал, его наличие не подтверждает текущие конверсии.

Перед модельным прогоном вычислить независимые ожидания для нового пакета:

```sh
python3 oracle.py --package-path /lab-65-field-parameters/<attempt-id>.lgp --output expected.json
python3 oracle.py --package-path /lab-65-field-parameters/<attempt-id>.lgp --initial --output expected-initial.json
```

Oracle использует только проверенные исходные байты и стандартную библиотеку Python; не импортирует обработчик, runtime или значения из таблицы Loginom. Правила закреплены для конкретного входа из прежнего `reform_goal_contract.py`, не распространяются на произвольные локальные конверсии. После модельного прогона выполнить общий `scripts/node-acceptance/cold-check.mjs` из того же SHA в новом профиле с `--expected expected.json`, конфигом рабочего аккаунта и ресурсами проверяемой сборки. Закрытие пакета и выход должны быть подтверждены отдельными квитанциями.

Общий cold-check проверяет имена, метки, типы, позиции полей, полный набор значений и новое выполнение. Дополнительно по журналу и native readback проверить первоначальный результат, повторное изменение того же узла, назначение суммы, excluded-поля, сохранение незапрошенных свойств, точную входную привязку и сохранение после всех чтений. Отдельно провести адресную матрицу разделов 3–5 подплана: 25 scalar-конверсий с независимыми ожиданиями, одинаковые метки, пустую и широкую схемы, отказы до мутации и recovery. Непроведённое обозначать `not_checked`; основной сценарий не заменяет матрицу.

Текущий комплект подготовлен без модельного прогона: назначенная модель недоступна в CLI на исходном SHA карточки. PASS, persistence и standalone-готовность узла не заявлены. Настройки модели берутся из текущих инструкций сквада.
