## 3. Данные и независимые проверки

Комплект `nodes/trees-treetodata/acceptance/stageN/`: `task.md` с `{{PACKAGE_PATH}}` на бизнес-языке, `data/` только с входами модели, независимый `oracle.py` и сгенерированный до обработчика `expected.json` вне её контекста.
Формат CSV: UTF-8, запятая, десятичная точка, заголовок, NULL-маркер `?`; пустая строка в кавычках отличается от NULL. Числа/даты и типы явно закрепить в manifest.

data/orders.csv: OrderID,Customer,SKU,Qty: (10,A,X,2),(10,A,Y,0); отдельный source manifest задаёт Order20 с пустыми Lines, Order30 без Lines и sibling Tags[]. Структура и значения дерева независимо заверяются до использования.

Для типизированных источников CSV описывает независимые значения, а не подменяет порт таблицей: на этапе 0 подготовить собственную копию малого fixture-пакета и подтвердить source identities, схему/значения отдельным reader. Готовый соседний handler не требуется. Модель сохраняет новый пакет по уникальному пути.
Адресные `fixtures/manifest.json`: байты, SHA256, кодировка, разделители, типы, NULL-маркер, порядок и source identity. Ожидания поздних этапов не входят в раннее назначение.

| Набор | Независимая проверка и ожидание |
|---|---|
| `r01` | На ветви из двух записей вывести ровно выбранные поля; нулевой выбор должен отказать. |
| `r02` | Независимый path-walker считает строки/поля и отличает отсутствующую ветку от scalar=NULL; observed Cartesian/zip semantics нескольких массивов закрепить до expected. |
| `r03` | Индекс/порядок и имена сверить с actual mapping. Служебный индекс -1 из документа относится порядку узла в мастере; не объявлять все значения data index равными -1. |
| `r04` | Два потомка одного родителя позволяют проверить каждую строку, а не только число строк; policy пустых ячеек off закрепить до прогона. |
| `r05` | Независимый typed-tree oracle сравнивает пути, флаги, порядок массивов, точные значения и отсутствие контейнеров отдельно от NULL примитива; обязательный корень нельзя оставить несвязанным. Загрузка схемы проверяется как замена старой структуры, Cancel её сохраняет. Отдельно прочитать Variant-столбец табличного результата с точным subtype каждой ячейки: integer9007199254740993, real1.25, строка"1", false, datetime и NULL. Независимый fixture задаёт эти значения в листьях массива; строковое отображение и округлённые числа не считаются равными исходным значениям. |
| `r06` | Настройки выбора, separators и mapping сохраняются; новый execution выдаёт тот же полный малый набор. |
| `empty/null/replace` | Нулевой вход, NULL/пустая строка, новый источник: результат по заранее закреплённой семантике, старое исполнение отклонено |

Oracle не импортирует runtime/обработчик. Считает по входам, проверяет каждое значение, имя/метку/тип/порядок, кратность и связи; отличает NULL, отсутствие, ноль и пустую строку. Для дерева schema отдельно от values, массивный порядок точный, Int64 — десятичный текст/целое Python, Variant — subtype каждой ячейки.
Отклонять чужой узел/порт, источник с другой identity, старый execution и подмену графа. E2E-снимки не являются oracle; LGD-импорт агента отсутствует, исходные данные доставляются текстом или независимо подготовленным источником.

Ограничения: `scripts/node-acceptance/expected-outputs.mjs:14,29-39` — до 100 строк на табличный выход, до 32 отчётов (`:8`); схема позиционная, строки как мультимножество. `:72-81` сопоставляет разные узлы по type/label/values и `node_id`, без identity порта. `cold-check.mjs:221,232` открывает порт 0 и требует точные числа.
Базовый cold-check не принимает дерево/набор переменных и не доказывает вложенные границы, исходный компонент или активность ветвей. Нужен согласованный W с независимым структурным/типизированным cold-аудитом; вывод через временную таблицу не заменяет исходный порт.
Полный табличный порядок проверять отдельно по RowID/адресному readback: базовый cold-check сравнивает мультимножество строк. Допуск, когда требуется W, задаётся в `expected.json` до прогона; округлять ответ ради PASS нельзя.

## 5. Ловушки — переподтвердить, не копировать

Один вход дерева и табличный выход. Выбор leaf выбирает ancestors; снятие ветки снимает descendants. Global index массива — отдельная выбираемая колонка, а не реальные данные дерева. Результат зависит от duplication parents, имён/меток и выбранных ветвей. Обучение не применяется.

Самостоятельное типизированное дерево заказов: Order10 c Customer=A и Lines[(SKU=X,Qty=2),(SKU=Y,Qty=0)], Order20 с пустыми Lines, Order30 без Lines. Отдельный sibling array Tags предотвращает молчаливое предположение о произведении/zip. Expected рассчитывать отдельным обходом дерева после подтверждения правила мультипликации; identities, types и порядок точные. Применение не требует уже готового JSONToTree: fixture может быть подготовлен диагностически, его schema/values независимо заверяются.

Узловые отказы: Ни одного выбранного узла, потерянные связи корня, конфликтные имена/сепаратор, data index перепутан с UI index, неполный вывод последнего массива.

- Наличие `navigation_path` или имени в палитре не доказывает поддержку. Не маскировать отсутствие typed reader строковым preview; не менять формулу/связь ради PASS.
- Семантика Help/E2E документирована на указанных ревизиях; настройки/лимиты актуального стенда до этапа 0 остаются гипотезой.
