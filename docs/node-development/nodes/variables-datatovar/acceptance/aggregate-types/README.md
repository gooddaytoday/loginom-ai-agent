Комплект LAB-1051 — **предложение до утверждения владельцем**, не каталог
действующих прогонов. Runtime и оснастка не меняются.

- `../task-aggregates.md` + `../../fixtures/aggregate-numeric.csv`: 10 переменных.
- `../task-scalar-types.md` + новая копия `aggregate-source.lgp`: 28 переменных.
- `../task-variant.md` + отдельная новая копия того же пакета: 9 переменных,
  **blocked** до решения об общем точном reader Variant.
- `expected.json` хранит также объединённый discovery-набор из 47 переменных;
  это ожидания от независимых исходных данных, а не сохранённый результат Loginom.

`oracle.py` использует только Python stdlib, авторский JSON и CSV. Медиана и
выборочная дисперсия вычисляются рационально; корень — `math.sqrt`.
Для ASCII string используется лексикографический порядок, для Boolean
false < true, для civil datetime — календарный порядок. Равенство Variant
учитывает вид JSON-скаляра (false отличается от 0). Только для данного
малого V-набора предлагается порядок boolean < number < string; это не
утверждённая общая семантика смешанных Variant. Числовой subtype V неизвестен:
`native_subtypes_verified:false`; этот expected нельзя выдавать за готовый
строгий Variant-контракт или передавать в существующий W1 matcher.
Boolean-мода имеет ничью false/true: наблюдён false, oracle предлагает
наименьшую моду для этого fixture. Общее правило разрешения ничьих ещё не принято.

Источник `aggregate-source.lgp` штатно сохранён и скачан через UI 7.4.2.
В нём только собственный JavaScript-источник и встроенные переменные сценария;
нет проверяемого агрегатора, его результата и экспорта. Oracle проверяет
ZIP/XML, единственный пользовательский engine, код источника, типы и все
строки на согласованность с JSON; пакет не является oracle результата.
Имеющийся CSV содержит только N/K и NULL-маркер ?, UTF-8, LF, запятая, header names.
JSON и пакет сохраняют остальные native-типы, включая Variant, которые
нельзя представить обычным нетипизированным CSV без потери сведений.

Проверка: `python3 acceptance/aggregate-types/oracle.py --check` из каталога
узла. Без `--check` команда обновляет только соседний `expected.json`.
Модель получает только task и соответствующий CSV либо частную копию
входного пакета. Oracle, expected, manifest и discovery модели не передаются.

Предложенные стандартные критерии: полный упорядоченный typed output 0,
все имена/метки/типы/NULL/значения; real abs/rel 1e-12; Save, новое cold
выполнение без перенастройки, Close и logout. Для variable output CSV не
применим: нет табличного порта. На одном SHA ≥2/3 PASS и отдельно ≥2/3
независимой проверки. Нужны новый адресный case и адаптация старого
`auditDataToVarHistory`: он закрепляет пять функций X и не подходит этой матрице.
Новые механизмы верификации не предлагаются; Variant и его precision-contract
остаются отдельным вопросом владельцу. Живые модельные прогоны, cold,
all-NULL/empty, source replacement и кастомные настройки списка — not_checked.
