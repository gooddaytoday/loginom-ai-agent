## 1. Итог исследования

Палитра и мастер DataToVariablesWizard присутствуют. Fulltype Engine
`TBGCustomModelComponentEngine` — общий, отличать по vendor конкретного
компонента. Вход таблицы 0, выход переменных 0. Перед параметрами при
необходимости открывается TuneDataSourceInputPortWizard; затем DoneWizard.

Это агрегирование всей таблицы. Для X=[2,4,6] получены sum=12 real,
count=3 integer, min=2 integer, max=6 integer, avg=4 real.
Порядок X_Sum,X_Count,X_Min,X_Max,X_Avg, метки в discovery/expected.
Для [2,NULL,4] — 6,3,2,4,3; для пустой таблицы — NULL,0,NULL,NULL,NULL.
После замены данных на [8,12] — 20,2,8,12,10 в прежнем узле без
перенастройки агрегатов. Синтаксис отказа пустого выбора прочитан из btnError.
Сохранён собственный пакет; модельная/cold-приёмка не проводилась.

## 2. Предлагаемый этап 1

- `r01`: пять числовых агрегатов sum/count/min/max/avg, один typed выход
  переменных; полный ordered readback имён/меток/типов/значений.
- `r02`: смена текущих данных без смены набора агрегатов; Save/cold по W1.
- Адресные случаи NULL и пустого входа заданы до прогонов в fixtures/expected.

Количество включает NULL-строки; остальные агрегаты пропускают NULL.
Сумма/среднее real; количество integer; min/max сохраняют числовой тип.
Допуск real abs/rel=1e-12; остальные значения и порядок точные.
Бизнес-задание на русском; модель получает только CSV и task, без oracle.

Вначале один числовой столбец с несколькими функциями. Для расширения на
несколько полей/один агрегат и real-источник этап 1 должен адресно подтвердить
порядок/имена/типы. Существующее имя для одного агрегата пока гипотеза Help;
его нельзя зашить как доказанный readback. Не расширять автономную приёмку
до неподтверждённых случаев без утверждённой матрицы.

## 3. Зависимости и реализация

Общий W1: typed переменные, refs/связи/read/context/cold исходного порта.
Его контракт утверждается отдельно до этапа 1. В этой карточке не меняются
общие модули, публичная схема и механизмы верификации.
Expected с port_kind:variables — проект формата для W1, текущий табличный
cold-check его не поддерживает. Согласовать формат до run-check.

После W1: собственный handler/parameters/procedure/readback и тесты,
аддитивная регистрация, собственный раздел навыка и сценарий run-check.
Реальные размеры карточек и схемы повторно измерить после регистрации.
Другая общая правка требует остановки по условию карточки.

## 4. Следующие этапы и проверки

Позже: медиана, мода, отклонение, unique/missing, first/last/single/list,
нечисловые типы, все NULL и несколько полей. Это отдельные назначения;

(≥2/3 PASS и отдельно ≥2/3; Save/cold/close/logout).

модельные прогоны и cold — not_checked. Оценка после W1: 2–3 цикла.
