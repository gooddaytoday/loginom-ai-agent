## Предлагаемое разбиение на этапы

Разбиение — гипотеза до этапа 0. Каждый этап должен приниматься самостоятельно; общие изменения, нужные этапу, входят в его же карточку.

- `variables-datatovar:s1` — Базовые агрегаты и выход переменных. Требования: `variables-datatovar:r01`, `variables-datatovar:r02`.
- `variables-datatovar:s2` — Все допустимые агрегаты, типы и выходная схема. Требования: `variables-datatovar:r03`, `variables-datatovar:r04`. После: `variables-datatovar:s1`.

## Заметки черновика

Одна входная таблица преобразуется в набор переменных. Каждая выбранная пара «поле — агрегат» даёт отдельную переменную; это не выбор произвольной строки. Порядок выбранных полей, итоговые имена, метки и типы читаются из результата.

Текущие `node-target-browser.mjs` и `node-contracts.mjs` работают с табличными портами; перед handler нужны типизированные ссылки/связи и независимое чтение переменных. Общий lifecycle `node-apply.mjs` сохранить. Переиспользовать семантическую валидацию из `grouping-parameters.mjs`, но не копировать таблицу допустимых агрегатов без сверки мастера этого узла.

Наблюдать полный список агрегатов по типам; разрешение Variant и пустой схемы, правила имён и тип результата. Не считать весь список общей страницы агрегаций автоматически доступным этому мастеру.
