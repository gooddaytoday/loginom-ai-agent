## 2. Этапы

### Этап 0 — завершённое исследование и предложение

Наблюдены палитра, native vendor/engine, все страницы основного мастера,
отдельные мастера табличных портов, явное событие, ручной Enter, epsilon и порог.
Train: 32 строки, классы no/yes, одна числовая X; все результаты совпали с
независимым MLE с максимальной ошибкой p 2.38e-10. 11 NULL Note сохранены.
Save / новый профиль / Execute без Teach вернули те же значения.
Замена источника того же импорта на holdout и Execute без Teach дала новые
прогнозы при NULL Target; Teach явно отказал по пропускам Target.
Это native-исследование, а не PASS `run-check` или `cold-check.mjs`.

### Этап 1 — бинарный Enter, прогноз и сохранение (предложение)

- `r01`: непрерывные числовые факторы, ровно одна строковая дискретная цель
  с двумя непустыми категориями; все остальные столбцы сохраняются без роли.
- `r02`: явное обучение / переобучение того же узла на текущем входе,
  сохранение модели и cold Execute без повторной настройки / Teach.
- Событие задаётся **меткой**, сверяется с наблюдёнными двумя категориями;
  его native индекс не угадывается. `threshold` обязателен, диапазон 0..1;
  событие определяется по **p >= threshold** (включая равенство, проверено).
- Ручной Enter, intercept=true, epsilon=1e-10, без нормализации факторов,
  без весов / регуляризации / валидации / поправки на долю событий;
  100% строк в обучении. Категориальное кодирование цели штатное.
- Чтение только полного порта **0**: PredictionEvent (Boolean),
  PredictionProbability (Real), ActualEvent (Boolean), Target_predicted
  (String) и исходные поля с точными типами и NULL.
- `finish=execute` явно обучает и выполняет; Done только сохраняет настройку,
  Close отбрасывает черновик. Иные режимы/порты/веса/привязки — отказ до мутации.
- Применение к holdout исследовано, но отдельный runtime mode `apply` и его
  модельный сценарий предлагаются следующей карточке; ожидания сохранены отдельно.

Схема `parameters.logistic` — [parameter-schema.json](acceptance/parameter-schema.json).
Каждое поле имеет description; enum режима строковый. Semantics и компактный
readback перечислены в discovery. Не изменять описания прежних общих полей.

Ожидаемые изменения: собственные файлы `logregression-*`, аддитивная регистрация
типа / handler / readback, UI-маркеров и контролов, собственного раздела
`packages/product/skills/loginom-automation` и сценария run-check.
Публичные стадии можно сохранить, добавив маркеры LogRegression как алиасы
к `lin_regression` / `lin_regression_details`. Общих алгоритмов не требуется
по наблюдённым опытам; новая потребность — стоп по карточке.

## 3. Данные и oracle

Канонические входы — `fixtures/`; в `acceptance/data/` **только train.csv**
для основной модельной просьбы. Формат UTF-8, заголовок, запятая, точка, NULL `?`.
RowID Integer, X Real / непрерывный, Target String / дискретный, Note String.
32 строки: по X=-2/-1/0/1/2 размеры групп 10/4/4/4/10, yes=1/1/2/3/9.
Обе категории в каждой группе исключают полную разделимость.

Независимый Python stdlib Newton/IRLS сверяет аналитическую MLE
β₀=0, β₁=ln(3); прогнозы вычисляются точной рациональной формой
p=3^X/(1+3^X). При threshold 0.8: p=0.1/0.25/0.5/0.75/0.9,
no/no/no/no/yes. 10 положительных прогнозов, 22 отрицательных.

`acceptance/expected.json` использует штатный cold-формат: `output_port=0`,
`ordered=true`, `column_order=exact`; холодная схема — четыре служебных поля,
X, Target, RowID, Note. Для p допуск **abs=1e-8 / rel=1e-10**, как ЛинРег.
Boolean/строки/целые/NULL и типы точны. Служебные метки `label_any=true`;
имена и состав полей не ослабляются. Основной CSV oracle проверяет все 32×8
ячеек и порядок строк, допускает любой порядок уникальных имён CSV-колонок.

`holdout.csv` (RowID 33..35, X=-3/0/3, Target NULL) и отдельные ожидания —
операторское исследование apply: p=1/28,1/2,27/28, no/no/yes.
`null-x.csv` — пять строк с обоими классами; Teach отказал по NULL X.
`single-class.csv` — адресный вход для следующей проверки (not_checked).
Эти данные модели в основной просьбе не передаются; текст непроверенного отказа
не выдумывается.
`threshold-half-expected.json` — отдельная адресная проба границы решения.
Oracle / expected / discovery / история дефектов модели не передаются.
