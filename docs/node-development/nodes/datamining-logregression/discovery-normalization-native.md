07.11.2026, Loginom 7.4.2, mas, Node 24.19.0 / Chromium 1246.
Исходный код на момент опытов: `69b9a547bb2511bb9d4c9cd09f95b0c3e467fb3e`.
Выполнены ровно три native-обучения, без новой сборки CLI и без модельных
`run-check`. Это исследование семантики UI, а не приёмочные PASS.

Внутренний JS Loginom не изменялся; читались связанные с видимым DOM контролы,

порог 0.8, константа true, epsilon `1e-10`, обучение 100%, тест 0%,
валидация 0. Настройки прочитаны после завершения загрузки native-страниц.

как незавершённая и не используется в выводах.

Точные контролы нормализации:

Выбрана **«Стандартизация», NormType=5**, множитель 1,
неудаляемость false. Target сохраняет «Отклонение», NormType=9.
После reopen прочитан тот же NormType=5 и сохранённый denormalize=true.

## Порядок полей — поведение платформы

Таблица читалась по
`MF;TF-1;ModelForm;PreviewWindow;PreviewForm;DataSetForm;grdDataTable;grd-1;tbl`.
Технические имена взяты из native grid columns; типы — из связанного
`DataSetForm.Controller.FColumnInfosStore`. Все 32 записи прочитаны из
материализованных страниц Ext PageMap, без загрузки данных через proxy.

После четырёх служебных полей native UI показал:

| Состояние | Порядок исходных полей | Журнал |
|---|---|---|
| None, main | RowID, X, Target, Note | `:9`, `:10` |
| Standardize + true, main | RowID, X, Target, Note | `:19` |
| Тот же сохранённый узел, новый профиль, reopen + Execute без Teach/настройки | X, Target, RowID, Note | `:26`–`:29` |

Снимки: `standardize-true-main-port0.png` и
`standardize-true-reopen-port0.png`. Значения и типы сохранены.
Следовательно, перестановка воспроизводится **без обработчика** и зависит
от reopen, а не от patch/readback нашего узла. После reopen индексы X/Target
в native нормализаторах также стали 0/1 вместо 1/2 (`:32`).

Нынешний `expected.json` задаёт холодный порядок X,Target,RowID,Note
и используется оснасткой также для main/CSV. Замена единственного порядка
на RowID,X,Target,Note исправит main и сделает неверным cold. Поэтому expected
оставлен неизменным до решения о двух native порядках; сравнение не ослаблялось.

Все 32×8 значений, включая исходные поля и NULL, совпали с неизменным
oracle в предусмотренных допусках. После reopen без Teach они также совпали
(`:28`, `:40`), коэффициенты порта 1 сохранились (`:30`).
Полные таблицы прогнозов и коэффициентов при true/false одинаковы по именам.

Для исходных X' среднее равно 10, выборочное SD = sqrt(352/31) =
3.369694156696928. Аналитический коэффициент для Z=(X'-10)/SD равен
`(ln(3)/2)*SD = 1.850993704800184`: наблюдение согласуется со шкалой Z.
Mean/SD здесь вычислены независимо из fixture; native UI показал тип 5,
множитель и неудаляемость. Исследовался выход порта 1; внутреннее представление
коэффициентов исполняемой модели не исследовалось.

Таким образом, в этих опытах флажок «Денормализировать коэффициенты модели»
не изменил шкалу **таблицы порта 1**. Он не доказывает исходные единицы этой
таблицы. По п.2 указания владельца дальнейший подбор остановлен, статус blocked:
нужна семантика владельца. Обработчик, oracle, expected, значения и типы не менялись.
Модельная приёмка ≥2/3 с cold не запускалась; дополнительных сборок 0/2.

Пакеты true/false сохранены в своём каталоге. В обоих профилях штатно
закрыты пакет и сессия, без discard; финальный журнал `:43` подтверждает
`package_closed=true`, `logged_out=true`. Браузеры закрыты.
Журнал, JSON-readback и исходные снимки доставляются вложением карточки;
raw traces и приватные профили не включаются в Git.
