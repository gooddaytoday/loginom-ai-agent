## Что передавать модели

Только `task-<режим>.md` и файлы из соседнего `data/` выбранного случая.
В apply нужны два CSV; в остальных — один. Oracle, expected, схема предложения,
наблюдения, снимки и этот README модели не передаются.
CSV: UTF-8, comma, decimal point, header, NULL `?`. Типы задаются явно:
RowID/Split/Fold Integer, X/Weight Real, Target/Note String. X непрерывный,
Target дискретная. Integer-Weight хранится отдельно как отрицательное наблюдение
`fixtures/modes/integer-weight.csv`; подменять его вещественным в отрицательном
сценарии запрещено.

## Независимый oracle и expected

`python3 .../acceptance/modes/oracle.py` создаёт 11 JSON из fixtures;
`--check` сверяет их без записи. Python stdlib, без Loginom, runtime и
подгонки коэффициентов под наблюдённые результаты. Для воспроизводимости имена
native полей привязаны по UI, но численные значения получены из математики:

- Enter: двухпараметрический Newton/IRLS, β=(0, ln(3)).
- Apply: те же β на X=-3,0,3, p=1/28,1/2,27/28.
- Weight yes=3, no=1: β=(ln(3), ln(3)); аналитически шансы умножаются на 3.
- Нормализация: X'=10+2X, β'=(-5ln(3), ln(3)/2); при обратимой аффинной
  нормализации и свободной константе прогноз Enter остаётся прежним.
- Штрафы: минимизировать **сумму** negative log-likelihood + λL1|β| + λL2β²/2.
  Константа не штрафуется. На симметричном наборе intercept=0, slope находится
  бисекцией score=λL1+λL2β. Не копируется алгоритм оптимизации Loginom.
- Коэффициенты: обратная Fisher information, Wald z², normal-tail p-value,
  exp(β), exp(β±z.975 SE). Допуск 1e-7 absolute / 1e-8 relative.
- Сводка: deviance, null deviance, McFadden R², adjusted R², DFE, LR χ²,
  AIC/AICc/BIC/HQC **на одну строку**, RMS и entropy в битах.
- Split: первые 32 строки / Split=0 дают исходную MLE; все 64 дали бы β=0.
- K-fold: три полных копии исходного набора; любая пара полных блоков имеет
  исходную MLE. Это не доказательство случайного разбиения или Монте-Карло.

Табличные expected — существующий stock-формат, `output_node_type`, `outputs`,
`ordered=true`, `column_order=exact`, все ячейки, без row_count-подмены.
`package_path` заменяется runner на собственный `.lgp`. Служебные метки,
не заданные задачей, — `label_any`; имена, типы и NULL не ослабляются.
Холодный порядок passthrough X/Target/RowID/Note наблюдён; порядок новых
Weight/Split/Fold в cold остаётся предложением до живой приёмки нового SHA.

`summary/expected.json` использует существующий `variable_inventory`, ровно
19 переменных и `ordered=true`. Variable matcher не принимает label_any:
метка здесь просто не задаётся, её сравнение не требуется. **Это заведомо
не PASS:** независимое число ошибок классов — 8/32=25%, native вернул 6.25%.
Исходные native-числа не заменяют oracle. До решения владельца не вводить
subset/exclusion/custom comparator и не править обработчик.

## Непокрытые варианты внутри обнаруженных UI-семейств

| Вариант | Что есть | Чего нет для допуска этапа 1 |
|---|---|---|
| Случайная train/test-выборка | Picker, seed, процентные поля; fixture partition.csv | Независимая привязка выбранных обучающих строк; точный PRNG не исследован |
| K-fold random / by-column | UI выбора способа, поле числа блоков | Численная проверка разбиения; таблица прогноза не доказывает скрытую принадлежность строк |
| Монте-Карло | Выбран native mode 4, iterations=10, доли 80/20 | Независимые ожидания агрегатов по реально отобранным подвыборкам |
| scale_min_max / [-1;1] / [0;1] / absolute / ratio | Полный список normalizer picker | Для standardize есть обучение; остальные пока UI-only, не численный PASS |
| Автоматические λ | Ручной/автоматический picker для LASSO/Ridge | Область поиска, выбранный λ, независимый oracle оптимума |
| Auto method / варианты события / scoring / калибровка / coefficient denormalize=false / confidence / intercept=false / bindings | Контролы видны в мастере; существующая база их запрещает | Отдельное живое исследование семантики и задач, вне численно проверенных ручных циклов |

Не следует выдавать 11 комплектов за полное принятие всех возможностей узла.
Отсутствие Integer-Weight и несовпадение сводки — наблюдённые стоп-пункты.
Неисследованные варианты перечислены явно; обходов нет. Ни случайный PRNG,
ни новый механизм проверки этим docs-PR не реализуются.

## Бюджеты и проверки

[`budgets.json`](budgets.json) воспроизводится `measure-proposal.mjs`.
Команда `node --test test/model-schema-budget.test.mjs` из client на базе:
model_tool_bytes=14 539 (лимит 20 000), full_input_schema_bytes=63 280
(лимита нет). Сжатая маршрутизация apply для предложения не расширяется.
Карточка типа: база 4 276 Б, ручное предложение 6 103 Б (лимит 12 000).
Файл узла после ручных циклов: 3 682 Б (лимит 6 000).
SKILL.md: 39 954 Б, свободно 46; пример строки маршрутизации 95 Б.
Её добавление дало бы 40 049 Б (+49 к лимиту), поэтому SKILL.md не менялся.
Реальная замена существующей строки зависит от отдельного решения архитектуры;
рост файла узла не означает необходимость копировать его в SKILL.md.

В предложенной карточке все cache/hash/digest-поля — 64 нуля, не реальные
контрактные пины. Автоматические режимы/калибровка не входят в этот замер;
их отдельные будущие схемы нужно измерить до регистрации.

CLI не собирался. Модельных run-check/cold-check: **0/3**.
Native-исследование подтверждает UI и отдельные числа, а не приёмку продукта.
После утверждения: red→green на production-коде, required-checks list/verify,
полный client и проверки изменённых путей; run-check start → wait,
Save/cold, ≥2 PASS/3 у исполнителя и независимая приёмка того же SHA.
