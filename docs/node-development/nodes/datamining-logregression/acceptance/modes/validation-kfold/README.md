## K-fold: три последовательных блока

Комплект использует исходный `task-validation-kfold.md`, только `validation.csv`
и неизменённый независимый `expected.json` из `../oracle.py --check`.
Три одинаковых блока дают одинаковую MLE: одних прогнозов недостаточно.
Нужны readback метода валидации, folds/sampling и отдельное доказательство
фактического выполнения валидации, связанное с этим узлом и выполнением.

Решение владельца 16.11 `logreg-kfold-csv-by-name`: CSV сравнивается по
техническим именам столбцов. Native первое выполнение сохраняет
`RowID,X,Target,Note,Fold`, после переоткрытия ожидается `X,Target,RowID,Note,Fold`.
Число строк, набор столбцов, значения, NULL и проверки типов остаются строгими;
пропавший/лишний столбец и другое значение отказывают. Порядок native-выхода
в cold строго проверяется по expected. Expected/oracle не меняются.
