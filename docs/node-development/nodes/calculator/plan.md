### Препятствия и эскалация

Порядок — [координация сквада](../../../testing/loginom-ai-agent/multica-mas.md). Обычные ошибки исполнитель исправляет сам; вопросы о пределах технического исправления решает Генератор. При неизвестном исходе остановить опасные действия и сохранить попытку, но продолжить анализ через Генератора. Критерии приёмки ниже не меняются.

При каждом препятствии явно упомянуть Генератора и завершить запуск, сохранив in_progress; blocked устанавливает Генератор только при реальном внешнем ожидании:

- в ветке задания нет RUNBOOK, подплана или инструментов приёмки;
- пара аккаунтов или CLI не `ready` на назначенном стенде;
- неизвестный исход операции; попытку сохранить, writer marker не удалять;
- дефект лежит в общей оболочке или `cold-check.mjs`, а не в модулях Калькулятора;
- для прохождения нужен режим вне принятого объёма (JavaScript, переменные, промежуточные выражения).

## 2. Этапы

### Этап 0 — перепроверка принятого объёма

Подготовка: checkout и проверка SHA, сборка кандидата из закоммиченных исходников, `loginom status` = `ready` на назначенном стенде.

1. Собрать `acceptance/` (раздел 3) из `calculator_goal_contract.py`: ожидания переносятся в независимый `oracle.py`, транспорт Hermes, pins и receipts прежнего формата не переносятся. Прежний launcher не запускать.
2. Адресные тесты узла `client/test/calculator-*.test.mjs` (10 файлов), затем весь `client/test`: `bun run test:upstream` в `packages/loginom-runtime`.
3. CLI-сценарий и cold-check по RUNBOOK.
4. При расхождении — живая сверка мастера штатными средствами runtime с `?testable=true`, причина отказа — из кнопки ошибки; наблюдение записать в `discovery.md`.
5. Дефект в модулях Калькулятора исправить тем же этапом с адресным тестом; дефект общей оболочки передать Генератору для согласования исправления.

Выход этапа 0: PASS исполнителя и независимая приёмка того же SHA; реестр отражает `client_technical_validation` и `analytical_validation` по результату.

### Этап 1 и далее — непокрытые режимы Help 7.4 (отдельные карточки по решению владельца)

- Промежуточные выражения, кэширование, описание, клонирование и перестановка в мастере.
- Приоритет Field/Expr, регистр имён, комментарии, рекурсивный `Data()` с кэшированием.
- Необязательный порт переменных и явный `Var.` при конфликте имён.
- Режим JavaScript: тело и `return`, `this.Expr`/`this.Var`, функции калькулятора, ошибки и консоль, Variant, CommonJS `require`; ES modules и Promise не поддерживаются.

Подплан расширения пишется по шаблону, когда расширение назначено.

## 3. Данные и независимые проверки

Приёмочный комплект `nodes/calculator/acceptance/`:

- `task.md` на бизнес-языке с `{{PACKAGE_PATH}}`;
- `data/sales.csv` — копия прежнего входа: `Id;Region;Quantity;UnitPrice;Comment`, разделитель `;`, NULL-маркер `\N`, 6 строк, включая пустую строку в кавычках, `\N`, разделитель внутри кавычек, ноль и отрицательное количество;
- `expected.json` — из независимого `oracle.py`.

Ожидания прежнего контракта (переподтвердить, не копировать вслепую):

| Выражение | Тип | Формула и смысл |
|---|---|---|
| `Revenue` (метка «Сумма») | real | `Qty * UnitPrice`; вход `Quantity` переименован во входном mapping в `Qty` |
| `Adjusted` (метка «Сумма») | real | `Revenue + 0.0001` — зависимость от предыдущего выражения, одинаковые метки |
| `UnitPrice` | real | `UnitPrice * 2`, `replace=true` |
| `Note` (метка «Комментарий») | string | `If(IsNull(Comment), "missing", Concat(Comment, "!"))` — строковый NULL отличается от пустой строки |
| `Moment` (метка «Дата») | datetime | `EncodeDate(2024, 2, 29)` |

Порядок выхода: `Id, Qty, Revenue, Adjusted, UnitPrice, Note, Moment, Comment`; `Region` исключён выходным mapping.

Oracle не импортирует код обработчика, считает по CSV, проверяет все ячейки, типы, имена, метки и порядок полей, отличает NULL от 0 и от пустой строки, отклоняет старое исполнение, чужой узел и подмену значений. Формулы сравниваются по токенам, не вычисляются как выражения Loginom.

Ограничения источников: cold-check сверяет порядок, имена, метки и типы колонок, а строки — без учёта порядка; до 100 строк на выход (`scripts/node-acceptance/expected-outputs.mjs:14,29-39`). E2E — снимки мастера, а не oracle.

## 4. Проверки, приёмка и завершение

Адресная матрица; непроведённая проверка — `not_checked`:

| Проверка | Условие успеха |
|---|---|
| Контракт | Лимиты 128/2048, неизвестный тип, коллизия имени без `replace` отклонены до мутации |
| Зависимые выражения | `Adjusted` использует `Revenue`; значения совпадают с oracle |
| Replace и mapping | `UnitPrice` заменён; `Qty` из входного mapping; `Region` исключён; порядок выхода совпадает |
| NULL и строки | `Note` = `missing` для `\N`, `!` для пустой строки |
| Изменение существующего | Переименование и перестановка выражений сохраняют незапрошенные свойства |
| Ошибка формулы | Неверный синтаксис даёт ошибку узла, формула не исправлена автоматически |
| Persistence | Сохранение после всех чтений; новое открытие и выполнение без восстановления настроек |
| Recovery | Неизвестный эффект не повторяется; отказ мастера читается из кнопки ошибки |
| Регрессия | Весь `client/test` |

Задание модели (бизнес-язык, без имён инструментов и ожидаемых чисел): загрузить продажи из `sales.csv`, рассчитать сумму продажи и скорректированную сумму, удвоить цену, подготовить комментарий с отметкой пропуска и дату отчёта, убрать регион из результата, показать все строки и сохранить пакет в `{{PACKAGE_PATH}}`.

PASS исполнителя: приёмка обвязки (CLI, cold-check, `package_closed=true`, `logged_out=true`) и адресная матрица. Публикация, независимая приёмка и отражение в реестре — по RUNBOOK; слои `integration` и `release` не трогаются.

## 5. Ловушки — переподтвердить, не копировать

- Выходная страница мастера появляется условно при добавлении выражения (`04-completion-audit.md`, `calculator-extend`): однократная синхронизация не должна терять прежние имена и исключения.
- Done не запускает узел и не объявляет свежий выход; выполнение — отдельным шагом с графа.
- Потеря ответа после подтверждения строки: повтор не должен создавать второе выражение.
- Close мастера отбрасывает черновое выражение, Cancel редактора сохраняет записи — не путать при проверке отмены.
- `Revenue + 0.0001` — real; сравнение чисел точное (`requireExactNumbers`), ожидания считать в том же представлении double.
