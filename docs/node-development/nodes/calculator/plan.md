# 04. Калькулятор: подплан сопровождения и приёмки

[Карточка и принятые границы](README.md) · [реестр](../../registry.json) · [работа с одним узлом](../../workflow/single-node.md).

Обработчик `transform.calculator` уже реализован в режиме `expression`. Этот подплан адаптирует исторический 04 к текущему runtime и standalone CLI: это маршрут адресного исправления, проверки переноса или отдельно назначенного расширения, не повторная разработка с нуля. Историческое принятие сохраняется в своём scope; технические Desktop проверки не являются аналитической CLI-приёмкой. Новых живых наблюдений и прогонов при составлении документа не было, readiness не повышается.

До начала выбрать точное изменение и пройти [подготовку/жизненный цикл](../../workflow/lifecycle.md). Разработчик работает в Astra medium в своей задаче, ветке и worktree. Первичная разработка получает Goal до готовности изменения к первому ревью, без собственного token_budget. Этот документ не назначает следующий узел и не разрешает слияние.

## Узловые требования

Обработчик выполняет выражения языка Loginom; смысл формулы выбирает агент, рассчитывает Loginom. Новое выражение задаёт name, label, type, formula и replace. Existing target адресует точное сохранённое имя и сохраняет незапрошенные свойства. Порядок выражений не включает унаследованные входные поля.

Изменение имени и output mapping нужно согласовать: нельзя потерять связь ранее настроенного выхода или незапрошенное выражение. Цикл переименований в Калькуляторе имеет собственный план временных имён; не переносить сюда запрет из «Параметров полей». Поддержаны пять scalar-типов, до 128 выражений и 2048 символов формулы; JavaScript-режим отсутствует.

## Шаги изменения

1. Выписать изменение конкретной формулы/редактора и проверить его на текущем мастере; синтаксис и зависимость позднего выражения от раннего сверить до фиксации oracle.
2. В validateCalculatorParameters/resolveCalculatorPatch валидировать полный итоговый набор и collisions с входами, затем planCalculatorEdits должен сохранить record identity и свойства неперечисленных выражений.
3. Применять выражения и их порядок с подтверждением строки, текста и синтаксиса. Ошибку формулы возвращать с исходным смыслом запроса; не «чинить» формулу незаметной сменой расчёта.
4. Проверить отдельный выходной мастер и inline mapping при autosync=false. Только после завершения обоих мастеров выполнять узел общим циклом; configure-only не запускает расчёт.
5. Расширить проверку конфигурации и значений отдельно: совпавшая схема не доказывает формулу, результат первой строки не доказывает сохранность остальных выражений.

## Независимые fixtures и oracle

Ниже — обязательная узловая матрица для объявленного полного scope. При адресном исправлении выбрать затронутые строки и обосновать выбор; расширение режима добавляет новые строки. До автономной попытки сохранить входы и expected отдельно от handler, с версиями и SHA. Ожидания не вычислять импортом реализации и не подгонять по её приёмочному выводу.

| Случай | Вход/изменение | Независимая проверка |
| --- | --- | --- |
| Выручка | Quantity/UnitPrice: (2,10.125), (0,4.2), (-3,1.25), (NULL,8). | Для трёх непустых строк Revenue=20.25,0,-3.75. Правило NULL явно зафиксировать по языку Loginom; вычислять oracle независимо десятичной арифметикой. |
| Зависимость и replace | Второе выражение использует Revenue; отдельный вариант явно заменяет исходный Amount. В existing узле есть третье незапрошенное выражение. | Проверить зависимость, сохранение третьего выражения и различие add/replace; выходные имена и порядок заданы отдельно. |
| Scalar и границы | Строка с кавычками/кириллицей, boolean, datetime на границе месяца, дробь >2 знаков, пустой вход. | Полный типизированный output и сохранённый текст каждой формулы; для дат не использовать неявный часовой пояс среды. |
| Изменение и persistence | Переименовать выражение, переставить два выражения, исключить одно выходное поле через mapping. | Сравнить конфигурацию и связи перед/после сохранения и нового открытия без повторной передачи настроек. |

## Негативные случаи

- Неверный синтаксис, цикл вычислительных зависимостей, деление на ноль/NULL: ожидаемая диагностическая семантика, без ложного SUCCEEDED и без незапрошенной коррекции.
- Коллизия имени с входом без replace, несовпадающий existing target, неполный order, переполнение лимитов: отказ до мутации.
- Потерянный ответ Apply/Execute или отмена вложенного редактора: не добавлять второе выражение и не терять неуказанные свойства.
- Для изменённых фаз отдельно различить отказ до эффекта, известную ошибку с подтверждённым cleanup и неизвестный эффект. Повтор operation_id не создаёт второй узел/запуск; lost reply не оправдывает слепой retry. Чужой пакет и посторонние связи неизменны.

## Автономная проверка и передача

Рассчитать выручку и согласованные производные показатели по данным, изменить существующий расчёт и сохранить пакет. Независимо проверить формулы, все малые выходы и повторное выполнение сохранённого узла.

Первичная отладка — штатными скриптами текущего runtime в назначенной изоляции. После неё выполнить адресные source tests и проверить независимый oracle, включая его отказ на подменённых значениях/схеме/идентичности. Только затем подготовить неизменный candidate и получить слот по [CLI-регламенту](../../workflow/acceptance-cli.md): standalone CLI Loginom AI Agent, Sol low, согласованная подписка, бизнес-цель и входные файлы без пошаговых UI-команд.

Критерий аналитического PASS — полный малый output/артефакт, проверенная схема и настройки, новый execution и сохранённый пакет, которые независимо воспроизводятся после отдельного открытия. Configure-only и Close проверяются отдельно; обычный продуктовый путь не переоткрывает мастер ради повторной проверки. Непроверенные платформы, большие наборы и дополнительные режимы остаются явно ограниченными.

Передать checkpoint с точными source/runtime/client/model/platform pins, заявленным scope, результатами и неизменёнными исходными FAIL. Техническое завершение, аналитическая проверка, integration и release — отдельные состояния реестра. Один этап ревью и один раунд исправлений выполняются по общему жизненному циклу; этот подплан не добавляет повторного полного ревью.
