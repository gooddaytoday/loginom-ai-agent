# Предложение контракта этапа 1

Статус: предложение для утверждения по LAB-771, не зарегистрированный handler.
Основание — [живое исследование](discovery.md) Loginom 7.4.2 на базе
`2910b8782c1ad8c016c6fc478369ddd179457e3e`.

## Объём и параметры

`transform.ungroup_data`, единственный режим `shares`. Два обязательных
табличных входа: 0 — уникальные групповые итоги; 1 — опорные позиции с уже
заданными долями. Два native выхода регистрируются честно; обработчик этапа 1
публикует чтение только выхода 0. Порт 1 не выдаётся за второй результат
распределения. Вычисляемые веса, сезонность и переменные отклоняются до UI.

[parameter-schema.proposal.json](parameter-schema.proposal.json) — полная
схема `parameters` карточки типа. Новый узел требует полного `ungroup`;
существующий принимает `{}` для повторного Execute без изменения настройки.
Если `ungroup` передан, все его роли/связи и политики задаются целиком.
Статические поля и переменные не смешиваются. Неизвестные свойства запрещены.
Все имена — точные технические имена соответствующего входа.

| Поле | Смысл |
|---|---|
| `ungroup.keys[]` | Упорядоченные пары `total`/`support`; составной ключ групп. В итогах ключ уникален, NULL совпадает с NULL, пустая строка отдельно |
| `ungroup.value_field` | Одно разгруппируемое непрерывное числовое поле входа 0 |
| `ungroup.item_field` | Одно строковое наименование из входа 1; NULL сохраняется |
| `ungroup.share_field` | Числовая готовая доля входа 1; NULL-строка пропускается, отрицательная доля даёт ноль |
| `ungroup.rounding.format` | Строка `none`, `precision`, `multiple`; округляется и групповой итог |
| `ungroup.rounding.value` | Отсутствует для none; число знаков для precision, положительный целый шаг для multiple |
| `ungroup.balance` | Строка `none`, `last`, `proportional`, `equal` |

Предлагаемые защитные пределы: precision 0..12, multiple 1..2147483647;
это **границы предлагаемого handler**, не измеренные пределы native редактора.
Проверенные native значения — precision=0 и multiple=3. Несовместимая пара
format/value отвергается до создания узла. Числа enum native UI наружу не
передаются. Для первой реализации обязательна проверенная комбинация
строковых ключей/наименований и real итогов/долей; integer и составные ключи
нужно отдельно проверить перед заявлением их поддержки. Схема параметров
описывает имена полей; фактические типы проверяет preflight по обоим входам.

При `none`/`none` рассчитывается Total × max(Share,0), без нормирования.
Нельзя всегда требовать сохранения суммы: при ненормированных долях и
отключённой балансировке это изменило бы задачу. NULL Total и группы без
сопоставления не дают деталей. При включённой балансировке примеров с
положительными суммами долей сумма OutputValue равна Total_Rounded.
`last` означает последнюю опорную позицию во входном порядке.

Для проверенного двухколоночного входа итогов выход 0: поля входа 0 в его порядке, `<value_field>_Rounded:real`, поле
наименования, `OutputValue:real`. Для назначенных fixtures точная схема:
`Group:string, Total:real, Total_Rounded:real, Item:string, OutputValue:real`.
Проверять наличие и тип пустых полей, а не трактовать их как отсутствие поля.
Порядок строк — порядок итогов, затем порядок опорных позиций внутри группы.
Пустой набор итогов даёт активную таблицу с той же схемой и нулём строк.

Входные и выходные переименования остаются в существующем `mappings`, вне
параметров алгоритма. Расширение его публичного контракта не требуется.
Коллизии генерируемых имён и несовместимая схема должны давать объяснимый
отказ; не придумывать суффиксы или преобразования типов ради успеха.

## Видимость модели и readback

[node-card.proposal.json](node-card.proposal.json) содержит предлагаемый
`NODE_TYPES.semantics` и parameter_schema: роли входов, порядок, NULL,
ненормированные/отрицательные доли, округление, ограничения и повторное
выполнение. Значения в JSON — проект будущей карточки; наличие файла не
объявляет текущему runtime доступный тип.

Компактный readback собственного handler должен подтверждать фактический
режим, обе связи входов и настройки после сохранения. Например его часть:

```json
{
  "mode": "shares",
  "ungroup": {
    "keys": [{"total": "Group", "support": "Group"}],
    "value_field": "Total",
    "item_field": "Item",
    "share_field": "Share",
    "rounding": {"format": "none"},
    "balance": "none"
  },
  "readable_ports": [0]
}
```

Идентичности узла и источников использовать из существующего общего
контекста графа. Одних меток или повторения запроса недостаточно. Сохранённые
связи ключей, роли и настройки читаются независимо от введённых значений;
для нового узла сверяется полный набор, для повторного — сохранение набора.
Не добавлять отдельные механизмы доказательства происхождения.

Предложены короткая строка маршрутизации
[skill-route.proposal.txt](skill-route.proposal.txt) и будущий файл
`references/nodes/transform-ungroupdata.md`, текст которого лежит в
[skill-node.proposal.md](skill-node.proposal.md). Реальный продуктовый навык
этим docs-PR не изменяется.

## Объём реализации и общие точки

Предварительно 3 цикла: собственный writer/readback и основной бизнес-кейс;
округление/балансировка и сохранение; регрессия и серия приёмки точного SHA.
Это оценка, не разрешение делать этап 1 в этой карточке.

Основа — lifecycle Группировки и двух входов Слияния. Собственные модули
узла и их тесты; аддитивные записи в `node-contracts.mjs` / `.d.ts`,
`node-support.mjs`, `node-api.mjs`, `node-procedure.mjs`,
`node-result-schema.mjs`, обработке компактного результата, собственный
файл навыка, маршрут и сценарии `run-check.py`.
Публичный интерфейс Host/Agent и общая логика чтения/бюджетов не меняются.
Если потребуется расширение общей логики — stop и один вопрос, а не
самостоятельное расширение разрешения.

Новая реализация допусков/порядка/identity порта не нужна: эти возможности
уже есть в текущем expected-outputs и cold-check. Непринятый старый W1 из
исходного подплана не является препятствием для использования существующей
проверки. Сам допуск **1e-12 absolute и relative** — предложенный критерий,
подлежащий утверждению до этапа 1.

## Измерение размеров

Считать UTF-8 `JSON.stringify` без пробелов. Для инструмента, видимого модели,
считать `{name,description,inputSchema}` после `userNodeTool`; выходная MCP
схема не является входным описанием функции модели. Отдельно считать всю
опубликованную inputSchema. Для предлагаемой карточки использовать
`describeNodeTypes` с пустым session_manifest, кандидатной схемой и полями
из `node-card.proposal.json`; cache_key — 64 ASCII-символа. Это статическая
оценка: фактический session_manifest дополнительно занимает байты.
