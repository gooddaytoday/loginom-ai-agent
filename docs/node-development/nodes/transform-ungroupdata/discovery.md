## Числа, NULL и порядок

Значения прочитаны через штатный «Быстрый просмотр»:
`mn;mniShowDataPreview` → `ModelForm;PreviewWindow;PreviewForm;DataSetForm`.
Имена и типы — заголовки `normalHeaderCt;<имя>` с native CSS-типами,
ячейки — `normalHeaderCt;<имя>_<индекс>`. Проверенные выходные числа — целые или половины; отображение до двух знаков не выдаётся
за доказательство точности произвольных real.

Без округления и балансировки для `totals.csv` / `shares.csv`:

| Группа / позиции | Total | Share | OutputValue |
|---|---:|---|---|
| G / a,b | 100 | 0.25, 0.75 | **25, 75** |
| H / c,d,e | 10 | 0.2, 0.3, 0.5 | **2, 3, 5** |
| N / f,g | 80 | 0.25, 0.25 | **20, 20**, без нормирования к 80 |
| Z / h,i | 30 | 0, 1 | **0, 30** |
| NEG / j,k | 100 | -0.25, 1.25 | **0, 125**, отрицательная доля ограничена нулём |
| NULL / n | 20 | 1 | **20**; NULL-ключ совпадает с NULL |
| пустая строка / o | 16 | 1 | **16**, отдельная группа |

Итого **13 строк**. M без опорных позиций, Q с NULL Total и лишняя опорная
группа U строк не создают. NULL и пустая строка различены ещё в импорте
(`?` и `""`). Для `null-totals.csv` / `edge-shares.csv` результат:
`(X,20,c,10), (D,8,NULL,8), (G,100,a,25), (G,100,d,75)`.
NULL Share у позиции X/b пропущен; NULL Item у D сохранён.
Опорный порядок групп G,X,D,X,G не переносится на результат: первичен порядок
итогов X,D,G; внутри G сохраняются a,d. На округлении позиции c,a,b остаются
c,a,b, лексикографической сортировки нет.

Наблюдаемая выходная схема, **в точном порядке**:

1. `Group:string` — исходный ключ входа 0;
2. `Total:real` — исходный итог, повторённый для каждой позиции;
3. `Total_Rounded:real` — округлённый групповой итог, также повторённый;
4. `Item:string` — наименование из входа 1;
5. `OutputValue:real` — распределённое значение.

Без округления Total_Rounded равен Total. Share на выход не переносится.
Для пустого входа итогов получен активный выход с нулём строк и той же
схемой из пяти полей.

Непредписанные метки проверяются через `label_any`; технические имена,
типы, порядок полей, кратность и NULL проверяются строго.

## Округление и балансировка

На `round-*` total=10, позиции c,a,b, доли 0.25/0.25/0.5:
без округления **2.5/2.5/5**; точность 0 без балансировки **2/2/5**;
«Все последнему» **2/2/6**; пропорционально **2/2/6**.
Это подтверждает 2.5 → 2, но не доказывает все отрицательные половинные случаи.
Кратное 3 без балансировки: Total_Rounded=**9**, OutputValue=**3/3/6**.
Сумма деталей без балансировки может отличаться даже от округлённого итога.

На `balance-*` total=10, позиции c,a,b, доли 0.125/0.125/0.25,
точность 0:

| Метод | Результат | Сумма |
|---|---|---:|
| Нет балансировки | **1/1/2** | 4 |
| Все последнему | **1/1/8** | 10 |
| Пропорционально | **2/3/5** | 10 |
| Равномерно | **3/3/4** | 10 |

Поэтому названия методов не являются взаимозаменяемыми. В oracle предложена
последовательная коррекция уже округлённых деталей с пересчётом оставшегося
остатка и весов/числа позиций; последней позиции достаётся остаток. Эта формула
независимо воспроизводит выбранные примеры. Её обобщение на все отрицательные
итоги, нулевые суммы долей и произвольные вещественные значения — **гипотеза**,
а не заявленная полная спецификация native алгоритма.

## Контракт и границы подтверждения

Предложение — [contract.md](contract.md), машинная схема параметров —
[parameter-schema.proposal.json](parameter-schema.proposal.json), карточка типа —
[node-card.proposal.json](node-card.proposal.json). До этапа 1 они не регистрируют
runtime type. Все поля схемы снабжены description, enum строковые.

Покрыто: заданные доли, одно строковое групповое поле, строковые наименования,
вещественные Total/Share, все четыре метода балансировки на приведённом
fixture, отсутствие округления, precision=0, multiple=3, NULL/пустая строка,
unmatched, неуникальный итог и обновление источников того же формата.
Не проверено: все native границы редакторов, другие типы ключей, целочисленные
Total/Share, несколько разгруппируемых полей, произвольный выходной mapping,
нормирование вырожденных долей, все варианты округления отрицательных итогов,
сезонность, переменные, обучение сезонной модели, перенос дополнительных
неназначенных полей входа 0. Будущий handler должен
отклонять неподдерживаемый режим до мутации, а не подменять его вычисляемыми
долями или JavaScript.
