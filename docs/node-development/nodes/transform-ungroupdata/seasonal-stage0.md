## Выбор и роли

Префикс этого сеанса: `MF;TF-2;WizrdMCF;`, страницы `UngroupDataWizard`
и `UngroupDataWizard-1`. Номер вкладки — пример, не стабильная identity.
В `pedUngroupMethod;ValueControl;boundlist` выбран пункт
`С_учётом_временных_колебаний_и_сезонности_опорных_данных`.
Далее появляется «Настройка порядка следования данных».

Group связан только с Group. Total — «Разгруппируемое», Weight — «Поле с
долями», Item — «Поле с наименованиями». Period на обоих входах назначен
«Порядковое поле», **не связан как группа**: иначе прошлые и будущие даты
не задают один временной ряд. Для Period использованы дата/время,
для Total/Weight — целый непрерывный тип, Group/Item — строковый.
Импорты: `ImportTextFilePreviewWizard;edtFileName;ValueControl`, затем
`ImportTextFileParamsWizard;ColumnDefsTuning;btnRefreshAll` при первом
добавлении Period; DateTime подтверждён и в импорте, и в выходном preview.

Роли меняются через `colUngroupUsageType_Period` /
`colSupportUsageType_Period`, редактор `grdUngroupColumns` /
`grdSupportColumns;tbl;celleditor;cbx`, список `;boundlist;Порядковое_поле`.
Нужны раскрытие picker и Enter; наличие скрытого boundlist не доказывает
выбор. На следующей странице `txtUngroupColumn` и `txtSupportColumn`
показывают Period. Сохранённые значения перепроверены повторным открытием.

## Настройки второй страницы

Все приведённые `ped...` — относительно `UngroupDataWizard-1`, значение
читается из `;ValueControl input`. Переменные не использовались.

| Поле | Наблюдённое значение / поведение |
|---|---|
| pedSeasonalityPeriod | С датой: Год, Квартал, Месяц, Неделя, День, Час, Нет сезонности |
| pedSeasonalityMultiplier | 1; блокируется при «Нет сезонности» |
| pedNumSeasonalIndexes | 12; число выходных столбцов индексов, не число месяцев входа |
| pedMaxRareDensity | 0.25 |
| pedAbsentPeriodFraction | 1; блокируется без сезонности |
| pedAbsentDataPoints | 10, заблокировано при Год; доступно без сезонности |
| pedNoveltyPeriodFraction | 1; блокируется без сезонности |
| pedMaxDepthPeriodFraction | 0, все периоды; блокируется без сезонности |
| pedMaxDepthDataPoints | 100, заблокировано при Год; доступно без сезонности |

Год × 1 и 12 индексов — исследованный вариант месячной годовой сезонности.
Прежний task с «календарным месяцем» и связью Period→Period исправлен как
черновик этапа 0. Другие периоды присутствуют в UI, но их численные результаты
и режим без сезонности не проверялись. До появления страницы пустые input
не являются её умолчаниями.

Установка числа индексов 0 оставляет страницу и даёт native отказ Next.
`pedNumSeasonalIndexes;ValueControl input[data-errorqtip]` сообщает минимум 3;
`msgbox-1;cnt;cnt;MessagesView`: «Значение этого поля не может быть меньше 3».
Это отказ валидации, не вычисление нулевого числа индексов. Значение
восстановлено в 12. Пустой редактор числа отдельно не проверялся.

## Порты и выходные типы

Два входа и два выхода сохраняются. Execute достаточен для получения
результатов на этих входах; отдельная команда Teach не вызывалась.
Повторное Execute после изменения источника того же формата пересчитывает
обе таблицы. Saved-model apply без переобучения не исследован.

Чтение: `Graph;Разгруппировка:_Total;Output_Data-0` / `Output_Data-1` →
`mn;mniShowDataPreview` → `ModelForm;PreviewWindow[/-1];PreviewForm;DataSetForm`.
Имена/типы — `normalHeaderCt;<имя>` и CSS `dtString/Integer/DateTime/Float-before`,
строки — `normalHeaderCt;<имя>_<номер>`. Скрытые прежние PreviewWindow
не считаются текущим портом; у таблиц различаются полные префиксы окон.

На сконфигурированных из прежнего пакета импортах порядок порта 0:

| Поля по порядку | Тип |
|---|---|
| Group | string |
| Total, Total_Rounded | integer |
| Item | string |
| OutputValue | integer |
| Period | datetime |
| ConfidenceBandUpper, ConfidenceBandLower, OutputTrend | integer |
| OutputSI | real |
| OutputVT | integer |
| OutputVTDesc | string |

Это **12 столбцов** вместо пяти shares/computed. Порядок у нового импорта
может зависеть от его mapping; task явно задаёт порядок проверяемого выхода.
Для real Total типы деталей/границ этим опытом не установлены.

Порт 1: **Item:string, Group:string, UngroupQuality:real,
SeasonalIndex1…SeasonalIndex12:real**, 15 столбцов именно в таком порядке.
Это показатели по позициям, а не ещё одна детализация по будущим датам.
Число индексов задаётся в мастере, готовые сезонные индексы через отдельный
вход не подавались. Дополнительного порта для индексов не появилось.

## Числа и крайние случаи

Параметры: Год×1, 12 индексов, редкость .25, отсутствие/новизна 1, глубина 0,
округление и балансировка выключены. Заменялся только файл опоры/итогов,
сохранённые схемы пустых импортов не определялись заново.

| Опора / итоги | Порт 0 | Порт 1 |
|---|---|---|
| seasonal-support, сезонные итоги | январь a/b=8/92, февраль=41/59; code 0 | 2 позиции, неединичные индексы, качество отображено 0.00 |
| seasonal-constant-support, сезонные итоги | 25/75 в обе даты; trend=detail, factor=1, code0 «Разгруппированное» | 2 позиции; все индексы 1.00, качество пусто |
| seasonal-zero-support, сезонные итоги | 4 строки, detail=trend=0, factor=1, code6 «Исключено» | 2 позиции, качество/индексы 1.00 |
| seasonal-null-support, сезонные итоги | 0 строк с полной схемой | 0 строк с полной схемой |
| seasonal-empty-support, сезонные итоги | 0 строк с полной схемой | 0 строк с полной схемой |
| constant-support, seasonal-empty-totals | 0 строк с полной схемой | 0 строк с полной схемой |

Нули не нормируются в равные ненулевые доли. Полностью NULL-опора не
равнозначна нулевой. Смешанные NULL/положительные значения, отрицательные
показатели, редкие и новые позиции в этом исследовании не проверялись.
Числа real из preview приведены только с экранной точностью, не как эталон
17 значащих цифр. Пустое качество в DOM — `&nbsp;`; native NULL против NaN
точным чтением ещё не различён. В expected **предложен** null, нужна проверка
native typed-read на этапе 1; это не доказанный точный NULL.

Для постоянной целой опоры native границы отображены 24/26 вокруг 25 и
74/76 вокруг 75. Независимая формула границ не установлена. Для исходной
чередующейся опоры прежние 25/75 и 75/25 опровергнуты приведённым опытом.
Скопировать значения native estimator в oracle означало бы подменить
независимую приёмку; они не записаны в expected.

## Предлагаемая приёмка и граница готовности

[Комплект](acceptance/seasonal-proposal.md): пять task/expected, Fraction-oracle,
малые fixtures и отдельный seasonal manifest. Полный ожидаемый бизнес-выход
порта 0 — десять столбцов после явного исключения двух confidence-полей
из native mapping; порт 1 целиком. Исключение проверено в
`DerivedDataSourceOutputSocketWizard;colTargetDelete_ConfidenceBandUpper` /
`...ConfidenceBandLower`; после Done/Execute preview содержит десять полей.
Сравнитель не игнорирует дополнительные actual-столбцы.

Этот ограниченный объём **не заменяет** приёмку произвольных сезонных рядов.
Нужен выбор владельца: разрешить предложенную бизнес-проекцию как первый
этап либо сначала дать независимую спецификацию estimator/интервалов.
По стоп-условию карточки «нужен новый критерий приёмки сверх стандарта»
итог — blocked, готовность полного сезонного режима не объявлена.
Существующий runner и стандартные критерии серии/CSV/cold не меняются.
Task/oracle/expected не регистрируются и не передаются модели этим PR.

## Объём этапа 1

Собственные `client/lib/ungroup-{parameters,context,procedure,node,mappings,readback}.mjs`:
роли порядковых дат, отдельная seasonal-страница, сохранение и readback её
значений, учёт двух выходов, реальных integer-типов, исключений output mapping.
Текущий context видит только первую страницу, допускает лишь прежние роли;
node/readback закреплены на shares и порт 0. Заимствовать computed-изменения
или менять его семантику этой карточкой не предлагается.

Аддитивная регистрация mode/schema/типа/readback, собственный файл навыка
и пять сценариев существующего run-check. Generic API уже допускает read
двух портов; новый механизм проверки, packages/agent, deadline и общие
контракты менять не требуется по результатам исследования. Если реализация
покажет обратное — отдельный stop, не разрешение общего изменения из docs.

Оценка ограниченного набора: **3–4 цикла** с живым бизнес-прогоном в каждом:
настройки/сохранение; оба выхода/типы/mapping; крайние входы; серия приёмки.
Непостоянный estimator и доверительные границы в эту оценку не включены:
сначала нужен независимый oracle. Без него оценивать полный этап 1 преждевременно.
Размеры поверхностей: [seasonal-budgets.md](model-contract/seasonal-budgets.md).

## Ограничения и сохранение

Ни одна исследованная настройка не объявлена «ограничением платформы»:
сезонный UI и оба результата доступны в 7.4.2. Неизвестная формула — пробел
приёмки, не доказательство отсутствия функции. Нижняя граница 3 — наблюдённая
валидация платформы. Другие типы/периоды не проверены, не названы отсутствующими.
Разрывов сеанса и переподключений при исследовании не было.
Сырые DOM-снимки и пакет не коммитятся; сохранённая копия и входы находятся
только в собственном каталоге пары. Модельных PASS, CSV/cold и red→green
runtime на docs-этапе нет; сборка CLI по назначению не выполнялась.
