# Факторный анализ (`research.factor_analysis`)

Предложение LAB-1022 для отдельного утверждения; установленный skill не меняется.

Прочитай карточку типа в `dock_action_describe`. Настройки находятся в
`parameters.factor_analysis`. `features` — полный набор технических имён
непрерывных Integer/Real признаков в порядке входных полей; переданный набор
заменяет роли, RowID и текст не выбираются. Пропущенные настройки существующего
узла сохраняются. Переменные не поддерживаются.

`pca_fixed` задаёт `factors`; `pca_auto` — `selection.criterion` eigenvalue
или variance и `threshold`. Eigenvalue-порог 0,1…1,5, variance 1…100%.
Не совмещай selection и factors. Новый узел требует features, rotation и
один способ отбора. Граница eigenvalue ровно на собственном значении пока
не входит в предложение. `rotation` задаётся явно: none, varimax, quartimax;
native default Varimax. Оба вращения используют Kaiser-нормировку.

`output_cap` — максимальное число физических Factor-колонок в обоих портах;
null выключает ограничение. Это отдельная настройка от числа обученных факторов.
Без cap native сохраняет P Factor-колонок по числу признаков. Неиспользованные
scores — NULL, нагрузки — 0. Константные признаки имеют нулевые нагрузки;
запрошенные сверх ранга компоненты не превращаются в выдуманные факторы.

Для обучения Execute обязан явно выполнить Teach текущего источника перед
обычной активацией. Одна активация применяет сохранённую модель. `apply` —
только существующий обученный узел, без Teach и перенастройки; сохрани точные
настройки модели, используй inputs:[], mappings:[], finish:execute.
После замены файла проверь свежий вход; старый fit не выдавай за новое обучение.

При NULL статистика обучения использует marginal means/SD каждого поля и
pairwise raw moments пар. Это отличается от pairwise Pearson с попарными
средними. Строки с пропуском сохраняются, их scores NULL; не заполняй и не
удаляй их самостоятельно. All-NULL, все константы и не-PSD матрица здесь
не обещаются. Исходные значения и типы сохраняются.

Прочитай оба полных порта: 0 — факторы и исходные поля, 1 — ColumnName,
ColumnDisplayName и нагрузки Factor1…FactorP с учётом cap. При смене cap
проверяй фактическую схему. Обработчик закрепляет порядок через autosync=false;
публичные mappings оставь пустыми. Знак фактора общий для scores и нагрузок
этого фактора, а не для отдельных ячеек. Экспортируй обе таблицы и сохрани пакет.
Oracle и ожидаемые числа в пользовательское задание не включай.
