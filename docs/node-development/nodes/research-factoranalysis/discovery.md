## Выходы, точность и жизненный цикл

«Готово» сохраняет настройки. Выполнение не обученного узла через
`mn;mniActivateNode` дало ошибку; `Graph;<узел>;Status` открыл причину:
**«Модель не построена. Необходимо обучить узел перед применением»**.
`mn;mniTeachNode` обучает, после него нужна отдельная активация.
Подтверждённый образец для реализации — существующий `trainConfiguredNode`
и `datamining.clustering`, а не новый общий lifecycle.

Полные таблицы прочитаны через `Output_Data-<порт>` →
`mn;mniShowDataPreview`. В Preview есть вкладки «Факторы» / «Факторные нагрузки».
Заголовки привязаны к `ModelForm;PreviewWindow;PreviewForm;DataSetForm;normalHeaderCt;<имя>`.
Типы сверены с `FColumnInfosStore` видимого DataSetForm; значения — из уже
загруженного `$FHelper.$FData[0].$Values` того же видимого источника, без
вычислителей, перехвата JS, server RPC или подмены Loginom.
Обычное отображение округляет Real до двух знаков и само по себе не доказывает
допуск 1e-8; сравнение использовало полные кэшированные числа.

| Порт | Поля в первом профиле | Типы / порядок строк |
|---|---|---|
| 0 | Factor1, Factor2, Factor3, RowID, X, Y, Z, Tag | Real×3, Integer, Real×3, String; исходные 8 строк |
| 1 | ColumnName, ColumnDisplayName, Factor1, Factor2, Factor3 | String×2, Real×3; X, Y, Z в порядке входных признаков |

Метки факторов — «Фактор1»…«Фактор3»; метки первых двух полей нагрузок —
«Имя», «Метка». При K=2 и P=3 native оставляет **P=3** полей факторов:
Factor3 во всех scores — **NULL**, в нагрузках — **0**. Это разные значения.
Число выбранных факторов нельзя превращать в предположение о числе колонок.

Oracle `acceptance/oracle.py` — Python stdlib, симметричный Jacobi eigensolver,
не импортирует runtime и не читает Loginom. Данные matrix.csv построены из
всех восьми сочетаний u/v/w=±1: X=3u+v, Y=3u−v, Z=2w.
Корреляция X/Y=0.8, X/Z=Y/Z=0; λ=**1.8, 1, 0.2**.
Нагрузки `L=V sqrt(λ)`:

| Признак | Factor1 | Factor2 | невыбранный Factor3 |
|---|---:|---:|---:|
| X | 0.9486832980505138 | 0 | 0 |
| Y | 0.9486832980505138 | 0 | 0 |
| Z | 0 | 1 | 0 |

Scores: `(x−mean)/population_SD · V / sqrt(λ)`, Factor1=u, Factor2=w.
Максимальная ошибка нагрузок **3.4e-16**, scores **4.5e-16**;
исходные значения и все NULL совпали. Порядок факторов — убывание λ,
без перестановок при различных λ. Знак одного фактора может меняться только
согласованно во всех строках нагрузок и scores. Сравнение абсолютных ячеек
по отдельности ошибочно и не предлагается.

Замена файла **того же** импорта на update.csv (X+10, Y−4, Z×3), затем обычная
активация **того же** факторного узла без обучения дала Factor1=0/2,
Factor2=±3: применена прежняя модель, а не выполнен скрытый fit.
Переобучение запускалось, но полный свежий readback после него не получен:
раннее чтение увидело ещё не заполненный кэш. Это **not_checked**, не PASS.
`expected-update.json` — независимое предложение, а не наблюдённый успех.

При новом профиле сохранённая исходная модель открылась неактивной;
обычная F9 без настройки/обучения вновь дала исходные scores ±1 и NULL.
Однако естественный порядок порта 0 стал
**Factor1, Factor2, Factor3, X, Y, Z, RowID, Tag**.
Значения сверены по техническим именам; точный порядок не прошёл будущую
приёмку. Для требуемого стабильного порядка предлагается существующий
output mapping с autosync=false; его настройку и cold сохранение ещё нужно
проверить в этапе 0/1. Не обходить проблему unordered/column_order:any.

## NULL и границы

null.csv отличается Y=NULL в строке 3. После штатных train и execute:
все 8 исходных строк сохранены, Y в строке 3 остаётся NULL; оба её выбранных
scores — NULL. Невыбранный Factor3 по-прежнему NULL. Native обучился,
нагрузки изменились: например X/Factor1=0.9440688537284835.
Независимые варианты complete-case PCA и обычной попарной корреляции этим
нагрузкам не совпали. Точная политика обучающих статистик с NULL **не установлена**;
не утверждать listwise deletion, mean imputation или pairwise Pearson.
Этот опыт — характеристика границы, не готовый численный oracle NULL-обучения.

Предложение первого среза: полные конечные числовые признаки, ненулевая
дисперсия, полный ранг; неизвестные/неподдержанные входы явно отказывать до
обучения. Пропуски в используемых признаках не превращать в нули и не удалять
без отдельного решения. constant.csv подготовлен, но не запускался;
пустой вход, коллинеарность и K выше ранга — not_checked, отдельный будущий срез.

## Предложение контракта и комплект

`fixtures/type-card.proposal.json` содержит `NODE_TYPES.semantics` и полную
предлагаемую карточку. `parameter-schema.proposal.json` — только
`parameters.factor_analysis` с features (технические имена), factors и
строковым enum rotation=["none"]. У каждого свойства/элемента есть description.
Отдельный объект предотвращает коллизию со schema features Кластеризации.
У нового узла требуются все три поля; существующий пропуск сохраняет,
переданный набор признаков полностью заменяет роли. Числовые native enum
не передаются модели. Existing `{}` сохраняет только поддерживаемые настройки.

Компактный readback: identity узла и источника/порта, mode, полный список
features в фактическом порядке, factors, rotation, native критерий fixed,
состояние trained/not_trained, схемы и индексы обоих портов. Табличные данные
и полная модель в нём не дублируются. Для pca_fixed Execute — train/retrain,
затем execute, чтение обоих выходов; отдельный apply вне предложения этапа 1.

`acceptance/task.md` содержит только пользовательскую задачу; `data/` — только
входы. Oracle и expected в модель не передавать. Основной expected:
ordered=true, column_order=exact, output_port=0/1; исходные значения, строки,
типы и NULL точно; выбранные scores/нагрузки abs=1e-8, rel=1e-10.
Метки, не заданные пользователем, label_any=true. Основной набор 8/3 строки;
два CSV, Save и штатный cold-check обязательны на этапе 1.

Oracle сравнения принимает нормализованный JSON двух таблиц, выравнивает
**один общий знак на фактор по нагрузкам** и проверяет обе таблицы целиком.
На прочитанном matrix проверен успех, общий переворот Factor1 — успех;
изменение одной нагрузки, только scores, NULL, типа, порядка — отказ.
Это адресная офлайн-проверка oracle, не новая производственная приёмка.

## Общий блокер и размеры

W1 (train/execute) уже имеет обучаемый образец; W2 (допуски/порядок) и W3
(несколько портов) существуют в базе. W5 автоматического отбора не нужен.
Но `scripts/node-acceptance/expected-outputs.mjs` сравнивает каждую числовую
ячейку отдельно (`matchesCell`) и не умеет совместно выравнивать знаки двух
портов. `cold-check.mjs` использует этот matcher. `run-check.py` также
самостоятельно проверяет CSV. Одной аддитивной регистрации типа/сценария
недостаточно для критерия владельца «с точностью до знака фактора».
Менять ожидания после просмотра факта, считать abs каждой ячейки или ослаблять
допуск до принятия обоих знаков нельзя.

**Стоп LAB-776: требуется решение о минимальном общем подключении sign-aware
oracle к main/CSV/cold приёмке. Общий код не изменён.** До решения и закрытия
открытых пунктов подплан остаётся discovery_required; ready_for_development
