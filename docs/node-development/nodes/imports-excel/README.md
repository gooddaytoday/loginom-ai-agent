## Состояние

Обработчика нет; статус `discovery_required`. Две последовательные карточки Multica: сначала этап 0 — живое исследование, контракт и независимые ожидания; затем этап 1 на принятом SHA той же ветки. Type/mode `imports.excel` / `xlsx` подтверждает discovery. Владелец 2026-10-07 согласовал первый срез и W1 (бинарная доставка, представление вложения для модели и полная warm/cold проверка источника/результата); W2/W3 отложены. Готовность реестра не повышалась.

Ветка `excel-import`, один новый PR в `loginom`; исходная база `ef84e68a22bd46f3f24549edd829cfb293836703` после слияния PR #36. Вторая карточка остаётся в Backlog до независимой приёмки исследования. Источник выбирается автоматически только при однозначности; иначе нужны варианты и уточнение. Это не включает автоопределение столбцов. В первую приёмку входят все ячейки малых книг и 20 789 строк большой книги, включая порядок. Desktop, merge и release не назначены.

Внешняя среда первых карточек: Loginom Server Linux с доступным Excel importer, собственные XLSX fixtures и независимый writer/reader; ожидается 7.4.2, фактическую версию фиксирует discovery. До W1 квалифицировать native/диагностическую загрузку fixture без объявления продуктового XLSX CLI PASS. Windows для xls и контролируемый HTTP(S)/Basic-сервис нужны только этапу 2. Если среда/компонент недоступны — Blocked, документальное покрытие сохраняется.

## Планируемый объём по этапам

- Этап 1 — Одна xlsx-книга, один лист или named range, A1/R1C1 диапазон, заголовки/пустые строки, вручную закреплённые типы; автоопределение Нет.
- Этап 2 — r04, r05, r06, r07: три политики и same-node A/B→B/C, несколько файлов/маски/параллельность, provenance/mtime, URL/Basic, xlsm/xls, метки/clone; допуск W2 до реализации.

Файловые/внешние/переменные результаты требуют соответствующего независимого аудита; существующий cold-check покрывает только табличные выходы. CLI, UI, E2E и модельная приёмка при переработке документации не запускались.
