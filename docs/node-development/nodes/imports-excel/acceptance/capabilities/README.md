Это **предложение владельцу**, а не регистрация новых режимов или автономная

## Входы и oracle

`fixtures/` содержит 13 небольших книг, суммарно 70 003 Б. XlsxWriter 3.2.9
создаёт OOXML, xlwt 1.3.0 — BIFF8/OLE XLS. `format.xlsm` имеет правильный
macro-enabled content type, без VBA-проекта; переименование XLSX не используется.
Все источники имеют фиксированные значения до Loginom. `manifest.json` фиксирует
размеры и SHA256 исходных байтов. У XLS отдельные значения 71/710, 72/720:
старый preview XLSM с 1/10, 2/20 не доказывает успешного чтения XLS.

Независимые OpenPyXL 3.1.5 и xlrd 2.0.2 читают исходные книги; `oracle.py`
не импортирует Loginom, runtime или actual-результат. Он проверяет manifest,
типы Python (`bool` отдельно от `int`), все клетки и воспроизводит `expected.json`.
Ожидания схемных политик заданы как предложение семантики; это не догадка о PASS
фактического обработчика. Многократные заголовки соединяются `_` по наблюдённому UI.

```sh
python3 -m venv /your/private/excel-env
/your/private/excel-env/bin/pip install -r requirements.txt
/your/private/excel-env/bin/python generate-fixtures.py
/your/private/excel-env/bin/python oracle.py --check
```

Генератор воспроизводит книги с фиксированными ZIP timestamps и порядком entries.
Не запускайте его поверх источников уже идущего живого сценария.
`oracle.py --check` сверяет комплект, **не выполняет Loginom**.

`expected.json` — контейнер `cases` с предложенными стандартными таблицами,
которые следующий этап выделит в отдельные scenario fixtures. Он пока не
зарегистрирован в `run-check`. Не подавать весь контейнер stock matcher как
одну принятую задачу. Модели передаются только соответствующий `task-*.md` и
нужные исходные книги; oracle, expected, manifest и карточки не передаются.

Порядок — сначала повседневные статические книги, затем несколько файлов и
происхождение, потом новые форматы/переменные и динамическая схема. Один цикл —
один будущий PR; ни один цикл этим комплектом не разрешён к реализации.

В C8 основная задача проверяет `all`. Для `none` и `new` существующие определения
сохраняются **по позиции**, не по имени заголовка: AB→BC даёт прежние A,B со
значениями 20,2. Новый заголовок C в уже существующей позиции не добавляет поля.
`new` добавляет новые позиции: AB→ABD даёт A,B,D; в живом обратном случае
BC→AB сохранились B,C с 1,10, а BC→ABD добавило D со строкой `new`.
Отдельная задача смены типов: types-a→types-b,
автоматически определить текущий строковый Value без потери `text`. В живом
Execute Value изменился integer→string, строки 1/10 → 2/`text`, тот же node GUID.
При «Нет» на сохранённых определениях B,C получен B20,C2; сохранение ранее
добавленного при Execute D требует отдельного Save/cold и не предполагается.
Эти
предложения должны быть сопоставлены с наблюдениями политики и утверждены;
исчезновение A при `all`, тип NULL-only поля и порядок новых полей нельзя принять по одному
успешному row count. Обязателен отдельный same-node Execute без повторного
восстановления схемы и сохранённых пользовательских настроек.

## Происхождение и недоступная среда

C5 покрывает все семь вариантов `Нет`, имя, относительный/абсолютный путь,
и каждый из трёх с временем. Для `Нет` достаточно стандартной 2-полевой таблицы.
Для остальных предложены FileName:string и, при запросе, FileTime:datetime после
Id,Amount. Значения пути и mtime нужно связать с серверными файлами до запуска.
`expected.json` оставляет environment bindings явными. Нельзя подставлять время
из самой выходной таблицы, локальной файловой системы или ZIP; сравнение только
отформатированного DOM-времени теряет секунды и не является oracle.

Доступ к абсолютной файловой системе сервера не предоставлен в назначении как
независимый источник истины. Наблюдено виртуальное файловое хранилище и его UI;
обход к реальному пути ОС не предлагается. Нужен допуск владельца к проверке
серверной метаинформации штатным source receipt либо отдельный стенд.

Для HTTP/Basic не дан собственный reachable endpoint и защищённое подключение.
Внешние адреса не угадываются; локальное скачивание/конверсия не заменяют эту
возможность. `{{OWNED_HTTP_URL}}`/`{{BASIC_CONNECTION}}` в задаче — обязательные
неразрешённые bindings, не готовый к запуску тест. Доступность HTTP не считается
отрицательно доказанной одним отсутствием fixture. Basic password не помещается
в карточку типа, task, URL, git или expected.

## Приёмка будущих циклов

После утверждения: red→green production-кода, обязательные проверки изменённых
путей, cold-check пакета, исполнитель ≥2 PASS из 3 и независимый проверяющий
≥2/3 на **том же SHA**, каждый раз новый чат/профиль/пакет. Только `run-check
start` + foreground `wait`, стандартные CSV/Save/cold/cleanup. Без сравнения
полной таблицы и сохранённых настроек preview не означает PASS.

Ручные DOM-наблюдения этапа 0 не подменяют эту приёмку. Новых механизмов
верификации и зарегистрированных сценариев здесь нет. C5/C7/C8/C10 требуют
согласования указанных ниже общих границ до работы с runtime.

## Предложения выдачи модели

`card-current.json` — текущая карточка `dock_action_describe` на базе назначения,
хеши заменены 64 нулями. `card-proposed.json` — размерная и контрактная заготовка;
не загружать её как принятый контракт. Значения новых пределов 64/1000 —
предложение, а не пределы Excel или UI. Проверки верхних границ и 65/1001 должны
быть добавлены при утверждении этих пределов. Множественная доставка, разрешение
масок и сохранение bindings требуют отдельного решения; один `source` не
доказывает все файлы списка. Для HTTP секретный параметр не предлагается.

`node-reference-proposed.md` — полный текст отдельного файла узла для оценки
бюджета. `skill-routing-proposed.txt` — необязательная замена существующей строки
таблицы маршрутизации (100 Б вместо 99). Установленный SKILL.md остаётся 39 954 Б;
замена строки дала бы 39 955 Б. Новые абзацы в него добавлять не требуется.
