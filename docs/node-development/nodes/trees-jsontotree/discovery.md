# JSON в дерево → Дерево в таблицу: этап 0

Исследование LAB-536, 2026-10-30. База runtime:
`2098aafcf46eaea118b18cb529f6bf045a5704eb` (`v038`).
Loginom **7.4.2**, версия прочитана из `LoginForm;Login;lblProductVersion`.
Стенд — `https://app.loginom.ai/app/?testable=true`, собственный новый черновик
под worker назначенной пары. Сборки CLI, модельной приёмки и cold-прогонов нет.
Ниже — наблюдения UI и предложение v0.3.9, не PASS обработчиков.

## Наличие, идентичность и порты

Оба компонента присутствуют в группе **Дерево данных**. Префикс сценария в этом
черновике — `MF;TF-1`; он не является постоянным идентификатором.

| Компонент из назначения | Палитра: суффикс `ModelForm;colVendors_Компоненты>` | Порты на графе |
|---|---|---|
| `component.trees.JSONToTree` | `Дерево_данных>JSON_в_дерево;TreeText` | `Input_Data-0` → `Output_DataTree-0` |
| `component.trees.TreeToData` | `Дерево_данных>Дерево_в_таблицу;TreeText` | `Input_DataTree-0` → `Output_Data-0` |

Каждый имеет один основной вход и выход. Без подключённого источника мастер
открывается, но это не означает возможности выполнить узел без данных.
Древовидная связь реально создана между `Output_DataTree-0` и
`Input_DataTree-0`. Дерево передаётся непосредственно портом, без JSON-строки,
табличного посредника или повторного импорта. Табличный вход первого узла
подключён к выходу собственного импорта `documents.csv`.

**Native FullType — `not_checked`.** Отдельного поля FullType на исследованных
поверхностях с `data-tid` нет. Component ID назначения, название, класс страницы
мастера и иконка не считаются доказательством native FullType. Для будущей
регистрации требуется штатное чтение идентичности либо согласованная владельцем
привязка GUID/workflow/портов/мастера; внутренние обработчики JS не вызывались.

После Execute автоматические подписи меняются на `JSON в дерево: Document` и
`Дерево в табл.: id, active, sku, qty, price, note`; меняется и текстовая часть
`data-tid`. Future handler должен сохранять GUID, заново наблюдая DOM.

## Мастер «JSON в дерево»

Корень `WizrdMCF`; страницы, обнаруженные в собственном мастере:

1. `TuneDataSourceInputPortWizard` — «Настройка входных столбцов»; при уже
   подключённом и сопоставленном входе эта страница может пропускаться.
2. `JSONToTreeWizard` — «JSON в дерево».
3. `DataTreeNodesMappingEngineOutputPortWizard` —
   «Настройка соответствия между деревьями данных».
4. `DoneWizard` — «Описание узла»; `btnDone`, `btnExecute`, `btnClose`.

Наблюдаемые параметры страницы `JSONToTreeWizard`:

| `data-tid` после корня страницы | Смысл и наблюдение |
|---|---|
| `pedSourceColumn;ValueControl` | Обязательное строковое поле; список предложил `Document`, без целого `RowID` |
| `pedDateTimeFormat;ValueControl` | По умолчанию `YYYY-MM-DDThh:mm:ss`; даты в fixture не используются |
| `pedBuildTreeAuto;ValueControl` | Автоопределение структуры; исходно off, для исследования включено |
| `pedRootExcluded;ValueControl` | Исключить корневой узел; сохранено off |
| `pedStrictMode;ValueControl` | Строгое соответствие структуры; сохранено on |
| `pedRootGeneration;ValueControl` | При автоструктуре доступны «Автоопределение», «Всегда массив», «Всегда не массив»; выполнен только auto |
| `trpJSONTree`, `btnBuildTreeTemplate`, `btnLoadByXSD` | Дерево структуры, построение шаблона, загрузка схемы; ручная структура/XSD не выполнялись |

Checkbox читать по состоянию компонента (`x-form-cb-checked`), а не
`input.checked`: скрытый input давал false и для визуально включённой настройки.
Root selector недоступен до включения автоструктуры. Первое соответствие деревьев
до Execute содержало только Root; после выполнения и повторного открытия
появилась фактическая структура. Пустой первоначальный mapping не доказывает
пустой результат.

`btnNext` без выбранного JSON-поля дал «Переход запрещен» / «Это поле обязательно
для заполнения». Причина прочитана из `WizrdMCF;btnError[data-qtip]` и штатного
`msgbox;cnt;cnt;MessagesView`. Диалог закрыт штатно.

## Мастер «Дерево в таблицу»

Входной мастер дерева, `TreeToDataWizard` («Выбор узлов дерева»), выходное
сопоставление и `DoneWizard` составляют маршрут. Пустой источник первоначально
показывает только Root. После выполнения JSON-источника дерево содержит
`Root > id, active, items > sku, qty, price, note`.

- `colNodes_0>Root>items>sku;TreeCheckbox`: выбор leaf автоматически выбирает
  `items` и `Root`, оставляет sibling leaves невыбранными.
- `btnSelectAll`, `btnDeselectAll`, `btnReverse` — отдельные команды состава.
- В массиве есть отдельный «Глобальный индекс узла», в основном случае он
  **не выбран**; это служебная колонка, не поле исходного JSON.
- `pedRepeatParentNodeValues;ValueControl` — дублировать родителей; исходно on.
- `pedCompositeColumnNames;ValueControl` — составные технические имена; off.
- `pedCompositeColumnDisplayNames;ValueControl` — составные метки; исходно on,
  в проверенном сценарии off.
- `pedCompositeDisplayNameSeparator;ValueControl` — точка, вертикальная черта,
  пробел, дефис, подчёркивание. При выключенных составных метках недоступен;
  сохранена точка. Стрелки `->` в этом списке **нет**.
- Выход отдельно открывается как `DerivedDataSourceOutputSocketWizard`;
  отображает все шесть имён, типов и порядок. Вход/выход не настраивать ради
  обычного чтения: Loginom предупреждает о деактивации узла.

Нулевой выбор → `btnError[data-qtip]` «Не выбрано ни одного узла с данными»;
эта же причина прочитана в штатном диалоге. Мастер предлагает «Всё равно далее»;
будущий handler должен отказывать до мутации, а не обходить проверку.

## Выполненные наблюдения на малом fixture

До исследовательского Execute записаны `fixtures/`, бизнес-task, независимый
Python oracle и основное `expected.json`. Табличное ожидание после наблюдений
не менялось. Древовидная нормализация уточнена по наблюдению missing scalar →
NULL до любых модельных/cold-прогонов. Вариант no-repeat рассчитан отдельно
до его исследовательского Execute.

| Проверка | Наблюдение |
|---|---|
| `documents.csv` → JSON auto → table, repeat=true | 1 документ, 4 строки A/B/C/D, 6 полей в порядке `id, active, sku, qty, price, note` |
| Типы из выходного мастера | `dtInteger, dtBoolean, dtString, dtInteger, dtFloat, dtString` |
| Количества/цены | qty `2,0,3,1`, сумма 6; price `1.25,0.50,2.00,0.50` |
| Большое целое | Все родительские id отображаются как `9,007,199,254,740,993`; это исходное `9007199254740993`, не округлённое double |
| NULL / пустая строка | note A и D — NULL; B — пустая строка; C — `x` |
| repeat=false | Те же 4 строки; id/active только в первой, последующие ячейки имеют `bg-cell-null-value` |
| Свойства после повторного открытия | JSON поле Document, auto=true, strict=true, root exclusion=false, root=auto; выбор и параметры таблицы сохранены в текущем черновике |

Таблица прочитана через собственный
`ModelForm;PreviewWindow;PreviewForm;DataSetForm;normalHeaderCt;...`.
NULL подтверждён классом `bg-cell-null-value`: пустые отображения числового
родителя при no-repeat и строковой пустоты B визуально похожи, но B этого
класса не имеет. Чтение 24 ячеек UI не доказывает универсальную точность real64.
Здесь все цены двоично точны; приёмка потребует полного проверенного readback.

Дерево просмотрено через
`PreviewWindow;PreviewForm;DataTreeForm;colTreeNode_Root>0;TreeExpander`.
Root имеет id, active и четыре последовательных экземпляра items; каждый
экземпляр раскрыт. **Отсутствующий `/items/3/note` тоже материализован как
leaf note=NULL.** Явный null и missing scalar уже неразличимы в этом дереве;
обещать обратимое восстановление исходного JSON нельзя. Пустая строка сохранена.

В меню собственных узлов присутствует `mn;mniTeachNode` («Обучить узел»).
Для JSON команда штатно вызвана; отдельного отказа/диалога не наблюдалось.
Основные значения получены через Execute обоих мастеров. Наличие общей команды
не доказывает обучаемую модель: отдельные train/apply контракты и сохранённое
состояние обучения не исследованы. Предлагается один режим исполнения с
автоструктурой, без обещания ML train/apply.

## Границы результата

`not_checked`: FullType; несколько JSON-строк; object/array/scalar с принудительным
корнем; пустой вход и NULL целого документа; пустой/отсутствующий массив;
sibling arrays (zip/Cartesian); mixed arrays; duplicate keys; Variant;
даты/timezone; ручная схема/strict mismatch; XSD; смена источника; сохранение и
независимое cold-открытие. Наличие edge fixtures не означает их выполнения.
Это не критерии первого ограниченного этапа, их нельзя объявлять PASS.

Для первого этапа v0.3.9 предлагается один object-документ, auto root, одна
повторяющаяся ветвь и её scalar ancestors; оба режима повторения родителей,
leaf names/labels. Остальные запросы отклоняются до мутации. Точный контракт,
общие изменения, оценка и критерии — [contract.md](contract.md).
