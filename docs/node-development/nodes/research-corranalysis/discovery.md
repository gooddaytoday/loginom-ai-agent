## Идентичность и порты

Палитра «Компоненты → Исследование → Корреляционный анализ»:
`MF;TF-1;ModelForm;colVendors_Компоненты>Исследование>Корреляционный_анализ;TreeText`.
Component ID `component.research.CorrAnalysis`, иконка `bg-vendor-icon-corranalysis`.
Native engine fulltype в сериализации сохранённого собственного `.lgp`:
**`TBGCorrAnalysisEngine`**, атрибут `CorrTypes="caPirson"`.
Vendor GUID **`1a0ef37e-bdb3-4cf1-908e-79b9b0763a6d`**.
XML узла сопоставлен с GUID того же живого узла, не только с его подписью.
Живой мастер держит `CorrAnalysisWizardVendor` и интерфейс
`$bg_rpc_TIBGCorrAnalysisEngine_Proxy`. Отдельного свойства `FullType` у этого
UI-proxy не обнаружено; getter через RPC не вызывался. Fulltype выше — native
`Engine xsi:type`, а не имя JavaScript-интерфейса или вывод из иконки.

| Порт | Native имя / метка | DOM |
|---|---|---|
| Вход, таблица 0 | DataSource / Входной источник данных | `Graph;<подпись>;Input_Data-0` |
| Выход, таблица 0 | DataSource / Выходной набор данных | `Graph;<подпись>;Output_Data-0` |

Служебные порты в native пакете: порядок выполнения (вход/выход), управляющие
переменные (вход), компонент и зависимые узлы (выход). Они не являются вторым
табличным выходом и не входят в этап 1. Индекс 0 табличного выхода подтверждён
и в DOM, и созданием Table именно в панели этого выхода.

Суффикс `TF-1` и подпись не константы. После настройки native меняет подпись:
`Корр. анализ: 2 x 2`, для одной пары — `Корр. анализ: age x blood_pressure`.
Идентичность сохраняется по GUID; метка узла в expected не фиксируется.

Корень `MF;TF-1;WizrdMCF`. Наблюдены страницы:

|---|---|
| `cbCorrTypeLinear` | Пирсон, по умолчанию включён |

Для readback имеется локальный `FColumnsStore`: `Name`, `DisplayName`,
`DataType`, `ChkFirstSet`, `ChkSecondSet`. Типы в исследованном мастере:
integer=4, real=3. Это внутренние значения UI, их не передавать модели как enum.
У ExtJS-флажка `input.checked` ложно даже при включённом Пирсоне; проверять
связанный UI-компонент / `x-form-cb-checked`, не сырой input.checked.

Без выбранных столбцов Next оставил страницу и показал `WizrdMCF;btnError`.
Нажатие открыло `msgbox;cnt;cnt;MessagesView` с причиной:
**«Не указаны столбцы для обработки»**. Диалог закрыт штатно;
«Всё равно далее» для обхода отказа не использовалось.

При изменении активного узла native предупреждает о деактивации. При замене
схемы импорта и переходе input mapping: **«Обнаружены связи с несуществующими
объектами. Вы хотите удалить все потерянные связи и продолжить?»**.
Даже после «Удалить и продолжить» старые X/Y остаются в таблице назначений.
Для age-pressure назначения X/Y явно сняты, выбран только age / blood_pressure.
Следствие для обработчика: заданный набор полностью заменяет сохранённый,
включая снятие всех незапрошенных флажков; не дополнять старый выбор.

## Полный табличный выход и порядок

Table: `MF;TF-1;ViewsForm;BrowseView[суффикс];normalHeaderCt;<имя>`.
Типы подтверждены иконками заголовков `bg-TBGDataType-dtString-before` и
`bg-TBGDataType-dtFloat-before`. Поля в native порядке:

| Имя | Метка | Тип |
|---|---|---|
| ColSet1 | Поле1.Имя | string |
| ColSet1_Label | Поле1.Метка | string |
| ColSet2 | Поле2.Имя | string |
| ColSet2_Label | Поле2.Метка | string |
| Pirson | Пирсона | real |

`Pirson` — точное native имя, не исправлять его на Pearson/Pearson_r.
Отключённые коэффициенты не добавляют колонок; исходные строки не проходят
на выход. Схема одинакова для четырёх пар и одной пары age-pressure.

Наборы X/Y × Z/W выбирались кликами **Y, X / W, Z**. Получен порядок
**X/Z, Y/Z, X/W, Y/W**: снаружи второй набор, внутри первый; оба в порядке
входных полей узла после input mapping, а не в порядке кликов/массива запроса.
Повторное выполнение на заменённых данных сохранило этот порядок.
Одинаковые наборы X/Y × X/Y дают **X/X, Y/X, X/Y, Y/Y**: self-пары и
симметричные пары сохраняются, native не удаляет их как дубликаты.
В этих опытах все четыре self/cross коэффициента равны 1.

Предложение expected: `ordered:true`, `column_order:"exact"`, `output_port:0`;
точные имена, метки, типы и NULL. Только для `Pirson` — `tolerance:{"abs":1e-6}`.
Table показывала 10 знаков после запятой; это сопоставление в отображаемой
точности. Полноточное чтение/CSV и cold-check будущего обработчика ещё должны
пройти приёмку с объявленным допуском; discovery не заменяет их.

## NULL, константы, пустой вход

`null.csv`: X=[1,2,3,4], Y=[2,NULL,6,8], Z=0, W=[3,1,4,1].
На X/Y × Z/W получено по порядку **NULL, NULL, -0.2581988897, -0.5**.
Для константного Z две ячейки подтверждены как `<null>` с
`.bg-cell-null-value` после включения `btnDataGridShowNulls`.
NULL не равен пустому тексту, нулю, NaN или бесконечности.

X/W использует все четыре строки; Y/W — только строки 1/3/4.
Глобальное удаление строки с NULL Y дало бы X/W=-0.5, чего native не делает.
Таким образом, пропуски исключаются **попарно**, отдельного переключателя NULL
в параметрах не обнаружено. При нулевой дисперсии одной стороны — NULL.
Все значения/NULL получены независимо oracle до их чтения в UI.

**Ограничение native на пустом входе:** после замены того же импорта на
`empty.csv` новая Table импорта подтвердила 0 строк. Повторная активация того
же корреляционного узла и новая Table его выхода показали прежние четыре
коэффициента 1 для X/Y × X/Y. Эти числа не принимаются как свежая математическая
корреляция пустого множества и не включены в expected. Сохранены ли прежние
значения или это отдельная native ветка вычисления на пустых рядах, не установлено. Пустой вход/полностью
пустая пара/одна совместная строка остаются адресными границами r05 этапа 3;
контракт этапа 1 не обещает их обработку. Для этапа 1 предлагаются непустой
источник и не менее двух совместных наблюдений на пару. Константное числовое
поле и частичные NULL на таком входе проверены и входят в предложение.

## Lifecycle и независимые числа

Обучающих страниц, разбиения, seed и модели в корреляционном мастере нет.
На непустом входе достаточно **Выполнить / обычная активация**. Отдельные
train/apply режимы не нужны и не предлагаются.

| Вход / пары | Oracle | Native Table |
|---|---:|---:|
| pairs.csv: X/Z, Y/Z | -1 | -1 |
| pairs.csv: X/W, Y/W | 0.4774552605594227 | 0.4774552606 |
| update.csv: Y/Z | 1 | 1 |
| update.csv: Y/W | -0.4774552605594227 | -0.4774552606 |
| age-pressure.csv: age/blood_pressure | 0.8322856293730624 | 0.8322856294 |

Импорт и корреляционный узел при pairs→update сохранили свои GUID. Файл
заменён через тот же импорт, затем выполнена обычная активация того же узла,
без вызова обучения. Прочитаны все четыре обновлённые строки.
Первый ввод URL до полной загрузки импортного мастера был перезаписан native
инициализацией: старый результат не засчитан. После ожидания сохранённого пути,
Enter и проверки нового Y=1 в preview обновление подтверждено.

Для age-pressure: все 300 исходных строк; age integer, blood_pressure real,
непрерывные; остальные поля не выбраны. Независимые средние age=43.32,
blood_pressure=117.58466666666666. Итог eval после округления:
`300,43.32,117.584667,0.832286`. В комплекте пользовательское задание с узлом
корреляции и expected для native выхода и финальной таблицы экспорта.
Средние/число строк рассчитаны oracle; полный бизнес-сценарий ещё не выполнялся
моделью. Oracle — Python stdlib, точные Fraction-суммы и Decimal sqrt, 50 знаков;
не импортирует handler/runtime и не читает фактический результат Loginom.

## Сохранение и повторное открытие

Пакет сохранён в собственном каталоге пары через штатный Save As. Его копия
скачана через Files UI только для чтения native engine type. Сырые пакеты,
журналы и квитанции в Git не включены. Штатная очистка первого профиля:
`package_closed=true`, `logged_out=true`; браузер закрыт.

Первое открытие в новом профиле подтвердило READY и тот же GUID с status=0
(не активирован). Затем появилось native «Обнаружен разрыв связи. Восстановить
сессию?»; потерянная сессия не восстанавливалась, браузер закрыт.

Повтор: в другом новом профиле создан чистый черновик для работы Files UI,
загружена побайтовая копия собственного сохранённого пакета под новым именем,
чистый черновик закрыт, копия открыта штатным prepare. Тот же GUID был неактивен.
Без настройки и обучения обычный Execute дал в **новой** Table одну строку
age / blood_pressure / **0.8322856294**. Отдельная Table входа подтвердила
**300 строк**. Это проверка native сохранения/повторного выполнения, не
cold-check.mjs и не модельный PASS.

После завершённых чтений при checkpoint Save связь снова разорвалась
(`msgbox-1;cnt;cnt`). Save этой копии и её package_closed/logged_out не подтверждены.
Потерянная сессия не восстанавливалась; браузер закрыт. Обе диагностики разрыва
сохранены вне Git в fail-logs; низкая нагрузка не объявлялась причиной и
попытки не засчитывались как приёмочные. Для основного первого профиля штатные
package_closed/logged_out=true подтверждены до этих опытов. Это ограничение
окружения завершения native диагностики, а не ослабление будущей приёмки.
Модельных прогонов 0, `cold-check.mjs` 0, сборок CLI 0.

## Контракт для модели и размер схемы

Runtime `research.corr_analysis`, строковый mode enum **`pearson`**;
числовые integer/real поля. `fixtures/parameter-schema.json` — предложение
`first_set`/`second_set`, у каждого свойства и элемента есть description.
Новый узел требует оба набора; на существующем пропуск сохраняет набор,
переданный массив полностью заменяет его. Наборы могут пересекаться.
Текстовые категории, Kendall, Spearman и взаимнокорреляция вне этапа 1;
их запрос отклонять до мутации, без скрытого включения коэффициентов.

Предлагаемый `NODE_TYPES.semantics`:

> Pearson correlation of numeric fields in first_set × second_set. Exact input
> field names, not labels. Output 0: ColSet1, ColSet1_Label, ColSet2,
> ColSet2_Label, Pirson. Rows follow second-set then first-set input order;
> self and symmetric pairs are retained. Pairwise missing-value deletion;
> zero variance gives NULL. Nonempty input with at least two joint observations
> per pair in stage 1. Execute recomputes the current input without training.
> Other coefficients and text-category encoding are unsupported.

Компактный readback: `mode`, полные `first_set`/`second_set` в native порядке,
`coefficients:["pearson"]`, source node/port, существующая идентичность узла,
схема выхода и число пар, port 0. Не дублировать весь UI или вводить receipts.

База: inputSchema dock_node_apply **45 891 Б**, предложение **46 633 Б**,
приращение **742 Б** (type enum + mode enum + два массива с описаниями).
Расчёт: `node docs/node-development/nodes/research-corranalysis/fixtures/schema-size.mjs`.
Это оценка аддитивной части до возможных дополнительных conditional guards.
Порог теста остаётся **<46 000 Б**. По решению владельца регистрация идёт в
этапе 1 после F2/LAB-516; сообщённая база F2 ≈38 900 даёт ≈39 642 Б с данным
приращением. Это арифметическая оценка, не замер объединённой головы.

W2 в базе уже поддерживает tolerance/ordered/column_order/output_port.
Других необходимых общих изменений сверх F2, аддитивной регистрации,
собственного раздела skill и сценариев run-check на исследованном срезе
не выявлено. Предварительная оценка этапа 1 — **2–3 цикла**:
контракт/мастер/readback; выход/CSV/Save/cold; правка по живому отказу и повтор.
Критерии остаются предложением до утверждения владельцем; реализация и
модельная приёмка назначаются отдельно.
