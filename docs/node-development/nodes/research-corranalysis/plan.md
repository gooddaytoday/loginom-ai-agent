## 2. Этап 1 — наборы числовых полей и Pearson

`research-corranalysis:r01`: два явных набора непрерывных числовых полей
integer/real, полное произведение пар, Пирсон, точные идентичности и метки сторон,
полный табличный выход. Создание и изменение существующего узла, полный readback,
чтение, экспорт, Save, новый профиль и cold-check.

Предлагаемая граница: непустой вход, не менее двух совместных наблюдений на
каждую пару. Частичные NULL исключаются попарно; константное поле даёт NULL.
Пустой источник, полностью пустые пары и одна совместная строка остаются r05
этапа 3; native на пустом источнике вывел значения, совпавшие с прежними. Этот результат
не принимать как свежую корреляцию и не выводить из него expected для этапа 1.
Границу явно утверждает владелец; она не является результатом реализации.

Наборы могут пересекаться: self и симметричные пары сохраняются. Поля следуют
порядку входной схемы узла после input mapping; порядок массива запроса не
сортирует результат. Снаружи второй набор, внутри первый.

### Предлагаемый API и readback

`first_set`, `second_set` — массивы точных технических имён. Полная JSON Schema
с description каждого свойства/элемента — `fixtures/parameter-schema.json`.
Новый узел требует оба непустых набора. На существующем пропуск сохраняет набор;
переданный массив полностью заменяет его, снимая все лишние флажки.
Модель получает строковый enum `pearson`, не native numeric enum/caPirson.

Semantics для NODE_TYPES — текст в discovery: точный выход, порядок, NULL,
Execute без обучения и границы метрики. Mode pearson задаёт только Пирсон;
остальные флажки выключены. Запросы иных метрик/категориального кодирования
отклоняются до мутации с понятной причиной.

Компактный readback: mode, оба полных набора в native порядке,
coefficients=[pearson], source node/port, существующая идентичность узла,
схема выхода, число пар и output_port=0. Не дублировать весь UI, receipts не нужны.

### Схема результата

| Имя | Метка | Тип |
|---|---|---|
| ColSet1 | Поле1.Имя | string |
| ColSet1_Label | Поле1.Метка | string |
| ColSet2 | Поле2.Имя | string |
| ColSet2_Label | Поле2.Метка | string |
| Pirson | Пирсона | real |

`Pirson` сохраняется дословно. Остальные коэффициенты и passthrough-поля не
добавляются. ordered=true, column_order=exact, output_port=0. Имена, метки,
типы, строки и NULL точны; только Pirson имеет tolerance abs=1e-6.

### Реализация и размер

Новые собственные `corr-analysis-{node,parameters,procedure,context,readback,output}.mjs`
и адресные тесты в client. Аддитивные регистрации NODE_TYPES/NodeType,
node-support, node-api, node-procedure, node-result-schema/user-results и
соответствующего readback; свой раздел `packages/product/skills/loginom-automation`;
собственные сценарии run-check. Образцы — Кластеризация / Линейная регрессия
для таблиц и стандартного lifecycle, без копирования их обучения.

Оценка полной inputSchema: 45 891 → 46 633 Б, **+742 Б** на базе назначения.
После сообщённого F2 ≈38 900 Б арифметически ≈39 642 Б; точный замер объединённой
головы сделать перед регистрацией. Лимит node-caption-schema остаётся <46 000.
W2 уже поддерживает tolerance/ordered/column_order/output_port; заново его
реализовывать не нужно. Иных обязательных общих правок на исследованном срезе
не выявлено. Оценка этапа 1 — **2–3 цикла** с живым сценарием между правками.

## 3. Приёмочные данные и предложение критериев

До модельных прогонов подготовлены задания, входы, независимый oracle и expected:

| Сценарий | Oracle и ожидаемые числа | Полный expected |
|---|---|---|
| X/Y × Z/W, pairs.csv | X/Z=-1, Y/Z=-1, X/W=Y/W=0.4774552605594227 | acceptance/expected.json |
| Тот же узел, update.csv | Y/Z=1, Y/W=-0.4774552605594227; X-пары прежние | acceptance/expected-update.json |
| Частичные NULL, константа Z | NULL, NULL, -0.25819888974716115, -0.5 | acceptance/expected-null.json |
| Age-pressure через узел | Native r=0.8322856293730624; итог 300,43.32,117.584667,0.832286 | acceptance/expected-age-pressure.json |

Oracle использует Python stdlib, Fraction и Decimal sqrt с 50 знаками; Loginom,
handler и фактический результат не являются входами. Manifest закрепляет входы,
типы, формат, порядок, байты и SHA256. Модель получает только задание и данные;
oracle/expected/discovery остаются вне её workspace. Свободные метки узлов не
фиксируются. label_any используется для не заданных задачей меток вычисленных
финальных полей age-pressure; native метки корреляции точны по UI.
