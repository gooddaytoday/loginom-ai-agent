# Корреляционный анализ (`research.corr_analysis`)

Предложение LAB-1022; расширения не установлены и требуют утверждения.

Прочитай карточку типа. `first_set` и `second_set` — полные массивы технических
имён; переданный массив полностью заменяет набор. Подключи таблицу к входу 0,
finish:execute, read.ports:[0]. Обучения и переменных нет.

Режимы pearson, spearman, kendall выбирают соответствующий коэффициент.
Spearman использует средние ранги совпадающих значений, Kendall — tau-b с ties.
Все пары сохраняются, включая self и симметричные. Порядок строк — второй
набор снаружи, первый внутри, в порядке входной схемы, а не массива запроса.

Числовые дискретные поля сохраняют значения. Текстовые ASCII-категории native
кодирует равноотстоящими ordinal-кодами в лексикографическом порядке, а не
порядке первого появления. Не придумывай собственные коды. Семантический
порядок категорий не следует из их названий; Unicode/case/locale collation
в данном предложении не проверена.

Порт 0: ColSet1, ColSet1_Label, ColSet2, ColSet2_Label (String), затем
Pirson, Spearman либо TauBKendall (Real) для одиночной метрики. У комбинации
native порядок Pirson, CFExtremum, TauBKendall, Spearman, затем CFLag Integer.
Не сохраняй отсутствующие метрики пустыми колонками и не угадывай состав
по прежнему результату. Читай всю таблицу, выгрузи CSV и сохрани пакет.

Cross_correlation остаётся непроверенной частью checkpoint: UI содержит
флажок экстремума ВКФ и поля CFExtremum/CFLag, но ненулевой лаг, его знак,
поиск экстремума и нормировка ещё не установлены. Не выдавай этот режим
за готовую поддержку. Пустой вход также ещё требует живого исследования;
предыдущую таблицу за свежий результат принимать нельзя.

Пирсон сохраняет прежнее попарное исключение NULL и NULL при нулевой дисперсии.
Иные NULL-политики ранговых режимов этим предложением не утверждаются.
