## Что имеет смысл предлагать модели

Наличие API в платформе не равно безопасному допуску в handler. Действующий
`javascript-module-policy.mjs:25–32` разрешает только статический builtIn/Data,
отказывает dynamic import, прямой require и другие module specifiers. Это
синтаксическая политика, не security sandbox; async-функция сама по себе этим
фильтром не запрещена. Документация и политика не означают сертификацию async.

| Возможность | Пользовательский сценарий и штатная альтернатива | Предложение / циклы |
|---|---|---|
| Две таблицы | Последовательное размещение целых заказов по остаткам контейнеров (first fit). Обычные Join/Union/Группировка не несут изменяемый остаток между решениями. Подготовлены task/data/oracle. **Но** данные можно заранее привести к размеченному Union и подать текущему одновходовому JS; отдельные входы не являются доказанно единственным решением. | Условный кандидат M1–M6, только если владелец подтверждает ценность двух прямых входов. До этого цикл реализации не назначать. |
| builtIn/Calc | Нормализация строки, regex, календарные/финансовые расчёты. Штатный Калькулятор предоставляет эти функции без расширения JS. Уникального реального плагина, нужного внутри алгоритма, в назначении нет. | 0 циклов; не открывать весь Calc ради двух диагностических функций. |
| Внешние ESM/CJS/JSON | Потенциально — существующая проверенная библиотека прикладных правил для нескольких JS. Реальной библиотеки/версии/требования повторного использования нет; x×3+7 решается Калькулятором. | 0 циклов. Для настоящего sidecar сначала отдельное решение об артефактах, зависимостях и их byte-проверке при cold. |
| Fetch | Для простого HTTP GET по строкам уже есть REST-запрос. Зависимая cursor pagination могла бы потребовать программного протокола, но конкретного API и задачи в назначении нет; одного echo GET недостаточно. | 0 новых циклов; использовать существующее [предложение Fetch/FS](fetch-fs-discovery.md), не считать его принятым здесь. |
| FS | CSV/XLSX/LGD/XML импортируются штатными узлами, экспортируются штатно. Прикладной бинарный формат без готового импортера мог бы требовать FS, но формат не задан. | 0 новых циклов. Запись/append/delete требуют дополнительных критериев по эффектам и файлам; стандартный табличный CSV oracle их не доказывает. |
| async | Может понадобиться Fetch или dynamic import. Сам Promise не даёт нового бизнес-результата; синхронный табличный расчёт в нём не нуждается. | 0 самостоятельных циклов. Проверять вместе с реальной зависимой задачей, после решения по completion/error/Stop. |

Не утверждается невозможность произвольной композиции штатного Цикла и других
узлов. Предложенный first-fit показывает необходимость алгоритма с состоянием,
а не теорему о необходимости именно второго JS-порта. Если критерий владельца
требует отсутствие даже альтернативы «подготовка + прежний JS», M1–M6 остаются
только готовым резервным комплектом, а рекомендуемый объём handler — ноль.

## Ограничения платформы и безопасности

- [Входные наборы](https://help.loginom.ru/userguide/processors/programming/java-script/input-tables.html):
  InputTable — первый InputTables; читать каждый вход по его текущим именам и
  типам. Отсутствующая таблица и таблица с нулём строк — разные случаи.
- [Calc](https://help.loginom.ru/userguide/processors/programming/java-script/calc-functions.html):
  IF/IFF и функции входного контекста не доступны тем же способом импорта.
  Плагины зависят от установки сервера. Две функции не подтверждают весь модуль.
- [Внешние модули](https://help.loginom.ru/userguide/processors/programming/java-script/external-modules.html):
  ESM и CommonJS различаются; require не предоставляет Node.js/npm.
  Внешние файлы не становятся частью LGP. Saved-путь считается от пакета,
  unsaved — от каталога пользователя; вложенный импорт — от импортирующего
  файла. Перенос LGP без sidecar меняет результат. Транзитивный импорт и код
  при загрузке способны обращаться к сети/файлам; allowlist только корневого
  исходника их не изолирует.
- [Fetch](https://help.loginom.ru/userguide/processors/programming/java-script/fetch-api.html):
  это серверный запрос, не браузерный fetch. HTTP-статус нужно отличать от
  rejection; body потребляется; собственные credentials/headers/redirects могут
  передать данные за пределы задачи. Не отключать TLS. Ограничение URL только
  в подсказке не защищает private endpoints и redirect. Повтор после
  неизвестного исхода может повторить эффект; Preview, материализация,
  Execute и cold способны исполнять программу несколько раз.
- [FS](https://help.loginom.ru/userguide/processors/programming/java-script/fileapi.html):
  синхронный API с FileHandle/ArrayBuffer; серверная область — файловое
  хранилище и права аккаунта, Desktop — права процесса ОС. Ссылки/пути и
  транзитивные модули не дают гарантии read-only. Пара с расширенными правами
  не доказывает отказ за пределами собственной области. Проверка собственного
  каталога не является проверкой изоляции. Запись/удаление и разрешённая
  загрузка модулей требуют явных границ, контроля побочных эффектов и решения
  по переносу файлов, а не одной правки module allowlist.
- Top-level await не считать поддержанным. В новой пробе await был только
  внутри async-функции. Не обещать отмену запроса/узла, обработку unhandled
  rejection, отсутствие поздней записи или одинаковый Windows/Linux без
  соответствующих сценариев.

Онлайн-Help не закреплён за 7.4.2; его утверждения выше — ограничения для
проверки, а не новые живые PASS. Предыдущее [исследование Fetch/FS](fetch-fs-discovery.md)
содержит конкретные GET/abort/FS/saved/cold пробы другого SHA и хоста; они не
повторялись в LAB-1013 и не переносят приёмку на новую реализацию.

## Условная реализация после решения владельца

Готов [приёмочный комплект](acceptance/capabilities/README.md) M1–M6:
малые CSV, независимый Python oracle, четыре expected, задачи пользователя.
Используются существующие typed CSV, Save, cold, cleanup и 2/3 + 2/3 критерии.
Новых механизмов верификации, runner или общего execution/cancellation не
предлагается. На этапе 0 model/run-check прогоны не запускались.

Если выбран прямой двухвходовый контракт: ориентир **2–3 цикла, 250–450 строк
с адресными тестами**, одна предметная правка на PR. Это оценка, не назначение.
Сначала живое чтение двух подключённых таблиц и точных native/DOM индексов,
затем red→green на production-ветке, проверки путей и сценарии через run-check.

| Файлы-кандидаты | Причина изменения |
|---|---|
| `client/lib/javascript-parameters.mjs`, `javascript-code-node.mjs` | Сейчас input0/≤1 input, один inputMapping, new/existing ограничения; добавить второй вход и сохранить старый контракт. |
| `javascript-context-read.mjs`, `javascript-managed-source-adapter.mjs`, `javascript-wizard-page.mjs` | Context имеет ровно два объекта input0/output0, port=0; нужны полный отдельный input1 и прохождение двух input-страниц без ослабления ownership. |
| `javascript-execution-continuation.mjs`, `javascript-source-admission.mjs` | Сохранять и сверять обе mappings/identities при effect, continuation и source replace. Точный diff определится наблюдением, файлы не менялись. |
| `javascript-knowledge.mjs`, JS tests и skill reference | Только проверенные дополнительные таблицы, точная граница API и отсутствие новых импортов. |
| `client/lib/node-contracts.mjs` | Аддитивная регистрация additional_tabular_inputs для этого типа; общий алгоритм links уже поддерживает дополнительные входы. Нужен локальный предел 2. |
| `client/lib/node-port-open.mjs` (возможный общий diff) | На строках 171–175 исключение native ordinal сейчас только для Union/Enrich/ColUnion. Наблюдён Data-2; если JS FPortIndex=1, потребуется добавить JS к существующему списку. Пока это риск, не подтверждённый отказ. |

Новый публичный параметр mode не нужен: сохраняется script, выбирается наличие
второго элемента inputs. Дополнение JS-specific context schema — аддитивное,
без изменения старых ветвей. Новые общие процедуры, budgets, deadline,
packages/agent, общая обработка Stop/unknown outcomes не входят в оценку.
Если без неаддитивной общей правки нельзя — blocked с вопросом до неё.
