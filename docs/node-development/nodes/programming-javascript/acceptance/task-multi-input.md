Распредели заказы orders.csv по контейнерам bins.csv в Loginom. Используй один
узел JavaScript с двумя отдельными табличными входами: заказы первым,
контейнеры вторым. Сохрани исходные таблицы самостоятельными источниками.

OrderID и Size — целые числа; BinID — строка, Capacity — целое число.
Пустая ячейка означает пропущенное значение. Обрабатывай заказы по возрастанию
OrderID. Для каждого заказа выбирай первый по BinID контейнер, в котором ещё
хватает свободного места на весь Size. Уменьшай остаток только при размещении;
пропущенный заказ не расходует место. Заказ не дели и уже размещённые заказы
не перемещай. Контейнеры с пропущенной или неположительной Capacity не используй.

Результат: OrderID (целое), BinID (строка), Allocated (целое), Status (строка),
по одной строке на заказ в порядке OrderID. Для размещённого заказа Allocated
равен Size, Status — assigned. Если места нет, BinID пропущен, Allocated равен
нулю, Status — no_capacity. Для пропущенного, нулевого или отрицательного Size
используй пропущенный BinID, нулевой Allocated и Status invalid_size.
Пустой список контейнеров допустим; пустой список заказов даёт пустую таблицу
с теми же четырьмя полями и типами.

Выгрузи результат в allocation.csv, скачай файл и сохрани пакет по указанному
пути. После нового открытия пакет должен снова вычислять распределение из
сохранённых источников. Не используй сеть или внешние файлы из кода узла.
