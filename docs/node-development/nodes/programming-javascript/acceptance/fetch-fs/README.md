# Предложение приёмки Fetch / FS

Этап 0 LAB-842. Владелец утверждает объём до handler. Ничего не зарегистрировано
в `run-check`; это не готовый сценарий его каталога и не новый cold-reader.
Основания, живые результаты и ограничения: [discovery](../../fetch-fs-discovery.md).

| Срез | Модель получает | Проверяющий получает |
|---|---|---|
| F1 | `../task-fetch-get.md`, назначенный путь пакета | `expected-get.json` |
| F2 | `../task-fetch-errors.md`, `../../fixtures/fetch-fs/requests.json` | `expected-errors.json`, lifecycle-матрицу discovery |
| R1 | `../task-fs-read.md`, пути уже доставленных `utf8.txt` / `bytes.bin` и пакета | `expected-read.json`, hashes fixtures |
| W1 | `../task-fs-write.md`, собственный разрешённый каталог и путь пакета | `expected-write.json`, независимо скачанные report.txt/report.bin |

Не передавать модели oracle, expected, manifest, discovery, Python или готовый JS.
Для каждого прогона — новые пакет, чат, профиль и изолированный подкаталог своей
пары. Не передавать модели весь репозиторий fixtures. requests.json — явные
данные пользователя, не техническая подсказка обработчику.

`python3 oracle.py --check` заново вычисляет четыре expected и сверяет manifest.
Параметр `--case get|errors|read|write` печатает соответствующий expected.
Параметр `--downloaded-files DIR` дополнительно проверяет точные report.* и
отсутствие лишних файлов В ЛОКАЛЬНОМ КАТАЛОГЕ СКАЧАННЫХ РЕЗУЛЬТАТОВ. Он не
утверждает, что на сервере нет других файлов: серверный итоговый список каталога
нужен отдельно. Результаты Python не исполняют Loginom или candidate JS.

F1 Amount — Decimal из параметров фиксированного URL, проверяется ответ сервера,
не таблица с зашитыми константами. Изменение существующего источника: отдельный
прогон с Price=4.25 и `expected-get-updated.json`, Amount=12.75; тот же узел,
остальные поля/связи/тип не менять. Задание продолжения на языке пользователя:
«В этом же источнике поменяй Price на 4.25, получи новую сумму и перезапиши get.csv.
Сохрани пакет и проверь после повторного открытия».

F2 Status — реальный HTTP-код или NULL, если ответа не получено. Обработанный
abort не равен отмене всего узла. Нативный unhandled rejection, отмена узла,
late callback, TLS и неизвестный эффект — отдельные технические случаи этапа 1,
не покрыты этими пятью строками. Endpoint `/delay/3` предварительно проверяется
на сохранение задержки; кешированный быстрый ответ делает fixture непригодным,
а не основанием подгонять expected.

R1: сначала доставить оба файла в изолированный серверный каталог, пакет
сохранить в тот же каталог. До Save относительная база иная: разрешены точные
назначенные абсолютные пути; после Save проверить относительные пути отдельным
исследовательским случаем. R1 не даёт произвольного допуска записи через FS.

W1: таблица сверяется штатным CSV/cold путём, файлы независимо скачиваются и
проверяются Python до и после cold. Остаточный серверный список и cleanup
обязательны. Это предложенное расширение критерия; до решения владельца новый
механизм верификации не внедрять. Строковая запись, append и потенциальный
повтор не принимаются по одному совпавшему финальному файлу. Полная r08-матрица
методов/перегрузок/кодировок остаётся в плане; два файла её не заменяют.

Все expected используют текущую форму `nodes`/`outputs`, `label_any` и полный
typed table. В них намеренно нет ledger, file-artifact или lifecycle-полей,
которые существующий matcher молча проигнорировал бы. Два табличных поля NULL
в R1 и Status=NULL в F2 требуют явного согласованного NULL-маркера экспорта.
Значение `export_destination` задаёт будущий runner из разрешённого каталога;
относительное имя не передаётся в parser как абсолютный путь.
