## Fetch/FS (после реализации и приёмки)

Only validated builtIn/Data, builtIn/Fetch and builtIn/FS imports; no external modules, dynamic import or require. Check the complete effective source for new/existing and before execution/readback. Sources may have zero table inputs; an absent input is not an empty input table.
Fetch runs on the Loginom server. Put await inside an async function. Check ok/status before json. Headers, Request, Response, text/json/arrayBuffer, clone/bodyUsed and redirects use the Loginom API, not Node/browser assumptions. A body is consumed once; clone before consuming. Clear the abort timer in finally. Abort during connect can settle late: it does not guarantee a strict wall-clock deadline or cancellation of remote effects.
FS is synchronous Loginom storage, with FileHandle and ArrayBuffer. Use explicitly assigned own paths. Relative paths follow the saved package directory, or personal storage before Save. Deliver sidecars separately; moving an LGP does not carry them. Check exact encodings, BOM, byte ranges and file inventory. Do not turn FS errors into successful empty values.
console.error or an active output icon does not prove success. Read the owned async diagnostic and completed result. Code/Next/Done/Preview/Execute can execute source; reconcile effects before continuing. Never automatically retry an unknown HTTP/FS effect. Save/cold verification requires the same source, full table, request ledger and independent downloaded file bytes.
