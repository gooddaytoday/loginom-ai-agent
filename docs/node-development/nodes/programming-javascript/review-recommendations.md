## 1. Пробы движка 7.4.2, от которых зависит oracle (0B)

Oracle ожидает `ёж` из `Ёж` и `гамма` из `Гамма`, то есть корректный
`toLowerCase` кириллицы в ChakraCore на сервере. На Linux это зависит от
сборки движка с ICU. До фиксации oracle проверить отдельными snippets:

- `toLowerCase`/`toUpperCase` кириллицы, включая Ё/ё; `trim`;
- наличие `Intl`, `toLocaleString('ru-RU')`, `localeCompare`;
- `Date.parse` для форматов без ISO: `2024-02-29 23:59:59`, `29.02.2024`;
- `OutputTable.Set()` дробного числа, строки, NaN и Infinity в Integer-столбец:
  округление, усечение или ошибка;
- strict mode ES-модуля: e2e уже ожидает
  `ReferenceError: Variable undefined in strict mode`;
- сохраняется ли `globalThis` между запусками (пул движков) — влияет на J11;
- regex: named groups, положительный и отрицательный lookbehind, флаги `s`/`u`/`y`;
- встроенные ES2016–2022: `includes`, `flat`/`flatMap`, `Object.entries`/
  `fromEntries`, `padStart`, `replaceAll`, spread, `**`, optional catch binding,
  class fields.

Результат оформить профилем движка: build 7.4.2, ОС сервера и hash результатов.
Из профиля генерировать раздел синтаксиса в знаниях. Если кириллица не
переводится в нижний регистр, это ограничение движка, а не дефект handler:
пересмотреть задание и oracle до приёмки, а не после неё.

## 2. Бюджеты ответа и лимит исходника (1A, 1B, фаза 2)

- `user-preview-budget.mjs:4`: ответ узла в `user-v1` ограничен 46 000 байт
  при двойном JSON-экранировании. При превышении `configuration.readback`
  заменяется сводкой (строки 30–34). При точном чтении бюджет не применяется
  (строка 11).
- Агент обрезает вывод `loginom_*` свыше 50 KiB или 2000 строк
  (`packages/agent/src/tool/truncate.ts:14–15`). Для квитанции узла остаётся
  только управляющая сводка без таблицы (`packages/agent/src/session/tools.ts:586–592`),
  для describe — начало JSON.
- Замеры: исходник 32 KiB занимает около 38 KB этого бюджета; весь справочник
  в JSON — 52 772 байта при лимите агента 51 200; существующие `parameter_schema`
  весят 0,3–3 KB.

Рекомендации:

- в ответе `dock_node_apply` не возвращать полный исходник: только digest,
  длину, число строк и признак совпадения с запросом;
- полный текст выдавать отдельным ограниченным чтением; размер считать так же,
  как `previewWireSize`;
- лимит v1 снизить, например до 16 KiB и 512 строк, либо вычислить его
  от бюджета ответа, а не от байтов исходника;
- для JS-карточки describe задать бюджет (например, 20 KB) и тест на
  сериализованный размер, в том числе при запросе нескольких типов сразу;
- в J01 и J18 проверять `metadata.truncated=false` в реальном CLI.

## 3. Точность ввода в CodeMirror (G4, фаза 2)

Калькулятор вводит текст через `page.keyboard.type`
(`workspace-ui.mjs:3497–3501`). В JS-режиме CodeMirror 5 Enter добавляет
автоотступ, `}` заново выравнивает строку (electric chars), возможен
closebrackets. Многострочный код не сохранится байт-в-байт, и точная сверка
readback будет отказывать.

В G4:

- подтвердить версию CodeMirror (5 или 6) и API полного чтения;
- выбрать способ ввода и доказать его точность: клавиатура, `insertText`
  или буфер обмена под общей блокировкой хоста;
- тестовый исходник: вложенные блоки, табы, ведущие и хвостовые пробелы,
  строки длиннее 100 символов, кириллица в комментариях, пустые строки;
- проверить формат `Code` в сохранённом `.lgp` (LF или CRLF, XML-экранирование)
  и определить канонизацию для digest, иначе J15 даст ложный FAIL;
- замерить время ввода максимального исходника относительно бюджета configure.

## 5. Доставка знаний (1B)

- Оформить runtime-редакцию модулем `.mjs`, например `javascript-knowledge.mjs`
  с текстом и `validated_for`. Managed pin автоматически включает только
  `.mjs`/`.d.ts` (`runtime-pin.mjs`, `session.mjs:49`); `.md` потребует правки
  fixed paths и bundle.
- 5–7 критичных правил движка положить в `limitations` карточки: они приходят
  модели уже в `dock_prepare` через `compactKnowledgeBundle`
  (`user-results.mjs:205–211`), даже если модель не вызовет describe.
- Закрепить приоритет: знания 7.4.2 важнее удалённой справки. Инструменты
  `find/search/read` в `user-v1` видят Help без привязки к версии.
- Переписать правила советника в обязанности handler или исключения v1:
  «рекомендуй удалить поля и включить автосинхронизацию» — политика handler
  для code-режима; «рекомендуй сохранить пакет» и пути модулей — вне v1;
  «код редактора не передаётся» — наоборот, handler читает код сам.
- Серверные правила оставить; настольные пути (`C:\…`) и разделы FS, Fetch,
  внешних модулей убрать из v1-карточки с пометкой «не поддерживается handler v1».
- Каждый пример кода runtime-редакции выполнить на стенде 7.4.2
  (исполняемая документация) и записать результат в `discovery.md`.

## 6. Мастер и диагностика (G1, G6)

- Справочник содержит «Правила чат-помощника». Если в мастере 7.4.2 есть
  встроенный помощник, описать его элементы в G1. Handler не вводит в него
  текст и не запускает его LLM: это была бы вторая, неучтённая модель в приёмке.
- Проверить, есть ли в мастере или свойствах узла выбор версии движка либо
  режима совместимости. Если есть — это параметр контракта и readback.
- Сообщения ChakraCore отличаются от V8: `SyntaxError: Expected ';' at code`,
  `TypeError: Unable to get property 'b' of undefined or null reference`
  (e2e `js_errors.ts:107–208`). Модели передавать класс ошибки, точный текст,
  позицию, если Loginom её даёт, и digest исходника. В знаниях — короткая
  таблица типичных сообщений.

## 7. Среда и live-пробы (0A, 0B)

- Прямые пробы и операторские скрипты используют URL с `?testable=true`
  (`diagnostics.mjs:55`; managed Host добавляет параметр сам). Исторически на
  этом стенде работали `http://logi-test-plan.bg.local/app/?testable=true`
  и аккаунты `test-2`/`test-4` (`tools/loginom-acceptance/node14/*-live.mjs`).
- Стенд — адрес по умолчанию продукта с пользователем `user`
  (`docs/migration/linux-implementation-checkpoint.md:327`), то есть общий.
  Нужен отдельный аккаунт, не `user`. Бесконечные циклы и нагрузочные пробы
  запрещены; долгие пробы делать конечными.
- Механизм проб 0B: обычные `dock_ui_action` по замыслу блокируют редакторы
  кода (`workspace-ui.mjs:442–448`), а handler ещё нет. Явно назвать
  операторский диагностический `javascript-live.mjs` по образцу
  `tools/loginom-acceptance/*-live.mjs`. В образцах зашиты
  `~/.loginom-dock/runtime/browsers` (на этой машине каталога нет) и build 7.4.2;
  пути адаптировать к Linux-окружению 0A.

## 8. Решения контракта, которые не стоит оставлять разработчику (1A)

- Политика импортов v1: разрешён только `builtIn/Data`; `builtIn/FS`,
  `builtIn/Fetch`, `builtIn/Calc`, относительные импорты, `require` и `import()`
  отклоняются до мутации. Это ограничитель scope по явным объявлениям импорта,
  не песочница.
- Имена столбцов в code-режиме: что Loginom делает с кириллическим или
  недопустимым `Name` — транслитерирует, как у импорта, или выдаёт ошибку
  (e2e `js_data_output.ts:56`). Handler возвращает фактические имена;
  в знаниях — правило `Name`.
- Resume после перезапуска процесса, если журнал хранит только digest:
  приватный снимок исходника с правами 0600 либо явный отказ от такого resume.
- «Bindings до эффекта» в code-режиме — только проверка формы запроса;
  существование динамических полей проверяется после materialization.
- Записать причину выбора `source_text`: ключ `code` запрещён
  `scanForbiddenDefinition` (`action-catalog.mjs:93`), а redactor заменяет
  строку под ключом `code` целиком, если в ней есть `password` (`redact.mjs:78–79`).
  Redactor-регрессия, кроме URL: `Basic <слово>`, `токен: …`, `PRIMARY_KEY = …`
  внутри исходника.
