# Fetch/FS: предложение контракта полного #69

LAB-1549, база `8b6462aaf26bb7767089f77a6203a8e224ac5d58` (`v040`).
Этот документ предназначен для утверждения владельцем до runtime-правок.
Он не расширяет действующую поддержку и не объявляет пробы приёмкой.
Внешние ESM/CJS, dynamic import, require и `builtIn/Calc` не входят.

## Политика и исходник

Расширить существующую `javascript-module-v1` только статическими импортами
`builtIn/Fetch` и `builtIn/FS` наряду с `builtIn/Data`. Сохранить синтаксический
разбор, bounds, отказы прочим specifier и проверку полного effective source
для new/existing, source change, configure/execute/read и continuation.
Политика является фильтром импортов, не изоляцией произвольного JavaScript.
Разрешение FS открывает также запись и удаление; промежуточный выпуск
«разрешён весь FS, но поддерживается только чтение» не предлагается.

Сохранить `mode:script`, существующие `code` и `declared` схемы и один output0.
Расширения выбираются программой, не новым визуальным режимом мастера.
Нулевая входная таблица должна означать отсутствие input mapping, а не
фиктивную пустую таблицу. При одном входе сохраняются прежние требования
к identity, именам, типам, связям и чтению. Multi-input и variables вне объёма.
Выход — типизированная таблица пользователя. HTTP status, тело и обработанные
ошибки не создают автоматически служебный порт, как у REST-запроса.

## Завершение и ошибки

Весь async-код завершается внутри async-функции; top-level await не обещается.
До запуска фиксируются полные source/settings, ожидаемая схема, разрешённые
эффекты и identity операции. Успех требует свежего собственного completed
execution, полного конечного результата и совпадения независимых внешних
свидетельств. Зелёная иконка и `console.error` этого не заменяют.

| Ситуация | Требуемый наблюдаемый исход |
|---|---|
| Успешный Promise | результат записан после последнего await, нет pending callback, свежий execution и полная таблица |
| HTTP 404/500 | различать fulfilled response с `ok=false` и транспортный rejection; исход и status отражены по бизнес-задаче |
| Malformed JSON | явный диагностический результат или собственная failed execution; не успешная пустая таблица |
| Rejected Promise | обработанный отказ даёт явно запрошенную диагностику; необработанный отказ не выдаётся за успех по зелёному status |
| Timeout/abort | фиксируются причина и отсутствие результата; таймер очищен; abort запроса не равен отмене узла или удалённой операции |
| TLS | включённая проверка сертификата, отказ с подтверждённой TLS причиной; fallback на небезопасный HTTP не выполнять |
| Local cancel/server Stop | определить исход собственной execution; проверить late callbacks и неизменность файлов/ledger после подтверждённого завершения |
| Потерянный ответ | сохранить operation identity и неизвестность эффекта; сверять состояние/ledger, не запускать эффект автоматически повторно |

Поведение late callback проверяется на управляемом `/slow`: снимки таблицы,
ledger и файлов до отмены, после terminal и после времени ответа fixture.
Интервал наблюдения задаётся задержкой fixture и существующим deadline;
увеличение общих лимитов не требуется и не разрешается этим предложением.
На этапе 1 native toast/unhandled rejection должен быть связан с собственной
execution. Если для этого необходима неаддитивная общая процедура — stop,
а не ослабление критерия.

## Внешние эффекты и повторы

Материализация code schema сейчас исполняет узел отдельно от final Execute
(`javascript-code-node.mjs:71–78,338–363`). Поэтому правка allowlist сама по себе
не обеспечивает однократный POST/append. До допуска записи нужно снять ledger
и file snapshots на Code/Next/Done/Preview/Execute, включая повтор source-read.
Предлагаемая цель: configure и диагностическое чтение не выполняют внешние
эффекты; один явный бизнес-Execute выполняет одну программу. Cold Execute —
отдельное явно заданное выполнение, не скрытый retry.

Если code schema требует исполнения для получения output mapping, сначала
проверить возможность локально использовать уже полученную собственную
execution вместо второго Execute. Для declared исследовать прохождение
без материализации. Ни одна ветка не должна разрешать effects по неизвестному
исходу предыдущей попытки. Append и POST проверяются числом фактических эффектов,
даже когда итоговая таблица или перезаписанный файл совпали.

## FS и доставка файлов

Разрешены только явно назначенные каталоги собственной пары и их созданные
подкаталоги. Корень для каждого прогона уникален. Проверять абсолютный путь
в файловом хранилище Loginom; это не путь Linux-хоста CLI. Не обходить права
через `..`, ссылки, чужой каталог или произвольный системный путь.
Отрицательный permission fixture должен подготовить владелец внутри своей
области; наличие broad permissions пары не доказывает изоляцию.

Для saved/unsaved/moved отдельно установить базу относительных путей,
проверить её до эффектов, после Save As и cold reopen без изменения source.
Не выводить путь из имени `.lgp` без наблюдения. Sidecar доставляются и
проверяются отдельно: сохранение `.lgp` не обещает упаковки внешних файлов.
Перенос без sidecar должен давать объяснимый missing; перенос с доставленными
sidecar — те же байты и таблицу.

Матрица r08 включает path/FileHandle, строку/ArrayBuffer/ArrayBufferView,
read/write/append, readSync/writeSync обеих форм, закрытие в finally,
stat/fstat/lstat и Dirent, mkdir/readdir/rmdir/rm, copy/rename/truncate/
ftruncate/unlink, flags/exclusive и ошибки, UTF-8/UTF-16LE/BOM, binary и
position/offset/length. Реально поддержанные overload и constants записать
после нативной проверки; наличие одноимённой функции не доказывает все формы.
Метаданные времён сравниваются по типу/валидности, не с фиксированным timestamp.
Чистоту каталога доказывает независимый inventory, байты — скачанные файлы;
самоотчёт JavaScript не является независимой проверкой.
