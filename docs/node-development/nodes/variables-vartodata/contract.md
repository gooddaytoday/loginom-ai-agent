# Предложение контракта этапа 1

Статус: критерии предложены для утверждения перед этапом 1.
Наблюдения и ограничения — [discovery.md](discovery.md); runtime не изменён.

## Вход и результат

`variables.to_table`, строковый `mode:"columns"`, `parameters:{}`.
Один явный типизированный вход переменных 0, один табличный выход 0.
Переменные создаёт источник, конвертер не принимает константы и формулы.
Непустой набор даёт одну запись; порядок, имена, метки и типы полей равны
входному набору. Дополнительные столбцы и сортировка не подразумеваются.

Поддерживаемый первый срез: integer, real, boolean, string, datetime и типизированный
NULL. NULL не равен отсутствующему полю, пустой строке, FALSE или нулю.
Datetime — гражданское время с точностью до миллисекунды без timezone-конверсии.
В приёмке real `1.25` имеет `tolerance:{abs:0,rel:0}`; остальные сравнения точные.
Integer фикстуры — 7 и 0: приёмка не доказывает весь Int64. Полную поддержку Int64
можно обещать только при подтверждённом точном reader W1, не через JS Number.

Новые/существующие узлы используют тот же явный источник. Для existing пустые
parameters сохраняют текущую поддерживаемую ориентацию; rows нельзя молча менять
на columns. `finish:"done"` — настройка, `finish:"execute"` — вычисление текущего
источника и чтение, `finish:"close"` — выход без применения. Модель обучения
и отдельный apply не вводятся. Сохранение пакета — отдельное действие.

Rows/Variant, пустые наборы, переменные системы/сессии/пользователя,
межсценарные связи и неподтверждённые типы вне первого среза. Наблюдённая
допустимость native узла без связи не делает его положительным сценарием handler.
Неизвестная точность и несоответствие вида порта должны приводить к понятному
отказу до мутации; причины native отказов читаются через кнопку ошибки.

## Поля схемы и readback

[node-card.proposal.json](node-card.proposal.json) — измеряемый проект карточки,
не регистрация. `semantics` объясняет результат, NULL, порядок, точность,
источник, lifecycle и пределы. `parameter_schema` — закрытый пустой object
с описанием: у native страницы нет параметров кроме ориентации, которая уже
выражена верхнеуровневым строковым enum `mode:["columns"]`.
Собственные поля settings не выдумываются; создавать фиктивный Boolean
`to_rows` или дублировать mode полем `layout` не требуется.

Описания общих полей, которые надо подтвердить в W1:

| Поле | Требуемый смысл description |
|---|---|
| mode | `columns`: одна запись; rows не поддерживается первым этапом |
| inputs[].source | Выданная ссылка на узел источника того же document/workflow |
| inputs[].output | Проверенный индекс **выхода переменных**, не таблицы и не control port |
| inputs[].input | Вход переменных конвертера; единственное значение 0 |
| kind, если W1 его вводит | Строковый enum `variables`; точное имя и форма принадлежат W1 |
| mappings | Существующий контракт табличного выхода: точные configured_field, порядок/метки/имена |
| read.ports | Табличный выход 0; полный единственный результат |
| finish | Execute вычисляет/читает, Done только применяет, Close отменяет |

Не закреплять локальный вариант формы inputs раньше W1. Числовые native enums
не пересылаются модели. Предлагаемый компактный readback — `mode`, текущие
имя/метка/тип переменных в порядке источника, фактический источник/индексы/вид
портов и схема выхода 0. Значения возвращаются один раз в output, без копий
preview, сырых UI stores, квитанций или отдельного протокола происхождения.
Readback существующего узла обязан отличать выбранную настройку от executed output.

## Приёмка для утверждения

1. Свежая копия входного fixture, один калькулятор переменных → новый конвертер;
   связь var output 0 → var input 0 в одном сценарии. Значения калькулятора
   не переписываются в табличные константы. W1 должен уметь выполнить и прочитать
   такой существующий источник без реализации отдельного handler его создания.
2. Полный результат 1 × 8, точные имя/метка/тип/порядок и значения из
   [acceptance/expected.json](acceptance/expected.json). `ordered:true`,
   `output_port:0`, `column_order:"exact"`. Все метки заданы задачей, поэтому
   здесь нет `label_any`; пользовательскую метку узла задача не задаёт.
3. Независимый CSV oracle и cold-check сохранённого пакета: повторное выполнение,
   та же типизированная связь и весь выход, `package_closed=true`, `logged_out=true`.
   Нужная проверка связи/источника входит в W1; обычное сравнение выходной таблицы
   само по себе этого не доказывает. Нового verifier/receipt-механизма не предлагается.
4. На одном опубликованном SHA ≥2 PASS из 3; затем независимые 2/3 на том же SHA
   под второй ролью пары отдельным назначением. Модель `openai/gpt-6.1-sol`, medium,
   1800 с. Сборки и прогоны выполняются только после нового назначения этапа 1.

Проверки неподдержанного mode, foreign source и неверного вида порта нужны
как адресные preflight-тесты реализации, а не как скрытые требования в task.md.
Нет нового критерия для этого discovery; изменения критериев после утверждения
требуют согласования до прогонов.

## Общие изменения и оценка

До W1 базовый `validateNodeTargetRequest` суммирует только tabular/tree inputs,
а `readGraph`/связи и cold-читатель не предоставляют согласованный вход переменных.
Локальная регистрация конвертера это не исправит. **Требуется уже выделенный W1**:
типизированная ссылка/связь/чтение существующего источника переменных и cold-аудит
этой связи. Его форма и принятый SHA должны быть утверждены до этапа 1.
`local_variables`/`bindings` Кросс-таблицы к нему неприменимы.

Режим строк наблюдён и поэтому включён в предложение по объёму назначения:
[task-rows.proposal.md](acceptance/task-rows.proposal.md) и
[expected-rows.proposal.json](acceptance/expected-rows.proposal.json) предлагают
8 × 3, точный порядок, Name/DisplayName string и Value variant с subtype
integer/boolean/string/datetime/real, отдельным NULL. Ожидания вычислены из тех же
авторских входов; они не заявляют, что subtype или civil datetime в Variant уже
прочитаны на стенде. Это отдельный сценарий после утверждения.

**Нужен выбор объёма перед следующим этапом.** Базовый
`variant-native-read.mjs:1` — private Collapse capability: фиксированная привязка
к importtextfile и Collapse либо статической CrossTable-цепочке. Это не общий
reader для источника переменных. `variant-native-values.mjs` для datetime
подтверждает native serial, а не civil time. Поэтому полная приёмка наблюдённых
строк требует **W2 сверх W1**, адресной привязки и temporal-контракта; копирование
reader с новыми receipts не предлагается. В рамках стоп-условия карточки нужна
санкция на W2 либо решение оставить первый этап столбцами, строки — отдельным
назначением после W2. Самовольно не обещать оба режима в реализации.

После W1 ожидаются файлы своего handler и аддитивная регистрация типа/режима,
свой файл навыка и одна строка маршрутизации, собственный сценарий
`variables-columns` в run-check. Создание Calculator (переменные) handler не нужно:
исходный пакет готовит оператор. Признаков необходимости ещё одной общей правки
вне W1 сейчас нет. Если чтение нового SVG/схемы потребует её при реализации —
остановиться с конкретным наблюдением и вопросом, не расширять общий код заранее.

Оценка после принятого W1: **2 цикла**: handler + проверки + первые 3 прогона;
затем один адресный цикл исправления с новыми прогонами при наблюдённом отказе.
Независимая приёмка — отдельное назначение. W1 и W2 в эту оценку не включены;
для одновременных columns+rows после готовых W1/W2 оценка — **3 цикла**
(столбцы, строки/переключение, один адресный цикл по фактическим отказам).

## Размеры UTF-8

Измеряется `Buffer.byteLength(JSON.stringify(value))`; pretty JSON указан отдельно.
База — точный SHA выше. Измерение без регистрации, imports из исходников базы.

| Поверхность | База / проект | Предел / ограничение |
|---|---:|---|
| Сжатый `dock_node_apply`, name+description+inputSchema | 13 181 / 13 212 Б | 20 000 Б; проект добавляет только type/mode enums, W1 ещё не учтён |
| Полная inputSchema | 50 099 / 50 130 Б | Без предела; W1 ещё не учтён |
| Карточка проекта, pins/session_manifest пустые | 2 582 Б | 12 000 Б; actual describe с pins перемерить после W1 |
| Тот же файл, отступы/LF | 2 748 Б | Не размер wire-карточки |
| Основной SKILL.md | 39 686 Б | 40 000 Б |
| Строка маршрутизации | 133 Б | Ориентир ~200 Б |
| SKILL.md после этой строки | 39 819 Б | Остаётся 181 Б; другие дополнения здесь не оценены |
| Свой [проект references/nodes](skill-proposal.md) | 1 973 Б | 6 000 Б |

Строка проекта (с LF):

```text
| Переменные в столбцы | `variables.to_table` / columns | [читать](references/nodes/variables.to_table.md) |
```

До реализации нужно перемерить **реальные** сжатый tool, карточку describe с pins,
полную схему и упакованный skill после интеграции W1. Эти числа — точные размеры
проектных артефактов, а не заявление о размере несуществующего handler.
