Native отсутствие связи допускается, но не входит в положительную приёмку.
Точная кратность zero-column таблицы и пустой типизированный источник не доказаны.

Историческая Help-основа: `loginom-help@353e506b`,
`data/processors/variables/variables-to-table.md`; это справка, не доказательство
живого поведения. Исторический E2E: `486caef44:bg/labels.ts:199` — имя компонента.

## 2. Этапы

### Этап 0 — завершённые материалы

- [discovery.md](discovery.md): наблюдения/ограничения, DOM-адреса,
  native engine, вход variables 0 / выход table 0, оба режима.
- [contract.md](contract.md): предлагаемые semantics, schema descriptions,
  компактный readback, точность, критерии, зависимость W1, оценка в циклах/байтах.
- `fixtures/`: авторские переменные и малый пакет только с источником;
  `acceptance/`: пользовательское задание, независимый oracle, expected до прогонов.
- Изменение статуса подплана не является утверждением критериев или W1.

### Этап 1 — Переменные в столбцы (`r01`)

Предлагаемый срез: integer/real/boolean/string/datetime/типизированный NULL,
один непустой источник, один табличный выход 0. Значения/типы/имена/метки/порядок
сохраняются. Положительная приёмка — 1 × 8 по `acceptance/expected.json`.
Unsupported rows, пустота, чужой/табличный/control порт отклоняются до мутации.
Числовые enum UI не выходят в модельный контракт.

**До старта:** утверждены критерии contract.md и W1 по принятому SHA.
W1 — типизированные refs/связи/чтение существующего источника переменных
и независимая cold-проверка связи. Не использовать локальные переменные
Кросс-таблицы как подмену графового порта. Источник создаётся малым fixture,
а не новым handler калькулятора в этом срезе.

Предлагаемые узловые файлы: `variables-vartodata-{node,parameters,procedure,context,readback}.mjs`
в `packages/loginom-runtime/client/lib`, адресные тесты в `client/test`.
Аддитивные регистрации — `node-contracts.*`, `node-support.mjs`, `node-api.mjs`,
readback/result schema, dispatch и UI selector admission ровно в нужных местах.
Новые общие подсистемы заранее не создавать. Образцы: lifecycle табличных
преобразований `calculator-node.mjs`; порт переменных относится к W1.

Свой файл навыка `references/nodes/variables.to_table.md` и одна строка routing;
проект текста — [skill-proposal.md](skill-proposal.md). Сценарий run-check
`variables-columns`, исходные копии пакета готовятся в собственной паре.
Перепроверить после W1 реальные размеры model tool, describe, SKILL и reference.

До отчёта — `required-checks.py list --base origin/v040 --head HEAD`,
все проверки по изменённым путям и `verify` по отчёту. При изменении client —
полный client suite с pinned Chromium; при изменении оснастки — её полный suite;
при runtime src — полный host `bun test`. Полные наборы под `nice -n 19`.
Прогоны — только run-check start/wait; cold PASS и ≥2/3 на одном опубликованном
SHA, независимые 2/3 тем же SHA под второй ролью пары отдельным назначением.

### Этап 2 — отдельное назначение (`r02`, `r03`)

- `r02`: строки, точные `Name string`, `DisplayName string`, `Value variant`;
  независимое чтение subtype каждого значения и точной даты внутри Variant.
  Отдельные task/expected уже предложены в `acceptance/*rows.proposal*`.
- `r03`: добавление/удаление/изменение исходных переменных без настройки
  конвертера, пустой типизированный источник, переключение схемы и повторное
  открытие. Не наследовать старый output mapping как доказательство порядка.
- В базе наблюдена привязка существующего Variant reader к Collapse/CrossTable,
  поэтому для строк нужен W2. Утвердить его либо разделение реализации до старта;
  общий код в этом docs-назначении не меняется.

## 3. Данные и oracle

`fixtures/variables.json`: A=7, B=FALSE, Text=Привет,
Moment=2026-01-02T03:04:05.006, Missing=NULL integer, Rate=1.25,
Empty="", Zero=0, с точными типами/метками/порядком.
`source.lgp` содержит только Calculator (переменные) и служебный блок сценария,
без конвертера, результата, экспортов и визуализаторов. Перед каждым прогоном
это новый пакет по пути, который run-check подставит в `{{PACKAGE_PATH}}`.

Oracle — Python stdlib, без импорта runtime/Loginom. Читает авторские входы,
проверяет согласованность input fixture и формирует expected. Типы/NULL/порядок
проверяет cold-readback; отдельный `--csv` сравнивает весь экспорт.
Схема/значения oracle не извлекаются из Loginom output. SHA/байты manifest относятся
только к целостности входных fixture, отдельные receipts не создаются.
