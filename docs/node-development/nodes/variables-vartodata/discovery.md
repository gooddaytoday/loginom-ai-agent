## Мастер и жизненный цикл

Префикс вкладки меняется (`MF;TF-1`, `MF;TF-2`, `MF;TF-4` в исследовании).
Корень — `<prefix>;WizrdMCF`, заголовок первой страницы — **Переменные в таблицу**.

| Страница / control | Наблюдение |
|---|---|
| `VariablesToDataWizard` | Записать переменные: В столбцы / В строки |
| `rbVarToColumns;DisplayEl` | Умолчание; одна переменная — отдельное поле |

| `DoneWizard` | Описание узла; `btnDone`, `btnExecute`, `btnView` |
| `btnPrev`, `btnNext`, `btnClose` | Назад, Далее, выход из мастера |

При повторном открытии подключённого узла обычный Next переходил с выбора режима
сразу к описанию; скрытый mapping panel сохранялся в DOM. Наличие panel в DOM
не доказывает, что переход на него предусмотрен текущим путём мастера.
Выбор radio читать по `x-form-cb-checked` контейнера/локальному UI-компоненту:
`InputEl` имеет `type=button`, его DOM `checked=false` не является значением radio.
Для клика использовался `DisplayEl`.

Done применяет настройки, Execute выполняет источник и конвертер. Открытие
настройки активного узла требует штатного подтверждения деактивации
`msgbox;tlb;yes`. Подпись и `data-tid` узла меняются после связи и смены режима:
«В столбцы: Количество, Флаг, Текст, Момент (+4)» / «В строки: …».
Нельзя удерживать старый текстовый TID как identity.

В контекстном меню есть общая команда «Обучить узел»; отдельно она не запускалась.
В собственном мастере нет страниц обучения и выбора сохранённой модели.
Вывод для предлагаемого runtime: обычное преобразование текущих значений,
без отдельного train/apply-контракта. Это проектное решение, а не PASS обучаемого режима.

## Значения, порядок и точность

Авторские входы — [fixtures/variables.json](fixtures/variables.json), восемь
выражений калькулятора. Во входном fixture [source.lgp](fixtures/source.lgp)
конвертера и визуализаторов результата нет.

Режим **столбцов**: одна строка, восемь полей в порядке
`A, B, Text, Moment, Missing, Rate, Empty, Zero`.
Имена и заданные метки сохраняются. Типы заголовков полного визуализатора
`BrowseView;normalHeaderCt` соответственно:
`dtInteger, dtBoolean, dtString, dtDateTime, dtInteger, dtFloat, dtString, dtInteger`.
Значения: `7, FALSE, Привет, 2026-01-02T03:04:05.006, NULL, 1.25, "", 0`.

После включения `btnDataGridShowNulls` ячейка Missing получила
`bg-cell-null-value` и `<null>`; Empty осталась без этого класса и содержала
неразрывный пробел представления. Boolean в полном визуализаторе — «Ложь».
При включённом `btnDataGridDataTypeIcon` типы читаются из
`bg-TBGDataType-dt…-before`; строковый preview не является типизированным чтением.

Дата в быстром просмотре показывала только минуты, в обычном полном просмотре —
секунды. Через `btnDataGridFormat`, строку `colDisplayName_Moment`,
`BrowseFormatPanel;cbFormatStr` и `edtFormatStr` установлен формат
`yyyy-mm-dd hh:nn:ss.zzz`. После Tab, ухода на другое поле и возвращения маска
сохранилась; после Apply прочитано **2026-01-02 03:04:05.006**.
Гражданское время без timezone; UTC и перенос между timezone не проверялись.
`1.25` представимо точно в binary64, в UI — `1,25`. Другие real,
Int64 за пределами безопасного JS integer, NaN/Infinity не исследовались.

Режим **строк** того же узла после переключения и Execute: восемь записей
в том же порядке. Точные поля:

| Имя | Метка | Тип заголовка |
|---|---|---|
| Name | Имя | string |
| DisplayName | Метка | string |
| Value | Значение | variant |

Value визуально сохраняет 7/Ложь/Привет/дату/NULL/1,25/пустую строку/0.
NULL-класс есть только у Missing. **Subtype каждой Variant-ячейки и миллисекунды
даты внутри Variant отдельно не доказаны**; это не приёмка этапа 2.
Переход столбцы → строки меняет схему после Execute и сохраняет выходной порт.

## Пустота и отказы

Новый конвертер **без связи** прошёл мастер без ошибки; Execute активировал
табличный выход. Полный визуализатор не показал полей и записей. Это наблюдение
пустого неподключённого входа, а не доказательство логической кратности таблицы
с нулём колонок и не проверка пустого типизированного источника.
Непустой источник, добавление/удаление переменной и смена значений без настройки
конвертера ещё требуют адресной характеристики при реализации.

Отказ мастера с `btnError` в исследованных переходах не наблюдался:
причина из несуществовавшей кнопки не выдумывается. Несовместимый табличный вход,
потеря ранее подключённого источника и недопустимые runtime-параметры не проверены.
Будущий handler должен отклонять их до мутации в пределах согласованного W1.

У окна быстрого просмотра переменных сценария не обнаружен собственный
`data-tid` в видимом инвентаре; окно закрывалось Escape. У активного табличного
порта наблюдалась дублированная SVG-картинка без TID, перекрывавшая старую.
Исследование продолжено через выбранный узел → `Visualizers`, затем Table.
Это существующая особенность поверхности; общей правки здесь не делалось.
