Предложение проверки границ LAB-1012, не новый сценарий и не новый oracle.
Живая проверка CrossTable в этой карточке не завершена. Продолжение —
на назначенном стенде и собственной паре, только после решения владельца.

1. Использовать существующий малый комплект `../continuous-real/task.md`,
   его `data/keys.csv`, `oracle.py` и `expected.json`. Они не меняются.
2. В собственном мастере открыть numeric-факт через
   `WizrdMCF;CrossTabWizard;grdUsedFields` → `WizrdMCF;FactorEditDialog`.
   Зафиксировать все checkbox data-tid, наличие 11 известных функций и
   отсутствие «Единственного», медианы, моды. Адреса — кандидаты из кода,
   в LAB-1012 ещё не наблюдены. Не выбирать замену отсутствующему агрегату.
3. После свежего Execute осмотреть собственный выход и Required источников.
   Проверить отказ исключения, затем отменить только свой draft.
4. Full native read 50×8/1 MiB — принятый **cap клиента**, по коду
   `variant-native-values.mjs` и `variant-native-schema.mjs`; без увеличения
   cap, новых общих изменений или циклов. Не объявлять его пределом Loginom.

Это ручное исследование UI и принятой границы чтения; оно не заменяет
CSV/Save/cold/cleanup и не выдаётся за PASS. Новых критериев, runner и
сценариев run-check для этих ограничений не предлагается.
