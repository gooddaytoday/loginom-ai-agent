## Состояние и границы

`discovery_required`: компонент есть в историческом каталоге, но отдельного зарегистрированного обработчика, публичного режима, адресных runtime tests и независимого аудитора в текущем клиенте не обнаружено. Это состояние подготовки подплана, не новый статус приёмки. В [реестре](../../registry.json) сохраняются `not_implemented`, `not_accepted`, `not_validated`, `not_revalidated_standalone`, `not_integrated`, `not_released`.

Предварительный scope из подплана 15: ключи строк, одно дискретное измерение колонок, числовые факты с sum/avg/min/max и отдельный счётчик строк; фиксированные колонки с явной политикой «Прочие»/«Пропущенные» и скользящие уникальные значения. Оба режима требуют исследования текущего Loginom; это ещё не подтверждённый runtime-контракт. Изменение схемы при новых/исчезнувших категориях обязательно учитывать.

Это компонент сценария, а не визуализатор «Куб». Многомерные колонки, дополнительные агрегаты, переменные и усечение категорий не входят в исходный scope. Нельзя считать пустое пересечение нулём без отдельно выбранного преобразования.
