## Состояние и границы

Обработчик `transform.cross_table` / `pivot` зарегистрирован. Код, адресные runtime tests, бизнес-сценарий и независимый cold oracle находятся в этом репозитории. Этап 3 разрабатывается от `0e273580198ddfa670523c19930d3333e2b347c9` с целью PR `cross-table`. Регистрация и живые проверки не означают полного standalone PASS или независимой reviewer-приёмки; текущие доказательства и отрицательные попытки описаны в [discovery.md](discovery.md).

Поэтапный контракт включает фиксированные и скользящие категории, типизированные агрегаты и Variant, несколько измерений колонок и изменение схемы после нового источника. Этап 3 добавляет резервирование и ограничение категорий, разделители `|`, `.`, `->` и пробел, имена по категориям и три локальные управляющие переменные. Точные типы, функции, ограничения и критерии находятся в подплане и публичном контракте.

Собственный выход поддерживает переименование, порядок и автосинхронизацию. Его источники `Required=true` не исключаются: обязательная отрицательная попытка должна подтвердить отказ без изменения состояния. Согласованное исключение выполняется отдельным downstream-узлом «Параметры полей» и проверяется после нового открытия сохранённого пакета. Пустые пересечения сохраняют NULL. Пределы точного native-чтения 50×8 и 1 MiB, протокол 321, проверки происхождения, исполнения и Variant subtype сохраняются.
