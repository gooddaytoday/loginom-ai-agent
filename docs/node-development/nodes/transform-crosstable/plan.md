## 2. Этапы

### Этап 0 — живое исследование

Результат — [discovery.md](discovery.md): интерфейс мастера, матрица функций по типам, семантика режимов, имена и метки, W2, переменные, выход. Независимый oracle, `expected.json` и бизнес-задание созданы до кода обработчика.

### Этап 1 — числовое ядро (LAB-10)

- Один табличный вход и выход; дискретные ключи строк; одно дискретное измерение колонок; числовые факты `sum/min/max/avg`.
- Режимы `fixed` («Группа значений», явные флаги «Прочие» и «Пропущенные») и `sliding` («Скользящие уникальные значения»).
- Создание и настройка существующего узла; при смене режима зависимые настройки заменяются целиком.
- Отказ до мутации графа на неподдержанные параметры; тексты ошибок объясняют исправление.
- W1: схема снимается после материализации; смена категориальных колонок при повторном чтении разрешена только операции, readback которой подтвердил `sliding`. `fixed` и остальные 14 обработчиков остаются на строгой проверке.
- W2: размер берётся из привязанной native записи `FileStore` (`Size` — целое число байт); формат отображения не парсится.
- W3: `expected.json` в форме `outputs[]`, каждый выход однозначно сопоставляется ровно одному узлу; `crosstable-transcript-audit.mjs` проверяет, что после смены файла не было `dock_node_apply` к CrossTable и есть чтение с исходным `source_operation_id`.

### Этап 2 — агрегаты, типы, измерения (LAB-12)

- Функции по наблюдённой матрице: integer и real — 11 функций; string и Boolean — 7; DateTime — 9; Variant — 7. «Единственный», медиана, мода не поддерживаются.
- Несколько упорядоченных измерений строк и колонок; категории колонок — декартово произведение, включая ненаблюдавшиеся сочетания.
- Native «Количество», число уникальных и пропусков, первый и последний, стандартное отклонение (делитель n−1), сумма квадратов.
- Variant — через подготовленный источник «импорт → Свёртка столбцов»; точное native-чтение с проверкой subtype и происхождения.

### Этап 3 — параметры схемы, переменные, выход (LAB-13)

- «Минимальное число значений» (резерв групп) и «Ограничение количества значений» (верхняя граница групп, включая резерв).
- Разделители `|`, `.`, `->`, пробел; «Уникальные значения как имена полей».
- Три локальные управляющие переменные: ограничение (integer), имена по категориям (Boolean), разделитель (string).
- Собственный выход: переименование, порядок, выключение и повторное включение автосинхронизации. Исключение источника с `Required=true` отклоняется; исключение полей — отдельным downstream «Параметры полей».
- Переходы `fixed → sliding → fixed`, перестановка полей входа с повторным применением ролей по именам.

### Видимость для модели

- Тип виден в `knowledge.node_types` после `dock_prepare` с `semantics` «сводная таблица: строки × категории колонок × агрегаты фактов»; схема параметров — через `dock_action_describe`, у каждого поля есть `description`, enum строковые.
- После смены источника узел пересчитывается через `dock_node_read` с исходным `source_operation_id`; для `sliding` схема возвращается заново.
- Readback компактный: режим, роли, функции, флаги, соответствие «категория + факт + функция → поле». Ответ модели ограничен 46 000 байт.

Правила oracle:

- не импортирует runtime и не берёт ожидания из результата прогона;

- выходы сопоставляются по точному порядку имён, меток и типов, затем значениям и пропускам; перестановки отвергаются;
- порядок полей продаж — категория, затем факт и функция (как у native);
- стандартное отклонение — `sqrt((Σx²/n − mean²)·n/(n−1))` в binary64, сравнение точное, без допуска;

- Variant Min включает NULL как нижнее значение, скалярный Min пропуски игнорирует.

## 5. Ловушки

Мастер и граф:

- Режим переключает общий `pedSlidingUniqueValues`; радиокнопки диалога только отражают режим. Смена режима не очищает латентные флаги «Прочие» и «Пропущенные».
- `ColumnEditDialog` и `FactorEditDialog` — модальные окна вне корня мастера; читать их отдельным корнем.
- До первого Execute выходной маппинг пуст. Native Next валидирует настройку; полный инвентарь выхода проверяется после материализации.
- При полной замене ролей удалять записи группы с конца: удалённая запись получает `Disposition=0`, `Order=-1`.
- Cancel неизменённого редактора выходного порта деактивирует порт и заменяет тело узла; для чтения использовать Preview после свежего Execute, а не редактор выхода.
- Повторное включение автосинхронизации через основной мастер отказывает на Native Next; включать отдельным собственным выходом, только когда последний readback подтвердил `autosync=false`.
- Заполненная видимая область: новый узел ставится в свободный ряд ниже, затем штатное уменьшение масштаба.
- Поле за пределами видимой области списка выбирается прокруткой единственного view.

Данные и чтение:

- Первый снимок Table сразу после открытия может вернуть старую схему и 0 строк при `isLoading=false`.
- В таблице ASCII-пробел и пустая строка отображаются NBSP; значение брать из кэша записи.
- Метка пустой категории не имеет ведущего разделителя (`Amount.Сумма`), у пробела он есть.
- При двух фактах порядок полей — сначала весь первый факт, затем второй; порядок ролей и материализованных полей не совпадает.
- Сумма целого — real; Count, UniqueCount, NullCount — integer; Min, Max, First, Last сохраняют тип факта.
- Native-чтение ограничено 50 × 8 и 1 MiB, протокол 321; шире — точный formatted reader. Отказ native не даёт fallback.
- Для чтения Variant предок должен быть исполнен в текущей группе процессов; старые группы истории не принимаются.

Процесс:

- Промежуточное сохранение ломало следующее чтение: сохранять один раз после всех чтений.
- В ограниченном executor standalone нет `structuredClone`.
- `UI_EPOCH_CHANGED` — действие по устаревшему наблюдению; повторять только после нового наблюдения.
- Вложений не больше восьми.
