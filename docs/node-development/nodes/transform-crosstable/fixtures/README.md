Эти входы подготовлены до кода обработчика. `manifest.json` фиксирует байты и SHA256; наблюдённый контракт и ограничения перечислены в ../discovery.md. Наблюдения на отдельном диагностическом `base.csv` (154 байта) не являются проверкой версионированного `fixtures/base.csv` (175 байт).

- `base/add/drop/replace`: добавление, удаление и замена категории при повторном выполнении того же узла.
- `wide`: 13 категорий, 52 строки; при пяти агрегатах ожидаемая ширина превышает 64 поля. Выходной контракт пока не закреплён.
- `many-fields`: роли за пределами исходного viewport списка полей.
- `multi-key`: несколько ключей строк.
- `null-empty`: NULL, пустая строка, пробел, литерал `null`, all-null факт.
- `empty`: только заголовок.

`acceptance/data/sales-base.csv` и `sales-update.csv` содержат по 64 строки и 1510 байт: замена B на D и изменение фактов. Независимый oracle.py, expected.json, initial.json и бизнес-задание сохранены до реализации. Это подготовленная приёмка, не PASS автономного прогона.

Дополнительные numeric/numeric-integer/types/categories/names проверяют типы, NULL, StdDev, Sliding limit/min и коллизии имён. Непроверенные варианты не расширяют scope ядра.
