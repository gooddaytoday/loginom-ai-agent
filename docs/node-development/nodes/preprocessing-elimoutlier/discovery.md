## Обучение, применение и смена источника

У узла в native меню есть **«Обучить узел»**, `mn;mniTeachNode`, отдельно
от «Выполнить узел», `mn;mniActivateNode`. Начальный SD выполнился через
обычный Execute. После смены файла того же импорта на IQR-набор выполнено
отдельное Train; оба аномальных выхода прочитаны без пересоздания узла.
В диалоге режима активации штатно включены «Выполнить узел и все его подузлы»
и «Переобучить узел и все его подузлы»; собственный режим определяется
контекстом процесса, а не «Всегда переобучать». Диалог отменён без правок.

Проверка обычного Execute на сдвинутом распределении прервалась разрывом
связи: `msgbox;cnt` — **«Обнаружен разрыв связи. Восстановить сессию?»**.
Сессия не восстанавливалась; выбран её собственный «Закрыть» и закрыт
browser context. Штатное закрытие пакета и logout этой попытки не доказаны.
Результаты сдвига, сохранённая модель без retrain и её persistence остаются
`not_checked`. Этот отказ окружения не засчитывается как продуктовый PASS
или дефект обработчика. Продолжение исследования — новый профиль и пакет.

Предложение этапа detect: всегда явный Train на текущем входе, затем Execute;
использовать уже имеющийся `trainConfiguredNode` по образцу Кластеризации.
Не вводить пользовательский mode apply или неявно обещать перенос модели
на новый вход. Само наличие кнопки Train не доказывает конвенцию дисперсии.

## Предлагаемый контракт модели

`NODE_TYPES.semantics`:

> Detect outliers in selected continuous numeric fields using explicit SD or
> IQR multipliers. Train/retrain on the current input before Execute. Keep
> all original values. Read all three ports: 0 all rows, 1 outliers excluding
> extremes, 2 extremes. NULL is retained and excluded from statistics. Other
> editing policies and applying a saved model to another input are unsupported.

Это предложение поведения обработчика, не существующий runtime-контракт.
Параметры помещены в отдельный `parameters.outlier`, чтобы не менять прежний
публичный `parameters.ordered` другого типа. В `parameter-schema.json`
описан каждый параметр; метод — строковый enum `sd|iqr`, а не native ordinal.

| Поле | Смысл предлагаемого контракта |
|---|---|
| fields | Полный непустой уникальный список технических имён numeric/continuous; остальные поля сохраняются и не участвуют |
| method | Один метод для выбранных полей; native SD или IQR |
| outlier_factor | Конечное число ≥0, задано явно |
| extreme_factor | Конечное число ≥outlier_factor, задано явно |
| ordered | Уже упорядоченный вход; false в двух основных сценариях; флаг не является командой сортировки |

Новый узел требует все поля; существующий поддерживает patch с чтением
исходных настроек. Список fields целиком определяет ChkUsable; unlisted
поля не удаляются из таблицы. Для каждого выбранного поля явно ставить keep
обоих классов, не сохранять native default clipping. Отказы — до мутации.
Краткий readback: fields, строковый method, оба factors, ordered, обе policies
keep, training basis current_input и три схемы с output_port. Не включать
в него весь DOM, статистические таблицы или oracle. Source/node binding и
исполнение использовать существующие, нового механизма не добавлять.

NULL исключён из статистик/классификации и сохранён на порту 0 в опыте
`conventions` ниже. Пустая строка Note и NULL различены по native маркеру и
кэшу UI, Note не обрабатывался. Это не проверка all-NULL или редактирования
самого строкового поля.

## Oracle, общие изменения и размер

`acceptance/oracle.py` читает только независимо authored CSV из fixtures.
SD сравнивается через квадрат расстояния и рациональную дисперсию;
IQR — через рациональные квартили/границы. После различителя SD исправлен на
population variance с делителем n; прежний sample-вариант был неподтверждённым
предположением этапа 0. Неравенства oracle строгие; native equality проверено
для IQR, а не SD. Точная IQR-конвенция остаётся
открытой: без явной диагностической гипотезы oracle требует совпадения всех
оставшихся вариантов. Оба основных expected остались побайтно прежними;
ни один модельный FAIL задним числом не корректировался. Подробные критерии,
допуски, ordered и независимые порты — в acceptance/README.md.

Общие W2/W3 уже есть в базе: `expected-outputs.mjs` принимает `tolerance`,
`ordered`, `column_order:exact`, `output_port`; матчинг различает node_id/port.
Существуют общий Train, оболочка табличного узла, чтение нескольких выходов,
портовые редакторы и lifecycle. По наблюдённому срезу отдельное изменение
общих алгоритмов не выявлено. Нужны собственные elim-outlier-модули и их
аддитивная регистрация в node-contracts/API/support/procedure/result/UI,
раздел навыка и сценарии run-check. Старые guards не ослабляются.
Если реализация обнаружит необходимость общей правки сверх регистрации,
это стоп с вопросом, а не разрешение её сделать по этому документу.

## История первой остановки исследования

Три последовательных новых профиля потеряли native соединение с тем же
сообщением `msgbox;cnt`: «Обнаружен разрыв связи. Восстановить сессию?».
Первые два — worker (основные SD/IQR-наблюдения; затем попытка SD-boundary),
третий — reviewer своей пары (сохранение минимального пакета; попытка его
скачивания). Во всех выбрано собственное «Закрыть» без восстановления и
закрыт browser context. В первом профиле разрыв стал явно виден после
перерисовки окна; до него старый DOM не использован как результат сдвига.
Штатные package_closed/logged_out этих прерванных попыток не подтверждены.
Ближайший записанный образец нагрузки перед третьим отказом (11:31:30 UTC):
load1=2.41, load5=3.44, 12 ядер. Load ровно в момент отказа и стартовая
нагрузка каждой ручной попытки не фиксировались; класс «нагрузка» не
заявляется. Эти попытки не выдаются за run-check-прогоны.

По правилу сквада «3 одинаковых подряд — вопрос» дальнейшие живые попытки
остановлены, LAB-531 переведён в blocked. Ни один из трёх исходов не объявлен
PASS. Полный native fulltype, NULL/пустая строка, конвенции SD/квартилей,
точные equality-границы, ordered=true и сохранённая модель/apply остаются
not_checked. Дополнительный исходный CSV и oracle не заменяют наблюдение.
На момент этой остановки требовалось продолжение исследования. Итоговый объём
позднее уточнён оркестратором; непроверенные пункты не стали PASS.
