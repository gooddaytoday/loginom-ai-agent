## Политики: что различено

`policies.csv`: non-NULL X=[0,2,2,2,2,4,20], SD 1/2; только RowID 7 —
экстремум. Все нетронутые столбцы/NULL сохранялись. На выходе 2 оставались
исходные RowID=7, X=20, Note=spike, включая delete и constant.
Схема выходов — RowID integer, X real, Note string.

| Политики обоих классов | Наблюдение порта 0 | Независимое предложение |
|---|---|---|
| constant: выброс −7, экстремум −9 | RowID 7 → −9 | отдельные константы |
| delete | RowID 7 отсутствует; 7 строк | удалить всю запись только в порту 0 |
| mean | RowID 7 → 2,00 | среднее нормальных [0,2,2,2,2,4] = 2 |
| median | RowID 7 → 2,00 | верхняя медиана всей non-NULL выборки = 2 |
| most_probable | RowID 7 → 2,50 | центр модального интервала всей non-NULL выборки = 5/2 |
| limit | RowID 7 → 3,15 | 2+sqrt(4/3), по нормальной выборке; **точность и обобщение требуют preflight** |

Прежний oracle LAB-1018 использовал все значения для mean и исходные
1σ/2σ для limit: эти две гипотезы отвергнуты. Исправлены предложения
`expected-mean.json`/`expected-limit.json`, а не подогнан результат
продуктового FAIL: обработчик edit ещё не реализован.

`replacement-discriminator.csv` различает выборку замены: нормальные
[0,2,2,2,3,4,6], экстремум 60. Независимые альтернативы:
mean=19/7 против 79/8 со spike; median=2 против 3; most_probable=9/4
против 15/2. Native дал соответственно **2,71; 3,00; 7,50**: среднее использует
нормальную выборку, медиана и наиболее вероятное — всю non-NULL выборку.
Это дополнительные положительные задания и expected.
Числа Quick Preview отображаются с двумя знаками: такое чтение подтверждает
различитель, но не binary64 точность computed real. Предлагаемый допуск
abs/rel 1e-10 проверяется только CSV и точным native чтением этапа 1.
Дополнительное чтение штатной Table: `ViewsForm;BrowseView;btnDataGridFormat`,
выбор X в `ModalWindow_BrowseFormat;BrowseFormat;colDisplayName_X`,
custom mask `0.################E+00` в `BrowseFormatPanel;edtFormatStr`.
В `ViewsForm;BrowseView;normalHeaderCt;X_7` для replacement fixture получены
Moda=7,5E+00 и limit=4,463921244845127E+00. Последнее совпало с независимым
19/7+sqrt(150/49), подтверждая SD 1/2 clip на втором наборе с 17 значащими
цифрами. Это native preflight Table, не CSV/cold или модельная приёмка.
С теми же исходными данными и SD 1,5/2,5 ограничение экстремума стало
5,338739010124833E+00: соответствует 19/7+1,5*sqrt(150/49) с погрешностью
binary64 около 1e-15, а не множителю экстремумов 2,5.
Для limit произвольные множители, действия разных классов и нулевая
нормальная выборка пока не образуют подтверждённого общего алгоритма.

## Квартили: численный независимый oracle

В `quartile-conventions.csv` перед запуском прочитаны именно SD=11,
IQR=12,25, Fence=13,25, Nullable=12,75 в исходном порту. Все четыре поля —
IQR 1,5/3 и keep/keep. Порт выбросов дал **только RowID 23, Fence=13,25**.
Это единственная из шести заранее описанных гипотез: upper-rank,
Q(p)=sorted_non_null[min(floor(n*p),n−1)]. Никакой интерполяции.

| Поле | n | Q1 | Q3 | Границы 1,5 IQR | Ожидаемый выброс |
|---|---:|---:|---:|---|---|
| SD | 7 | 2 | 6 | −4…12 | нет |
| IQR | 8 | 3 | 7 | −3…13 | нет |
| Fence | 9 | 3 | 7 | −3…13 | 13,25 |
| Nullable | 8 | 3 | 7 | −3…13 | нет |

Это вывод из различителя, не чтение внутренних learned-statistics.
Для прямого численного контроля границ добавлен `quartile-boundaries.csv`:
n=16, Q1=3, Q3=7, внешние границы −3/13, экстремальные −9/19.
Native порт 0 сохранил все 16 строк, порт 1 дал только RowID 1 (−3,25)
и 15 (13,25), порт 2 — только RowID 16 (25). Равенства −3/13 не аномальны.
Все числа точно представимы; этот набор полностью сверяется с независимым
`oracle.py --case quartile-boundaries --quartile-convention upper_rank`.
Старый oracle не выбирает конвенцию молча для остальных diagnostic cases.

## Ограничения платформы и apply

На активной странице с выбранным используемым SD-полем `pedUseQuality`
имеет inline `display:none`; `ValueControl;InputEl/DisplayEl` невидимы.
Штатное значение false прочитано существующим read-only reader
`readElimOutlierBrowser`, который подтвердил binding_ready=true.
**Ограничение платформы 7.4.2:** качество выхода нельзя включить через UI.
Скрытый checkbox не нажимался, XML/RPC для изменения настроек не использовались.
По этому пункту действует stop из карточки, до согласования исключения.

Для apply обучен policies.csv с constant −7/−9, затем в том же импорте
выбран policies-apply.csv и выполнен только импорт и `mn;mniActivateNode`.
Получено X=[−7,12,−7,NULL], порт 1 содержит исходные 2 и 30, порт 2 пуст.
Это пересчёт по новому среднему 44/3 и дисперсии 1208/9, а не старый fit
32/7 и 2000/49 (при нём порт 1=[12], порт 2=[30]).
Повтор с `ConfigureBatchProcModesForm;rbAlwaysRun;DisplayEl`, явным Train
исходных данных и повторной сменой файла дал тот же пересчёт.
Ограничение проверенного UI-пути: «Всегда выполнять» не сохраняет старые
границы после настройки нового источника. Иные пути переноса модели и
persistence apply не проверены; общего доказательства невозможности нет.
`expected-apply.json` и `--apply` остаются желаемым frozen-fit контрастом,
**не native expected и не критерием выпуска**. Текущий проект карточки
типа исключает quality/apply до решения владельца.

## Предложенная приёмка и этап 1

Задания/CSV передаются модели; oracle/expected ей не передаются.
Критерии: полные типизированные 0/1/2, неизменяемые поля и NULL, точные ID,
число/порядок строк, исходные боковые выходы, независимые политики/константы;
непредписанные метки через label_any. CSV, Save, cold без перенастройки,
cleanup; 2/3 исполнителя и 2/3 независимой проверки одного SHA. Ни один
из этих прогонов здесь не выполнен. [Матрица предложений](acceptance/modes-proposal.md).

Собственные изменения: `elim-outlier-parameters.mjs`, `-procedure.mjs`,
`-context.mjs`, `-readback.mjs`, `-output.mjs`, `-node.mjs`, собственные тесты;
аддитивная карточка/схема в `node-contracts.mjs`, описание навыка и сценарии
run-check. Общего рефакторинга, изменения `packages/agent` или нового verifier
не требуется для detect/edit. Для apply этого вывода нет — не реализовывать.
Оценка после решения: 2–3 цикла для политик, 1 цикл для границ/регрессии;
каждый цикл с новым бизнес-прогоном. Limit вне SD 1/2 — дополнительный discovery,
а не обещанная задача на один цикл. [Бюджеты предложений](model-contract/modes-budgets.md).
