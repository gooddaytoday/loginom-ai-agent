**Несколько листов в одной книге — огр. 7.4.2, не берём.** В мастере нет
режима «добавить лист» (`plan.md:34-35`), а запись в существующую книгу
заменяет её целиком (`plan.md:43-46`): второй узел экспорта в тот же файл
оставит только свой лист. Это то же ограничение, что «замена одного листа».

Источник переменных — штатный Калькулятор переменных (string), как в LGD #793:
выход builtin «Переменные сценария» до активации не исполняется
(`../../../exports-lgd/acceptance/task-variable.md:8`). Путь к файлу собирает
run-check (`{{EXCEL_*_DESTINATION}}`, по образцу `{{LGD_INITIAL_DESTINATION}}`).
Имена файлов в этих путях должны быть `excel-var-a.xlsx` и `excel-var-b.xlsx`:
oracle сверяет `path.name` с `filename` (иначе FAIL `FILENAME`).

состояние того же sink и обе реальные привязки, не переписывая настройки.

### Предлагаемые критерии карточки цикла

1. Книга A: имя файла = начальное значение ExcelPath, единственный лист
   «Январь», заголовок Code/Amount, три строки в исходном порядке, Code — текст,
   Amount — число с исходной точностью.
2. После смены только значений переменных и повторного выполнения того же
   Калькулятора и того же Экспорта (`parameters:{}`) — книга B по новому пути
   с единственным листом «Февраль» и теми же данными; второго узла экспорта нет.
3. В сохранённом пакете у узла обе привязки (`/excel_export/destination`,
   `/excel_export/sheet_name`) — к переменным, не литералы; cold-проверка
   читает привязку, а не текущее значение. Литеральный путь/лист — FAIL.
4. `overwrite:reject` сохраняется: существующий файл не заменяется.
5. Стандарт сквада: cold, Save, cleanup, 2/3 у исполнителя и 2/3 у
   проверяющего на одном SHA. Новых критериев сверх стандарта нет.
