## 1. Наблюдения и пределы

Живое исследование на `https://app.loginom.ai/app/?testable=true` подтвердило
Loginom 7.4.2, компонент «Экспорт > Excel файл», icon class
`bg-vendor-icon-exportexcelfile`, один табличный вход и отсутствие табличного выхода.
Страницы: входные столбцы → ExportExcelFilePreviewWizard → DoneWizard.
Точные data-tid, defaults и причина отказа пустого пути — в discovery.
Fulltype известен из назначения, самостоятельное чтение в UI не выполнено;
редакция/ОС сервера, train/apply, исполнение и формирование XLSX не проверены.
Текущая готовность runtime не повышается.

Работа остановлена по условию карточки «нужна общая правка сверх разрешённых»:
общий observer не распознаёт страницу Excel, lifecycle sink ограничен
exports.text, run-check/cold ориентированы на CSV. Исходные locations и
минимальные предложения перечислены в discovery. Общий код здесь не изменяется.

## 2. Решения для утверждения владельцем

- Этап 1: новая `.xlsx` книга, один явно названный лист, исходный порядок полей
  и строк, scalar types; файл доставляется через `output.file_artifacts`.
- `parameters.excel_export`: destination, sheet_name, header (none/names/labels),
  overwrite (только reject). New требует все четыре; existing — patch с сохранением
  пропущенного. Числовой формат — общий, без параметров округления.
- NULL и пустая строка различаются в OOXML; формулоподобный текст остаётся строкой.
  Boolean отличается от number; даты — локальные, допуск 1 мс. Числа Amount:
  abs 1e-9, rel 1e-12. Остальные значения и порядок точные.
- Результат — sink; `read.ports=[]`, в предлагаемом expected `output_port:null`.
  XLSX numeric не доказывает native integer/real schema: cold сверяет её на входе.
- Разрешить минимальные общие изменения observer/lifecycle и XLSX-сценария/cold,
  перечисленные в discovery, либо выделить их в отдельное назначение.

Предложение не означает утверждения. При схлопывании NULL/empty штатным exporter,
неподтверждённой точности или необходимости иной семантики вернуть критерий
владельцу. Не менять oracle под фактический результат.

## 3. Приёмочные данные и ожидаемые числа

`fixtures/cells.csv`: пять строк, Id/Text/Amount/Occurred/Active в этом порядке.
Id — integer, Text — string, Amount — real, Occurred — datetime, Active — boolean.
UTF-8, comma CSV, dot decimal, NULL marker `NULL` (не устаревший `\N`).
Пустая строка Text отдельно от NULL, кириллица, кавычка и перенос,
1234.56789, ноль, отрицательное значение и строка `=SUM(A1:A2)`.

Ожидания созданы до прогонов: 25 значений, 4 NULL, одна пустая строка,
Amount sum 1242.06789. С метками/именами заголовков — 30 позиций ячеек,
без заголовка — 25. `empty.csv` — та же схема без строк; с header ожидается
пять заголовков. Полные значения — `acceptance/expected.json`.

`acceptance/task.md` — только бизнес-задание; модель получает его и входной CSV.
Oracle/expected/schema/tests модели не передаются. Независимый oracle читает
XLSX ZIP/XML средствами Python, без Loginom. Offline-тесты используют openpyxl
как независимый writer и намеренно искажённые книги.
Квитанции, receipts и доказательства происхождения не требуются.

## 4. Этап 1 после разрешения блокера

| Требование | Предлагаемый критерий |
|---|---|
| r01: workbook | Новая книга XLSX, один лист, все 25 значений и scalar cell types |
| r02: headers | none/names/labels, точный порядок, кириллические метки |
| NULL/empty | Отдельная пустая строка и четыре NULL, false и 0 различаются |
| Precision | Числа не округлены отображением; даты в допуске 1 мс |
| Safe failure | Неверные параметры и существующий destination отвергаются до записи |
| Existing node | Patch сохраняет пропущенное; свежий источник не возвращает старый файл |
| Delivery | Штатный file_artifacts с XLSX; независимый oracle проверяет сам файл |
| Save/cold | Новый профиль, сохранённый граф/настройки/типы, полный XLSX, close/logout |
| Regression | Проверки по required-checks для реально изменённых путей |

Done сохраняет настройки без исполнения, Execute создаёт файл без обучения,
Close закрывает собственный draft. Это контракт для реализации, не live-PASS.
При неизвестном эффекте записи не повторять автоматически. Подмена файлового
результата проверкой одной входной таблицы запрещена.

Общая inputSchema: оценка 43 329 → 44 263 Б, **+934 Б** на тип, лимит 1 050 Б.
Повторяемый замер — `acceptance/schema-size.mjs`; базовая проверка —
`client/test/node-caption-schema.test.mjs`. Запас всего состава v0.3.9 оценивается
отдельно; общий budget не меняется.

Оценка: 3–4 цикла после разрешения общих изменений. Приёмка после реализации:
run-check, ≥2 PASS из 3 на одном SHA и независимые 2/3 на том же SHA; тесты по
путям, Save, cold, штатные package close/logout. Этот docs-PR не заменяет приёмку.
