## 2. Этапы

### Этап 0 — подготовка, живое исследование, контракт

Checkout/SHA и сборка из закоммиченных исходников, `loginom status` = `ready`; квалифицировать внешнюю среду отдельно. Каждый отказ мастера читать из кнопки ошибки.

1. Палитру «Экспорт > Excel файл», корень мастера, входную таблицу и отсутствие табличного выхода.
2. Имя листа (Help: Лист 1), xls/xlsx и заголовки; умолчания числового отображения и границы 0..30.
3. Когда возникает файл: Execute и «Активация и просмотр»; последний жест также имеет файловый эффект.
4. Создание/перезапись существующего файла и листа; способы download, имена/типы ячеек и NULL/empty.
5. Смену исходной таблицы того же узла; неверный лист/путь, недоступный каталог, пустой вход и потерю ответа.

Результат — `discovery.md`: observed/hypothesis, exact значения/типы/имена, границы источника и side effects, решения по W. Выход — `ready_for_development` только после снятия блокеров; закреплённые type/mode, `fixtures/` и `acceptance/` до кода обработчика.

### Этап 1 — самостоятельный первый срез

Scope: Новая xlsx-книга, один явно названный лист, фиксированный путь; варианты заголовка без строки / имена / метки; небольшой полный лист. Создание и настройка существующего узла; readback фактически наблюдённых настроек и свежести результата. Неподдержанные формат/порт/режим/тип/параметр отклоняются до мутации с понятным объяснением исправления.

Требования этапа 1 (частичные режимы явно ограничены разделом 1):

- `exports-excel:r01` — Имя файла/листа и форматы Excel 2003 .xls / Excel 2007 .xlsx.
- `exports-excel:r02` — Заголовок отсутствует / имена полей / метки полей.

Источник и подключение выбираются по наблюдённой identity, не по похожей метке. Для внешней БД/Kafka/DW/1С `artifact_id` и `upload_operation_id` не описывают подключение и не заменяют проверку внешнего объекта. Табличные входы экспорта можно доставить принятым текстовым импортом с проверенным upload receipt; загрузка не подтверждает экспортированный результат.

Файлы: новые `packages/loginom-runtime/client/lib/exports-excel-{node,parameters,procedure,readback}.mjs`, тесты `client/test/exports-excel-*.test.mjs`; регистрация `node-contracts.mjs`/`.d.ts`, `node-support.mjs`, `node-api.mjs`, `node-result-schema.mjs`, `user-results.mjs`. Образец — [Текстовый экспорт](../../../../packages/loginom-runtime/client/lib/text-export-node.mjs), не переносить его семантику/формат. Общие `node-procedure.mjs`/`workspace-ui.mjs` меняются только в согласованных W.

Общие изменения, каждый отдельным коммитом с адресными тестами:

- **W1** — расширить файловый результат экспорта за пределы exports.text: бинарные байты, размер/digest, destination и execution receipt; node-result-schema/user-results и проверяемый artifact transport.
- **W2** — независимая файловая приёмка после сохранения и нового открытия: oracle XLS/XLSX, полный лист, формат/метаданные; scripts/node-acceptance, без фиктивного табличного expected.
- **W3** — этап 2: управляющие bindings пути и настроек; node-api/node-procedure/workspace-ui, без переноса ограниченного контракта Кросс-таблицы.

Видимость для модели: `NODE_TYPES.semantics` объясняет бизнес-результат и побочные эффекты; `description` у каждого параметра, строковые enum, компактный readback. Наблюдённые значения отличать от запроса модели.

Тесты из `packages/loginom-runtime`: `bun run test:upstream`; при изменении приёмки — из того же каталога `node --test ../../scripts/node-acceptance/tests/*.test.mjs`. Команды новых адресных тестов закрепить после появления файлов; сейчас они не существуют.

## 3. Данные и независимые проверки

Комплект `nodes/exports-excel/acceptance/` (для следующих этапов `acceptance/stageN/`): `task.md` с `{{PACKAGE_PATH}}`, `data/` только для входов модели, `expected.json` из независимого `oracle.py` до обработчика. Внешние manifests, oracle и ожидания модели не передаются; секреты — только во внешнем окружении.

CSV-спецификации: UTF-8, разделитель `,`, decimal `.`, header, NULL-маркер `\N`; empty string отличается от NULL. `fixtures/manifest.json`: фактические байты/SHA256, типы/метки/порядок и происхождение каждого бинарного файла/внешнего объекта; размер фиксируется при генерации, а не угадывается.

| Набор | Содержание и назначение |
|---|---|
| `cells.csv` | Id,Text,Amount,Occurred,Active; пять строк с кириллицей, кавычками/переносами, NULL, пустой строкой, датой, true/false, 1234.56789 и строкой =SUM(A1:A2). |
| `empty.csv / replace.csv` | Ноль строк с той же схемой; новая таблица той же схемы и другими Id/Amount для проверки свежего файла. |
| `destination-copy.xlsx` | Независимый reader/writer готовит книгу со вторым листом и контрольным значением: отказ/замена проверяются только на этой копии. |

Правило `typed.csv`/`cells.csv` для этих типов: столбцы `Id,Text,Amount,Occurred,Active`; строка i=1..5 имеет Id=i, Amount=[1234.56789,0,NULL,-2.5,10][i−1], Text=[Кириллица,строка с кавычкой и переносом,NULL,пустая строка,=SUM(A1:A2)][i−1], Occurred=2024-02-29T12:30:00.000 (у i=3 NULL), Active=true у нечётных Id, false у чётных (у i=3 NULL). Для семи строк добавить (6,Ж,0.5,2024-03-01T00:00:00.000,true),(7,З,-0.5,2024-03-02T00:00:00.000,false). Метки/виды/назначения и Variant исходного пакета перечислить в manifest до прогона.

Oracle не импортирует handler/runtime, считает по входам, сверяет все ячейки/объекты/байты, имена/метки/типы/порядок полей, NULL/empty/0. Отклоняет старое исполнение, чужой destination/узел и подмену данных; E2E preview/обратный импорт не является независимым эталоном.

Нынешний cold-check принимает только таблицы: `expected-outputs.mjs:2-23`, нет файлов, sink или переменных. `expected.json` этого узла — **предлагаемая** схема files[] с destination/format/size/digest/структурой, до W она не принимается обвязкой. Нельзя добавлять фиктивный табличный output или объявлять PASS лишь по входной таблице. W приёмки обязателен перед этапом 1; после cold-open сверять настройки/граф и уже произошедший эффект, не повторять внешнюю запись вслепую.

## 4. Проверки, приёмка и завершение

Непроведённая проверка — `not_checked`; ожидания/границы фиксируются до модельного прогона.

| Требование / проверка | Независимое условие успеха |
|---|---|
| `exports-excel:r01` | Проверить сигнатуру формата, лист, все ячейки и метаданные; одинаковое расширение не доказывает формат. Пустой вход даёт согласованную книгу. |
| `exports-excel:r02` | Сравнить первую строку и смещение данных: count=5 без header, count=6 с header; кириллические метки сохраняются. |
| `exports-excel:r03` | Проверять значение ячейки отдельно от number format: отображение 1234.57 не должно округлять исходное 1234.56789. Границы -1/31 отвергаются. |
| `exports-excel:r04` | Ключи переменных получить discovery; повтор/конфликт destination проверять на копии. Preview activation имеет file effect и учитывается в journal. |
| Контракт и отказы | Неверные настройки/типы отклонены до эффекта; исходная ошибка мастера сохранена |
| Изменение существующего | Настройки/связи readback подтверждены; новый источник не даёт старый результат; незапрошенные свойства сохранены |
| Persistence | Сохранить после всех чтений; открыть новым профилем без восстановления настроек; внешние эффекты и происхождение проверить по согласованному W |
| Recovery | Потерянный ответ не повторяет неизвестный эффект; результат сверяется независимо перед продолжением |
| Регрессия | Адресные тесты нового узла и полный `client/test`; прежние контракты не ослаблены |

Задание модели: Выгрузить приложенную таблицу в новую книгу Excel с понятным именем листа и русскими заголовками, проверить результат и сохранить новый пакет в {{PACKAGE_PATH}}.

PASS исполнителя: CLI и применимый cold-check/согласованный независимый аудит результата, адресная матрица, `package_closed=true`, `logged_out=true`. Файловый/внешний/переменный результат нельзя объявить принятым неподходящим oracle. Публикация и Ловец принимают тот же чистый SHA по RUNBOOK; `integration` и `release` не меняются.

## 5. Ловушки — переподтвердить, не копировать

Ниже документальные ограничения и требования прежнего черновика; точные controls и runtime-семантика для стенда остаются гипотезами до этапа 0.

Исходная таблица + необязательные управляющие переменные → файл Excel; табличного выходного порта нет.

Независимо приготовленная таблица из 5 строк: кириллица, кавычки/переносы, NULL/empty, дата, boolean, 1234.56789 и формулоподобный текст. Файл читает независимая библиотека XLS/XLSX, без handler импорта.

Имя листа/формат/destination проверять до записи. Сохранить старый файл при отказе; не предполагать append/overwrite семантику — её требует discovery. Активация в мастере не является безопасным read.
