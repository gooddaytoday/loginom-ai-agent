# REST: комплект расширения, этап 0 (LAB-976)

**Предложение, не принятая функциональность.** База — `v040` на
`4b202757f6d0021160dd4dfc104ee788ae33cbec`. Runtime и установленный skill
этим комплектом не меняются. Результаты живого UI-исследования и границы
доказательств — в `../../modes-discovery.md`; порядок отдельных PR — в разделе 7
`../../plan.md`. Перед кодом владелец утверждает критерии каждого цикла.

У всех циклов один сетевой oracle: заранее заданные стабильные поля публичного
echo/auth/status контракта; вычисления ожидаемых значений выполняет Python stdlib,
без Loginom, модели и сети. У имитации источником истины служат исходные байты
response.json. Относительный `export_destination` — подсказка размещения:
при подготовке запуска `run-check` заменяет его полным уникальным путём своей
пары, а `{{PACKAGE_PATH}}` — новым `.lgp`. В stock parser эти значения проверяют
уже после такой подстановки. Имена результатов не совпадают с входными файлами.

Для request dump oracle независимо вычисляет исходные UTF-8 тела и их длины
41/29 байт. Формат/имена native dump-файлов не наблюдались. Исполняемый файловый
matcher не добавлен: нужен отдельный одобренный критерий и наблюдение формата;
совпадение echo-таблицы само по себе не принимает этот цикл.

Модели передаются **только задание и указанные исходные файлы**.
`oracle.py`, expected, manifest, предложение карточки и наблюдения — исключительно
для приёмки/ревью. Auth-подключения готовятся в приватном исходном пакете своей
пары; секретный пакет и значения не коммитятся и не прикладываются к отчёту.
Оператор проверяет доступность обоих адресов со стенда до модельного запуска.
Bearer может возвращать token в JSON: модель должна читать только конечную
таблицу с authenticated, а readback не должен раскрывать credentials.

Проверка воспроизводимости (из корня checkout):

```sh
python3 docs/node-development/nodes/integration-restrequest/acceptance/modes/oracle.py --check
```

Для осознанного обновления предложения используется `--write`; один цикл можно
выбрать `--case methods-body`. `--write` не запускает модель и не утверждает
полученные ожидания. Все десять гидратированных документов проверяются существующим
`parseExpectedOutputs` из `scripts/node-acceptance/expected-outputs.mjs`.
Для C1 решение оркестратора LAB-985 разрешает raw Response вместо модельного
разбора JSON. RowID 0/1 связывает ответ с прежними двумя requests.csv; Body
и метки методов в requests-c1.csv повторяют те же исходные строки. Python oracle
генерирует ожидаемые method/data, CSV и cold сравнивают только эту проекцию,
не меняя типы/NULL и не нормализуя текст Body. Нестабильные headers/origin/url
ответа не сравниваются. Expected/oracle модели не передаются.
Для error-descriptions внешний сценарий штатно убирает routing hint
export_destination перед stock parser. Проверяется непосредственно REST port 1,
поэтому удаление ErrorDesc только после REST не сможет подменить native критерий.

После утверждения и реализации каждый табличный цикл получает аддитивную
регистрацию в существующем каталоге `run-check`, без своего runner и новых matcher.
C9 остаётся остановлен до отдельного решения по файловой приёмке.
Нужны штатные CSV/Save/cold/cleanup, ≥2 PASS из 3 на одном SHA у исполнителя
и 2/3 на том же SHA у независимой проверки своей парой. Cold читает конечный
экспорт (для C10 — REST port 1) из сохранённого пакета без повторной настройки. В headers/variables
первый ответ `first` показывается до изменения; expected проверяет сохранённый
окончательный `second`. Первое выполнение и неизменность binding дополнительно
проверяются по штатным configuration/readback и журналу операций того же узла;
один конечный CSV этого не доказывает.

Повторы и TLS-negative требуют отдельного решения: итоговые данные не позволяют
утверждать точное количество/интервалы HTTP-попыток или отказ неверного сертификата.
Новый ledger, перехват Loginom, собственный сервис и новые виды проверки здесь
не предлагаются как уже разрешённые. Симуляция сравнивает возвращённое тело;
отсутствие сетевого запроса по этому CSV не утверждается. Отрицательные auth/TLS,
клиентские сертификаты, бинарные MIME, timezone и пустая таблица пока не включены
в PASS-критерий: их состояние явно отделено в discovery.

`type-card-proposed.json` и `node-reference-proposed.md` — измеримые предложения
для будущих циклов, не файлы установленного продукта. Хеш-поля карточки заменены
64 нулями. Новые числовые/строковые ограничения карточки — предлагаемые защитные
границы обработчика, а не измеренные границы Loginom UI.
