### Цикл 3 (external): приёмка

Решение оркестратора (LAB-1177): нужны оба способа, singleton-пример сам по себе
даёт ложный PASS — автообучение 5%/2/0 на zero-frequency.csv строит те же два
класса с той же нумерацией.

(а) **Контрастный пример** — task-external-contrast.md, fixtures/external-contrast.csv
(19 строк: A 3/1, B 5/2, C 1/7 событий/не-событий) и external-contrast-classes.csv
(B=0, A и C=1) / expected-external-contrast.json. Заданный класс {A,C} не смежен
по доле событий (C<B<A), поэтому слиянием соседей автообучение его не получит;
лучшее такое слияние {C}|{A,B} даёт IV≈1.72 против 0.572 у заданного. В каждом
классе есть события и не-события (правило нулевой доли не участвует), WoE различны,
а заданные номера уже идут по возрастанию WoE (B=0, {A,C}=1) — expected не зависит
от наблюдения о перенумерации. Отличие от автообучения видно в портах 0
(A и C в одном классе) и 2 (общий IV). Oracle проверяет эти условия assert'ами.

(б) **Аудит в цикле:** readback `fine_classes=true` у Segment и связей дополнительного
входа (ColumnName → идентификатор, ClassNumber → номер класса, UniqueValue →
категория) до и после reopen. Без него остаётся ложный PASS: внешний вход
подключён, но готовое разбиение выключено и оптимизация стартует с тех же классов.

**Сверка на стенде — первый шаг цикла 3** (при расхождении — стоп и docs-PR):
1. нумерация классов внешнего разбиения (перенумерация по WoE);
2. форма порта 1 для класса из нескольких категорий: в expected — строка на каждое
   UniqueValue со статистикой класса, порядок ClassNumber, затем UniqueValue;
3. текст ClassMark многокатегорийного класса (в expected сверяется биекцией
   `category_labels_any`, «[A,C]» — условная метка);
4. Significance при IV=0.572 («Высокая» наблюдалась только при 1.66 и 3.64).

Проекты `*proposal*` (справка, карточка, схема, semantics) — источник идей для
цикла, а не замена текущей справки и semantics.
Служебный текст не переносить; дописывать внутри mode-секций действующих
