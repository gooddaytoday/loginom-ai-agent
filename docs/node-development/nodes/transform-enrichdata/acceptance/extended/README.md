## Живое исследование

Новый собственный черновик, worker назначенной пары. Элементы выбраны по
data-tid, прочитан DOM без вмешательства во внутренний JavaScript Loginom.

Для доступности третьего/четвёртого входа использовался один собственный
импорт replacement/fixtures/extended/input.csv на всех пяти входах, ключ Id=Id.
Это наблюдение доступности и добавления столбцов, не испытание дубликатов.
Имена и все значения прочитаны через
`MF;TF-1;ModelForm;PreviewWindow;PreviewForm;DataSetForm;normalHeaderCt;`:
ячейки `Id_<0..7>`, `Code_<0..7>`, `Code_1_<0..7>` ... `Keep_4_<0..7>`.
Заголовок Code_1 и ячейка Code строки 1 имеют одинаковый data-tid; для чтения
ячеек дополнительно использован DOM-тег td. Это неоднозначность UI-идентификатора,
не основание ослаблять идентичность поля в runtime.

Исследовательский UI один раз показал `msgbox` «Обнаружен разрыв связи»;
восстановлен штатно, не модельный прогон. Сырые DOM-снимки хранятся вне Git.
Save/cold и выполнение предложенных adversarial fixtures не проводились.

### Ненайденные режимы и общая граница

Другие виды соединения, вычисляемый ключ и его преобразование не обнаружены
как настройки EnrichDataWizard. Это граница наблюдения данного мастера,
не утверждение о невозможности решить задачу другим узлом или общей настройкой
входного порта. Upstream Калькулятор / Параметры полей / Соединение не считаются
новыми режимами Дополнения. Общий mapping API сейчас допускает имя/метку/
исключение, но не type/formula; расширять его в этом назначении нельзя.
Для этих трёх пунктов цикл обработчика не предлагается: требуется решение
владельца по отсутствию режима в UI.

`coverage=full` — политика инструмента, а не переключатель Loginom.
В базе node-api.mjs, условие allOf для full, и node-apply.mjs:77 разрешают
только Collapse/CrossTable/JavaScript. Поддержка full для Дополнения требует
согласованной общей правки допуска/чтения и проверки полноты; одного изменения
enrich-*.mjs недостаточно. Это отдельный стоп, не повод обойти gate и назвать
sample полным покрытием full. В предложении карточки full не объявлен.

## Предложенные сценарии

Входы — `../../fixtures/extended/`, manifest с байтами/форматом.
RowID и Key — integer; Note/A/B/C/D — string. UTF-8, запятая,
заголовок, NULL ?, пустая строка отдельно.
`oracle.py` независимо делает null-safe equality и декартово произведение
совпадений, импортируя только Python stdlib. Loginom/handler не вызываются.

| Задание | Входы | Expected | Контрольная ловушка |
|---|---|---|---|
| `../task-three-lookups.md` | main, ref-a, ref-b, ref-c | `expected.json`, 7×6 | 2 A × 2 C для Key=1; отсутствие B не мешает C; NULL совпадает |
| `../task-four-lookups.md` | те же плюс ref-d | `expected-four.json`, 7×7 | Добавить четвёртый вход тому же узлу; D найден для Key=4 при отсутствии A/B/C |

Модели передаются только task и перечисленные входы. Oracle/expected и карточка
proposal ей не передаются. Проверяется весь порт 0: точная схема и порядок полей
через autosync=false, все значения и кратность как мультимножество, метки
label_any, неизменные NULL/empty. Численных допусков не требуется: вычислений real нет.
Повторное выполнение того же узла, полный CSV с ?, Save, cold заново выполняет
сохранённый граф без настройки из expected, затем Close/logout.
Требование full пока отделено от этих сценариев и не подменяется sample_complete.

Будущая стандартная приёмка после утверждения: cold PASS; ≥2/3 исполнителя
и ≥2/3 независимых PASS на одном SHA с разными аккаунтами. Только run-check
start+wait, без новой оснастки, новых лимитов, критериев или special reader.
На этапе 0 fixtures и ожидания — предложение, эти бизнес-прогоны не запускались.

## Предложение реализации и бюджета

Третий и последующие справочники: 1..14 в пределах нынешнего inputs.maxItems=15
и mappings.maxItems=16 (15 входов + выход). Четыре наблюдены, предел 14 —
проектная граница существующего запроса, не проверенный нативный максимум.
Сначала один PR для расширения до ≥3, затем отдельный PR только при наблюдённом
дефекте повторной настройки; оценка 1–2 цикла с живым прогоном между ними.

Собственные файлы: enrich-parameters/context/mappings/procedure/preflight/readback.mjs,
проверить enrich-node.mjs. В них явно зашиты tables≤2, joined stores≤2 и count≤3;
запрещено просто снять guards без полной инвентаризации новых портов/полей.
Аддитивное описание типа/схемы — node-api.mjs/.d.ts, node-contracts.mjs;
существующее additional_tabular_inputs=true уже позволяет создавать порты.
Общая перестройка не нужна для количества справочников по исследованной ветке;
необходимость её при реализации — blocked. Full и типизация mapping в этот
аддитивный срез не входят, нужен ответ владельца.

`node-type.proposal.json` и `skill-node.proposal.md` — только docs, не поставляемые
ресурсы. Hash-поля заменены на 64 нуля. Центральная строка маршрутизации
не расширяется. Точные размеры и воспроизведение — в разделе LAB-1003 подплана.
