## Безопасность

Политика `python-module-v1` (`packages/loginom-runtime/client/lib/python-source-policy.mjs`) проверяет текст кода модели до любой мутации узла. Это не песочница. Решение владельца `python-security-boundary` (15.11.2026): граница безопасности — права ОС среды Python на сервере Loginom; политика защищает от вредного кода, который модель пишет под влиянием данных или текста, а не от пользователя (компонент Python доступен ему в Loginom напрямую). Рекомендация администратору — в [README](../../../../README.md#узел-python-и-сервер-loginom).

Найденные и закрытые классы обходов:
- рассинхрон разбора f-строк — вложенный литерал со скобкой скрывал код поля (#1134, разбор по PEP 701, разностный тест с `tokenize`);
- вызов метода pandas по строковому имени — `df.agg("query", …)`, `df.agg("to_csv", …)` (LAB-1689).

Остаточный риск: методы объектов, которые возвращают разрешённые функции, закрывает только список запретов по именам. После каждой правки политики — новый независимый поиск обходов с подтверждением выполнением; чистый поиск снижает риск, но не доказывает отсутствие обходов.
