## 2. Этапы

### Этап 0 — подготовка, живое исследование, контракт

Checkout/SHA и сборка из закоммиченных исходников, `loginom status` = `ready`; квалифицировать внешнюю среду отдельно. Каждый отказ мастера читать из кнопки ошибки.

1. Палитру «Экспорт > XML файл», root мастера и обязательные XSD/таблицу; табличного выхода нет.
2. Корневой элемент, namespace и совместимость типов связей; одинаковые leaf-name в разных ветвях.
3. BOM, отступы, escaping tabs/newlines и кавычек; умолчания и доступность флагов.
4. Когда возникает файл, его кодировку, NULL/empty/nil и имена/типы целевых элементов.
5. Смену источника того же узла, неверный mandatory field/XSD/mapping, существующий путь и partial XML после потери ответа.

Результат — `discovery.md`: observed/hypothesis, exact значения/типы/имена, границы источника и side effects, решения по W. Выход — `ready_for_development` только после снятия блокеров; закреплённые type/mode, `fixtures/` и `acceptance/` до кода обработчика.

### Этап 1 — самостоятельный первый срез

Scope: Один XSD root, явные и автоматические совместимые field→element/attribute связи, новый XML; BOM и флаги форматирования/escaping по наблюдённому контракту. Создание и настройка существующего узла; readback фактически наблюдённых настроек и свежести результата. Неподдержанные формат/порт/режим/тип/параметр отклоняются до мутации с понятным объяснением исправления.

Требования этапа 1 (частичные режимы явно ограничены разделом 1):

- `exports-xml:r01` — Destination, XSD root, явные и автоматические field→element/attribute связи совместимых типов.
- `exports-xml:r02` — BOM, отступы/переводы строк, экранирование табуляций/переносов в атрибутах и обоих видов кавычек.

Источник и подключение выбираются по наблюдённой identity, не по похожей метке. Для внешней БД/Kafka/DW/1С `artifact_id` и `upload_operation_id` не описывают подключение и не заменяют проверку внешнего объекта. Табличные входы экспорта можно доставить принятым текстовым импортом с проверенным upload receipt; загрузка не подтверждает экспортированный результат.

Файлы: новые `packages/loginom-runtime/client/lib/exports-xml-{node,parameters,procedure,readback}.mjs`, тесты `client/test/exports-xml-*.test.mjs`; регистрация `node-contracts.mjs`/`.d.ts`, `node-support.mjs`, `node-api.mjs`, `node-result-schema.mjs`, `user-results.mjs`. Образец — [Текстовый экспорт](../../../../packages/loginom-runtime/client/lib/text-export-node.mjs), не переносить его семантику/формат. Общие `node-procedure.mjs`/`workspace-ui.mjs` меняются только в согласованных W.

Общие изменения, каждый отдельным коммитом с адресными тестами:

- **W1** — контракт XSD-подключения и порта Подключение с точным набором схем/root/namespace; node-contracts/node-api/node-procedure/workspace-ui.
- **W2** — файловый результат XML за пределами текстового экспорта: digest/size/destination и execution receipt; node-result-schema/user-results.
- **W3** — независимая файловая приёмка байтов/XML/XSD и reconciliation partial файла; scripts/node-acceptance.
- **W4** — этап 2: управляющие bindings пути/параметров, node-api/node-procedure/workspace-ui.

Видимость для модели: `NODE_TYPES.semantics` объясняет бизнес-результат и побочные эффекты; `description` у каждого параметра, строковые enum, компактный readback. Наблюдённые значения отличать от запроса модели.

Тесты из `packages/loginom-runtime`: `bun run test:upstream`; при изменении приёмки — из того же каталога `node --test ../../scripts/node-acceptance/tests/*.test.mjs`. Команды новых адресных тестов закрепить после появления файлов; сейчас они не существуют.

## 3. Данные и независимые проверки

Комплект `nodes/exports-xml/acceptance/` (для следующих этапов `acceptance/stageN/`): `task.md` с `{{PACKAGE_PATH}}`, `data/` только для входов модели, `expected.json` из независимого `oracle.py` до обработчика. Внешние manifests, oracle и ожидания модели не передаются; секреты — только во внешнем окружении.

CSV-спецификации: UTF-8, разделитель `,`, decimal `.`, header, NULL-маркер `\N`; empty string отличается от NULL. `fixtures/manifest.json`: фактические байты/SHA256, типы/метки/порядок и происхождение каждого бинарного файла/внешнего объекта; размер фиксируется при генерации, а не угадывается.

| Набор | Содержание и назначение |
|---|---|
| `xml-source.csv` | Id,Text,Occurred,Amount: три строки; Text содержит одинарные/двойные кавычки, табуляцию, перенос и &; есть NULL и пустая строка. |
| `schema.xsd` | Независимая схема с повторяющейся записью, атрибутами, date/dateTime, optional/nillable и двумя различимыми ветвями. |
| `empty.csv / replace.csv` | Нулевой набор; новая таблица той же схемы и другими значениями. Валидность пустого документа задаёт XSD. |

Правило трёх исходных строк: Id=1..3, Amount=[10,NULL,25], Text=[строка с кавычками/табом/переносом/& ,NULL,пустая строка], Occurred=2024-02-29T12:30:00.000. Точный текст спецсимволов и XML-структуру с namespace/root записать в oracle до прогона; XSD требует обязательный Id и допускает NULL Amount.

Oracle не импортирует handler/runtime, считает по входам, сверяет все ячейки/объекты/байты, имена/метки/типы/порядок полей, NULL/empty/0. Отклоняет старое исполнение, чужой destination/узел и подмену данных; E2E preview/обратный импорт не является независимым эталоном.

Нынешний cold-check принимает только таблицы: `expected-outputs.mjs:2-23`, нет файлов, sink или переменных. `expected.json` этого узла — **предлагаемая** схема files[] с destination/format/size/digest/структурой, до W она не принимается обвязкой. Нельзя добавлять фиктивный табличный output или объявлять PASS лишь по входной таблице. W приёмки обязателен перед этапом 1; после cold-open сверять настройки/граф и уже произошедший эффект, не повторять внешнюю запись вслепую.

## 4. Проверки, приёмка и завершение

Непроведённая проверка — `not_checked`; ожидания/границы фиксируются до модельного прогона.

| Требование / проверка | Независимое условие успеха |
|---|---|
| `exports-xml:r01` | Проверить XML tree и значения всех трёх записей; incompatible mapping отказывает до записи. Одинаковые leaf-name в разных ветвях различимы. |
| `exports-xml:r02` | Проверять одновременно байты соответствующих escaping/BOM и семантический XML; экранирование не приводит к потере символов. |
| `exports-xml:r03` | При pinned server zone отдельно проверить Date и DateTime, суффиксы зон и сохранение момента без зависимости от timezone проверяющей машины. |
| `exports-xml:r04` | Схема независимо определяет допустимый пустой документ/nil; неверный mandatory field даёт отказ. После reopen подтверждён свежий XML нового execution. |
| Контракт и отказы | Неверные настройки/типы отклонены до эффекта; исходная ошибка мастера сохранена |
| Изменение существующего | Настройки/связи readback подтверждены; новый источник не даёт старый результат; незапрошенные свойства сохранены |
| Persistence | Сохранить после всех чтений; открыть новым профилем без восстановления настроек; внешние эффекты и происхождение проверить по согласованному W |
| Recovery | Потерянный ответ не повторяет неизвестный эффект; результат сверяется независимо перед продолжением |
| Регрессия | Адресные тесты нового узла и полный `client/test`; прежние контракты не ослаблены |

Задание модели: Подготовить XML по предоставленной схеме из приложенной таблицы, сохранить все специальные символы и пропуски, проверить файл и сохранить пакет в {{PACKAGE_PATH}}.

PASS исполнителя: CLI и применимый cold-check/согласованный независимый аудит результата, адресная матрица, `package_closed=true`, `logged_out=true`. Файловый/внешний/переменный результат нельзя объявить принятым неподходящим oracle. Публикация и Ловец принимают тот же чистый SHA по RUNBOOK; `integration` и `release` не меняются.

## 5. Ловушки — переподтвердить, не копировать

Ниже документальные ограничения и требования прежнего черновика; точные controls и runtime-семантика для стенда остаются гипотезами до этапа 0.

Таблица + обязательный набор XSD + необязательные управляющие переменные → XML-файл. Выбор root задаёт структуру документа.

Независимая таблица 3 строки и XSD с повторяющимися элементами, атрибутами, date/dateTime, optional/nillable. Значения содержат кавычки, табуляцию, перенос и &. Oracle — XML parser + XSD validator и явная ожидаемая структура, не импорт-обработчик.

До выполнения проверить bindings, XSD/destination и возможность overwrite. Partial XML не объявлять готовым файлом; новый запуск только после reconciliation предыдущей записи.
