## Предлагаемое разбиение на этапы

Разбиение — гипотеза до этапа 0. Каждый этап должен приниматься самостоятельно; общие изменения, нужные этапу, входят в его же карточку.

- `exports-warehouse:s1` — Процесс и измерение с независимым DW reader. Требования: `exports-warehouse:r01`. Среда: Изолированный DW fixture.
- `exports-warehouse:s2` — Удаление, агрегации и провайдеры. Требования: `exports-warehouse:r02`, `exports-warehouse:r03`, `exports-warehouse:r04`. После: `exports-warehouse:s1`.

## Заметки черновика

Обязательные подключение DW и исходная таблица → изменение процесса/измерения. Страница Help не заявляет порт управляющих переменных или выходной таблицы; не добавлять их по аналогии.

Матрица подключений: Deductor Warehouse на Firebird, MS SQL и Oracle. Для каждого закрепить версию DW, СУБД, драйвер и отдельные процесс/измерение; начальная ветка — Firebird, другие профили остаются NOT_RUN до своей приёмки.

Независимо готовое DW с измерением Product и процессом Sales. Исходное A=10,B=20; вход A=15,A=5,C=7 с известным порядком. Новый объект/снимок на каждый case; результат читает отдельный SQL/DW-клиент.

Транзакционность и upsert DW не предполагать: фиксировать before/after каждого процесса и измерения. Потерянный ответ/частичная запись запрещают слепой повтор.
