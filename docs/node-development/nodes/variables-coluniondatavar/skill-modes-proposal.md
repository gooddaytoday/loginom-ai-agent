# variables.column_union / append_variables — предложение LAB-1038

Этот файл — проект замены node reference после утверждения и реализации;
он не расширяет текущий runtime.

Для соединения наборов параметров используй `dock_node_apply`,
`target.type:"variables.column_union"`, `mode:"append_variables"`.
Передай `inputs:[]`, `mappings:[]` и явные `variable_inputs` из свежего графа:
`{source:NodeRef,output:наблюдённый_порт,input:0,kind:"variables"}`,
аналогично для входов 1 и, после расширения, 2. Только источники текущего
документа и сценария; индексы копируй из наблюдения. Дополнительный вход создаёт
сам native узел. Пустой `variable_inputs` существующего узла сохраняет связи.

`parameters:{}` сохраняет настройки существующего узла. Автоматическое
соответствие: `parameters:{column_union:{mapping:"automatic"}}`.
Сначала идут переменные входа 0, затем 1 и 2. Коллизии имён разрешает Loginom:
a0/a0/a1 → a0/a1/a2, title → title_1. Метки не нумеруются.
integer/real/string/boolean и typed NULL; NULL, пустая строка, false и 0 различны.

Предлагаемое ручное соответствие: `column_union.mapping:"manual"` и
`column_union.output_variables` — полный упорядоченный список
`{input,source,name,label,type}`. input — индекс источника, source — точное
имя переменной. Выводи только перечисленные переменные и сохраняй заданный
порядок. Пока предлагается только integer → string для простых целых;
точное преобразование и повторное открытие должны быть подтверждены приёмкой.
Другие преобразования, Variant/datetime и потеря точности не разрешаются
этим предложением. Не заменяй соединение Калькулятором или JavaScript.

`finish:"execute"`, `read:{ports:[],variable_ports:[0],sample_rows:0,
require_exact_numbers:true}` — полный типизированный набор, не таблица.
После изменения источника повторно выполни тот же узел с его свежим NodeRef,
`parameters:{}`; проверь сохранение ручного соответствия и остальных связей.
Done применяет настройки, Close отменяет черновик; Save отдельный.

Управляющий вход на исследованном узле не обнаружен. Не создавай его и
не подключай управляющий набор как добавляемые данные; сообщи ограничение.
Сохрани пакет через `package.save_checkpoint`; после reopen получи новую
подготовку и новые refs. Старые operation/workflow refs не переносить.
