# Соединение (переменные)

`variables.column_union`, режим `append_variables`: два набора переменных →
один набор переменных. Прочитай карточку типа. В `variable_inputs` W1 укажи
два разных выданных source ref, `kind:variables`, целевые входы 0 и 1;
`inputs:[]`. Номер выхода каждого источника бери из его inventory.
Для результата используй `read.ports:[]`, `read.variable_ports:[0]`.

Новый узел использует автоматическое соответствие: `parameters:{}` либо
`parameters:{column_union:{mapping:"automatic"}}`. Существующий пустой patch
сохраняет настройки и связи. Сначала проверь, что существующая настройка
соответствует поддержанному автоматическому режиму.

Сначала идут переменные входа 0, затем входа 1. Одинаковые имена сохраняют
оба значения; читай фактические имена, а не вычисляй их для следующего шага.
Например, a0/a0/a1 дают a0/a1/a2, два title — title/title_1. Метки могут
совпадать и не являются идентификаторами.

Поддержаны integer/real/string/boolean и типизированный NULL, суммарно не
больше 128 переменных. NULL, пустая строка, false и ноль различаются.
Дроби читай типизированно, без округления по экрану. Точность unsafe integer
не обещается. Execute пересчитывает текущие источники без обучения.
После изменения источника повтори Execute/read того же узла; сохраняй пакет
отдельно после итогового чтения.

Дополнительные входы, ручные переименования/исключения/перестановки,
константы выхода, изменения типов, datetime и Variant требуют другого
объёма. Не используй `Input_Add` или табличное Соединение для обхода.

оно пока не входит в установленный навык.
