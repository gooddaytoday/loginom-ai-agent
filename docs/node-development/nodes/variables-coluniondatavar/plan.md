## Предлагаемое разбиение на этапы

Разбиение — гипотеза до этапа 0. Каждый этап должен приниматься самостоятельно; общие изменения, нужные этапу, входят в его же карточку.

- `variables-coluniondatavar:s1` — Два набора и коллизии имён. Требования: `variables-coluniondatavar:r01`, `variables-coluniondatavar:r02`.
- `variables-coluniondatavar:s2` — Дополнительные порты и перенастройка. Требования: `variables-coluniondatavar:r03`, `variables-coluniondatavar:r04`. После: `variables-coluniondatavar:s1`.

## Заметки черновика

Два и более необязательных входных набора объединяются с сохранением значений. Одноимённые переменные переименовываются, а не перезаписывают друг друга. Дополнительные порты создаются явно.

Текущие `node-target-browser.mjs` и `node-contracts.mjs` работают с табличными портами; перед handler нужны типизированные ссылки/связи и независимое чтение переменных. Общий lifecycle `node-apply.mjs` сохранить. Динамический список входов взять за образец из `union-node.mjs`, заменив табличные refs/reader на типизированные переменные.

Подтвердить максимальное наблюдаемое число портов и отсутствие ложных обязательных источников; пустой набор и неподключённый порт проверять отдельно.
