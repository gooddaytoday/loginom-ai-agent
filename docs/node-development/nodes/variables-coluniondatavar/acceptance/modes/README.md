Manual с двумя входами принят в работу по LAB-1085; третий/control остаются предложением.
Вход — `../../fixtures/modes.json`. Модель получает только входы и
`../task-manual.md` либо `../task-inputs.md`; oracle/expected ей не передавать.
Для manual подготовить два самостоятельных источника в новом пакете своей
пары; JSON не является готовым .lgp или источником, который runner уже загрузил.

`python3 docs/node-development/nodes/variables-coluniondatavar/acceptance/modes/oracle.py`
проверяет expected.json; `--write` явно обновляет предложение.
Oracle использует только авторские JSON и Python, не результат Loginom.
Expected — семантическое предложение фаз, **не новая схема cold-check**.
До реализации перенести утверждённые фазы в существующий формат приёмки,
не добавляя нового verifier. Контроль отсутствующего control-порта не PASS
положительного режима. Непроверенные преобразования не включать как принятые.

Предлагаемые критерии: полный ordered variable output 0, точные имена/метки/
типы/значения без преобразования типа, тот же GUID при
изменениях, отдельный patch источника, текущий вывод вместо кеша, Save и
typed cold в новом профиле. Прочие существующие сценарии сохраняются.
Стандарт: worker ≥2/3 и независимые ≥2/3 на одном SHA, затем проверки путей.
Живые прогоны только существующим run-check start + wait; этап 0 их не заявляет.

Integer→string — ограничение Loginom 7.4.2, отдельный отрицательный сценарий
`variables-union-type-refusal` проверяет отказ до мутаций и сохранение источников.
`oracle.py --check` сверяет также оба stock expected-manual-*-run.json.
