# Offline fixed Import read collectors

This is an offline preparation module and its negative controls. It is NOT
installed into `captureImport`, the host/router, a shared gate or the packaged
runtime. The accepted runtime/product remains `9509310f5`. A future reviewed
integration can serialize the fixed reader through the existing private Page
seam using its existing identity fields; no model-selected module/code/callback,
new IPC/MCP/public route or clean authority is introduced here.

`readFixedImportCandidates(identity)` uses cached native/DOM/Ext paths, checks
existing document/account/tab/preparation/package/workflow ownership and reads
bounded candidate facts. Tests serialize the actual function in VM against
labelled native/DOM/Ext doubles. They do NOT claim captureImport/installed actual
or live PASS for this prototype. `collectRecordLabelPair(view,grid,row)` is a
separate candidate for layouts with a native row record, not a fabricated
association to Import's transposed grid.

All existing runtime results stay PARTIAL, complete=false, close_authority=false,
effect_possible=false. Candidate facts cannot satisfy the production pre-config
or read-only clean-close gate. Additional proof must establish current owner and
ordered lineage, not just matching hash/GUID/caption or cached success status.

The historical `cold-before-wizard-native.json` capture in the 2026-10-11 cold
materializer evidence is an output/materializer context. It records partial
port configuration, not current Import enum/output/activity/freshness. It cannot
establish compatibility of950's own-data descriptor guard with CURRENT real
native ports. Such compatibility remains unmeasured. No historical object refs,
private Maps, .writer/pending/unknown attempt are reused in production.

Negative controls cover foreign view/record/icon/kind, changed account/document/
package, duplicate or missing wizard opening, foreign engine/data/tree parent,
wrong output direction/index, foreign/multiple selected nodes, ambiguous toggle,
foreign/partial/loading/cyclic process store, duplicate process record and
completed cached status without freshness. These are useful offline controls,
not proof that today's server exposes these native paths.

No full product build is required for this docs/test preparation. The minimal
production integration remains a later step after collector review, current
native proof availability and LAB-68 exact Import routing/gate/opaque proof PASS.
No new live/native/server/model/prepare/upload/rebind/Done/Save/execute/replay.

Prototype claim revalidation retains native/DOM identities before final provider
reads and removes observed claims after the last outer owner read if relations
changed. This includes wizard data/tree/engine/opening and process ModelNode/
record/parent/children/diagram. Row record/view/index/cell/icon aliases are checked
after final getStore/getAt. A defined native FPortIndex must equal nativeIndex;
undefined remains permitted by node-context's existing contract.

The outer active-tab read and all late selection/state/Ext/store/root provider reads finish before the common owner check. Process observations resample the current views, their stores and the current root; retained root equality alone is insufficient. Only then are all retained claim bindings checked, without calling those providers again. Account/tree drift refuses all observations; a changed process view/store/root drops its process claim. These are bounded SOURCE prototype controls on doubles, with no production integration or native proof.
