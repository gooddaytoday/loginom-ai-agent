Предложение LAB-1038. `../../fixtures/modes.json` — входы, не готовый пакет.
Модель получает только их и `../task-types-dates.md`/`../task-scopes.md`.
Oracle/expected остаются вне модельного контекста.

`python3 docs/node-development/nodes/variables-user/acceptance/modes/oracle.py`
проверяет expected.json; `--write` формирует его из JSON через Python datetime.
Это семантическое предложение, не новая схема проверки. Числовые IDs не
задаются: сравнить сохранённые IDs с независимым baseline того же пакета.

Предлагаемый положительный срез: integer→real со значением 7.5 на том же ID,
неизменённые label/order/соседние переменные; date-only → civil midnight;
Close отменяет patch, Done/readback подтверждает значения, Save и новый
профиль/cold сохраняют типы и точность. Consumers после type patch не должны
использовать старую схему. Стандарт worker ≥2/3 + независимые ≥2/3 на одном SHA.

Создание отдельного builtin и запись в другие scopes заблокированы отсутствием
наблюдённого UI. Не считать refusal успешной реализацией этих режимов.
Ненулевые мс и timezone предлагается оставить ранними отказами без изменений
пакета, пока нет точного writer и согласованной timezone policy. Дата без
времени — явное предложение расширения, текущий guard её отклоняет.
Для стадии 1 сначала утвердить именно эти границы; общие контракты,
дедлайны/бюджеты и новый механизм верификации не менять по этому комплекту.
