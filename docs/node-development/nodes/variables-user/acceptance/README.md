Предложение критериев LAB-898; до изменения обработчика утверждает владелец.
Это комплект этапа 0, не запись о PASS модельного бизнес-прогона.

Модель получает только task-real-datetime.md и fixtures. Oracle и expected
остаются у проверки. CSV: UTF-8, `;`, заголовок имён, пустая Share = NULL;
OccurredAt импортировать как datetime с тремя цифрами миллисекунд,
Share как real, Id/Amount как integer. Значения непосредственно ниже и выше
0.15 различимы в binary64; не округлять и не применять epsilon.

Независимый oracle: `python3 acceptance/oracle.py` из каталога узла.
`--write` явно пересоздаёт expected.json. Он вычисляет обе фазы обычными
csv/datetime/float Python, не исполняет формулы Loginom. Ожидаются Id:
отчёт сначала 2/3/4/8/10, затем 5/6/9; выше порога сначала 1/4/5/6/7,
затем 1/6/7. Весь набор строк, схема, NULL, количество и сумма сверяются.
Сравнение по Id не навязывает пользователю незаданную сортировку.

Предложенная матрица:

| Случай | Критерий |
|---|---|
| Create / patch / repeat read | Восемь typed-переменных; patch только двух имён; IDs/labels/порядок и шесть остальных значений сохраняются; новый read_id |
| Бизнес | Два результата обеих фаз из expected; зависимости используют переменные, без вшитых значений и строковых конвертеров |
| Save + cold | Отдельный Save; новый профиль/сеанс, открыть тот же пакет, полная typed-сверка переменных и обоих пересчитанных результатов; Close/logout |
| No-op / Close | Повтор равного patch без изменения значений; Close отменяет draft; Save/read не подменяются Done |
| Смена типа | integer→real, real→datetime, datetime→string запрещены до первой мутации; смешанный patch тоже целиком отказывает |
| NULL / empty | null допустим у real/date; пустая строка допустима только у string; `real:""`, `datetime:""`, отсутствие value, NaN/Infinity, неверный тип отвергаются до UI |
| Дата | Валидное civil ISO с секундами, optional .000; nonzero .sss и timezone/date-only в API отвергаются до UI; пользовательская дата дня нормализуется моделью в начало дня |
| Precision | finite real сохраняется как тот же binary64; NULL не превращается в 0; дата читается до мс, включая заранее сохранённую .160; не выдавать native-byte proof из wizard |
| Регрессия | Старый integer/boolean/string сценарий проходит; dirty snapshot по-прежнему отказывает; нет новых связей/Execute у builtin |

Стандарт сквада: на одном SHA минимум 2/3 модельных PASS у исполнителя,
2/3 независимых PASS под отдельным аккаунтом, cold PASS, проверки затронутых
пакетов. Адресные отказы не заменяют бизнес-прогон. Перепроверка cold при другом
timezone полезна как адресный регрессионный случай, не новый общий merge gate.

Прямой variable-операнд Фильтра строк на базе поддерживает только integer/string.
Для real/date доступен существующий табличный Калькулятор с `Var.name` и
typed variable mapping, затем фильтр вычисленного признака. Не расширять
Фильтр строк в этой работе. Работоспособность связки с новыми типами ещё
проверяется в этапе 1, успех здесь не заявлен.
