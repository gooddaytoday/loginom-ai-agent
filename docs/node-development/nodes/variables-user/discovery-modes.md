## Смена типа

Выход 4 открыл `MF;TF-1;WizrdMCF;VariablesEditValuesWizard` (V),
`V;btnAddMappingColumn`/`btnEditMappingColumn` → `EditVariableForm` (E).
Integer: `E;pgcValue;Int64Field`, real: `E;pgcValue;num`,
datetime: `E;pgcValue;datetimefield`. Выбор типа — `E;cbxDataType;trg_picker`
и `E;cbxDataType;boundlist;Целый/Вещественный/Дата/Время`.

Создан amount integer=7 (ID=0), затем через существующую строку
`V;colName_amount` изменён тип на real и явно задано 7.5. Apply → Done →
повторное открытие выхода 4: ID=0, name/label=amount, DataType=3, value=7.5.
Соседние stamp (ID=1, datetime) и mixed (ID=2, Variant) сохранились.
Это readback ручного UI; Save/cold и consumers после смены типа не доказаны.
Текущий production `crosstable-variables.mjs` запрещает смену типа до записи;
это ожидаемый red будущего расширения, не исправленный дефект этапа 0.

## Дата и точность

В этом браузере timezone America/New_York. Только штатные fill→Tab:

| Ввод | Прочитанные civil компоненты | Ошибки control |
|---|---|---|
| 2026-01-02T03:04:05.123 | 2026-01-02 03:04:05.000 | нет |
| 2026-01-02 | 2026-01-02 00:00:00.000 | нет |
| 2026-01-02T03:04:05+03:00 | 2026-01-01 19:04:05.000 | нет |

Миллисекунды потеряны молча. Timezone превратился в локальное время браузера
(сдвиг даты), поэтому это не civil-preserving ввод. Точная запись .sss≠0
штатным жестом не доказана; отдельного поля timezone нет. После исследования
сохранено в wizard только civil значение с целыми секундами.
Предлагается date-only → полночь того же гражданского дня; .sss≠0 и timezone
остаются отказами до эффекта, пока не согласована и не доказана точная запись.
Никаких прямых Date setters для обхода потери не применять.

## Комплект и следующая правка

`fixtures/modes.json`, `acceptance/task-types-dates.md`, `task-scopes.md`,
`acceptance/modes/{oracle.py,expected.json}` — предложение, старые expected
сохраняются. Положительный срез: явная смена integer→real с сохранением ID,
метки/порядка/неупомянутого, date-only, Done/Close/Save и cold typed read.
Стандарт 2/3 + независимые 2/3 на одном SHA. Модель не получает oracle/expected.
Отсутствующие UI-действия — отдельные blocked/refusal cases, не положительные
ожидания. JSON этого предложения не является новой схемой cold-check.

Несмотря на название в назначении, файлов `variables-user-*.mjs` в базе нет:
`node-support.mjs` ведёт тип в **crosstable-variables.mjs**.
Затронутся его validator/preflight/editor/independent comparison,
`node-api.mjs` (описание date-only/явной смены типа), узловые тесты и reference.
Форма результата, native transport и package/dirty guards не требуют изменения
для наблюдённого integer→real. Потребители могут иметь устаревшую схему:
её обновление после type patch ещё проверять, без общего рефакторинга.
Создание builtin, другие scopes и точная запись .sss не оценены как решённые.
Узкий положительный срез — **2 цикла**, каждый с бизнес-прогоном.
Бюджеты — `mode-budgets.md`; до кода требуется решение по границам приёмки.
