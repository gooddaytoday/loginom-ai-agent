Amount-only staged entry component (not stock-selected)

The fixed amount-private-launcher-entry.ts exports only launchAmountDiagnostic,
implemented by launchStagedAmountDiagnostic, never an FP/Calculator alias.
The stock legacy Amount closure, selector, public host routes and builders remain
unchanged. The accompanying builder patch is a future receiving proposal only.

Stage A closed caller argument: {signal: actual original AbortSignal reference,
deadline: already-established absolute scalar, operation, request}. No run/lease
is accepted or described as pre-acquired here. These values and a newly minted
private startup authorization are retained before inventory awaits. The factory
holds its original input/control references, independent input snapshot and
environment snapshot; copied operation/request carriers are fenced before IO.
Real FS inventory reads use the fixed existing Node/host/Amount/collector paths.
Guards run before/after each awaited read/parse; owned failures and original
control refusal have separate boxed presence. New owned failures are secondary
only when a primary already exists; propagation never creates a new event.

Current shared provider is absent. After verified inventory the exact refusal is
ORIGINAL_BOUND_TUPLE_PROVIDER_UNAVAILABLE. There is no uncontrolled fallback,
fork, minted run/lease/generation/chat, child controller or native action. The
private retained(input, originalControl) diagnostic projection keeps the original
signal/deadline/authorization and first refusal available, reports pending until
the original IO finishes, and always reports unavailable stage B/native false,
evidenceSettled=false/cleanupSettled=false/acknowledged=false. It is NOT a receipt
verifier or release method. No consumer-supplied booleans can settle the root.
