## Основной бизнес-сценарий и редактирование

`task.md` теперь описывает импорт → сводку по Group → одну перенастройку того же узла → сохранение. На перенастройке ключи становятся Segment, Group; показатели — Other(sum), Amount(avg), Text(count). Исчезают прежние Amount(sum/count/min/max), добавляется Other(sum), меняется порядок, выходной Segment исключается. После сохранения cold-check должен заново выполнить узел и сравнить конечный результат без восстановления настроек из ожиданий.

`initial.json` хранит промежуточный выход первой сводки, `expected.json` — только конечный выход целевого узла; `reconfiguration.json` совпадает с ним. Две строки Group=A после исключения Segment остаются отдельными группами: скрытый ключ не отменяет группировку по нему.

Входные CSV сохранены побайтно. `fixtures/manifest.json` фиксирует размер, SHA-256, число записей, формат импорта и упорядоченные типы/виды полей. `fixtures/matrix.json` связывает входы, задания и ожидания; все ещё не выполненные пункты имеют `not_checked`. Значения all-null и пустого входа — независимые ожидания до запуска; их подготовка не означает native PASS.

`python3 oracle.py` пересчитывает все JSON из CSV через независимый `legacy_goal_contract.py`, без handler/runtime и результатов Loginom. Count считает строки, включая NULL/empty. Для all-null sum/avg/min/max ожидается NULL; header-only сохраняет полную схему и не создаёт группу. Позиционно сравниваются все имена/метки/типы, строки сравниваются как мультимножество. Совпадение чисел само по себе не подтверждает свежее выполнение и полное чтение.

Модели передаются только выбранный `task.md` с новым `{{PACKAGE_PATH}}` и его CSV. Oracle, expected и matrix остаются у проверяющего. Каждое задание содержит не более 15 строк и одно итоговое сохранение.
