Предложение LAB-998, этап 0; утверждение владельца до изменения runtime.
`expected.json` — контейнер предложений, **не вход stock run-check**.
Один task соответствует одному будущему циклу, всего десять. Для concat три
последовательных состояния одного узла входят в один цикл. Для cache и
sort_result нужны оба выполнения одного узла; финальное состояние — cold.

Только выбранный `task-*.md` и `../../fixtures/modes.csv` передаются модели.
Пути, метки, oracle, expected, manifests и доказательства остаются в проверке.
`{{PACKAGE_PATH}}` подставляется штатным runner. До этапа 1 новые имена
сценариев в run-check не зарегистрированы; текущая карточка их не запускает.

Из корня checkout:

```sh
python3 docs/node-development/nodes/grouping/acceptance/modes/oracle.py
python3 docs/node-development/nodes/grouping/acceptance/modes/oracle.py --check
```

Oracle читает только CSV, применяет определённые в предложении функции и
строит все поля/строки независимо от Loginom. `--check` сравнивает вычисление
с committed expected; сам expected не используется как источник чисел.
StdDev — выборочный, n=1 даёт 0, n=0 — NULL; binary64 порядок вычисления —
сырой второй момент и поправка n/(n−1), без нового допуска/матчера.
Median игнорирует NULL; Mode исключает NULL и на all-NULL Integer/String
возвращает типовое 0/пустую строку. Fixture не содержит ничьей мод.
First/Last включают крайний NULL. Only требует единственного **различного**
значения среди всех строк, повторы допустимы. Списки исключают NULL,
сохраняют пустой текст и возвращают пустую строку на all-NULL.

Положительная приёмка использует существующий стандарт: полный основной
typed-результат, все CSV, точные типы/имена/порядок полей, кратности и NULL,
сохранённая конфигурация, Save, новый профиль, cold Execute без настройки,
полный результат и cleanup. Незаданные метки — `label_any`.
Для sort_result порядок строк обязателен; для остальных групп сравнивается
мультимножество. Порядок **внутри списка** проверяется строковым значением.
Cache не меняет агрегаты; его сохранённое значение проверяется штатным
конфигурационным readback, а не замером скорости.
Существующие stock readers/matchers сохраняются. На этапе 1 потребуется
аддитивно связать cases со штатными сценариями и читать concat-настройки;
новый механизм верификации здесь не предлагается.

После реализации: red→green на production-пути, обязательные проверки
по required-checks, ≥2/3 PASS исполнителя и независимые 2/3 на одном SHA.
В этом docs-PR нет утверждения runtime PASS, Save/cold или независимой приёмки.
Начальный объём новых агрегатов — Integer и применимые String; Real/date/
Boolean/Variant, ничья мод и пустой вход отдельным PASS не заявлены.
