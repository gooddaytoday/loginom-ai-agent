# Amount original preparation and completion

The bridge retains the original workspace preparation reference and bytes before
its verified save action. Amount capture refuses a copied/drifted preparation,
missing full workflow or a save outcome whose nested phase is not `verified`.
The private lifecycle handle binds the original retained owner/session/runtime,
save operation and actual child signal/deadline; it never enters IPC.

Consumer result, capture file bytes, completed journal, confirmed package cleanup
file and bridge transport-close result must agree before the bridge brands the
result. Managed capture uses the original startup controller and verifies that
brand immediately before sending its result. Receipt flags supplied by IPC cannot
create it. A refusal does not replay capture/native work or relax writer custody.

`test/diagnostics/amount-lifecycle` checks actual lifecycle/retainer modules and the
literal managed branch with real AbortController and file IO. Page/native,
preparation/save and consumer/cleanup outcomes remain explicitly labelled doubles.
This is component qualification, not native acceptance or a selected embedded
host/factory proof. The existing HostPort Amount `amountHeld` capture refusal
remains: the next own step must bind that original request/control path rather
than declaring the component to be full dispatch/cleanup/ACK completion.
