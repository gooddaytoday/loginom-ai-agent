## Предлагаемое разбиение на этапы

Разбиение — гипотеза до этапа 0. Каждый этап должен приниматься самостоятельно; общие изменения, нужные этапу, входят в его же карточку.

- `datamining-arimax:s1` — Ручная несезонная модель и три выхода. Требования: `datamining-arimax:r01`, `datamining-arimax:r02`.
- `datamining-arimax:s2` — Автоподбор/сезонность/диагностика. Требования: `datamining-arimax:r03`, `datamining-arimax:r04`. После: `datamining-arimax:s1`.
- `datamining-arimax:s3` — Внешние факторы и нормализация. Требования: `datamining-arimax:r05`, `datamining-arimax:r06`, `datamining-arimax:r07`. После: `datamining-arimax:s2`.

## Заметки черновика

Один табличный упорядоченный вход: ровно одна вещественная непрерывная прогнозируемая переменная, внешние факторы имеют определённый data_kind, NULL запрещены. Выходы: прогноз/опциональные остатки/интервалы, coefficients (тип, параметр, лаг, поле, категория, beta/SD/t/p) и сводка переменных. Горизонт добавляет строки. ARIMAX с внешними факторами действует лишь на один шаг; для горизонта >=2 Help описывает ARIMA без факторов, это должно быть явно видно модели-пользователю.

Горизонт прогноза изменяет число строк. Дополнительные столбцы задаются явными параметрами мастера: после configure/train закрепить фактическую схему каждого выхода и применять строгий readback к сохранённой модели. Новая конфигурация или retrain устанавливает новую проверяемую схему; изменение строк при apply сохраняет её контракт.

Использовать 64 заранее вычисленные точки y[t]=0.5*y[t-1]+e[t] с фиксированным числовым массивом e и отдельным сезонным рядом периода4. Independent reference fit с закреплённой likelihood/initialization проверяет фиксированную ARIMA структуру; до прогона сопоставить соглашения об intercept, residual и differencing. Для аналитически вычисляемых прогнозов сохранённых coefficients atol=1e-6; оценённые коэффициенты разных решателей сравнивать только при совпавшей целевой функции и заранее принятом rtol=1e-4. Для внешнего x добавить y=3*x+noise. Проверить p/d/q=0 отдельно: Help пишет >0, обычные ARIMA соглашения этого не доказывают, потому baseline выбирается после discovery границ.

Узловые отказы: Неупорядоченный/слишком короткий ряд, больше одной цели, NULL, неподходящий период/порядок, несходимость. Не уменьшать горизонт и не отключать сезонность молча ради PASS.
