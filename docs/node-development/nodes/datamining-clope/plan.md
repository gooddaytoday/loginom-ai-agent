## 0. Как выполняется назначение

Оркестрация — Multica, сквад «Обработчики узлов»: Генератор тасок готовит назначение, Тест-Манки #1 разрабатывает, Ловец Галюцинаций независимо принимает опубликованный SHA.

```text
Ветка: <ветка задания>
Узел: datamining-clope
Обработать узел по его подплану до независимой приёмки. Объём — этап <N> подплана.
```

Первая карточка — этап 0 отдельно; этап 1 после решения владельца по W1/W2/W3. В ветке задания обязательны RUNBOOK, подплан и инструменты CLI-приёмки (`scripts/node-acceptance/cold-check.mjs`, сборка `--no-archive`).

### Стоп-условия

Каждое оформляется как Blocked с конкретным вопросом Генератору:

- в ветке задания нет обязательных документов или инструментов;
- аккаунты или CLI не `ready` на назначенном стенде;
- неизвестный исход операции: сохранить попытку, writer marker не удалять;
- в палитре нет «Кластеризация транзакций» либо native component/fulltype не совпал;
- нет решения владельца по W1/W2/W3, если изменение нужно назначенному этапу;
- недоступны полные результаты/свежесть/независимый oracle; это не PASS.

## 1. Цель и проверенная основа

Согласованный планируемый срез из реестра: Подготовленные транзакции и одна наблюдённая настройка кластеризации; состав кластеров и результат применения.
Этап 1 — «CLOPE и независимые N/W/S»; остальные режимы разнесены по отдельным карточкам ниже. Разбиение и элементы мастера уточняются этапом 0, без изменения критериев владельца.

CLOPE принимает основную/дополнительную таблицы транзакций с дискретными полями Транзакция и Элемент. Число кластеров выбирается алгоритмом; коэффициент отталкивания и limits его ограничивают. Требуется обучение.

## 2. Этапы

### Этап 0 — подготовка, живое исследование, контракт

Подготовка: проверить checkout/SHA, собрать кандидата из закоммиченных исходников, получить `loginom status = ready`. UI только штатными средствами runtime с `?testable=true`; каждый отказ мастера прочитать из его кнопки ошибки.

1. Палитра «Кластеризация транзакций», точный заголовок и корень мастера, native component/fulltype, входы/выходы и их виды, все страницы.
2. Коэффициент отталкивания 1..4, limits итераций и кластеров; смысл N/W/S при дублях и дополнительном входе; устойчивость разбиения к порядку.
3. Умолчания и границы каждого элемента мастера этапов 1+; зависимые/disabled настройки, NULL/пустая строка, пустой вход, неподдержанный тип.
4. Имена, метки, типы и порядок всех выходных полей; момент появления схемы до/после Execute или обучения; все порты одного исполнения.
5. Явное обучение/переобучение, применение на независимом holdout без скрытого retrain, сохранение модели; смена источника/параметров инвалидирует модель по наблюдённому правилу.
6. Тот же узел после замены файла существующего импорта: свежие значения и схема, необходимые явные retrain; не пересоздавать узел для обхода.
7. Фиксированный seed (если элемент seed доступен) и два повторных расчёта/обучения на одинаковом входе; при недетерминированности заранее закрепить проверяемые инварианты и допуски. Для random/uniform воспроизводимость состава проверяется в рамках гарантий Help, без копирования чужого PRNG.
8. Ожидаемые отказы из раздела 5; неизвестный эффект сохранить, не повторять автоматически.

Результат — `discovery.md`: конкретные значения с пометками «наблюдено / гипотеза», решения по W1/W2/W3, схема портов/соответствия полей и численный oracle. `ready_for_development` только после закрытия вопросов назначаемого среза и согласования общих изменений; `fixtures/` и `acceptance/` готовятся до кода.

### Этап 1 — CLOPE и независимые N/W/S

Покрытие требований этого этапа:

- `datamining-clope:r01` — Роли дискретных полей, коэффициент отталкивания 1..4, обучение Источник: `datamining-clope:help01`.
- `datamining-clope:r02` — Два выхода, N/W/S и сохранность транзакционных IDs Источник: `datamining-clope:help01`.

Scope: основной транзакционный вход, дискретные роли, коэффициент отталкивания; принадлежность транзакций и параметры кластеров N/W/S. Создание, изменение существующего узла, readback всех назначенных настроек и чтение всех выходов в объёме этапа. Режимы следующих этапов отклоняются до мутации с объяснением исправления.
Файлы: новые `packages/loginom-runtime/client/lib/clope-{node,parameters,procedure,context,readback}.mjs`, `client/test/clope-*.test.mjs`; регистрация в `node-contracts.mjs` и `.d.ts`, `node-support.mjs`, `node-api.mjs`, `node-procedure.mjs`, `node-result-schema.mjs`, `user-results.mjs`; общая оболочка `calculator-node.mjs:38`. Образец — Фильтр строк (`filter-*.mjs`) для чтения табличных портов; обучаемого образца в базе нет.
Видимость для модели: `semantics` — «Кластеризация транзакций; требуется явное обучение/переобучение»; `description` у каждого поля `parameter_schema`, строковые enum и компактный readback с идентичностью источника и результата.
Общие изменения: W1/W2/W3 только после решения владельца, отдельными коммитами с тестами.
Тесты из каталога `packages/loginom-runtime`: `bun run test:upstream`; при изменении приёмки из каталога `scripts/node-acceptance`: `node --test tests/*.test.mjs`.

## 3. Данные и независимые проверки

Комплект `nodes/datamining-clope/acceptance/` (следующие этапы — `acceptance/stageN/`): `task.md` с `{{PACKAGE_PATH}}`, `data/` только с входами модели, `expected.json` из независимого `oracle.py` до обработчика; oracle и ожидания вне workspace модели.
Формат: UTF-8, заголовок в первой строке, разделитель `,`, десятичный `.`, NULL `?`; пустая строка отличается от NULL. `fixtures/manifest.json` фиксирует типы, порядок, байты, SHA256, формат и версии вычислительных зависимостей.

Данные: transactions.csv: Transaction, Item (string); T1/T2={A,B}, T3/T4={X,Y}, T5={A,B,C}, 11 строк. holdout.csv: T6={A,B}; auxiliary.csv содержит Transaction, Item для независимых дополнительных элементов.

| Набор | Содержание и назначение |
|---|---|
| основной CSV из описания | самостоятельные данные для среза этапа 1; не требует соседнего нового обработчика |
| `empty.csv`, `null.csv`, `invalid.csv` | заголовок без строк; NULL/пустая строка; границы/несовместимые типы и параметры |
| `replace.csv` / `update.csv` | те же имена/типы, заведомо другие значения; переисполнение того же узла |
| `holdout.csv` | для обучаемых: новые RowID вне обучения, применение сохранённой модели без скрытого fit |

Каждое требование сопоставлено независимой проверке; адресные данные создаются по основному правилу с минимальным изменением для указанной границы. Expected и допуски фиксируются до проверяемой попытки.

| Требование | Адресный набор | Независимая проверка и ожидаемый результат | Доказательство |
|---|---|---|---|
| `datamining-clope:r01` | `stage1-r01.csv` / manifest + oracle | Базовые транзакции с двумя непересекающимися наборами, проверка состава и принадлежности каждой транзакции ровно одному кластеру. | Полный readback, expected и квитанция исполнения; до прогона |
| `datamining-clope:r02` | `stage1-r02.csv` / manifest + oracle | Из фактического разбиения независимо пересчитать N/W/S и целевую функцию CLOPE; номера кластеров не фиксировать как смысл. | Полный readback, expected и квитанция исполнения; до прогона |
| `datamining-clope:r03` | `stage2-r03.csv` / manifest + oracle | На том же fixture проверить cap и фактическое окончание обучения; stop по cap итераций не доказывает глобальный optimum. | Полный readback, expected и квитанция исполнения; до прогона |
| `datamining-clope:r04` | `stage2-r04.csv` / manifest + oracle | Матрица подключений и трактовка дубликатов установлена до expected; непрерывные поля отклоняются. | Полный readback, expected и квитанция исполнения; до прогона |
| `datamining-clope:r05` | `stage2-r05.csv` / manifest + oracle | На фиксированном обучающем входе сохранить модель; отдельно применить к holdout. Подмена параметров, модели или источника должна нарушить проверку происхождения. Применение не должно скрыто переобучать модель. | Полный readback, expected и квитанция исполнения; до прогона |

Независимый oracle не импортирует runtime/handler и не использует фактический результат текущего прогона как expected. Проверяет все ячейки, схему, типы, порядок полей и происхождение; IDs/строки/Boolean/NULL точны. Отрицательные подмены одного значения, типа, связи, источника и модели обязаны нарушить проверку.

T1={A,B}, T2={A,B}, T3={X,Y}, T4={X,Y}, T5={A,B,C}. Независимый расчёт для каждого найденного кластера проверяет N, W, S; для небольшого случая перебрать возможные разбиения и записать стоимость, но не требовать от эвристики глобального максимума без спецификации. Для принятия алгоритмического режима использовать заранее закреплённый reference результат на однозначном fixture, сравнивая множества кластеров с точными IDs без нумерации. При r=1/2.6/4 подтвердить чтение настроек и проверяемые структурные ограничения, не обещать строго монотонное число кластеров.

Cold-check базы: до 100 строк/выход и 32 ожидаемых выхода (`expected-outputs.mjs:8,14`), поля позиционно, строки без учёта порядка (`:29-39`); порядок проверяет отдельный ordered oracle. Числа сравниваются точно (`cold-check.mjs:232`, `expected-outputs.mjs:70`): W2 нужен для заранее объявленных допусков, где результат не представим точно.
`matchExpectedOutputs` (`expected-outputs.mjs:72-81`) сопоставляет type/label и уникальный node_id без индекса порта: outputs[] не принимает несколько портов одного узла. Полная приёмка нескольких табличных портов требует W3; для переменных — W4. До их реализации не объявлять такие результаты PASS.

## 4. Проверки, приёмка и завершение

Адресная матрица; непроведённые проверки — `not_checked`:

| Проверка | Условие успеха |
|---|---|
| Контракт/режимы | Все требования назначенного этапа проверены, неподдержанные настройки отклонены до мутации с причиной |
| Полные выходы | Каждая ячейка и все порты из одного свежего исполнения, схема/метки/типы и требуемый порядок совпали |
| NULL/границы | Пустой/ошибочный вход даёт заранее наблюдённый результат/отказ, NULL не заменён нулём |
| Изменение существующего | Readback сохранил незапрошенные настройки, режимы и связи; без подмены другим узлом |
| Lifecycle/источник | Явное обучение/переобучение, применение на независимом holdout без скрытого retrain, сохранение модели; смена источника/параметров инвалидирует модель по наблюдённому правилу. После смены данных проверены новый source identity и полный результат |
| Недетерминированность | Seed/повторяемость и объявленные допуски проверены без подгонки после FAIL |
| Persistence | Сохранение после всех чтений; cold reopen и выполнение, модель/настройки не восстанавливаются вручную |
| Recovery | Неизвестный эффект не повторён, причина отказа прочитана, собственный пакет/аккаунт закрыт |
| Регрессия | Адресные тесты и весь `client/test`; тесты изменённых общих контрактов и приёмки |

Задание модели: Сгруппируйте покупки по похожему составу методом кластеризации транзакций, покажите назначение каждой покупки и состав групп. Примените сохранённую модель к новым покупкам, затем обновите данные, явно переобучите тот же узел и сохраните пакет в {{PACKAGE_PATH}}.

PASS исполнителя: CLI, независимый cold-check после нового открытия, адресная матрица и oracle; `package_closed=true`, `logged_out=true`. Публикация чистого SHA и независимая приёмка той же головы — по RUNBOOK. Discovery/исторический PASS/skip не заменяют реализацию; `integration`/`release` не повышаются.

## 5. Ловушки — переподтвердить, не копировать

- Неподходящие типы и отсутствие ролей, r вне диапазона, разрыв обучения/сохранения; output старого обучения не подходит новому входу.
- Для обучаемых узлов обучение/применение/выполнение и идентичности источника/модели разделены; старые данные или модель не принимаются как свежие.
- Схема CrossTable sliding разрешена только его режиму: право менять схему автоматически другим узлам не переносится.
- E2E-снимки preview и `:toreview` не являются численным oracle; LGD-тесты адаптируются на самостоятельный CSV.
- Указанные элементы мастера и предлагаемая схема параметров не наблюдались на стенде; значения и ошибки закрепить до кода.
