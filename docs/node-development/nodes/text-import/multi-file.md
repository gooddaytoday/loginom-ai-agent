| Отсутствует последний Note | Запись присутствует, Note показан пустой ячейкой; NULL/empty по этому отображению не установлено | `21-heterogeneous-output`, `…;Note_3` |

| Month → Period без перестановки | Значение попало в прежний Month по позиции; нового поля Period нет | `21-heterogeneous-output`, `…;Month_5` |

Время: нативный заголовок `…;DataSetForm;normalHeaderCt;FileTime` имеет класс
`bg-TBGDataType-dtDateTime-before`; FileName — текстовое служебное поле.
Экранное время имеет минутное представление. Серверная точность, timezone,
миллисекунды, одинаковые имена в разных подкаталогах, коллизия с CSV-столбцом
FileName/FileTime, максимальная длина списка и нагрузочное масштабирование —
NOT_CHECKED. Нет оснований обещать равенство FileTime локальному mtime вложения.

При исследовании формат и типы были нативно автоопределены: Month стал датой,
Amount в части вариантов — строкой. Поэтому эти снимки доказывают расположение
данных и семантику режима, но не PASS типизированного бизнес-задания ниже.
Пустые отображённые значения не названы точными NULL. При программном вводе
списка нужен readback всего input: простое fill в опыте сохранило прежний префикс;
после Ctrl+A/Backspace и ввода получено точное значение. Ошибочную склейку не
использовали как доказательство отказа маски.

## Save и cold

Сохранённый явный список был закрыт, выполнен выход, создан новый browser context,
снова открыт пакет и выполнен узел **до открытия мастера**, без передачи настроек.
`23-cold-list-output` вернул те же пять строк, абсолютные пути и FileTime.
Затем `24-cold-list-settings` прочитал оба пути в прежнем порядке, threads=2 и
«Абсолютный путь, Время модификации»; поле потоков было активным.

После этого сохранена маска, parallel=false и «Имя файла». В каталог отдельно
доставлен `variants/sales_2026-03.csv`, пакет закрыт, выполнен выход, создан ещё
один чистый context. Execute без открытия мастера дал **шесть строк**, включая
SaleID=9 из марта (`26-cold-mask-new-month`). Значит, сохраняется сама маска,
а список её совпадений перечитывается при новом выполнении. Март оказался
первым: нативное перечисление не гарантирует лексикографическую сортировку.
`27-cold-mask-settings` подтвердил текст маски, «Имя файла» и снятую параллельность.

Это UI-проверка сохранения настроек и повторного чтения данных. Экспорт CSV,
stock cold-check, точное typed readback всех полей, сохранение переменного
числа файлов в модели и независимая приёмка SHA — NOT_RUN. Формат/полная схема
после cold отдельно не инвентаризированы. Закрытие и logout — снимки
`22-main-closed`, `29-final-closed`; финальный браузер закрыт.

## Предложенные критерии

Основное задание — [загрузить sales_*.csv одной таблицей и добавить источник](acceptance/task-multi-file.md).
Дополнительное — [явный список](acceptance/task-multi-file-list.md).
[Комплект](acceptance/multi-file/README.md) содержит независимые ожидания до прогонов.

1. Один imports.text / delimited, output 0. В первичном опыте одинаковая схема
   двух CSV, все пять строк, все значения/типы/NULL/пустой текст/дубликаты,
   заданный порядок пяти полей, FileName с исходным basename каждой записи.
   returns исключён. CSV, Save, неизменный cold, штатный cleanup обязательны.
2. Список сохраняет порядок путей; пустые позиции пропускаются, полностью
   пустой список отклоняется до мутации. Маска — только `*` в basename одного
   назначенного каталога, без рекурсии, URL, `?`, переменных и смешанного списка
   масок. Нет совпадений — понятный отказ без выдуманного пустого PASS.
3. Отдельный опыт после Save: добавить март и без перенастройки проверить шесть
   строк по `expected-new-month.json`. Полный N нельзя доказывать числом строк
   одного файла. Список от появления нового файла не расширяется.
4. Начальная приёмка охватывает одинаковые схемы. Перестановка/нехватка/добавление/
   переименование столбцов — диагностическая матрица; нельзя выдавать нативное
   позиционное чтение за объединение по именам без потери данных. Предлагается
   явный отказ на несовместимую схему до применения, с сохранением узла. Это
   предложенная граница, а не уже принятый критерий или исправленный дефект.
5. Параллельность затем проверять на том же наборе: false, true/2, patch с
   сохранением незапрошенных параметров, CSV/Save/cold. Сравнивать мультимножество,
   не обещать порядок потоков. Путь/время — отдельный последующий цикл;
   FileTime требует решения об эталоне точности, этот expected его не утверждает.

Стандарт 2/3 + независимые 2/3 на одном SHA и проверки изменённых пакетов
сохраняются. Нового oracle-протокола/механизма верификации не предлагается;
используются обычные table expected и CSV. Решение владельца требуется до
правки обработчика, а не для публикации этого docs-предложения.

## Аддитивный эскиз и оценка циклов

[`multi-file-card.proposal.json`](multi-file-card.proposal.json) — полная карточка
типа для оценки объёма; `cache_key` и hash-поля — 64 нуля. Она ничего не включает
в runtime. `mode` остаётся delimited, старые source/settings запросы сохраняются.
Предлагаются `sources` — конкретные issued ссылки каждого файла; в settings.source
`source_paths` **или** `source_mask`, а также `parallel_processing`, `max_threads`,
`file_info`. Одна single-file квитанция не разрешает произвольную маску каталога.
Новые ветки взаимоисключающие; валидатор обязан это проверять, как и равенство
набора совпадений текущему наблюдению назначенного каталога. Бюджетный эскиз:
≤16 файлов и ≤2048 символов всего нативного source input; UI-границы ещё не приняты.

| Цикл / самостоятельный PR после решения | Оценка | Что доказывает следующий бизнес-прогон |
|---|---:|---|
| 1. Явный список, одинаковая схема, FileName, последовательно | 300–450 строк, 1–2 цикла red→green | Две подтверждённые доставки, список, полный выход с метаданными, patch, CSV/Save/cold |
| 2. Маска одного каталога | 200–350 строк, 1–2 цикла | Реальный `sales_*`, несовпадение, новый файл после Save; свежий набор источников |
| 3. Parallel/threads и настройки без сброса | 120–220 строк, 1 цикл | Та же таблица как мультимножество, чтение сохранённых параметров |
| 4. Относительный/абсолютный путь и FileTime | 120–220 строк, 1 цикл после решения о времени | Служебные типы и пути, точность времени по согласованному стандарту |

Диапазоны включают адресные тесты, не CLI-сборку/ожидание живых прогонов.
Это оценка, не обещание четырёх правок в одной карточке. Между циклами обязателен
новый бизнес-прогон. Совместимость разных CSV-схем не спрятана в эти числа:
её полная поддержка требует отдельного решения.

Изменяемые адресно файлы в `packages/loginom-runtime/client/lib/`:

- `text-import-procedure.mjs`: сегодня требует один путь и запрещает `*`;
  сериализация списка, поля обработки, полное чтение и сохранение patches.
- `text-import-node.mjs`: `verifyTextImportSource` связывает одну квитанцию с
  одним destination; `bindIdentityOutputColumns` ожидает только CSV поля.
  Нужны несколько источников, служебные поля и корректный суммарный N.
- `text-import-readback.mjs`: сейчас число output полей равно числу used CSV
  полей; FileName/FileTime должны стать явной наблюдённой частью readback.
- `node-import-continuation.mjs`: проверить сохранение новых source options при
  продолжении существующей операции; не реконструировать их из запроса.
- `workspace-ui.mjs`: адресно расширить только selectors/import_source первой
  страницы и owner-bound checkbox/combo bindings. Общую оболочку не перестраивать.
- `node-api.mjs`, `storage-policy.mjs`:
  только дополнительные ветки для imports.text и ссылки на несколько уже
  подтверждённых источников. Старый importSourceSchema остальных узлов не ослаблять.
- `user-workflow.mjs`: адресный разбор новых параметров и defaults без подстановки
  первого файла за весь список; `node-contracts.mjs`: только описание семантики.

Общие изменения **в текущем PR не нужны**. Для этапа 1 обязательны аддитивные
расширения schema/readback и адресной проекции UI; не только изменение skill.
Новый инструмент, другой deadline/общий бюджет, модуль packages/agent или
новый механизм выдачи directory authority не входят в предложение. Если
существующие native Files refs не обеспечат полный текущий набор маски,
остановиться с вопросом; не расширять права одного server_source_ref.
Тесты — адресные `text-import-*`, полный client с pinned Chromium; для будущей
регистрации сценариев ещё весь acceptance-tests и требования required-checks.
