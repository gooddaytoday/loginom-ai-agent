# Исходные файлы для предложения multi-file

UTF-8 без BOM, LF, `;`, десятичная точка, `"`, заголовок в каждом файле,
`\N` — NULL только в Amount. Исходный порядок полей:
`SaleID` integer, `Month` string, `Amount` real, `Note` string.
Текстовый месяц нужно настроить явно: нативное автоопределение считает его датой.

| Файл | Записи | Назначение |
|---|---:|---|
| `sales_2026-01.csv` | 3 | Кириллица, ноль, NULL, пустой текст |
| `sales_2026-02.csv` | 2 | Отрицательное real, разделитель внутри кавычек, повтор записи из января |
| `returns_2026-01.csv` | 1 | Отрицательный контроль маски: не включать |
| `variants/sales_2026-03.csv` | 1 | Добавляется отдельно после Save, перед повторным cold Execute |
| `variants/reordered.csv` | 1 | Те же заголовки в другом порядке |
| `variants/missing.csv` | 1 | Нет последнего Note |
| `variants/extra.csv` | 1 | Добавлен Extra |
| `variants/renamed.csv` | 1 | Month переименован в Period, позиция сохранена |

В первичный каталог испытания доставляются только три файла из корня.
`variants/` туда целиком не копировать. Для проверки нового месяца отдельно
доставить мартовский файл под исходным именем в тот же каталог. Диагностические
варианты загружаются отдельно и выбираются явным списком, не маской `sales_*`.

Пять строк до добавления марта и шесть после него рассчитывает
[`oracle-multi-file.py`](../../acceptance/oracle-multi-file.py). Oracle читает
исходные файлы, а не DOM, результаты Loginom или код обработчика.
Готовые ожидания и порядок допуска к прогонам —
[`acceptance/multi-file/README.md`](../../acceptance/multi-file/README.md).
