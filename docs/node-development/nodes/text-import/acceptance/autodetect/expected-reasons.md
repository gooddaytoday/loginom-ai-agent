Ожидания фиксируются до прогона и не передаются модели.

| Поля | Тип | Обоснование |
|---|---|---|
| RuId, IsoId, SlashId | string | Коды 0012, 0007, 0100, 0000: ведущие нули значимы. |
| RuDate, RuStamp | datetime | dd.MM.yyyy и dd.MM.yyyy HH:mm:ss; день 23 исключает MM/dd. |
| IsoDate, IsoStamp | datetime | yyyy-MM-dd и yyyy-MM-ddTHH:mm:ss; секунды значимы. |
| SlashDate, SlashStamp | datetime | dd/MM/yyyy; 23/04 определяет порядок для 03/04. |
| RuAmount, IsoAmount, SlashAmount | real | Дробные и отрицательные суммы; ru: запятая и пробел тысяч. |
| RuActive, IsoActive, SlashActive | boolean | true/false и пустое значение различаются. |
| RuText, IsoText, SlashText | string | Текст; ru.csv содержит кириллицу в CP1251. |

Пустые ячейки — NULL, включая даты и логическое значение. В каждом файле четыре
строки. `oracle.py` независимо разбирает байты CSV стандартной библиотекой Python,
выбирает фиксированный формат даты по договорённости фикстуры и сохраняет точные
коды; сравниваются все поля и все значения. `expected.json` — зафиксированный
результат oracle, а не результат Loginom.

ISO/Slash проверяются на именованных исходных Import. Для ru проверяется
штатный `export_input`: Loginom теряет сумму с пробелом тысяч при ручном real,
поэтому итог может потребовать стандартного Калькулятора после строкового
импорта. Числовое ожидание 1234.5 и остальные типы/значения не меняются;
проверяются все шесть полей конечного результата, а не только CSV. Cold повторяет
сохранённый граф без настройки и проверяет те же значения и нативные типы.
