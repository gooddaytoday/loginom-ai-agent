## TXT delivery supplement (LAB-14)

This narrowly assigned supplement uses the original Multica attachment, stored outside Git. `txt-oracle.py prepare` independently parses its pinned bytes before the model run and writes private full expectations. Neither the oracle nor its expectations are attached to the model. `task.md` is the CLI task; only it and the original TXT are admitted through `--file`.

The ordinary cold-check retains its 100-row limit. This supplement instead compares every value in both the CLI native text export and a fresh execution of the saved export, checks native import definitions and persisted source/format, and downloads the persisted source to recheck its bytes. The cold profile must be new and cleanup must confirm both package closure and logout. CLI evidence does not certify Desktop or other operating systems.

The supplement uses the installed Multica `common`, `linux`, `accept`, redactor and session-release helpers without changing that operational bundle. Run from the managed checkout after a clean candidate build:

```sh
python3 docs/node-development/nodes/text-import/acceptance/txt-oracle.py prepare \
  --source <downloaded-original-transactions.txt> --expected <private-oracle-file-outside-model-attempt>
python3 docs/node-development/nodes/text-import/acceptance/run-txt-cli.py \
  --worktree "$PWD" --config "$HOME/.config/loginom-multica/cards/<issue>/worker.json" \
  --source <downloaded-original-transactions.txt> --expected <private-oracle-file-outside-model-attempt> \
  --out "$PWD/.multica-node/attempts/<new-attempt>"
```

The runner admits only the task and original TXT through standalone CLI `--file`; it uses the configured model/variant and the normal 7200-second foreground boundary. Expectations and administrative credentials are copied into the attempt only after the model process exits. `txt-cli-audit.py` binds the exact admitted artifact/grant to the single successful delivery, source import, fresh schema, linked export and verified local bytes. The product transport adds a prefix to attachment basenames; cold verification checks the exact admitted basename and destination from the receipt, retaining `.txt` and the original bytes.

`txt-cold-check.mjs` uses a new browser profile, reads/cancels persisted native settings, verifies the server source again, executes the import freshly without changing its settings, and executes the saved export. Explicit replace is authorized only for that export's independently observed saved destination. The default scenario-variables node is accepted; extra processing nodes or links are refused. Python compares complete downloaded exports before and after reopen as multisets, including duplicate multiplicities, dates, numeric values, and unchanged string identifiers. Full expected records and exported data stay private. Publication uses `publish-evidence.py` on this attempt's sanitized evidence.

A known failed import with confirmed draft cleanup may be corrected on the same retained node. The transcript binds the single original creation and its cleanup to that node GUID, then requires one successful import and the same persisted GUID; ambiguous effects, extra creations and duplicate uploads are refused.
