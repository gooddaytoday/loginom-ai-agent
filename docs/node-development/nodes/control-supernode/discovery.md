## Что требует общего решения

Одной аддитивной регистрации недостаточно. Основания в назначенной базе:

1. `client/lib/node-target-browser.mjs:27` требует неизменный navigation_path;
   вход в наблюдённый внутренний граф меняет его. На строках 34–48 проход
   предков перезаписывает workflowNode и выбирает внешний workflow вместо
   ближайшего. Старый ref нельзя переносить во внутреннюю область.
2. `client/lib/workspace.mjs:219` допускает existing_workflow только с прежними
   вкладкой и breadcrumbs; `node-workflow-activation.mjs:34` активирует вкладку,
   но не выполняет enter/leave. Нужен подготовленный переход с выдачей свежих
   refs внутреннего графа и восстановлением родительского контекста.
3. В `node-target-browser.mjs:67` тип определяется по иконке; InputNode и
   OutputNode оба nullvendor. Нужна явная роль граничного узла и локальная
   связь с ним. `node-contracts.mjs:130` запрещает межсценарный input — этот
   запрет сохраняется: внешняя и внутренняя связи каждая локальны.
4. `scripts/node-acceptance/cold-check.mjs` наблюдает подготовленный корневой
   граф. Существующий matcher умеет ordered/output_port/tolerance, но сам
   не доказывает местонахождение Калькулятора и граничные связи. Предложение:
   использовать ту же принятую W1-навигацию и обычное observe/read в сценарии
   run-check и cold, без нового механизма проверки и без XML-oracle.

Предлагаемый W1: подготовленная enter/leave-навигация, refs по точному
вложенному workflow и роли его граничных узлов; адресные тесты старого ref,
чужого узла, одинаковых GUID разных областей и возврата на родителя.
Точный публичный API перехода **не утверждён** и этим PR не вводится.
Общие модули и публичный контракт не менялись. По стоп-условию LAB-1543
допуск реализации blocked до решения; предложенный комплект готов к review.

## Переиспользование — оценка, не живая проверка других компонентов

| Компонент | Общая основа | Что остаётся самостоятельным |
|---|---|---|
| Условие | ownership вложенного workflow, граничные порты, enter/leave, сохранение | выбор ветви, агрегированные условия, неактивные выходы |
| Цикл | область базового компонента, refs и табличные границы, сохранение | итерации, сбор выходов, ошибки и обучение |
| Выполнение узла | точная identity базового компонента/пакета/портов | независимость исполняющего экземпляра, trained state, привязка компонента |
| Узел-ссылка | различение owner/source, GUID с областью, read внешнего результата | разрешение ссылки и кэш, доступность другого пакета, циклы ссылок |

Подмодель не доказывает, что Условие/Цикл имеют тот же DOM; для них требуется
своё discovery. Для узла-ссылки корневого сценария enter/leave может вовсе
не понадобиться. W1 не разрешает произвольные межсценарные связи.

## Семантика данных и предел наблюдения

Контейнер должен сохранять то, что выдаёт внутренний граф; он не сортирует,
не агрегирует и не обучается сам. Для предлагаемого Калькулятора: исходные
поля в исходном порядке, затем Doubled=2×Amount, NULL распространяется,
пустой Note отличается от NULL, повторы и порядок строк сохраняются.
Integer/real/string/boolean/datetime и exact binary fractions закреплены в
fixtures/manifest.json и независимом oracle. Это **предложенный контракт**:
живых табличных результатов, NULL/readback, пустого входа, Execute после смены
источника и cold PASS в этапе 0 не получено. Их нельзя считать подтверждёнными.

Параметры с descriptions и строковыми enum — `parameter-schema.proposal.json`;
NODE_TYPES semantics — `node-type.proposal.json`. Компактный readback должен
содержать оба порта (index, GUID, name, label, kind, required для input),
их зеркальные node/port refs и текущий выданный workflow_ref. Все значения
наблюдаемые; не возвращать весь вложенный граф или XML в карточке типа.
Чтение конфигурации и получение полного графа — отдельные операции.
