## Предлагаемое разбиение на этапы

Разбиение — гипотеза до этапа 0. Каждый этап должен приниматься самостоятельно; общие изменения, нужные этапу, входят в его же карточку.

- `control-supernode:s1` — v1: внутренний граф 1→1, один уровень. Требования: `control-supernode:r01`, `control-supernode:r02`.
- `control-supernode:s2` — Несколько табличных портов и структура графа. Требования: `control-supernode:r03`, `control-supernode:r04`. После: `control-supernode:s1`.
- `control-supernode:s3` — Переменные, деревья и расширенный lifecycle. Требования: `control-supernode:r05`, `control-supernode:r06`, `control-supernode:r07`. После: `control-supernode:s2`.

## Заметки черновика

Подмодель содержит собственный граф. Порты создаёт пользователь; входы могут быть таблицами (включая необязательные), переменными и деревьями, выходы — таблицами/переменными/деревьями. Рекурсивная вложенность поддерживается продуктом; агент вводит только явно объявленные границы конкретного этапа.

`node-contracts.mjs` отклоняет межсценарные связи; `node-workflow-activation.mjs` не реализует вход в Подмодель. Расширять подготовленные refs и навигацию с доказательством владельца; обычный input link не превращать в межсценарный обход.

v1 намеренно не включает compose/expand, переменные, деревья и рекурсию. UI создания/разворачивания подтверждается отдельно по общему workflow. Исследовать boundary refs и nested cold oracle; ни navigation_path, ни наличие компонента в палитре не доказывают готовую навигацию.
