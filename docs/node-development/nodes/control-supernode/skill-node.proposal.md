# Подмодель

Предложение для этапа 1; сейчас обработчика и разрешённой навигации нет.

<!-- mode: tabular_boundary -->
Тип `control.supernode`, mode `tabular_boundary`: контейнер одного внутреннего
сценария с обязательным табличным входом 0 и табличным выходом 0.
В `parameters.boundary` полностью задай input/output: kind=table, name, label;
для input также requirement=required. Имена — латинские идентификаторы.
Настройки нового узла обязательны; пропуск boundary у существующего сохраняет
поддержанные порты. Подключение внешнего источника задаётся обычным inputs.

Подмодель сама не вычисляет формулу. Войди в неё штатной операцией навигации,
получи свежий workflow_ref и прочитай граф. Создай обычный поддержанный узел
внутри: выход внутреннего «Входного узла» → обработчик → вход внутреннего
«Выходного узла». Внутренние связи принадлежат внутреннему workflow.
Внешний источник подключается к внешнему входу Подмодели, не к её внутреннему
узлу. GUID без workflow не является достаточным адресом.

При выходе получи свежий контекст родителя. Выполни саму Подмодель и прочитай
её внешний выход 0 с точными числами и полным чтением малой таблицы
(sample_rows=100, sample_complete=true). Проверь типы, NULL, пустые строки,
повторы, порядок полей и требуемый порядок строк. Изменение файла источника
не требует пересоздавать Подмодель. Сохрани пакет после окончательного чтения.

У Подмодели нет отдельного режима обучения/применения. Вложенные Подмодели,
перенос готовых узлов, разворачивание, несколько портов, необязательные входы,
деревья, переменные, Условие и Цикл отложены. Не пытайся обойти отсутствие
разрешённой навигации общим UI-действием. При отказе мастера читай btnError.
