## Срез для утверждения

Один уровень Подмодели, один обязательный табличный вход и один табличный
выход с явными именами/метками. Внутренний Калькулятор создаётся с нуля.
Перенос существующих узлов/compose/expand отложен: создание внутри уже
покрывает полезный минимальный сценарий и не требует миграции ownership.
Нет Условия/Цикла, дополнительных/необязательных портов, переменных, деревьев,
вложенных Подмоделей и обучения. Поддержанные скалярные поля в таблице
не являются отдельными границами переменных/деревьев.

1. Создать внешнюю Подмодель и порты, войти, создать Калькулятор и локальные
   связи InputNode → Calculator → OutputNode. Вернуться и выполнить родителя.
   Проверить полный внешний выход 0: 5 строк, 6 полей.
2. Сменить только файл того же импорта; Подмодель, Калькулятор и порты
   сохраняют identity в своих workflow. Повторный Execute: 3 строки, 6 полей.
   В старом результате этих RowID и значений нет.
3. Данные точные и упорядоченные; CSV initial.csv/result.csv, Save после
   последнего чтения, повторное открытие в новом профиле и cold Execute
   без восстановления настроек. Итог совпадает с expected.json.
4. Обычный observe через принятую W1-навигацию подтверждает вложенный
   Calculator и обе границы в основном прогоне и после reopen/cold.
   Только корневой табличный matcher не доказывает топологию.
5. Отрицательные адресные проверки на production-ветке: старый ref после
   перехода, чужой workflow/node, одинаковый GUID в разных областях,
   межсценарная прямая связь, недопустимое имя порта и неподдержанный mode.
   Отказ до мутации; native причина из btnError; неизвестный эффект не повторять.
6. Исполнитель ≥2/3 PASS на одном SHA; независимая приёмка 2/3 на том же SHA
   под своим аккаунтом; stock cleanup package_closed/logged_out.

`empty.csv` + `task-empty.md` + `expected-empty.json` — отдельно предлагаемая
граница 0 строк с полной схемой. В native UI не выполнялась; пока не является
PASS или утверждённой частью основного сценария. Если владелец включает её
в этап 1, проверять как самостоятельный run-check, не подменять ошибку
выполнения пустой таблицей. Остальные режимы относятся к будущим этапам.

## Независимые числа и типы

Oracle использует Python stdlib и Decimal, не импортирует runtime/Loginom и
не читает результаты стенда. NULL — только маркер `?`; пустое поле Note —
пустой текст. Boolean true/false/NULL различны. Datetime — гражданское время
без timezone conversion; дата проверяется на нативном типизированном выходе,
а не только по экспортированному тексту.

| Случай | Строки | Порядок RowID | Doubled по порядку |
|---|---|---|---|
| initial | 5 | 3, 1, 2, 2, 4 | 2.5, NULL, -5, -5, 0 |
| final | 3 | 9, 8, 7 | 0.25, NULL, -8 |
| empty, предложение | 0 | — | — |

Порядок полей: RowID integer, Amount real, Note string, Flag boolean,
Moment datetime, Doubled real. `label_any:true` для незаданных меток полей;
метки портов заданы в task и проверяются readback конфигурации.
`output_node_type:control.supernode`, `output_port:0`, `ordered:true`,
`column_order:exact`. У Amount/Doubled tolerance abs=0, rel=0: все значения
— двоичные рациональные, нет округления/агрегации. Одинаковые строки
RowID=2 должны остаться двумя строками. Не сортировать по RowID ради проверки.
Для точного порядка полей следует использовать существующий полный output
mapping с autosync=false, если discovery этапа 1 обнаружит перестановку;
сначала наблюдение, затем согласованное исправление, не изменение oracle.
Пустой импорт требует явной схемы; Int64 вне safe JS range и Variant не входят.

```sh
python3 docs/node-development/nodes/control-supernode/acceptance/oracle.py --case initial --check
python3 docs/node-development/nodes/control-supernode/acceptance/oracle.py --case final --check
python3 docs/node-development/nodes/control-supernode/acceptance/oracle.py --case empty --check
```

Ожидания уже используют существующий формат expected-outputs.mjs, без новых
ключей и механизмов приёмки. Зарегистрированный run-check сценарий — `supernode-calc`, со сменой источника
на том же графе; empty —
`supernode-empty`, только если включён в утверждённый срез. Основной сценарий зарегистрирован; empty не зарегистрирован. Модель `openai/gpt-6.1-sol`, medium, 1800 с.
Фикстуры/задания/oracle/expected зафиксированы до будущих прогонов.

## Предлагаемый readback

Показывать компактную конфигурацию обоих портов: direction/index/GUID,
name/label/kind, required у входа; refs зеркальных InputNode/OutputNode и
их портов, выданный workflow_ref внутреннего графа. На enter/leave выдавать
свежие refs, сохраняя возможность вернуться к родителю. Не возвращать весь
граф, XML или preview таблицы вместо типизированного read.
Формат публичной навигации и readback refs требует решения по W1.
