## Предлагаемое разбиение на этапы

Разбиение — гипотеза до этапа 0. Каждый этап должен приниматься самостоятельно; общие изменения, нужные этапу, входят в его же карточку.

- `variables-replace:s1` — Внутренние точные правила. Требования: `variables-replace:r01`, `variables-replace:r02`.
- `variables-replace:s2` — Регулярные выражения и типы замены. Требования: `variables-replace:r03`, `variables-replace:r04`. После: `variables-replace:s1`.
- `variables-replace:s3` — Файлы правил и перенастройка. Требования: `variables-replace:r05`, `variables-replace:r06`. После: `variables-replace:s2`.

## Заметки черновика

Вход/выход — переменные. Сначала применяются точные правила, затем регулярные выражения, затем правило для остальных значений. Импорт файла правил копирует таблицу в узел; дальнейшее изменение файла само по себе не меняет узел.

Текущие `node-target-browser.mjs` и `node-contracts.mjs` работают с табличными портами; перед handler нужны типизированные ссылки/связи и независимое чтение переменных. Общий lifecycle `node-apply.mjs` сохранить. `replacement-node.mjs` и `replacement-parameters.mjs` служат образцом exact-редактора, но текущий scalar exact handler не покрывает весь список режимов.

По exact-match и regex установить дубликаты правил, интервалы и substitution syntax; импорт/экспорт правил требует самостоятельного файлового oracle, а не text-export handler.
