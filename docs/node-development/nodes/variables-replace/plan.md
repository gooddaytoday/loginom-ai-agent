## 2. Контракт этапа 1 — предложение

Один обязательный variables-вход и variables-выход 0. Выбранные переменные
адресуются точным именем из W1 inventory. Для каждой — полная таблица уникальных
однородных пар, other=keep; строки case_sensitive=true, числа precision=0.
Каждое исходное значение ищется один раз; типы/имена/метки/порядок сохраняются.
NULL не равен пустой строке, false, 0 или отсутствующей переменной.
При patch меняется полная таблица только перечисленных переменных;
сохранённые правила остальных, identity, связи и mapping не меняются.

Отказы до мутации: дубликаты, неизвестные имена/параметры, неверные типы,
несовместимый вход, regex, смена типа и другие режимы вне среза.
Semantics, описания всех полей, строковые enum — в node-card-proposal.json;
компактный configuration/readback и детали precision — в contract.md.

## 4. Реализация после принятого W1

W1 предоставляет typed refs/связи `variable_inputs` kind `variables|control`,
`read.variable_ports`, точные значения и typed cold. Нужное **сверх W1**:
собственные узловые редакторы/контекст/readback `ReplaceVariablesWizard`,
Boolean/NULL пары, duplicate refusal, сохранение меток на странице
`DerivedVariablesMappingEngineOutputPortWizard`, аддитивная регистрация
`variables.replace`, reference навыка и сценарий `variables-replace-exact`.

Образец — `replacement-*.mjs`; он привязан к табличному мастеру и не покрывает
Boolean. Не расширять общий handler ради совпадения имён controls. Новый
узел подключает свои процедуры аддитивно, сохраняя общие guards/lifecycle.
Потребуется менять общее поведение/контракт сверх разрешённого — стоп до кода.

Пути: узловые `variables-replace-*.mjs` и тесты; аддитивные точки регистрации;
`references/nodes/variables.replace.md` и строка маршрутизации; существующий
каталог сценариев run-check. Проверки по фактическому диффу определяет
`required-checks.py list --base <база>`; report сверяется через verify.

Оценка: **2 цикла + 1 резервный**, без разработки W1 и независимой приёмки.
Первый — правила/редакторы/mapping и живой сценарий; второй — patch/source
refresh, cold и регрессия. Каждый цикл включает бизнес-прогон.
