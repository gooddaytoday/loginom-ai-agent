# Дополнительные режимы Замены переменных — LAB-1031

07.11.2026, mas2, Loginom 7.4.2; база
`8943d291b046698d67828f19dcca88aab790cf2c`.
Только testable-стенд и собственный пакет назначенной пары.
Этот документ фиксирует checkpoint, а не завершённое исследование режимов.

Создан узел «Замена (переменные)», вход переменных 0 связан с собственным
Калькулятором-источником. Источник содержит datetime, Variant, integer, real
и string. Порты по наблюдённому DOM:
`MF;TF-1;Graph;Замена_(переменные);Input_Var-0` / `Output_Var-0`.
`discovery2.jsonl:35` во вложении отчёта подтверждает собственный узел.

До открытия мастера настройки произошли разрывы связи. После двух
разрешённых переподключений исследование остановлено; третье не выполнялось
(`discovery2.jsonl:16,18,36`, `table-discovery.jsonl:6–7`). Поэтому ни один
из режимов ниже не объявляется отсутствующим в 7.4.2 или поддержанным runtime.
Старый exact-срез и его критерии не менялись.

| Режим назначения | Статус | Причина / поверхность |
|---|---|---|
| Regex | not_checked | Мастер Замены не открыт до лимита переподключений |
| Без учёта регистра | not_checked | Та же остановка; состояние chkCaseSensitivity не читалось |
| precision≠0 | not_checked | Та же остановка; edPrecision не читался и не изменялся |
| Смена типа | not_checked | Та же остановка; btnTypeChange в текущем исследовании не открыт |
| datetime | not_checked | Тип создан в источнике; настройка/выполнение замены не выполнены |
| Variant | not_checked | Variant=7 создан в источнике; таблица замены не исследована |
| Импорт правил | not_checked | Та же остановка; btnLoad не использовался |
| Экспорт правил | not_checked | Та же остановка; btnSave не использовался, файл не получен |
| other=NULL | not_checked | Та же остановка; cbxReplaceOther не читался |
| other=значение | not_checked | Та же остановка; значение для остальных не задавалось |

Имена контролов в последнем столбце, кроме явно наблюдённых Graph TID,
относятся к прежнему [discovery exact](discovery.md). Они обозначают следующий
шаг исследования, а не новые снимки соответствующих режимов.

Приёмочный комплект дополнительных режимов не готов: до наблюдения UI
не зафиксированы тип результата, синтаксис regex, формат файла правил,
точность сравнения и выходные имена/метки. Независимые expected для этих
режимов не выдумываются. Карточка типа и reference дополнительных режимов
не предлагаются, размеры после расширения и циклы реализации не оценены.
Базовая реальная карточка exact — 5572 Б; новый замер нужен после исследования.

Следующий шаг после стабилизации сеанса: открыть свой связанный узел,
начиная с regex/регистра и числовой точности, затем исследовать типы,
файлы правил и обе политики остальных. Oracle/expected — до модельных
прогонов, критерии — владельцу до runtime-кода; работа остаётся docs-only.
