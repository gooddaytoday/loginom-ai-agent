Числовая замена NULL нулём: независимый oracle

`oracle.py` читает только исходные CSV, не импортирует обработчик и не использует
ответы модели. Исходные `expected*.json` сформированы до реализации метода.
Ожидания zero для all-null и порога уточнены по наблюдённому нативному порту:
этому методу не нужно вычислять статистику известных значений.
Модели передаются только соответствующее задание и один CSV.

Основание семантики — [справка Loginom](https://help.loginom.ru/userguide/processors/preprocessing/imputation.html):
обрабатываются настоящие NULL. Общие оговорки справки о доле пропусков и all-null
не применяются к фиксированному zero: наблюдённый native enum 11 заполняет NULL
нулями при пороге 0%, включая полностью пустое поле; mean при этом сохраняет NULL.
В смешанном threshold-сценарии I использует mean, R/A — zero при пороге 20%.
Доля NULL в I/R ровно 25%: I сохраняет NULL, R заполняется нулём; A полностью
пустое и тоже заполняется. Такое различие не требует пограничного округления.
Ноль среди известных значений сохраняется, Keep не включается в обработку.
Пустой вход сохраняет всю исходную схему.

Cold выбирает порт 0 по типу узла. `export_destination` для такого output не
передаётся: это поле предназначено только для `export_input`. Регистрация
сценариев проверяет fixtures штатным `parseExpectedOutputs` до живого запуска.

Основной сценарий меняет mean на zero в том же узле. Регрессия mean использует
точно представимые средние I=2 и R=2.5; округление не входит в этот срез.
Технические имена, типы, порядок полей и строк точны; свободные метки проверяются
через `label_any`. CSV и холодное выполнение проверяют все ячейки.

Перегенерация из этого каталога:

```sh
python3 oracle.py > expected.json
python3 oracle.py threshold > expected-threshold.json
python3 oracle.py empty > expected-empty.json
python3 oracle.py mean > expected-mean.json
```
