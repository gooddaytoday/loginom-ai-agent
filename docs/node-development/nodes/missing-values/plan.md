# 14. Заполнение пропусков: подплан сопровождения и приёмки

[Карточка и принятые границы](README.md) · [реестр](../../registry.json) · [работа с одним узлом](../../workflow/single-node.md).

Обработчик `preprocessing.data_recovery` уже реализован в режиме `impute`. Этот подплан адаптирует исторический 14 к текущему runtime и standalone CLI: это маршрут адресного исправления, проверки переноса или отдельно назначенного расширения, не повторная разработка с нуля. Историческое принятие сохраняется в своём scope; технические Desktop проверки не являются аналитической CLI-приёмкой. Новых живых наблюдений и прогонов при составлении документа не было, readiness не повышается.

До начала выбрать точное изменение и пройти [подготовку/жизненный цикл](../../workflow/lifecycle.md). Разработчик работает в Astra medium в своей задаче, ветке и worktree. Первичная разработка получает Goal до готовности изменения к первому ревью, без собственного token_budget. Этот документ не назначает следующий узел и не разрешает слияние.

## Узловые требования

Полный набор fields задаёт mean только для непрерывных integer/real и constant только для дискретных string; ordered=false и целый max_nulls_percent 0–100 обязательны. Неперечисленные поля отключаются. Пустой parameters разрешён только для повторного выполнения existing сохранённой конфигурации.

NULL отличается от пустой строки, нуля и текста null. Порог или all-null могут оставить пропуски после успешного выполнения. Числовая константа, медиана/мода, интерполяция, previous/random/delete, переменные и неявная смена типа/вида не поддержаны.

## Шаги изменения

1. Проверить матрицу type/data_kind/method и реальную семантику порога, integer rounding и all-null. Наличие обученного состояния установить по текущему режиму, не делать вывод по общему названию preprocessing.
2. В validate/resolveMissingValuesParameters валидировать весь processing set. При обновлении явно выключить поля вне списка; неподдержанный сохранённый метод не считать принятым.
3. Применить mean/строковую константу и порог, прочитать значения редактора. При input mapping помнить, что это отдельное сохранение и Close не отменяет уже сохранённый input.
4. Связать Execute с версией входа; изменение среднего источника должно давать подтверждённый новый результат/обучение согласно наблюдённой семантике.
5. Независимо проверить все ячейки и количество оставшихся NULL. Save/reopen проверяет настройки и сохранённое/пересчитанное состояние, а не только наличие файла.

## Независимые fixtures и oracle

Ниже — обязательная узловая матрица для объявленного полного scope. При адресном исправлении выбрать затронутые строки и обосновать выбор; расширение режима добавляет новые строки. До автономной попытки сохранить входы и expected отдельно от handler, с версиями и SHA. Ожидания не вычислять импортом реализации и не подгонять по её приёмочному выводу.

| Случай | Вход/изменение | Независимая проверка |
| --- | --- | --- |
| Среднее | Real=2.5,NULL,7.5; другой неизменяемый столбец с NULL. | При разрешающем пороге получить 2.5, 5, 7.5; неперечисленный столбец не меняется. Отдельная серия с отрицательными/длинными дробями. |
| Integer | Integer=1,NULL,2. | Проверить тип и нативное округление1.5 отдельным независимым expected из согласованной семантики, не применять round() языка проверки автоматически. |
| Строковая константа | NULL,empty,literal null,X; existing меняет replacement на другую строку. | Только NULL получает новую константу; исходные empty/null/X и порядок сохраняются. |
| Порог | Ниже/на/выше доли пропусков, случай1 NULL из 120 при 0%, all-null при100%, header-only. | Для каждой серии зафиксировать ожидаемые оставшиеся NULL и округление доли до автономного прогона; успех не означает полного заполнения. |
| Новый источник | После первого исполнения заменить числа на 10, NULL, 30, сохранив узел. | Проверить обновлённое среднее/обученное состояние и отдельное воспроизведение после reopen, без глобального retrain графа. |

## Негативные случаи

- Mean для дискретного числа, constant для числа, variant, ordered=true, неверный порог, повтор/чужое поле: отказ без автоконверсии.
- Потерянный ответ input Done/configure, источника нет, разрыв связи: различать известную ошибку с cleanup и AMBIGUOUS; не сбрасывать pending ради следующего запуска.
- Oracle отвергает заполнение неперечисленного поля, подмену threshold/method, ноль вместо NULL и старый результат после смены входа.
- Для изменённых фаз отдельно различить отказ до эффекта, известную ошибку с подтверждённым cleanup и неизвестный эффект. Повтор operation_id не создаёт второй узел/запуск; lost reply не оправдывает слепой retry. Чужой пакет и посторонние связи неизменны.

## Автономная проверка и передача

Заполнить допустимые пропуски средним и заданной строкой, показать оставшиеся пропуски из-за порога, проверить обновление на втором источнике и сохранить пакет.

Первичная отладка — штатными скриптами текущего runtime в назначенной изоляции. После неё выполнить адресные source tests и проверить независимый oracle, включая его отказ на подменённых значениях/схеме/идентичности. Только затем подготовить неизменный candidate и получить слот по [CLI-регламенту](../../workflow/acceptance-cli.md): standalone CLI Loginom AI Agent, Sol low, согласованная подписка, бизнес-цель и входные файлы без пошаговых UI-команд.

Критерий аналитического PASS — полный малый output/артефакт, проверенная схема и настройки, новый execution и сохранённый пакет, которые независимо воспроизводятся после отдельного открытия. Configure-only и Close проверяются отдельно; обычный продуктовый путь не переоткрывает мастер ради повторной проверки. Непроверенные платформы, большие наборы и дополнительные режимы остаются явно ограниченными.

Передать checkpoint с точными source/runtime/client/model/platform pins, заявленным scope, результатами и неизменёнными исходными FAIL. Техническое завершение, аналитическая проверка, integration и release — отдельные состояния реестра. Один этап ревью и один раунд исправлений выполняются по общему жизненному циклу; этот подплан не добавляет повторного полного ревью.
