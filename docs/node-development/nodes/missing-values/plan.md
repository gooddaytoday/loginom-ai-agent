## 2. Этапы

### Этап 0 — перепроверка принятого объёма

Подготовка: проверить SHA, собрать кандидата из закоммиченных исходников, получить `loginom status` = `ready` на назначенном стенде.

1. Собрать `acceptance/` из прежнего контракта (раздел 3): независимые ожидания и значения сохранить; транспорт, pins и receipts прежнего формата не переносить. Прежний launcher Hermes не запускать.
2. Адресные тесты `client/test/missing-values-*.test.mjs` (6 файлов), затем весь `client/test`: `bun run test:upstream` в `packages/loginom-runtime`.
3. CLI-сценарий и независимое холодное открытие по RUNBOOK; generic cold-check и адресные дополнения — в разделах 3–4.
4. При расхождении — живая сверка мастера с `?testable=true`; прочитать причину из кнопки ошибки, записать в `discovery.md`; наблюдение не подменять E2E-снимком.
5. Исправить дефект с адресным тестом; правка общего кода — минимальная и только под наблюдённый отказ сценария; расширение объёма — вопрос владельцу.

Выход: PASS исполнителя и независимая приёмка того же SHA; `client_technical_validation` и `analytical_validation` отражаются только по новому результату.

### Адресные действия при FAIL

1. Проверить матрицу type/data_kind/method и реальную семантику порога, integer rounding и all-null. Наличие обученного состояния установить по текущему режиму, не делать вывод по общему названию preprocessing.
2. В validate/resolveMissingValuesParameters валидировать весь processing set. При обновлении явно выключить поля вне списка; неподдержанный сохранённый метод не считать принятым.
3. Применить mean/строковую константу и порог, прочитать значения редактора. При input mapping помнить, что это отдельное сохранение и Close не отменяет уже сохранённый input.
4. Связать Execute с версией входа; изменение среднего источника должно давать подтверждённый новый результат/обучение согласно наблюдённой семантике.
5. Независимо проверить все ячейки и количество оставшихся NULL. Save/reopen проверяет настройки и сохранённое/пересчитанное состояние, а не только наличие файла.

### Этап 1 и далее — непокрытые режимы Help 7.4 (отдельные карточки владельца)

- Median, наиболее вероятное, ноль, случайное, оставить, удалить строки и заданное строковое значение.
- Seed: фиксированный/всегда случайный/генерировать/копировать; целочисленное округление доли NULL.
- Previous, linear/cubic/spline interpolation и переключение ordered.

Перечень будущей полноты сохраняет прежний подплан: частично принятые действия перепроверяются на этапе 0, дополнительные controls/типы/режимы назначаются отдельно; совпавшее название режима не расширяет scope.

Комплект `nodes/missing-values/acceptance/` собирает будущая карточка:

Прежние входы: `fixtures/missing-values/core.csv`: 103 байт, 4 записей, колонки `Id, Amount, Count, Note, Untouched`, разделитель `;`; `fixtures/missing-values/changed.csv`: 101 байт, 4 записей, колонки `Id, Amount, Count, Note, Untouched`, разделитель `;`; `fixtures/missing-values/one-in-120.csv`: 1848 байт, 120 записей, колонки `Id, Amount, Count, Note, Untouched`, разделитель `;`; кодировка UTF-8, NULL-маркер `NULL`. Размеры и SHA сохранить в manifest до прогона.

Ожидания прежнего контракта: Из `missing_values_goal.py` и acceptance-pins.json: core Amount→5, Count→2 (прежний ROUND_HALF_UP), Note только NULL→MISSING/NEW_NODE; Untouched сохраняет NULL. Порог — целая доля `missing*100//rows`, all-null остаётся NULL; boundary при 40/41/42 и 1 из 120 при 0% проверяются независимо.

Матрица сохранена из прежнего подплана; ожидания и неоднозначные правила переподтвердить до модельного прогона:

| Случай | Вход/изменение | Независимая проверка |
| --- | --- | --- |
| Среднее | Real=2.5,NULL,7.5; другой неизменяемый столбец с NULL. | При разрешающем пороге получить 2.5, 5, 7.5; неперечисленный столбец не меняется. Отдельная серия с отрицательными/длинными дробями. |
| Integer | Integer=1,NULL,2. | Проверить тип и нативное округление1.5 отдельным независимым expected из согласованной семантики, не применять round() языка проверки автоматически. |
| Строковая константа | NULL,empty,literal null,X; existing меняет replacement на другую строку. | Только NULL получает новую константу; исходные empty/null/X и порядок сохраняются. |
| Порог | Ниже/на/выше доли пропусков, случай1 NULL из 120 при 0%, all-null при100%, header-only. | Для каждой серии зафиксировать ожидаемые оставшиеся NULL и округление доли до автономного прогона; успех не означает полного заполнения. |
| Новый источник | После первого исполнения заменить числа на 10, NULL, 30, сохранив узел. | Проверить обновлённое среднее/обученное состояние и отдельное воспроизведение после reopen, без глобального retrain графа. |

Oracle не импортирует handler/runtime, рассчитывает по исходным байтам, сверяет все ячейки и схему, отличает NULL/пустую строку/0, отвергает неполное чтение.

Cold-check: схема проверяется позиционно (имена, метки, типы), строки — как мультимножество, до 100 строк/выход и 32 выходов (`scripts/node-acceptance/expected-outputs.mjs:14,29-39,72-81`). Числа сравниваются точно (`cold-check.mjs:232`); большие Int64 — десятичные строки. Каждый ожидаемый выход однозначно связан с типом и меткой узла. E2E-снимки мастера не являются oracle.

Случай `one-in-120.csv` (120 строк) не помещается в generic cold-check; сохранить его полную независимую адресную проверку. Старый oracle содержит допуск real 1e-14: его перенос в общий comparator — отдельное W1 с решением владельца. Основной cold-check использует точно представимые core-значения; precision/skew остаются адресными случаями и не выдаются за generic PASS.

Свежесть результата обеспечивает сам cold-check: он заново выполняет узлы сохранённого пакета в новом профиле. Отдельные доказательства происхождения, квитанции и receipts не требуются. Порядок строк, несколько портов одного узла, допуск для вещественных и выход переменных в cold-check добавляет общая карточка LAB-78 (ветка `acceptance-tools`); в ветке узла эти возможности не реализуются.

## 5. Ловушки — переподтвердить, не копировать

- Mean для дискретного числа, constant для числа, variant, ordered=true, неверный порог, повтор/чужое поле: отказ без автоконверсии.
- Потерянный ответ input Done/configure, источника нет, разрыв связи: различать известную ошибку с cleanup и AMBIGUOUS; не сбрасывать pending ради следующего запуска.
- Oracle отвергает заполнение неперечисленного поля, подмену threshold/method, ноль вместо NULL и старый результат после смены входа.
- Чужой пакет и посторонние связи неизменны.
- История 14: восстановление ответа input Done не равно восстановлению configure; сохранение входного mapping — отдельный известный эффект. Прежний oracle допускает real 1e-14, текущий cold-check — точное сравнение: длинные дроби не исключать из адресного аудита.
- Приёмки текущего CLI нет; неподтверждено: integer rounding, пороги/all-null, повторное среднее после смены источника. Исторические замеры/локаль/платформа не являются гарантией текущего стенда.
