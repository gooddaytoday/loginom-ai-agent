## 0. Как выполняется назначение

Оркестрация — Multica, сквад «Обработчики узлов»: Генератор тасок готовит назначение, Тест-Манки #1 разрабатывает, Ловец Галюцинаций независимо принимает опубликованный SHA.

```text
Ветка: <ветка задания>
Узел: preprocessing-datapartition
Обработать узел по его подплану до независимой приёмки. Объём — этап <N> подплана.
```

Первая карточка — этап 0 отдельно; этап 1 после решения владельца по W3. В ветке задания обязательны RUNBOOK, подплан и инструменты CLI-приёмки (`scripts/node-acceptance/cold-check.mjs`, сборка `--no-archive`).

Не разрешено: merge и релиз, следующие этапы, новые общие контракты без решения владельца, изменение конфигураций обвязки.

### Стоп-условия

Каждое оформляется как Blocked с конкретным вопросом Генератору:

- в ветке задания нет обязательных документов или инструментов;
- аккаунты или CLI не `ready` на назначенном стенде;
- неизвестный исход операции: сохранить попытку, writer marker не удалять;
- в палитре нет «Разбиение на множества» либо native component/fulltype не совпал;
- нет решения владельца по W3, если изменение нужно назначенному этапу;
- недоступны полные результаты/свежесть/независимый oracle; это не PASS.

## 2. Этапы

### Этап 0 — подготовка, живое исследование, контракт

Подготовка: проверить checkout/SHA, собрать кандидата из закоммиченных исходников, получить `loginom status = ready`. UI только штатными средствами runtime с `?testable=true`; каждый отказ мастера прочитать из его кнопки ошибки.

1. Палитра «Разбиение на множества», точный заголовок и корень мастера, native component/fulltype, входы/выходы и их виды, все страницы.
2. Conflict размеров и округление процентов, фактический состав общего выхода, test flag и unused; seed каждого случайного режима, методы uniform/stratified/bias.
3. Умолчания и границы каждого элемента мастера этапов 1+; зависимые/disabled настройки, NULL/пустая строка, пустой вход, неподдержанный тип.
4. Имена, метки, типы и порядок всех выходных полей; момент появления схемы до/после Execute или обучения; все порты одного исполнения.
5. Execute/configure/read без искусственного обучения; для обычных статистических преобразований train не вводить.
6. Тот же узел после замены файла существующего импорта: свежие значения и схема, необходимые явные retrain; не пересоздавать узел для обхода.
7. Фиксированный seed (если элемент seed доступен) и два повторных расчёта/обучения на одинаковом входе; при недетерминированности заранее закрепить проверяемые инварианты и допуски. Для random/uniform воспроизводимость состава проверяется в рамках гарантий Help, без копирования чужого PRNG.
8. Ожидаемые отказы из раздела 5; неизвестный эффект сохранить, не повторять автоматически.

Результат — `discovery.md`: конкретные значения с пометками «наблюдено / гипотеза», решения по W3, схема портов/соответствия полей и численный oracle. `ready_for_development` только после закрытия вопросов назначаемого среза и согласования общих изменений; `fixtures/` и `acceptance/` готовятся до кода.

### Этап 1 — Размеры, приоритет и три выхода

Покрытие требований этого этапа:

- `preprocessing-datapartition:r01` — Train/test количество или процент, остаточный принцип при конфликте размеров, приоритет test. Источник: `preprocessing-datapartition:help1`.
- `preprocessing-datapartition:r02` — Приоритетное test: алгоритм/начало/конец; последовательный отбор sampled/unused размеров. Источник: `preprocessing-datapartition:help1`.

Scope: количество/процент train и test, остаточный принцип, приоритет test начало/конец, последовательное выделение; общий, обучающий и тестовый выходы. Создание, изменение существующего узла, readback всех назначенных настроек и чтение всех выходов в объёме этапа. Режимы следующих этапов отклоняются до мутации с объяснением исправления.
Файлы: новые `packages/loginom-runtime/client/lib/data-partition-{node,parameters,procedure,context,readback}.mjs`, `client/test/data-partition-*.test.mjs`; регистрация в `node-contracts.mjs` и `.d.ts`, `node-support.mjs`, `node-api.mjs`, `node-procedure.mjs`, `node-result-schema.mjs`, `user-results.mjs`; общая оболочка `calculator-node.mjs:38`. Образец — Фильтр строк (`filter-*.mjs`) для чтения табличных портов; обучаемого образца в базе нет.
Видимость для модели: `semantics` — «Разбиение на множества; выполнение по настройкам»; `description` у каждого поля `parameter_schema`, строковые enum и компактный readback с идентичностью источника и результата.
Общие изменения: W3 только после решения владельца, отдельными коммитами с тестами.
Тесты из каталога `packages/loginom-runtime`: `bun run test:upstream`; при изменении приёмки из каталога `scripts/node-acceptance`: `node --test tests/*.test.mjs`.

### Этап 2 — Все методы сэмплинга и seed (отдельная карточка)

Покрытие требований этого этапа:

- `preprocessing-datapartition:r03` — Random, uniform с группами, stratified поля, bias factor/явное количество. Источник: `preprocessing-datapartition:help1`.
- `preprocessing-datapartition:r04` — Seed fixed/always-random/generate/copy и повторное разбиение. Источник: `preprocessing-datapartition:help1`.

Назначается после приёмки зависимого среза; обновить `acceptance/stage2/` до реализации. Режимы/параметры этого этапа проверяются самостоятельным oracle по матрице раздела 3; незакрытые общие изменения — Blocked.

### Общие изменения — только по решению владельца

- **W3** — адресация и независимое чтение нескольких портов одного узла: node-read-*.mjs, node-result-schema.mjs, expected-outputs.mjs и cold-check.mjs; идентичность node_id + port index/kind, одна квитанция исполнения для всех портов.

## 3. Данные и независимые проверки

Комплект `nodes/preprocessing-datapartition/acceptance/` (следующие этапы — `acceptance/stageN/`): `task.md` с `{{PACKAGE_PATH}}`, `data/` только с входами модели, `expected.json` из независимого `oracle.py` до обработчика; oracle и ожидания вне workspace модели.
Формат: UTF-8, заголовок в первой строке, разделитель `,`, десятичный `.`, NULL `?`; пустая строка отличается от NULL. `fixtures/manifest.json` фиксирует типы, порядок, байты, SHA256, формат и версии вычислительных зависимостей.

Данные: rows.csv: RowID (integer)=1..20, Class (string)=A для 1..10 и B для 11..20, Value (integer)=RowID*10. Test=5 из начала, Train=10 из остатка; update.csv: тот же состав, RowID=101..120.

| Набор | Содержание и назначение |
|---|---|
| основной CSV из описания | самостоятельные данные для среза этапа 1; не требует соседнего нового обработчика |
| `empty.csv`, `null.csv`, `invalid.csv` | заголовок без строк; NULL/пустая строка; границы/несовместимые типы и параметры |
| `replace.csv` / `update.csv` | те же имена/типы, заведомо другие значения; переисполнение того же узла |
| `holdout.csv` | для обучаемых: новые RowID вне обучения, применение сохранённой модели без скрытого fit |

Каждое требование сопоставлено независимой проверке; адресные данные создаются по основному правилу с минимальным изменением для указанной границы. Expected и допуски фиксируются до проверяемой попытки.

| Требование | Адресный набор | Независимая проверка и ожидаемый результат | Доказательство |
|---|---|---|---|
| `preprocessing-datapartition:r01` | `stage1-r01.csv` / manifest + oracle | Полные membership трёх выходов, flag consistency и остаток; не требовать общего выхода равным всему входу. | Полный readback, expected и квитанция исполнения; до прогона |
| `preprocessing-datapartition:r02` | `stage1-r02.csv` / manifest + oracle | Заданные RowID в начале/конце и точный порядок; все строки учтены без ложной потери. | Полный readback, expected и квитанция исполнения; до прогона |
| `preprocessing-datapartition:r03` | `stage2-r03.csv` / manifest + oracle | Матрица пяти методов, неодинаковые классы и несколько strata; проверить кратности и разбиение. | Полный readback, expected и квитанция исполнения; до прогона |
| `preprocessing-datapartition:r04` | `stage2-r04.csv` / manifest + oracle | Одинаковые входы/seed дают одинаковые множества; настройки сохраняются после reopen. | Полный readback, expected и квитанция исполнения; до прогона |

Независимый oracle не импортирует runtime/handler и не использует фактический результат текущего прогона как expected. Проверяет все ячейки, схему, типы, порядок полей и происхождение; IDs/строки/Boolean/NULL точны. Отрицательные подмены одного значения, типа, связи, источника и модели обязаны нарушить проверку.

RowID=1..20. Приоритет test в начале с 5 строками закрепляет test=[1..5]; train 10 выбирается только из остатка. Общий выход содержит 15 строк, test flag true ровно 5, train/test не пересекаются. Наборы для последующего ML допустимо подавать готовыми файлами.

Cold-check базы: до 100 строк/выход и 32 ожидаемых выхода (`expected-outputs.mjs:8,14`), поля позиционно, строки без учёта порядка (`:29-39`); порядок проверяет отдельный ordered oracle. Числа сравниваются точно (`cold-check.mjs:232`, `expected-outputs.mjs:70`): W2 нужен для заранее объявленных допусков, где результат не представим точно.
`matchExpectedOutputs` (`expected-outputs.mjs:72-81`) сопоставляет type/label и уникальный node_id без индекса порта: outputs[] не принимает несколько портов одного узла. Полная приёмка нескольких табличных портов требует W3; для переменных — W4. До их реализации не объявлять такие результаты PASS.

## 4. Проверки, приёмка и завершение

Адресная матрица; непроведённые проверки — `not_checked`:

| Проверка | Условие успеха |
|---|---|
| Контракт/режимы | Все требования назначенного этапа проверены, неподдержанные настройки отклонены до мутации с причиной |
| Полные выходы | Каждая ячейка и все порты из одного свежего исполнения, схема/метки/типы и требуемый порядок совпали |
| NULL/границы | Пустой/ошибочный вход даёт заранее наблюдённый результат/отказ, NULL не заменён нулём |
| Изменение существующего | Readback сохранил незапрошенные настройки, режимы и связи; без подмены другим узлом |
| Lifecycle/источник | Execute/configure/read без искусственного обучения; для обычных статистических преобразований train не вводить. После смены данных проверены новый source identity и полный результат |
| Недетерминированность | Seed/повторяемость и объявленные допуски проверены без подгонки после FAIL |
| Persistence | Сохранение после всех чтений; cold reopen и выполнение, модель/настройки не восстанавливаются вручную |
| Recovery | Неизвестный эффект не повторён, причина отказа прочитана, собственный пакет/аккаунт закрыт |
| Регрессия | Адресные тесты и весь `client/test`; тесты изменённых общих контрактов и приёмки |

Задание модели: Разделите rows.csv на обучающую и тестовую выборки последовательным отбором с приоритетом тестовой части из начала. Покажите обе выборки и общий результат с признаком тестовых строк. Замените данные, повторно выполните тот же узел и сохраните пакет в {{PACKAGE_PATH}}.

PASS исполнителя: CLI, независимый cold-check после нового открытия, адресная матрица и oracle; `package_closed=true`, `logged_out=true`. Публикация чистого SHA и независимая приёмка той же головы — по RUNBOOK. Discovery/исторический PASS/skip не заменяют реализацию; `integration`/`release` не повышаются.

## 5. Ловушки — переподтвердить, не копировать

- Отказы пустого входа, неподдержанного типа и границ выяснить в этапе 0; не подменять их timeout или молчаливым изменением режима.
- Для обучаемых узлов обучение/применение/выполнение и идентичности источника/модели разделены; старые данные или модель не принимаются как свежие.
- Схема CrossTable sliding разрешена только его режиму: право менять схему автоматически другим узлам не переносится.
- E2E-снимки preview и `:toreview` не являются численным oracle; LGD-тесты адаптируются на самостоятельный CSV.
- Указанные элементы мастера и предлагаемая схема параметров не наблюдались на стенде; значения и ошибки закрепить до кода.
