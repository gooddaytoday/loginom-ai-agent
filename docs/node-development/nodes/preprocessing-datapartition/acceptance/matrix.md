Предлагаемая матрица последовательного режима; утверждение владельца перед
этапом 1. `oracle.py --case CASE` строит независимые expected-файлы.

| CASE | Вход | test / train | Ожидаемые порты 0 / 1 / 2 |
|---|---|---|---|
| rows | RowID 1..20 | 5 / 10 | 6..15 + 1..5 / 6..15 / 1..5 |
| update | RowID 101..120, Value +1000 | 5 / 10 | 106..115 + 101..105 / 106..115 / 101..105 |
| null | 3 строки, пять явных типов, пустая строка и NULL | 1 / 2 | 2,3,1 / 2,3 / 1 |
| empty | заголовок5 полей без данных | 0 / 0 | 0 / 0 / 0 строк с сохранением схем |

Порядок выделения test → train → unused; общий выход в исследованном порядке — train + test.
Его первое поле — Boolean IsTestSet («Тестовое множество»), затем исходные
поля. Порты 1 и 2 имеют только исходные поля в прежнем порядке. NULL и false
различны; точные типы и значения, ordered=true, output_port=0/1/2, допуск 0.
Сумма размеров не превышает объём входа. Приоритет test из других методов,
seed, проценты и недетерминированные режимы в этот контракт не включаются.

Живое native discovery подтвердило только rows. Null/empty — NOT_CHECKED
после потерь связи; update — NOT_RUN. Ожидания не являются результатом приёмки.
