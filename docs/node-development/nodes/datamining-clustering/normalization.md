# Стандартизация признаков (LAB-717)

Наблюдение 01.11.2026, Loginom 7.4.2, Chromium 1246, mas3, назначенная пара
LAB-68. Собственная копия `lab717-normalization-discovery.lgp`; исходный пакет
не изменён. Секреты и сырые DOM/значения хранятся вне Git.

## Нативные настройки

После настройки ролей мастер открывает `WizrdMCF;NormTuneWizard`.
Каждое используемое числовое поле имеет собственный нормализатор.
Выбор строки `NormTuneWizard;colDisplayName_<имя>` и `btnEdit` открывает
`WizrdMCF;ColumnsEditForm`; выбор метода — `cbxNormType;trg_picker` и
`cbxNormType;boundlist;<метод>`, подтверждение — `btnApply`.

Предлагаются «Нет», «Масштабирование [-1;1]», «Масштабирование [0;1]»,
«Абсолютное масштабирование», «Стандартизация». Штатное умолчание нового
используемого поля — стандартизация; native `NormType=5`, «Нет» — 0.
В этом срезе добавлена только `normalization:"standardize"`. API нового узла
по-прежнему выбирает `none` по умолчанию. На существующем узле пропуск сохраняет
одинаковый поддерживаемый метод у полей; смешанный или другой метод требует
явного выбора. Множители и неудаляемость не изменяются.

Для стандартизации `NormSettingsForm;lblEmptyNormParams` показывает
«Для данного типа нормализации настройки отсутствуют». Контроль диапазона
и ручной диапазон в этот срез не входят.

## Числа и сохранение

На симметричных 12 точках с отношением масштабов Y/X=1000 наблюдены группы
у трёх углов. Расстояние каждой точки примерно 0.0143605988553771 совпадает
с евклидовой нормой после деления каждого признака на выборочное SD (`n−1`).
Центры порта 1 имеют исходный масштаб: (0,20000), (20,0), (0,0), с погрешностью
около 1e-12. Порт 0 сохраняет исходные X/Y/ID, а Distance — нормализованный.

Save → Close → Open подтвердил `NormType=5` у обоих полей без повторного
применения. Живая приёмка дополнительно читает сохранённые роли, нормировку,
число кластеров и seed и отменяет мастер без сохранения настроек.

Константный Hours=7 принят штатной активацией и обучением вместе с переменным
Materials. Порт центров сохранил Hours=7 во всех трёх строках; деления на ноль
и отказа обучения не наблюдено.

NULL проверен отдельно: маркер `NULL` выбран точным пунктом
`ImportTextFileParamsWizard;edtValueNull;ValueControl;boundlist;NULL`;
свежий порт импорта подтвердил `Materials=null` в первой строке. Активация
нормализации завершилась `source_status:"Ошибка"`, прочитанным по
`NormTuneWizard;txtActivationPortStatus`. Обработчик ждёт терминальное
состояние активации и при отказе возвращает `NODE_APPLY_STOPPED` с объяснением
о пропущенных/некорректных признаках до Train/Execute. Подстановка значений
и включение разрешения пропусков не выполняются.

## Независимый критерий

Инициализация и PRNG Loginom не раскрыты в наблюдаемом мастере; соответствие
независимого k-means тому же начальному состоянию не установлено. Выбран
разрешённый карточкой критерий инвариантов, без эмуляции неизвестного PRNG:
повторное исполнение на одном seed и узле; три непустые группы; каждая исходная
строка ровно один раз; центр равен среднему назначенных строк в исходных единицах
(abs 1e-6); ожидаемое геометрическое разбиение и отличие от raw.
Номера кластеров свободны, но связаны между портами.

`acceptance/normalized/oracle.py`, CSV и `expected.json` зафиксированы коммитом
`381ee52079` до реализации. Oracle использует только CSV, средние и выборочное
SD; ожидаемые значения, исходные группы и центры не считываются из результата.
Stock matcher проверяет весь CSV и cold; отдельная проверка инвариантов связывает
порты, повторные исполнения и нативный readback настройки.
