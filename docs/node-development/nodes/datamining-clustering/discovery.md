## Наблюдено

### Компонент и мастер

- Иконка native-узла: `bg-vendor-icon-clusterization`.
- Один табличный вход (0), два табличных выхода (0 и 1).
- Мастер: `WizrdMCF`; страница параметров: **Кластеризация**,
  корень `ClusterizationWizard`.
- На использованном входе страницы шли в порядке: настройка входных столбцов
  (`TuneDataSourceInputPortWizard`), нормализация (`NormTuneWizard`),
  кластеризация (`ClusterizationWizard`), описание (`DoneWizard`).
  Между жестом Next и готовностью следующей страницы есть асинхронная загрузка.
- Исходное имя «Кластеризация» после сохранения настроек автоматически стало
  «Кластериз.: X, Y». Нельзя адресовать сохранённый узел по прежнему имени.

Предлагаемый runtime type: **`datamining.clustering`**, mode **`k_means`**.
`component.dataMining.Clustering` — идентификатор из подплана/реестра;
native fulltype отдельно пока не считан. Идентичность живого компонента
подтверждена палитрой, иконкой, корнем мастера и схемами обоих выходов.
Сопоставление полного native типа остаётся проверкой перед регистрацией.

### Роли и нормализация

Вход: RowID integer, X/Y real, все три поля непрерывные. При первом открытии
у всех назначение «Не задано». Для сценария выставлены X/Y **«Используемое»**,
RowID оставлен **«Не задано»**. Редактор назначения предлагает именно эти
два варианта. RowID при этом сохраняется в первом выходе.

Наблюдённый отказ при отсутствии используемых полей: кнопка `btnError`,
подсказка **«Не указаны столбцы для обработки»**. Это не ошибка диапазона k.

После назначения X/Y их нормализатор по умолчанию — **«Стандартизация»**.
Для этапа 1 нужно явно выбрать **«Нет»** у обоих. Кнопка «Редактировать»
открывает `ColumnsEditForm`; список нормализаторов: Нет, масштабирование
[-1;1], масштабирование [0;1], абсолютное масштабирование, стандартизация.
Остальные режимы не проверялись. Вход активирован штатной кнопкой страницы.

### Обучение и результаты

Контекстное меню содержит отдельное действие **«Обучить узел»**, а также
«Выполнить узел». Обучение запущено штатным пунктом меню. Обе таблицы
прочитаны существующими runtime-процедурами нового табличного визуализатора,
с подтверждённой числовой точностью и без фильтрации.

| Выход | Порядок технических имён / типов / меток |
|---|---|
| 0, назначения после Execute (12 строк) | `Cluster` integer «Номер кластера»; `Distance` real «Расстояние до центра кластера»; `X` real; `Y` real; `RowID` integer |
| 1, центры (3 строки) | `Cluster` integer «Номер кластера»; `X` real; `Y` real |

Метки RowID/X/Y совпадают с именами. На этих данных нумерация начинается с 0:
центр (0,20) → 0, (20,0) → 1, (0,0) → 2. Точки каждой группы получили
одинаковый Cluster; расстояние — евклидово в исходном пространстве:
√(0.1²+0.1²). Фактические значения около 0.14142135623730953 и
0.14142135623731053 укладываются в заранее выбранный `abs=1e-8`.

После повторного действия обучения и нового чтения первого выхода все
12 строк совпали, включая номера кластеров. Это наблюдение для данных,
версии и seed из данного комплекта, не гарантия нумерации для любых входов.
Схема до первого обучения отдельно не проверялась. После Train первый
выход первоначально имел порядок `Cluster, Distance, RowID, X, Y`.
Первый cold Execute выдал `Cluster, Distance, X, Y, RowID`, при тех же
значениях и номерах кластеров; позиционный matcher закономерно дал
`COLD_OUTPUT_NOT_UNIQUELY_MATCHED`. Пакет закрыт, logout подтверждён.
Для следующей попытки создан новый пакет и профиль; перед ней expected
закрепляет наблюдённую схему Execute. Это исправление спецификации схемы,
не подгонка численных ожиданий. Порядок полей после Train нельзя принимать
за окончательную схему Execute.

Пакет сохранён после чтений; штатное закрытие подтвердило
`package_closed=true`, `logged_out=true`, без отброса изменений.
Повторный native cold-check **PASS** (17.10.2026, 18:20 UTC): новый профиль,
новый путь пакета (копия собственного успешно сохранённого native-сценария),
обычный Execute и чтение обоих портов одного исполнения; настройки не
применялись заново, закрытие пакета и logout подтверждены. Файл результата
и полный readback приложены к карточке. Это не модельная приёмка и не 2/3.

Между холодными проверками попытка нового импорта остановилась на configure
с `UI_SCAN_LIMIT`, AMBIGUOUS. Её собственный черновик закрыт штатно,
несохранённые изменения отброшены, `package_closed=true`, `logged_out=true`.
Сеанс не восстанавливался; копия native-сценария и cold использовали новые
пути и профили. Продуктовый код под этот отказ не менялся.

## Независимые ожидания и воспроизведение

`acceptance/data/points.csv`: 12 собственных точек вокруг (0,0), (20,0),
(0,20), по четыре симметричных смещения. `fixtures/manifest.json` фиксирует
байты, SHA256, формат и типы. Модели передаются только `task.md` и `data/`.

`oracle.py` не читает результаты, не импортирует runtime и не повторяет PRNG
Loginom. Он назначает точки трём заранее заданным удалённым областям,
считает средние через Decimal и расстояния через Евклидову норму. Номера
областей закрепляют наблюдённую seed-42 конвенцию. Численные значения и
входы не берутся из readback. `expected.json` сформирован до cold/model;
поля real используют существующий `tolerance`, integer сравниваются точно.

```sh
python3 acceptance/oracle.py > acceptance/expected.json
python3 acceptance/oracle.py --package-path /my-account/new-package.lgp
```

Вторую команду выполнять с новым личным путём. Для cold-check подставить
тот же `{{PACKAGE_PATH}}` в копии expected вне каталога задания модели.
Ожидается один импорт, один целевой узел и два экспорта, выходы целевого
узла 0 и 1. Порядок строк не является критерием; схема колонок позиционна.

Для native discovery использована отдельная локальная копия expected:
runtime type заменён на наблюдённую иконку, список узлов содержит импорт
и native-кластеризацию без экспортов. Такая проверка не означает PASS
будущего обработчика или бизнес-сценария модели.

## Предложение общих работ W

- **W1 — нужен контракт обучения.** Наблюдён отдельный native пункт
  «Обучить узел». Предлагается минимальное штатное действие обучения,
  доступное узловой процедуре, с чтением состояния и понятным модели текстом.
  Автоматическое скрытое переобучение не обещать. Изменять общие файлы должен W.
- **W2 — уже есть.** `expected-outputs.mjs` принимает `tolerance` для real;
  новый механизм не нужен. На обоих native выходах existing matcher совпал
  с oracle; подмены чисел/типов/меток отвергнуты.
- **W3 — формат уже есть.** `output_port` адресует оба порта одного узла;
  matcher различает пару node_id/port. Общий код этой карточкой не меняется.
  Поддержку cold-исполнения фиксирует отдельный native cold-прогон.

Нельзя выдавать обучаемый runtime type модели, пока W1 и узловой обработчик
не поддерживают наблюдённый путь. Требуется решение владельца по объёму W1
перед этапом 1. Нумерация кластеров проверяется точной seed-42 конвенцией;
новый механизм нормализации/перестановок кластеров не предлагается.

## Гипотезы и not_checked

Применение модели к holdout без fit, замена исходного файла, инвалидация
модели, NULL/пустой/постоянный/строковый вход, g-means, остальные нормировки
и полная матрица границ остаются `not_checked` и относятся к дальнейшим
срезам. Независимый cold-прогон подтвердил повторное выполнение сохранённого
пакета на том же обучающем входе, но не доказывает отсутствие скрытого retrain
при обычном Execute. Применение модели к независимому holdout не проверено.
`ready_for_development` полного подплана и готовность продукта не заявляются.
