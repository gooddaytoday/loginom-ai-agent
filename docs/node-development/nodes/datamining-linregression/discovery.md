## Наблюдено: обучение, применение и сохранение

Импорт собственного публичного CSV по HTTPS URL с GitHub работает с сервера
Loginom. Для опыта использованы только синтетические fixtures этой ветки.
Заголовок, запятая, десятичная точка и `?` заданы в мастере импорта;
X/Y явно приведены к вещественному непрерывному типу.
Ожидаемые коэффициенты независимо вычислены `oracle.py` **до чтения результата**.

1. Существующий импорт → регрессия, X — фактор, Y — цель; Enter,
   константа, без нормализации/регуляризации, 100% обучения.
   «Выполнить» на последней странице первоначального мастера обучило узел:
   прогнозы `-1, 1, 3, 5, 7, 9`, коэффициенты 3 и 2.
2. Через настройку **того же импорта** файл заменён на `holdout.csv`.
   Readback подтвердил новый URL и строки 7/8, X=4/5, Y отсутствует, IsTest=true.
   Затем выполнена обычная активация **того же узла**: прогнозы 11/13,
   коэффициенты 3/2, счётчики обучения остались 6/6/6.
3. Выход коэффициентов штатно сокращён до `Name`, `Y_coefficients`.
   Сохранён собственный пакет `/lab85-worker-01a14aa4/lab85-discovery2.lgp`;
   runtime подтвердил `package_closed=true`, `logged_out=true`, без discard.
4. Пакет открыт в **новом профиле**, до Execute UI сообщает «Узел не активирован».
   После обычного Execute, без настройки/обучения, снова получены 11/13,
   коэффициенты 3/2 и прежние счётчики. Это native-опыт сохранённой модели,
   а не результат `cold-check.mjs` или модельной приёмки.
5. После этих чтений команда «Обучить узел» на holdout с пустой целью дала
   ожидаемый явный отказ: `Пропущенные значения запрещены (пропущенное значение в колонке "Y")`.
   Прочитано штатное сообщение ошибки; несохранённое состояние этого опыта
   отброшено при подтверждённом закрытии пакета и выходе.

Следствие опыта: отсутствие Y в holdout различает применение и обучение.
После замены источника нельзя автоматически вызывать Teach вместо Execute.
Инвалидация при смене параметров и переобучение на `replace.csv`, повторяемость
random и два независимых обучения одинакового входа **не проверены**.

Технические ограничения наблюдения: первая сессия потеряла stdin, черновик
не сохранён; её процессы завершены, далее новый профиль/пакет. Первая CLI setup
без headless дала `LOGINOM_BROWSER_START_FAILED`; новый headless setup подтвердил
`browser.state=verified`. В одной попытке смены источника мастер сохранил старый
URL — это обнаружено readback, старые строки не приняты за holdout.
Management `status` после setup сообщает `state=starting`, `browser.state=unknown`;
это не заявляется как `status=ready`. Последующий CLI `loginom check`
вернул `ok=true`, `LOGINOM_CONNECTION_VALID`, `help.state=ready`,
`browser.state=verified`. В native подготовке обеих рабочих сессий
получен `READY` на Loginom 7.4.2. Сырые свидетельства и screenshots — во вложении
карточки, в Git не включены.

Опечатка `rergession` принадлежит наблюдаемой схеме Loginom, её не исправлять

`RowID, IsTest, X, Y`. Не выводить контракт холодной схемы из этого preview.
Типы пяти полей подтверждены CSS-иконками Float/Integer/Boolean заголовков.
UI пустую Y отображает пустой ячейкой; точный native NULL ещё требует cold-reader.

Выход 1 по умолчанию: `Name`, `DisplayName`, `UniqueValues`, `Y_coefficients`,
`Y_stdError`, `Y_TStat`, `Y_PValue`, `Y_lowerBound`, `Y_upperBound`.
Для этапа 1 наблюдено штатное исключение всех полей, кроме двух:

| Имя | Метка | Тип | Значения |
|---|---|---|---|
| `Name` | Имена входных полей | string | `<Константа>`, `X` |
| `Y_coefficients` | `Y\|Коэффициенты` | real | 3, 2 |

Типы подтверждены диалогом редактирования столбца. На идеальной линии
T-статистики UI показывают ∞; не проверять их нулём/NULL. Полная статистика
отнесена к этапу 4 с отдельным `noisy.csv`, а не к приёмке базового Enter.

Нужные бизнесу переменные выхода 2; имена, метки и Integer-иконки наблюдены
после первоначального обучения и после применения/холодного открытия:

| Имя | Метка | Значение |
|---|---|---:|
| `TotalSamples` | Всего примеров | 6 |
| `TotalSelectedSamples` | Всего отобранных примеров | 6 |
| `TrainSamples` | Примеров в обучающем множестве | 6 |
| `DFE` | Число степеней свободы ошибки | 4 |
| `ModelDF` | Число степеней свободы модели | 1 |

`oracle.py` решает OLS с константой рациональной арифметикой Fraction,
не импортирует Loginom и не читает наблюдения. Для `replace.csv` закон
`7 - 3X`, прогнозы -5/-8; для noisy — независимые RSS/DF/R².
Для прогнозов и коэффициентов заранее объявлены `tolerance.abs=1e-8`,
`rel=1e-10`; IDs, типы, метки, Boolean и NULL сравниваются точно.
