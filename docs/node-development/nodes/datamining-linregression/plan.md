### Стоп-условия

Стоп — `blocked` с одним вопросом владельцу (правила сквада), только если:

- в палитре нет «Линейная регрессия» либо native component/fulltype не совпал;
- нет решения владельца по W1/W2/W3/W4, если изменение нужно назначенному этапу;
- недоступны полные результаты или независимый oracle; это не PASS;
- нужен режим или критерий сверх назначенного этапа;
- сработал бюджет сквада: 2 цикла без прогона бизнес-сценария или больше 400 строк вне файлов узла.

Не стоп: неудачный или неизвестный прогон в тестовом пакете — перезапуск в новом пакете и профиле; дефект кода, в том числе общего, — исправить в ветке карточки минимальной правкой под наблюдённый отказ; недостающие файлы, CLI или аккаунты готовит Генератор.

## 2. Этапы

### Этап 0 — подготовка, живое исследование, контракт

Подготовка: проверить checkout/SHA, собрать кандидата из закоммиченных исходников, получить `loginom status = ready`. UI только штатными средствами runtime с `?testable=true`; каждый отказ мастера прочитать из его кнопки ошибки.

1. Палитра «Линейная регрессия», точный заголовок и корень мастера, native component/fulltype, входы/выходы и их виды, все страницы.
2. Роли цели/предикторов и переменных, denormalize и опорные коэффициенты; Enter/Forward/Backward/Stepwise/Ridge/LASSO/Elastic-Net и реальные bindings L1/L2.
3. Умолчания и границы каждого элемента мастера этапов 1+; зависимые/disabled настройки, NULL/пустая строка, пустой вход, неподдержанный тип.
4. Имена, метки, типы и порядок всех выходных полей; момент появления схемы до/после Execute или обучения; все порты одного исполнения.
5. Явное обучение/переобучение, применение на независимом holdout без скрытого retrain, сохранение модели; смена источника/параметров инвалидирует модель по наблюдённому правилу.
6. Тот же узел после замены файла существующего импорта: свежие значения и схема, необходимые явные retrain; не пересоздавать узел для обхода.
7. Фиксированный seed (если элемент seed доступен) и два повторных расчёта/обучения на одинаковом входе; при недетерминированности заранее закрепить проверяемые инварианты и допуски. Для random/uniform воспроизводимость состава проверяется в рамках гарантий Help, без копирования чужого PRNG.
8. Ожидаемые отказы из раздела 5.

Независимый oracle не импортирует runtime/handler и не использует фактический результат текущего прогона как expected. Проверяет все ячейки, схему, типы и порядок полей; IDs/строки/Boolean/NULL точны. Отрицательные подмены одного значения, типа, связи, источника и модели обязаны нарушить проверку.

Основной train: X=[-2,-1,0,1,2,3], Y=2X+3; Enter, без нормировки/регуляризации, константа включена. Ожидаемые beta=(3,2), holdout X=4 даёт 11, atol=1e-8. Для статистик использовать отдельные 20 строк с заданными остатками и полноранговой матрицей: идеальная линия не подходит для проверки конечных t/p. Независимый QR/SVD даёт beta, covariance и интервалы; степеням свободы и вариантам normalization соответствует отдельный oracle. Категории/опорные коэффициенты проверять прогнозами и матрицей контрастов, а не голым размером таблицы.

Cold-check базы: до 100 строк/выход и 32 ожидаемых выхода (`expected-outputs.mjs:8,14`), поля позиционно, строки без учёта порядка (`:29-39`); порядок проверяет отдельный ordered oracle. Числа сравниваются точно (`cold-check.mjs:232`, `expected-outputs.mjs:70`): W2 нужен для заранее объявленных допусков, где результат не представим точно.
`matchExpectedOutputs` (`expected-outputs.mjs:72-81`) сопоставляет type/label и уникальный node_id без индекса порта: outputs[] не принимает несколько портов одного узла. Полная приёмка нескольких табличных портов требует W3; для переменных — W4. До их реализации не объявлять такие результаты PASS.

Свежесть результата обеспечивает сам cold-check: он заново выполняет узлы сохранённого пакета в новом профиле. Отдельные доказательства происхождения, квитанции и receipts не требуются. Порядок строк, несколько портов одного узла, допуск для вещественных и выход переменных в cold-check добавляет общая карточка LAB-78 (ветка `acceptance-tools`); в ветке узла эти возможности не реализуются.

## 4. Проверки, приёмка и завершение

Адресная матрица; непроведённые проверки — `not_checked`:

| Проверка | Условие успеха |
|---|---|
| Контракт/режимы | Все требования назначенного этапа проверены, неподдержанные настройки отклонены до мутации с причиной |
| Полные выходы | Каждая ячейка и все порты из одного свежего исполнения, схема/метки/типы и требуемый порядок совпали |
| NULL/границы | Пустой/ошибочный вход даёт заранее наблюдённый результат/отказ, NULL не заменён нулём |
| Изменение существующего | Readback сохранил незапрошенные настройки, режимы и связи; без подмены другим узлом |
| Lifecycle/источник | Явное обучение/переобучение, применение на независимом holdout без скрытого retrain, сохранение модели; смена источника/параметров инвалидирует модель по наблюдённому правилу. После смены данных проверены новый source identity и полный результат |
| Недетерминированность | Seed/повторяемость и объявленные допуски проверены без подгонки после FAIL |
| Persistence | Сохранение после всех чтений; cold reopen и выполнение, модель/настройки не восстанавливаются вручную |
| Recovery | Неизвестный эффект не повторён, причина отказа прочитана, собственный пакет/аккаунт закрыт |
| Регрессия | Адресные тесты и весь `client/test`; тесты изменённых общих контрактов и приёмки |

Задание модели этапа 1 — только актуальный `acceptance/task.md`: прогноз на train, коэффициенты с константой, выгрузка и сохранение. Расширенная матрица жизненного цикла выше относится к этапам 2+.

PASS исполнителя: CLI, независимый cold-check после нового открытия, адресная матрица и oracle; `package_closed=true`, `logged_out=true`. Публикация чистого SHA и независимая приёмка той же головы — по RUNBOOK. Discovery/исторический PASS/skip не заменяют реализацию; `integration`/`release` не повышаются.

## 5. Ловушки — переподтвердить, не копировать

- NULL предиктора, неверный target kind/type, нулевой train size, rank deficiency, недоступное сочетание denormalize/константа. Не считать альтернативный набор collinear coefficients дефектом при эквивалентных прогнозах без заявленной уникальности решения.
- Для обучаемых узлов обучение/применение/выполнение и идентичности источника/модели разделены; старые данные или модель не принимаются как свежие.
- Схема CrossTable sliding разрешена только его режиму: право менять схему автоматически другим узлам не переносится.
- E2E-снимки preview и `:toreview` не являются численным oracle; LGD-тесты адаптируются на самостоятельный CSV.
- Указанные элементы мастера и предлагаемая схема параметров не наблюдались на стенде; значения и ошибки закрепить до кода.
