CLI-сборки и регистрации сценариев. Критерии ниже требуют утверждения владельца.

Для C9/C10: `abs=1e-8`, `rel=1e-10` до прогона. C9: native ε=1e-10; C10: внутренний ε=1e-12 (решение LAB-1288 после native-исследования, ошибка <1e-15). Параметром модели ε не является.
Имена, типы, целые, Boolean, NULL и идентичность портов точны. Метки узлов — label_any.
Порядок прогнозного порта в expected — предложение до cold-проверки, не повод
ослаблять сравнение после отказа. Полная таблица коэффициентов со статистикой
не входит в C9/C10: как у существующего обработчика, оставляются Name и Y_coefficients.
Стандарт после утверждения: tests затронутых путей, ≥2 PASS из 3 у исполнителя
и 2/3 независимых на одном SHA, настоящий CSV, Save/cold без перенастройки,
подтверждённый cleanup. Эта карточка не содержит таких PASS.

`oracle.py` — Python stdlib, рациональное перечисление активных множеств/знаков
и проверка необходимых и достаточных KKT для выпуклой функции. Это независимая
математика, не повтор native решателя. Он читает только авторские CSV;
результаты Loginom не используются как expected. Сопоставление формулы с UI
проверяется отдельно. expected.json содержит точные дроби коэффициентов,
RSS для 14 диагностических случаев и две полные приёмочные таблицы; не является drop-in каталогом run-check.

```sh
python3 docs/node-development/nodes/datamining-linregression/acceptance/penalty/oracle.py --write
python3 docs/node-development/nodes/datamining-linregression/acceptance/penalty/oracle.py --check
node docs/node-development/nodes/datamining-linregression/acceptance/penalty/measure.mjs
```

Оценка C9: один цикл, 100–180 строк handler/адресных тестов (ортогональный комплект);
C10: один цикл, 120–220 строк; C13: отдельный исследовательский цикл до выбора
проверяемого критерия, реализация пока не оценивается как готовая.
Кандидаты: `client/lib/linregression-{parameters,procedure,context,readback,node}.mjs`,
аддитивные режимы/параметры в node-api/node-contracts и справка узла.
Нужен readback pedLassoSetupMethod/λ и явный Teach на каждом изменении.
Общий reader таблиц уже пригоден; новый механизм верификации не предлагается.
Нужда в неаддитивной общей правке — отдельное решение владельца.

Проект [карточки](proposed-card.json) и [размеры](sizes.json) измеряются offline
через те же userNodeTool/describeNodes, что production. Все hash-поля проекта —
64 нуля. Предложение сокращённой справки — отдельный документ, действующий
SKILL.md и справка продукта не меняются. Текущая справка — 5996 Б при лимите 6000 Б,
поэтому простое дописывание новых режимов нарушило бы её лимит.

Измерение на базе: model-visible apply 8051 Б / 20000; текущая карточка с
инструкциями всех методов 10876 Б / 12000; SKILL.md 28823 Б / 40000;
текущий маршрут типа 172 Б, проект маршрута 133 Б. Проект содержит только добавляемые фрагменты новых режимов; действующие
правила не заменяются. Размер полного сочетания с guidance и новой схемой — в sizes.json.
Это оценка предложения, а не обещание размеров после реализации.

Матрица proposal шире выполненных опытов: negative.csv и некоторые сочетания
scaled/duplicated с методом пока не имеют live-подтверждения. Наличие expected
не объявляет их PASS. Основная приёмка C9/C10 использует только shifted.csv;
correlated/scaled/duplicated предназначены для адресных проверок семантики.

На correlated-LASSO при ε=1e-10 уже наблюдена ошибка β≈1.9e-7 относительно
exact oracle, выше abs=1e-8. Поэтому этот адресный случай не принят и не может
быть добавлен в модельную приёмку с обещанием указанной точности. Допуск в
expected не повышен. Уточнение точности на коррелированных данных — отдельная
граница до расширения C9 за ортогональный shifted.csv.

Уменьшение ε до 1e-12 не улучшило correlated-LASSO. Для обещания общего
abs=1e-8 на коррелированных данных нужен отдельный критерий/решение владельца;
текущее предложение C9 такую гарантию не включает. Итерационный алгоритм
Loginom не подменяется точным active-set oracle внутри продукта.

C13 воспроизвёл автоматическую L1 без валидации и 4-fold sequential/seed42
с повторным Teach. Метрика, полная λ-сетка и правило конечного refit остаются
неидентифицированными; в сводке нет loss/истории поиска. Нужен наблюдаемый
контракт платформы либо отдельное утверждение владельцем проверки качества
на внешнем holdout. Выбор произвольного log-grid и MSE не выдаётся за oracle
Loginom. Для C13 нет сгенерированного expected с числами из actual.

`node-reference-proposal.md` содержит только фрагменты новых режимов, а не
готовую замену справки. `measure.mjs` добавляет их к действующему файлу в
изолированном fixture, сохраняя все прежние правила, и измеряет **полный**
результат отдельно от размера фрагментов. Значения находятся в `sizes.json`.
Простое добавление всех трёх проектов превышает бюджет: это не готовый
model-visible файл. В C9 добавляется только LASSO, а сжатие выполняется без
потери старых указаний; действующий файл этапа 1 обязан оставаться ≤6000 Б.
Elastic Net/auto_lambda не переходят в продукт по наличию фрагмента.

Для подключения к будущему штатному сценарию взять `cases[имя].expected`,
заменить только `{{PACKAGE_PATH}}` фактическим путём пакета и использовать

типа узлов с label_any и оба табличных порта; незапрошенные метки колонок
также label_any, имена и типы точны. Граф/CSV/Save/cold/cleanup — стандарт
сквада, отдельной оснастки этот комплект не добавляет.
