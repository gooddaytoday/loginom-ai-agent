# Приёмочный комплект этапа 1

Комплект подготовлен на этапе 0 **до модельных прогонов**, без реализации обработчика.
Рабочий runtime type `datamining.lin_regression` пока является предложением.
Discovery принят владельцем 17.10.2026. Этап 1 проверяет одну просьбу:
прогноз по строкам train, коэффициенты с константой, выгрузка и сохранение.
Живые наблюдения и расширенные сценарии остаются в `../discovery.md` для этапов 2+.

Модели передаются **только `task.md` и `data/train.csv`**.
Подставить новый путь личного пакета вместо `{{PACKAGE_PATH}}`.
Секреты остаются в конфиге роли. Остальные fixtures — операторские входы
для будущих адресных проверок, их не добавлять в основной модельный workspace.

Входы содержат синтетические данные. В этапе 1 используются шесть строк train:
X = -2, -1, 0, 1, 2, 3; Y = 2X + 3; RowID = 1..6.
Holdout, замена источника, переобучение, валидация, сводка и W4 — этапы 2+.
Их входы можно хранить в `data/`, но oracle этапа 1 их не читает.
Формат, типы, порядок, байты и SHA256 — в `../fixtures/manifest.json`.

```sh
python3 oracle.py          # независимые аналитические значения
python3 oracle.py --write  # воспроизвести expected.json этапа 1
python3 oracle.py --check  # проверить неизменность ожиданий относительно входов
```

Oracle использует только стандартную библиотеку Python, OLS с константой
и точную рациональную арифметику. Не читает пакет или результаты Loginom.
Имена/метки схемы закреплены по исследованию; числа получены из входных CSV.
Идентификаторы, Boolean, типы и метки точные; допуск есть только
у прогноза и коэффициента. Порядок колонок строгий; порядок строк несущественен.

`expected.json` имеет действующий формат `cold-check.mjs` для табличных
выходов 0 и 1 **того же узла**. В нём подставляется тот же путь пакета.
Выход 0 содержит прогнозы -1, 1, 3, 5, 7, 9 и соответствующие исходные строки
train; выход 1 — коэффициенты: константа 3, X — 2. Ожидания проверяют
имя фактора и коэффициент; бесконечные статистики идеальной линии не входят в этот срез.
Имена native-полей и порядок схемы задают представление результата, а не
добавляют требования к режимам мастера или способу построения сценария.

`stage2/expected-variables.json` — сохранённое предложение W4 для будущего
этапа, а не часть ожиданий этапа 1 и не действующий формат cold-check.
Выход 2 не требуется просьбой этапа 1; W4 не является условием его PASS.

Сценарий включает импорт → регрессию → экспорт CSV и сохранение. Модель:
`openai/gpt-6.1-sol`, medium, предел 1800 с. На этапе 1 нужны 2/3 PASS
исполнителя и независимые 2/3 Ловца на одном опубликованном SHA,
адресные тесты, полные runtime/client тесты и typecheck затронутых пакетов.
Этап 0 этого результата не заявляет.
