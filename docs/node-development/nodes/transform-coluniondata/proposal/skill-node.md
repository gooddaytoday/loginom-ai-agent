# Соединение таблиц по позиции

Используй `transform.col_union_data`, mode `positional`, для ровно двух таблиц.
Запроси карточку типа через `dock_action_describe`. Вход 0 — главная таблица,
вход 1 — присоединённая. Строки сопоставляются по позиции; порядок входов важен.
Прочитай оба источника перед настройкой. Выход 0 сохраняет поля обоих входов,
в том числе одноимённые. Читай реальные имена; для нужного порядка/переименования
задай полный выходной mapping с `autosync:false`. Не угадывай суффикс коллизии.

`parameters.col_union.row_count`: `minimum`, `maximum` или `input`.
Для `input` обязательно `determining_input:"main"` либо `"attached"`.
`padding`: `null` — пропуски; `repeat` — циклически весь короткий набор;
`last` — последняя запись. Пустой набор нечем повторять: его поля дают NULL.
Существующие NULL сохраняются; пустая строка, 0 и false — отдельные значения.

Новый узел требует оба табличных источника и явные row_count/padding.
У существующего `parameters:{}` сохраняет поддерживаемые настройки.
Проверь компактный readback: режим, правило размера, дополнение, выбранный
вход, две фактические связи и выходной mapping. Execute пересчитывает текущие
входы без обучения. Прочитай все строки выхода 0, затем сохрани пакет.
Переменные, третий вход и режим применения обученной модели пока не поддержаны.

Это предложение этапа 0. В продуктовый skill переносится только после утверждения
критериев и реализации обработчика на этапе 1.
