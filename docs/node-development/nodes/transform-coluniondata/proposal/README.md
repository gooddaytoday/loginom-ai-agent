# Предлагаемый контракт и размеры

`type-card.json` — инертный черновик карточки типа с semantics и description
каждого поля parameter_schema. Он не регистрирует тип в runtime.
`skill-route.txt` и `skill-node.md` — будущая строка маршрутизации и файл
`references/nodes/transform-coluniondata.md`; текущий product skill не менялся.
При реализации нужно завершить discovery и утвердить критерии acceptance.

`parameters.col_union` содержит строковые enum:
row_count = minimum/maximum/input; padding = null/repeat/last;
determining_input = main/attached только для input.
Для нового узла обязательны row_count и padding и оба табличных подключения.
Для существующего omission сохраняет поддерживаемое значение; `{}` ничего
не сбрасывает. Переход с input на minimum/maximum должен очистить неактивный
выбор определителя в компактном readback. Сохранённые переменные/третий вход
и неизвестные режимы отклоняются до мутации; не перезаписывать их молча.

Компактный readback: kind=col_union, mode=positional, node identity,
row_count, padding, determining_input либо null, два логических входа с
фактическим source node/output и native index, output port=0 и его полный
ordered mapping (имя, метка, тип, source, исключение, autosync).
Он отражает прочитанные и подтверждённые UI-настройки; сохранение пакета
подтверждается отдельно. Квитанции/доказательства происхождения не предлагаются.

База `2910b8782c`; JSON — `Buffer.byteLength(JSON.stringify(value))`,

`{...userNodeTool(dock_node_apply),outputSchema:userResultSchema}`.

Предложение tool измерено **симуляцией только аддитивных полей** в памяти:
добавлены type/mode в enum и schema col_union. Это оценка регистрации,
не размер выпущенного обработчика. Карточка содержит пустой session_manifest
и placeholder cache_key; реальные pins/sources ещё добавят байты. Запас
до 12 000 Б большой, но окончательный ответ dock_action_describe измеряется
на этапе 1. Карточка Объединения измерена с пустыми pins тем же способом.

Сжатый tool и основной skill уже превышают лимиты **на базе**.
Согласно LAB-773 это пункт отчёта этапа 0, не самостоятельное стоп-условие.
Общее сокращение schema/skill этим PR не предлагается и не выполняется.

## Изменения сверх регистрации

Нужна **W0 в node-port-open.mjs:162–165**: поддержка фактически наблюдённых
DOM/native индексов нового динамического входа. Точное условие и границы
разрешения описаны в discovery. Это единственная установленная общая правка;
в остальных частях пригодность существующего lifecycle ещё требует проверки.
Предполагается переиспользовать multiple-input lifecycle Объединения и
существующие output mappings/CSV/cold. Нового reader, oracle-механизма,
публичного контракта или изменения packages/agent не требуется по текущим данным.

Оценка этапа 1: **3–4 цикла** с живым бизнес-прогоном между циклами;
сначала W0/два входа, затем настройки/mappings, затем пустые входы/persistence
и устойчивость. Это оценка до завершения discovery, не обещание 2/3 PASS.
