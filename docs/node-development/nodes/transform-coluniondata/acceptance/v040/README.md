решения владельца; существующий комплект двух входов не изменён.

| Задание | Fixtures | Expected | Смысл |
|---|---|---|---|

| task-third-determining.md | те же | expected-third.json | длина третьего входа, 1 строка |

CSV находятся в fixtures/. Oracle использует только Python csv/json,
соединяет записи по исходному индексу; actual/UI не являются его входами.
`python3 -B oracle.py --write` / `--check`. Все 7 полей, каждый тип и значение
проверяются в заданном порядке. Три Code связываются с реальными источниками,
а не с угаданными суффиксами; метки не заданы — label_any.
Другие padding/empty cases остаются в прежнем комплекте двух входов.

Предложение контракта сохраняет positional и добавляет логический вход 2
и determining_input=third. Старые main/attached остаются входами 0/1.
Существующий patch без новых настроек сохраняет три связи и полный mapping.
Новые узлы имеют ровно 2 или 3 явно указанных источника. Несопоставленный,
повторный вход или неизвестный определитель должен быть отвергнут до мутации.

DOM подтвердил Input_Data-0/2/3, три строки определителя и собственную
табличную настройку. Три полные связи, output для длин 3/2/1 и сохранённое
исполнение этой новой матрицы пока не подтверждены; oracle — предложение.
Не переносить PASS двух входов на третий.

Отдельный saved-model apply **не определён**: на странице ColUnionDataWizard
нет такого переключателя; Done имеет «Готово»/«Выполнить». Общая команда
«Обучить узел» существует, а общий диалог активации предлагает контекст,
«Всегда выполнять» и «Всегда переобучать». Их наличие не доказывает ни
отдельную обученную модель, ни невозможность такого режима на платформе.
Контракт apply и критерий его отличия от Execute требуют ответа владельца;
ожидания apply и цикл его реализации не предлагаются.
