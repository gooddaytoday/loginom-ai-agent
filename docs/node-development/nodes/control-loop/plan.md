## 0. Назначение

Стенд — `https://app.loginom.ai/app/?testable=true`; внешняя среда — публичный
`httpbin.org` (сервер Loginom ходит в интернет, LAN-хосты ему недоступны).

## 1. Что говорит справка

Источники: `packages/product/help/loginom-help/data/processors/control/loop.md`,
`execute-node.md`, `supernode.md`.

- **Назначение.** Повторно выполняет выбранный узел, обычно Подмодель. Цикл не содержит
  графа: он **ссылается** на узел и при настройке всегда создаёт производный компонент
  по нему (область видимости «Закрытый», «Производные узлы» выключены). Тело цикла
  строится в отдельной Подмодели того же модуля.
- **Порты.** У нового узла портов нет. После мастера у Цикла порты заключённого узла,
  **кроме выходных портов переменных**.
- **Шаг 1 — выбор узла.** Дерево «Узлы текущего модуля» и «Компоненты» (текущий пакет и
  открытые компоненты внешних), фильтр по имени и комментарию. Запрещены Выполнение узла,
  Узел-ссылка, Условие и Цикл. Флаг «Сохранять конфигурацию выбранного узла» — для
  переобучаемых компонентов, по умолчанию выключен.
- **Шаг 2 — вид цикла.**
  - «Заданные итерации» — число итераций (FOR); все строки входа подаются в каждую итерацию.
  - «Цикл с постусловием» — выход, когда **выходная переменная** заключённого узла
    удовлетворяет отношению со значением (DO…WHILE); параллельность недоступна.
  - «Групповая обработка» (FOR EACH) — фиксированный размер групп, фиксированное число
    групп или уникальные значения полей; выбирается входной порт. Группа из одной строки
    перебирает строки.
  - «Параллельная обработка», «Максимальное количество потоков» (авто = число процессоров).
  - «Добавлять идентификаторы итераций» — поле номера итерации в выходной таблице
    (для разбиения по полям — и значения этих полей).
  - «Игнорировать ошибки».
  - «Переменная цикла» — номер итерации с 0; выбирается **из переменных входных портов
    заключённого узла**.
- **Шаг 3 — сопоставление переменных.** Только для Подмодели с портами переменных:
  выходная переменная итерации → входная следующей итерации.

## 2. Что даёт NW1 и чего не хватает

В этой базе NW1 и `control.supernode` уже есть. Навигация enter/leave сохраняет
ближайший workflow и выдаёт новые scoped refs; native input boundary распознаётся
по роли. `node-target-browser.mjs:149` уже читает variable-порты, а
`node-contracts.mjs:135` запрещает межсценарные variable-связи. Это позволяет
переиспользовать локальный W1 путь после добавления границы; живой runtime-проверки
переменного тела в этой карточке нет.

Не реализованы: создание/редактирование определений входного `Input_Var`,
var-in/table-out в `control.supernode`, FOR и выбор переменной в `control.loop`.
Текущий preflight отклоняет переменное тело, readback и reread принимают только
group_rows/size=1 без идентификаторов. Точные места и необходимые расширения —
[таблица аудита](discovery-for.md#что-уже-есть-в-базе-что-добавить).

Новую навигацию, межсценарные связи или XML-механизм проверки не предлагается
вводить. Требуются сохранённые GUID порта/переменной, сопоставление native index
и логического ordinal, наблюдение локальных variable_links и readback FOR.
Выбор тела по identity и проверка производного компонента уже существуют в этапе 1
и должны сохраниться при расширении. Обычный табличный matcher пригоден для выходов
обоих FOR-сценариев; конфигурацию и расположение тела доказывают отдельные наблюдения.

**Постраничный REST без Цикла.** REST-запрос уже отправляет по запросу на каждую строку
входа (`references/nodes/integration.rest_request.md`, «Каждая строка отправляется
отдельно»). Для известного числа страниц таблица `limit/skip` + REST решает задачу #673
без Цикла. Цикл нужен, когда страниц заранее не знают: постусловие «страница пуста» или
«собрано total». Это этап 3 — после границы переменных Подмодели.

## 3. Принятый срез этапа 1

**Групповая обработка, группы по одной строке**, вместо «фиксированного числа итераций».
Причина: этот вид не требует переменных — каждая итерация получает одну строку
`pages.csv` (Limit, Skip) через табличный вход, и тело остаётся в срезе этапа 1 Подмодели
(одна табличная граница). FOR с переменной цикла требует границы переменных (раздел 2, п. 1)
и переносится в этап 2.

- Тело: Подмодель с одним обязательным табличным входом Page и выходом Answers.
  Основной случай — REST GET `https://httpbin.org/response-headers` с query
  `limit`←Limit, `skip`←Skip; выход Подмодели — порт 0 REST (RequestID, Response).
  Вариант без сети — Калькулятор `LastIndex = Skip + Limit − 1`.
- Цикл: заключённый узел — эта Подмодель; групповая обработка, фиксированный размер 1,
  входной порт — таблица; без параллельности, без идентификаторов итераций, ошибки
  не игнорируются; «Сохранять конфигурацию» выключен.
- Execute Цикла и полное чтение выхода: 3 строки в порядке страниц.
- Save после последнего чтения, cold Execute без восстановления настроек.
- Readback: заключённый узел (ref и подпись), производный компонент, вид цикла, размер
  группы, входной порт, флаги; фактические порты Цикла.
- FOR, постусловие, параллельность, ключевые поля групп, переменные — отказ до мутации.

**Источник страниц.** Сервер Loginom видит интернет, но не LAN-хосты.
Предлагается `https://httpbin.org/response-headers`: эхо query-параметров в теле, ответ
зависит только от `limit` и `skip`, httpbin уже используется с этого стенда (REST LAB-690,
C1/C2). Oracle воспроизводит тело байт в байт; 13.11 с freak три страницы совпали
с oracle полностью (98 байт каждая). Запасные: `postman-echo.com/response-headers`
(компактный JSON, доступ со стенда не проверен) и `dummyjson.com/products?limit=&skip=&select=id`
(настоящая пагинация, как в #673; `total` может меняться — для точного oracle не годится).

## 4. Следующие этапы (отдельные карточки)

### Этап 2: предложение после native-пробы

Первый срез **FOR + ordinary variable input**, последовательное выполнение,
count — положительное целое literal; один вход переменных Подмодели, один выход
таблицы, без табличного входа. Определения Page integer=99 и Limit integer=2
сохраняются во входном порту; Цикл заменяет только выбранную Page на 0…count−1.
Имена/метки порта можно задать явно; native-проба использовала имена по умолчанию,
поэтому их persistence проверяется при реализации, а не объявляется доказанным здесь.

Внутреннее тело: InputNode → «Переменные в таблицу» (columns) → Калькулятор;
та же variable-граница → обычный переменный вход Калькулятора.
`Skip = Var.Page * Var.Limit`, затем сразу OutputNode (offline) либо REST GET
httpbin с query limit←Limit/skip←Skip → OutputNode. Исходное тело выполняется
для получения полной схемы до настройки REST. Число строк/значения и IterationId
доказывают подстановку переменной, не один счётчик выполнения.

**Идентификаторы входят в этот FOR-срез:** false/true с readback; задания требуют
true. Native добавляет последний integer IterationId. Выходы и порядок фиксированы
в `expected-for-*.json`; Save и cold повторяют сохранённый FOR без настройки.
Переменная выбирается по наблюдённому порту и ID определения, с readback имени/типа;
одного текста «Переменные 1.Page» недостаточно для разрешения неоднозначности.
Точный публичный формат параметров, mode и readback — предложение к согласованию,
этот PR их не вводит.

Продолжение этапа 2 — table-in/table-out **fixed group count** и **group keys**.
Проба дала count=2 на трёх строках → IterationId=0,1,1; key=Limit на том же
pages.csv → IterationId=0,0,0 и дополнительный integer Limit_1.
Это две конкретные точки, не универсальный алгоритм распределения/порядка групп.
Для полного принятия ключей нужны отдельные задания с не соседними повторяющимися
значениями, несколькими ключами и конфликтующими выходными именами; до их утверждения
не расширять поддержку на NULL, пустой вход, больше групп, чем строк, или иной порядок.

**Предлагаемые отказы до первой мутации**, после утверждения FOR-среза:

- Чужой/stale document/workflow/ref, тело не Подмодель текущего parent workflow,
  self/cyclic body, запрещённый тип тела; одинаковые подписи без точной identity.
- Несуществующая, неоднозначная или не integer переменная выбранного входного порта;
  NULL-значение в этом срезе; выбор по одной метке вместо native ID.
- Смешанная table+variables граница, дополнительные входы/выходы, control/tree-порт,
  выходные переменные и вложенная Подмодель; отсутствие согласованной полной границы.
- Count не положительный integer literal, variable binding самого count,
  настраиваемые start/step; предел общего бюджета не менять и нового общего лимита не вводить.
- Постусловие/обратное сопоставление, parallel, ignore_errors, save_configuration,
  внешние компоненты; fixed_count/group_keys до отдельного принятого среза.
- Удаление, перестановка или замена связанных портов/определений при сохранённом теле;
  существующая неподдержанная конфигурация не должна молча приводиться к FOR.

Это план проверок runtime preflight, а не утверждение о запретах native Loginom.

## 5. Вопросы native-пробы (первый шаг разработчика)

Только `https://app.loginom.ai/app/?testable=true`, свой пакет пары. Каждый ответ —
наблюдение с `data-tid`; где `data-tid` нет — пробел в отчёт. Шаблоны — по Подмодели,
до пробы гипотеза.

1. Палитра и создание: `…colVendors_Компоненты>Управление>Цикл;TreeText`,
   `mnComponentsContextMenu;mniAddNewNode`, `MF;TF-N;Graph;Цикл;Setting`; корень мастера.
   Иконка Цикла до и после настройки: если она станет иконкой Подмодели, тип по иконке
   (`node-target-browser.mjs`) неоднозначен — нужен другой признак типа.
2. Шаг 1: `data-tid` дерева узлов, корней «Узлы текущего модуля»/«Компоненты», строки
   узла (по подписи или GUID?), фильтра, флага «Сохранять конфигурацию». Видна ли
   Подмодель корневого сценария; скрыты ли запрещённые типы или выдают ошибку?
3. Должен ли вход заключённой Подмодели быть связан? Выполняется ли сама Подмодель
   при Execute Цикла (для Выполнения узла справка говорит «базовый узел не выполняется»)?
4. Шаг 2: радиокнопки вида цикла, список «Вид групповой обработки», поле «Количество
   строк в группе», выбор входного порта, флаги параллельности, идентификаторов, ошибок,
   «Переменная цикла»; `data-tid` каждого и значения по умолчанию.
5. Порты Цикла после мастера: число, порядок, имена (`Цикл;Input_Data-N`, `Output_Data-N`),
   совпадают ли с портами Подмодели.
6. Выход: строки всех итераций подряд в порядке групп? Точное имя и тип поля
   «Идентификатор итерации» при включённом флаге. Пустой вход — 0 итераций без ошибки?
7. REST со стенда: доступен ли `httpbin.org/response-headers` и сохраняется ли Response
   без изменений (отступы, перевод строки в конце)? Если нет — проверить postman-echo.
   Ошибка REST в одной итерации прерывает Цикл; причина из `btnError/@data-qtip`.
8. Изменения тела после настройки: видит ли Цикл новую версию Подмодели (производный
   компонент живой или снимок)? Нужна ли повторная настройка Цикла?
9. Сохранение: fulltype Цикла и ссылка на производный компонент в `Unit_0/Unit.xml`;
   переоткрытие пакета и Execute без перенастройки.
10. Для этапа 2: порт переменных Подмодели появляется в списке «Переменная цикла»?

## 7. Оценка циклов

**Этап 2: всего 4 цикла, включая текущий; до FOR с приёмкой — 3.**

| Цикл | Самостоятельный результат | Проверка |
|---|---|---|
| 1, эта карточка | Native FOR/вход переменных/группы, предложение двух задач и эталонов, аудит пробелов | Native Save/cold обоих FOR; `oracle.py --check`; продукт не меняется |
| 2, первая часть границы | Создание var-in/table-out, integer-определений входа, наблюдаемые GUID; локальные variable_links в NW1 | Отказы до мутации; живое тело с Page=99 → Skip=198; Save/cold определений; регрессия supernode-calc |
| 3, вторая часть границы и FOR | Readback сохранённой переменной/зеркала и её выбора в FOR, счётчик и identifiers; два сценария run-check | Полные typed/CSV; Save/cold без настройки; ≥2/3 и независимо 2/3 на одном SHA; регрессии loop-pages-offline, supernode-calc, rest-get-plain |
| 4 | Fixed group count и group keys с собственным утверждённым комплектом | Не соседние группы/размеры/ключи/суффиксы полей, флаги, Save/cold и приёмка |

Два цикла (2 и 3) затрагивают границу переменных; объединение настройки границы,
identity и FOR в один цикл рискованно. 3 цикла на весь этап возможны только если
срез групп принят и проверяется вместе с FOR; это оптимистичная оценка, не обещание.
Каждый цикл назначается отдельно, без изменений общих контрактов до решения владельца.

### Риски и вопросы владельцу перед реализацией

1. **Утвердить минимальную границу var-in/table-out без табличного входа**,
   integer-определения в Input_Var и начальный маркер Page=99. Native это выполняет;
   прежний публичный контракт требует table-in/table-out. Нужны согласованные
   schema/mode/readback и отражение фактических портов, а не снятие прежних guards.
2. **Подтвердить identifiers в двух FOR-задачах** и полный cold-readback выбранной
   переменной по ID. Native IterationId не равен RequestID; точный текст Response
   включает LF. Расширение `node-read-contract` требует решения как общий контракт.
3. **Утвердить отдельный комплект групп в цикле 4**: границы 1+2 наблюдены только
   для N=3/K=2; Limit_1 — только для одного постоянного ключа и конфликта имени.
   Порядок/NULL/несколько ключей нельзя считать критериями до нового комплекта.
4. **Живой NW1-путь переменной ещё не проверен.** Существующие readers умеют Var-порты,
   но настройка определения и новый readback отсутствуют. Нового механизма проверки
   не предлагается: расширить аудит наблюдений существующего run-check/cold.
5. **Сеть httpbin:** внешний отказ классифицировать отдельно; offline — основной
   диагностический случай. До настройки REST нужна полная схема выполненного тела.

Вопросы — предложения решения для следующей карточки; эта документальная задача
от них не заблокирована, продуктовый контракт и критерии этапа 1 не изменены.

### Историческая оценка этапа 1 (этап 0, LAB-1554)

**5 циклов** собственно Цикла: 1 — native-проба и правка комплекта; 2 — обработчик
(выбор узла по identity, групповая обработка, флаги, readback портов и производного
компонента, отказ неподдержанного до мутации, адресные red→green); 1 — сценарии
`loop-pages-offline` и `loop-pages-rest` в run-check; 1 — Save/cold и наблюдённые отказы.
**Предусловие:** принятый этап 1 Подмодели (NW1 #1078 + обработчик `control.supernode`;
по её README 4 цикла при принятом NW1). Итого путь до PASS — около **9 циклов**.
Этап 2 (FOR + переменная цикла) — ещё **3–4**, из них 2 на границу переменных Подмодели.

## 8. Ловушки

- Цикл ссылается на узел: нельзя «войти в Цикл»; тело правится в Подмодели.
- Выходные переменные заключённого узла не становятся выходами Цикла.
- Нумерация итераций с 0; RequestID REST внутри итерации тоже с 0 — не путать.
- Параллельность недопустима для источника без параллельных запросов; в срезе выключена.
- Постусловие без изменения переменной в теле — бесконечный цикл; в срез не входит.
