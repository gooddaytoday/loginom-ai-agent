## 0. Назначение

Порядок работы, прогоны, бюджеты и стоп-условия — регламент сквада; раздел 0 прежней
редакции не действует. Этап 1 назначается карточкой оркестратора после принятия этапа 1
Подмодели; первый шаг — native-проба по разделу 5 и правка комплекта до прогонов.
Стенд — `https://app.loginom.ai/app/?testable=true`; внешняя среда — публичный
`httpbin.org` (сервер Loginom ходит в интернет, LAN-хосты ему недоступны).

## 1. Что говорит справка

Источники: `packages/product/help/loginom-help/data/processors/control/loop.md`,
`execute-node.md`, `supernode.md`.

- **Назначение.** Повторно выполняет выбранный узел, обычно Подмодель. Цикл не содержит
  графа: он **ссылается** на узел и при настройке всегда создаёт производный компонент
  по нему (область видимости «Закрытый», «Производные узлы» выключены). Тело цикла
  строится в отдельной Подмодели того же модуля.
- **Порты.** У нового узла портов нет. После мастера у Цикла порты заключённого узла,
  **кроме выходных портов переменных**.
- **Шаг 1 — выбор узла.** Дерево «Узлы текущего модуля» и «Компоненты» (текущий пакет и
  открытые компоненты внешних), фильтр по имени и комментарию. Запрещены Выполнение узла,
  Узел-ссылка, Условие и Цикл. Флаг «Сохранять конфигурацию выбранного узла» — для
  переобучаемых компонентов, по умолчанию выключен.
- **Шаг 2 — вид цикла.**
  - «Заданные итерации» — число итераций (FOR); все строки входа подаются в каждую итерацию.
  - «Цикл с постусловием» — выход, когда **выходная переменная** заключённого узла
    удовлетворяет отношению со значением (DO…WHILE); параллельность недоступна.
  - «Групповая обработка» (FOR EACH) — фиксированный размер групп, фиксированное число
    групп или уникальные значения полей; выбирается входной порт. Группа из одной строки
    перебирает строки.
  - «Параллельная обработка», «Максимальное количество потоков» (авто = число процессоров).
  - «Добавлять идентификаторы итераций» — поле номера итерации в выходной таблице
    (для разбиения по полям — и значения этих полей).
  - «Игнорировать ошибки».
  - «Переменная цикла» — номер итерации с 0; выбирается **из переменных входных портов
    заключённого узла**.
- **Шаг 3 — сопоставление переменных.** Только для Подмодели с портами переменных:
  выходная переменная итерации → входная следующей итерации.

## 2. Что даёт NW1 и чего не хватает

NW1 — навигация во вложенный граф, PR #1078 (`nested-workflow`, на ревью, SHA `764a9cba`):
вход в Подмодель и выход к родителю, свежий workflow ID, refs по ближайшему workflow,
роли граничных узлов. Сам Цикл в граф не входит; NW1 нужен, чтобы **построить тело** —
Подмодель с узлами внутри. Регистрации `control.supernode` в #1078 нет; её даёт этап 1
Подмодели (комплект #1071, 6 циклов или 4 при принятом NW1).

Чего не хватает (код `v040@56be59c804`):

1. **Граница переменных Подмодели.** Ориентир карточки «фиксированное число итераций,
   тело — Подмодель с REST по skip» требует, чтобы номер итерации попал в тело. Справка:
   переменная цикла выбирается только из переменных входных портов заключённого узла.
   Этап 1 Подмодели прямо исключает порты переменных (`control-supernode/acceptance/README.md`,
   «Срез для утверждения»), NW1 их не добавляет. Значит, FOR + переменная цикла требует
   отдельной доработки Подмодели: вход переменных, связь внутреннего узла с граничным
   узлом переменных (`node-contracts.mjs:116-125` проверяет связи только внутри одного
   workflow — внутренняя связь локальна, это допустимо) и readback.
2. **Выбор заключённого узла по identity.** Дерево шага 1 адресует узлы подписью;
   нужен выбор по node ref (тот же document и workflow, что у Цикла) и readback выбранного
   узла и созданного производного компонента. Одинаковые подписи узлов не должны
   подменять identity.
3. **Порты, которые появляются после мастера.** Тип с фиксированными числами портов
   (`node-contracts.mjs:8-58`) не описывает «порты как у заключённого узла»; нужен readback
   фактических портов Цикла.
4. **Накопление результата.** Справка не говорит прямо, что выход — объединение строк
   всех итераций; на это указывает только описание поля номера итерации. Проверка пробой.
5. **Приёмка.** Stock `expected-outputs.mjs` читает табличный выход `control.loop` порт 0
   без нового механизма; число итераций доказывается данными (по строке на итерацию).

**Постраничный REST без Цикла.** REST-запрос уже отправляет по запросу на каждую строку
входа (`references/nodes/integration.rest_request.md`, «Каждая строка отправляется
отдельно»). Для известного числа страниц таблица `limit/skip` + REST решает задачу #673
без Цикла. Цикл нужен, когда страниц заранее не знают: постусловие «страница пуста» или
«собрано total». Это этап 3 — после границы переменных Подмодели.

## 3. Срез этапа 1 — предложение

**Групповая обработка, группы по одной строке**, вместо «фиксированного числа итераций».
Причина: этот вид не требует переменных — каждая итерация получает одну строку
`pages.csv` (Limit, Skip) через табличный вход, и тело остаётся в срезе этапа 1 Подмодели
(одна табличная граница). FOR с переменной цикла требует границы переменных (раздел 2, п. 1)
и переносится в этап 2.

- Тело: Подмодель с одним обязательным табличным входом Page и выходом Answers.
  Основной случай — REST GET `https://httpbin.org/response-headers` с query
  `limit`←Limit, `skip`←Skip; выход Подмодели — порт 0 REST (RequestID, Response).
  Вариант без сети — Калькулятор `LastIndex = Skip + Limit − 1`.
- Цикл: заключённый узел — эта Подмодель; групповая обработка, фиксированный размер 1,
  входной порт — таблица; без параллельности, без идентификаторов итераций, ошибки
  не игнорируются; «Сохранять конфигурацию» выключен.
- Execute Цикла и полное чтение выхода: 3 строки в порядке страниц.
- Save после последнего чтения, cold Execute без восстановления настроек.
- Readback: заключённый узел (ref и подпись), производный компонент, вид цикла, размер
  группы, входной порт, флаги; фактические порты Цикла.
- FOR, постусловие, параллельность, ключевые поля групп, переменные — отказ до мутации.

**Источник страниц.** Сервер Loginom видит интернет, но не LAN-хосты.
Предлагается `https://httpbin.org/response-headers`: эхо query-параметров в теле, ответ
зависит только от `limit` и `skip`, httpbin уже используется с этого стенда (REST LAB-690,
C1/C2). Oracle воспроизводит тело байт в байт; 13.11 с freak три страницы совпали
с oracle полностью (98 байт каждая). Запасные: `postman-echo.com/response-headers`
(компактный JSON, доступ со стенда не проверен) и `dummyjson.com/products?limit=&skip=&select=id`
(настоящая пагинация, как в #673; `total` может меняться — для точного oracle не годится).

## 4. Следующие этапы (отдельные карточки)

- **Этап 2.** Фиксированное число итераций; переменная цикла во входе переменных Подмодели,
  тело считает `Skip = Page × Limit` и делает REST — нужна граница переменных Подмодели.
  Идентификаторы итераций; фиксированное число групп; ключевые поля групп.
- **Этап 3.** Постусловие по выходной переменной тела и сопоставление переменных шага 3:
  постраничная загрузка до пустой страницы (dummyjson) — главный сценарий #673.
- **Этап 4.** Параллельность, «Игнорировать ошибки», внешние компоненты, «Сохранять
  конфигурацию» и переобучение, деревья.

## 5. Вопросы native-пробы (первый шаг разработчика)

Только `https://app.loginom.ai/app/?testable=true`, свой пакет пары. Каждый ответ —
наблюдение с `data-tid`; где `data-tid` нет — пробел в отчёт. Шаблоны — по Подмодели,
до пробы гипотеза.

1. Палитра и создание: `…colVendors_Компоненты>Управление>Цикл;TreeText`,
   `mnComponentsContextMenu;mniAddNewNode`, `MF;TF-N;Graph;Цикл;Setting`; корень мастера.
2. Шаг 1: `data-tid` дерева узлов, корней «Узлы текущего модуля»/«Компоненты», строки
   узла (по подписи или GUID?), фильтра, флага «Сохранять конфигурацию». Видна ли
   Подмодель корневого сценария; скрыты ли запрещённые типы или выдают ошибку?
3. Должен ли вход заключённой Подмодели быть связан? Выполняется ли сама Подмодель
   при Execute Цикла (для Выполнения узла справка говорит «базовый узел не выполняется»)?
4. Шаг 2: радиокнопки вида цикла, список «Вид групповой обработки», поле «Количество
   строк в группе», выбор входного порта, флаги параллельности, идентификаторов, ошибок,
   «Переменная цикла»; `data-tid` каждого и значения по умолчанию.
5. Порты Цикла после мастера: число, порядок, имена (`Цикл;Input_Data-N`, `Output_Data-N`),
   совпадают ли с портами Подмодели.
6. Выход: строки всех итераций подряд в порядке групп? Точное имя и тип поля
   «Идентификатор итерации» при включённом флаге. Пустой вход — 0 итераций без ошибки?
7. REST со стенда: доступен ли `httpbin.org/response-headers` и сохраняется ли Response
   без изменений (отступы, перевод строки в конце)? Если нет — проверить postman-echo.
   Ошибка REST в одной итерации прерывает Цикл; причина из `btnError/@data-qtip`.
8. Изменения тела после настройки: видит ли Цикл новую версию Подмодели (производный
   компонент живой или снимок)? Нужна ли повторная настройка Цикла?
9. Сохранение: fulltype Цикла и ссылка на производный компонент в `Unit_0/Unit.xml`;
   переоткрытие пакета и Execute без перенастройки.
10. Для этапа 2: порт переменных Подмодели появляется в списке «Переменная цикла»?

## 7. Оценка этапа 1

**5 циклов** собственно Цикла: 1 — native-проба и правка комплекта; 2 — обработчик
(выбор узла по identity, групповая обработка, флаги, readback портов и производного
компонента, отказ неподдержанного до мутации, адресные red→green); 1 — сценарии
`loop-pages-offline` и `loop-pages-rest` в run-check; 1 — Save/cold и наблюдённые отказы.
**Предусловие:** принятый этап 1 Подмодели (NW1 #1078 + обработчик `control.supernode`;
по её README 4 цикла при принятом NW1). Итого путь до PASS — около **9 циклов**.
Этап 2 (FOR + переменная цикла) — ещё **3–4**, из них 2 на границу переменных Подмодели.

## 8. Ловушки

- Цикл ссылается на узел: нельзя «войти в Цикл»; тело правится в Подмодели.
- Выходные переменные заключённого узла не становятся выходами Цикла.
- Нумерация итераций с 0; RequestID REST внутри итерации тоже с 0 — не путать.
- Параллельность недопустима для источника без параллельных запросов; в срезе выключена.
- Постусловие без изменения переменной в теле — бесконечный цикл; в срез не входит.
