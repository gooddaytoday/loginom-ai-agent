Оркестрация — Multica, сквад «Обработчики узлов»: Генератор тасок готовит назначение, Тест-Манки #1 разрабатывает и проходит приёмку, Ловец Галюцинаций независимо принимает опубликованный SHA.

```text

Обработать узел по его подплану до независимой приёмки. Объём — этап <N> подплана.
```

Первая карточка — этап 0 отдельно. Этап 1 назначается после решения владельца по W1; следующие W — перед соответствующим этапом. Общие исправления, подплан, RUNBOOK и инструменты приёмки должны быть в ветке задания до старта.

Разрешено:

1. Живое исследование штатными средствами runtime в собственном аккаунте.
2. Реализация назначенного этапа и только согласованных общих изменений (W1; W2).
3. Приёмочный комплект, PR в ветку задания, публикация доказательств и независимая приёмка.

Не разрешено: merge/релиз; следующие этапы; новые общие контракты без решения владельца; изменение конфигурации обвязки. Внешние объекты и файлы — только собственные объекты из задания.

## 2. Этапы

### Этап 0 — подготовка, живое исследование, контракт

Checkout/SHA и сборка из закоммиченных исходников, `loginom status` = `ready`; квалифицировать внешнюю среду отдельно. Каждый отказ мастера читать из кнопки ошибки.

1. Палитру «Импорт > Loginom Data файл», root мастера, optional переменные и одну таблицу; E2E ImportNativePreviewWizard — ориентир.
2. Имена/метки/типы/виды полей, Variant/NULL/empty, порядок и пустую таблицу с полной схемой.
3. Compression/bitness informational fields, checksum вкл/выкл, поведение файла без checksum.
4. Когда появляется схема и как новый digest выбранного источника меняет данные того же узла.
5. DDF отдельно от LGD, неверный путь/формат, corrupt копию и cancellation; checksum-off не считать исправлением данных.

Результат — `discovery.md`: observed/hypothesis, exact значения/типы/имена, границы источника и side effects, решения по W. Выход — `ready_for_development` только после снятия блокеров; закреплённые type/mode, `fixtures/` и `acceptance/` до кода обработчика.

### Этап 1 — самостоятельный первый срез

Scope: Один самостоятельный LGD с всеми значениями и свойствами полей; NULL/empty, пустая схема и честный отказ повреждённого файла. Создание и настройка существующего узла; readback фактически наблюдённых настроек и свежести результата. Неподдержанные формат/порт/режим/тип/параметр отклоняются до мутации с понятным объяснением исправления.

Требования этапа 1 (частичные режимы явно ограничены разделом 1):

- `imports-lgd:r01` — LGD источник, имена/метки/типы/виды полей, пустая таблица и неизменность данных.

Для бинарного/XML источника использовать admission вложения: `parameters.source.artifact_id` и `upload_operation_id` из завершённой `artifact.upload`, exact bytes/SHA256/destination из server-copy proof; не брать их из текста модели и не синтезировать старый receipt. Контракт text-import-node.mjs:31-63 — образец проверки, поддержка imports.lgd пока отсутствует. После reopen читать persisted source без повторной конфигурации и без receipt прежнего процесса; способ квалифицировать этапом 0 и реализовать W.

Файлы: новые `packages/loginom-runtime/client/lib/imports-lgd-{node,parameters,procedure,readback}.mjs`, тесты `client/test/imports-lgd-*.test.mjs`; регистрация `node-contracts.mjs`/`.d.ts`, `node-support.mjs`, `node-api.mjs`, `node-result-schema.mjs`, `user-results.mjs`. Образец — [Текстовый импорт](../../../../packages/loginom-runtime/client/lib/text-import-node.mjs), не переносить его семантику/формат. Общие `node-procedure.mjs`/`workspace-ui.mjs` меняются только в согласованных W.

Общие изменения, каждый отдельным коммитом с адресными тестами:

- **W1** — источник бинарного LGD с verified artifact_id/upload_operation_id, bytes/digest/destination, persisted source для cold-open; scripts/node-acceptance (cold reader/source lineage без восстановления прежних настроек); node-api/node-procedure/workspace-ui и тесты.
- **W2** — этап 2: управляющий путь через bindings, чтение информационных metadata и независимые проверки формата/checksum; node-api и scripts/node-acceptance.

Видимость для модели: `NODE_TYPES.semantics` объясняет бизнес-результат и побочные эффекты; `description` у каждого параметра, строковые enum, компактный readback. Наблюдённые значения отличать от запроса модели.

Тесты из `packages/loginom-runtime`: `bun run test:upstream`; при изменении приёмки — из того же каталога `node --test ../../scripts/node-acceptance/tests/*.test.mjs`. Команды новых адресных тестов закрепить после появления файлов; сейчас они не существуют.

### Этап 2 и далее — отдельные карточки

Этап 2 — r02, r03, r04: LZO/LZ4/без сжатия, 32/64-bit, checksum/corruption, DDF и управляющий путь; каждую совместимость принимать отдельно.

- `imports-lgd:r02` — Без сжатия, LZO, LZ4; 32/64-битные файлы и информационные поля мастера.
- `imports-lgd:r03` — Проверка checksum вкл/выкл; без checksum, сжатые блоки, сжатые и несжатые данные.
- `imports-lgd:r04` — DDF и путь через управляющую переменную; сохранённый источник после повторного открытия.

Полный текст каждого требования сохранён в его этапе; проверки в разделе 4 относятся к соответствующей карточке, не являются PASS первого среза.

## 3. Данные и независимые проверки

Комплект `nodes/imports-lgd/acceptance/` (для следующих этапов `acceptance/stageN/`): `task.md` с `{{PACKAGE_PATH}}`, `data/` только для входов модели, `expected.json` из независимого `oracle.py` до обработчика. Внешние manifests, oracle и ожидания модели не передаются; секреты — только во внешнем окружении.

CSV-спецификации: UTF-8, разделитель `,`, decimal `.`, header, NULL-маркер `\N`; empty string отличается от NULL. `fixtures/manifest.json`: фактические байты/SHA256, типы/метки/порядок и происхождение каждого бинарного файла/внешнего объекта; размер фиксируется при генерации, а не угадывается.

| Набор | Содержание и назначение |
|---|---|
| `lgd-values.csv / source.lgd` | Id,Amount,Occurred,Active,Text; integer/real/date/boolean/string, NULL/empty. CSV — независимая спецификация; stock writer готовит бинарный файл и manifest свойств. |
| `empty.lgd / replace.lgd` | Нулевая таблица с полной схемой; изменённые данные той же схемы, иной digest. |
| `compressed-32-64.lgd / legacy.ddf / corrupt.lgd` | Независимый квалифицированный набор bitness/compression/checksum; повреждается только копия проверяемого файла. |

Правило `typed.csv`/`cells.csv` для этих типов: столбцы `Id,Text,Amount,Occurred,Active`; строка i=1..5 имеет Id=i, Amount=[1234.56789,0,NULL,-2.5,10][i−1], Text=[Кириллица,строка с кавычкой и переносом,NULL,пустая строка,=SUM(A1:A2)][i−1], Occurred=2024-02-29T12:30:00.000 (у i=3 NULL), Active=true у нечётных Id, false у чётных (у i=3 NULL). Для семи строк добавить (6,Ж,0.5,2024-03-01T00:00:00.000,true),(7,З,-0.5,2024-03-02T00:00:00.000,false). Метки/виды/назначения и Variant исходного пакета перечислить в manifest до прогона.

Oracle не импортирует handler/runtime, считает по входам, сверяет все ячейки/объекты/байты, имена/метки/типы/порядок полей, NULL/empty/0. Отклоняет старое исполнение, чужой destination/узел и подмену данных; E2E preview/обратный импорт не является независимым эталоном.

Для табличного выхода cold-check сверяет имена/метки/типы и порядок колонок, строки без учёта порядка (`expected-outputs.mjs:14,29-39`), до 100 строк/выход и 32 выходов. Числа точны (`cold-check.mjs:232`); использовать точно представимые значения или отдельно согласованный допуск до прогона. Метаданные видов/назначений и порядок строк требуют отдельного аудита. Выходы связываются по type/label с уникальным node_id (`expected-outputs.mjs:72-81`), port index отсутствует: переменные статуса не покрыты.

## 4. Проверки, приёмка и завершение

Непроведённая проверка — `not_checked`; ожидания/границы фиксируются до модельного прогона.

| Требование / проверка | Независимое условие успеха |
|---|---|
| `imports-lgd:r01` | Полностью сверить manifest, включая метаданные и порядок строк; ноль строк не означает отсутствие схемы. |
| `imports-lgd:r02` | Принятый независимый набор всех комбинаций читается с одинаковыми значениями; непроверенные совместимости разрядности остаются NOT_RUN. |
| `imports-lgd:r03` | Испортить один байт копии с проверяемой checksum: включённая проверка отказывает. Отсутствие checksum отражается честно; отключение проверки не доказывает целостность. |
| `imports-lgd:r04` | Сверить отдельный DDF oracle; смена переменной выбирает файл другого digest и показывает его данные. |
| Контракт и отказы | Неверные настройки/типы отклонены до эффекта; исходная ошибка мастера сохранена |
| Изменение существующего | Настройки/связи readback подтверждены; новый источник не даёт старый результат; незапрошенные свойства сохранены |
| Persistence | Сохранить после всех чтений; открыть новым профилем без восстановления настроек; внешние эффекты и происхождение проверить по согласованному W |
| Recovery | Потерянный ответ не повторяет неизвестный эффект; результат сверяется независимо перед продолжением |
| Регрессия | Адресные тесты нового узла и полный `client/test`; прежние контракты не ослаблены |

Задание модели: Загрузить приложенный файл данных Loginom, сохранить имена и свойства полей, проверить пропуски и все строки, затем сохранить новый пакет в {{PACKAGE_PATH}}.

PASS исполнителя: CLI и применимый cold-check/согласованный независимый аудит результата, адресная матрица, `package_closed=true`, `logged_out=true`. Файловый/внешний/переменный результат нельзя объявить принятым неподходящим oracle. Публикация и Ловец принимают тот же чистый SHA по RUNBOOK; `integration` и `release` не меняются.

## 5. Ловушки — переподтвердить, не копировать

Ниже документальные ограничения и требования прежнего черновика; точные controls и runtime-семантика для стенда остаются гипотезами до этапа 0.

Необязательные управляющие переменные → таблица с метаданными из LGD; поддерживается также исторический DDF.

Внешний проверяющий заранее готовит принятые .lgd/.ddf и manifest значений/схемы на stock Loginom/Deductor, без нового export handler. Набор содержит integer, real, datetime, boolean, строку, NULL, empty; отдельные пустой и повреждённый файлы.

Проверять provenance байтов; corrupt-файлы только копии в выделенном каталоге. Не считать выключенную checksum способом исправления повреждения.
