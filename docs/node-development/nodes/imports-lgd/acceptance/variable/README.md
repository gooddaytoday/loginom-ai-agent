`lgd-import-variable` использует два штатно экспортированных 64-bit LZ4. Оба содержат 5 × 4 с исходными типами, метками и порядком; во втором только RecordId увеличен на 10 штатным Калькулятором с явной заменой поля. Ожидания заданы независимыми `properties-values.csv` и `properties-schema.json`, арифметикой +10 до модельных прогонов; digest различается.

Первый CSV сравнивается со всем исходным набором, второй — со всем изменённым. Main требует два полных прямых чтения того же LGD-узла с разными execution_id, наблюдаемым source_variable=SourceFile и разными source_path. Cold выполняет сохранённый узел вместе с его зависимостями, сравнивает весь второй набор и свойства, затем читает и отменяет без настройки мастера входных переменных/источника. Привязка проверяется по точному cached record и совпадению выбранного proxy, без разыменования proxy.

Реальный порт LGD — обычный variables 0, native Input_Var-1, а не скрытый control. Нет 32-битного Loginom и Deductor: 32-bit/DDF не квалифицируются и остаются запрещены.
