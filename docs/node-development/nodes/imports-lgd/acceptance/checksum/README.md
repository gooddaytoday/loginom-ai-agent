`lgd-import-checksum`: LZ4, 64-bit, три варианта сохранённой checksum. Файлы получены через штатный ExportNativeParamsWizard Loginom 7.4.2; digest и размеры — в `fixtures/64bit/files.json`. Значения, свойства и порядок заранее заданы `properties-values.csv` / `properties-schema.json` и перенесены в `expected.json` независимым CSV-oracle.

Все три файла сначала читаются с включённой проверкой. Тот же импорт файла с обеими суммами повторно выполняется с явно выключенной проверкой; main требует два полных чтения одного узла, разные execution_id, наблюдённые true → false и неизменные значения/схему. CSV проверяет все строки. Cold читает сохранённую политику каждого узла, повторно выполняет и проверяет весь результат. Повреждённый файл отдельно проверяет `lgd-corrupt` на том же SHA, без успешного табличного результата.

Модели передаются только задание и бинарные LGD. Отсутствие checksum не считается доказательством целостности. Не допускается выключение проверки после checksum-ошибки для того же digest или узла.
