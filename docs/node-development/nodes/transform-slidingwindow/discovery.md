## Три политики и NULL

Пусть N — длина входа, H — максимум history, F — максимум horizon.
Окно поля в позиции i использует исходную позицию i+offset, а не уже отфильтрованный ряд.

| API / UI | Позиции строк | Значение |
|---|---|---|
| keep_incomplete / Оставлять неполные записи | -F … N+H-1 | Добавляет F строк перед входом и H после |
| drop_added / Удалять добавленные неполные записи | 0 … N-1 | Только исходные строки, лаги на краях могут быть NULL |
| drop_all_incomplete / Удалять все неполные записи | H … N-F-1 | Только структурно полные окна; реальные NULL сохраняются |

По умолчанию выбран последний способ. В сохранённом собственном Engine
для «Оставлять» наблюдалось IncompleteRecordsProcessing=irpLeave.
В API предлагаются только строковые enum, без нативных числовых кодов.

Для N=5, I=2/1 и R,S,B,D=1/0: keep=8, drop_added=5, drop_all=2 (RowID 3,4).
При I=NULL в третьей строке drop_all всё равно вернул RowID 3 и 4:
у RowID 3 исходный I=NULL, у RowID 4 I_H_1=NULL.
keep вернул 8 строк с теми же настоящими NULL и пустыми краями.
Дополнительной фильтрации по значению NULL нет.

Для пустого типизированного входа: drop_all=0 с прежней схемой,
keep=3 полностью пустые строки. Для одной строки с этим окном drop_all=0.
В добавленных строках исходные неоконные поля и исходные значения полей пусты;
доступные history/forecast заполнены. False не равен NULL: false отображался
как false, NULL Boolean — пустым. NULL string отображался как <null>.
