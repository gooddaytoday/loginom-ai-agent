# v0.4.0: предложение этапа 0 (LAB-1021)

Статус: **checkpoint, blocked; не принятый комплект**. Runtime не изменён.
Владелец утверждает критерии до правки обработчика. Файлы task — заготовки
пользовательских просьб; до решения владельца их нельзя передавать модели.
Модели впоследствии передаются только task и указанные CSV из fixtures/v040.
Oracle, expected, карточки и этот документ модели не передаются.

Живое исследование этого узла **not_checked**: пакет работ остановлен
на недоступном нормализаторе Кластеризации. Здесь только предварительное
математическое предложение. Сведения прежнего discovery не считаются
новым подтверждением рекомендаций, вспомогательного входа и holdout.

`oracle.py` перебирает подмножества маленьких корзин через itertools и
Fraction, независимо от FP-Growth. train: 4 корзины; A встречается в 4,
B/C — в 3. Проверяются support/confidence/lift, разница лимитов 1/2 следствия
и отсечение лифтом 1.2. Для holdout H1={B,C} отсутствует только разрешённый
товар A; H2 уже содержит A, H3 не имеет основания. Ожидается одна бизнес-
рекомендация H1→A, без предположения о выборе RuleID между эквивалентными
правилами. Точные native IDs, схема/NULL-padding для нескольких следствий,
роли Item/Keep вспомогательного входа и доступность фильтра следствий
остаются незаданными. Если UI не предоставляет такой фильтр, этот task
нельзя запускать: сначала скорректировать предложение с владельцем.

Полная схема, все ячейки порта 2 и сохранение модели без retrain не доказаны.
Динамические RuleID не следует исключать из приёмки молча; их привязка
должна быть установлена до создания stock expected и run-check.

## Предлагаемая приёмка после снятия блокировки

`oracle.py` читает только CSV; `expected.json` — независимое предложение,
**не stock expected**. Непроверенные схемы и семантика явно перечислены.
Точные integer/string/boolean/NULL и типы; допуски только для real.
Изменение существующего узла без пересоздания, два повтора при тех же
настройках, полный CSV/все порты, Save, cold без повторной настройки,
cleanup и правило 2/3 на одном SHA остаются обязательными на этапе 1.
Новых проверяющих механизмов в этой ветке нет; нельзя засчитать PASS
по одному аналитическому расчёту либо игнорировать нерешённые поля.

Воспроизведение из каталога v040:

```sh
python3 oracle.py > expected.json
python3 oracle.py --check
```
