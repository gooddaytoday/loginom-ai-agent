Replacement registration is a closed private factory. `launchReplacementDiagnostic`
selects `replacement-input0-readonly-v1`; the ordinary launcher cannot accept
structural `acceptanceCapture`. Entry accepts the legacy authorization/path tuple
or that exact tuple plus the Replacement literal. Undefined, null, foreign
selectors, extra/hidden/symbol keys, inherited operands and accessors refuse
before host creation. The selector grants no authority by itself.

Host/port mint owner/run/lease/generation/chat/account/admission from the actual
connection lease. Managed entry validates that tuple, verifies resource bytes,
canonical realpath and the unique inventory entry, loads only the fixed export
and requires its read-only validator. Replacement rechecks realpath/hash and the
original expiry after awaited import; self-modifying resources refuse before
registration. Generic ownership, publication, persistence,
no-replay and close paths are unchanged.

The fixed adapter distinguishes the original outer phase receipt ID from the
native opening operation ID. Publication binds the former; linked input0 proof
must equal the original phase value's native ID. Both are immutable independent
pins. No receipt or native opening is rewritten to make those IDs equal.

The new tests cover closed selectors, Calculator compatibility at the entry/start
boundary, inventory/export/mode failures, genuine whole host/port/supervisor IPC,
and whole managed-entry/bridge/executor composition with the fixed reader and
serialized observer. IPC and filesystem are real. Auth/Page, prepared/opening
native objects, catalog transport, configuration driver and Save are explicit
doubles. The executor creates and retains the original request and phase receipt;
reader/observer readiness is computed, not injected. Fixture node.apply and Save
are synthetic prerequisites, never live Replacement mutation or native authority.

DIAGNOSTIC_READ has effect=false and cleanupComplete=false. It does not admit
native capture, release, ACK, apply, execution, or native cleanup. Host recovery
and repeat refusals are expected. Node-child exit/disposal in these offline tests
is not Loginom cleanup. Fixture files remain available for evidence.
