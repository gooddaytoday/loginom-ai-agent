# Замена

Предложение этапа 0; доступность расширений подтверждается только после
реализации и принятия точного SHA. Прочитай `dock_action_describe` для
`transform.replace_columns` перед настройкой.

Точный словарь: `mode:"exact"`; `rules[].type` — тип входного ключа,
`result_type` — тип констант замены. Без result_type сохраняется тип ключа.
Предлагаются результаты string/integer/real/datetime/boolean. Значение
Boolean передавай JSON true/false, не строкой и не числом. Ключи остаются
string/integer/real. Строковые exact-правила требуют case_sensitive;
числовые — precision≥0 с двумя знаками: допуск включительно, ближайший,
при равном расстоянии больший; precision>0 добавляет real `_Delta=ключ−вход`.

Пары from/to и `other.value` типизированы. `other:null` заменяет все остальные
значения, включая исходный NULL, и ставит флаг true. Это словарь соответствий,
не автоматический разбор текста. Для иного result_type с `other:keep`
результат становится Variant: совпадение имеет новый подтип, остальные ячейки
сохраняют исходный подтип и NULL. Требуется точное нативное чтение подтипов;
один CSV не различает строку true и логическое true. До допуска такого чтения
комбинация остаётся недоступной.

`mode:"regex"` использует упорядоченные string pairs: from — шаблон,
to — строковая константа; первое совпадение подстроки заменяет всю ячейку.
Ссылки на группы ($1) остаются буквальным текстом. Опускай case_sensitive и
precision; для игнорирования регистра используй inline `(?i)`. Допущенная
ASCII-подграмматика: литералы, скобки, `[0-9]`, положительный `{n}`, ^/$.
Regex другого типа результата и подстановка групп не обнаружены в UI.

Предлагаемый `mode:"mixed"`: pairs — точная таблица, regex_pairs — строковые
regex-константы. Exact имеет приоритет; затем первое regex-совпадение;
затем other. Сохраняй обе таблицы, в том числе при patch только одной группы.
Внутренние пары и external одного поля взаимоисключающие.

Внешняя точная таблица: дополнительный табличный input 1..14 и
`rules[].external={port,value,replacement,information,unused}` с точными
именами всех полей справочника. Value сравнивается с ключом входного поля,
replacement задаёт замену, information добавляет информационные столбцы,
unused явно перечисляет оставшиеся поля. При дубликате ключа берётся первая
строка, число главных строк не растёт. Нативные имена информационных полей
прочитай после настройки. Изменение входов требует полной конфигурации.

`output_mode:"replace"` меняет исходное поле; add сохраняет его и добавляет
`<поле>_Replace`. `<поле>_Replaced` — boolean. Незаданные поля и правила
сохраняй, пустые parameters существующего узла их не стирают. Порядок полей
закрепляй полным output mapping с autosync=false. Выполни, прочитай полный
малый результат, выгрузи CSV с маркером ?, сохрани и проверь cold.
Импорт/экспорт файлов правил — удобство редактора, не отдельный способ
получить другой результат. В предложенный runtime-контракт транспорт этих
файлов не входит. Привязки к переменным исключены.
