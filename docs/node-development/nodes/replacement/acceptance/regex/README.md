# Приёмочный комплект regex — предложение этапа 0

[Исследование и границы](../../discovery.md), [основное задание](../task-regex.md),
[replace/inline-задание](../task-regex-replace.md), [данные](../../fixtures/regex/input.csv).
Передавать модели только соответствующее задание и CSV с именем `input.csv`.
`{{PACKAGE_PATH}}` заменить на новый путь в назначенном личном каталоге.
Не передавать этот README, oracle или expected модели.

Независимый oracle использует только Python stdlib и исходные байты CSV:
`re.search` для выбора первого правила, затем целая строковая константа.
`re.sub` и интерполяция `$1` не используются. Общий флажок регистра exact
не является regex-флагом; дополнительный сценарий использует `(?i)`.

```sh
python3 docs/node-development/nodes/replacement/acceptance/regex/oracle.py --write
python3 docs/node-development/nodes/replacement/acceptance/regex/oracle.py --check
```

`--write` создаёт оба expected и manifest исходного CSV; `--check` независимо
пересчитывает их и требует совпадения. Вход: 116 Б, 8 записей, три колонки,
UTF-8 без BOM, LF, разделитель `;`, NULL-маркер `NULL`. Пустота — `""`, не NULL.
Схема и все ячейки проверяются штатным cold-check; строки — мультимножество,
поля — в заданном пользователем порядке, незаданные метки через label_any.

Для основного задания используется `expected.json`, для дополнительного —
`expected-replace.json`. Значения ожидаемого результата зафиксированы до
модельных прогонов; генерация не читает Loginom или вывод обработчика.
В этапе 0 они являются предложением владельцу, а не PASS реализации.
Сценарии пока не зарегистрированы в run-check; регистрацию в существующем
каталоге выполнить на этапе 1 после утверждения объёма. Собственные runner
или новые способы проверки не нужны.
