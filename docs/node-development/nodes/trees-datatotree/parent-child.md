## Соседние узлы группы «Дерево данных»

Все семь компонентов присутствовали в палитре
`ModelForm;colVendors_Компоненты>Дерево_данных>…;TreeText`.
У каждого создан собственный узел и открыт мастер по `Graph;…;Setting`.

| Узел | Наблюдаемые порты | Страница / назначение UI |
|---|---|---|
| Таблица в дерево | Data 0 → DataTree 0 | `DataToTreeWizard`, ручная структура и связи |
| JSON в дерево | Data 0 → DataTree 0 | `JSONToTreeWizard`, уже готовый JSON |
| Дерево в JSON | DataTree 0 → Data 0 | `TreeToJSONWizard`, сериализация |
| Дерево в таблицу | DataTree 0 → Data 0 | `TreeToDataWizard`, выбор узлов дерева |
| Калькулятор (дерево) | DataTree 0, Var 1 → DataTree 0 | `CalcTreeWizard`, выражения над деревом |
| Объединение (дерево) | DataTree 0/1, Input_Add → DataTree 0 | `UnionTreeWizard`, конкатенация всех / первое активное дерево |
| Слияние (дерево) | DataTree 0/1 → DataTree 0 | `JoinTreeWizard`, включение в контейнер или массив |

У слияния проверен `JoinTreeWizard;cbxOperationType;boundlist`: только
«контейнер» и «массив»; есть `trpMainTree`, `trpJoinedTree` и
`edtSkipJoinedRootNode`. Это соединение уже существующих деревьев.
Соседи с деревом на входе не дают настройки ключевой рекурсии из одной таблицы.
Вычисления/JSON как обход не создавались. Native FullType не читался.

## Связка с JSON и непроверенные случаи

`TreeToJSONWizard` содержит `pedRootExcluded`, `pedPrettifyJSON`,
`pedDisplayNameAsKey`, `pedMultiRowOutput`, `pedDateTimeIsISO8601`,
`pedDateFormat`, `pedTimeFormat` с `ValueControl`. Выход — табличный Data 0.
Настройки не менялись, сериализация оргструктуры не выполнялась:
нет найденного native-построителя такой структуры. Наличие сериализатора не
доказывает возможность создать рекурсивное дерево.

| Случай | Native-результат | Предложение, не утверждённая семантика |
|---|---|---|
| NULL в parent_id | not_checked | Строка становится корнем |
| Два и более корня | not_checked | Массив roots, порядок исходных корневых строк |
| Потомок раньше родителя, глубина 4 | not_checked | Поиск по ключу, без ограничения двумя уровнями |
| Цикл A ↔ B, в том числе вне корней | not_checked | Явный отказ всего входа, без частичного результата |
| Несуществующий parent_id | not_checked | Явный отказ, без потери строки или превращения в корень |
| Оргструктура → вложенный JSON | not_checked | Полное дерево и один JSON-документ, см. draft oracle |

Эти политики требуют решения владельца; они не выводятся из UI. При появлении
native-режима сначала сопоставить его поведение с предложением, не подгоняя
oracle под результат. Штатная приёмка после отдельного назначения — 2/3 на одном
SHA, независимые 2/3, Save/cold/cleanup и проверки затронутых пакетов.
Сейчас run-check не запускался: режим отсутствует, критерии не утверждены.

## База кода и размер следующего шага

В текущей базе runtime-имена — `trees.from_table` и `trees.to_json`.
`trees.datatotree` / `trees.treetojson` из назначения не являются их runtime alias.
Ручной режим уже есть в `node-contracts.mjs`, `node-support.mjs`,
`tree-conversion-node.mjs` и `tree-conversion-parameters.mjs`.
`validateTreeConversionParameters` допускает одну ветвь-массив и один вложенный
объект; `validateSerializationTree` требует ровно один массив во всей схеме.
Описания и ссылки skill: `references/nodes/trees.from_table.md`, `trees.to_json.md`.
Историческое «handler не реализован» в исходном подплане к этой базе не относится.

В этом PR **0 циклов правки обработчика**, runtime/skill/оснастка не меняются.
Оценка реализации в циклах до найденного native-режима невозможна. Потенциально
затрагиваются перечисленные handler/parameters/registration, описание skill,
`tree-conversion-context.mjs` и наблюдение/чтение рекурсивной схемы; это не
разрешение на такие изменения. Ослабление общих guard или новый comparator
нельзя объявить аддитивной настройкой обработчика. Обход не проектируется.
