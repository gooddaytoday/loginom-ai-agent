# Дерево в JSON

Предложение этапа 0; устанавливается только после утверждения и реализации.
Прочитай карточку trees.to_json. Сначала выполни и полностью прочитай собственный
типизированный источник: его tree output 0 подключается к tree input 0.
Режим serialize: exclude_root=true, pretty=false, keys=names, multi_row=false,
datetime=iso8601. Это один object root и одна повторяющаяся ветвь объектов;
поле datetime сохраняет настройку платформы, но даты в первый срез не входят.

Выход 0 — таблица с одной JSON-строкой. Прочитай строку полностью; строковый
preview с усечением не доказывает сохранение данных. Сохраняются порядок массива,
числа, Boolean, null, пустая строка и декодированные Unicode/кавычки/переносы.
Int64 нельзя округлять через JS Number. Разные допустимые JSON escape-последовательности
и запись 2/2.0 семантически эквивалентны; исходный тип real проверяется на дереве.
Порядок ключей объекта проверяется на tree schema, не по отсортированному JSON.
Если JSON→дерево материализовал отсутствующий скаляр как NULL, результат содержит
null; исходное отсутствие уже невосстановимо.

Для нового узла задай все пять параметров. Для существующего parameters:{}
сохраняет настройки; явный patch сохраняет пропущенные параметры. Нет обучения
ML в заявленном контракте; Execute пересчитывает текущий вход. Отдельные train/apply
не заявлены до наблюдения. Save после чтения; cold reopening отдельно проверяет
настройки и свежий результат. Корневые массивы, splitting, форматирование,
метки вместо имён, даты, Variant и переменные пока отклоняются до мутации.
