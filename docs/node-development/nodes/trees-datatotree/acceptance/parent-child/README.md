# Предложение приёмки id / parent_id

LAB-887, **blocked / не утверждено**. В Loginom 7.4.2 режим в UI не найден.
Это независимый бизнес-oracle, а не новый механизм проверки runtime и не
описание фактического результата Loginom. Запуск через run-check не зарегистрирован.
Параметры native-режима, точная схема tree-порта, его instance count, имя
JSON-колонки и текст native-ошибки неизвестны. Не подставлять их из manual_structure.

| CSV из ../../fixtures/parent-child | Предлагаемый критерий |
|---|---|
| org.csv | 5 элементов, глубина 4, строковые ключи с нулями, потомок перед родителем, NULL-корень |
| multiple-roots.csv | 5 элементов, корни B затем A; у A дети A2 затем A1 |
| cycle.csv | Отказ на A ↔ B, хотя рядом есть правильный корень R |
| orphan.csv | Отказ на Z → MISSING, без частичного леса и потери Z |

Все CSV: UTF-8, запятая, заголовок, три строковых поля; пустая parent_id
должна импортироваться как NULL. Пустые id/name, дубли id, самоссылки, пустой
вход, quoted empty parent_id, другие типы и предельная глубина — вне предложения.
Общая валидация oracle не означает включения этих случаев в критерии приёмки.

`oracle.py` использует только CSV и Python stdlib: строит отображение ключей,
проверяет существование всех родителей, обнаруживает циклы во всех компонентах,
восстанавливает детей и корни в порядке входных строк. expected.json сохраняет
два предложенных JSON-результата и две причины отказа; точные native error codes
не задаются. JSON-ключи объектов не упорядочиваются при сравнении, массивы — строго.
Требуются точные строковые значения, NULL отдельно от пустого текста.

Воспроизводимость из корня checkout:

```sh
python3 docs/node-development/nodes/trees-datatotree/acceptance/parent-child/oracle.py --check
```

Без --check печатает рассчитанное предложение, файл не перезаписывает.
Сравнивается весь независимый комплект с checked-in expected, не только размеры.
Для модели допускаются лишь выбранное бизнес-задание и соответствующий CSV.
Этот README, oracle и expected модели не передаются.
Ответ об отсутствии режима означает блокировку, не PASS положительного или
отрицательного сценария: отказ на неподдержанную возможность не проверяет
распознавание цикла/сироты.

После решения владельца и появления native-режима нужны отдельно: полное typed
чтение tree-порта 0, JSON AST сериализатора на табличном порте 0, проверки всех
значений и глубины; Save/cold/cleanup и 2/3 + независимые 2/3 на одном SHA.
Существующие check_tree и ограничение сериализатора одним массивом не доказывают
корректность рекурсивного дерева. Новые adapter/comparator здесь не реализованы.
