# Приёмка id / parent_id

Решение владельца от 06.11.2026: агент вычисляет иерархию на существующих узлах.
В 7.4.2 штатного рекурсивного режима id/parent_id в «Таблица в дерево» нет.
Рецепт продукта: `references/nodes/parent-child-recipe.md` навыка loginom-automation.

| Сценарий run-check | CSV из ../../fixtures/parent-child | Критерий |
|---|---|---|
| tree-parent-child | org.csv | 5 элементов, глубина 4, строковые ключи с нулями, потомок перед родителем, NULL-корень |
| tree-parent-roots | multiple-roots.csv | Корни B затем A; у A дети A2 затем A1 |
| tree-parent-cycle | cycle.csv | Ошибка выполнения с id A, B; без частичного дерева |
| tree-parent-orphan | orphan.csv | Ошибка выполнения с id Z; без превращения в корень |

Все CSV: UTF-8, запятая, заголовок, три строковых поля. Пустой parent_id
импортируется как NULL. Все вершины должны присутствовать ровно раз. Результат —
один JSON-документ {roots:[…]}, id/parent_id/name сохранены; у листьев children:[].
Порядок соседей и корней соответствует порядку строк файла. Технического Root нет.
Дополнительные ограничения на пустые id/name, дубли, типы и глубину не являются
новыми критериями этого пакета приёмки.

`oracle.py` независим от рецепта и Loginom: Python DFS проверяет все компоненты,
а построение дерева выбирает детей по исходным строкам. `expected.json` содержит
бизнес-ожидания. `expected-*-run.json` — их перенос в существующие typed CSV/cold
ожидания: json_ast для JSON и execution_error для отрицательных случаев.
Коды runtime не переопределяются, новый comparator не вводится.
Отрицательные сценарии требуют наблюдённую ошибку инструмента и сообщение
пользователю с полным перечнем id, без экспорта; Save и cleanup обязательны.
Положительные сценарии требуют полного CSV, Save, cold Execute и cleanup.

```sh
python3 docs/node-development/nodes/trees-datatotree/acceptance/parent-child/oracle.py --check
```

Без флагов oracle печатает бизнес-ожидания; `--write` воспроизводит все пять
checked-in JSON. Только выбранное бизнес-задание и один соответствующий CSV
передаются модели. README, oracle и expected остаются вне её контекста.
Отказ из-за отсутствия штатного режима не считается PASS ни одного сценария.
