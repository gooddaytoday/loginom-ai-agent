## Предлагаемое разбиение на этапы

Разбиение — гипотеза до этапа 0. Каждый этап должен приниматься самостоятельно; общие изменения, нужные этапу, входят в его же карточку.

## Заметки черновика

Табличный вход преобразуется в дерево выбранной структуры. Help не ограничивает количество уровней; этап1 ограничивает fixture, а не целевой полный scope. Соответствия между полями и узлами явные; правила образования элементов массива и объединения повторных строк нужно подтвердить без догадки о группировке. Выход дерева требует typed-tree reader, табличный preview его не заменяет.

CSV RowID,OrderID,SKU,Qty: (1,10,A,2),(2,10,B,0),(3,20,C,NULL). Создать Root→Orders[] с дочерними полями и вложенным контейнером. До oracle наблюдением установить: каждая строка отдельный элемент или допускается особая mapping-группировка; не подставлять ожидание по GroupData. Числа, NULL, имя/label и массивный порядок сравнить exact; schema loaded from JSON и XSD должна дать такой же результат при одинаковых mappings. Дополнительный источник меняет порядок колонок и добавляет поле, выявляя зависимость от позиции.

Узловые отказы: Дубли имени в одном уровне, неверный scalar/container, несвязанный обязательный узел, несовместимый тип связи, отмена замены схемы; в этих случаях не сохранять случайно частично построенную структуру.
