## Мастер, параметры и динамическая схема

Открытие настройки показывает информационное сообщение об отсутствии отдельного
мастера «Качество данных»; доступны страницы полей и описания узла.
Контроллер содержит пять `DerivedDataSourceMappingEngineOutputPortWizard`
(без суффикса, затем `-1`…`-4`) и `DoneWizard`.
До первого выполнения поля выходов ещё не материализованы: страницы соответствия
пусты, «Далее» может штатно перейти сразу к описанию узла. После выполнения
табличные схемы прочитаны через собственные Table-визуализаторы пяти портов.
Обычный мастер алгоритмических порогов, метода или seed не обнаружен.

В сериализации штатного экземпляра:

- `TBGQualityEngine MaxNullsPercent="50"`;
- числовые непрерывные поля имеют `TBGQualityColumnDefExtension` с
  `ActionNull=anMedian`, `ActionOut=aoLimitation`, `ActionExtr=aeLimitation`;
- дискретные строки: `anMostFreq`, `aoMostFreq`, `aeMostFreq`;
- input mapping: `SyncThroughColumns=true`, поля используются (native UsageType=3,
  UI-подпись «Используемое»).

Это наблюдённые сохранённые умолчания, а не доступные публичные параметры.
Их изменение и дополнительные режимы не входят в предложение `profile`.
Нельзя обещать исправление данных лишь по названиям этих скрытых действий.
Предложенный `parameter_schema` принимает только `{}`; полей параметров нет,
строковый enum режима — `profile`. Объяснение находится в description схемы
и semantics карточки типа. Схема и файл навыка — в `model-contract/`.

Native input mapping подтвердил integer/real continuous и string discrete.
Boolean, datetime, входной variant, нестандартные роли и изменение скрытых
действий не исследованы и этим первым срезом не объявляются поддержанными.

## Наблюдённый дефект распознавания страниц

На второй странице owner — собственный Quality, виден
`MF;TF-1;WizrdMCF;DerivedDataSourceMappingEngineOutputPortWizard-1;btnAddMappingColumn`,

классификация общим reader не утверждается.

В этапе 0 код не менялся. Операторское чтение остальных выходов продолжено.
На этап 1 разрешено адресное распознавание пяти страниц Quality с owner/port
binding, без изменения распознавания Квантования; обязательны оба red→green,
регрессионный тест и один живой binning.

Отказ алгоритмического мастера не наблюдался: отдельного мастера нет.
Скрытое наличие `btnError` не считается ошибкой; неактивная кнопка не нажималась
принудительно. Ожидаемые ошибки пустого/неподдержанного входа пока не установлены.

## Данные и смысл пяти результатов

`fixtures/diagnostic.csv`: 8×4, RowID=1…8, Value=1,1,2,NULL,3,4,100,0;
Class=A,A,B,B,A,B,пустая строка,NULL; Note содержит Unicode и NULL.
Импорт: integer/integer/string/string, первые два continuous, последние discrete.
UTF-8, запятая, десятичная точка, двойная кавычка, NULL `?`.

`probe.csv`: 36×8. X имеет один 100 среди нулей, Y — два, Z — четыре;
TieA/TieB проверяют противоположный порядок равных частот A/B, Hole — два NULL,
Real — вещественные четверти. `boundary.csv`: 28×8, специальные X/Y различают
генеральную и выборочную дисперсию. `update.csv` — 8×4, те же типы/имена,
Value=0,1,2,3,NULL,NULL,NULL,NULL. Входы самостоятельные, без чужих пакетов.

Штатная конфигурация не возвращает списки плохих строк по названиям портов:

| Набор | Порт 0 | Порт 1 | Порт 2 | Порт 3 | Порт 4 |
|---|---:|---:|---:|---:|---:|
| diagnostic | 8 | 0 | 0 | 8 | 4 |
| probe | отдельно не читался | 0 | 0 | 36 | 8 |
| boundary, новая сессия | 28 | 0 | 0 | 28 | 8 |

У 0/3 исходные поля, типы, значения и порядок строк сохранены; NULL не заменён
нулём или строкой. Первый порт проверен полностью на diagnostic/boundary,
третий — на всех трёх. На probe/boundary итоговая таблица содержит положительные
Out/Extr, а порты 1/2 всё равно пусты. Пустые выходы сохраняют входную схему.
Это контракт предложенного штатного режима на данных приёмки; иной набор
скрытых действий требует отдельного исследования.

## Итоговая таблица: все поля

Порядок фиксирован; одна строка на входное поле в его исходном порядке:

| Имя | Метка | Тип | Смысл |
|---|---|---|---|
| Col0 | N | integer | Порядковый номер поля, от 1 |
| Col1 | DisplayName | string | Метка входного поля |
| Col2 | DataType | string | «Целый», «Вещественный», «Строковый» |
| Col3 | DataKind | string | «Непрерывный»/«Дискретный» |
| Col4 | Null | integer | Число NULL; пустая строка — значение |
| Col5 | Out | integer | Число выбросов по полю, без экстремумов |
| Col6 | Extr | integer | Число экстремумов по полю |
| Col7 | Avg | real | Среднее непрерывных чисел без NULL; для string — NULL |
| Col8 | Moda | variant | Гистограммная числовая или частотная строковая мода |
| Col9 | Median | real | Верхнее среднее наблюдение чисел; для string — NULL |

Для n ненулевых чисел oracle использует Avg=Σx/n и генеральную дисперсию
v=Σ(x−Avg)²/n; Out: 9v < (x−Avg)² ≤ 25v, Extr: (x−Avg)² > 25v.
На boundary X даёт 2 Out, Y — 1 Extr; выборочная дисперсия дала бы другие
категории. При нулевой дисперсии Z получены нулевые счётчики и нулевые
среднее/мода/медиана. Строгость сравнений на равенстве ровно 3σ/5σ остаётся
предложением: текущие фиксированные данные не содержат этих равенств.

Median — sorted(x)[n//2], не интерполяция: RowID=1…8 → 5; 1…36 → 19;
1…28 → 15. Числовая Moda: центр первого наиболее частого из
ceil(1+log2(n)) равных интервалов min…max; максимум включён в последний.
Наблюдения: RowID=1…8 → 1.875; 1…36 → 33.5; 1…28 → 3.25;
probe.X/Y/Z → 50/7; boundary.X/Y → 25/3. Строковая мода A/B при равных
частотах — B для обоих порядков входа. Общая Unicode-коллация ничьих не проверена.
Все формулы независимо вычислены Fraction-oracle, не вызовом обработчика.

На исследованных числах k совпадает при подсчёте числа интервалов как по
ненулевым значениям, так и по всем строкам. Нативное различение этой гипотезы
пока не завершено: `update.csv` с четырьмя NULL предложен именно как такой
критерий. Oracle предлагает k=3 и Moda(Value)=2.5; k по восьми строкам дал бы
4 и 0.375. Это явно предложенное ожидание до утверждения, не прочитанная метрика.

## Точность и существующие границы API

Integer, NULL и строковые ячейки прочитаны штатным bounded Table reader.
Для real Avg/Median установлен и проверен 17-значный формат; совпадение
с рациональным oracle проверено. Moda/variant доступна только как форматированный
текст: числовые значения согласуются с формулой до округления UI, но точный
native subtype и binary64 не объявляются проверенными.

`decodeTableOutput(requireExactNumbers=true)` отказал на variant, сохранив
ограничение. Имеющийся private exact variant путь ограничен Collapse port 0,
≤50 строк, ≤8 колонок, ≤400 ячеек; Quality summary — port 4 и 10 колонок.
Требуется отдельно согласованная адресная адаптация, например чтение только
Moda существующим декодером при сохранённых пределах и полном owner binding.
Без неё нет полного численного PASS пяти выходов.

В `node-api.mjs:194,249` публичный read допускает только 0…2 и три порта.
Пять выходов требуют адресного допуска Quality в apply/read с сохранением
границ остальных типов. Это дополнительная адаптация сверх регистрации
типа/файла навыка/сценария и уже разрешённого распознавания страниц.

При 1280×800 `openNewOutputTable` отказал для пятого порта до Add:
`Owned viewer scroll anchor unavailable`. Штатное раскрытие по data-tid и
увеличение viewport позволили прочитать порт. Ослабления guards или общей
правки для обхода отказа не делалось; геометрия по умолчанию требует проверки
при реализации и отдельного согласования, если понадобится ещё общий код.

## Lifecycle, сохранение и ограничения

Native меню содержит доступные «Выполнить узел» и «Обучить узел».
Для diagnostic выполнены обе команды; повторное чтение первого выхода
сохранило исходные значения, включая NULL. Это не доказывает отдельный
контракт сохранённой модели или apply без обучения. Такой mode не предлагается.
Новая сессия boundary дала новые независимые средние и классификацию.
Нативный импорт изменён на update.csv тем же node_id; квитанции source,
configure, output_mapping, finish, execute и read подтверждены. Последующее
чтение того же Quality заблокировано диалогом «Обнаружен разрыв связи»
(`msgbox;cnt;cnt;cmp`). Новые числа Quality не прочитаны и PASS обновления
не заявляется. Модельное обновление, Save/cold и повторяемость на одном SHA
являются критериями этапа 1; нативная диагностика не подменяет их.

Свой пакет штатно сохранялся и скачивался для определения native engine type;
cold-численная приёмка не запускалась. В ходе продолжения был разрыв связи;
сессию восстановили только для уборки, собственный пакет закрыт без сохранения
последних изменений и выполнен штатный выход: package_closed=true, logged_out=true.
Пограничный набор затем повторён в новом пакете/профиле, без восстановления прогона.
После повторного разрыва и в этой сессии восстановление выполнено только для
уборки: собственный пакет закрыт без сохранения, штатный выход подтверждён;
`package_closed=true`, `logged_out=true`, `unsaved_changes_discarded=true`.
Браузер закрыт после этих подтверждений. Никакой прерванный прогон не возобновлялся.
Первоначальная попытка 03.11 сохраняет исторический UNSAVED_CHANGES и
неподтверждённое закрытие той прежней серверной сессии; новый пустой документ
не выдаётся за доказательство её закрытия.
