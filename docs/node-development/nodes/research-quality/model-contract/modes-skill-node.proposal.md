# Качество данных — предложение LAB-1103

Это проект расширения этапа 1, не описание принятой поставки.
Штатный узел `research.quality`, один табличный вход, пять выходов.
Скрытые MaxNullsPercent/ActionNull/ActionOut/ActionExtr не являются параметрами UI.
Мастер сообщает, что отдельного мастера Quality нет: только выходные поля
и описание узла. Входной редактор задаёт имя, метку, тип, вид и назначение поля.

<!-- mode: profile -->
`mode:profile`, `parameters:{}`. Проект расширяет вход: boolean/discrete,
datetime/continuous, integer/real как continuous или discrete, string/discrete.
Variant на входе и continuous string не исследованы и не входят в проект.
Не создавай новый режим только ради типа входного столбца.

Запроси все `read.ports:[0,1,2,3,4]` со свежими полными результатами.
Порты 0/3 сохраняют всю исходную таблицу, 1/2 могут быть пустыми при положительных
Out/Extr в SummaryTable. Их подписи не задают фильтр строк.
Схема 4: N, DisplayName, DataType, DataKind, Null, Out, Extr, Avg, Moda, Median.
Строки соответствуют входным полям в исходном порядке; NULL отличается от пустой строки.

Для числовых полей, включая discrete, Moda — центр интервала гистограммы;
для string/boolean — частотная мода. На A/B при ничьей наблюдена B.
Avg(boolean) — доля true среди непустых, Median(boolean) — NULL.
Для дат Avg/Median и показанная Moda представлены числовыми серийными днями,
не ISO-строками; входные/проходные даты остаются datetime без часового пояса.
Точные значения и variant subtype проверяет ограниченный native reader;
поддержку boolean Moda нужно добавить в собственном quality-moda, не в общем
decoder. На этапе 0 нативные теги boolean/date Moda не прочитаны: это отдельный
обязательный preflight до модельной приёмки, не основание ослабить проверку.

После смены входа выполни узел и читай новые сводки. Отдельный saved-model apply
и настройка скрытых действий через UI не наблюдены; их нельзя обещать.
Сохрани пакет, проверь CSV, холодное выполнение и уборку.
