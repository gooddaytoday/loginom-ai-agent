# Предложение приёмки research.quality / profile

Комплект этапа 0, до реализации и до модельных прогонов. Критерии требуют
утверждения. Нативное исследование не объявляется PASS обработчика или cold-check.

## Входы и изоляция oracle

- Основной сценарий: `task.md`, `data/diagnostic.csv`, `data/update.csv`.
- Числовые границы: `probe/task.md`, `probe/data/probe.csv`, `probe/data/boundary.csv`.
- `fixtures/empty.csv` и `fixtures/null.csv` — заготовки дополнительных границ;
  не добавлять их к утверждённым модельным сценариям без зафиксированного исхода.

Модели выдаются только задание и соответствующий каталог data/. `oracle.py`,
expected, discovery и model-contract находятся вне её workspace. CSV в data/
должны побайтно совпадать с одноимёнными входами fixtures/.
UTF-8, заголовок, `,`, десятичная `.`, ограничитель `"`, NULL `?`;
`""` — строка длины 0, отличная от NULL.
Типы задаются в заданиях и SCHEMAS oracle, автоопределение не является критерием.

## Независимые вычисления

`oracle.py` читает только CSV и SCHEMAS. Python standard library; без Loginom,
runtime, модели, пакетов стенда, сетевых входов и сторонних статистических библиотек.
Рациональные числа `Fraction` используются до финального округления результата
в JSON binary64. Ожидания не извлекаются из таблиц проверяемого выполнения.

Предложенные соглашения для непрерывных чисел, без NULL:

1. `Avg = Σx/n`.
2. Дисперсия `v = Σ(x−Avg)²/n`; классификация сравнивает квадраты без корня.
   `Extr`: `(x−Avg)² > 25v`; `Out`: `9v < (x−Avg)² ≤ 25v`.
   Одно значение не считается одновременно Out и Extr. При v=0 обе категории пусты.
3. `Median = sorted(x)[n//2]` с индексом от нуля: для 1…8 это 5.
4. `Moda`: `k=ceil(1+log2(n))` равных интервалов от min до max; индекс
   `min(k−1,floor((x−min)k/(max−min)))`. Возвращается центр самого частого
   интервала, при равенстве — первого. Константный ряд имеет моду-константу.

Для дискретных строк: NULL не участвует; пустая строка участвует; мода — самое
частое значение, в проверенной ASCII-связке A/B при равенстве выбирается B.
Oracle фиксирует лексикографически наибольшее значение при равных частотах.
Нативная коллация при произвольных Unicode-ничьих не проверена; Unicode в основном
наборе имеет единственную наиболее частую строку. Avg/Median для string равны NULL.

`N` — 1-based номер входного поля. `DisplayName`, `DataType`, `DataKind` выводятся
из явных описаний полей. `Null` — число NULL по полю, а не пустых строк.
Счётчики Out/Extr вычисляются по полю, а не по числу строк выходов 1/2.
Точное поведение на равенстве ровно 3σ/5σ отдельным нативным набором не проверено;
утверждаемые файлы не содержат таких равенств. Строгие границы выше — предложение.

Штатные порты на исследованных входах: 0 и 3 — весь вход, 1 и 2 — пустые
таблицы той же схемы; 4 — итоговая таблица. Положительные Out/Extr в probe
специально проверяют, что имена портов не превращены в выдуманные row predicates.
Изменение скрытых действий над данными или MaxNullsPercent в этот режим не входит.

## Зафиксированные ожидания

| Вход | Строки портов 0/1/2/3/4 | Независимые контрольные числа |
|---|---|---|
| diagnostic | 8 / 0 / 0 / 8 / 4 | Value: Null=1, Avg=111/7, Median=2, Moda=12.5; RowID: Avg=4.5, Median=5, Moda=1.875 |
| update, предложение | 8 / 0 / 0 / 8 / 4 | Value: Null=4, Avg=1.5, Median=2, Moda=2.5 по гипотезе n=4 ненулевых наблюдения |
| probe | 36 / 0 / 0 / 36 / 8 | X: Extr=1; Y: Out=2; Z: оба счётчика 0; RowID Median=19, Moda=33.5; X/Y/Z Moda=50/7 |
| boundary | 28 / 0 / 0 / 28 / 8 | Генеральная и выборочная дисперсии дают разные решения: X — 2 Out, Y — 1 Extr по предложенной генеральной формуле |

Файлы: `expected.json`, `expected-update.json`, `probe/expected.json`,
`probe/expected-update.json`. Каждый содержит пять outputs с явными
`output_port`, `ordered:true`, `column_order:exact`.

Обновление импорта тем же node_id подтверждено нативно, но последующее чтение
Quality прервано разрывом связи. Поэтому update — предложенный критерий,
не наблюдённый численный результат. В частности, включение NULL в число
интервалов гистограммы пока не различено нативно: для четырёх действительных
значений среди восьми строк oracle предлагает k=3 и Moda=2.5; k по всем строкам
дал бы 4 и 0.375. Эту гипотезу нужно подтвердить до фиксации приёмки и модельных
прогонов; её нельзя молча подгонять после FAIL. Остальные три набора дают
одинаковое k по обоим вариантам и не закрывают эту границу.

Порты 0…3 сохраняют входные имена, типы и значения; исходные метки не назначены
заданием и проверяются с `label_any`. Поля порта 4 имеют имена Col0…Col9 и
фиксированные метки N, DisplayName, DataType, DataKind, Null, Out, Extr, Avg,
Moda, Median. Типы: integer/string/string/string/integer/integer/integer/real/variant/real.

NULL, строки, целые, размеры, схема, порядок и номера портов — точное сравнение.
Для Avg/Median: abs=1e-9, rel=1e-12. Для исходного Real четверти представимы
точно. Moda/variant в expected содержит явный `cell_type` и независимое значение;
числовые моды данных fixtures допускают однозначное ожидаемое binary64.
Приёмка должна подтвердить точный native subtype/value. Обычный Table-text даёт
для Moda только ограниченное наблюдение; численный PASS по нему запрещён.
Прежние ограничения exact variant reader не обходить и не ослаблять.

Пересчитать до прогонов:

```sh
python3 -B docs/node-development/nodes/research-quality/acceptance/oracle.py --write
python3 -B docs/node-development/nodes/research-quality/acceptance/oracle.py
```

Первый вызов генерирует предложения. После утверждения и начала модельных
прогонов expected и допуски не подгоняются под FAIL.

## Предложенные критерии этапа 1

1. Реальный узел, точный вход, все пять результатов одного выполнения; никакой
   подмены визуализатором или вычислением показателей другим узлом.
2. Все ячейки и объявленные типы, включая variant Moda, проходят независимый oracle.
3. На том же импорте и Quality смена файла даёт новые числа/размеры, связи и
   незапрошенные настройки сохраняются. Пересоздание узла не принимается.
4. Скачанные CSV всех пяти выходов проверяются полностью. Save после чтений;
   cold reopen и выполнение без повторной настройки, пять портов по тем же expected.
5. Негативные сверки должны отвергать NULL→0, неверный subtype Moda, обмен портов,
   перестановку полей/строк, пропуск метрики и сохранённый старый результат.
6. Регламент: исполнитель ≥2 PASS из 3 на одном SHA; независимая приёмка отдельно
   тем же SHA; cold PASS; `package_closed=true`, `logged_out=true`.

Предлагаемые имена сценариев run-check: `quality-default`, `quality-spikes`.
Регистрация выполняется на этапе 1, своими обвязками эти задания не запускаются.
Сначала решить адресацию пяти портов и точность variant в существующем API;
успех по первому порту не принимается за успех узла. Для разрешённой общей
правки страниц дополнительно обязательны red→green Quality/Квантование и
один живой `preprocessing.binning`. Бюджеты модели и общие deadlines сохраняются.
