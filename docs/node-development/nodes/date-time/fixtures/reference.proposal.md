# Дата и время (`transform.date_time`)

Предложение LAB-1012, не действующий навык до утверждения владельцем.

Используй `mode:"calendar"`, `parameters.fields` с точным именем datetime-поля
и полным набором его `transformations`. Сохраняются существующие календарные
и ISO-операции, включая minute/second. Конец ISO-недели остаётся ограничением
Loginom; не подставляй вычисленное значение.

Новые строковые операции: `string_year` — `%Y`, `string_date` — `%Y-%m-%d`,
`string_time` — `%H:%i:%s`; `string_custom` требует `format`.
Пример: `{operation:"string_custom",name:"Stamp",label:"Дата строкой",
format:"%Y-%m-%d %H:%i:%s.%u"}`. Выход — string, NULL остаётся NULL.
В предложенный проверяемый срез входят числовые маркеры `%Y` год, `%Q` квартал,
`%m` месяц, `%d` день, `%H` часы, `%i` минуты, `%s` секунды, `%u` миллисекунды.
Ширина дополнения нулями и поведение пользовательского редактора подлежат
живому подтверждению до реализации; expected — предложение, не факт Loginom.
Маркеры названий месяцев/дней и номер недели наблюдены в native StringFmt,
но locale/границы недель этим комплектом не утверждены.

Вход обязан уже иметь тип datetime. Этот мастер не предлагает разбор исходных
строк и перевод часового пояса; сообщи ограничение, не обещай такую операцию
данным узлом. Raw string сохраняется как исходное поле, не превращается в дату.
Не переводить гражданское время через системный часовой пояс.

Изменение одного поля заменяет только его набор преобразований; неуказанные
поля и их форматы сохраняются, `transformations:[]` очищает указанное поле.
До 12 преобразований на поле, до 128 полей. Имена результатов уникальны.
Для явного порядка выходных полей задавай полный output mapping с
`autosync:false`. `finish:"execute"`, чтение порта 0, затем отдельный Save.
