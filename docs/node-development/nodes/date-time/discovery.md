Наблюдение 01.11.2026 на Loginom 7.4.2 / mas3, Chromium 1246,
`https://app.loginom.ai/app/?testable=true`, worker назначенной пары.
Исходники — `004e96dbfa47e8b5251493ab38ae5766ecc0fa5a`.

данных импорта. До реализации сохранены фикстура, независимый Python oracle
и [expected.json](acceptance/minsec/expected.json), коммит `3963096eee`.

Корень — `MF;TF-1;WizrdMCF;DateReformWizard`; матрица — `;grdDataFormat`.
Чтение cached store этой матрицы, связанного с точным DOM-корнем, подтвердило:

| Операция | Ячейка после корня | Func | ISO8601 | Флаг | Native suffix / тип |
|---|---|---|---|---|---|
| `minute` / Минуты | `;colDoNumber_13` | 13 | false | DoNumber | MIN / integer |
| `second` / Секунды | `;colDoNumber_14` | 14 | false | DoNumber | SEC / integer |

Строки — обычная группа; `StringFmt` `%i` / `%s` не выбирались и не менялись.
Числовые суффиксы DOM — наблюдённые адреса, а не native enum.

метки `DateA (Минуты)` / `DateA (Секунды)`, `DataType=4`.
При ручной выходной раскладке источники добавлены через `rbLinks;DisplayEl`,
точные `colSourceName_DateA_MIN_1` / `colSourceName_DateA_SEC_1` и
`btnCreateMapping` в `DerivedDataSourceMappingEngineOutputPortWizard`.

После Execute `mn;mniShowDataPreview` открыл
`MF;TF-1;ModelForm;PreviewWindow;PreviewForm;DataSetForm`.
Точность подтверждена **не форматированным временем preview**, а read-only
чтением уже загруженного `$FHelper.$FData[0].$Values` этого DOM-bound dataset:
13 строк, integer-метаданные двух новых колонок, 26 числовых/NULL ячеек.
Никакие RPC, native handlers или методы вычисления не вызывались.
Все 26 значений совпали с независимыми `datetime.minute` / `.second`
для исходного `iso-weeks.csv`: например, `23:59:59 → 59/59`,
`12:34:56 → 34/56`, `13:14:15 → 14/15`, NULL → NULL.
Сырые DOM/cache и сравнение хранятся вне Git как доказательства карточки.
После чтения возник штатный `msgbox` «Восстановление сессии / Обнаружен разрыв
связи». Save и native cleanup исследовательского сеанса не подтверждены;
восстановления и discard не выполнялись, browser context закрыт, профиль сохранён.
Это ограничение исследования, не приёмочный PASS минут/секунд.

[Сценарий minsec](acceptance/minsec/task.md) отдельно проверяет два поля,
00/59, NULL и пустые ячейки, удаление только минуты DateA и сохранность DateB.
Общий reader и механизм проверки не расширяются; действуют стандартные CSV,
Save, cold и cleanup. `iso_week_end` по-прежнему исключён.

Живое наблюдение: 31.10.2026, Loginom **7.4.2**, хост mas, только

Это исследование мастера, предложение данных и критериев. Обработчик, публичная

### Выбор операций и интерфейс

Палитра: `MF;TF-1;ModelForm;colVendors_Компоненты>Трансформация>Дата_и_время;TreeText`.
Создан собственный черновик, затем узел; исследовались только собственные данные.
После подключения текстового импорта входной порт 0 имеет `RowID:integer`,
`DateA:datetime`, `DateB:datetime`. На шаге преобразований показываются только
DateA/DateB; переключение поля меняет его собственную матрицу.

Корень мастера — `MF;TF-1;WizrdMCF;DateReformWizard`, список полей — `;grdColumns`,
матрица — `;grdDataFormat`, группа ISO — `;grdDataFormat;tbl;GroupHeader;true`.
Нового отдельного переключателя режима или порта нет: это группа строк того же
мастера, вход 0 / выход 0 остаются табличными. Заголовки флагов — `;colDoNumber`,
`;colDoDateTimeFirst`, `;colDoDateTimeLast`, `;colDoString`.

| Наблюдённая операция | Группа / строка | Наблюдённый ключ `(Func, ISO8601)` | Флаг / ячейка `data-tid` после корня | Выход |
|---|---|---|---|---|
| `iso_year` | ISO / Год | `(4, true)` | `DoNumber` / `;colDoNumber_22` | integer |
| `iso_week` | ISO / Неделя | `(7, true)` | `DoNumber` / `;colDoNumber_25` | integer |
| `iso_week_start` | ISO / Год + Неделя | `(2, true)` | `DoDateTimeFirst` / `;colDoDateTimeFirst_21` | datetime |
| `iso_week_end` | ISO / Год + Неделя | `(2, true)` | `DoDateTimeLast` / `;colDoDateTimeLast_21` | datetime |
| `day_of_week` | Обычный / День недели | `(11, false)` | `DoNumber` / `;colDoNumber_11` | integer |

Суффиксы `_21` и т.п. — наблюдённые DOM-адреса, **не** постоянные native enum.
Связь установлена по read-only cached store матрицы соответствующего `data-tid`;
29 строк, из них 19 обычных и 10 ISO. Для действий использовались только

У ISO «Неделя» нет checkbox начала/конца; эти флаги есть у «Год + Неделя».
Строковые представления и остальные ISO-строки в предложение не включены.
Для исследованных действий пробела `data-tid` не обнаружено.

### Выходные поля и отличие от обычного календаря

Штатный контекстный пункт выходного порта `mn;mniConfigurePort` открывает
`MF;TF-1;WizrdMCF;DerivedDataSourceOutputSocketWizard;grdTargetColumns`.
Чтение cached records этого грида подтвердило типы integer (`DataType=4`) и
datetime (`DataType=2`), все добавленные поля непрерывные (`DataKind=1`).
Ниже `L` — текущая метка входного DateA; никакой суффикс номера не следует угадывать.

| Наблюдённое имя | Метка | Тип |
|---|---|---|
| `DateA_Y_1` | `L (Год)` | integer, прежняя операция `year` |
| `DateA_DW_1` | `L (День недели)` | integer |
| `DateA_YW_1` | `L (Год + Неделя, Последний день, ISO8601)` | datetime |
| `DateA_YW_2` | `L (Год + Неделя, Первый день, ISO8601)` | datetime |
| `DateA_Y_2` | `L (Год, ISO8601)` | integer |
| `DateA_WY_1` | `L (Неделя, ISO8601)` | integer |

ISO-год и календарный год используют один префикс `_Y_`; начало/конец недели —
`_YW_`. Прежнего соответствия `Func + flag` недостаточно: нужны также ISO-признак,
точная метка с `, ISO8601` и реальная связь source→target.
В наблюдённом порядке «Последний день» оказался перед «Первым днём»;
порядок checkbox-действий и числовой суффикс не доказывают назначение столбца.
Настройка только DateB сохранила уже выбранные шесть преобразований DateA.
Импорт и результат содержат 13 строк, в том числе NULL. Раскладка предложения
задаётся явно; для неё сохраняется существующее требование `autosync=false`.

### Наблюдённое расхождение конца ISO-недели

`iso_week_end` не вводится до исправления в Loginom (решение оркестратора 31.10).

После Execute первый preview показывал следующие значения DateA. Повторный Execute
после добавления пяти операций DateB оставил оба расхождения DateA без изменения.

| Вход DateA | ISO год / неделя | Начало в UI | Конец в UI | Независимый конец ISO |
|---|---|---|---|---|
| 2016-01-01 00:00:00 | 2015 / 53 | 2015-12-28 | 2016-01-03 | 2016-01-03 |
| 2018-12-31 23:59:59 | 2019 / 1 | 2018-12-31 | **2018-12-30** | **2019-01-06** |
| 2021-01-01 00:00:00 | 2020 / 53 | 2020-12-28 | 2021-01-03 | 2021-01-03 |
| 2024-12-30 00:00:00 | 2025 / 1 | 2024-12-30 | **2024-12-29** | **2025-01-05** |

На втором поле DateB даты 2019-01-01 и 2025-01-01 дают корректные воскресенья
2019-01-06 и 2025-01-05. Следовательно, смешение двух входных полей не объясняет
наблюдение. Это локализованное наблюдение UI, не доказанная внутренняя причина
ошибки Loginom. Preview показывает время до минут (`12:00 AM`); секунды,
миллисекунды и сохранность после холодного открытия этим не подтверждены.
Сравнены 104 отображаемые ячейки ISOYear/ISOWeek/WeekStart/WeekEnd двух полей:
два расхождения, оба описаны выше. NULL отображается пустой ячейкой; строгий
NULL/type-check остаётся задачей стандартного cold-check.

Источник наблюдения: вложение карточки `iso-weeks-evidence.zip`, файлы
`iso-matrix.json`, `iso-output-schema.json`, `iso-preview.json`,
`iso-preview-b.json`, `iso-preview-comparison.json` и PNG. Точные адреса, например:
`MF;TF-1;ModelForm;PreviewWindow;PreviewForm;DataSetForm;normalHeaderCt;DateA_YW_1_4`
и `...;DateA_YW_1_10`. Артефакты не являются oracle.

Решением оркестратора 31.10 утверждены четыре операции: `iso_year`, `iso_week`,

Ожидания [acceptance/expected.json](acceptance/expected.json) вычисляются независимым

понедельник по ISO weekday, гражданские даты без timezone conversion,
начало недели в полночь, NULL→NULL. Расчёта и столбцов конца недели в oracle и
обоих expected нет; все исходные строки, включая две даты расхождения, сохранены.
Файлы fixtures синтетические; формат, типы, размеры и SHA — в
[iso-manifest.json](fixtures/iso-manifest.json).

Основной сценарий [task-iso-weeks.md](acceptance/task-iso-weeks.md): импорт → один
целевой узел → удаление только дня недели DateA из того же узла → Save.
Проверяются все 13 строк и 12 столбцов: два поля, ISO/обычный год одновременно,
неделя 53/1, декабрь следующего ISO-года, воскресенье/понедельник, високосный день,

Дополнительный [пустой сценарий](acceptance/task-iso-weeks-empty.md) предлагает ту же

### Оценка этапа 1

Утверждены четыре новых значения operation в существующем `mode=calendar`:
[iso-operations.proposal.json](fixtures/iso-operations.proposal.json).
Нового top-level mode/type, параметра и порта нет. Сохраняются лимиты 128 полей и
12 преобразований на поле: новый набор не означает возможность выбрать все 16
старых и новых операций одного поля одновременно.

Полная `dock_node_apply.inputSchema`, minified UTF-8 JSON на базовом SHA:
**34 972 Б → 35 025 Б, +53 Б** за четыре enum-значения; запас до 46 000 Б — **10 975 Б**.
Текст tool description и будущая редакция ограничений в эти числа не включены.
Воспроизведение: `node docs/node-development/nodes/date-time/fixtures/measure-iso-schema.mjs`.
Скрипт клонирует полную схему в памяти, runtime не меняет. Предел 46 000 Б не
используется как стоп этапа 0; сжатие общей схемы не предлагается.

Утверждённая оценка: **2 цикла** реализации с бизнес-прогоном после каждого,
ориентировочно 80–160 строк в четырёх файлах узла:

1. `date-time-parameters.mjs`: четыре операции с явным ISO-признаком;
   `date-time-procedure.mjs`: выбирать по `(func, iso, flag)`, сохраняя обычные строки.
2. `date-time-output.mjs` и `date-time-removal.mjs`: ISO-метки, разрешение источников,
   удаление ISO-преобразования без ложных orphan/смешения с календарным годом.

`date-time-context.mjs`, `date-time-readback.mjs`, `date-time-continuation.mjs` уже
хранят ISO-признак; необходимость их изменения не обнаружена. Нужны адресные
расширения существующих тестов параметров/настройки/выходов/удаления/continuation.
Сопутствующее аддитивное изменение общей точки регистрации: enum и описание в
`node-api.mjs`, актуализация ограничений узла в продуктовых справочных материалах.
Общая оболочка, `packages/agent`, форматы readback, бюджеты и deadline изменений
не требуют по результатам этого исследования. Нативное расхождение конца недели
не предлагается исправлять в общем runtime или маскировать новой верификацией.
