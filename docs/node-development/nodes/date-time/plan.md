## 3. Данные и независимые проверки

Комплект `nodes/date-time/acceptance/` собирает будущая карточка:

- `task.md` на бизнес-языке с `{{PACKAGE_PATH}}`; без имён инструментов и ожидаемых чисел;

- `expected.json` из независимого `oracle.py` до прогона; адресные наборы — `fixtures/` с manifest (байты, SHA, формат, типы, порядок).

Прежние входы: `fixtures/date-time/sales.csv`: 413 байт, 10 записей, колонки `Id, DateA, DateB, Amount`, разделитель `;`; кодировка UTF-8, NULL-маркер `NULL`. Размеры и SHA сохранить в manifest до прогона.

Ожидания прежнего контракта: Из `date_time_goal_oracle.py`, `date_time_oracle.py` и expected.json: все 10 строк, числовые year/quarter/month/day_of_month/hour и datetime начала/конца периодов/date. Прежний Gregorian oracle задаёт конец периода как последний календарный день в 00:00:00.000; это гипотеза для текущего стенда, не 23:59:59.999.

Матрица сохранена из прежнего подплана; ожидания и неоднозначные правила переподтвердить до модельного прогона:

| Случай | Вход/изменение | Независимая проверка |
| --- | --- | --- |
| Високосный день | 2024-02-29T13:14:15,2023-02-28T23:59:59,2024-03-01T00:00:00. | Для первой строки year=2024/quarter=1/month=2/day=29/hour=13; date и начала периодов в полночь. Точный last-instant для end функций зафиксировать по принятой семантике отдельно, не угадывать 23:59:59 или миллисекунды. |
| Границы | 31 марта→1 апреля,31 декабря→1 января; два datetime-поля одной строки. | Независимая календарная таблица ожидаемых кварталов/лет, начало и конец периодов для каждого поля; не смешивать поля при одинаковых метках. |
| NULL/empty | Настоящий NULL и header-only typed input. | NULL сохраняет предусмотренную нативную семантику, пустая таблица имеет полную ожидаемую схему и типы. |
| Existing/persistence | Добавить month к year, убрать hour, поменять имя/метку и порядок выходов. | После save/reopen конфигурация и все значения совпадают без повторной передачи transformations; никакой «восстановительной» настройки из expected. |

Oracle не импортирует handler/runtime, рассчитывает по исходным байтам, сверяет все ячейки и схему, отличает NULL/пустую строку/0, отвергает чужой узел, старое исполнение, неполное чтение и подмену данных. Freshness, происхождение и настройки доказываются отдельно от правильных значений.

Cold-check: схема проверяется позиционно (имена, метки, типы), строки — как мультимножество, до 100 строк/выход и 32 выходов (`scripts/node-acceptance/expected-outputs.mjs:14,29-39,72-81`). Числа сравниваются точно (`cold-check.mjs:232`); большие Int64 — десятичные строки. Каждый ожидаемый выход однозначно связан с типом и меткой узла. E2E-снимки мастера не являются oracle.

## 5. Ловушки — переподтвердить, не копировать

- String вместо datetime, ISO-week/неизвестная операция, дубль операции, коллизия output с input, autosync=true при явном layout: отказ до мутации.
- Исчезнувший источник либо changed owner при редактировании: не применять преобразование соседнему полю.
- Потеря ответа после Apply/removal/Execute: точная сверка фазы без повторного добавления; аудитор отвергает старые даты, неправильный тип и частичный output.
- Для изменённых фаз отдельно различить отказ до эффекта, известную ошибку с подтверждённым cleanup и неизвестный эффект. Повтор operation_id не создаёт второй узел/запуск; lost reply не оправдывает слепой retry. Чужой пакет и посторонние связи неизменны.
- История 13: configure, manual-output и terminal gates принимались отдельно; полный goal не следовал из этих адресных PASS. Новые/удалённые поля при autosync=false должны синхронизироваться без фантомной схемы.
- Приёмки текущего CLI нет; неподтверждено: конец периода/NULL и точность дат/производительность чтения текущего CLI. Исторические замеры/локаль/платформа не являются гарантией текущего стенда.
