# 13. Дата и время: подплан сопровождения и приёмки

[Карточка и принятые границы](README.md) · [реестр](../../registry.json) · [работа с одним узлом](../../workflow/single-node.md).

Обработчик `transform.date_time` уже реализован в режиме `calendar`. Этот подплан адаптирует исторический 13 к текущему runtime и standalone CLI: это маршрут адресного исправления, проверки переноса или отдельно назначенного расширения, не повторная разработка с нуля. Историческое принятие сохраняется в своём scope; технические Desktop проверки не являются аналитической CLI-приёмкой. Новых живых наблюдений и прогонов при составлении документа не было, readiness не повышается.

До начала выбрать точное изменение и пройти [подготовку/жизненный цикл](../../workflow/lifecycle.md). Разработчик работает в Astra medium в своей задаче, ветке и worktree. Первичная разработка получает Goal до готовности изменения к первому ревью, без собственного token_budget. Этот документ не назначает следующий узел и не разрешает слияние.

## Узловые требования

Calendar принимает уже типизированный datetime. Двенадцать операций: year, quarter, month, day_of_month, hour; year_start/year_end, quarter_start/quarter_end, month_start/month_end и date. Несколько преобразований одного/разных полей разрешены; повтор операции одного поля — нет.

До128 исходных полей и 12 преобразований на поле. Выходные имена ASCII, уникальны и не конфликтуют с входами. Явная выходная раскладка требует autosync=false. Строковый парсинг, ISO-недели, timezone conversion и произвольное форматирование вне scope.

## Шаги изменения

1. В DATE_TIME_OPERATIONS сопоставить operation, native enum Func и флаг; позиция строки или совпавшая локализованная метка не заменяет это соответствие.
2. До настроек разрешить только точные datetime-поля и полную будущую схему имён; проверить несколько операций и несколько исходных полей.
3. Применить добавление/удаление преобразований, проверить native настройки и итоговые типы integer/datetime. Existing patch должен сохранить неуказанные свойства и правильную связь output.
4. Проверить date-time-output-additions/removal и mapping при autosync=false: новые поля добавлены, удалённые не остаются фантомными, порядок согласован.
5. Сравнить все результаты календаря независимым oracle без timezone host-преобразований. Чтение точных дат и сохранение .lgp — отдельные доказательства, длительный preview не заменять округлённой выборкой.

## Независимые fixtures и oracle

Ниже — обязательная узловая матрица для объявленного полного scope. При адресном исправлении выбрать затронутые строки и обосновать выбор; расширение режима добавляет новые строки. До автономной попытки сохранить входы и expected отдельно от handler, с версиями и SHA. Ожидания не вычислять импортом реализации и не подгонять по её приёмочному выводу.

| Случай | Вход/изменение | Независимая проверка |
| --- | --- | --- |
| Високосный день | 2024-02-29T13:14:15,2023-02-28T23:59:59,2024-03-01T00:00:00. | Для первой строки year=2024/quarter=1/month=2/day=29/hour=13; date и начала периодов в полночь. Точный last-instant для end функций зафиксировать по принятой семантике отдельно, не угадывать 23:59:59 или миллисекунды. |
| Границы | 31 марта→1 апреля,31 декабря→1 января; два datetime-поля одной строки. | Независимая календарная таблица ожидаемых кварталов/лет, начало и конец периодов для каждого поля; не смешивать поля при одинаковых метках. |
| NULL/empty | Настоящий NULL и header-only typed input. | NULL сохраняет предусмотренную нативную семантику, пустая таблица имеет полную ожидаемую схему и типы. |
| Existing/persistence | Добавить month к year, убрать hour, поменять имя/метку и порядок выходов. | После save/reopen конфигурация и все значения совпадают без повторной передачи transformations; никакой «восстановительной» настройки из expected. |

## Негативные случаи

- String вместо datetime, ISO-week/неизвестная операция, дубль операции, коллизия output с input, autosync=true при явном layout: отказ до мутации.
- Исчезнувший источник либо changed owner при редактировании: не применять преобразование соседнему полю.
- Потеря ответа после Apply/removal/Execute: точная сверка фазы без повторного добавления; аудитор отвергает старые даты, неправильный тип и частичный output.
- Для изменённых фаз отдельно различить отказ до эффекта, известную ошибку с подтверждённым cleanup и неизвестный эффект. Повтор operation_id не создаёт второй узел/запуск; lost reply не оправдывает слепой retry. Чужой пакет и посторонние связи неизменны.

## Автономная проверка и передача

Подготовить календарные признаки и границы периодов для двух дат, сгруппировать согласованный показатель по месяцу и сохранить пакет; независимо проверить все даты и агрегаты.

Первичная отладка — штатными скриптами текущего runtime в назначенной изоляции. После неё выполнить адресные source tests и проверить независимый oracle, включая его отказ на подменённых значениях/схеме/идентичности. Только затем подготовить неизменный candidate и получить слот по [CLI-регламенту](../../workflow/acceptance-cli.md): standalone CLI Loginom AI Agent, Sol low, согласованная подписка, бизнес-цель и входные файлы без пошаговых UI-команд.

Критерий аналитического PASS — полный малый output/артефакт, проверенная схема и настройки, новый execution и сохранённый пакет, которые независимо воспроизводятся после отдельного открытия. Configure-only и Close проверяются отдельно; обычный продуктовый путь не переоткрывает мастер ради повторной проверки. Непроверенные платформы, большие наборы и дополнительные режимы остаются явно ограниченными.

Передать checkpoint с точными source/runtime/client/model/platform pins, заявленным scope, результатами и неизменёнными исходными FAIL. Техническое завершение, аналитическая проверка, integration и release — отдельные состояния реестра. Один этап ревью и один раунд исправлений выполняются по общему жизненному циклу; этот подплан не добавляет повторного полного ревью.
