# Managed evidence physical-close contract

node-orchestration-v2. This correction is confined to managed-entry recordClose and its tests. Node24 FileHandle.close retires fd and emits its close event before returning the original native close promise; neither observation proves kernel completion. Lost/early fulfilled wrapper responses cannot release the original writer.

The managed producer instead owns raw descriptors from the supported Node fs callback API. Its close operation is registered on the existing foreground state before invocation. Only the success callback of that original fs.close operation marks completion; the function's return value, descriptor projection, later EBADF or another close never does. Callback errors and synchronous Error/undefined/null/false/0/empty throws are failures; unresolved callbacks remain UNKNOWN. A late genuine callback may complete the original operation, permitting evidence-only repair without another file/native/bridge close. No timeout or PID projection creates ACK.

Every owned writer stays registered until its original close callback succeeds. write→file fsync→confirmed close→parent directory fsync→confirmed directory close precede return. Primary write/sync failure is independent of secondary close/persistence failure; the first value/cause persists on owner/evidence. UNKNOWN blocks opening the next writer, release/profile removal/outer ACK. Confirmed bridge/startup cleanup remains cached and is not replayed by storage retry. Existing strong cleanup/logout, drain, identity and ownership guards stay unchanged.

Tests use genuine Node FS descriptors and kernel completion, with explicit callback fault injection and scripted message IPC children. Native/Page/bridge/context are doubles. A throw after scheduling original kernel close retains its callback transaction; an early function return is ignored; a missing success callback remains unknown even after actual kernel close. No native teardown/current-resource PASS follows from these controls.
