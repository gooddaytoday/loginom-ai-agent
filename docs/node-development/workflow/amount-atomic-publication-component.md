# Amount atomic publication prerequisite

This is a private bridge writer component above reviewed close39, not native
admission or a completion grant. Constructor retains original directory,
metadata and sessionId before its first await; evidence binding cannot be minted
from a substituted tuple. Publication retains the same immutable bytes/temp and
original tuple before IO. No public route, RPC/opcode, module selector, callback
or owner capability is introduced.

The accepted INPUT69 cccc/e422/c795 operands are adapted only at the defining
private writer: captureRename/constants, prepared/publication retention, guarded
atomic rename and owned callback/projection settlement. Existing main47 FD
lifetime, original diagnostics destination, close39 raw first/secondary and
owner/abort/expiry guard are preserved. Unchanged delivery/consumer algorithms
are not transplanted. Kernel facts and original execution-journal IO are tested
separately from named binding/native/SDK conformance operands.

A temporary is created 0600 with O_EXCL/O_NOFOLLOW, written once, synced, fstat
identity retained and physically closed. Before publication, original tuple,
directory inode/UID and temp inode/UID/size/mode/link identity are rechecked.
Existing unowned receipt files are refused. Original rename callback and returned
projection both settle before directory sync/close and journal/receipt completion.
Early failure retains pending until peer settlement. A throw without callback,
or physical rename with rejected projection, stays uncertain and cannot replay
rename or complete evidence. Same-tuple repair reuses confirmed temp/bytes;
failed callback EISDIR can retry storage after its original projection settles.
A completed publication/journal is cached without read/browser/native replay.
Foreign metadata remains unchanged; diagnostics belong to constructor origin.

Remaining completion ABI is explicit: managed-entry currently emits static
{frame,settled:true,evidenceSettled:false,cleanupSettled:false,acknowledged:false}
and HostPort preserves LOGINOM_AMOUNT_PHYSICAL_SETTLEMENT_UNAVAILABLE. Neither
publication success nor an idle FD/fixture exit replaces original bridge/native
cleanup proof. Original workspacePreparation/managedSave admission still refuses
before consumer read. Original bridge must later retain capture evidence bytes,
metadata/destination/journal and physically confirmed cleanup tuple, then bind
completion to existing outer/managed/capture IDs and same child/current owner.
Unknown/lost journal effect needs an original per-record physical disposition;
only confirmed storage-only repair is claimed here. Full journal/native cleanup,
whole writer union/consumer/ACK and embedded factory remain NOT_QUALIFIED.

The addressed runner executes literal production private persistence/readonly
repair on real kernel FS and production execution-journal with named signal,
binding, callback/projection faults. Positive is bounded storage evidence only;
no native/Page/model/Save/Close/ACK/release authority follows from it.
