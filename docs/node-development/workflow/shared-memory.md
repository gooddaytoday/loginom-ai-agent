## Подключение следующего узла

Следовать [CURRENT.md](../../../services/loginom-ai/tools/project-memory/CURRENT.md):
создать отдельный linked worktree под `<repo>/.worktrees`, подготовить локальную
конфигурацию **до создания задачи**, выполнить bootstrap, проверить реальные
metadata и доверие hooks, активировать регистрацию, проверить actor health/find/read.
Первый содержательный результат проверить через capture/extraction и read-back.
После подготовки и до активации проектный MCP отказывает; собственный Peer не
служит запасным путём. Ещё не подготовленный worktree сохраняет обычный плагин,
поэтому порядок «сначала конфигурация, затем задача» обязателен.

Подготовка проекта уже выполнена на этой машине. Не переустанавливать её перед
каждым узлом и не использовать проверочные задачи для разработки других узлов.
Старые внешние worktrees требуют отдельного перехода с сохранением их состояния.
Откат настройки не означает откат capture cursor или удаление добавленной памяти.

Подробный отчёт и инструменты переноса находятся в проекте `~/Git/openviking`:
`docs/PEER_MEMORY_COPY_2026-09-24.md`, `integrations/peer-memory-copy/`.
