# Карточка этапа Multica

```text
Ветка: <база работы и цель PR>
Узел: <slug>
Этап: <slug:sN либо crosstable-core>
Обработать только указанный объём по каноническому подплану до независимой приёмки.
Для изменений создать отдельную рабочую ветку и PR в указанную ветку.
```

Для отдельной общей возможности заменить `Узел` на `Общая возможность: <foundation:ID>` и добавить `Подплан: docs/node-development/foundations/<slug>/plan.md`. Это требует соответствующей поддержки загруженной инструкции Генератора; нельзя выдавать такую карточку старому шаблону, который ищет только `nodes/<slug>`.

В работе используется [карта параллельности](../parallel-execution.json) и [регламент](../workflow/multica-parallel.md). Длинные инструкции в карточку не копируются. Генератор фиксирует в комментарии допуска:

- issue ID, stage/bundle и путь подплана, фактический source SHA и цель PR;
- каждый обязательный prerequisite: принятый scope, SHA, ссылка на проверенные evidence и факт включения в базу; внутренние этапы bundle — отдельно;
- выбранный профиль параллельности, native checkout, пару конфигов/аккаунтов, уникальные artifact/package paths без секретов;
- допущенные общие участки/ресурсы и условия освобождения; режим OAuth и количество разрешённых модельных попыток;
- перед передачей Reviewer: candidate SHA, PR, результаты, receipt/проверенные вложения, завершение операций Worker.

Эта запись — проверяемое назначение в Multica, не собственный исполняемый планировщик. Настройки агента, генераторные шаблоны и состояние очереди получают из Multica/обвязки; статический JSON этого репозитория не является журналом живых блокировок.
