# Пример заполнения: Кросс-таблица (15)

**Документальная проверка шаблона. Не рабочее назначение.** Статус:
`discovery_required`; новый live осмотр и разработка в этой работе не выполнялись.
Исходный [подплан 15](../../../services/loginom-ai/docs/plans/loginom-dock/15-cross-table.md)
сохранён как исторический источник, его статусы и API не подменяют текущий runtime.

## Идентификация и границы

Компонент: `component.transform.CrossTable` — Кросс-таблица из [реестра](../registry.json).
В активном списке зарегистрированных типов обработчик отсутствует. Планируемый результат:
преобразовать категорию в столбцы, агрегировав значения по ключам строк.
До ready_for_development подтвердить runtime type, редакцию Loginom и конкретные
агрегаты живым исследованием. Нельзя считать строку roadmap доказательством UI.

## Самостоятельный fixture и ожидаемый результат

Вход: `(region, month, amount)` = `(A, Jan, 2)`, `(A, Jan, 3)`, `(A, Feb, 7)`,
`(B, Jan, 11)`. Для режима суммы ожидаются значения A/Jan=5, A/Feb=7,
B/Jan=11. Правило отсутствующей B/Feb, сортировки колонок и имён полей пока
**не установлено**: его нужно наблюдать и закрепить до приёмки, не считать нулём.
Дата/время (13) не является зависимостью: категории месяцев уже заданы строками.

## Контракт, ошибки и исследование

Определить динамическую выходную схему, коллизии имён категорий, NULL категории,
пустой вход, повторную настройку с новым набором категорий и сохранность настройки.
Проверить, как ранний отказ отличается от частичной настройки. Точки реализации
выбираются в актуальном runtime после исследования; не копировать старые UI IDs.

## Проверки и критерии

| Требование | Проверка | Критерий |
| --- | --- | --- |
| Правильное суммирование | Независимый oracle fixture выше | Три известных значения совпадают |
| Пустая комбинация | Live наблюдение B/Feb | Семантика установлена до model run |
| Динамическая схема | Второй fixture с новой категорией | Правило изменения имён/типов подтверждено |
| Сохранность | Save и независимое reopening | Настройки/связи/схема/значения сохранены |
| Некорректный запрос | Адресные отрицательные случаи | Нет непроверенного повторного эффекта |

CLI получает только задачу сводной таблицы, исходный CSV и уникальный package path.
Expected и этот проверочный документ не передаются. GPT-6 Sol (`openai/gpt-6-sol`) / low, один слот, 30 минут
по умолчанию с уточнением после discovery. Команды аудита ещё требуется выбрать
из текущих средств либо реализовать в рамках будущего узла.

## Результат проверки шаблона

Шаблон позволяет явно выразить scope, независимые expected, зависимости и
неизвестные свойства. Пример НЕ ready_for_development из-за перечисленных
пробелов discovery. Следующий шаг — назначение пользователем подготовки
подплана, затем изолированное исследование; сейчас оно не назначено.
