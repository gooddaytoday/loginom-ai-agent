## Минимальная вложенная основа

`node-workflow-activation.mjs` и WorkflowRef готовят текущий граф; `node-contracts.mjs` запрещает обычные links между workflow. Нужны отдельные bounded операции входа/выхода, refs границ и подтверждение принадлежности каждому графу; нельзя ослабить запрет всех межсценарных связей. `node-target-browser.mjs`, `workspace-ui.mjs` и cold oracle должны различать внешние/внутренние узлы и одноимённые элементы.

Первый потребитель — [Подмодель v1](../../nodes/control-supernode/plan.md): 1 table in/out, один уровень, 1–2 существующих handler. Общая навигация и boundary oracle принимаются в его назначении до узлового verdict. Этап foundation:control-flow независимо от вложенной навигации добавляет служебные связи активации/деактивации и наблюдение выбранной/заблокированной ветви. Он проверяется в одном root workflow: два независимых узла с различимыми результатами должны выполняться только согласно заданной управляющей связи. Наличие navigation_path не доказывает такую поддержку.

Проверки: root→inner→root, несовпадающий родитель, две одноимённые Подмодели, смена UI epoch, сохранение/новое открытие, отмена на каждом переходе. Fixture x=[1,2] через внутреннее x+1 возвращает [2,3] с точными связями через границы.

## Производные компоненты

[Help](https://help.loginom.ru/userguide/workflow/derived-component.html), [доступ](https://help.loginom.ru/userguide/workflow/access-modifier.html) и [ссылка на пакет](https://help.loginom.ru/userguide/workflow/reference-to-package.html) описывают отдельные объекты. План охватывает создание/редактирование/удаление производного компонента, привязку к базовому ref, область видимости и разрешённые типы потомков. Не регистрировать бесконечное множество пользовательских компонентов как стандартные node IDs.

Проверять наследование обновлений, собственные переопределения и возврат исходной конфигурации; запрещённые изменения портов/полей не обходить прямой записью. Закреплять точную версию внешнего пакета и его доступность. Искать по имени/комментарию можно, выбирать источник — только по наблюдённой identity. Настройки доступа вложенных подключений проверять независимо от доступа компонента.

Минимальный reusable fixture — существующий табличный Calculator; полный handler Подмодели не обязателен. Для матрицы наследования два потомка получают изменение базы, один с переопределением сохраняет собственную настройку; сброс возвращает наследуемую. Закрытый источник недоступен вне области, открытый с ссылкой на пакет доступен, скрытая метка и рекурсивные производные уровни проверяются отдельно. Удаление компонента/исчезновение пакета даёт явный отказ без привязки к совпадающей метке.

## Независимая приёмка

Cold oracle проверяет nested paths, граничные/служебные связи и ссылки на базовый компонент, а не только root node types. Все порты переменных/деревьев принимаются после соответствующей typed foundation. Обученные собственные конфигурации — после foundation:training. Ошибка источника и неоднозначная навигация сохраняют evidence и не дают повторного запуска неизвестного эффекта.

## Приёмка и продолжение

Назначение закрепляет одного владельца общей возможности, базовый SHA и конкретный принимаемый scope. Проверить существующих потребителей и отказ неизвестных/несовместимых запросов до эффекта. Команды Node tests выполнять из `packages/loginom-runtime/client`; новые test filenames и контракт фиксируются в этапе discovery. После реализации — независимые приёмочные доказательства на чистом SHA по RUNBOOK. Непроведённые проверки остаются `not_checked`.

Потребитель не должен ждать всех будущих режимов общей возможности: его обязательное ребро означает только описанный в этом подплане минимальный принимаемый контракт. Не переносить незавершённую ветку соседа; общую работу разрешено выполнить в одном назначении с первым потребителем, отдельно доказав её критерии. Изменения контракта сверх этого подплана требуют решения владельца.

Текущий результат: статическое исследование; реализации и live-проверок здесь не было. Следующий шаг — адресное discovery и фиксация интерфейса/ожиданий. Checkpoint до 20 строк.
