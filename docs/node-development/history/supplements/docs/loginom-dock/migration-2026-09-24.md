старше после успешного создания и проверки новой. Проверка и удаление выполняются

при ошибке создания/проверки старые копии не удаляются. Посторонние папки, ссылки и
незавершённые архивы автоматически не удаляются. Расписание — ежедневно 05:00 МСК.

4,18 GB архивов образов. Образы сейчас экспортируются независимо в каждую копию:
семь ежедневных копий — примерно 36,6 GB (34,1 GiB), временно при создании восьмой —
41,9 GB (39,0 GiB). Планировать 45 GB с запасом; размер растёт вместе с данными.
Незначительный сдвиг времени завершения может временно оставить дополнительную копию
в скользящем семисуточном окне. На момент настройки свободно 64,0 GB.

код установлен в действующий toolkit без остановки сервиса. Текущих копий после
предыдущего удаления нет — правило начнёт применяться к новым ежедневным копиям.

## Текущие эксплуатационные команды

На новом VPS все команды выполняются от root. Для пассивной доступности использовать
`/health`; `/ready` обращается к моделям и расходует средства.

```sh
python3 /opt/loginom-dock/tools/memory-maintenance.py monitor --root /opt/loginom-dock/current-memory
python3 /opt/loginom-dock/tools/memory-maintenance.py backup --root /opt/loginom-dock/current-memory
systemctl list-timers 'loginom-memory-*'
```

Backup кратковременно останавливает только работающие компоненты памяти и затем
возобновляет именно их. TLS вход остаётся запущенным; в этот период возможен 502.
Копии старше семи суток удаляются после проверки новой; монитор отмечает свободное место ниже 10 GiB
и возраст последней копии более 48 часов. Результат записывается в
`current-memory/monitoring/health.json` и systemd journal; внешняя доставка уведомлений
не настраивалась. Off-host копия текущего переноса проверена; последующие копии следует
выносить с VPS операторской процедурой, не размещая ключи доступа в Git.

Ручное обновление GitLab использует профиль sources текущего production compose,
его `tunnel/gitlab.sock` и защищённый операторский SSH-канал. Сначала native dry-run
обоих manifests (`sources.yaml`, `sources-loginom-help.yaml`), затем только явно
запрошенный импорт. По окончании закрыть туннель и остановить optional services.
Туннель обновления знаний не является VPN для моделей.

На старом VPS обслуживать только сайт инструментом
`python3 /opt/loginom-dock/tools/site-maintenance.py backup|monitor`.
При новом выпуске сайта сохранять блок app.loginom.ai и отключённый старый origin памяти;
не использовать прежний полный compose up для deployment сайта.
