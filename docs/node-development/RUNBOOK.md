# Разработка и техническая приёмка узлов

Инструкции относятся к клиенту. Подготовка окружения, аккаунтов и управление задачами задаются внешним операционным руководством.

1. Уточнить component ID, slug, режимы, критерии и закреплённый базовый SHA из назначения. Изучить подплан узла `nodes/<slug>/plan.md`. Если это черновик требований, сначала переписать его по [шаблону](templates/node-plan.md); образцы — [Кросс-таблица](nodes/transform-crosstable/plan.md) и [Скользящее окно](nodes/transform-slidingwindow/plan.md).
2. Исследовать интерфейс штатными средствами runtime с `?testable=true` в собственном аккаунте. Сверить Help и существующие E2E. Не заменять наблюдения догадками. Результат записать в `nodes/<slug>/discovery.md`. Ожидаемые числа, типы и порядок строк записать до модельного прогона.
3. Реализовать обработчик в `packages/loginom-runtime/client/lib`, сохранить контракты Host и Agent. Адресные тесты запускать из пакета. Durable journal и подтверждения закрытия пакета и выхода обязательны.
4. Собрать standalone CLI закреплённым Bun 1.3.14 и источниками Node/Chromium из product release manifest. Для промежуточного клиента допустим `--no-archive`:

```sh
cd packages/loginom-host
bun run script/build-cli.ts /absolute/new-output --no-archive
```

Без флага создаётся обычный релизный архив с checksum и проверочной распаковкой. Оба режима сохраняют манифест, SHA исходников и проверку целостности. Сборщик не перезаписывает выход. Повреждённый клиент пересобирается.

5. Выполнить полный CLI-сценарий из `nodes/<slug>/acceptance/task.md` под назначенной моделью с пределом 7200 секунд. Модель получает задание и входные данные; oracle, ожидаемые числа и история дефектов остаются вне её контекста.
6. Независимо открыть сохранённый пакет в новом браузерном профиле и выполнить `scripts/node-acceptance/cold-check.mjs` из того же checkout. Проверить граф, числа, типы, порядок строк и `package_closed=true`, `logged_out=true`. Убийство процесса и код 0 без этих подтверждений не означают PASS.
7. Перед проверкой опубликовать чистый SHA. Независимый проверяющий проверяет именно его под другим аккаунтом. PASS старого SHA не доказывает новый. Сохранить результат, манифест и проверенные доказательства без секретов.

Технические рекомендации: [приёмка CLI](workflow/acceptance-cli.md), [цикл узла](workflow/single-node.md), [возобновление](workflow/lifecycle.md). Реестр описывает границы подтверждённой готовности, а не назначает работу.
