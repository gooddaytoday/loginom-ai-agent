# Loginom Hub: архитектурные решения

Каталог навыков и действий Loginom AI Agent: формат, подпись, уровни доверия, политика администратора, угрозы и
выкладка. Код — этап E плана; здесь — решения, на которые он опирается.

Статус: ADR-0001…0003 и модель угроз приняты владельцем 18.11.2026 («делаем как ты рекомендуешь»), черновик
выкладки — черновик. Решения — В-34…В-62 в [decisions.md](../product/loginom-agent/decisions.md).

Что сменило прежний план (этап A4 и «Целевая архитектура»):
- отдельного сайта с бэкендом нет: каталог — подписанные статические файлы, сайт каталога собирается из них
  (В-38, В-51); сервис публикации — отдельно и позже;
- подпись не в GitHub Environments и вход не через GitHub OAuth (В-38…В-40);
- конверты DSSE на каждый элемент не нужны: подписаны метаданные TUF, в них хеши всех файлов (ADR-0002).

## Решено 18.11.2026

- **В-58. Ключи подписи.** Корневых ключей два, хватает одного: основной у владельца, запасной хранится отдельно.
  Это защита от потери, но не от кражи; когда появятся сотрудники Loginom — 2 из 3. targets и `loginom` — офлайн у
  владельца. Ключ «Проверено Loginom» — у проверяющего на его компьютере, не на сервере сборки (уточняет В-40). Раз
  в год владелец переподписывает root, targets и `loginom`, проверяющий — `verified`.
- **В-59. Что публикуют другие.** Навык и Действие; Готовый сценарий и Подключение — только от Loginom.
- **В-60. Срок файла для закрытого контура** — 180 дней. После срока установленное работает, а ставить и обновлять
  из этого файла нельзя; за 30 дней приложение предупреждает.
- **В-61. Каталог организации** — свой подписанный каталог, ключ у администратора, создаётся программой от Loginom;
  корень рядом с `policy.json`; отметка «Организация», работает как «Проверено Loginom». Делается после публичного
  каталога.
- **В-62. Навык из файла в закрытом контуре** — как «Сообщество»: только если разрешил администратор.
