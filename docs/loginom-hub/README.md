выкладка. Код — этап E плана; здесь — решения, на которые он опирается.

[decisions.md](../product/loginom-agent/decisions.md); остальное — предложения, вопросы по ним — в разделе
«Открытые решения» каждого документа и на странице «Что решить» прототипа.

Что сменило прежний план (этап A4 и «Целевая архитектура»):
- отдельного сайта с бэкендом нет: каталог — подписанные статические файлы, сайт каталога собирается из них
  (В-38, В-51); сервис публикации — отдельно и позже;
- подпись не в GitHub Environments и вход не через GitHub OAuth (В-38…В-40);
- конверты DSSE на каждый элемент не нужны: подписаны метаданные TUF, в них хеши всех файлов (ADR-0002).

## Открытые решения

1. **Ключи подписи.** Рекомендую:
   - root — два ключа с порогом 1: основной у владельца, запасной хранится отдельно, чтобы потеря одного не
     остановила каталог; когда появятся сотрудники Loginom — 2 из 3;
   - targets и `loginom` — тоже офлайн у владельца;
   - ключ «Проверено Loginom» — у проверяющего на его компьютере, а не на сервере сборки. Иначе взлом сервера
     позволит выпускать поддельные «Проверено Loginom». Это уточняет В-40 («ключи для ежедневной подписи — на
     сервере сборки»).

   Вариант: ключ «Проверено Loginom» на сервере сборки — проще, но с этим риском.
2. **Что могут публиковать другие в первой версии.** Рекомендую только Навык и Действие (текст и параметры);
   Готовый сценарий и Подключение — только от Loginom. В пакете `.lgp` бывают узлы с кодом и подключения к базам, а
   Подключение передаёт данные внешнему сервису: по четырём пунктам В-43 это не проверить. Вариант: все четыре
   типа, но Готовый сценарий и Подключение — только с «Проверено Loginom» после отдельной проверки.
3. **Срок файла каталога для закрытого контура.** Рекомендую 180 дней. После срока установленное работает, а
   поставить или обновить что-то из этого файла нельзя; за 30 дней приложение предупреждает. Варианты: 90 дней
   (отзывы приходят быстрее, файл носить чаще); или после срока установленное выключается (строже, но работа
   встанет, если администратор не успел).
4. **Каталог организации.** Прототип уже обещает: «передайте администратору — он добавит навык в каталог вашей
   организации». Рекомендую:
   - у организации свой подписанный каталог, его ключ — у администратора, создаётся командой от Loginom;
   - корень каталога лежит рядом с `policy.json`;
   - отметка «Организация», работает как «Проверено Loginom»;
   - делать после публичного каталога.

   Вариант: каталога организации нет, администратор раздаёт файл, а пользователи ставят его «Из файла». Тогда в
   закрытом контуре администратору придётся разрешить непроверенное (В-50), а текст в прототипе нужно поменять.
