# Модель угроз Loginom Hub

Статус: Proposed, 2026-11-18. Опирается на [ADR-0001](adr-0001-catalog-format.md),
[ADR-0002](adr-0002-signing-and-trust.md), [ADR-0003](adr-0003-policy-hub.md).

**Что защищаем:**
- данные и пакеты пользователя в Loginom;
- файлы на компьютере;
- данные, которые не должны уйти из сети организации;
- честность отметок «Loginom» и «Проверено Loginom».

**Вне рамок:** программа с правами пользователя на его компьютере может поменять что угодно, в том числе
установленные навыки. Хеш дерева это заметит, но не предотвратит; так же устроена опись встроенных навыков
(`bundled-skill-manifest.mjs`: «a corruption check, not a signature against writers of the installation»).

## 1. Атаки из спецификации TUF

Список — [TUF 1.0.37, п. 1.5.2](https://theupdateframework.github.io/specification/v1.0.37/).

| Атака | Защита | Что остаётся |
|---|---|---|
| Установка произвольного | Ставится только цель из подписанных метаданных с совпавшим хешем | — |
| Бесконечные данные | Длины в метаданных, пределы `tuf-js`, пределы распаковки ADR-0001 | — |
| Лишние зависимости | Зависимостей у элементов нет: навык — текст, действие — параметры встроенного обработчика | Появятся зависимости — пересмотреть |
| Скачок версий вперёд | Смена ключа snapshot или timestamp через root: по коду `tuf-js` сохранённые метаданные со старым ключом не проходят проверку и отбрасываются (`dist/updater.js:193-205`), номера начинаются заново | Нужен порядок действий при взломе сервера сборки |
| Бесконечная заморозка | Срок timestamp — 1 день онлайн; у офлайн-репозитория свои ключи timestamp и snapshot, онлайн-клиент его метаданные не примет | Офлайн-набор можно «заморозить» до 180 дней — цена закрытого контура |
| Злонамеренное зеркало | Зеркало не может подписать; копия у организации — те же подписанные файлы | Зеркало может не отдавать обновления — приложение покажет, что каталог устарел |
| Смешение версий | snapshot фиксирует версии всех метаданных; `consistent_snapshot`: в `tuf-js` метаданные берутся по номеру версии, а файлы — с хешем в имени (`dist/updater.js:124-129`) | — |
| Откат | Клиент помнит номера версий, в том числе между импортами файлов (ADR-0002, п. 9); откат по просьбе — только на неотозванную версию из текущих метаданных | — |
| Взлом ключа | Офлайн root и targets, роли разделены по путям; порог от 2 ключей защищает от кражи одного | При рекомендованном пороге 1 из 2 для root (вопрос 1) кража любого ключа root даёт всё; взлом ключа `verified` позволяет выпустить «Проверено Loginom» — см. раздел 3 |
| Не тот файл | Цель ищется по пути с отметкой и `id`; хеш сверяется | — |

## 2. Подмена пакета и архива

| Угроза | Защита |
|---|---|
| Подменили архив элемента или `.loginom-hub` | Подпись метаданных и хеши; неподписанное в архиве — только название набора, оно показывается простым текстом |
| Zip Slip, ссылки, повторы имён, разный регистр, NFC/NFD | Читатель ZIP отвергает (ADR-0001, п. 7) |
| ZIP-бомба | Пределы размера, числа файлов и степени сжатия |
| Подменили установленные файлы на диске | Хеш дерева при каждой загрузке; не совпал — элемент выключен, «Файлы навыка изменены вне приложения» |
| Подменили пакет `.lgp` между выбором и запуском | Host сверяет sha256 пакета при приёме вложения (план, «Целевая архитектура») |
| Чужое название, похожее на Loginom | «Loginom» в имени издателя у сообщества запрещено; похожие названия ловит модерация |

## 3. Взлом ключей и серверов

| Что взломали | Что может злоумышленник | Чего не может | Восстановление |
|---|---|---|---|
| Сервер сборки (ключи `community`, `revocations`, snapshot, timestamp) | Подписать элемент «Сообщество»; отозвать любой элемент; задержать каталог до конца срока | Выпустить «Loginom» и «Проверено Loginom»; обойти отметку согласия; попасть в закрытый контур без разрешения администратора | Смена онлайн-ключей новым root или targets, отзыв подписанного |
| Ключ модератора `verified` | Выпустить «Проверено Loginom» | Выпустить «Loginom» | Отзыв, смена ключа через targets; поэтому ключ не держим на сервере (вопрос 1) |
| Сервис публикации | Подложить заявку в очередь модерации, менять статусы | Подписать что-либо: ключей на нём нет | Восстановление из резервной копии |
| Root (ключей не меньше порога) | Всё | — | Только новая версия приложения со свежим корнем; поэтому root офлайн, а порог поднять до 2 из 3, когда появятся держатели |
| Почта автора | Опубликовать новую версию от его имени | Обойти модерацию | Каждая версия проверяется заново; «Проверено Loginom» не переходит на новую версию само |

## 4. Вред от содержимого навыка

После отметки согласия навык сообщества действует и в Loginom (В-41). Текст навыка — это указания модели; от
подсказки-инъекции защищают не подписи, а права и вопросы приложения.

| Что пытается навык | Что его останавливает | Где закрыть |
|---|---|---|
| Отправить данные наружу | «Открывать сайты» — спрашивать; в закрытом контуре сайтов нет; Подключение от сообщества — нельзя (вопрос 2) | Правила прав, этап F |
| Изменить или перезаписать пакет в Loginom | «Сохранять пакеты в Loginom» — спрашивать; оригинал не меняется без отдельного подтверждения | План, «Запуск решения» |
| Запустить сценарий с выгрузками | «Запускать сценарии с выгрузками» — спрашивать | Правила прав |
| Запустить команду | Терминал выключен; в закрытом контуре — всегда | Правила прав |
| Получить доступ к Loginom без человека | `loginom_request_access` всегда спрашивает; без человека — отказ | Этап B |
| Включить профиль `loginom-automation` | Сегодня модель включает его сама: подсказка просит её активировать навык (`packages/opencode/src/product/turn-lifecycle.ts:219`) | Этап B, пробел доверия из плана |
| Включить другой навык мимо прав | `POST /api/experimental/session/:id/skill` активирует навык без проверки прав | Правка U3 |
| Поставить себе другой элемент или отметить согласие | У модели нет такого инструмента и вызова | ADR-0002, п. 5 |
| Скрытый текст: невидимые символы, комментарии, белый текст | Для «Проверено Loginom» — проверка В-43; перед установкой сообщества приложение показывает полный текст и помечает невидимые символы | Этап E |
| Выдать себя за встроенный навык | Регистрационное имя с источником (`community.…`), встроенные — без точки | ADR-0001, п. 4 |
| Утомить согласиями | Согласие — на версию, с понятным текстом В-49; без потока вопросов | UX |

Что остаётся: навык сообщества может подталкивать агента к действиям в пределах того, что пользователь разрешил.
Так решено (В-41); защита — отметка согласия, права и вопросы приложения.

## 5. Политика администратора

| Угроза | Защита |
|---|---|
| Пользователь правит `policy.json`, чтобы разрешить сообщество | Файл принимается, только если менять его может лишь администратор (ADR-0003, п. 7) |
| Файл с ошибкой или неизвестным ключом | «Только этот компьютер», причина в «Диагностике» (В-33, ADR-0003, п. 2) |
| Подменили корень каталога организации | Корень лежит рядом с политикой с теми же правами |
| Запрет из политики обходят через API сервиса | Запрет действует в сервисе — хранилище каталога и правила прав, — а не только в окне приложения |
