# Черновик: выкладка тестового каталога Loginom Hub

Статус: черновик, 2026-11-18. **Ничего из этого не выполнялось.** Тестовый экземпляр — на сервере владельца (В-40);
боевой — на поддомене loginom.ai. Имена серверов, пути и ключи в git не пишутся: они берутся из окружения или из
`.env.local`, который покрыт `.gitignore`, как у прототипа (`apps/loginom-agent-prototype/deploy.ts`).

## Что выкладываем

| Часть | Что это | Когда |
|---|---|---|
| Каталог | Статические файлы: `tuf/online/`, `tuf/offline/` и архивы элементов (ADR-0001, ADR-0002) | Первым |
| Сайт каталога | Статические страницы, собранные из каталога (В-51) | Вместе с каталогом |
| Сборщик каталога | Команда: одобренные элементы → метаданные TUF → подпись онлайн-ключами | Вместе с каталогом |
| Сервис публикации, шаг 1 | Приём заявки из приложения, подтверждение почты, статус по квитанции (В-38, В-42) | После каталога |
| Сервис публикации, шаг 2 | Аккаунты, сканер, консоль модерации (В-38, В-39) | Когда авторов станет много |

## Устройство на сервере

- Статические файлы — в отдельном контейнере с файловым сервером, по схеме прототипа: релиз в
  `releases/<хеш>/`, `current` — ссылка, переключение под `flock` атомарной заменой ссылки, хранится 10 релизов,
  откат — переключение ссылки на прежний релиз.
- Сервис публикации — свой контейнер; база SQLite и заявки — в своём томе.
- Отдельная сеть контейнеров для входа (`loginom-hub-ingress-net`), а не общая сеть edge-прокси.
- Маршрут в edge-прокси: резервная копия конфигурации → `caddy validate` → **подтверждение владельца** → reload.
  Этот конфиг обслуживает и другие сервисы владельца.
- Заголовки сайта каталога — как у прототипа: только свои скрипты, без внешних запросов. Метаданные TUF — с
  коротким кэшем (timestamp не дольше минуты), архивы элементов — неизменяемые.

## Ключи тестового экземпляра

- Тестовые root и targets создаются офлайн у владельца и на сервер не попадают.
- Тестовые онлайн-ключи (`community`, `revocations`, snapshot, timestamp) — файлом на сервере, читать может только
  пользователь сборщика; в git, журнале и отчётах их нет.
- Тестовые корни встраиваются только в сборки для проверки — так же, как тестовый ключ обновлений
  `LOGINOM_AI_AGENT_UPDATE_TEST_PUBLIC_KEY` (`packages/desktop/electron.vite.config.ts:18`). В выпуск тестовые корни
  не попадают; это проверяет тест сборки.

## Проверка после выкладки

1. `curl -sI` главной сайта каталога: 200 и прежние заголовки.
2. Клиент `tuf-js` с тестовым корнем делает `refresh()` против `tuf/online/` и скачивает один элемент.
3. Архив `.loginom-hub`, скачанный с сайта, проходит «Импорт из файла» в сборке для проверки.
4. Подделки отвергаются: изменённый байт в архиве элемента, просроченный timestamp, timestamp с меньшей версией.
5. Предупреждение о сроке: проверка раз в день пишет, сколько дней осталось у timestamp, snapshot и офлайн-набора.
