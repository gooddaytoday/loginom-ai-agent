# ADR-0003: раздел `hub` в `policy.json`

## Статус

Proposed. Опирается на решение 8, В-33, В-36, В-45, В-50; полная схема политики (режим, Loginom, модели,
разрешения) — этап F.

## Дата

2026-11-18

## Контекст

- Сегодня `policy.json` знает только обновления: `updates`, `channel`, `feedUrl`
  (`packages/desktop/src/main/update-policy.ts:24`). Путь: `C:\ProgramData\Loginom AI Agent\policy.json`,
  `/Library/Application Support/Loginom AI Agent/policy.json`, `/etc/loginom-ai-agent/policy.json`.
- Особенности нынешнего разбора:
  - неизвестные ключи проходят молча (`update-policy.ts:49`, `{ ...policy }`);
  - `managed: Object.keys(policy).length > 0` (`update-policy.ts:35`): любой новый раздел, например `hub`, сделает
    обновления «управляемыми администратором»;
  - файл с ошибкой выключает только обновления (`packages/desktop/src/main/updater.ts:57`);
  - путь к файлу продублирован в CLI (`packages/opencode/src/cli/update-notifier.ts:116`).
- По спецификации политика задаёт и источник каталога; файл с ошибкой переводит приложение в режим «Только этот
  компьютер», запуск не прерывается (В-33); заданная строка показывает замок и «Задано администратором»
  ([ux-spec.md](../product/loginom-agent/ux-spec.md), «Настройки и закрытый контур»).
- Сервис продукта может быть общим на машину, поэтому переменные окружения Desktop до него не доходят (план,
  «Ключевые факты»): политику сервис должен читать сам.

## Решение

1. **Один разбор политики — `packages/product/src/policy.ts`.** Путь по платформе, строгая схема (Effect Schema),
   типизированный результат. Им пользуются Desktop (обновления), сервис продукта (каталог, режим работы; читает
   файл сам при старте) и отдельный CLI. Копии в `update-policy.ts` и `update-notifier.ts` уходят.
2. **Неизвестный ключ — ошибка файла**, и приложение работает по В-33: «Только этот компьютер», причина и путь
   вверху настроек и в «Диагностике». Так ведут себя версии с новым разбором: если им дали политику с ключами
   из более поздней версии, они перейдут в «Только этот компьютер» и скажут почему. Уже выпущенные версии
   неизвестные ключи пропускают молча и раздел `hub` не выполнят; это нужно написать в документации
   администратора.
3. **`managed` для обновлений** считается только по ключам обновлений.
4. **Раздел `hub`:**
   ```json
   {
     "hub": {
       "source": "loginom",
       "community": "deny",
       "own": "allow",
       "organization": { "root": "org-root.json", "source": { "url": "https://hub.corp.example/loginom/" } }
     }
   }
   ```

   | Ключ | Значения | Смысл |
   |---|---|---|
   | `source` | `"loginom"` · `{ "url": "https://…" }` · `"file"` · `"off"` | Откуда каталог: интернет-каталог Loginom; копия офлайн-репозитория на сервере организации; только импорт из файла; каталога нет, только встроенное |
   | `community` | `"allow"` · `"deny"` | Навыки «Сообщество» (В-50) и, по предложению ADR-0002, «Из файла» (В-45) |
   | `own` | `"allow"` · `"deny"` | Свои навыки и действия (В-36) |
   | `organization` | `root`, `source` | Каталог организации (вопрос 4): корень относительно папки `policy.json` и откуда брать |

   Адрес — только `https:`, без имени, пароля, параметров и `#`, как у `feedUrl` (`update-policy.ts:29`).
5. **Умолчания без политики** зависят от режима работы:

   | Режим | `source` | `community` | `own` |
   |---|---|---|---|
   | Интернет | `loginom` | `allow` (с отметкой согласия) | `allow` |
   | Сеть организации, Только этот компьютер | `file` | `deny` | `allow` |

6. **Принуждение в два слоя:**
   - хранилище каталога в плагине продукта не регистрирует запрещённое (`skill.transform`) и не даёт его
     установить: «Администратор вашей организации не разрешил…»;
   - правила прав по регистрационному имени: `skill` · `community.*` · `deny`, так же `file.*` и `own.*`
     (в S9 правило `hub.*` → `deny` давало `Permission denied: skill`).

   Если политика запретила уже установленное, оно выключается, но не удаляется, и включается снова, когда
   администратор разрешит.
7. **Файлы политики и корня организации** принимаются, только если их может менять лишь администратор (на Windows —
   проверка прав на папку, этап F). Файл, который пользователь может изменить сам, — ошибка файла.

## Рассмотренные альтернативы

- **Переменные окружения.** До общего сервиса не доходят; отклонено.
- **Групповые политики Windows и реестр.** Позже, этап F, поверх того же разбора.
- **Пропускать неизвестные ключи.** Старое приложение молча не выполнит запрет из нового раздела. Отклонено:
  лучше «Только этот компьютер» с объяснением.

## Последствия

- Перенос разбора в `product` — отдельная правка с тестами: неизвестный ключ; `managed` только по ключам
  обновлений; ошибка файла даёт «Только этот компьютер»; запрет `community` выключает установленное.
- Администратору нужна документация с примерами `policy.json` для трёх режимов.
