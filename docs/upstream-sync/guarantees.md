# Охранные тесты гарантий

Шесть гарантий продукта и тесты, которые падают, если перенос кода или слияние upstream их ослабляет. Тесты выполняются при каждой синхронизации ([procedure.md](procedure.md), шаг `check`) и в CI (workflows форка на дереве v2 — B5.1). Живые сценарии Desktop/CLI (LNX-*), macOS и Windows скриптами не заменяются: их перечень — разделы 4–5 матрицы совместимости LAB-200.

**Дерево переноса на OpenCode v2.3.0.** Пакеты форка `loginom-host` и `product` перенесены как есть (B1.2a), вместе с ними — их охранные тесты. Код, который в 0.4 жил в пакете `opencode` (швы `ProductHooks`, `standalone`, мост воркера TUI), на v2 переносят задачи B2 в плагин `loginom.product`, Desktop — задачи B4. Каждая такая задача переносит охранные тесты своей гарантии и проверяет их мутацией (план B, раздел B2). Шлюз B, пункт 2: G1–G6 перенесены, зелёные и проверены мутацией (B6.2). Таблица 0.4 — где исполнялась гарантия, тесты, мутации — в выпуске 0.4.0 (эталон 0.4, В-99): `git show v0.4.0:docs/upstream-sync/guarantees.md`.

Мутации в последнем столбце проверены на 0.4: в копии итогового дерева в код вносилась точечная поломка гарантии, тест становился красным, после отката — зелёным (стенд: Linux, root, bun 1.3.14, Node 24.19.0, 3 CPU/3,8 ГБ; дерево `f37dbf40`). На дереве v2 мутации не перемерялись, кроме G1 (B2.2, B2.5a…d, B2.9b), G6 (B2.4), кода аренды G3, G4 (B2.3) и G5 (B2.7a2, B2.7a2b); стенд тот же, bun 1.4.4; журнал переноса, разделы B2.2, B2.4, B2.3, B2.7a2, B2.7a2b и B2.9b.

## Как запускать

Из корня рабочего дерева, Bun 1.4.4 (`packageManager`) и Node 24.19.0 (`packages/product/loginom-release.json`):

```bash
export LOGINOM_AI_AGENT_TEST_NODE=<node 24.19.0>                 # путь к bin/node, нужен loginom-host, dashboard и package-docs в server
cd packages/dashboard/template && "$LOGINOM_AI_AGENT_TEST_NODE" "$(dirname "$LOGINOM_AI_AGENT_TEST_NODE")/../lib/node_modules/npm/bin/npm-cli.js" ci --ignore-scripts
cd packages/product && bun test                                  # repo-paths, names, identity, cli-profile, маршруты узлов
cd packages/cli && bun test test/flag-identity.test.ts test/service-identity.test.ts
cd packages/loginom-agent && bun test                            # G1: политика инструментов и переходы допуска, признак папки дашборда, ядро профиля файла; G6: источники навыков; G4: попытка восстановления браузера
cd packages/server && bun test test/loginom-access.test.ts       # G1 и G6: пути S1, источники допуска, контракты хуков, профиль дашборда (B2.9b), S3, U3
cd packages/server && bun test test/loginom-local-file.test.ts   # G1: доступ к локальным файлам, loginom_file_admit (B2.5a), профиль файла (B2.5b1)
cd packages/server && bun test test/loginom-package-docs.test.ts # G1: package_docs_run (B2.5c); нужны npm ci клиента и LOGINOM_AI_AGENT_TEST_NODE, около 80 с
cd packages/server && bun test test/loginom-dock-catalog.test.ts # G1: каталог Dock по поколению подключения, привязка задачи к Host, вызовы Dock (B2.5d)
cd packages/server && bun test test/loginom-host-lease.test.ts   # G3 и G4: аренда Host, случаи S2, напоминание о восстановлении браузера (B2.3); нужны npm ci клиента и LOGINOM_AI_AGENT_TEST_NODE
cd packages/cli && bun test test/loginom-host.test.ts            # G3: serve находит зависшие аренды Host до прослушивания порта (B2.3)
cd packages/cli && bun test test/cli-resources.test.ts          # G5: сервер собранного CLI берёт ресурсы только из полного артефакта (B2.7a2); нужен npm ci клиента
cd packages/loginom-host && xvfb-run -a bun test
cd packages/dashboard && bun run test
scripts/upstream-sync/selftest.sh
```

Три шага, без которых прогон врёт (B1.1, B1.5, checkpoint B1):

- `npm ci` клиента `packages/loginom-runtime/client` закреплённым Node — до тестов `loginom-host`, `packages/server/test/loginom-access.test.ts` (проверка встроенного каталога навыков, B2.4; без него там 3 падения из 9) `packages/server/test/loginom-package-docs.test.ts` (проверка ресурсов исполнителя, B2.5c), `packages/server/test/loginom-host-lease.test.ts` (сборка `node-host.mjs`, B2.3) и `packages/cli/test/cli-resources.test.ts` (проверка навыков продукта в манифесте артефакта, B2.7a2). У клиента свой npm-lockfile, `bun install` его не ставит. Без него на дереве v2 у `loginom-host` 16 ошибок загрузки (`Cannot find package 'yaml'`) и 52 падения из 379 тестов вместо 38 из 555.

- `npm ci` шаблона `packages/dashboard/template` закреплённым Node — до тестов дашбордов. Без него на точке отсечения было 17 ложных падений (B1.1); на дереве v2 — 19 в `test:coverage:workers`, и скрипт `test` дальше не идёт (B1.7).
- `LOGINOM_AI_AGENT_TEST_NODE` — путь к `bin/node` Node 24.19.0 для `loginom-host`, `dashboard`, `packages/server/test/loginom-package-docs.test.ts` (встроенный Node исполнителя, B2.5c) и `packages/server/test/loginom-host-lease.test.ts` (Node host, B2.3). Без неё `loginom-host` на дереве v2 даёт 205 падений вместо 38 (B1.5). В 0.4 то же требовалось набору пакета `opencode`: без неё 66 падений вместо 6 (B1.1); при переносе кода туда, где тесты запускают Node, переменную берут с собой.

`bun turbo test` переменную не передаёт: задачи `turbo.json` с `passThroughEnv` для пакетов форка на дереве v2 ещё нет (B5.1). Поэтому `loginom-host` и `dashboard` запускают из каталога пакета, как выше.

## Базовые падения стенда

Часть тестов падает на стенде независимо от изменений (запуск от root, нет sudo, малый объём памяти). Падение, присутствующее до и после правки в том же виде, не считается регрессией, но и не маскируется. Сравнение «до/после» на одном стенде — в журнале переноса (`oc2-migration-log.md`) по задачам. Известные примеры:

- `cli-manifest.test.ts` «archive verification preserves manifest modes under a private umask» и `managed-work-entry` «Expected refusal» (под root) — в `loginom-host` с точки отсечения;
- на дереве v2 в `loginom-host` ещё 3 падения `bundled-ripgrep` (B1.5), итого 5 базовых падений пакета вместе с двумя выше; `skills-acceptance` (24) и `skills-acceptance-turns` (8) закрыты в B4.8b: манифест выпуска Desktop и корпус маршрутизации перенесены; девятое падение того же корпуса, в `package-docs.test.ts`, закрыто в B2.5c: фикстура `edit-source.lgp` перенесена в `loginom-host`;
- `dashboard`, `folder.test.mjs` «a partial source copy is retried completely…» (2 подтеста и сам тест): под root `chmod 0` не даёт `EACCES` (B1.7).
