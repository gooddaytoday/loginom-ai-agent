В C5.4б штатное хранилище плагинов импортирует ключ 0.4 `systemProxyEnabled` из `loginom-ai-agent.settings` в `plugin.updater`, не изменяя старый файл. Desktop и updater используют одну запись, явный прокси остаётся приоритетным. Встроенный GUI-плагин Loginom добавляет строку в общие настройки: она показывает `unreachable`, `socks-only`, `timeout` и `failed` без адресов, а при выключенном переключателе скрывает предупреждения. Настройка вступает в силу для фоновой службы при перезапуске приложения.

Main определяет прокси один раз после `whenReady`, прекращает ожидание при остановке или через 10 секунд и отменяет собственные фоновые операции. При восстановлении после неудачной установки обновления останавливает старое определение, если оно ещё не завершилось, и запускает новое до старта службы. Electron не предоставляет отмену самого запроса Chromium, только отмену ожидания. `LOGINOM_AI_AGENT_RUNTIME_NO_PROXY` содержит применённые адреса и списки обхода, чтобы Runtime не снимал другое, явно заданное значение из терминала. Табличный тест Desktop проверяет миграцию, оба метода через сырой `PluginCall`, предупреждения и отмену с восстановлением после сбоя обновления.

**Не перенесено:** перезапуск службы без прокси при падении до готовности — это поведение 0.4 v1, не v2. Как и раньше, у службы v2 нет локального реле; разные прокси для разных URL одной схемы и очередность запасных маршрутов PAC не представимы в переменных окружения. Updater в системном режиме продолжает использовать правила Chromium/ОС. Проверка WinINET/PAC и обновления установленной Windows-сборки — на стенде.
