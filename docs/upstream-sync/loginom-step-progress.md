# Ход шага Loginom (C3.3)

`SessionEvent.Tool.Progress` несёт `metadata.loginomStep` для текущего вызова
Dock. Привязка к инструменту — по штатному ID вызова OpenCode. Событие заменяет
предыдущий снимок целиком; ответ инструмента для модели не меняется.

| Поле | Тип и назначение |
| --- | --- |
| `version` | `1`. Неизвестные версии следует игнорировать. |
| `phase` | `waiting` — «Жду Loginom»; `configuring` — «Настраиваю узел»; `executing` — «Запускаю узел» / ожидание выполнения; `reading` — «Читаю результат». |
| `nodeType` | Код типа узла, например `transform.group_data`, либо `null`. Подставлять локализованное название типа, не имя из пакета. |
| `substep` | `null` либо `{ kind: "fields", index: 2, total: 3 }`. Нумерация с 1; в «Группировке» учитываются назначение полей и настройка агрегатов. Другие мастера пока передают только фазу. |
| `startedAt` | Unix-время в мс. Для `dock_node_wait` — начало исходной попытки операции, если она ещё идёт; для прямого вызова — начало вызова в runtime. |
| `lastReplyAt` | Unix-время в мс последнего HTTP-ответа настроенного origin в браузере или входящего кадра WebSocket Loginom; `null`, если ещё не наблюдался. Это признак связи, не подтверждение завершения. |
| `stalledSince` | `null` либо Unix-время в мс, от которого отсчитывается тишина: более позднее из перехода этапа/подшага и последнего ответа. Значение, отличное от `null`, означает «Похоже, шаг завис», а не ошибку, отмену или разрешение на повтор мутации. |

Лента сама обновляет длительности относительно этих отметок: «Loginom ответил
N с назад» от `lastReplyAt`, «нет ответа N с» от `stalledSince`. Не показывать
возраст неизвестного ответа; относительные значения ограничивать снизу нулём.
После терминального события инструмента остановить обновление. Новая фаза или
ответ Loginom снимают предупреждение, если порог тишины больше не превышен.

Runtime отправляет только изменившиеся снимки с шагом 1,5 с; быстрый вызов может
не прислать ни одного. Между вызовами (включая фоновые операции без активного
`dock_node_wait`) событий нет. Локальные инструменты и холодный запуск самого
runtime не используют этот канал. Пороги `STEP_STALL_MS` предварительные:
ожидание 30 с, настройка 60 с, выполнение 90 с, чтение 45 с. Desktop-замеров пока
нет. Сырые кадры, URL, параметры и содержимое ответа не публикуются.

### Защищённая операция Loginom (S10-3)

`metadata.loginom.busy` — отдельный снимок `{ version: 1, windowId,
operationId, active }`. `windowId` непрозрачен и действует до замены runtime;
идентичность операции задаётся парой `windowId` и `operationId`.
Активный снимок приходит при подписке на текущий вызов. Начало и конец
отправляются сразу, не дожидаясь такта `loginomStep`. В итоговой квитанции
снимок относится только к этой операции и остаётся историческим. Общий
построитель `metadata.loginom` включает не более 256 байт для `busy` в бюджет 16 KiB.

После `pending` операция может работать без открытого вызова, поэтому
отсутствие `Tool.Progress` не означает конец. Лента (C3.18б, LAB-2234) читает
актуальный снимок через продуктовый RPC `loginom.work/busy` в Location
разговора: `{ sessionID }` → `{ busy: снимок | null }`. `null` означает, что
для этого разговора нет снимка в имеющемся runtime. Запрос не требует аренды
хода, не запускает runtime и не ждёт урегулирования. Лента читает снимок при
открытии разговора и повторно по таймеру, в том числе после `pending` и
между ходами; сетевой сбой не подтверждает конец операции. Историческая
квитанция и состояние текущего вызова не заменяют этот снимок.

Runtime держит сигнал под шлюзом браузерного шага `node.apply`, `node.delete`,
`package.save_checkpoint` и `package.save_as`. При `AMBIGUOUS` предупреждение
остаётся до подтверждённого урегулирования или закрытия окна. Прерывание
вызова ожидания не отменяет фоновый Apply. Детектор ручной правки относится
к S10-4. Отдельное чтение исходника JavaScript (source/context) сигналом не
покрыто: оно использует отдельную очередь и собственный шлюз очистки.

Окно получает через `page.evaluate` в текущем контексте собственный shadow-слой
рядом с `body` вне UI Loginom; вторая CDP-сессия не открывается.
Он не принимает фокус и указатель. Слой адресуется странице разговора, на
которой прошёл вход, независимо от других вкладок того же origin. При закрытии
или навигации старый документ теряет предупреждение; на том же origin оно
восстанавливается до урегулирования. Начальная отрисовка ждёт не более 250 мс;
снятие плашки не держит шлюз. Если страница недоступна, состояние остаётся
доступным через RPC без браузерной плашки.
