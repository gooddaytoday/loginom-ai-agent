# Spike OpenCode 2, часть 2: интерфейс (этап A3)

17.11.2026. OpenCode v2.3.0, веб-приложение из `packages/app` (vite dev), язык «Русский». Цель — проверить на
настоящем OpenCode 2, ложатся ли на его механизмы решения прототипа (demo, итерации 1–4), и измерить правки
upstream. Первая часть spike (S1–S10, сервер) — в [oc2-spike-report.md](oc2-spike-report.md).

Метки доказательств: **[браузер]** — видел в работающем приложении, скриншот в `oc2-spike-ui/`;
**[код]** — прочитано в исходниках v2.3.0, в браузере не проверено; **[оценка]** — мой расчёт объёма правки.

## Итог

- **Без правок OpenCode показывает внутренние имена [браузер]:** «Использовано 4 loginom_table_read,
  loginom_scenario_build…», «Вызван `loginom_table_read` file=sales-demo.csv». В пресете по умолчанию
  («compact») он прячет в свёрнутую группу и карточку изменений, и ошибку шага.
- **Механизмов нет, нужны правки [код + оценка]:**
  - «Разрешать в этом разговоре» и «сказать иначе» в доке разрешения;
  - вопрос от инструмента плагина;
  - удаление проекта;
  - русский перевод (переведено 55% строк приложения и 67% строк ui).
- **Шов покрывает только классическую ленту [браузер].** В экспериментальной новой ленте (New timeline) строки
  шагов наши, а заголовок группы английский: «Used loginom_table_read, …».

### Разрешение подробнее (В-22)

- **«Разрешить всегда» без `save` работает как «один раз» [браузер].** Нажал «Разрешить всегда», в новой сессии
  тот же инструмент снова спросил. С `save` правило пишется в таблицу `permission` на весь проект и навсегда [код].
- **Уровня «в этом разговоре» в ядре нет [код].** Дешевле всего сделать его в серверном плагине продукта: хук
  `permission.evaluate` разрешает запомненное действие для этой сессии, а кнопка дока сообщает плагину выбор.
  В OpenCode остаётся только кнопка в доке: 40–80 строк вместе с продуктом [оценка].
- **«Сказать иначе» [код].** Сервер принимает `message` при отказе и передаёт текст модели. Интерфейс шлёт только
  решение. Поле в доке и передача текста — 30–50 строк [оценка].
- **Понятный заголовок вместо `loginom.package.save` [браузер].** Заголовок дока жёсткий. Описание берётся из
  ключа перевода по имени действия, а текст — только из хука `permission.evaluate`. Наши `metadata.title/effect`
  док не показывает. Правка — 5–10 строк [оценка].
- **Скрыть «Разрешить всегда» — около 3 строк [оценка].**

## Шов отрисовки инструментов

Патч `spike/oc2/patches/ui-tool-registry.patch` — **+46 −3, 5 файлов `session-ui`**:

| Файл | Строки | Что |
|---|---|---|
| `package.json` | +1 | экспорт `./tool-renderer` (`ToolRegistry`) |
| `src/tools/tool-titles.ts` (новый) | +33 | названия инструментов для заголовка группы и карточки ошибки; признак `separate`; сигнал версии |
| `src/tools/tool-renderer.tsx` | +7 −2 | `register({ name, render, title, separate })`; заголовок группы берёт название; чтение реестра реактивно |
| `src/components/tool-error-card.tsx` | +2 −1 | русское название в карточке ошибки |
| `src/timeline/projection.ts` | +3 | инструмент `separate` и упавший шаг не сворачиваются в группу ни в одном пресете |

- **Поздняя регистрация [браузер].** Без сигнала версии отрисовщик, зарегистрированный через 8 с после старта,
  применялся только к новым сессиям; открытая сессия оставалась с `loginom_flaky` даже после смены вкладки.
  С сигналом открытая сессия перерисовалась сама: через 8 с «Использовано 1 loginom_package_edit» стало
  отдельной карточкой изменений.
- **Где жить коду продукта.** `ui-tool-renderer-loginom.patch` (+66: импорт в `entry.tsx` и
  `runtime/loginom/tools.tsx`) — только для spike. Внешний GUI-плагин `session-ui` импортировать не может: его нет
  в списке модулей плагина [код]. Встроенные плагины из `packages/gui-plugins` уже импортируют `session-ui`
  [код]. Значит, отрисовщик Loginom — во встроенном GUI-плагине продукта; это шов «регистрация встроенных
  GUI-плагинов» из плана.
- **Противоречие [код, не проверено].** По коду встроенному плагину вызовы `ctx.client` запрещены, а кнопкам
  карточки («Сохранить новой версией», «Отменить изменения») нужен RPC в серверный плагин. Варианты: разрешить
  встроенному плагину продукта RPC или выделить кнопки во внешний плагин. Решаю при проектировании этапа C.
- **Новая лента [браузер].** Строки шагов в ней наши, она берёт `ToolRegistry`. Заголовок группы и группировка
  идут своим путём, поэтому «Used loginom_table_read, …», и карточка свёрнута. Если upstream сделает её основной,
  нужно ещё 10–20 строк [оценка].
- **Проверки.**
  - `tsc` по `packages/app`: 0 ошибок. Все 5 изменённых файлов входят в проверку (`--listFilesOnly`). `tsc`
    запускал напрямую: в установленном Bun 1.4.3 нет `bun check`, на нём построен скрипт `typecheck`, а
    upstream требует Bun 1.4.4.
  - `bun test src` в `packages/session-ui` (скрипт пакета): 599 прошло, 0 упало.
  - Голый `bun test` без `src` даёт 28 падений в файлах вне `src`. С базой без патча не сравнивал.
  - Оба патча проверены `git apply -R --check`.

## Влияние на оценку

- Этап B не меняется: 28–45 агенто-дней (часть 1).
- Главный риск этапа C снят: настоящую ленту OpenCode можно довести до ленты прототипа малыми швами, без своей
  ленты.
- Оценку этапа C в днях даю в его плане: она зависит от объёма своих страниц (Главная, Пакеты, Hub, мастер),
  а spike их не мерил.

## Как повторить

```sh
spike/oc2/setup.sh                                 # песочница и патчи, включая ui-*.patch
cd spike/oc2/harness && bun ui.ts                  # сервер :4096 и сценарная модель :4097, пишет .run/ui/prompts.json
cd spike/oc2/opencode/packages/app && VITE_OPENCODE_SERVER_PORT=4096 bun dev   # приложение :5173
```

- Вход по паролю песочницы. Язык выставляется в «Настройки → Общие».
- Сценарии `feed`, `question`, `steer`, `change`, `error` вставляются в поле ввода из `prompts.json` одной
  строкой.
- Серверы слушают только 127.0.0.1.
