# Открытие черновика Dashboard из снимка

Вариант утверждён 19 ноября 2026 года. Пользователь нажимает «Создать dashboard» в Studio и сразу получает в Desktop чат, в котором можно описать Dashboard для выбранного узла.

## Создание и редактирование

Для создания достаточно одноразового снимка. В нём уже есть привязка к узлу, поля, пример строк, параметры и признак наличия готового Dashboard. Desktop скачивает и проверяет снимок, открывает черновик по шаблону и сохраняет правки, если для этого узла уже есть локальный черновик. Отдельный вход Desktop в Studio и чтение опубликованных исходников для этого шага не нужны. Адрес ссылки и формат снимка сохраняются.

При редактировании Desktop по-прежнему проверяет публикацию при открытии. Это позволяет начать работу с исходников существующего Dashboard.

## Публикация и выбор пользователя

По команде «Опубликовать» Desktop обращается к Studio и читает последнюю сохранённую версию для этого узла. Для первой публикации действует обычное разовое подтверждение.

Если версия на стенде отличается от той, с которой начинали работу, включая случай появления первой версии за время подготовки черновика, используем существующее окно подтверждения. Оно показывает узел и пакет. Для нового черновика предлагаем такое сообщение.

> Для этого узла уже сохранили Dashboard. Если вы опубликуете свой черновик, после успешной сборки пользователи увидят вашу версию. Опубликовать?

Desktop знает, какая версия сохранена. Сведения об авторе в ответе Studio отсутствуют, а сборка может ещё идти. Предлагаемые действия в этом случае — «Опубликовать мою версию» и «Отмена». Отмена сохраняет локальный черновик. Перед записью проверяется версия, которую видел пользователь. Если за это время появилась следующая версия, требуется новое подтверждение.

## Подходы

Владелец выбрал возможность продолжить публикацию с разового явного согласия. Обязательное открытие чужой версии на редактирование добавило бы шаг даже пользователю, который осознанно хочет опубликовать свой вариант. Для выбранного подхода хватает признака в снимке, существующего окна и действующей проверки версии при записи.

## Как проверить результат

1. В Studio выбрать узел без готового Dashboard и нажать «Создать dashboard». В Desktop открывается чат с данными узла, без второй вкладки Studio. Повторное открытие по свежему снимку сохраняет локальные правки.
2. Пока первый пользователь готовит черновик, второй публикует Dashboard того же узла. Первый нажимает «Опубликовать», видит предупреждение и отменяет. На стенде остаётся версия второго пользователя. После повторного запроса и явного согласия публикуется версия первого.
3. Обновить версию между показом предупреждения и согласием. Прошлое разрешение не приводит к записи поверх следующей версии. Открытие готового Dashboard на редактирование по-прежнему загружает опубликованные исходники для нового локального черновика.

Область проверки — переход из Studio в Desktop. Отдельный режим автоматизации CLI находится за рамками этого изменения.
