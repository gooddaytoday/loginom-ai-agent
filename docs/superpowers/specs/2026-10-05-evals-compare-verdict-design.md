Статус: утверждён пользователем 2026-10-05. Утверждены три состояния
«хуже / лучше / неразличимо» с отдельным признаком «не хуже», консервативный
интервал с кластером «задача», отдельное правило 3/3 → 0/3, запас 50 п.п.

## Результат для пользователя

`compare` публикует отдельно доведение до пакета, верность CSV по oracle и
структурный score судьи. Для каждой доступной оси: равновесные средние задач A/B,
парное падение A−B, нижняя и верхняя односторонние границы, статистический
вердикт и признак допустимости падения. Общего смешанного verdict нет.
Справочные `mean_score`, стоимость, ошибки инструментов и старые attempt-weighted
метрики сохраняются и явно отделяются от оснований вердикта.

Для конечного `AttemptResult.pass` дополнительно публикуются `pass^1` и `pass^k`.
Это описательная надёжность выполнения всей задачи, а не четвёртая ось
статистического тестирования. Наблюдаемый провал стабильной задачи выводится
отдельно от статистического вывода по всему набору.

## Альтернативы и выбранный подход

1. Рекомендуемый и выбранный: границы Hoeffding по независимым группам задач.
   Внутри одной группы допускается зависимость попыток и результатов A/B.
   Метод детерминированный, без runtime-зависимостей, не схлопывает неопределённость
   при одинаковых наблюдениях. Цена — низкая мощность на малом наборе.
2. Интервал для фиксированного набора при независимых отдельных попытках:
   заметно уже, но требует дополнительного допущения, которое пользователь
   предпочёл не принимать для интервала.
3. Парный t-интервал / task-bootstrap: возможное последующее исследование.
   При 5 задачах и одинаковых разностях может давать ложную точность; в этот
   патч не входит.

## Единица сравнения и покрытие

Из исходных `attempts`, без округлённых `metrics`, для задачи i строится
`xAi`, `xBi`; `di = xAi − xBi`, `D = mean(di)`. Каждая задача весит `1/T`,
независимо от числа её попыток. Попытки с одинаковыми номерами между A/B
не объявляются случайными парами. Пары образуются только по ID задачи.

- Completion: доля `status === "completed"` среди измеренных попыток.
- Oracle: доля `oracle_pass === true` среди измеренных попыток задачи,
  для которой сохранённый snapshot подтверждает применимость oracle.
- Structure: среднее `structural_score / 100` измеренных попыток.
- Из качества исключаются `interrupted`, `harness_error`, `infra_error`.
- Ошибка судьи, пропущенная проверка oracle и отсутствующий score не являются
  нулём. Условное среднее по известным значениям остаётся описательным;
  неполнота соответствующей оси блокирует её интервал и verdict.
- Для статистики нужны одинаковые непустые множества задач A/B и хотя бы одно
  измерение каждой применимой задачи в обоих прогонах. Oracle-задачи образуют
  явный одинаковый subset по snapshot; задачи без oracle — N/A.
- Разное число измеренных попыток предупреждает, но само по себе не запрещает
  task-paired completion. Прерванный/остановленный прогон не даёт inferential verdict.
- Несовпадение `tasks[].id` и `task_ids`, дубликаты task ID или измеренного
  `(task_id, attempt)`, отрицательные/неконечные/out-of-range scores и неверные
  типы результатов — ошибка входа, а не молчаливое исправление данных.

## Интервал и решения

Утверждённые заранее заданные параметры: `margin = 0.5`, `confidence = 0.95`.
Обе долевые оси и нормированный structural score лежат в `[0,1]`.
Бюджет ошибки распределяется между двумя направлениями трёх осей:

```text
alpha_tail = (1 − confidence) / 6
h = sqrt(2 * ln(1 / alpha_tail) / T)
L = max(−1, D − h)
U = min( 1, D + h)
verdict = worse, если L > margin
verdict = better, если U < −margin
verdict = indistinguishable в остальных случаях
non_inferiority = confirmed, если U <= margin
non_inferiority = rejected, если L > margin
non_inferiority = inconclusive в остальных случаях
```

Каждая граница односторонняя; совместная защита шести границ — минимум 95%
при заявленных допущениях. Бюджет фиксирован на трёх осях, даже если часть
недоступна. «Лучше» здесь означает доказанное улучшение сверх такого же запаса;
«неразличимо» не означает равенство агентов. Недоступная ось имеет `verdict: null`
и причины; это статус доступности, а не четвёртый статистический вердикт.

Предпосылка — независимость между группами задач. Интервал относится к среднему
ожидаемому падению на объявленном наборе; перенос на неизвестные задачи не
обещается. Общая деградация окружения или утечка памяти между задачами может
нарушить предпосылку; имеющиеся предупреждения об окружении сохраняются.

На 5 задачах `h = 1.383834057`, на 25 — `0.618869404`. Поэтому даже полное
падение всех 25 задач не доказывает превышение запаса 0.5 этим методом.
Для такого предельного случая нужно минимум 39 независимых задач
(`h = 0.495492076`). На одинаковых 5×3 получится «неразличимо», NI не доказан.
Запас в 10 п.п. и интервалы шириной 40–50 п.п. на 5×3 не обещаются.
Подбор параметров после просмотра результата не является корректной приёмкой.

Источник формулы: [Hoeffding, 1963, Theorem 2](https://www.cs.rpi.edu/academics/courses/spring06/random/hoefding.pdf).
Численные значения проверены отдельным вычислением и deterministic fixtures.
Добавлена воспроизводимая offline-симуляция `evals/script/check-compare-noise.ts`;
её фактические результаты и ограничения приведены ниже.

## Надёжность и локальное правило регрессии

Для задачи с n известными конечными `pass` и c успехами:

```text
pass^1_i = c / n
pass^k_i = C(c,k) / C(n,k) = product(j=0..k−1, (c−j)/(n−j))
```

Если `c < k <= n`, значение ноль; если `n < k`, значение недоступно.
Средние по набору равновесные. Примеры: 2/3 → `pass^1=2/3`, `pass^3=0`;
3/6 → `pass^3=1/20`; 3/3 → `pass^3=1`. `pass@k` («хотя бы один успех»)
и `(c/n)^k` не подменяют эту формулу.

Термин «несмещённый» требует обменности наблюдаемых повторов для оценки
совместного успеха k повторов; при iid это оценка `p_i^k`. Допуск зависимости
внутри кластера для CI сам по себе не доказывает iid для этой интерпретации.
При неоднородных повторах публикуется доля успешных k-подмножеств с явным
ограничением интерпретации, а не безусловное обещание несмещённости.
[Определение pass^k в τ-bench](https://arxiv.org/html/2406.12045v1#S3).

По умолчанию k равен числу повторов, если `config.repeat` совпадает у A/B;
иначе требуется явный общий `--k` для pass^k. k не уменьшается по наблюдаемым
успехам или после infra_error. Если любой необходимой задаче не хватает
известных pass, общий pass^k недоступен и показано покрытие.

Локальное правило: только при `repeat=3` в обоих прогонах и трёх измеренных,
известных результатах оси в каждом задача 3/3 → 0/3 помечается «хуже:
наблюдаемый провал стабильной задачи». Проверяется отдельно для completion,
oracle и конечного pass. Для неполных/несравнимых данных guard не срабатывает.
Guard не меняет общий статистический verdict, не доказывает 95% регресс и
не становится симметричным доказательством «лучше» при 0/3 → 3/3.

## Структурная ось и происхождение оценки

Текущий полный `score` смешивает структуру, CSV и финальный ответ. Поэтому
добавляется необязательная явная `checklist.axis`: `structure | result | report`.
Отсутствие означает unclassified; ось не выводится по ID/тексту/флагам.
Structural score доступен только при полностью размеченной рубрике и непустом
structural subset. Он равен `100 * sum(passed structural weights) / sum(structural weights)`;
для вычислений не округляется. Численное превышение верхней границы из-за
арифметики floating point ограничивается 100, чтобы сохранённая оценка оставалась
в допустимом диапазоне. Старые `score/pass` и calibration thresholds
сохраняют прежнюю семантику.

Три встроенные рубрики размечаются вручную: import, transform, export, links,
no-extra-nodes — structure; result-rows — result; honest-report — report.
Внешние коллекции не изменяются; без полной разметки structure недоступна.
Explicit axis меняет `rubric_hash`, но не `agent_inputs_hash`. Loader условно
опускает отсутствующую axis, сохраняя hash непромигрированных рубрик.

`RunSummary.tasks[]` содержит необязательный `rubric_snapshot`:
`version: 1`, checklist с ID/weight/required/requires_result_file/requires_run/axis,
`oracle_applicable`, `oracle_tolerance`. Попытка содержит необязательные
`structural_score` и `evaluation_contract_hash`. Последний — SHA256 канонического
JSON `{ version: 1, rubric_hash, judge: {backend,codex_version,model,reasoning,
prompt_sha256,schema_sha256}|null, pass_threshold }`. Он фиксирует полный
контракт оценки, включая версию deterministic structural scoring через version.
Snapshot строится из загруженной рубрики; compare никогда не читает текущие
task.json для старого результата. Одинакового rubric_hash недостаточно, если
изменился судья, его prompt/schema или порог pass.

Измеренная попытка без пакета при включённом judge получает structure=0,
если рубрика пригодна; skip-judge, error, excluded attempt — null.
При `--judge-only` только фактически пересуженная или заново детерминированно
оценённая no-artifact попытка получает новый evaluation hash. Пересудейство
сохраняет фактический новый judge и `config.pass_threshold`; сохранённые старые
оценки сохраняют происхождение. Отсутствующий/несовпавший hash блокирует
oracle/structure и reliability соответствующих старых оценок, не выдавая их
за результат новой рубрики. Completion от оценочной рубрики не зависит.
Для legacy без snapshot доступны описательные прежние метрики; новая oracle/
structure статистика недоступна. Автомиграции исторических summary нет.

## Публичная граница и CLI

Новый чистый модуль `evals/src/compare-analysis.ts` экспортирует
`analyzeComparison(a: RunSummary, b: RunSummary, options?: Partial<ComparePolicy>)`.
`ComparePolicy = { margin: number; confidence: number; k: number | null }`.
Возвращает policy, причины несравнимости, три `axes`, reliability и task rows.
Повторно используемый публичный `evaluationContractHash` из `evals/src/evaluation.ts`
строит fingerprint из rubric hash, judge и pass threshold; run/rejudge и analysis
используют один и тот же контракт сериализации.
У каждой оси: `task_count`, `observed: {a,b,drop}|null`,
`interval: {lower,upper}|null`, `verdict`, `non_inferiority`, `reasons`.
Reliability: `k`, `a/b: {pass1,passk}`, `reasons`. Task row:
`id`, наблюдаемые значения каждой оси и `regressions: (completion|oracle|pass)[]`.

`compare(a,b,options?) → string` сохраняется, форматирует этот результат.
CLI сохраняет два позиционных run ID и Markdown-файл; добавляет только
`--margin`, `--confidence`, `--k`. Margin: конечное `[0,1)`; confidence:
конечное `(0,1)`; k: положительное целое. Неизвестный флаг, дубликат флага,
лишний аргумент, неверное число, некорректный summary — exit 2.
Метка `summary.label` принимает string (включая пустую) или null, как в run;
пустая метка не делает сохранённый прогон некорректным.
Штатный отчёт с регрессом/неразличимостью/несравнимостью — exit 0: release gate
через exit code не добавляется. Результат содержит параметры, метод, покрытие,
ограничения и причину локального guard. JSON export не добавляется.

Сохраняются identity gates модели, variant, входов, рубрики, судьи, схемы,
порога и эффективных task limits. Два неизвестных критических поля не дают
доказанной сравнимости. Два `judge=null` позволяют только completion; это
не unknown judge identity. Commit/source/binary агента остаётся сравниваемой
величиной, не gate. Различия Dock/Loginom остаются предупреждениями.

## Объём и приёмка

Код — только `evals/`; каноническая спека обновляется перед первым изменением
контракта. Нет изменения runtime, Protocol/HttpApi, зависимостей, установленного
CLI, профилей, bundle, сохранённых живых результатов, слияния или нового baseline.

Приёмка: публичные поведенческие тесты дают правильный task weight, pass^k,
широкий интервал одинаковых 5×3, направленные verdict на достаточном наборе,
guard конкретной задачи, недоступность неполных осей и корректный lineage
judge-only. CLI показывает те же выводы и не изменяет входные summary.
Полный `bun test`, `bun typecheck`, `git diff --check` из owning directories;
независимый review без открытых замечаний. Симуляция отдельно проверяет
statistical false alarm при зависимых повторах и отдельно частоту guard.
