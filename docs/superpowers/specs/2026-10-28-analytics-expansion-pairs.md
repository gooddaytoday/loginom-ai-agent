## Общие правила результата для D и B

- Имена колонок перечислены в карточках; их порядок не оценивается. Состав строк и порядок строк оцениваются: если не указан особый порядок, сортировка по перечисленному ключу по возрастанию, числа — численно, строки — с учётом регистра без локали. Технические ключи synthetic fixtures используют однозначные ASCII-коды; адаптация ключей реального источника документируется. Порядок исходных строк не является дополнительным ключом.
- Категории следуют порядку, указанному в карточке. В P13 пустой owner_id располагается перед непустыми в пределах order_id. Каждый указанный итоговый ключ уникален; исключения для перестановки кластерных меток описаны в P46/P47.
- CSV: UTF-8, имена колонок в заголовке, разделитель `;`, десятичная точка, без разделителей тысяч; строковый квалификатор `"`. Дата — `YYYY-MM-DD`, календарный месяц — `YYYY-MM`; отдельные год/месяц/день/час — целые числа. Флаги — целые 0/1. Неизвестное или неопределённое значение — пустая ячейка, не текст `NULL` и не ноль. Численный допуск кейса одинаков для обеих форм; окончательное число знаков выбирается при проверке реального экспорта так, чтобы не потерять требуемую точность.
- Счётчики и суммы отсутствующих фактов равны нулю только для явно сохранённого полного реестра или календаря. При нулевом знаменателе отношение неопределённо и остаётся пустым, если карточка не определяет иное. `*_pct` — проценты 0–100, `*_pp` — процентные пункты, доли — 0–1; индекс P23 имеет базу 100. Денежное отклонение — фактическая сумма минус ожидаемая; иные разности явно названы в карточке. Промежуточного округления нет.
- У синтетических финансовых fixtures одна денежная единица, суммы без налогов и дополнительных сборов, если карточка прямо не задаёт валюты или удержания. Булевы входные признаки задаются как 0/1; словари статусов, границы снимка и выбранный срез реальных данных опубликованы одинаково для D/B; их конкретные даты фиксируются вместе с fixture до расчёта gold.
- Для воспроизводимости любой выбранный стохастический native-шаг использует `seed=42` в обеих формах. Это общий технический параметр выполнения, не указание B на алгоритм. Для P46/P47 gold по-прежнему требует независимо доказанного optimum и совпадения результата native-исполнения; seed не заменяет эти проверки.
