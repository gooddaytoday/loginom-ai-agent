# Создание и правка dashboard Loginom из Desktop

Пользователь работает в браузере с [нынешним локальным стендом](../../../dashboard/README.md) и пишет пожелания в Loginom AI Agent Desktop на той же машине. Исполнитель сам собирает Desktop, запускает его, ведёт диалог для проверки и устраняет ошибки. Результат для владельца — сборка, из которой можно повторить создание и правку обычным кликом из Loginom.

## От узла до сообщения

- У узла без dashboard «Создать dashboard» подготавливает снимок и открывает Desktop. Над полем ввода видно «Создаём dashboard для узла “По убыванию ROI”».
- У готового dashboard «Dashboard» открывает само приложение. В его общей шапке «Изменить в чате» открывает Desktop с меткой «Изменяем dashboard “По убыванию ROI”». Открытие для просмотра оставляет пользователя в Loginom.
- Создание нового dashboard всегда открывает отдельный черновик в последнем активном окне Desktop, включая переход из занятого чата другого dashboard. Текст, вложения и метка прежнего чата сохраняются, выполняющийся запрос продолжает работу. Курсор стоит в поле ввода нового чата. Отправляет сообщение пользователь.
- При действии «Изменить в чате» Desktop использует открытый чат; на главном экране и при холодном запуске создаёт новый черновик. Явный переход из другого узла для редактирования заменяет метку в этом черновике. Простое переключение в браузере её не меняет. При отправке Desktop прикладывает ровно тот ID снимка, которому соответствует видимая метка. Отправленный запрос сохраняет свой адресат, в том числе при ожидании в очереди.
- Решение автора для первого варианта — использовать метку как вложение к одной просьбе. Её можно снять перед отправкой. После принятия сообщения метка снимается, при ошибке отправки остаётся с черновиком. Следующую адресную правку можно начать кнопкой «Изменить в чате».

## Выбранный подход

В [предыдущем дизайне](2026-11-09-loginom-dashboard-design.md) выбран отдельный вход в текущий чат через системную ссылку Desktop. Это позволяет использовать уже опубликованный неизменяемый снимок. Существующий `new-session` открывает пустой чат и принимает текст. Обращение к общей цели `/dashboard/current` подходит для отладки через Codex, но между отправкой сообщения и первым чтением агентом другой узел может стать текущим.

Ссылка передаёт только ID снимка и действие создания или правки. Desktop принимает известные действия и ID ожидаемого формата. Имя и привязку читает по ID у сервиса этого локального стенда. Директория, произвольный URL и команды из системной ссылки не передаются исполнителю. Если снимок уже исчез после перезапуска сервиса, Desktop сохраняет текст и предлагает снова открыть dashboard в Loginom. Браузер может штатно запросить разрешение открыть приложение.

Новый чат открывается в локальном проекте, которому принадлежат исходники dashboard. При редактировании текущий чат сохраняет свой проект и режим работы. Штатный агент `build` располагает командами сборки и редактирования. Для доступа к исходникам за пределами текущего проекта действуют обычные разрешения Desktop. Сквозную проверку исполнитель начинает в чате проекта dashboard.

В Desktop используется существующий путь от черновика до сообщения. Служебная текстовая часть запроса может указать агенту точный снимок без изменения пользовательского текста и публичного протокола. При явно переданном ID исполнитель работает только с этим снимком. Инструкция проекта о чтении `/dashboard/current` должна применяться только к отладочному входу из Codex без явного ID. Нужный узел определяется в браузере пользователя. Агенту не требуется открывать его живую сессию Loginom.

Исходники брендированного Desktop и изменения стенда находятся в разных ветках. Для Desktop используется продуктовая версия с обработчиком `loginom-ai-agent://`. Для Loginom сохраняется существующая привязка dashboard и публикация по ID, включая проверку типов и сборку. При холодном старте Linux передаёт ссылку в аргументах первого процесса. При повторном открытии её получает уже работающее окно. Исполнитель проверяет оба входа и использует существующую доставку ссылок из Electron в интерфейс.

## Что проверить на стенде

1. Первый сквозной результат — правка готового dashboard из уже открытого чата. Исполнитель открывает dashboard A в собственной копии пакета, нажимает «Изменить в чате» в браузере и отправляет короткую просьбу. Затем открывает dashboard B из другой копии с тем же GUID узла. После публикации у A видна заказанная правка на данных Loginom, у B остаётся прежний вид. Проверяются сообщение и оба dashboard.
2. Из браузера при закрытом Desktop начать создание для узла без dashboard. В новом черновике видны правильное имя и курсор. Исполнитель отправляет просьбу штатному агенту. По кнопке Dashboard открывается созданное приложение. На главном экране уже работающего Desktop та же кнопка также ведёт в новый черновик. При создании из занятого чата другого dashboard открывается отдельный черновик; возврат в прежний чат подтверждает сохранность текста и метки, а прежний запрос продолжает выполняться.
3. Для запуска и отладки исполнитель использует отдельный профиль и свои копии пакетов. Проверяет системную ссылку в браузере, фактические права агента на чтение снимка, правку и публикацию, а также реальный маршрут отправки Desktop. Прямой вызов обработчика или публикация исполнителем из терминала не подтверждает пользовательский сценарий. Для владельца указываются проверенная сборка и способ направить в неё обычную ссылку со стенда.

Этап охватывает Linux и указанный локальный стенд с одним пользователем. Удалённые серверы, доставка выпусков другим пользователям и другие ОС находятся за его границами.
