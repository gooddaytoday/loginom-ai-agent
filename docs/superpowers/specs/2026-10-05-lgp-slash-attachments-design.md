# Вложения Loginom в slash-командах

Исправление проверено на ветке `docs-no-browser`, исходный HEAD `ba30b8b0b`.

## Подтверждённый дефект

`sendFollowupDraft` отбрасывал `.lgp` без `sourcePath`, не сообщая агенту о вложении. Основная slash-отправка в `createPromptSubmit` передавала пакет как data URL даже при наличии пути. Обычный prompt уже передавал ссылку на пакет или synthetic-текст с просьбой указать абсолютный путь.

## Решение

Общий `buildAttachmentParts` используется обычным prompt и обоими путями slash-отправки. Пакет с `sourcePath` передаётся как `file://` с экранированием пути; пакет без пути даёт прежний synthetic-текст. Пользовательские `arguments` остаются неизменными. В V1-адаптер передаются полные `legacyParts`, чтобы сохранить MIME и текстовые подсказки отдельно от аргументов.

Контракт V1 `SessionPrompt.CommandInput.parts` расширен текстовыми частями. Сервер добавляет их к сообщению после раскрытия `$1`, `$ARGUMENTS` и shell-вставок шаблона. Имя вложения остаётся буквальным контекстом: shell-код из него не запускается. Для `subtask` текстовые подсказки и пути пакетов добавляются в prompt дочернего агента после раскрытия шаблона; части с `ignored: true` пропускаются.

V1-адаптер сохраняет MIME из полных частей; для вызовов без `legacyParts` он распознаёт `.lgp` в файловом URI независимо от регистра расширения. Остальные загруженные вложения продолжают передаваться как data URL. Байты `.lgp` не читаются и не передаются модели в проверенных путях подготовки вложений.

Legacy JavaScript SDK пересоздан через `./packages/sdk/js/script/build.ts` в изолированном временном профиле. `bun run generate` из `packages/client` также выполнен; его сгенерированные файлы не изменились, поскольку публичный V2 Protocol не менялся.

## Приёмка

Тесты вызывают `createPromptSubmit.handleSubmit` и `sendFollowupDraft`: проверяют сохранение аргументов, несколько пакетов без пути, пакет с путём, экранирование пробела и `#`, соседнее PNG-вложение и отсутствие бинарного data URL пакета. Тесты V1-адаптера проверяют фактическое HTTP-тело: неизменные аргументы, отдельный synthetic-текст и MIME `application/x-loginom-package`.

Интеграционные проверки `SessionPrompt.command` используют временный локальный provider и реальные командные шаблоны. Для обычной команды и `subtask` проверяются буквальное имя со вставкой `!\`touch ...\``, отсутствие побочного файла, неизменные `$1` и `$ARGUMENTS`, выполнение доверенной shell-вставки шаблона, доставка подсказки и пути пакета, исключение байтов `.lgp` и игнорируемого текста из запроса модели.

Проверки: 58 тестов `prompt-input`, 10 тестов V1-адаптера, 21 тест HTTP-сессий; полный `SessionPrompt` — 64 pass, 1 существующий skip. Дополнительно повторены два интеграционных сценария после проверки `ignored`. `bun typecheck` для `app`, `agent`, `sdk/js`, Prettier и `git diff --check` прошли. Проверка установленного Desktop и внешней модели не выполнялась.
