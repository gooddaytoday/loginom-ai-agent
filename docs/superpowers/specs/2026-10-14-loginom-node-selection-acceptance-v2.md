# Приёмка политики выбора узлов — версия 2

Версия: `node-selection-policy-v2`. Утверждена прямым указанием пользователя
2026-10-14; запись 2026-10-14T14:33:36.064166+00:00. Применяется к отдельной повторной оценке
сохранённых доказательств и всем последующим попыткам текущей матрицы.
Исходный admission lock/protocol, attempt-файлы, audit и вердикты неизменны.
Это версия оценки, а не заднее изменение условий уже выполненных запусков.

## Три независимые оценки

1. **Политика:** `passed`, `violated` или `insufficient-evidence`. Проверяется
   весь доверенный журнал построения, включая временные узлы, failed/pending
   JS apply и дочерние сессии, а не только итоговый LGP. Отсутствие JS при раннем
   отказе до содержательных аналитических решений не даёт PASS.
2. **Аналитика:** исходные oracle/calculation/graph/export результаты сохраняются
   отдельно: правильный результат, неправильный результат или результат не
   получен/не проверен. Ошибка oracle не классифицируется автоматически как
   технический отказ. Политика PASS не превращает её в функциональный PASS.
3. **Runtime/завершение:** исходные CLI/runtime/Host/cleanup результаты и strict
   own release оцениваются отдельно. Адресное ручное освобождение не меняет
   первоначальный normalcleanup false, ACK false или неуспешный exit.

## Приёмка политики

- Во всех 25 candidate нет ни одной необоснованной JS-попытки. Подтверждённое
  нарушение останавливает серию; недостаток доказательств не объявляется PASS.
- Все шесть стандартных задач содержательно покрыты: решения и реальные
  запросы стандартных узлов относятся к ключевым аналитическим операциям
  задачи; полный журнал подтверждает отсутствие JS. Успешный результат не
  обязателен. Только prepare/import без содержательной аналитики недостаточны.
- Явный запрос JS проверен положительно: реальное JS-применение соответствует
  запросу и аналитической роли; код не имитирует работу и не подставляет oracle.
- Функциональный пробел проверен положительно: до JS агент проверил известные
  стандартные возможности и сформулировал конкретный пробел; фактический JS
  выполняет только недоступную часть. Стандартные доступные операции оставлены
  стандартным узлам, включая попытки, завершившиеся техническим блокером.
- При ошибке стандартного узла агент исправляет её либо сообщает конкретный
  блокер; ошибку не использует как основание перехода на JS. Не требуется
  functional recovery PASS или специальная restored-draft квитанция для PASS
  этой политики, если фактический отказ и последующее поведение доказаны.
- Технически неуспешная попытка может получить отдельный policy PASS только
  при достаточной полноте истории и содержательных решениях; отсутствие LGP
  само по себе не запрещает такой вердикт и не доказывает его.
- Сохраняются обязательные manual review JS-исключений, recovery, отказов,
  аномалий и трёх воспроизводимо выбранных стандартных успешных candidate.
- Полная матрица сохраняется: baseline6 + candidate25 (standard18, explicit3,
  tags3, recovery1). Снижение успешности, отдельные oracle/functional отказы
  и превосходство над baseline не являются блокирующими условиями политики.
- Baseline только для описательного сравнения на том же runtime/модели/inputs.
  Исторические серии с другим runtime не переносятся. Повторы не заменяют
  исходные отказы; альтернатива нужна только при недостаточном policy coverage,
  фиксируется до запуска и учитывается отдельно от31.

## Неизменные требования перед следующим процессом

Текущий safe CLI не прерывается ради переоценки. Model процессы профиля
последовательны. Next только после terminal CLI/runtime/Host, подтверждённого
освобождения собственной Loginom-сессии и профиля, доверенной полной истории
и обязательного review. Послабление функциональной приёмки не ослабляет
strict release и запрет JS после стандартной ошибки.

## Дополнительные вердикты и происхождение

Для каждой попытки отдельный новый policy-v2 verdict со ссылкой на эту версию
и SHA, phase/task/attempt/Session, исходный протокол/SHA, сохранённые evidence
и их hashes, substantive selection evidence, JS rationale/role, полноту истории,
policy verdict/reason/reviewer. Аналитика и runtime отражаются исходными
значениями, original verdict не переписывается.

Исходный frozen runner продолжает неизменные условия запуска; новый оценочный
слой не редактирует locked files. Если более строгий original gate остановит
попытку из-за аналитического результата, перед продолжением отдельно проверяются
policy-v2 и strict release; oracle failure не подменяется technical-failure.
Минимальное изменение audit/runner допустимо лишь при подтверждённой
необходимости, по TDD, отдельной prospective версии и без runtime rebuild.

## Итоговый отчёт

Отдельно: принята ли политика и достаточно ли покрытия; какие расчёты верны,
неверны или отсутствуют; normal runtime reliability и manual recoveries;
ограничения описательного baseline сравнения. Политика может быть принята при
достаточных доказательствах, даже если некоторые расчёты и сессии завершились
неуспешно. Не объявлять функциональную приёмку всех узлов.
