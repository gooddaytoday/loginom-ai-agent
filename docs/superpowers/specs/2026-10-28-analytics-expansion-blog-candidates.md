# Каталог постановок из полного архива блога Loginom

Срез: 28 октября 2026 года. Основа — [полный обзор](../../research/analytics-evals/2026-10-28-loginom-blog-archive.md) и [реестр всех 635 публикаций](../../research/analytics-evals/2026-10-28-loginom-blog-inventory.md). Связанные документы: [50 пар первой очереди](2026-10-28-analytics-expansion-pairs.md), [семейства B01–B20](2026-10-28-analytics-expansion-backlog.md), [резерв R01–R08 и демопримеры](2026-10-28-analytics-expansion-loginom-sources.md).

Это **95 карточек механизмов и условий корректности**, а не 95 готовых или независимых новых evals. Некоторые расширяют P/R; связанные варианты одного механизма и повторные публикации объединены. Карточка с несколькими вариантами будет разделена на конкретные задачи только при отборе. Первые 100 остаются 50×2, без автоматической замены выбранных пар.

Во всех карточках вход и проверка — предложение проекта на основе источника. Наличие метода в Loginom или ссылки на LGP не означает, что агент настраивает нужный режим. «Текущая композиция» означает кандидата на существующих обработчиках в границах основного design; до включения нужен один подтверждённый полный прогон. Data/RowNum/cache, RegEx, ISO/date-функции и перечисленные статистические функции требуют отдельной короткой проверки. Неподдержанные специальные узлы не заменяются JavaScript. Естественная формула или сведение таблиц допустимы только для прямо описанного ограниченного контракта; они не закрывают полный модельный/оптимизационный кейс.

Общий результат аналитического кейса — сценарий Loginom и итоговая таблица. Для деревьев, визуализации, повторного запуска и инспекции пакета дополнительно указан новый контракт артефактов/harness: эти случаи не включаются в первую очередь без его поддержки. Численный oracle независим от reference; видео и большинство внешних вложений не изучены. Три прочитанных PDF-задания выделены в обзоре. Право распространения данных и пакета проверяется перед импортом каждого кейса.

### LB001. Аудит эксперимента и взаимодействие факторов

Источники реестра: [A002](../../research/analytics-evals/2026-10-28-loginom-blog-inventory.md#a002).

Источники: [A002](https://loginom.ru/blog/ab-test). В тексте отдельно описаны A/A, закрепление группы повторного посетителя и многовариантное тестирование.

- Вход → выход: назначение user_id→variant и события → конфликты назначения, уникальные участники, дисбаланс распределения и показатели на пользователя; для 2×2 — основные контрасты и взаимодействие.

- Oracle/ловушка: независимые множества пользователей и таблица 2×2; повторные визиты не увеличивают размер независимой выборки, эффект взаимодействия не равен сумме двух marginal effects. A/A различие само по себе не доказывает неисправность: статистический критерий и уровень задаются явно.

- Путь: аудит таблиц и контрасты — существующие group/cross table/join/calculator; статистические интервалы/рандомизационный тест требуют проверки функций или режима sampling. Генератор назначений не маскировать JS.

- Связь: B08/B09; P09/P38 близки по знаменателям, но не проверяют корректность эксперимента. Данные синтетические; статья fixture не публикует.

### LB002. ABC методом касательных

Источники реестра: [A003](../../research/analytics-evals/2026-10-28-loginom-blog-inventory.md#a003).

Источник: [A003](https://loginom.ru/blog/abc-tangent), [псевдокод/реализация](https://github.com/loginom/loginom-silver-kit/blob/master/docs/abc-analysis-method-of-tangents.md).

- Вход → выход: объект и положительный вес → A при весе не ниже среднего всей совокупности; затем B/C относительно среднего оставшихся; вывести группы и использованные пороги.

- Oracle/ловушка: независимые два PARTITION, равенство среднему входит в верхнюю группу; равные веса, пустой остаток, один объект и недопустимые отрицательные/нулевая сумма. Не подменять результат фиксированными 80/95%.

- Путь: две естественные группировки среднего, joins/filters/calculator; специальный узел не обязателен для опубликованного двухшагового правила, фактическую передачу порога проверить. Вызов Silver Kit отдельно не считается доступным.

- Связь: B04/B05/P41/R08; добавляет именно иной метод порогов. Пакет и права из linked repo не проверены.

### LB003. Структуризация НСИ и извлечение из документов

Источники реестра: [A006](../../research/analytics-evals/2026-10-28-loginom-blog-inventory.md#a006), [A008](../../research/analytics-evals/2026-10-28-loginom-blog-inventory.md#a008), [A009](../../research/analytics-evals/2026-10-28-loginom-blog-inventory.md#a009).

Источник: [A006](https://loginom.ru/blog/ai-loginom-ld25).

- Вход → выход: описания товаров и заданный классификатор → class_id, извлечённые атрибуты и unknown для отсутствующих фактов; отдельный вариант — многостраничные PDF объектов недвижимости → поля со страницей/фрагментом происхождения.

- Oracle/ловушка: вручную размеченный компактный корпус, exact/F1 по атрибутам и проверка источника; неизвестный размер нельзя выдумывать по типичному товару, страницы разных объектов нельзя объединять.

- Путь: backlog B16/B01: токенизация/классификация или разрешённый LLM connector, JSON-tree parsing; PDF-import/OCR/multimodal и циклы сейчас не поддержаны. Статья прямо указывает кодовый этап загрузки PDF — не выдавать за текущий native node.

- Новизна: конкретизирует B16.1/B16.3; provenance полей и неизвестность должны входить в oracle. Нет открытого размеченного набора; использовать собственные документы с разрешёнными данными.

Дополнительный источник: [A008](https://loginom.ru/blog/ai-models-loginom) содержит точный пример класса «Автошина» и [ZIP](https://downloads.loginom.ru/using-external-ai-models-loginom.zip): пустая строка при неизвестном атрибуте, канонизация «-»/«/», OCR-ошибки и разные текстовые формы одного размера. Нужны REST POST/auth, JSON parsing, циклы и внешний сервис; текущий GET этого не покрывает. A009 подтверждает тему без новых правил.

### LB005. Инкрементальные признаки и составные решения

Источники реестра: [A011](../../research/analytics-evals/2026-10-28-loginom-blog-inventory.md#a011), [A058](../../research/analytics-evals/2026-10-28-loginom-blog-inventory.md#a058), [A063](../../research/analytics-evals/2026-10-28-loginom-blog-inventory.md#a063).

Источник: [A011](https://loginom.ru/blog/alpha-capital-case).

- Вход → выход: исходные портфели, изменения и снимок предрассчитанных признаков → обновлённые признаки и решение по составному ордеру при явно заданных денежных/рисковых ограничениях.

- Oracle/ловушка: полный пересчёт из исходных фактов равен инкрементальному; изменение одного договора не теряется, повторное событие не удваивает эффект, решение проверяет оба ограничения.

- Путь: пакетная сверка подготовленных snapshots доступна через join/group/calculator; настоящий CDC/state/очереди/DB integration — отдельный backlog B02/B19/B20. Не строить инфраструктуру только ради этой постановки.

- Данные частные: синтетический ledger и фиксированные правила. Числа ускорения кейса не становятся критерием eval.

- Дополнительные источники: [A058](https://loginom.ru/blog/case-positive-technologies), [A063](https://loginom.ru/blog/change-data-capture).

- Обязательные synthetic границы: одинаковый update timestamp у разных ключей, late arrival, удаление, повтор события и изменение после чтения watermark. Итог incremental должен совпасть с эталонным полным снимком; missing watermark не выдаёт пустой успешный результат.

- В A063 таблица delta для клиента 10 содержит старое значение, а текст timestamp-условия противоречив. Эти примеры нельзя копировать как expected; хранить пояснение расхождения и независимый эталон. Exactly-once как требование статьи не гарантируется простым max(timestamp).

- Подготовленные снимки сравниваются текущими left joins в обе стороны и Union/Filter; live CDC, состояние и транзакции требуют отдельных возможностей и harness.

### LB006. Эластичность спроса с явными предпосылками

Источники реестра: [A012](../../research/analytics-evals/2026-10-28-loginom-blog-inventory.md#a012).

Источник: [A012](https://loginom.ru/blog/altmacros-solution).

- Вход → выход: цена, спрос и известные контекстные факторы → коэффициент эластичности по заданной модели и прогноз при изменении цены.

- Oracle/ловушка: генератор с известной зависимостью, независимая оценка; отличать ассоциацию цены со спросом от причинного эффекта акции/сезона, не обещать рост прибыли без функции затрат.

- Путь: log-log OLS может использовать текущую регрессию после проверки log-функций и обучения; holdout/application и causal identification — B10/B09 backlog. Метод здесь предложение eval, в статье его алгоритм не раскрыт.

- Связь: P43–P45 близки по регрессии, B20 по решению; ценность новой задачи — масштаб и интерпретация коэффициента. Открытого fixture нет.

### LB007. Полнота постраничного источника

Источники реестра: [A013](../../research/analytics-evals/2026-10-28-loginom-blog-inventory.md#a013).

Источник: [A013](https://loginom.ru/blog/amazons3).

- Вход → выход: контролируемые ответы списка объектов с continuation token → полный реестр объектов и агрегат по всем частям; HTTP200 с некорректным XML → явная ошибка источника.

- Oracle/ловушка: независимый manifest, отсутствие потерь и повторов; первая тысяча объектов не равна всему источнику, успешный HTTP не означает валидные данные.

- Путь: B01/B16/B19 backlog: REST auth, pagination/control loops, XML parsing. Офлайн набор ответов полезен для преобразования, но не доказывает live-интеграцию. Специальные узлы не обходить JS.

### LB008. Оптимизация предложений при связанных ограничениях

HQC использует log-likelihood, а не likelihood; штраф не всегда мягче AIC. Фиксированные модели и логарифмы можно оценить естественной текущей композицией после проверки функций, auto-selection — отдельно.
- [A210](https://loginom.ru/blog/introduction-loginom) → последующее исследование: официальные examples и практикум, открытые учебники и презентации студентов A163/A164. Они ещё не прочитаны и не лицензированы в рамках этой части; не засчитывать их как проверенные задачи.

## Как превратить карточку в пару evals

Сначала зафиксировать полный контракт задачи и отличие от существующего корпуса. Затем выбрать разрешённый набор или синтетическую пограничную выборку, построить независимую ожидаемую таблицу, проверить минимальный сценарий и только после этого написать detailed/business версии. Бизнес-формулировка сохраняет определения и обязательные артефакты, но не подсказывает алгоритм. Источник, oracle, ограничения данных, возможности узлов и результат повторного исполнения сохраняются в материалах кейса по планируемому контракту `loginom-eval-case`.

Статьи с закрытыми данными дают постановки, а не воспроизводимый benchmark. Перечень найденных ZIP/LGP/PDF и ссылок на библиотеки находится в реестре; ни первая страница блога, ни число скачанных файлов не используются как мера покрытия.
