# Обычное скачивание артефактов в браузере Dock

## Задача и доказанная причина

Исправить доставку CSV, описанную в [диагностике](../../testing/loginom-ai-agent/artifact-save-picker.md). На защищённом origin Loginom 7.4.2 выбирает File System Access API. Постоянный слушатель `filechooser` в MCP вызывает исключение `showSaveFilePicker`; снятие слушателя не создаёт ожидаемое runtime событие `download`.

## Решение

До выполнения скриптов Loginom скрывать только `globalThis.showSaveFilePicker` через штатный Playwright init script. Loginom сам выберет существующий резервный путь обычного скачивания. Слушатели MCP, `input[type=file]`, `showOpenFilePicker`, серверные скрипты и алгоритм сверки байтов не изменяются.

Общий модуль `client/lib/browser-downloads.mjs` экспортирует `browserDownloadScript(loginomUrl)`, возвращающий JavaScript для `addInitScript`/MCP `browser.initScript`. Если URL задан, script действует только на точном origin этого URL. В старом standalone Dock без настроенного URL политика применяется ко всем страницам принадлежащего Dock браузерного контекста. URL никогда не вставляется в код без `JSON.stringify`; query и credentials в script не попадают.

Есть два владельца начальной навигации:

1. `client/lib/session.mjs`: записать script в приватный каталог сессии, указать абсолютный путь в MCP `browser.initScript`. Это покрывает браузер, который запускает сам MCP, включая reload, новые вкладки и фреймы.
2. `src/connection-check.mjs`, `loginBrowser`: зарегистрировать тот же script на контексте **до** `loginPage` и первого `goto`. Desktop/CLI авторизуют страницу раньше создания MCP и передают ему этот же контекст. Регистрация только в конфиге MCP была бы слишком поздней.

Дополнительный браузер/CDP не создаётся. На сторонних origin настроенной сессии API остаётся доступным. На незащищённом origin отсутствие API допустимо и не вызывает ошибки. Невозможность записать/подключить script прерывает запуск обычным существующим путём ошибки; никаких успешных квитанций без проверки bytes не появляется.

## Альтернативы

- Управлять системным диалогом и прямой записью через File System Access API: существенно расширяет контракт получения/очистки файлов и отличается между ОС; для исправления не требуется.
- Снять перехват `filechooser` или обновить MCP: не меняет способ сохранения Loginom и не обеспечивает `download`, поэтому не решает задачу самостоятельно.
- Chromium feature flags: затрагивают более широкую поверхность API и зависят от внутренних флагов браузера; узкий init script уже подтверждён экспериментом.

## Проверки и критерии завершения

- Регрессионные тесты используют настоящий pinned Chromium и MCP, а не подставное событие `download`: источник API определён до скрипта приложения, обычный download даёт ожидаемые bytes/hash, загрузка через `setInputFiles` и file chooser остаётся работоспособной.
- Покрыть оба запуска (MCP-owned и предварительно авторизованный managed context), reload/новую вкладку, точное ограничение origin. Browser-тест требует явного пути к pinned Chromium; обычные проверки модуля выполняются без браузера.
- На Loginom 7.4.2 выполнить настоящий `dock_artifact_deliver` с новым допущенным CSV через managed runtime в headed/headless: `SUCCEEDED`, подтверждённые bytes/hash и cleanup. Не повторять неопределённую операцию под новым ID.
- Проверить поддерживаемый TSV и скачивание результата экспорта через существующий механизм, а также сохранение `.lgp`, чтобы сессия могла продолжить работу после доставки. Все данные acceptance имеют уникальные имена и отдельный профиль.
- Прогнать релевантные artifact/connection/source-pin тесты и полный client suite с Node 24.19.0 из `client/`.
- Записать результат и границы acceptance в диагностике и правило владения ранним init script в `packages/loginom-runtime/AGENTS.md`. Изменение исходников не объявляется проверкой уже установленного Desktop/CLI или других ОС.

Версии Node 24.19.0, MCP 0.0.80, Playwright 1.63.0-alpha-2026-08-31 и Chromium revision 1243 сохраняются. Сборка переносит весь `client/lib`, source pin автоматически включает новый `.mjs`.
