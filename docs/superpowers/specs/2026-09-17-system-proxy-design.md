# Системный прокси Linux и авторизация ChatGPT

Пользователь подтвердил 17 сентября 2026: Loginom AI Agent должен использовать системные HTTP/HTTPS-прокси. Это уточняет прежнее решение сохранить способы подключения моделей.

## Подтверждённая причина

Установленный DEB 0.1.0 передавал Node только proxy-переменные shell. В GNOME ручной системный прокси был включён, но соответствующие переменные отсутствовали. Оба прямых запроса к auth.openai.com возвращали `403 unsupported_country_region_territory`. Через настроенный системный прокси device flow получил 200, а заведомо неверный authorization code дошёл до проверки и вернул `401 token_expired`.

## Решение

При запуске Linux main читает ручные настройки GNOME, после загрузки shell применяет системные HTTP/HTTPS-маршруты и исключения. Системная настройка имеет приоритет над конфликтующими переменными окружения. Node main и utility backend включают proxy support; изолированный runtime получает только разрешённые сетевые/desktop-переменные, без ключей провайдеров. Localhost остаётся прямым. Отказ настроенного прокси не разрешает прямой повтор.

Варианты: задавать proxy вручную в launcher устранило бы проблему только на этой машине; использовать renderer как HTTP-мост расширило бы IPC и затронуло streaming. Выбран импорт системной конфигурации в существующий Node proxy transport. Способы OAuth, client ID и контракты OpenAI не меняются.

Диагностика OAuth включает HTTP-статус и только известные коды ошибок. Сырые ответы, ключи и authorization codes не выводятся. Исправленный desktop получает версию 0.1.1; старый пакет и пользовательский профиль сохраняются.

## Проверки и границы

Unit-тесты: системный приоритет, оба регистра переменных, общая настройка для HTTP/HTTPS, IPv6, исключения, отсутствие изменений других платформ, отказ некорректной конфигурации. Интеграция: настоящие Node HTTP/fetch/HTTPS CONNECT, localhost bypass, запрет прямого fallback; затем оба OAuth-маршрута в packaged backend и Loginom check/save/restart.

Импорт в Node охватывает ручной GNOME HTTP/HTTPS без proxy-auth. Изменение настроек требует перезапуска. PAC/SOCKS, KDE и нативные Windows/macOS остаются отдельными расширениями. Полную авторизацию собственной учётной записи выполняет пользователь.
