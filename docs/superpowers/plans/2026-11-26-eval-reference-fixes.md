# Исправление оценки эталонов Loginom

> Рабочий процесс — Subagent-Driven Development и TDD для кода harness.

**Цель** — исправить четыре причины ошибочных вердиктов в десяти кейсах, проверить спорный `city-weather-risk` и закрепить отдельно проверенную версию корпуса.

**Подход** — уточнить конкретные рубрики и связанные места в SPEC, сохранить общий промпт судьи. Штатный harness передаёт ровно недостающее доказательство доставки. Копии архивов и синтетические контрпримеры проходят через обычный судейский путь.

**Основание** — аудит от 26 ноября 2026 и реестр 166 кейсов. База `loginom` на `154a040c8bca857ce28423ba5f2c90f443bf88fc`, деревья задач и калибровки совпадают с `2eb327b3982dab41e3a6c977035c74ce40e02543`.

## Global Constraints

- Сохранить побайтно reference.lgp, входы, oracle и исторические вердикты. LAB-901/LAB-1747 и 876 контрольных измерений остаются исходной точкой сравнения.
- Новый корпус — Git-снимок с идентификатором версии и SHA-256. Prompt, входы, oracle, таймауты и веса сохраняют прежние значения. Права, граф, формат CSV и доказательства исполнения продолжают проверяться.
- Промпт `evals/src/judge-prompt.md` оставить побайтно прежним. Модель адресной калибровки — `gpt-6-sol/xhigh`. Если понадобится общий промпт, сначала пересмотреть план с учётом обязательной полной калибровки.
- Закрытые архивы и временные данные держать в каталоге временных данных владельца. В Git сохранить обезличенные результаты, воспроизводимый рецепт вариантов и хэши. Перед каждым коммитом проверить подготовленное через `bun run secrets staged` и штатный hook. Слияние и публикация вне задачи.

### Task 1: Рубрики десяти кейсов

- [x] Уточнить `task.json` и только при необходимости пояснение в `SPEC.md`: `gdCount` считает все строки, включая пустые и null, `gdNullCount`/уникальные значения имеют другую семантику. Для contract-payment-churn `gdSum(churn)` допустим при доказанном 0/1 на группируемом входе.
- [x] Уточнить обязательные пункты train-only-mase-business и tied-score-auc-business. `Count(Replace(a,b,"",False,False))=0` для непустых ключей использует одно регистрозависимое вхождение. Повтор подстроки и другой регистр должны отклоняться.
- [x] Уточнить observed-purchase-cohort-retention-business. `frtIsNotNull` допустим с типизированным чтением строки I08 из того же импорта в `input-delivery.json`, пустой ключ равен null, обе ветви проходят действующий фильтр. При отсутствии такого подтверждения вариант должен явно исключать и null, и пустую строку.
- [x] Уточнить age-pressure-correlation. Для реальной попытки судья сверяет успешно выполненный импорт с сохранённым XML и машинно сверенной доставкой, цепочка обязательна, совпадающий CSV и basename недостаточны. Название материала согласовано с задачей 2, `input-delivery.json`. Для обычной статической калибровки на заведомо поданном эталоне проверяется его граф; без квитанций ей не приписывается реальное выполнение.
- [x] Обновить только соответствующие source hashes существующих near-miss (без изменений ожиданий), прогнать штатную загрузку и независимый пересчёт калибровки. Точное изменение задачи city откладывается до результата задачи 3.

### Task 2: Квитанция исходника для живого судьи

- [x] Начать RED через публичные `parseEvents` и `prepareJudgeDir` или основной judge путь. Из завершённого доверенного результата Dock принять только подтверждённую доставку, сверенную с SHA-256 и размером указанного приложения из корпуса. Передать узкий `input-delivery.json` только для нужного кейса; избыточные данные, credentials и произвольные поля исключить. Формат не должен выдавать доставку за успешное выполнение: XML и рецепты node-readbacks сопоставляются в рубрике.
- [x] GREEN минимальным изменением harness. Следующим RED отдельно проверить несходящийся SHA, неподтверждённую доставку и правильный SHA/размер с чужим путём назначения. Проверять точный полный путь в readback и привязку к тому же сохранённому узлу, а не basename.
- [x] Отдельный RED для cohort. Типизированные I08/client=null из успешного свежего чтения того же импорта должны дойти до судьи даже при обрезке общего node-readbacks. Пустая строка, чужой узел и неуспешное чтение не дают этого доказательства. Сохранить читаемость старых run.json; для архивного replay использовать исходные events.jsonl через штатный parseEvents. Точки приёма и scoring оставить прежними.
- [x] Проверить, что байты `judge-prompt.md` неизменны, и что появление квитанции не меняет чужие рубрики/пороговые значения. Проверить `bun typecheck` и затронутые тесты из evals.

### Task 3: Нативный RegExMatch

- [x] Отдельная локальная одноразовая копия сервера и пакета, без доступа к общему стенду и его хранилищу. Пин Loginom 7.4.2 и образ из summary LAB-1996. Выполнить сохранённое выражение целиком для Rain, rain, RAIN и Rain с LF. Подтвердить на выходе исходный LF (например, длиной строки) и записать хэш пакета, образ и четыре ответа. Целевой результат 1/0/0/0 определяет, допускается ли сохранённое выражение по существующему смыслу. При невозможности записать конкретный блокер и продолжить.
- [x] Если результат показывает эквивалентность, пояснить допустимость точного RegExMatch в рубрике без ослабления контракта и пересудить копию. При неэквивалентности зафиксировать сохранение критерия.

### Task 4: Архивное пересуживание, адресные контрпримеры и выпуск версии

- [x] Перепроверить SHA-256 архивов, извлечь/скопировать только выбранные попытки. Взять все документированные ошибочные вердикты с доступными пакетами и сохранённые отрицательные контроли (две выгрузки в один путь, целое с дробной частью представления). Не изменять исходные результаты.
- [x] Для каждой из четырёх причин выполнить допустимый вариант и близкий неверный с конкретным ожидаемым непройденным пунктом. Повторные вызовы только по транспортной ошибке штатным механизмом.

Подтвердить целостность всех защищённых файлов. Сохранить итоговый отчёт по каждому кейсу и вывод по city. Проверить релевантные evals тесты, типы и итоговую ветку независимым ревью.
