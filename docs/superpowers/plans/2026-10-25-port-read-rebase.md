# Port reading rebase Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Перенести `port-read-design` на текущую локальную `loginom` и проверить работоспособность доступными тестами проекта.

**Architecture:** Сохранить локальную точку возврата, выполнить обычный rebase, затем независимо сравнить деревья и последовательности патчей. Использовать существующие команды пакетов и CI, без нового тестового runner.

**Tech Stack:** Git, закреплённые проектом Bun и Node, Python unittest, Playwright.

**Spec:** Прямое поручение владельца: rebase на текущую `loginom`, затем все тесты.

## Global Constraints

- Не менять основной checkout, чужие незавершённые изменения и установленный продукт; без push, PR и слияния.
- Выполнять тесты и `bun typecheck` из каталогов пакетов. Зависимости worktree не должны ссылаться на исходники другого checkout.
- Сохранять полные журналы вне Git; не включать секреты. Отделять ошибки продукта от ограничений окружения и ранее существовавших сбоев.
- Ожидаемый размер: один документ, около 60 строк; продуктовых изменений не ожидается. При конфликтах или новой регрессии сначала воспроизвести причину.

## Review Focus

- Перенос не теряет коммиты: сравнить `git range-diff` и итоговое дерево с точкой возврата.
- Ошибочная база: зафиксировать SHA локальной `loginom` перед rebase и подтвердить её предком результата.
- Общие node_modules: проверить workspace-ссылки, при необходимости восстановить отдельные зависимости из lockfile.
- Ложный зелёный результат: учитывать каждый пакет с тестами, отдельные Node/Python-проверки runtime и CI-проверки типов/генерации.
- Недоступные стенды и ОС: явно перечислить пропуски; не выдавать локальные unit-тесты за новый живой модельный прогон.
