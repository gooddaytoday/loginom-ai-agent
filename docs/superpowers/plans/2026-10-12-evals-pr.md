# Подготовка evals PR

**Goal:** создать проверенный PR `evals → loginom` с локальной проверкой harness, существующими GitHub gates и успешной кандидатной сборкой.

**Architecture:** harness проверяется локально по собственному lockfile. Отдельный `evals-unit` job в reusable `test.yml` выполняет только offline infrastructure tests и typecheck; существующие workflows проверяют продукт и сборки. Исправления только по наблюдаемым отказам. Рабочее дерево пользователя сохраняется; работа выполняется в отдельном checkout.

**Tech Stack:** Bun 1.3.14, GitHub Actions, bubblewrap, Python 3, pinned native product inputs.

**Scope:** запрос пользователя от 2026-10-12 на PR и проверки; окончательное уточнение «Пока что добавь в CI только unit тесты инфраструктуры evals».

## Ограничения

- Тесты и `bun typecheck` выполняются из каталога соответствующего пакета.
- Harness не вызывает живую модель или судью в offline тестах.
- В CI только `bun run test:unit` и typecheck harness. Docker/bubblewrap suites `isolated-storage`, `node-eval-ops`, `node-skill`, `sandbox` остаются в полном локальном `bun test`; живые eval и калибровка модели не запускаются.
- Candidate не создаёт/публикует релиз; merge не входит в запрос.
- Исторические live evidence не переносится на новый commit.
- Незакоммиченные документы и local.env основного checkout не включаются в PR.
