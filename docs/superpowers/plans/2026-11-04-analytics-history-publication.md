# Подготовка истории analytics-expansion к публикации

**Цель:** убрать сведения о локальной машине и рабочем окружении из всех шести собственных коммитов ветки, сохранив 33 пары / 66 evals и содержательный provenance.
**Подход:** проверенный закрытый Git bundle и отдельный clone; преобразование деревьев каждого собственного коммита стандартными Git plumbing-командами; затем адресное обновление одной ветки. Авторы, даты и сообщения коммитов сохраняются, кроме возможных приватных значений в сообщениях. Общая база и другие refs не переписываются.
**Инструменты:** Git, Python stdlib, существующие Bun-проверки и Gitleaks. Новых зависимостей и постоянного механизма очистки нет.

## Границы

- Незакоммиченные файлы всех рабочих деревьев остаются прежними; перед применением перепроверяются исходный tip, индекс и рабочие файлы целевой ветки.
- Частные пути доказательств превращаются в честные указания на непубликуемый архив, а не несуществующие публичные ссылки. Существующие файлы репозитория получают относительные ссылки.
- Фактические локальные endpoints, аккаунты, контейнеры, профили и session IDs удаляются или заменяются нейтральными описаниями. Искусственные примеры в коде/тестах сохраняются, поскольку не относятся к рабочей машине.
- Публичные URL, версии, метрики, семантика данных, имена колонок, идентификаторы предметных данных, GUID узлов и безопасные content hashes сохраняются.
- LGP проверяются из Git во всех версиях; изменение необходимо только при подтверждённых частных данных. При изменении файла обновляются все связанные content pins в том же дереве.
- Push, force-push, merge, выпуск и очистка старых Git objects исключены. Резервный bundle остаётся только локально.
- Оценка: до 220 текстовых файлов и 2300 изменённых строк после полной инвентаризации SPEC и зависимых pins, включая этот документ; runtime-код и данные evals не меняются. Размер контролируется через git diff --stat.

## Шаги и проверяемые результаты

1. [x] Проверить refs/рабочие деревья, сохранить и проверить bundle и fingerprints незакоммиченных файлов. Результат: восстановимая исходная история и изолированный clone.
2. [x] Независимо проверить план и классы замен. Результат: нет нерешённых обязательных замечаний.
3. [x] В отдельной копии обработать все собственные деревья, включая промежуточные/удалённые файлы, и сохранить mapping старых/новых коммитов. Результат: шесть коммитов с прежней общей базой и метаданными, без выявленных частных значений.
4. [x] Проверить все новые версии текстов и архивов, Gitleaks range, загрузку 66 задач, D/B parity, oracle/corpus/source pins и независимый пересчёт калибровки. Сравнить код, данные, oracle, LGP с оригиналом; они должны остаться прежними, если отдельная находка не потребовала изменения. Результат: проверенная кандидатная история и независимое итоговое ревью.
5. [x] При неизменном исходном состоянии обновить только analytics-expansion и синхронизировать её чистый tracked checkout. Повторить проверку refs, статуса и fingerprints незакоммиченных файлов. Результат: ветка подготовлена локально, оригинал восстановим из bundle, публикация не выполнена.

## Риски и проверки

Ошибочная замена GUID может повредить калибровку; GUID узлов не обезличиваются. Изменение документа в provenance/corpus может сделать pin устаревшим; pins пересчитываются адресно. Частная ссылка может оказаться публичной ссылкой на источник; сохраняется проверенный URL публичного источника. Скрытые данные архива требуют проверки распакованного содержимого, а не только Git diff. Новая работа другой задачи блокирует применение к целевой ветке до сохранения её состояния.

## Завершение

Шесть собственных коммитов очищены с сохранением авторства и общей базы. Код, входные данные, oracle и LGP побайтно сохранены; обновлены только текстовые сведения и зависимые pins. Обе коллекции содержат по33задачи/137калибровочных вариантов; независимый пересчёт, загрузка66задач, D/B parity, проверки всех промежуточных pins, Git и Gitleaks прошли. Независимое ревью: обязательных замечаний нет. Исходная история сохранена в закрытом локальном bundle. Общая история до разветвления и другие ветки не переписывались; push/merge/публикация не выполнялись.
