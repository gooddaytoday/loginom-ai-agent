> **For agentic workers:** Use superpowers:executing-plans or superpowers:subagent-driven-development. Track the steps with checkboxes.

**Goal:** Опубликовать `port-read-design`, открыть PR в `loginom` и получить успешные применимые сборки и тесты CI на окончательном SHA.

**Architecture:** Обычный Git push новой remote-ветки, существующий GitHub PR и штатные workflows. Каждый отказ проверяется по фактическому логу; исправляется причина в продукте или тестовой фикстуре, затем точечная локальная проверка и новый push.

**Tech Stack:** Git, GitHub Actions, закреплённые инструменты проекта.

**Spec:** Прямое поручение владельца: push, PR в `loginom`, успешный CI с необходимыми исправлениями.

## Constraints and review focus

- Не выполнять merge, auto-merge, выпуск или установку продукта. Сохранять чужие checkout и изменения.
- Не ослаблять проверки, не отключать тесты и не менять workflows ради зелёного результата. Известные локальные отказы описаны в [результатах rebase](2026-10-25-port-read-rebase.md); CI проверяется самостоятельно.
- Перед каждым изменением перечитать свежие конфликты, открытые замечания и CI. После исправления проверить точный отказ и ближайший затронутый набор package-local.
- Для недоступного внешнего ресурса установить конкретную причину, использовать существующий штатный способ подготовки; не подменять результат PASS.
- Начальная оценка: один документ, около 50 строк. Размер необходимых исправлений определяется конкретными логами; новый механизм получает отдельное обоснование и независимое ревью перед реализацией.
