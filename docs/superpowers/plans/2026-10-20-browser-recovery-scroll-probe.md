# Browser recovery: native scroll probe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Одной новой подготовительной native-пробой после scoped re-review исправленного preparation установить, обновляется ли rendered row window после подтверждённого scroll без следующего жеста, либо записать точный blocker/NOT_REPRODUCED; отдельно подтвердить собственную очистку.

**Architecture:** Один временный driver вне Git использует отдельную диагностическую Page по существующему `packages/desktop/test/loginom/cold-readback.mjs`, только hash-verified native helpers свежего штатного stage. Это отдельно разрешённая internal preparation, не BR-сценарий и не публичный `dock_ui_action` (его нет в `user-v1`).

**Tech Stack:** Существующие Bun staging, bundled Node/Playwright/Chromium, `makeWorkspacePrepareCode`, `makeCapabilityCode`, `makeWorkspaceUiCode`, `makePackageCleanupCode`.

**Spec:** Назначение владельца для одного causal probe; фактическая граница — [source report](../../testing/loginom-ai-agent/reports/2026-10-20-browser-recovery-source/report.md), раздел read-only NativeC diagnosis; подробности в ignored `.superpowers/sdd/2026-10-20-browser-recovery-storage-reason/anchor-diagnosis.md`.

**Текущее основание следующей попытки:** первая preparation завершила verified checkpoint Save, но ошибочная обязательная проверка nonempty `workflow_continuations` остановила driver до filegrid/scroll; очистка пакета не вызывалась. `packageContinuations` учитывает только receipts с `nodeTargetWorkflowNode`, которого empty `new_draft` не создаёт. Новая проверяемая гипотеза: удаление этой проверки внутреннего представления при сохранении фактических Save/identity/saved-state/UI guards позволит дойти до native scroll; исходный причинный вопрос об обновлении window без жеста не меняется. Один fresh attempt/new profile/new UUID разрешён только после независимого scoped preflight; первую запись/сессию не трогать, её native cleanup UNCONFIRMED и OS ownership NOT_CONFIRMED сохранить.

## Global Constraints

- Ветка `recovery-build-flag`; исходный HEAD передать через `git rev-parse HEAD` в приватное evidence, не копировать pins/SHA в другие документы.
- Один собственный новый empty draft, один UUID `.lgp` в выбранном `workflow_profile.storage_directories.packages`; old session/business artifact не открывать. Серверный диагностический пакет после close сохраняется; удаления файлов нет.
- Production, catalog, staged helpers не менять; новых API/hooks, retry/wait в продукте, actuator/wheel, fixtures/dependencies/infrastructure нет. Изучаем именно существующий scrollTop actuator.
- Ни экспорт, ни fault/recovery (включая скрытый connection recovery в подготовке), ни S5 rerun здесь не выполняются. `withStorageIdentity` и `guardLoginomConnection` нигде в driver не вызывать: последний способен нажать «Восстановить». S5 остаётся FAIL/deferred; критерии file/bytes/SHA/lineage/Save/native cleanup неизменны. Probe не может дать S5 PASS.
- Частные profile/evidence только вне Git, dirs0700/files0600, `umask 077`; конфигурация `/home/george/.config/loginom-ai-agent-tests/browser-recovery.json` читается без печати значений/секретов. Сохранять все исторические FAIL/UNKNOWN.
- Ошибка/неопределённый gesture, потеря binding, неопределённое сохранение → STOP без повторного действия. Native cleanup и OS cleanup — отдельные результаты; direct probe не имеет managed ACK.

## Review Focus

- Новый folder/root/owner/document при follow-up: сначала отказ binding, затем оценка readiness.
- Нет nonempty all-outside state: NOT_REPRODUCED, без поиска «подходящего» каталога или дополнительных scroll.
- Неподтверждённый Save: не начинать filegrid probe, не заменять файл и не discard. Подтверждённый Save не теряется из-за последующего assertion/journal error; native cleanup проверяется штатным helper независимо от auxiliary bookkeeping.
- Native close отказал: сохранить BLOCKED отдельно от context/process termination; историческую очистку не переоценивать.
- Дополнительные read потребовали больше 250/1000ms: записать реальные времена; не считать их точными native event timings и не вводить новый deadline/retry.
