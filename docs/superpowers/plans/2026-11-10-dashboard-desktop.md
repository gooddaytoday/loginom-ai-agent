# Пульт Loginom в чате Desktop — план реализации

> Исполнитель ведёт разработку, сборку и приёмку в этом чате по шагам. Стенд и Desktop можно готовить параллельно после независимого ревью.

**Цель** — создать и изменить приложение по обычной просьбе в Loginom AI Agent Desktop. Проверить заказанную правку живого пульта через браузер и сохранение адресата при переключении на другой узел. [Утверждённый дизайн](../specs/2026-11-10-dashboard-desktop-design.md)

**Устройство** — bootstrap локального стенда выдаёт системную ссылку `loginom-ai-agent://dashboard?id=<uuid>&action=create|edit`. Electron доставляет её один раз нужному окну. Desktop читает снимок по ID с фиксированного loopback-адреса и прикладывает цель к одной отправке. Используются существующие Electron, Solid, API сообщений и публикация Node.js.

**Границы** — брендированный Linux Desktop 0.3.9 из ветки `loginom` в отдельном рабочем каталоге, стенд в `dashboard-app`. Один пользователь. Собственные пакеты и профиль для проверки. Оценка двух diff вместе с тестами и документами — 14–22 файла, примерно 330–580 изменённых строк. Публичный релиз, изменения API платформы, удалённые стенды и новые зависимости в этап не входят.

**Особые случаи при ревью** — холодный запуск с URI, быстрое переключение A/B, медленный ответ после смены черновика, истёкший ID, ошибка отправки или постановка сообщения в очередь. Проверить, что запрос не может задавать адрес сервиса или исполняемую команду и что уже набранный текст и файлы сохраняются.

- [ ] **1. Проверить короткий путь до рабочего приложения.** Найти совместимые готовые ресурсы сборки и штатный способ подключить модель в отдельном профиле. Подготовить на том же стенде собственные копии A и B. Получить прямую проверку запущенного Desktop и открытого сценария. В пользовательский профиль и исходный пакет ничего не записывать.
- [ ] **2. Передать ссылку.** В `dashboard/bootstrap.js` после POST снимка связать «Создать dashboard» и «Изменить в чате» с его ID. Сохранить отладочный вход через Codex, а в `AGENTS.md` уточнить приоритет явного ID. В продуктовом `packages/desktop/src/main/index.ts` принять initial argv Linux и исключить повторную доставку в то же либо другое окно. В `packages/app/src/pages/layout/deep-links.ts` проверить схему, UUID и допустимое действие. Проверка — нормальная ссылка разбирается, подмена адреса/действия отклоняется, открытие пульта для просмотра не переключает приложение.
- [ ] **3. Прикрепить к одной отправке.** В продуктовом `packages/app/src/pages/layout.tsx` направить проверенную цель в текущий чат или новый черновик проекта пультов. Загружать только с `http://127.0.0.1:32768/dashboard/targets/<id>` с доверенной стороны Desktop. При исчезновении снимка сохранить ввод и предложить открыть пульт заново. Показать съёмную метку средствами имеющегося редактора черновика. В `context/prompt-state.ts`, `components/prompt-input/{context-items.tsx,submit.ts,build-request-parts.ts}` и смежных фактических путях протянуть ID до обычной и отложенной отправки, сохранить его при ошибке. Проверить точечными тестами сборки сообщения и черновика, затем `bun typecheck` из затронутых пакетов.
- [ ] **4. Пройти основной путь.** Собрать Desktop в отдельном каталоге, обновить bootstrap двух клиентов без перезапуска сервиса снимков. Нажать ссылку в браузере из A, проверить метку и фокус, отправить короткую правку агенту `build`, открыть B. Прочитать принятое сообщение через API локального Desktop, сверить ID в его служебной части с ID браузерного клика A. Убедиться по интерфейсу и опубликованным результатам, что изменился только A. При ошибке исправлять первый неработающий переход и повторять его.
- [ ] **5. Создать приложение.** Закрыть свой Desktop, нажать «Создать dashboard» у нового узла, проверить новый черновик и отправить просьбу. Открыть созданное приложение в Loginom. На главном экране открытого Desktop повторить передачу. Проверить доступную владельцу сборку, записать способ направить в неё системную ссылку и способ возврата. Сохранить скриншоты и доказательства вне Git, завершить свою сессию, провести независимое ревью результата.

## Точка продолжения

- Дизайн утверждён. Рабочий стенд запущен. Системная ссылка хоста пока ведёт в установленный Desktop 0.3.2. Доставка новой цели через пользовательский интерфейс ещё не проверена.
