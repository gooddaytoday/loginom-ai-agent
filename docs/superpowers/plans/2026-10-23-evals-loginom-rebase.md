# Rebase evals-parallel на loginom

**Цель:** перенести текущие изменения `evals-parallel` на актуальную `loginom`,
сохранив их поведение, изменения базы и чужие незакоммиченные документы.
**Подход:** обычный Git rebase с резервной локальной ссылкой; без новых механизмов.
**Инструменты:** Git, закреплённый проектом Bun, Node и существующие проверки.
**Основание:** запрос владельца в текущем чате; инструкции корня и `evals/AGENTS.md`.

## Границы и критерии завершения

- Перед началом обновить обе remote refs; локальная `loginom` должна совпадать
  с `origin/loginom`, а remote `evals-parallel` не содержать неизвестных изменений.
- Сохранить исходную вершину в `evals-before-rebase` и содержимое трёх чужих
  untracked документов; rebase выполнять в текущей рабочей копии.
- `loginom` является предком итоговой ветки; незавершённого rebase/конфликтов нет.
- `range-diff` объясняет каждое изменение/исключение исходного патча.
- Проверены evals unit/typecheck, затронутые CLI/runtime тесты, agent typecheck
  и нативная standalone-сборка. Ошибки сначала отделяются от состояния до rebase.
  Полный unit baseline используется повторно только для побайтово неизменных
  evals source/dependencies/tests; исправленные тесты выполняются повторно.
- Новые контракты, live evals, очистка стендов, merge, push и выпуск не входят
  в задачу. Никакие старые incidents/reservations не меняются.

## Риски и размер

Пересечение файлов веток ограничено `packages/loginom-runtime/src/connection-check.mjs`
и его тестом. В базе уже есть перевод фокуса через Tab и санитаризация ошибок;
ветка добавляет фокус пароля через click. Сохранить обе гарантии без лишнего жеста;
если исправление уже обеспечено базой, его повторный патч не требуется.
Остальные патчи проверяются через `range-diff` и source-тесты.

Оценка новой работы относительно механически перенесённых патчей: один документ
до 80 строк и до двух файлов разрешения конфликтов до 30 строк. Большой исходный
diff ветки переносится без рефакторинга. Резервная ссылка нужна для восстановления
истории; отдельные служебные подсистемы и новые зависимости не нужны.

Baseline выявил два дефекта самих fixtures: фиксированный каталог другого хоста
и противоречивый набор cgroup controllers/counters. Исправить только подготовку
этих двух тестовых файлов, сохранив исходные утверждения и production-код.
Дополнительный размер: два файла, до 10 изменённых строк. Независимое чтение
подтвердило причины обоих отказов. Повтор неизменных долгих shutdown-тестов
не нужен; после rebase дополнительно проверить тождество evals source и lock.

- [x] Независимое ревью этого плана до изменения истории; обязательные замечания
  устранены. Результат: согласованный проверяемый порядок без лишних механизмов.
  Ревью: No findings. При конфликте сохранить документальную часть коммита
  исправления фокуса, оставив два runtime-файла из актуальной базы.
- [x] Снять baseline evals unit/typecheck и runtime login, сохранив логи вне Git.
  Результат: подтверждённый baseline или воспроизводимая исходная ошибка.
- [x] Создать резервную ссылку, выполнить rebase, проверить каждый конфликт по
  обеим историям и тестам. Результат: завершённый rebase и объяснимый range-diff.
- [x] Выполнить перечисленные source-проверки и standalone build; при сбое
  сравнить с исходной веткой/базой и исправлять только вызванную rebase регрессию.
  Результат: проверенная сборка и тесты либо точный внешний blocker.
- [x] Независимо проверить изменённые/пропущенные патчи, сохранность чужих файлов
  и Git-состояние; заполнить checkpoint и сохранить документ отдельным коммитом.
  Результат: ветка готова к дальнейшей работе, ограничения сообщены владельцу.
