# Открытие dashboard по адресу с именем пользователя

Результат — dashboard открывается при входе через user@127.0.0.1:32768. Принадлежащая нам вкладка освобождает демонстрационный пакет, чтобы владелец открыл его с правом записи.

Причина по коду — относительный fetch наследует имя пользователя из базового URL страницы. Исправление строит адрес запроса из location.origin. Привязка узла уже использует origin. Новых зависимостей и механизмов не требуется. Ожидаемый diff — bootstrap и этот план, 2 файла / 20–35 строк. Desktop, серверные сессии владельца и сам пакет за границами изменения.

## Результат

- Ошибка воспроизведена по адресу с user@ до правки. После свежей загрузки того же клиента dashboard открылся, показал пять каналов и 500 кампаний. Обычный адрес также проверен.
- Однострочная правка развёрнута в обоих клиентах без перезапуска сервиса снимков. Проверка синтаксиса и два теста сервера проходят.
- Подтверждённая наша отключённая сессия закрыта через Диспетчер. Повторное открытие пакета прошло с правом записи. Свои проверочные и административные сессии закрыты, вкладки завершены.
- Доказательства RED/GREEN и снятия блокировки находятся рядом со сборкой, в файлах credential-url-red.json, credential-url-green.json, plain-url-green.json и package-writable.json. Владелец обновляет клиент и заново открывает пакет для получения права записи.
