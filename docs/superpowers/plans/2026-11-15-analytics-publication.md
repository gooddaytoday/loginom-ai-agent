## Найденная несовместимость corpus checker

Полная проверка всех 86 парных задач нашла два прежних `direct-expense-lost`
в `budget-unbilled-commitments`: закреплённая мутация намеренно переподключает
SourcePort существующей связи. Новый blanket-запрет изменения `WorkFlow/Links`
отклоняет эти принятые предметные ошибки. Старый поиск первого descendant `Links`
вместо этого ошибочно сравнивал join-ключи и отвергал шесть новых мутаций.

Исправление ограничить сохранением GUID/inventory узлов и настоящих workflow-связей;
изменения endpoints допустимы через существующие точные `edits` с проверкой count
и исходных SHA. Отдельного неописанного изменения здесь нет: checker сам строит
пакет только из manifest. Нормативное слово «топология» уточнить этой фактической
границей, сохранив принятый корпус, pins, модельные результаты и формат manifest.
Новый парсер фрагментов ссылок и исключения по ID не нужны.

До исправления повторно независимо проверить это решение. RED воспроизводит
прежнюю объявленную замену SourcePort; GREEN сохраняет join-key mutations,
но отвергает изменение inventory GUID узлов/связей. Затем повторить затронутые
тесты и обе полные corpus-проверки. Оценка: checker, его тест и одна строка
спецификации, до 60 строк; итоговый независимый review по delta.

Полный unit suite также выявил прежнее ограничение в
`evals/test/campaign-admission.test.ts`: порядок двух параллельных admission
callbacks не гарантирован, тогда как results и unassigned сортируются scheduler.
Исправить одну проверку на точное множество `[0, 1]`, как соседнюю проверку
completed. Производственный scheduler не менять; после исходного RED полного
набора повторить только затронутый файл, сохранив результаты остальных тестов.

## Исключения и ограничения

Push, PR, merge в целевую ветку, выпуск, новые измерения и ремонт посторонних
кампаний исключены. Продуктовые пакеты не меняются, отдельная сборка поставки
не требуется. CI GitHub проверяется после публикации владельцем.
Снимки разрешённой памяти не доказывают runtime MCP Peer isolation.
