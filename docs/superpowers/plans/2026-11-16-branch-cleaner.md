# Branch Cleaner — план и состояние реализации

## Принятое решение

Ручные команды `$branch-cleaner` в Codex и `/branch-cleaner` в Claude Code запускают
отдельного подагента без истории основного разговора. Общий комплект лежит в
`.agents/branch-cleaner/`, вне автоматически обнаруживаемых каталогов навыков.
Два коротких входа находятся в `.agents/skills/branch-cleaner/` и
`.claude/skills/branch-cleaner/`. Проектная копия предназначена коллегам;
глобальная устанавливается копированием того же комплекта, без синхронизатора.

Агент изучает все коммиты заданного диапазона, очищает файлы и все новые
промежуточные коммиты, сохраняет действующий rationale, ограничения, регрессионные
тесты, авторский вклад и исторические свидетельства реально проверенных сборок.
Результат — логические линейные коммиты от прежней базы и замена исходной локальной
ветки после проверок. Push требует отдельного поручения. Эта установка не запускает
очистку текущей ветки проекта.

Внутренние навыки загружаются по необходимости: адаптированные `design-cleanup`,
`harmonize-docs` с используемыми ресурсами и новый `branch-history-rewrite`.
Убрать прежние публичные записи и ссылки первых двух навыков. Не добавлять новые
зависимости приложения, установщик, собственный Git-инструмент или дополнительные
сторонние навыки.

## Обязательные границы Git

Фиксировать repository/base/tip и исходный диапазон; базу не обновлять.
Работать в отдельном worktree. До реконструкции проверить очищенное дерево;
после неё сравнить tree SHA и проверить каждый новый коммит по перечню удалений.
Сохранить полезные изменения merge resolutions, авторство и исторические SHA.
Создать резервную ссылку и проверить bundle вне репозитория до замены ветки.

Для неоткрытой ветки заменить ref с проверкой ожидаемого старого SHA. Для открытой
найти owning worktree, проверить clean и исходный HEAD, безопасно detach на старом
SHA, выполнить compare-and-swap ref и обычный switch обратно. При изменениях или
конфликте сохранить подготовленный результат; не использовать force, reset --hard
или автоматический stash. Другие ветки, теги и remote не менять.

## Ревью плана

Независимое ревью выполнено до реализации. Учтены: синхронизация ref/index/worktree,
проверка всей новой истории, адаптация конфликтующих инструкций исходных навыков,
перенос guide вместе с harmonize-docs, проверки локального и глобального входов.

## Проверки и ограничения

Локальный комплект реализован и установлен. Исходные посторонние неотслеживаемые
файлы не входят в изменения этой задачи. Приватные runtime IDs, адреса, локальные
пути и сырые логи остаются вне Git.

- Форматы трёх внутренних навыков и Codex-команды прошли `quick_validate.py`;
  относительные ссылки и `git diff --check` проверены.
- Общий комплект и две команды установлены глобально. Настоящий Codex app-server
  обнаруживает проектную команду из корня и подкаталога, глобальную — из другого
  repo; внутренних навыков в каталоге нет.
- Native Codex CLI 0.167.0 выполнил `$branch-cleaner` на искусственном repo через
  отдельного подагента. Шесть коммитов пересобраны в три; удалены неиспользуемый
  кеш и временный документ, полезное содержание которого сохранено в документе
  решения. Динамически вызываемый публичный API, регрессионные тесты, смысловое
  разрешение merge и вклад двух искусственных авторов сохранены.
- В native прогоне прошли 6 тестов исходного/очищенного дерева и проверки
  логических промежуточных коммитов (3/4/6 тестов). Независимый внешний oracle
  подтвердил 6 CLI-сценариев и отказ неизвестному обработчику. Проверены отсутствие
  удалённых файлов во всех новых коммитах, точное равенство итогового tree SHA
  проверенному очищенному дереву, неизменность базы и remote-tracking refs.
- Замена открытой тестовой ветки завершилась с чистыми HEAD/index/worktree.
  Self-contained backup bundle проверен восстановлением исходной истории в
  отдельном bare repo. Push не выполнялся.
- Отдельные dirty/stale примеры подтвердили остановку до detach/CAS, сохранность
  staged/unstaged/untracked изменений и нового чужого коммита; prepared refs и
  проверенные backup сохранены. Это изолированное выполнение Git-инструкции,
  а не дополнительный native запуск Claude/Codex.
- Native audit-only запуск из подкаталога linked worktree выбрал проектную роль,
  обнаружил пустой диапазон и оставил refs, index и рабочее дерево без изменений.
- Формат Claude-команды проверен YAML-парсером по платформенным полям; общий
  Codex skill-validator эти расширения Claude не поддерживает. Глобальные копии
  обоих входов и всего внутреннего комплекта побайтно совпадают с проектными.
- Независимое ревью реализации: ACCEPT. Проверка фактического исполнения
  проводится отдельно и не заменяется ревью текста.
- Claude Code сейчас не запускается: существующая VPN-обёртка ссылается на
  отсутствующего системного пользователя. Настройки защиты не менялись;
  живой вызов Claude пока не проверен.
- Повторная read-only проверка Multica: выбранный runtime online, но персональный
  доступ текущему пользователю не предоставлен. Удалённый агент и задачи не

- Во время native проверки обновление каталога OpenViking завершилось сетевой

## Исправления ревью PR #1166

- Оба переключения исходного worktree требуют `--no-overwrite-ignore`. В отдельном
  Git-примере старая процедура затёрла ignored файл (RED); исправленная остановила
  переключение и сохранила файл, prepared ref и backup (GREEN). Сценарий без
  конфликта завершился с чистым HEAD/index/worktree. При отказе после CAS явно
  сообщается, что ref обновлён, а worktree остался detached.
- Глобальный Claude fallback заменён на `$HOME/.agents/branch-cleaner/AGENT.md`.
  Проверка с symlink каталога конфигурации сначала не находила установленную роль
  (RED), затем нашла её по исправленному пути (GREEN); проектная роль по-прежнему
  имеет приоритет. Это проверка разрешения путей, а не живой вызов Claude.
- Изменённые глобальные копии и локальная заготовка Multica обновлены. Форматы,
  ссылки, diff и staged secrets проверены; независимое ревью исправлений — ACCEPT.

## Исключительный доступ к ветке

Замечание review о гонке проверки worktree и CAS подтверждено на Git 2.34.1:
другой worktree занял ветку после проверки, а `update-ref` изменил её ref,
оставив индекс и файлы на старой версии. Для замены требуется основание для
исключительного доступа к целевой ветке и её worktree на всю операцию. При его
отсутствии агент сохраняет подготовленный результат и backup без замены ветки.
Частный lock-файл и `git worktree lock` не блокируют обычные команды другого Git.
Независимое ревью исправления — ACCEPT; существующие проверки и защита
игнорируемых файлов сохранены. Изменение задаёт порядок работы агента;
повторный живой запуск агента на этом сценарии не выполнялся.
