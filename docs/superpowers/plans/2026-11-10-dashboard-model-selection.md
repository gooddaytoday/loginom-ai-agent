# Desktop: модель в новом чате dashboard

Цель: восстановить доступность настроенной `openai/gpt-6.1-sol` при создании dashboard; сохранить отдельные чаты и пользовательский профиль.

Ограничения: пользовательский Desktop/backend не перезапускать, не менять модель ради обхода ошибки, не отправлять пользовательский черновик, не раскрывать секреты. Временные файлы только в `$HOME/storage/tmp/`.

- [ ] Независимо проверить план до исправления.
- [ ] Установить первую ошибку по настройкам, журналам и фактическому ответу provider API в отдельном профиле с той же конфигурацией. Сначала различить недоступный каталог/авторизацию и ошибку renderer.
- [ ] Получить минимальное воспроизведение; для исправления кода — RED→GREEN с проверкой выбранной модели и отсутствия её потери в новом чате.
- [ ] Применить минимальное исправление; проверить фактический Desktop с настоящим каталогом, без отправки запроса модели.
- [ ] Проверить доставку отдельного dashboard-чата, сохранность его черновика, необходимые package-local проверки. Если нужен новый артефакт — собрать и проверить его отдельно, не перезапуская пользовательское приложение.
- [ ] Записать установленную причину, результат, способ применения и ограничения.

Начальные факты: текущий Desktop —0.3.9 с исправлением отдельных чатов; профиль содержит OAuth OpenAI и default `openai/gpt-6.1-sol`. В журнале есть тайм-ауты Agent.state при первой загрузке. Каталог моделей в этом профиле ещё не проверен. Гипотезы не считаются установленной причиной.
