# Dashboard M1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** обновить dev-стенд поверх M0 один раз: прежний ROI-dashboard открывается без перепубликации в обеих Studio, пересчитывается и передаёт выбранный узел в Desktop.

**Architecture:** сначала закрепить поведение M0 на JavaScript, затем по очереди перенести HTTP-службу и браузерную оболочку в `@loginom-ai-agent/dashboard`. Bun собирает автономный модуль для Node и один браузерный IIFE; шаблон и скрипт публикации переезжают, данные и редактируемые приложения остаются на месте.

**Tech Stack:** TypeScript, Effect Schema из каталога workspace, `node:http`, `node:test`, Bun 1.3.14, Node 24.19.0, Chromium 154 из Loginom runtime, Turbo, Bash, Apache.

**Spec:** [утверждённый дизайн M1](../specs/2026-11-11-dashboard-m1-design.md); [таблица поведения M1 в roadmap](../specs/2026-11-11-dashboard-architecture-roadmap.md#порядок-миграции-этап-m1); [проверенная база M0](2026-11-11-dashboard-m0.md). Где более ранние цифры roadmap расходятся с дизайном, брать принятые в M1: 19 проверок M0 с вложенными; порог в M1 доказывается на web.

**Статус:** план прошёл независимое ревью; обязательные замечания устранены. Реализация и приёмка ещё не начинались.

## Global Constraints

- До M2 — только собственные доверенные dashboard. Сохраняются пути HTTP, доступ к снимкам, контракт опубликованного iframe, файлы публикаций и пользовательские изменения. Файлы пакетов Loginom (`.lgp`) не изменять.
- До M3 остаются обе формы снимка и `dashboard/apps/<ключ>`: по этому пути Desktop находит проект. Новый контракт, изоляция, SDK, черновик, release-установщик, службы publisher/builder и их тесты покрытия вне M1. Живая проверка совместимости 7.4.2 входит в M1.
- Команды тестирования выполнять из указанного каталога пакета, не из корня. В командах ниже `$LOGINOM_AI_AGENT_TEST_NODE` — абсолютный путь к закреплённому Node; `PLAYWRIGHT_BROWSERS_PATH` указывает на Chromium из [пинов продукта](../../../packages/product/loginom-release.json). Записать фактические версии, не подменять их системными.
- Оценка будущего изменения: 28–40 файлов, 900–1 700 добавленных и удалённых строк суммарно, включая тесты, документацию, CI и переносы (сверка через `git diff --stat --find-renames` от начала реализации). Не добавлять вторую установку в CI или досрочные компоненты следующих этапов.

### 3. Собрать одну оболочку и измерить её размер

**Файлы:** `P/src/shell/index.ts`, `P/src/shell/loginom/adapter.ts`, `P/src/shell/loginom/parameters.ts`, `P/src/shell/loginom/types.ts`, `P/tsconfig.shell.json`; дополнить сборку, пакет и тесты браузера. Входы M0 — `dashboard/bootstrap.js`, `dashboard/parameter.js`.

**Интерфейс:** опубликованные iframe по-прежнему используют `window.frameElement.dashboard.state()`, `change(value, name?)` и `run()`; на стороне Studio адаптер владеет обращениями к `bg`, `Ext`, `mxEvent`, `Out` и `ReleaseObject`. Браузерная часть не импортирует Node/web.

Если обязательный API Studio отсутствует, оболочка не должна оставлять частично работающую кнопку или прерывать инициализацию Studio. Зафиксировать это браузерным сценарием с отсутствующим методом: штатное действие Studio по-прежнему работает, dashboard недоступен. Оболочка проверяет потребляемые поля ответа службы; фикстуры дают реальные формы ответов, тесты сохраняют ожидания к поведению UI.

Убедиться в очередности расчётов, форме `loginom-ai-agent://dashboard`, открытии отдельного окна и сохранении защиты Studio от потери правок.
