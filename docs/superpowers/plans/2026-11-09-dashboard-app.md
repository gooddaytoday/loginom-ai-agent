# Dashboard в Loginom: план реализации

> Исполнение по шагам в текущем чате; независимые части можно поручать субагентам.

**Цель:** создать и исправить приложение по двум запросам через чат, увидеть на master результат нового расчёта, закрыть пакет и выйти.
**Архитектура:** выбранный узел владеет расчётом; bootstrap публикует контекст в NodeJS. Агент читает один снимок, работает в известном каталоге и копирует сборку в собственный контейнер.
**Стек:** Loginom master, JS, NodeJS stdlib; React, TypeScript, Vite, Recharts. **Спецификация:** [утверждённый дизайн](../specs/2026-11-09-loginom-dashboard-design.md).

## Границы и фокус ревью

Все ограничения, лестницы, тайм-боксы и разрешения раздела «Автономное выполнение» действуют. Старт 09.11 23:44 МСК; функциональная отсечка 06:14, предел 07:44. Оценка независимого ревью 4,5–9,5 агент-часа, медиана около 6,5; главное неизвестное — параметр. За пределами: Desktop и deep link, расширение API SDK, BI-конструктор, production/multiuser, installer, push/PR.
- Первый выход нетабличный или отсутствует: показать «Dashboard для этого узла недоступен» до любого Execute, особенно у экспорта.
- Повторное открытие во время очереди: показать ожидание, затем readback; старый iframe не обновляет новый.
- Ошибка после записи: текущий параметр и последний успешный результат различимы; после открытия без результата — «Выполнить».
- После выбора B с тем же GUID исходники/привязка из уже прочитанного снимка A не меняются. Позже B имеет свой текущий снимок.
- Сбой typecheck/build не заменяет рабочую версию; HTML без кеша, пути ограничены каталогом приложения.

Оценка diff разработки: 13–21 файл, 650–1 300 строк кода/тестов/описаний, отдельно lockfile автоматически до 2 500 строк и бинарная копия пакета. Реестр, БД, очереди NodeJS, upload API, новый агент или skill не нужны. История сборок не нужна: сохраняется последний рабочий dist.
