# Восстановление автообновления Dashboard

Цель — исправить шесть замечаний к автообновлению открытого окна Studio. Первый сквозной результат — Chromium продолжает показывать рабочую версию после HTTP 503 при загрузке следующей и самостоятельно открывает новую при восстановлении.

1. Проверить этот переход, Esc и сохранение фокуса в шапке. Использовать действующие опрос и сигнал готовности SDK. На время загрузки нужны два iframe, чтобы сохранить работающий экземпляр. Метку версии переключать вместе с приложением. После закрытия окна освободить оба канала.
2. При первой готовой публикации провести активацию через очередь Studio. Проверить результат ранее деактивированного узла. Первую ошибку сборки показывать рядом со ссылкой, сохранять выделение сообщения при очередном опросе.
3. Сверить ответ инструмента с общей инструкцией Desktop и CLI. Прогнать тесты пакета, проверки типов и лимита 17 000 байт для shell.js.
4. На dev master пройти две нативные публикации с параметром и временным отказом загрузки новой версии. Проверить возврат к готовой версии, параметр, строки и закрытие окна. Закоммитить проверенные правки в dashboard-auto-refresh.

Основные риски — запоздалый ответ от закрытого iframe и потеря состояния во время пересчёта. Оценка изменений — 5–8 файлов, 160–300 изменённых строк. Серверный протокол, установщик и формат пакета остаются прежними.
