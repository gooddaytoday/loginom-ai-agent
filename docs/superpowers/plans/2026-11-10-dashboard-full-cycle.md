Результат: в новой копии пакета пройти обычные действия пользователя — Создать dashboard → Desktop и отправка просьбы → открыть опубликованный пульт → Изменить в чате и отправка правки → открыть обновление → Esc при фокусе внутри. Первый end-to-end результат — реальное сообщение создания из Desktop приводит к работающему пульту на данных стенда.
1. Проверить существующий Desktop/браузер/сервис, подготовить отдельную копию campaign.lgp без опубликованного dashboard. Проверяем: кнопка «Создать dashboard».
2. Нажать её, через системный переход получить в обычном Desktop цель новой копии и отправить короткую просьбу создать сводку бюджета и выручки по каналам. Проверяем: опубликованный новый пульт показывает 500 кампаний.
3. Нажать «Изменить в чате», отправить просьбу о заметной правке заголовка и проверить ID сообщения и опубликованный результат. Проверяем: новый заголовок при повторном открытии.
4. Закрыть изнутри по Esc, снова открыть с теми же данными. Сохранить доказательства, штатно выйти из собственной сессии Loginom. Проверяем: нет overlay после Esc, пульт доступен при повторном открытии, выход завершён.
Риски: UI native Desktop может быть недоступен средствами CUA, устаревшая сборка/авторизация, незавершённые пользовательские чаты. Используем штатные механизмы и новый собственный чат, не удаляем данные владельца. Не подменяем отправку через UI вызовом API; API только для чтения принятых сообщений/диагностики.
Ожидаемые Git изменения без дефектов: один план 15–20 строк. Новый пульт и скриншоты — локальные тестовые результаты. Новых зависимостей/механизмов нет. Исправления дефектов только после воспроизведения и краткого обновления плана с ревью.

Контрольная точка: план независимо одобрен. Контейнеры текущего стенда работают; пользовательский desktop-файл указывает на готовую AppImage. Инвентаризация CUA показала только MCP Apps и встроенный браузер; нативное управление отключено. Живая проверка Desktop не начиналась, тестовая копия пакета и чат не создавались. Для продолжения нужен сеанс с доступом к нативному окну Desktop. После восстановления доступа начать с шага 1; прежние проверки не считать результатом этого прогона.
