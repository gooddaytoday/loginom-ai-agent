# Configured M3 on the local rootless stand

**Goal:** Обычная сборка с штатным Knowledge input подключается к Loginom; непривилегированный web читает опубликованные сборки в rootless Docker. Затем заканчивается исходная Task18, включая установленный Desktop, настоящую модель и всю матрицу.
**Scope/estimate:** 6–7 файлов, до 170 изменённых строк с этим планом, существующими тестами и итоговыми docs; production — `packages/dashboard/deploy/dev-master.sh` и `packages/dashboard/src/agent/publish.ts`, около 20–25 строк. Новых dependencies, сервисов, ACL, config options и framework нет.
**First real result:** normal native CLI с правильным build input проходит Check/Save через `loginom setup --stdin-json`, сохраняет active generation без failure, а штатный `loginom check` подтверждает help.ready/browser verified и clean exit на настоящем локальном Server; затем required web UID реально читает read-only builds mount. До этого полная финальная упаковка не начинается.

## Minimal choice and guarantees

В install предпочесть уже локальный **проверенный immutable ImageID** только на Linux/x64. Исходный registry pin остаётся default для отсутствующего локального ID и остальных platform: их поведение не менять. Это один cache branch для реально требуемого offline input, не общий image override. При отсутствии cached ID сохранить прежнее получение registry pin: inspect, затем обычный pull только если его нет. Оба run используют `--pull=never` после подготовки, чтобы запуск по ID не пытался искать registry fallback; новый daemon route не добавляется. Config ID криптографически связывает config и DiffIDs; связь с исходным registry pin уже проверена, native Docker load проверил layers. Существующий Node/образ preflight до остановки M1 сохраняется.

Оставить `state`700, сделать только `builds`755; после копирования полностью собранного публичного output сделать staging directory755 до atomic rename. Новые публикации остаются под закрытым state, sample/control/auth туда не переносятся. Container UID/GID остаётся прежним non-root, rootfs/mounts read-only, capabilities/NNP/CSP и подтверждение публикации прежние. Менять UID на0, chmod всего state/профиля, добавлять ACL/walkers и обход Knowledge не требуется.
