# Вмешательство пользователя в Loginom

Каждая цепочка начинается с сохранённого импорта, продолжается настройкой фильтра и заканчивается просьбой продолжить. Раннер возобновляет ту же сессию чата и проверяет граф, тип и строки выходного порта, сохранение и холодное открытие. Порог ручного фильтра проверяется по сохранённому состоянию мастера, а затем по результату выполнения.

| Кейс | Действие пользователя | Подтверждение вмешательства |
|---|---|---|
| x01 | Закрывает мастер фильтра во время настройки | Кнопка закрытия, затем мастер скрыт и схема видна |
| x02 | Перезагружает страницу Loginom во время настройки | Навигация основного фрейма |
| x03 | Передвигает фильтр между настройкой и просьбой продолжить | Дельта координат, тот же GUID и координаты после холодного открытия |
| x04 | Переключается на другую вкладку браузера с Loginom | Chromium подтвердил активацию другого идентификатора вкладки |
| x05 | Прерывает CLI во время настройки | Непосредственно запущенный процесс завершился от SIGKILL |
| x06 | Вручную связывает выход фильтра с сортировкой и меняет порог | Сохранённые дельты, та же связь и результат с новым порогом после холодного открытия |
| x07 | Оставляет стороннее информационное сообщение в интерфейсе | Видимое сообщение Ext JS в странице Loginom поверх мастера |

Сортировку для x06 размещает подготовительная ручная правка после первого хода. Она остаётся несвязанной до второй ручной правки. x04 использует вкладку Chromium, x07 открывает тестовое сообщение через компонент интерфейса Loginom.

## Запуск

Переменная `LAB_2047_RUNNER` указывает на worktree `bughunt-runner` с этими кейсами и изменениями LAB-2032 для ручных правок и проверки выходных портов. Рабочий процесс раннера получает PID демона через CLI Multica перед вмешательством. [PR #1353](https://github.com/gooddaytoday/loginom-ai-agent/pull/1353)

Файл `intervention.json` последнего кейса цепочки задаёт вид вмешательства и ход, на котором его выполняют. Обычный `run-check.py` отклоняет такие цепочки с указанием запустить `interruptions/run.py`.

Соберите нужный SHA штатным `run-check.py start --prepare-only`.
CDP без аутентификации слушает только loopback и включается только в отдельной тестовой копии сборки, созданной `instrument-build.py`.

```bash
fixture_dir=docs/testing/loginom-ai-agent/bughunt-2026-11/interruptions
case_dir="$PWD/${fixture_dir%/*}/cases"
python3 -B "$fixture_dir/generate.py" --check
python3 -B "$fixture_dir/instrument-build.py" "$ORIGINAL_BUILD" "$TRIAL_BUILD"

export RUN_CHECK_MODEL=deepseek/deepseek-flash
export RUN_CHECK_AUTH="$HOME/.config/loginom-run-check/auth-deepseek.json"
python3 -B "$fixture_dir/run.py" start --head "$SHA" --build "$TRIAL_BUILD" \
  --cases "$case_dir" --scenarios bh-x01,bh-x02,bh-x05,bh-x07 \
  --pair "$PAIR" --cold --host-load-max 16 --spacing 5 --out "$OUT"
python3 -B "$fixture_dir/run.py" wait "$OUT" --timeout 5400
```

Во втором пакете используйте `bh-x03,bh-x04,bh-x06`. Для повторов выберите новые каталоги результатов. Начинайте пакет при наличии свободного места в лимите прогонов хоста. Если остаток общего бюджета меньше бюджета пакета, задайте время отсечки в `LAB_2047_END_AT` как Unix timestamp в секундах.

Драйвер ждёт квитанцию `node_phase_prepared/configure` и видимую панель фильтра в браузере этого прогона. `intervention.jsonl` сохраняет ссылку на квитанцию, результат жеста и код выхода CLI. Неподтверждённое вмешательство отображается в сводке как `FAIL (runner/setup)`. После подтверждённого вмешательства ход восстановления запускается даже при отсутствии сохранения на прерванном ходу. Для x03 и x06 дельты лежат в `manual/execution-events.jsonl` и `manual-connect/execution-events.jsonl`. Ответы пользователю и вызовы инструментов находятся в `model.stdout`.
