# I1. Подключения и узлы программирования

| Кейс | Задача | Минимум узлов с CSV-экспортом |
|---|---|---:|
| bh-i101 | SQLite с SQL JOIN и агрегацией | 3 |
| bh-i102 | Именованный диапазон XLSX и справочник CSV | 4 |
| bh-i103 | REST GET с параметрами из таблицы и вложенным JSON | 4 |
| bh-i104 | Разбор JSON в JavaScript с обработкой повреждённой строки | 3 |
| bh-i105 | pandas, регулярное выражение и смена окна в том же узле | 3 |
| bh-i106 | Порог из входа переменных Python | 4 |

Подготовка из текущего каталога требует Python 3.10+ и openpyxl 3.1+.

```sh
umask 077
python3 -B generate.py --out "$HOME/bh-cases-i1"
for case in "$HOME"/bh-cases-i1/bh-i1*; do
  python3 -B "$case/oracle.py" --check || exit 1
done
```

Передайте каталог в `run-check start --cases`. Для двухходового кейса укажите
`bh-i105` в `--scenarios`. Раннер сам выполнит `bh-i105-start` в том же чате и
пакете. Проверьте идентификатор Python-узла на обоих ходах по
`graph-observed.json` или журналу операций. Проверьте фактические порты ребра
переменных в `bh-i106` по журналу графа.

Эталон считает результат по входным файлам. Для REST он использует снимки
ответов DummyJSON из `reference/`; они не передаются в чат. Если сервер
не может отправить запрос, подготовьте отдельный каталог с
`generate.py --out DIR --offline-rest` и выберите только `bh-i103`.
Этот вариант передаёт один JSON-ответ как вход для режима имитации.
