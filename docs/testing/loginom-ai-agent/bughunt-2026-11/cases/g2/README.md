# G2. Пошаговая правка сценария

Передай раннеру каталог `cases` и идентификаторы последних ходов.
`base` указывает на предыдущий ход в той же цепочке, пакет и чат общие.
Дополнительные входы прикладываются в том ходе, когда их приносит пользователь.

| Цепочка | Последний ход | Что проверяем |
| --- | --- | --- |
| g201 | `bh-g201-t5` | Вставка фильтра, замена агрегата, удаление CSV-экспорта, выгрузка XLSX |
| g202 | `bh-g202-t4` | Второй источник, перестановка входов, переход с левого слияния на внутреннее |
| g203 | `bh-g203-t4` | Добавление марта, отключение февраля, повторное выполнение с подсчётом строк |
| g204 | `bh-g204-t5` | Переименование, разрыв связи, прямое переподключение, удаление фильтра |
| g205 | `bh-g205-t4` | Замена файла в том же импорте, повторный расчёт, сортировка выручки по убыванию (LAB-2012) |
| g206 | `bh-g206-t5` | Открытие LGP с отдельным JS, подключение импорта, замена кода, Python после JS, выгрузка CSV |

В g202 начальное левое слияние использует один источник на двух входах.
Это даёт настроенный узел с рабочим ключом к приходу `returns.csv`.
Различающиеся суммы и несовпадающие ключи проверяют и перестановку, и смену
типа слияния. В g203 очередность входов задана при добавлении марта.
После отключения февраля март может остаться на порту 2 или перейти на порт 1.
В g206 файл `script-ready.lgp` создан из нативной фикстуры
`variables-datatovar/fixtures/aggregate-source.lgp`. Python появляется после
правки JS.

Из корня репозитория можно заново вычислить контракты и пересобрать LGP.

```sh
cases=docs/testing/loginom-ai-agent/bughunt-2026-11/cases
python3 -B "$cases/g2/generate.py" --out "$cases/bh-g206-t1/data"
python3 -B "$cases/g2/oracle.py" --write
python3 -B "$cases/g2/oracle.py" --check
```

`graph` задаёт полный целевой состав узлов и связей. Раннер проверяет
наличие требуемых элементов. По файлам `graph-observed.json` из каталогов
последовательных ходов скрипт ниже также проверяет отсутствие лишних узлов
и связей, сравнивает идентификаторы и выводит изменения. Переименование
в g204 должно сохранить идентификатор узла. Штатные «Переменные сценария»
учитываются при сравнении идентификаторов. Минимум узлов относится к узлам
пользовательской схемы.

```sh
python3 -B "$cases/g2/review-graph.py" 204 \
    /path/to/bh-g204-t1/graph-observed.json /path/to/bh-g204-t2/graph-observed.json
```

В `outputs` описаны запрошенные CSV. Ключ `g2_review` хранит дополнительные
проверки для разбора журналов, включая типы и полные ожидаемые строки,
режим слияния, количество строк в ответе и файл источника. На ходах с
выполнением ищи свежую квитанцию нужного узла. Если результат виден лишь
частично или журнал не содержит снимка графа, отмечай пробел в отчёте.
Ход g201-t5 проверяется также по реально скачанной книге с помощью `openpyxl`.

```sh
python3 -B "$cases/g2/oracle.py" --xlsx /path/to/summary.xlsx
```
