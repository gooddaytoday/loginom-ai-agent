# Волна 4, часть B (LAB-2042)

Передайте в `--scenarios` последние ходы: `bh-w44-t4,bh-w45-t5,bh-w46-t5`.
Используйте `--cases` с абсолютным путём к этому каталогу и `--cold`.
Нужна поддержка `output_mode: ports`, точного графа и `manual_edit` из PR #1353.
Каждая цепочка выполняется в одном пакете; изменения руками делаются после
сохранения и закрытия пакета, до следующей просьбы.

| Цепочка | Данные из dbseed | Что проверяется | Ручная правка |
|---|---|---|---|
| `bh-w44` | Строки выполненных и невыполненных заказов за 9 месяцев, скидки с пропусками | Выручка по месяцам в Python, добавление среднего за 3 месяца и смена окна на 6 в том же узле | Переименование импорта после t1 |
| `bh-w45` | Номера заказов ниже, на уровне и выше обоих порогов | Вычисление порога, привязка к фильтру и пересчёт после смены источника с 1000 на 500 | Перенос калькулятора после t2 |
| `bh-w46` | Цены товаров по категориям по обе стороны от 500 | Вставка фильтра в действующую связь, замена суммы средним, удаление фильтра и восстановление прямой связи | Переименование группировки после t2 |

Результат волны требует обеих проверок:

```sh
wait_rc=0
python3 scripts/node-acceptance/run-check.py wait "$RUN_DIR" --timeout 5400 || wait_rc=$?
node docs/testing/loginom-ai-agent/bughunt-2026-11/cases/wave4b-verify.mjs "$RUN_DIR/bh-w45-t5" && test "$wait_rc" -eq 0
```

Oracle автоматически сверяет `Limit=1000` на t2 по свежему типизированному
чтению выхода калькулятора. На t4/t5 раннер проверяет узлы, их идентичность
и табличную связь, а oracle — полный граф с управляющей связью, потому что
#1353 оставляет `Input_ControlVar` в журнале наблюдения неразобранной строкой.
Логические порты связи — выход переменных 0 и управляющий вход 0; холодная
проверка использует нативный граф и проверяет также значение `Limit=500`.
Порядок столбцов не проверяется; требуемый порядок строк сохранён.

Пересоздать входы и эталоны только этих цепочек из `dbseed/gen.py`:

```sh
python3 -B docs/testing/loginom-ai-agent/bughunt-2026-11/cases/wave4b-generate.py --out <каталог-кейсов>
```

`oracle.py` каждого хода независимо вычисляет эталон из CSV первого хода.
В задачи модели попадают только `task.md` и указанные входные CSV.
