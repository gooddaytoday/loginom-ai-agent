# H1. Аналитические задачи на разных датасетах

Каждый кейс — одна просьба о построении сценария в Loginom. Генератор создаёт
воспроизводимые CSV с заголовками на русском, разделителем `;` и UTF-8 BOM.
В каждом файле есть два формата даты, числа с десятичной запятой, пустые поля
и точные дубли строк с тем же идентификатором. Большие CSV генерируются при
подготовке к запуску.

| Кейс | Задача | Строк CSV без заголовка |
|---|---|---:|
| bh-h101 | ABC-анализ по выручке и пороги 80/95% | 56 000 |
| bh-h102 | RFM, три квинтильных балла и сегмент | 68 000 |
| bh-h103 | Месячные когорты удержания | 78 000 |
| bh-h104 | Недельная выручка и скользящее среднее по магазинам | 92 000 |
| bh-h105 | Кросс-таблица выручки и частоты по регионам и месяцам | 103 000 |
| bh-h106 | Выбросы по z-score датчика | 64 000 |

Из каталога H1 подготовьте отдельный корень для `run-check --cases` и сверьте
сохранённые эталоны. В команду генерации можно передать выбранные имена кейсов
после `--out`.

```sh
umask 077
python3 -B generate.py --out "$HOME/bh-cases-h1"
for case in "$HOME"/bh-cases-h1/bh-h10*; do
  python3 -B "$case/oracle.py" --check || exit 1
done
```

Эталон читает только входной CSV. Раннер сверяет типы, значения и порядок
результата с эталоном, проверяя итоговый CSV и выход сохранённого сценария.
Для пересчёта отдельного эталона запустите подготовленный `oracle.py` без
`--check`. Раннер передаёт в чат `task.md` и входной CSV.

Три узла — нижняя граница для цепочки с импортом, вычислением внутри Loginom
и CSV-экспортом. Штатная проверка принимает разные способы расчёта. Оценку
выбранных узлов, ручных исправлений и вычислений вне Loginom делайте по журналам.
