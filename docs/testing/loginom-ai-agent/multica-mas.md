# Обработка узла через Multica

Одна карточка — один узел. Пользователь указывает название узла, назначает существующему
скваду «Обработчики узлов» и переводит из Backlog в Todo («К выполнению»).
Multica автоматически запускает Генератора; комментарий с упоминанием не нужен.
Генератор сам дополняет назначение.
Карточки независимы; до восьми карточек обрабатываются параллельно.

## Порядок работы

1. **Генератор** находит узел в [реестре](../../node-development/registry.json) и его
   подплан. Добавляет в карточку ссылку, текущий этап, исходный SHA и ветку/цель PR.
   Существующие назначения и незавершённые изменения сохраняет.
2. Генератор в собственном браузерном сеансе входит в Loginom под предоставленным
   администратором и через штатное администрирование создаёт два обычных рабочих
   аккаунта: Манки и Ловца. Параллельные входы администратора разрешены; очереди,
   общей блокировки и отдельных администраторов карточек не требуется.
3. Имена создаются один раз, например `lab-54-monkey-<UUID>` и `lab-54-catcher-<UUID>`.
   UUID генерируется стандартным `uuidgen` или `crypto.randomUUID()`.
   До создания Генератор сохраняет имена и реквизиты в закрытых файлах карточки.
   При повторе проверяет уже созданные аккаунты и переиспользует их; если создан
   только один, создаёт только недостающий. После неопределённого ответа сначала
   проверяет наличие сохранённого имени, а не генерирует новую пару.
4. Обоим аккаунтам назначается доступ к каталогу пакетов этой карточки и право
   выполнять сценарии. Административные права им не выдаются. Генератор проверяет
   вход и доступ каждого аккаунта, выходит из собственных сеансов и передаёт карточку Манки.
5. **Манки** выполняет подплан: реализует недостающее, исправляет ошибки и проверяет
   реальные сценарии через Loginom CLI. Публикует SHA и результаты, передаёт Ловцу.
6. **Ловец** независимо проверяет тот же SHA по подплану. Конкретные замечания
   возвращает Манки в этой же карточке. После исправлений проверяет снова.
7. После успешной проверки карточка остаётся в `in_review` с результатом
   «Проверено, ожидает решения владельца». Завершает её пользователь; он же вручную
   удаляет аккаунты. Агенты не удаляют аккаунты ни после успеха, ни после ошибки.

Передача выполняется обычным комментарием с упоминанием только следующей роли.
Передающий агент завершает свой запуск. Внутри карточки роли последовательны;
готовая карточка не ждёт другие. Повторы — штатные Multica; перед ручным повтором
проверяются активный запуск и ожидающий повтор этой карточки.

## Окружение и настройки

Используется существующий runtime Codex (mas), лимиты ролей `8/8/8`, daemon `12`,
штатный интервал получения задач `3m`. Git-ресурс проекта использует `shared-oauth`;
ветку и SHA новой карточки фиксирует Генератор. Новые сквады и диспетчеры не нужны.

Каждая карточка имеет свою ветку, штатные рабочие копии Multica, пару аккаунтов,
каталог пакетов и результаты. Каждая роль/попытка имеет отдельный пустой профиль CLI
и браузер. Ловец получает доступ к сохранённым результатам Манки.
Закрытые настройки пары находятся в `~/.config/loginom-multica/cards/<issue-UUID>/`;
в карточку передаются пути `worker.json` и `reviewer.json`, а не пароли.
Каталоги имеют права 0700, файлы с реквизитами — 0600. Реквизиты администратора
читаются из закрытого `~/.config/loginom-multica/operator.json`, в Git не попадают.
Старый `provision-accounts.py` и подготовка LAB-53 не являются частью этого процесса.

CLI на mas: `~/.local/bin/loginom-ai-agent-cli`. Общая [OAuth-авторизация](shared-oauth.md)
находится в `~/.local/state/loginom-cli-oauth/shared-oauth-v1`; её не копируют по карточкам.
Настройки модели внутреннего CLI хранятся только в инструкциях сквада Multica.
В каждом новом профиле перед первым прогоном агент выполняет своим кандидатом
`loginom-ai-agent-cli models openai --refresh --verbose` и проверяет наличие модели
и варианта. Последующий прогон использует тот же `LOGINOM_AI_AGENT_CLI_PROFILE`: каталог
моделей хранится внутри профиля. При ошибке обновления сначала устраняется её причина.
Сетевые настройки: `LOGINOM_AI_AGENT_EXPERIMENTAL_WEBSOCKETS=false`,
`HTTP_PROXY`/`HTTPS_PROXY` — `http://127.0.0.1:2080`; `NO_PROXY` —
`localhost,127.0.0.1,::1,app.loginom.ai,mcp.loginom.ai,mas.kartamyshev.dev`.
Проверка сертификатов включена. Изменённый клиент собирается из SHA своей карточки.

После попытки агент закрывает свои пакеты, выходит из своего сеанса и завершает
собственные процессы. Чужие сеансы, файлы и аккаунты не затрагивает. Ошибка одной
карточки не останавливает остальные. История прежних попыток остаётся в карточке.

Критерии проверки задают [RUNBOOK](../../node-development/RUNBOOK.md) и подплан узла.
Успешный вход или запуск CLI не означает приёмку узла. Слияние и выпуск требуют
отдельной команды владельца. Eval и LAB-29/30 этим изменением не затрагиваются.
