# Аудит разграничения Loginom и Agent Skills

Дата: 2026-10-05. Ветка: `docs-no-browser`. Проверенный HEAD: `8e1e1917c`.
Аудит исходников и доступных локальных проверок; это не приёмка установленного
Desktop и не утверждённая спецификация реализации. Код продукта не изменён.

## Результат

Разграничение реализовано частично. Обычный запрос документации по локальному
или прикреплённому `.lgp` может выполняться без видимого окна Loginom. Skill
запрещает браузерные действия, а общий prompt больше не требует начинать любую
задачу с `loginom_dock_prepare`. Однако это инструкции модели, а не ограничение
исполнения. Есть пути запуска браузера до выбора skill. После чистой установки
Desktop этот skill не поставляется. Формальное имя `package_docs` не соответствует
Agent Skills.

## Что уже работает на уровне исходников

- [Skill](../../../.loginom-ai-agent/skills/package_docs/SKILL.md) принимает
  абсолютный локальный путь либо путь прикреплённого `.lgp`; описывает EXTRACT,
  SKELETON, HELP, NARRATIVE и EMIT. Форматы результата: PDF, DOCX, Markdown.
- `SKILL.md:35–49` запрещает изменение пакета, загрузку из файлового хранилища
  и вызовы `loginom_dock_*`, включая `prepare`.
- [V1 prompt](../../../packages/agent/src/session/prompt.ts):1330 ограничивает
  использование `prepare` созданием и изменением сценария.
- [SystemPrompt.skills](../../../packages/agent/src/session/system.ts):107–118
  сообщает модели каталог и предлагает загрузить подходящий skill по описанию.
- [SkillTool](../../../packages/agent/src/tool/skill.ts):47–60 возвращает тело
  skill, базовый каталог и список ресурсов. Ресурсы читаются по необходимости.
  [Compaction](../../../packages/agent/src/session/compaction.ts):31 защищает
  результаты инструмента `skill` от обычного pruning.
- [App attachments](../../../packages/app/src/components/prompt-input/build-request-parts.ts):206–227
  передаёт `.lgp` как `file://`, а не base64 для загрузки в Loginom.
  [V1 materialization](../../../packages/agent/src/session/prompt.ts):817–832
  добавляет `Attached Loginom package path:`;
  [model conversion](../../../packages/agent/src/session/message-v2.ts):216
  не отправляет пакет как бинарный документ провайдеру.
- Коммит `8e1e1917c` сохраняет этот путь и подсказку об отсутствующем локальном
  пути при slash-командах, включая отправку follow-up draft.
- [HostPort](../../../packages/loginom-host/src/host-port.ts):157–160 направляет
  справку и выбранные диагностические вызовы в `readiness`, пока runtime чата
  ещё не создан. Прерывание такого чата не создаёт runtime.

## Пробелы, влияющие на пользовательское поведение

### P1: вложение запускает браузер до выбора skill

В [SessionTools](../../../packages/agent/src/session/tools.ts):529–546 любые
`data:`-вложения с именем автоматически передаются в `loginom.admit`. Проверки
назначения запроса нет. [HostPort](../../../packages/loginom-host/src/host-port.ts):118
создаёт runtime чата для admission, а [Host](../../../packages/loginom-host/src/host.ts):63
делает обычный runtime чата видимым при стандартных настройках Desktop.

Пример: «Напиши документацию по прикреплённому `.lgp`; вот скриншот для пояснения».
Сам `.lgp` идёт через исправленный `file://` путь, но PNG идёт через `data:` и
вызывает запуск браузера до обращения модели к skill. Аналогично для других
base64-вложений в задачах прочих skills. Это подтверждено цепочкой исходников;
живой Desktop для этого запроса не запускался.

Хранение вложения для чата и его загрузка в Loginom должны быть отдельными
действиями. Admission исходных байтов в Loginom нужен только шагу построения
сценария, который использует эти данные. Существующее связывание загрузки
с оригинальным вложением пользователя нужно сохранить.

### P1: skill отсутствует в поставке Desktop

[electron-builder](../../../packages/desktop/electron-builder.config.ts):58–62
пакует `out`, icons и `resources/loginom`.
[stageResources](../../../packages/loginom-host/script/stage-resources.ts):96–115
копирует Node, Chromium и выбранные части runtime; каталог skill туда не входит.
В [V1 Skill](../../../packages/agent/src/skill/index.ts):275 встроен только
`customize-opencode`; V2 [SkillPlugin](../../../packages/core/src/plugin/skill.ts):18
также не регистрирует `package_docs`.

`.loginom-ai-agent/skills/package_docs` — допустимое расположение проектного
skill. Он обнаруживается при работе в этом репозитории или при отдельной
настройке источника. Наличие файла в исходном репозитории не устанавливает его
пользователям приложения. Одинаковый пробел есть в конфигурации сборки всех ОС;
это вывод по исходникам, без проверки новых установочных артефактов.

Нужно доставлять весь каталог: `SKILL.md`, scripts, references, assets/fonts.
Скрипты используют стандартную библиотеку Python, но требуют интерпретатор
`python3`, которого ресурсная сборка не гарантирует. На Windows особенно нельзя
полагаться на это имя команды. Нужен доставляемый интерпретатор с явным путём
или перенос обработки на уже поставляемый Node.

### P2: ограничения документации не исполняются кодом

[SessionTools](../../../packages/agent/src/session/tools.ts):549–577 продолжает
регистрировать весь каталог Loginom. SkillTool только получает разрешение на
загрузку skill; он не меняет набор инструментов и разрешения текущего шага.
Slash-команда также вставляет инструкции, не создавая отдельной области прав.
Разрешённый ошибочный вызов Dock может исполниться, несмотря на запрет в prose.

В одном чате после построения сценария его прежние инструкции остаются в
истории. Новый запрос документации не создаёт границу возможностей; Help
направляется в существующий runtime чата, если `hasRuntime` уже true.
Не следует считать отсутствие отдельного keyword classifier нарушением
Agent Skills; проблема здесь — отсутствие ограничения побочных действий.

### P2: справка зависит от браузера и подключения Loginom

[Host.prepare](../../../packages/loginom-host/src/host.ts):85–89 создаёт
`readiness`; он headless, но [managed-entry](../../../packages/loginom-runtime/src/managed-entry.mjs):104
всё равно вызывает `loginBrowser` с `keepOpen: true`. Даже чтение Help сегодня
использует runtime с авторизованным Chromium.

Ошибка подключения не останавливает общий чат: V1 acquire ловит её
в `prompt.ts:1125`. Но skill требует успешный Help-контекст и останавливает
отчёт при его недоступности (`SKILL.md:123–126`). Таким образом, видимое окно
исключено из UX, но реальной независимости от браузера и доступности сервера
Loginom нет. Следует отделить клиент справки от executor runtime, сохранив
необходимую авторизацию самого сервиса знаний.

## Соответствие Agent Skills

Проверено по [официальной спецификации](https://agentskills.io/specification)
и [руководству интеграции](https://agentskills.io/client-implementation/adding-skills-support).
Context7 использован для поиска документации; нормативные выводы сверены
непосредственно с официальным сайтом.

- Нарушение: `name: package_docs` содержит `_`. Нужно, например, `package-docs`,
  и такое же имя родительского каталога. Обновить ссылки, тесты и команды;
  совместимость старой slash-команды при необходимости решать отдельно.
- Frontmatter и структура `scripts/references/assets` соответствуют формату.
  Description непустой, 650 символов; основной файл — 176 строк.
- Спецификация не закрепляет единственный корневой каталог установки.
  Текущий проектный путь сам по себе не является нарушением стандарта.
- Полезно добавить `compatibility` с требованиями Python, локальной файловой
  системы и Help MCP. Это рекомендация, поле не обязательное.
- Поэтапная загрузка каталога, тела и ресурсов в V1 предусмотрена.
  Автоматическая активация предполагает решение модели по описанию; формат
  skill сам не гарантирует маршрутизацию и не ограничивает исполнение.

Нужно проверить выбор по естественным запросам, а не только ручной командой.
[Официальное руководство по descriptions](https://agentskills.io/skill-creation/optimizing-descriptions)
описывает отдельные проверки положительных и близких отрицательных запросов.
В текущем [session test](../../../packages/agent/test/session/prompt.test.ts):975
fake LLM получает готовый вызов `skill`; далее создаётся только `structure.json`.
Тест не доказывает автоматический выбор, обязательный Help, narrative, выпуск
финального документа или отсутствие запуска браузера.

## Рекомендуемая граница реализации

Оставить общую orchestration нейтральной: она сообщает доступные skills и
возможности, а сценарные инструкции активируются для соответствующего шага.
Нужны отдельные возможности локальной обработки документов, справки и
браузерного executor. Выбор skill и разрешение побочных действий — разные
части процесса. Проверять права следует и при публикации инструментов модели,
и при dispatch, включая действия инфраструктуры до LLM.

Для встроенных skills разумно выделить продуктовый источник, например
`packages/product/skills/package-docs`, и копировать его в версионированные
read-only resources. Зарегистрировать его в discovery с определённым приоритетом
переопределения; не копировать поверх пользовательских skills. Это предложение
архитектуры, а не требование Agent Skills к пути.

Первым внедрять V1: [Desktop](../../../packages/desktop/src/main/index.ts):70
использует его по умолчанию. V2 экспериментален и имеет отдельные discovery,
конфигурацию и execution; изменение только V2 не исправит установленный продукт.
V1 `skills: { paths, urls }` и V2 `skills: string[]` нельзя смешивать.

Поведение запросов:

1. «Построй сценарий»: активировать сценарный workflow, допустить нужные исходные
   вложения и явно получить браузерную возможность для выполнения.
2. «Документируй этот `.lgp`»: активировать документационный workflow, обработать
   локальный файл, воспользоваться независимым Help-клиентом, выпустить отчёт.
3. «Документируй текущий сценарий» без доступного пакета: использовать уже
   подтверждённый локальный артефакт чата либо запросить путь/вложение. Skill
   текущего MVP не скачивает пакет из Loginom.
4. «Построй, затем документируй»: последовательно выполнить оба workflow,
   передав подтверждённый сохранённый пакет между шагами.

Порядок доработок: поставка skill и исполнения; устранение eager admission;
ограничение возможностей документационного шага; независимая справка;
исправление имени и проверки активации. Не внедрять отдельное исключение
`if package_docs` для каждого следующего skill.

## Дополнительные недостатки генератора

Подтверждены на синтетическом XML того же вида, что существующие тесты;
совместимость с набором реальных пакетов не проверена.

- `extract_scenario_structure.py:235` обрезает дерево глубиной, затем `:453/:475`
  считают статистику по усечённому дереву. Default дал 6 узлов / 2 подмодели /
  глубину 3; полное раскрытие того же входа — 9 / 4 / 5. Skeleton называет
  статистику общей, без признака усечения. Считать полную статистику отдельно
  от глубины narrative либо обозначать ограничение.
- `extract_scenario_structure.py:444` принимает отсутствие индексированного
  `Unit.xml`: результат успешный, 1 модуль / 0 узлов. Нужна явная ошибка для
  отсутствующего модуля, указанного индексом.
- `emit_report.py:110` сохраняет skeleton с `PLACEHOLDER_*` как финальный файл.
  Добавить проверку завершённости перед выпуском.

## Проверки и ограничения

- Python suite `test_extract_scenario_structure.py`: 7/7 успешно, в том числе
  выпуск MD/PDF/DOCX. Выполнены дополнительные Python probes указанных выше
  недостатков. Временные входы не добавлялись в репозиторий.
- Простой PDF прочитан `pdfinfo` и `pdftotext`: PDF 1.4, A4, одна страница,
  русский текст извлекается. XML простого DOCX разобран ElementTree.
  Визуальная вёрстка и совпадение с эталоном не проверены.
- Локальная проверка ограничений имени/длины по спецификации: name invalid,
  parent matches, description 650 chars, file 176 lines. `skills-ref validate`
  не запускался; это не результат официального валидатора.
- HostPort targeted test не стартовал: отсутствует `effect`.
- Session targeted test не стартовал: отсутствует `@opentui/solid/preload`.
- App targeted suite не стартовал: отсутствует `@happy-dom/global-registrator`.
- `bun typecheck` в loginom-host не стартовал: отсутствует `tsgo`.
  Зависимости не устанавливались; эти результаты — ограничения окружения,
  а не найденные падения логики тестов.
- Реальные модельные запросы, установка новых Desktop-артефактов и native
  проверки на Linux/Windows/macOS в этом аудите не выполнялись.

Для приёмки доработок обязательны: чистая установка вне исходного репозитория;
локальный и прикреплённый `.lgp`; документация с дополнительным PNG;
отсутствующий путь; переход построение → документация в одном чате; составной
запрос; близкие запросы построения, которые не должны активировать docs skill.
Проверять отдельно выбор skill, полный выходной документ, неизменность `.lgp`,
вызовы инструментов и факт запуска Chromium, а не только видимость окна.
