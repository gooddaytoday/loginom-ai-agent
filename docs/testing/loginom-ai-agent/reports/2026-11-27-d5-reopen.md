# D5: холодное открытие сохранённого пакета — LAB-2156

27.11.2026, mas2, 20 ядер. **Серию блокирует вход на стенд из чистого Chromium.** Это новый блокер проверки, а не объяснение D5. Частота D5 на mas2 неизвестна: ни одна попытка не дошла до открытия пакета.

Базы: `50224d5efe032cbc1509cdd836c49d44f1754684` (`origin/oc2-migration`) и `75bef71f1af6b0006cd4f1aac239f2e473fe120f` (`origin/c0-v043-sync`, не влит в проверенную базу). Исторический шлюз B использовал `38757dac117f8545bc8dc1b5294212526609461c`; см. `2026-11-26-gate-b.md`, D5, и раздел B6.1-R журнала миграции.

Использована пара из LAB-2123. Исходные c1-3/c2-3 сохранены под другими учётками; чужие папки не открывались. Инвентаризация своей папки не дошла до файлов (`timeout`, выход 124). Старт раннера — выход 0, `wait` — выход 1. Оба сценария остановились до фазы модели и не создали пакеты. Вызовов модели и изменений сохранённых пакетов не было.

В журнале Chromium HTML-документ имел HTTP 200, но ожидание формы закончилось при незавершённых запросах: например, 104 из 483 и 312 из 483 на повторных попытках. На первой попытке `partition-random` загрузка одного скрипта завершилась ошибкой после HTTP 200. Независимая проба без авторизации: прямой `curl` — выход 28, HTTP 000 за 35 с; обычный `curl` с прокси хоста — HTTP 200 за 3,46 с; прямой Chromium — `ERR_CONNECTION_CLOSED`. Продукт намеренно запускает Chromium без прокси (`packages/loginom-runtime/src/connection-check.mjs:393`). Эти наблюдения локализуют блокер до графа и не разделяют сбой сервера, сетевого пути и загрузки приложения в браузере.

## Где возникает D5

- `partition-random`: `packages/loginom-runtime/client/lib/workspace-ui.mjs:4568` возвращает `UI_REFERENCE_STALE` при изменении границ элемента более чем на 0,75 px. На базе `packages/loginom-runtime/client/lib/node-procedure.mjs:1463` уже допускает одно свежее наблюдение для `execute_graph_node`, только когда достоверно не было эффекта и жеста. Без исходной трассы нельзя сказать, не прошли ли условия восстановления или отказ повторился после него.
- `sampling-random`: после возможной деактивации `packages/loginom-runtime/client/lib/node-execution-procedure.mjs:269` ждёт тот же проверенный разблокированный граф, выбранный узел и ровно один доступный `execute_graph_node`; истечение ожидания — `packages/loginom-runtime/client/lib/node-procedure.mjs:1209`. По сообщению ошибки не видно, какое из условий не выполнилось.
- 0.4.3 добавляет восстановление той же сохранённой рабочей области с повторным чтением графа после перезагрузки (`packages/loginom-runtime/client/lib/bridge.mjs:175`). `cold-check` создаёт другой браузер и открывает пакет напрямую (`scripts/node-acceptance/cold-check.mjs:160`), не через этот путь восстановления. В 0.4.3 запуск повторно использует уже готовое наблюдение, но после выбора или деактивации требует свежее; то же условие и защита геометрии остаются (`packages/loginom-runtime/client/lib/node-execution-procedure.mjs:276`, `packages/loginom-runtime/client/lib/workspace-ui.mjs:4657` в `75bef71f1a`). Это сокращает лишние чтения, но не доказывает, что D5 исправлен.

Локально: Node 24.19.0, `node --test` для `node-execution-viewport`, `node-graph-launch`, `reloaded-node` — 51/0 и 55/0; `packages/product`, Bun 1.4.4 — 118/0 и 125/0; все выходы 0. Ресурсы 0.4.3 для пробы входа проверены `verifyResources` (5343 хеша, те же закреплённые Node и Chromium). Код продукта не менялся: причина исторического D5 не подтверждена.

После восстановления входа нужен сохранённый экземпляр каждого сценария в папке пары, затем минимум пять холодных открытий на каждый узел и ревизию без повторных вызовов модели. При повторе отказа нужны два снимка границ и результат восстановления для `UI_REFERENCE_STALE`, а для таймаута — выбор узла, блокировка и число доступных контролов на последнем наблюдении.

## LAB-2176 · повторная проверка на mas

**На базе 0.4.3 D5 не воспроизведён.** Пять зачётных холодных прогонов каждого узла завершились с exit 0. Во всех десяти подтверждены два исполнения исходного узла, значения и типы портов, сохранённый seed 42, закрытие пакета и выход из Loginom. Настройки заново не применялись.

База испытаний `09b2d7d6fb50400a1a46e09e9c009573af891ecc` с 0.4.3. На `mas` 12 доступных логических ядер. Для c1-3 и c2-3 журнал шлюза B фиксирует только `partition-random` и `sampling-random` соответственно. Исходные пакеты находятся под учётками шлюза. Вход под обеими учётками пары `fca26310` подтверждён. Полное чтение через `dock_storage_list` (399 и 15 нативных записей, exit 0) не нашло `*.lgp` со штатными именами этих двух сценариев.

Штатный `build-cli.ts --no-archive` сначала завершился с exit 1 на повторной загрузке Bun (`ConnectionClosed`). Повторная сборка через тот же скрипт использовала локальный Bun 1.4.4 baseline из официального ZIP с SHA-256 `e0446eb55995772eb9894bebae9a6be368d985a8b9271ee124486f9946eedd76`. Сборка и проверка манифеста завершились с exit 0, `sourceDirty=false`, версия CLI `0.0.0-dev-202611272135`. Рантайм использовал Node 24.19.0 и Chromium 1246.

Подготовка — один запуск `openai/gpt-6.1-terra` (`medium`, OAuth ChatGPT) на сценарий. Для `sampling-random` подтверждены сохранение, закрытие пакета и выход из Loginom. Штатный оракул проверил оба CSV, два выполнения на одном нативном узле и 8 строк на выходе. Для `partition-random` модель запросила уточнение о восьми строках сверх размеров 8+4 и завершилась до сохранения. Раннер зафиксировал `SAVE_NOT_CONFIRMED`.

Пакет `partition-random` подготовлен через штатные инструменты Loginom без второго запроса к модели. Входной CSV содержит 20 строк. На одном узле с seed 42 получены два одинаковых полных результата с 12, 8 и 4 строками. Три экспортных узла настроены без выполнения. Оракул проверил нативные чтения. Штатный Save вернул `SUCCEEDED`, `save_completed:true`, затем подтверждены закрытие именно сохранённого пути и выход. Временная обёртка завершилась с exit 1 из-за лишнего ожидания `reopened:true` от Save. Запись и закрытие проверены по нативным квитанциям, сохранённый файл — отдельным холодным открытием.

`run-check.py start` — exit 0, `wait` — exit 1 из-за подготовки `partition-random` моделью. Успешная подготовка `sampling-random` подтверждена штатным отчётом. После прогона оба OAuth-профиля удалены, в результатах не осталось `auth.json`, БД и файлов журнала БД.

### Точки отказа шлюза B

- c1-3. `packages/loginom-runtime/client/lib/workspace-ui.mjs:4568` в `38757dac11`, `:4657` в `09b2d7d6fb` возвращает `UI_REFERENCE_STALE` до жеста, когда граница элемента отличается более чем на 0,75 px, либо прямоугольник стал невалидным или скрытым. В обеих ревизиях `execute_graph_node` допускает одно свежее наблюдение после доказанного отказа без эффекта. В проверенной базе условие находится в `packages/loginom-runtime/client/lib/node-procedure.mjs:1532`.
- c2-3. `packages/loginom-runtime/client/lib/node-execution-procedure.mjs:276` в `09b2d7d6fb` требует подтверждённый разблокированный граф, выбранный узел и единственный доступный `execute_graph_node`. Таймаут формируется в `packages/loginom-runtime/client/lib/node-procedure.mjs:1260` (`:1209` на шлюзе B). Изменение `e0e9cea8e2` переиспользует уже готовый снимок, а после выбора или деактивации по-прежнему требует свежего наблюдения. Штатный `cold-check.mjs` открывает новый браузер и не вызывает восстановление после перезагрузки страницы из 0.4.3.

На `09b2d7d6fb` охранные тесты `packages/product` (Bun 1.4.4) — 125/125, exit 0. Три файла `node-execution-viewport`, `node-graph-launch` и `reloaded-node` через `node --test` — 55/55, exit 0.

### Холодная серия без модели

В каждом прогоне использован новый браузерный профиль под Xvfb 1280×800. `load1` снимался перед запуском и каждые 2 с. В зачёт входят прогоны с итоговой квитанцией и наблюдавшимся максимумом не выше 12.

```sh
LOGINOM_AI_AGENT_TEST_HEADLESS=0 LOGINOM_AI_AGENT_ACCEPTANCE_VIEWPORT=1280x800 \
  xvfb-run -a -s '-screen 0 1280x800x24' "$CLI_RESOURCES/bin/node" \
  scripts/node-acceptance/cold-check.mjs --resources "$CLI_RESOURCES" \
  --config "$D5_CONFIG" --saved "$D5_PACKAGE" --expected "$D5_EXPECTED" \
  --sampling-baseline "$D5_BASELINE" --output "$D5_TRIAL"
```

Для `sampling-random` также передан `--csv` с выгруженным результатом второго выполнения.

Восемь дополнительных проходов `partition-random` с пиками load1 выше 12 тоже завершились с exit 0 (максимальный пик 24,98). Поэтому такие пики сами по себе не воспроизвели D5 на проверенном пакете. Три другие попытки оборвались с exit 1 при записи локального журнала (`EDQUOT`, errno −122). После переноса временных каталогов на рабочий диск оба файла повторно открылись и были штатно закрыты.

### Вывод

На `09b2d7d6fb` частота D5 составила 0/5 для каждого узла. В контроле с runtime `38757dac11` результат составил 0/2 для каждого узла. В журналах завершённых прогонов — 0 отказов защиты геометрии и 0 таймаутов ожидания Execute. Зачётные прогоны проверены по `result.json` и `execution-events.jsonl` для каждого открытия.

После деактивации появлялась маска Loginom, при которой наблюдение ещё не видело доступного Execute. На базе 0.4.3 готовность наступала за 0,393–1,623 с от начала наблюдения при бюджете 15 с. С runtime шлюза B готовность наступала за 0,184–0,579 с. На двух заново подготовленных пакетах это штатный переход с последующим запуском. Последнего нативного снимка из c2-3 и пары прямоугольников из c1-3 нет. Данными текущей серии нельзя отнести исторический D5 к стенду, нагрузке или клиенту.

Остались непроверенными исходные пакеты c1-3/c2-3 и точное окружение шлюза B. Редкий сбой холодного открытия остаётся возможным.
