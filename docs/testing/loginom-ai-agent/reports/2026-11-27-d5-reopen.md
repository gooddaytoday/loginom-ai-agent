# D5: холодное открытие сохранённого пакета — LAB-2156

27.11.2026, mas2, 20 ядер. **Серию блокирует вход на стенд из чистого Chromium.** Это новый блокер проверки, а не объяснение D5. Частота D5 на mas2 неизвестна: ни одна попытка не дошла до открытия пакета.

Базы: `50224d5efe032cbc1509cdd836c49d44f1754684` (`origin/oc2-migration`) и `75bef71f1af6b0006cd4f1aac239f2e473fe120f` (`origin/c0-v043-sync`, не влит в проверенную базу). Исторический шлюз B использовал `38757dac117f8545bc8dc1b5294212526609461c`; см. `2026-11-26-gate-b.md`, D5, и раздел B6.1-R журнала миграции.

Использована пара из LAB-2123. Исходные c1-3/c2-3 сохранены под другими учётками; чужие папки не открывались. Инвентаризация своей папки не дошла до файлов (`timeout`, выход 124). Старт раннера — выход 0, `wait` — выход 1. Оба сценария остановились до фазы модели и не создали пакеты. Вызовов модели и изменений сохранённых пакетов не было.

В журнале Chromium HTML-документ имел HTTP 200, но ожидание формы закончилось при незавершённых запросах: например, 104 из 483 и 312 из 483 на повторных попытках. На первой попытке `partition-random` загрузка одного скрипта завершилась ошибкой после HTTP 200. Независимая проба без авторизации: прямой `curl` — выход 28, HTTP 000 за 35 с; обычный `curl` с прокси хоста — HTTP 200 за 3,46 с; прямой Chromium — `ERR_CONNECTION_CLOSED`. Продукт намеренно запускает Chromium без прокси (`packages/loginom-runtime/src/connection-check.mjs:393`). Эти наблюдения локализуют блокер до графа и не разделяют сбой сервера, сетевого пути и загрузки приложения в браузере.

## Где возникает D5

- `partition-random`: `packages/loginom-runtime/client/lib/workspace-ui.mjs:4568` возвращает `UI_REFERENCE_STALE` при изменении границ элемента более чем на 0,75 px. На базе `packages/loginom-runtime/client/lib/node-procedure.mjs:1463` уже допускает одно свежее наблюдение для `execute_graph_node`, только когда достоверно не было эффекта и жеста. Без исходной трассы нельзя сказать, не прошли ли условия восстановления или отказ повторился после него.
- `sampling-random`: после возможной деактивации `packages/loginom-runtime/client/lib/node-execution-procedure.mjs:269` ждёт тот же проверенный разблокированный граф, выбранный узел и ровно один доступный `execute_graph_node`; истечение ожидания — `packages/loginom-runtime/client/lib/node-procedure.mjs:1209`. По сообщению ошибки не видно, какое из условий не выполнилось.
- 0.4.3 добавляет восстановление той же сохранённой рабочей области с повторным чтением графа после перезагрузки (`packages/loginom-runtime/client/lib/bridge.mjs:175`). `cold-check` создаёт другой браузер и открывает пакет напрямую (`scripts/node-acceptance/cold-check.mjs:160`), не через этот путь восстановления. В 0.4.3 запуск повторно использует уже готовое наблюдение, но после выбора или деактивации требует свежее; то же условие и защита геометрии остаются (`packages/loginom-runtime/client/lib/node-execution-procedure.mjs:276`, `packages/loginom-runtime/client/lib/workspace-ui.mjs:4657` в `75bef71f1a`). Это сокращает лишние чтения, но не доказывает, что D5 исправлен.

Локально: Node 24.19.0, `node --test` для `node-execution-viewport`, `node-graph-launch`, `reloaded-node` — 51/0 и 55/0; `packages/product`, Bun 1.4.4 — 118/0 и 125/0; все выходы 0. Ресурсы 0.4.3 для пробы входа проверены `verifyResources` (5343 хеша, те же закреплённые Node и Chromium). Код продукта не менялся: причина исторического D5 не подтверждена.

После восстановления входа нужен сохранённый экземпляр каждого сценария в папке пары, затем минимум пять холодных открытий на каждый узел и ревизию без повторных вызовов модели. При повторе отказа нужны два снимка границ и результат восстановления для `UI_REFERENCE_STALE`, а для таймаута — выбор узла, блокировка и число доступных контролов на последнем наблюдении.
