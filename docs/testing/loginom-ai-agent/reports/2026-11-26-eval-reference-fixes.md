## Десять исправленных кейсов

Новый вердикт ниже относится к копии сохранённых материалов. Раунд — номер из журнала кампании. В первых шести кейсах нативный `gdCount` в узле группировки учитывает все строки, включая пустые и `null`.

1. `contract-payment-churn` принимает нативный `gdCount` для числа клиентов и `gdSum(churn)`, если операнд по графу восходит к двоичному входу без изменения значений. У исходных 500 строк 362 значения `0` и 138 значений `1`. Копии LAB-901, раунд 1, и LAB-1996, раунд 1, получили 100. Первая использует прямой `gdSum(churn)`, вторая — сумму двоичного индикатора.
2. `currency-change-profile` принимает `gdCount(rate)` для числа наблюдений и знаменателя. Все три раунда LAB-901 получили 100.
3. `feature-usage-conversion` принимает `gdCount(converted)` для числа строк после разворота восьми функций. LAB-901, раунд 1, и LAB-1996, раунд 1, получили 100.
4. `tenure-churn-profile` принимает `gdCount(tenure_months)` для числа клиентов. В LAB-901, раунд 1, пункт `churn-measures` принят, оценка артефакта 100. Исторический запуск CLI завершился с кодом 1 и статусом `failed`. Повторного запуска CLI не было.
5. `monthly-demand` принимает `gdCount(daily_demand)` для числа строк одного месяца. LAB-1996, раунд 1, получил 100.
6. `treatment-followup-profile` принимает `gdCount(patient_id)` для числа пациентов. LAB-1996, раунд 1, получил 100.
7. `age-pressure-correlation` связывает SHA-256 и размер приложенного файла с подтверждённой доставкой, полным путём, ID сохранённого узла и завершённым импортом. Служебный путь эталона может отличаться. LAB-1996, раунд 1, получил 100. Независимо подтверждены 8 188 байт исходника, полный путь и квитанция импорта 300 строк.
8. `train-only-mase-business` принимает `Count(Replace(a,b,"",False,False))=0` для точного сопоставления непустых ключей обучающего ряда. LAB-1996, раунд 1, получил 100.
9. `tied-score-auc-business` принимает тот же способ точного сравнения непустых ключей, включая `case_id` в подсчёте классов. LAB-1996, раунд 3, получил 100.
10. `observed-purchase-cohort-retention-business` принимает фильтр `frtIsNotNull`, если свежее типизированное чтение того же импорта показывает `customer_id=null` у I08 и обе ветви используют результат отбора. В LAB-1996, раунд 3, оба пункта об отборе и о подсчёте уникальных клиентов приняты. Оценка 100.

## Адресная калибровка

Копии пересужены штатным harness на `gpt-6-sol/xhigh`, Codex CLI 0.167.0, порог 70. Проверены 19 архивных копий и 6 синтетических контрпримеров. У допустимых вариантов проверен соответствующий обязательный пункт. Для близких неверных вариантов сохранён исходный CSV, поэтому числовой oracle проходит. Судья отклонил каждый такой вариант по обязательному пункту.

- **Подсчёт строк.** В копии `currency-change-profile` из LAB-901, раунд 2, заменены `gdCount` на `gdNullCount` и сопоставление на `rate_NullCount`. Для `contract-payment-churn` в копии LAB-1996, раунд 1, заменён двоичный индикатор на `If(churn = 1, 2, 0)` перед суммированием.
- **Источник.** В копии `age-pressure-correlation` из LAB-1996, раунд 1, квитанция сообщает другой полный путь с тем же basename, SHA-256 и размером. Импорт и CSV сохранены.
- **Точное равенство.** В копии MASE из LAB-1996, раунд 1, `Replace` удаляет все вхождения. Например, `T01T01` и `T01` ошибочно дают пустой остаток. В копии AUC из LAB-1996, раунд 3, `Replace` игнорирует регистр, поэтому `A01` и `a01` ошибочно совпадают. С двумя флагами `False` эти пары различаются. Позитив и контрпример AUC пересужены после явного уточнения про `case_id`. В контрпримере судья отклонил `classes` и `native`.
- **Пустой покупатель.** В копии cohort из LAB-1996, раунд 3, типизированная ячейка I08 содержит пустую строку с `is_null=false`. Сохранены `frtIsNotNull`, граф и итоговый CSV.
- **Два экспорта в один файл.** Копии `district-weighted-indicators`, LAB-901, раунд 2, и `source-device-conversion`, LAB-901, раунд 3, отклонены обязательным пунктом `export` при пройденном oracle. Обе оценены на 89.
- **Дробное представление целого.** Копии `district-weighted-indicators`, LAB-1996, раунды 1 и 2, снова отклонены по `export`. Обе имеют oracle=true и 89 баллов. В графах `total_population` становится строкой с `.000000`.

Контрольные мутации XML проверены через `xmllint`. Для повторения используй копию указанного `artifact/`, сырой `events.jsonl` и исходный текст из `judge/TASK.md`. Штатные `parseEvents` и `judgeTask` принимают эти материалы и пишут новую оценку в отдельно заданный каталог. Для синтетических вариантов исключаются пункты `requires_run`. Полные идентификаторы прогонов, SHA-256 исходных и изменённых материалов, старых и новых verdict и обязательные пункты закреплены в манифесте. Для четырёх проверок доставки и типизированного импорта все материалы судьи побайтно совпали с повторной подготовкой на закреплённом коммите.

## Нативная проверка city-weather-risk

В отдельной паре Server и Studio использован образ сервера из LAB-1996. Из пакета раунда 1 извлечено точное выражение и нативно выполнено в том же калькуляторе на пробной копии. В копии подставлены четыре синтетические строки, добавлены диагностика длины и LF и удалён `Unit.bin`, чтобы сервер загрузил изменённый XML. Выражение флага сверено с оригиналом побайтно.

```text
IF(RegExMatch("\A(?:Rain|Snow|Mist)\z", Concat(weather_main, "")), 1, 0)
```

- `Rain` → 1.
- `rain` → 0.
- `RAIN` → 0.
- `Rain` с конечным LF → 0. Свежее чтение порта подтвердило длину 5 и UTF-8 `5261696e0a`.

Для проверенного варианта на 7.4.2 отдельный `(?-i)` и проверка длины из эталона необязательны. Критерий по-прежнему требует точного значения и регистра. Архивная копия `city-weather-risk` после уточнения получила 100 при положительном oracle. Временная пара удалена после штатного закрытия пакета и сессии. В манифесте закреплены SHA-256 пакета, копии и образов, версия и прочитанные значения.
