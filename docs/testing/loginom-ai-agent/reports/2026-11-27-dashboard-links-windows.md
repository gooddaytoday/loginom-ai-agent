# Ссылки Dashboard из Studio в Desktop, 27 ноября 2026

Три независимых дефекта доставки ссылки `loginom-ai-agent://dashboard?id=…&action=create` из Studio в Desktop.

## Причина

Windows передаёт ссылку как `loginom-ai-agent://dashboard/?id=…` (слэш перед `?`). Строгий разбор в `packages/app/src/pages/layout/deep-links.ts` отвергает непустой путь и молча отбрасывает ссылку. При открытом окне приложение получало её через `second-instance` и теряло. Ссылку из аргументов запуска Desktop читал только на Linux; на Windows при закрытом приложении ссылка терялась. На macOS ссылка через `open-url` до первого окна не создавала окно «как при холодном старте» (флаг `coldDashboard`), а `app.relaunch()` повторял аргументы запуска и мог снова открыть одноразовую ссылку.

## Изменение

Строгий разбор в приложении не менялся. `packages/desktop/src/main/deep-links.ts` — нормализация `dashboard/?` → `dashboard?` и `coldDashboard` для ссылки до первого окна. `packages/desktop/src/main/deep-links.test.ts` — два новых теста. `packages/desktop/src/main/index.ts` — чтение ссылки из аргументов на всех ОС, ранний и поздний `open-url`, перезапуск без ссылок `loginom-ai-agent://`.

## Попутные находки

- На Windows `pre-push` не проходит для новой ветки: `secret-scan` кладёт в командную строку `git rev-list` по одному `^oid` на каждую удалённую ветку, лимит длины Windows превышен (ENAMETOOLONG); обошлось созданием ветки на базовом SHA.
- В клоне без симлинков (`core.symlinks=false`, нет прав) корневой typecheck падает на `packages/enterprise` (TS1128); push выполнен с `LOGINOM_NODE_WORKFLOW=cli` по решению владельца, полный typecheck выполнил CI на Linux.
- Профиль dashboard на Windows может не определиться при нестандартной записи пути (регистр буквы диска, короткие имена 8.3); папки dashboard переименовываются без повторных попыток (антивирус); тест `dashboard-target.test.ts` с разделителем `/` не проходит на Windows; ссылка, пришедшая в момент завершения приложения, теряется.
