# Приёмка установщика Loginom 7.4.2 с Dashboard M7 в QEMU

## Среда проверки

- Чистая Ubuntu Server 24.04.5 LTS amd64 с ядром `6.8.0-147-generic`. ВМ загружена через `qemu-system-x86_64` с KVM и отдельным диском qcow2 поверх проверенного cloud image. SHA-256 базового образа `04e8f2461a16a44e78a370284471f29616cdd9baf1893df25807b71f985b6c94`.
- Docker Engine `29.1.3`, Compose `2.40.3`. Перед установкой в госте было 0 Docker-образов, 0 контейнеров и ни одного из четырёх каталогов Loginom и Dashboard.
- Комплект `loginom-release-7.4.2-6e72ef0f1824-dashboard-m7.tar` прошёл `sha256sum -c` на хосте и внутри ВМ. SHA-256 `32d8341fc7621bf573d4c6f05ed83dfe179fd33b8e990d6cfa1de2db7ab9acbb`.
- На гостевой ОС закрыт выход в интернет. Пробы из гостя и контейнера на Docker bridge подтвердили, что публичный адрес недоступен, а сетевой Guardant отвечает на TCP 3186 и 3187. У Docker отсутствовали HTTP и HTTPS proxy.

## Локальная отладка

`bash -n`, ShellCheck и десять сценариев `test-install-all.sh` прошли. Проверены повреждённый архив, чужой контейнер Compose, занятый порт, отказ лицензии, подмена каталога данных, прерывание на смене пароля и подтверждение без фактической смены. Проверены также продолжение прерванной установки Dashboard, повтор после сбоя его проверки и обработка опечатки в серийном номере. Тест выполняет установщик с экспортированным `HTTP_BIND=0.0.0.0` и проверяет, что штатная установка получает локальную привязку. Регрессия `test-pack.sh` подтвердила воспроизводимость tar, целостность вложений и отказ при неверном архиве.

## Первый запуск в госте

- Штатный `install.sh` загрузил Enterprise с диска, получил лицензию от сетевого Guardant и завершился с кодом 0. `verify.sh` подтвердил HTTP 200, WebSocket 101 и подключение Integrator. До создания тестовых данных в UserStorage было 0 пакетов `.lgp`.
- При запуске с конфликтующими `HTTP_BIND=0.0.0.0` и `HTTP_PORT` Docker опубликовал выбранный порт Studio только на `127.0.0.1` гостя. Прямой HTTP-запрос с рабочего места завершился без ответа. Через SSH-туннель `/app/` вернул 200.
- Первый запуск остановлен на запросе подтверждения смены пароля. Повторный запуск продолжил с этого шага. Пароль изменён через штатную форму Studio, затем проверен выход и повторный вход. После подтверждения прямой HTTP-запрос с рабочего места вернул 200.
- Установщик подключил Dashboard и запустил три контейнера M7. С рабочего места `/dashboard/shell.js` вернул 200. Первый терминал завершился по таймауту испытательного сценария уже после установки M7. Проверка продолжилась отдельным запуском установщика без переустановки.
- Повторный запуск вывел `Publication PASS`, `Server checks PASS` и `Cleanup PASS`. Заключительный штатный `verify.sh` прошёл, установщик завершился с кодом 0.

## Публикация из Desktop

- Установленный Desktop `0.3.9-m7.1` принял системную ссылку, но дважды остановился до открытия черновика. Повтор подтвердил код `LOGINOM_RUNTIME_CLEANUP_FAILED` операции `get-dashboard-target`. Studio и SSH-туннель в это время отвечали.
- На установленном Desktop `0.3.9` из `c6985aab6f` та же команда Studio открыла новый чат. Предпросмотр показал пять строк. Публикация с разрешением «Разрешить один раз» завершилась квитанцией `published` в журнале Desktop. Сервер получил один JSON и подтвердил `ready`, имя и хеши исходника и сборки.
- Независимая сессия Studio открыла опубликованный Dashboard. Для значений `10, 20, 30, 40, 50` получены пять строк и сумма 150. После порога 30 получены три строки и сумма 120.

## Проверка после перезагрузки

- Изменение `boot_id` подтвердило перезагрузку гостевой ОС. SSH, nftables и Docker восстановились, Studio вернула HTTP 200. Доступ к сетевому Guardant и блокировка выхода в интернет сохранились.
- В госте запущен финальный `install-all.sh` с SHA-256 `928d037e51325a9f696177ecee90421da622e470ec8956ca4575b25761db8eff`. Эта же версия положена рядом с архивом.
- Вход с новым паролем администратора прошёл. Независимый сеанс Designer открыл существующий Dashboard. Имя версии, SHA-256 исходника и сборки совпали с результатом до перезагрузки. Живые данные снова дали пять строк и сумму 150, затем три строки и сумму 120.
- Повторный `install-all.sh` вернул код 0. Получены `Publication PASS`, `Server checks PASS`, `Cleanup PASS` и успешный `verify.sh`. Идентификаторы всех шести контейнеров совпали до и после повторного запуска установщика.
