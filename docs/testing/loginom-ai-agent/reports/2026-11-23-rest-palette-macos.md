# REST-запрос превращается в «Слияние (дерево)» на macOS

На Mac arm64 воспроизведена гонка при перетаскивании из палитры. После создания REST-подключения исполнитель находит нужную строку по её идентификатору и вычисляет центр. Родительская панель продолжает прокрутку. Между чтением координат и нажатием мыши под указатель успевает попасть другой компонент. [Исходный инцидент #1247](https://github.com/gooddaytoday/loginom-ai-agent/issues/1247)

Проверка выполнена в новых несохранённых черновиках, через `runNodeApply` установленного Desktop 0.4.0, в его Chromium 1246. macOS 27.2.1 (26B131), Loginom 7.4.2 RU, область страницы 2048 × 1035. Для REST задан GET без таблицы и параметров запроса. SHA-256 установленного `node-target-browser.mjs` совпал с файлом тега `v0.4.0` (коммит `a63462dde1`).

## Что произошло в сбойном прогоне

| Момент | Наблюдение в браузере |
| --- | --- |
| Проверка перед drag | Центр строки REST — (148.6, 456), верх строки — 447. `elementFromPoint` подтвердил REST. «Слияние (дерево)» находилось на 69 пикселей выше. |
| Через 23 мс | Верх REST уже на 511. Событие `mousedown` по прежней точке получено строкой `Дерево_данных>Слияние_(дерево);TreeText`. |
| После отпускания | Для запрошенной позиции (510, 120) снимок графа показал единственный добавленный узел `bg-vendor-icon-jointree` в (512, 120). Ссылка на REST-подключение уже присутствовала до жеста. |

Исполнитель сохраняет точку, перечитывает граф и отправляет `mouse.move` и `mouse.down`. За это время граф может оставаться прежним при движущейся палитре. Внутренний `create` увидел один новый узел и вернул `SUCCEEDED`. Внешняя проверка потребовала точного совпадения типа и вернула `AMBIGUOUS` в фазе `target`. В журнале `pending=create`, `targetId=null`, подтверждённых эффектов — 0. [Жест в 0.4.0](https://github.com/gooddaytoday/loginom-ai-agent/blob/v0.4.0/packages/loginom-runtime/client/lib/node-target-browser.mjs#L242-L254) · [Проверка типа](https://github.com/gooddaytoday/loginom-ai-agent/blob/v0.4.0/packages/loginom-runtime/client/lib/node-target.mjs#L32-L37)

При автоматическом размещении в (400, 80) гонка проявилась с другим компонентом. Между проверкой и нажатием прошло 25 мс, строка REST сдвинулась на 53 пикселя. Нажатие получила «Таблица в дерево», на схеме появился `trees.from_table`. В этом черновике после inspect проверен штатный `abandon_operation`. Он вернул `NODE_RELEASE_REFUSED` с причиной `Original target effect remains unresolved`. [Условие отказа в 0.4.0](https://github.com/gooddaytoday/loginom-ai-agent/blob/v0.4.0/packages/loginom-runtime/client/lib/node-target.mjs#L564-L568)

## Контроль причины

При той же позиции (510, 120) один обычный прогон создал правильный REST-узел. Для контроля диагностическая обвязка перед drag дождалась пяти последовательных кадров с одинаковым прямоугольником строки. В прогоне с явной позицией ожидание заняло 240 мс. За это время `scrollTop` родительской панели `x-accordion-item` уменьшился с 487 до 0, а верх строки REST сместился с 185 до 672.

С ожиданием оба нажатия пришлись на REST. Узел появился в (512, 120) при явном размещении и в (400, 80) при автоматическом. В обоих случаях мастер затем остановился на `REST_CONFIGURE_REJECTED` при привязке поля описаний ошибок, выполнение GET не запрашивалось. [Отдельный дефект мастера #1246](https://github.com/gooddaytoday/loginom-ai-agent/issues/1246)

## Проверка исправления

В обработчике создания узла исполнитель ждёт совпадения центра строки палитры в двух последовательных наблюдениях и после перемещения указателя ещё раз проверяет строку непосредственно перед нажатием. Если после отпускания добавился узел другого типа, квитанция содержит ожидаемый и фактический тип, исходную строку палитры, координаты и снимок графа. Операция остаётся неопределённой. Повтор и автоматическое удаление исключены для такого эффекта.

Проверены исходники исправленного runtime от тега `v0.4.0` через `runNodeApply` с комплектными Node и Chromium на том же Mac. В каждом из четырёх новых черновиков зафиксировано одно нажатие на «REST-запрос». Снимки до и после жеста подтвердили появление ровно одного `integration.rest_request`.

| Запрошенное размещение | Обычный жест | Дополнительная задержка 65 мс перед перемещением мыши к строке |
| --- | --- | --- |
| Явное (510, 120) | REST в (512, 120) | REST в (512, 120) |
| Автоматическое | REST в (400, 80) | REST в (400, 80) |

Во всех четырёх прогонах узел прошёл проверку типа. Дальше мастер остановился на отдельном дефекте привязки поля. Выполнение GET во всех четырёх журналах имеет статус `not_requested`. [Дефект мастера #1246](https://github.com/gooddaytoday/loginom-ai-agent/issues/1246)

Локально прошёл 991 тест без пропусков. Для повторения из `packages/loginom-runtime/client` используйте закреплённый Node 24.19.0, укажите каталог комплектных браузеров в `PLAYWRIGHT_BROWSERS_PATH` и исполняемый файл Chromium в `LOGINOM_DOCK_TEST_BROWSER`.

```sh
node --test test/node-target*.test.mjs test/node-early-release.test.mjs test/node-placement*.test.mjs test/rest-*.test.mjs test/text-export-*.test.mjs
```
