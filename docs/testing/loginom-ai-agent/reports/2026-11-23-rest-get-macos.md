# REST-запрос на macOS, 23 ноября 2026

На Mac с Apple Silicon и macOS 27.2.1 воспроизведён отказ мастера из [#1246](https://github.com/gooddaytoday/loginom-ai-agent/issues/1246). Проверка использовала Loginom 7.4.2 с русским интерфейсом, Node 24.19.0, Chromium 1246 и каталог действий из установленного Desktop 0.4.0. Исполнитель запускался из рабочей копии с исправлением выбора компонента [#1247](https://github.com/gooddaytoday/loginom-ai-agent/issues/1247). Новый установщик и Windows в эту проверку не входили.

## Что воспроизвелось

На активной странице «Дополнительные параметры» оба флажка имели корректные идентификаторы, Ext-компоненты, DOM-поля ввода и булевы значения. Сразу после отказа и через 250 мс `getXType()` возвращал `checkbox`. Обработчик ожидал только `checkboxfield`, отменял настройку и оставлял выполнение в состоянии `not_requested`.

После исправления мастер принимает оба подтверждённых типа флажка и отдельно сообщает, какое поле и какая проверка не прошли. Для чтения длинного ответа с интерфейса 71 исполнитель использует штатный `GetValueAsString` источника, если столбец предоставляет только метаданные. Предварительная выборка валютного API содержала 5000 символов с многоточием. После повторного включения описаний Loginom помещает `ErrorDesc` за `HttpStatusCode`. Исполнитель проверяет имена, метки и типы и сохраняет фактический порядок.

## Что вернул узел

Все запросы ниже выполнены через `runNodeApply` со штатным REST-подключением, выключенной имитацией, `finish: execute` и чтением портов 0 и 1. В каждой операции оба порта содержали по одной полной строке с одинаковыми `RequestID` и идентификатором завершённого выполнения.

| Сценарий | Порт 0, Response | Порт 1 |
| --- | --- | --- |
| Новый узел, API курсов из issue, флаг включён | JSON с 54 валютами за 2026-11-21 | HTTP 200, ErrorCode 0, ErrorDesc OK |
| Новый узел, эхо-сервис, флаг включён явно или оставлен по умолчанию | JSON с методом GET и уникальным URL именно этого прогона | HTTP 200, ErrorCode 0, ErrorDesc OK |
| Существующий узел, флаг выключен, затем передан пустой патч | Оба ответа подтвердили GET и исходный URL | В обоих результатах HTTP 200, ErrorCode 0, поле ErrorDesc отсутствует |
| Тот же узел после повторного включения флага | GET и исходный URL | HTTP 200, ErrorCode 0, ErrorDesc OK в последнем столбце |
| Сохранённый пакет открыт в свежем профиле, тот же GUID узла, пустой патч | GET и URL, заданный до сохранения | HTTP 200, ErrorCode 0, ErrorDesc OK |

Тело валютного ответа на порту разобрано целиком. Дата и все записи валют совпали с независимым чтением API. Штатная обработка URL в публичном результате добавила завершающий слеш в поле `siteUrl`. [API курсов](https://kurs-rublya.ru/api/v1/rates/latest/)

При подготовке сохранённого примера операция `package.save_checkpoint` сообщила `REST_PACKAGE_NORMALIZATION_STILL_MODIFIED` после дополнительного сохранения. Повторное открытие файла в свежем профиле и выполнение сохранённого узла проверены независимо. Дальнейшая проверка ожидания сохранения приведена ниже.

Регрессионная выборка прошла на комплектном Node и Chromium. Из `packages/loginom-runtime/client` с заданными `PLAYWRIGHT_BROWSERS_PATH` и `LOGINOM_DOCK_TEST_BROWSER` выполнена команда, прошли все 1140 тестов без пропусков.

```sh
node --test test/node-target*.test.mjs test/node-early-release.test.mjs test/node-placement*.test.mjs test/rest-*.test.mjs test/text-export-*.test.mjs test/node-port-output*.test.mjs test/user-preview-budget.test.mjs
```

## Ожидание завершения сохранения

На том же Mac воспроизведена гонка после дополнительного «Сохранить». Агент вернул `AMBIGUOUS`, увидев `IsPackageModified = true` сразу после закрытия меню. Через 38 мс после начала контрольного наблюдения сервер уже вернул `false`. Следующие чтения вплоть до 14 секунд подтвердили это состояние без новых записей.

Исправленный исполнитель ждёт `false` до исходного срока операции. Между чтениями выдерживается интервал 100 мс, при каждом чтении проверяется принадлежность пакета и его серверной сессии. При смене сессии или истечении срока с установленным флагом сохранение остаётся неподтверждённым.

Для проверки на Mac в независимых черновиках выполнены GET и затем `package.save_checkpoint` либо `package.save_as`. Вызовы серверной сессии Loginom посчитаны в живом браузере. В каждом случае зафиксированы один `SavePackageAs` при создании файла и один `SavePackage` для изменённого после открытия пакета. После нажатия «Сохранить» сервер сначала вернул `true`, затем `false`. При итоговой проверке `false` получен через 212 мс после нажатия для `package.save_checkpoint` и через 182 мс для `package.save_as`. Обе операции завершились `SUCCEEDED`, независимое чтение после возврата также дало `false`.

Прошли все 348 тестов исполнителя, состояния пакета и завершения работы с ним. В первом прогоне расширенной выборки прошли 718 из 719. Тест `browser-recovery-bridge` задавал профиль Linux и на macOS останавливался при подготовке рабочего пространства. После выбора профиля по `process.platform` оба сценария восстановления прошли с профилем `unit-macos-chromium`. Повторный прогон той же выборки на Mac завершился за 141 секунду. Прошли все 719 тестов, пропусков и отмен не было.
