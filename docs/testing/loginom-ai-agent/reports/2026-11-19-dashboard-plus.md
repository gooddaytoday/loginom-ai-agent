# «+» из редактора дашборда в Desktop

Проверено 19 ноября 2026 года на Linux. База `dashboard-app@42d2152bbf`, кандидат `0.3.9-plus.2` собран с правками из рабочего дерева.

- RED на базе. После перехода A → B → редактор → «+» запрос создания сессии использовал служебную папку дашборда `work/`.
- Electron-регрессия на кандидате прошла для создания и редактирования одного узла из разных проектов. Проверены пустой чат без контекста дашборда, переход черновика в сессию, перезапуск, обычный «+», выбор проекта для старой вкладки и отмена выбора. Тест подменяет ответы бэкенда.
- Живой Desktop с отдельными HOME и XDG и постоянной БД прошёл A/B до первого сообщения, после него и после полного перезапуска. Studio выдала реальные снимки для обеих вкладок.
- В новом чате A на Loginom 7.4.2 штатный `loginom-automation` открыл тестовую копию `.lgp`, добавил целочисленную переменную `PplusCheck=12345`, сохранил пакет и повторно открыл его. Сравнение `Unit.xml` до и после подтвердило запись переменной. Проба инструмента на стенде дашборда с версией 7.5 завершилась `UI_BUILD_MISMATCH`.
- `bun typecheck` прошёл в App, Desktop, Product и Opencode. Прошли модульные и браузерные тесты App, тесты Product, проверки Desktop для дашборда и входящих ссылок, проверки изоляции и политики инструментов Opencode.
- Production-замер переключения вкладок на Chromium 1246 прошёл до и после правки. Медианы до стабилизации с закрытой панелью составили 50,6 → 55,4 мс для холодного и 29,4 → 29,6 мс для горячего перехода. С открытой панелью получено 71,3 → 49,4 мс и 45,3 → 42,4 мс соответственно.

Воспроизведение Electron-регрессии из `packages/desktop` с Node 24 и отдельным графическим сеансом Linux.

```sh
TMPDIR="$HOME/storage/tmp" LOGINOM_AI_AGENT_TEST_EXECUTABLE="<путь-к-кандидату>" \
  xvfb-run -a -s '-screen 0 1600x1000x24' node test/loginom/dashboard-chat.ts
```
