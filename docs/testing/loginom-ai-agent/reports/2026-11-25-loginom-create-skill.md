# Приёмка loginom-create-skill

Версия 0.3.9, канал `prod`. Desktop DEB и standalone CLI для Linux x64 собраны из чистого коммита `14b627e1ac`. Манифест и статическая проверка DEB, проверка манифеста CLI и контрольная сумма архива прошли. Для сборок использованы закреплённые версии из [конфигурации выпуска](../../../../packages/product/loginom-release.json). После сборки в ветке уточнялись Desktop smoke-тест, план и отчёт.

## Установленные приложения

DEB установлен через `apt`, CLI через `install.sh` из проверенного архива. Оба приложения работали в Ubuntu 24.04 x64 под одним непривилегированным тестовым пользователем с общим HOME, отдельными рабочими папками и раздельными профилями. Desktop использовал настоящий Electron, backend v1 и модель. Тестовый помощник пропустил экран подключения к Loginom в интерфейсе. В CLI использовались настоящий TUI, штатный диалог разрешений и модель.

1. Desktop выбрал `loginom-create-skill` и подготовил переносимую папку с `SKILL.md` и связанной `references/columns.md`. Машинная проверка прошла без ошибок и без установки. На `stock.csv` модель назвала отсутствующую `warehouse_code`.
2. В обоих чатах заранее отправлено сообщение и открыто меню `/`. Разовое согласие в Desktop скопировало папку в `~/.agents/skills`. После переноса исходника оба прежних чата самостоятельно выбрали скилл, прочитали вложенный файл из общей копии и вернули `warehouse_code`.
3. Явный выбор нового скилла при следующем открытии `/` в Desktop и CLI передал его инструкции в тот же чат. Оба приложения вернули `warehouse_code`.
4. Отказ в замене сохранил прежнюю копию и прежний ответ. Разовое согласие обновило описание в обоих меню и вложенный файл. Без перезапуска оба чата вернули `store_id`.
5. В отдельном прогретом прогоне CLI установил публичный `doc-coauthoring` из `anthropics/skills` по ссылке с закреплённым SHA. В TUI отдельно одобрены доступ к папке и установка. Уже открытый Desktop загрузил этот скилл на следующем сообщении и ответил на предметную пробу. Первая попытка с обычной ссылкой привела к выбору локальной проверки моделью. Для успешного прогона запрос явно указал действие установки.
6. С `LOGINOM_AI_AGENT_DISABLE_EXTERNAL_SKILLS=1` внешняя копия осталась на диске, а её команда исчезла из обоих меню `/`. Desktop также подтвердил отсутствие скилла в каталоге и неявного разрешения на вложенный ресурс. Поставляемый `loginom-create-skill` остался доступен в обоих меню.

## Проверки по исходникам

- Полный staging Loginom Host завершился с настоящими закреплёнными Node и Chromium. Изменённые TypeScript-пакеты прошли `bun typecheck`. Каталог upstream-sync прошёл проверку на закреплённой базе.
- Host — 34 теста, backend — 351 тест и 3 пропуска, Desktop — 16 тестов и 2 платформенных пропуска, App — 25 тестов, TUI — 5, Core — 3, Product — 60. Runtime с закреплённым Chromium — 9784 теста и 5 пропусков. Ошибок в итоговых пакетных прогонах нет.
- Проверены машинная диагностика и исправление отсутствующего ресурса, явные запреты на чтение, отсутствие постоянного разрешения на установку, одновременные замены, восстановление предыдущей копии при прерванной записи и сохранение активного ответа при обновлении каталога. Тесты команд подтвердили отдельную передачу буквального тела скилла, пользовательских аргументов и вложений.
- В живом чате из исходников модель исправила ошибку по диагностике, выбрала созданный скилл для проверки колонок и ответила на близкую просьбу о числе строк без него. Вопрос о настройке MCP направлен в `customize-opencode`.
- На локальном HTTP-стенде проверены запрос с искусственным GitHub-токеном, сохранение его только для исходного origin, выбор кандидата по SHA и сохранение установленной копии после отказа либо повреждения архива.
- Неизменённый черновик модели с двумя полями заголовка прошёл проверку ресурсов в одноразовом комплекте. Изменение вложенного файла привело к отказу по хешу. В распакованном Desktop отдельно проверены зарезервированные имена и отказ загрузки изменённого комплекта.
- Независимое ревью ветки нашло шесть обязательных исправлений. Повторная проверка подтвердила их закрытие, включая проверку доступа к корню установленной папки перед обходом и отказ читать отдельный вложенный файл при явном запрете.

На исходной сборке нажатие «Отклонить» сохранило файлы прежней версии. До модели дошло сообщение `An error occurred in Effect.tryPromise`, поэтому она сочла результат техническим сбоем и снова запросила замену. ## Отказ от замены в установленном CLI

CLI `0.0.0-dev-202611251657` из чистого коммита `3436673533` установлен через `install.sh` под непривилегированным пользователем в Ubuntu 24.04 x64 с отдельными HOME и профилем. Манифест и SHA-256 архива проверены, установленный бинарник совпал с бинарником в архиве. В интерактивном TUI использована реальная модель `openai/gpt-5.6-sol`.

1. Первая версия `check-order-statuses` установилась после разового согласия. В контрольном CSV она отметила одну ошибку `102,HOLD`.
2. При попытке установить вторую версию отклонили замену через TUI. До завершения чата журнал CLI зарегистрировал ровно один запрос `skill_install` на замену. В истории сессии был один вызов установки v2 со штатной причиной отказа `The user rejected permission to use this specific tool call.`.
3. Следующее сообщение в том же чате загрузило `check-order-statuses`, заново прочитало `references/statuses.md` из `~/.agents/skills` и снова вернуло `102,HOLD`. SHA-256 обоих установленных файлов совпал до и после отказа.
