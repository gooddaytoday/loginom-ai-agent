## Диагностика Windows

Отдельная ветка `windows-proxy-diag`, commit `91369bfab2`,
[run38866284961](https://github.com/gooddaytoday/loginom-ai-agent/actions/runs/38866284961).
Диагностика оставила все assertions и timeouts, добавив удержание trap-соединения
до чтения Windows TCP owner. Оба CRL GET имеют User-Agent `Microsoft-CryptoAPI/10.0`;
владелец client-side socket — `C:\Windows\system32\svchost.exe`,
command line `-k NetworkService -p -s CryptSvc`, parent `services.exe`.
Положительный proxy control отдельно атрибутирован Chromium network process.
Таким образом, в диагностическом прогоне CRL-трафик принадлежит системной службе,
а действующий gate всё равно завершается FAIL. Product/runtime не менялись.
Лог диагностики хранится рядом с тремя исходными логами вне git.

Предлагаемое уточнение:учитывать эти два точных CRL GET отдельно только при
подтверждённом владельце CryptSvc и User-Agent CryptoAPI; неизвестный, Chromium
и иной трафик по-прежнему запрещён. Уточнение gate ещё не применено и требует
согласования владельца. Для выпуска0.2.1 с исправленным gate нужен новый source
и явное разрешение заменить существующий неопубликованный tag; tag пока не менялся.
Следующий шаг:согласовать эти исключения,проверить исправленный gate,полный CI,
сверку assets/manifests/SHA256SUMS и только затем публикацию.
Новая installed GUI/live Loginom/provider приёмка не выполнялась;
пользовательская установка и профили не заменяются.
