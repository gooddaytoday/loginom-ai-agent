# Аналитический пилот: пять новых пар D/B

Основание — [принятый план](../../superpowers/plans/2026-11-13-analytics-pilot.md).
Это канон только нового пилота. Прежние 65 legacy, все P01–P50, включая deferred,
и резерв R01–R08 остаются отдельными наборами. Отбор сопоставлен с их контрактами,
[каталогом направлений](../../superpowers/specs/2026-10-28-analytics-expansion-backlog.md)
и [каталогом идей](../../superpowers/specs/2026-10-28-analytics-expansion-blog-candidates.md).
Новизна ниже относится к механизму относительно legacy/P/R, а не к отсутствию
направления в исследовательском каталоге.

Статус на 13.11.2026: **selection APPROVE — независимое SPEC+QUALITY review**.
Приняты постановки A01–A05; обязательных замечаний нет. Это приёмка отбора,
а не готовых eval-пар. Reviewer подтвердил source, новизну, D/B parity,
закреплённые входы, независимость oracle и различимость содержательных ошибок.
Детальные контракты, искусственные fixtures, D/B-промпты, draft oracle и evidence
хранятся в закрытых drafts вне Git и runnable-коллекций. Reference не построены,
cold rerun, judge calibration и контрольные попытки не выполнялись.

В каждой паре одни входные байты, определения, схема, порядок строк, NULL policy,
oracle, допуск `0.000001` и rubric. Только D содержит вычислительный путь; B
содержит бизнес-вопрос и необходимые точные определения. Обе формы требуют
native LGP и ровно один полный CSV. Fixtures полностью искусственные, без
внешних сервисов и персональных данных.

Offline selection: все пять draft oracle дали различимые содержательные ошибки;
20/20 синтетических near-miss CSV отвергнуты существующим `compareCsv` при заданном
допуске. Это ещё не judge calibration: распознавание предметных ошибок по rubric
проверяется после появления reference. Источники native-пути — текущие handlers,
schemas и validators в `packages/loginom-runtime/client/lib/`, включая
`node-support.mjs`, `grouping-parameters.mjs`, `join-parameters.mjs` и
`calculator-parameters.mjs`. Статическая доступность не заменяет live-проверку.

Следующий этап — полный путь A01 после отдельного допуска координатора к live.
Затем обязателен first-pair review; остальные четыре начинаются после проверки
main path. Будущие runnable формы
размещаются в существующих `evals/tasks/analytic-detailed` и `analytic-business`.
Для A05 выполнен blind-B в отдельном чистом контексте с бизнес-контрактом и двумя CSV. Ответ зафиксирован до сравнения с oracle; штатный `compareCsv` подтвердил все пять строк при допуске `0.000001`, включая сервисы с нулевым числом запросов. Закрытые ответ и evidence сохранены у координатора. Это независимый расчёт постановки; native reference проверяется своим полным путём.

Автор: `openai/gpt-6.1-sol/xhigh`; контроль: `openai/gpt-6.1-terra/high`;
judge: `gpt-6.1-sol/xhigh`, без подмен. На пару до трёх авторских попыток по 1800s
с общим для D/B счётчиком; повтор только по конкретной исправляемой причине.
Контроль `parallel=1`, `repeat=1`, одна начатая попытка формы; порядок A01 D/B,
A02 B/D, A03 D/B, A04 B/D, A05 D/B. Обязательны одинаковые D/B pins, полные снимки
памяти до/после серии и журнал между формами; запущенные FAIL/NULL сохраняются.
Cold rerun требует нового полного CSV, исполнения всех ветвей без настройки/Save,
неизменного SHA LGP и `check-rerun` PASS. Positive обеих форм ≥90/oracle=true,
foreign другой задачи той же формы ≤40, near-miss с предметным `expected_failed`
и точным `expected_oracle_pass`. Калибровка, reference и измерения пока не зачтены.
