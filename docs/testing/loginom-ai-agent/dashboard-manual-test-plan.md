# Ручная приёмка дашбордов в Loginom AI Desktop и Studio

## Целевая связка

Принимать сборки из `dashboard-app@ea22cd3143`. В этой ветке Desktop с номером **0.3.9** поддерживает создание черновика по одноразовому снимку, редактирование готового дашборда, публикацию с явным подтверждением, повторное согласие при конфликте и удаление через чат. Оболочка Studio из той же ветки открывает первую готовую публикацию и меняет версию в уже открытом окне с сохранением параметров. Фиксы автообновления входят через `52549388b0` и `ea22cd3143`, удаление с исправлениями ревью — через `94adc7f0c3`. Номер `0.3.9` встречается у разных сборок. Тег `v0.3.10` этих изменений не содержит. Точный состав установленной связки тестировщика пока неизвестен.

## Общая подготовка и запись результатов

1. Подключите Desktop к тому же стенду, что открыт в Studio. Автору нужны чтение пакета и запись в его каталог. Для основного маршрута нужен рабочий профиль с доступной моделью. Для чтения и отказа записи заранее подготовьте отдельную роль. Для двух авторов используйте независимые профили Desktop и сессии Studio с правом записи в один тестовый каталог. Подойдёт одна тестовая учётная запись в независимых профилях, если стенд поддерживает такой вход.
2. Откройте совместимый `dashboard-demo-roi/campaign-roi.lgp`, **Модуль1 → Сценарий → «По убыванию ROI»**. Для записи используйте **«Сохранить как»** со свободным именем в тестовой папке с доступом к CSV. Дайте копиям различимые имена. Проверьте первый табличный выход и, для нового дашборда, кнопку **«Создать dashboard»**. Оператор фиксирует SHA-256 сохранённой копии `.lgp` после подготовки и после операций. Во время сравнения не сохраняйте изменения сценария. Для регрессий, меняющих саму фикстуру, подготовьте отдельные копии.
3. Проверьте входной CSV и условие `budget >= MinBudget` перед группировкой. Для эталонного [CSV](../../../dashboard/fixture/dataset.csv) расчёт по файлу подтвердил **0 → 500 кампаний, Email 109**, **10 000 → 453, Email 97**, **100 000 → 0 строк**. На выходе узла строки соответствуют каналам, до пяти строк. В **«Данных узла»** суммируйте `campaigns` по каналам и сравнивайте `campaigns` в строке Email. При отличии исходных данных зафиксируйте собственный эталон из штатного выхода узла или расчёта по CSV. Одного совпадения названия пакета мало.
4. Репозиторный `dashboard/fixture/campaign.lgp` сохранён в master 7.5. Для 7.4.2 возьмите подготовленный совместимый демопакет. При его отсутствии оператор может взять eval-эталон 7.4.2, настроить читаемый CSV, добавить числовой `MinBudget` с начальным `0` и фильтр перед группировкой, связав его с переменной через управляющий порт. Затем сверить три порога. [Фикстура master](../../../dashboard/fixture/README.md) · [Схема eval-эталона](../../../evals/tasks/analytic/campaign-roi-by-channel/SPEC.md) · [Происхождение eval-пакета](../../../evals/tasks/analytic/campaign-roi-by-channel/provenance.json)
5. В Studio применяйте `MinBudget`, вводя число без пробелов и щёлкая вне поля. Дождитесь окончания пересчёта, кроме шагов на очередь. Для сверки откройте **«Данные узла»**, затем вернитесь через **«К dashboard»**. Записывайте полную видимую метку **«Версия»** с временем UTC и заголовок приложения. Ниже **A** и **B** обозначают первую и следующую публикации. Для соседа используйте собственный узнаваемый заголовок и заранее запишите версию и контрольное значение.
6. После команды публикации запишите время подтверждения, ответ Desktop и момент смены версии в Studio. Открытое окно проверяет обновления примерно раз в три секунды, время сборки зависит от стенда. Через две минуты ожидания Desktop может сообщить, что готовность ещё не подтверждена. В этом случае сверьте состояние своей публикации с оператором и продолжите наблюдение в пределах согласованного окна стенда. Повторное подтверждение до выяснения результата первой записи затруднит диагностику.
7. Отмечайте **«Пройдено»**, **«Не пройдено»**, **«Заблокировано»** или **«Не применимо»**. Для каждого шага со сбоем сохраните номер сценария и шага, паспорт связки, пакет/узел, роль, введённый запрос или параметр, время, ожидаемое и фактическое состояние обоих приложений. Минимум — снимок места сбоя и предыдущее наблюдение, от которого можно повторить шаг. Если Studio и Desktop разошлись, приложите оба экрана с временем. Убирайте пароли, одноразовые ссылки, токены и приватные адреса. Действия с пометкой **«Нативно»** выполняет тестировщик в системном диалоге, окне Desktop или открывшемся локальном предпросмотре.

## Короткий обязательный прогон

### Д01. Создать → опубликовать → изменить в открытой Studio

**P0.** Риск — автор теряет привязку, видит неверные данные или вынужден заново открывать окно после публикации. **Подготовка.** Чистая тестовая копия ROI, `MinBudget=0`, у узла ещё нет дашборда, Desktop полностью закрыт.

1. **Studio.** Выберите «По убыванию ROI» и нажмите **«Создать dashboard»**. Если браузер задержал запуск, нажмите **«Открыть чат в Desktop»**. **Нативно** разрешите системное открытие, если есть диалог. Запускается нужный Desktop, в нём появляется чат выбранного узла. Страница Studio остаётся на экране с предложением продолжить в чате. Оставьте её открытой.
2. **Нативно, Desktop.** Отправьте «Создай дашборд “Кампании по каналам — A”. Покажи число кампаний для каждого канала и общий итог, суммируя поле `campaigns` из текущих данных. Покажи пустой результат при нуле строк. Собери черновик и дай ссылку». Откройте ссылку. Видны заголовок A, пять каналов, 500 кампаний и Email 109. Шапка черновика показывает нужный пакет, **«Данные: пример из 5 строк»** и время снимка. Поле `MinBudget` доступно для просмотра, пересчёт доступен после публикации. Таблица, график или карточки подходят, если числа и смысл различимы. Число строк образца и число кампаний — разные показатели.
3. **Нативно, Desktop.** Напишите «Опубликуй этот дашборд». Проверьте в запросе имя узла и путь тестовой копии. Нажмите **«Разрешить один раз»**. До согласия публикация не появляется. Пока сборка идёт, Studio по-прежнему предлагает переход в чат. После серверной готовности Desktop подтверждает публикацию, а открытая Studio сама показывает A с меткой версии. Для фиксации результата не обновляйте страницу и не перевыбирайте узел.
4. **Studio.** При `0` сравните итог и Email с «Данными узла». Установите `10000` и дождитесь пересчёта. В поле остаётся **10 000**, в данных и на дашборде **453 кампании, Email 97**. Запишите метку версии A.
5. **Studio → Desktop.** Нажмите **«Изменить в чате»** и при необходимости **«Открыть чат в Desktop»**. **Нативно** подтвердите системный переход, если требуется. В чате отправьте «Поменяй заголовок на “Кампании по каналам — B”. Сохрани общий итог и разрез по каналам. Собери черновик и дай ссылку». Проверьте новый заголовок и числа образца на момент снимка, **453 и 97**. Studio пока показывает A.
6. **Нативно, Desktop.** Напишите «Опубликуй этот дашборд», сверьте цель и разрешите один раз. Оставьте A открытой в Studio. Пока B собирается или загружается, пользователь видит A и её метку. Когда B готова на сервере и сама загрузилась, заголовок B и новая метка появляются вместе без действий в Studio. Поле сохраняет **10 000**, «Данные узла» и B дают **453 / 97**. Запишите обе метки и время переключения.
7. **Studio.** Нажмите **Esc**, вернитесь к схеме и снова нажмите **Dashboard** на том же узле. Открывается B, `MinBudget=10000` и результат **453 / 97** сохраняются в открытом пакете этой сессии. Откройте обычное представление результата узла из сценария и проверьте, что оно работает. Сопоставьте хеш копии `.lgp` с исходным.

**Свидетельство.** Экран черновика A с пакетом и снимком, запрос разового согласия, короткая запись переключения A → B без закрытия окна, итог после Esc и повторного открытия, значения и хеши из шагов 4–7.

## Расширенная регрессия

Проводите Д02–Д07 на обычном стенде. Для Д08 нужен второй автор. Д09–Д12 требуют выделенного стенда и согласованных точек отказа. Д13–Д14 используют отдельную копию под удаление. P0 означает прямой риск неправильных данных, записи или срыва основного маршрута, P1 — риск регрессии с существенным влиянием на работу.

### Обычный стенд, один автор

#### Д02. Пустой результат, возврат данных и очередь параметров

**P0.** Риск — прежние строки или ошибочный итог после пересчёта. **Подготовка.** Готовый ROI-дашборд на копии, видны итог и Email, доступно «Данные узла».

1. Пройдите `0 → 10000 → 100000 → 0`. Для каждого значения дождитесь расчёта и сверьте дашборд и таблицу. При `100000` таблица показывает **«Нет строк»**, дашборд сообщает о пустом результате. После возврата к `0` восстанавливаются пять каналов, **500 / 109**.
2. Откройте «Данные узла». Примените `100000`, а в ходе **«Идёт расчёт»** примените `10000`. Пока очередь обрабатывается, таблица показывает состояние расчёта. После завершения остаются `10000` и **453 / 97** в таблице и на дашборде. Подождите до следующего штатного обновления и убедитесь, что старый пустой ответ не вернулся. При слишком быстром узле повторите на замедляемой тестовой копии с тем же эталоном. Если два изменения в очереди увидеть не удалось, шаг 2 заблокирован.
3. Повторите пару значений и нажмите **Esc** во время расчёта. Схема открывается, очередь завершается. Повторный вход показывает последнее принятое значение и его строки.

**Свидетельство.** Четыре пары «значение / итог и Email», запись шага 2 с двумя применениями и конечным состоянием, результат после Esc в шаге 3.

#### Д03. Запущенный Desktop, отказ браузера, повтор и истечение снимка

**P1.** Риск — неверный чат или тупик при неудачном запуске. **Подготовка.** Desktop открыт в обычном чате, в Studio тестовый узел без публикации, браузер может спросить об открытии внешнего приложения.

1. Нажмите **«Создать dashboard»** и **нативно** отмените переход в системном диалоге. Studio остаётся доступной и показывает **«Открыть чат в Desktop»**. В Desktop продолжается прежний чат. Нажмите ссылку и **нативно** согласитесь. Открывается чат нужного узла в уже запущенном Desktop.
2. Нажмите **ту же** ссылку Studio второй раз и разрешите переход, если требуется. Desktop сообщает, что снимок уже использован, устарел или создан на другом стенде, и предлагает нажать кнопку в Studio ещё раз. Создание второго действующего черновика из этого снимка означает сбой. Закройте окно Studio через Esc и заново нажмите кнопку узла. Свежая ссылка работает.
3. На отдельном свежем снимке снова отмените системный переход. Оставьте окно Studio открытым минимум на **15 минут** с момента выдачи. Нажмите оставшуюся ссылку и разрешите запуск. Desktop показывает ту же подсказку. Новый клик по кнопке узла в Studio даёт рабочий снимок. Если исходный переход фактически состоялся или сервер перезапускался в ожидании, повторите шаг с контролируемыми условиями.

**Свидетельство.** Системная отмена и последующий успешный запуск, два отдельных отказа с отметками времени, успешное получение свежего снимка после каждого. При отсутствии диалога в этом браузере используйте согласованный профиль с запросом внешних ссылок или отметьте зависимые шаги заблокированными.

#### Д04. Свежий снимок, прежний черновик и перезапуск Desktop

**P1.** Риск — потеря неопубликованной правки или подмена снимка живыми данными. **Подготовка.** Копия ROI без публикации, черновик при `0` с заметным неопубликованным заголовком «Проверка сохранения».

1. Проверьте ссылку черновика и время снимка. Вернитесь к схеме и измените `MinBudget` в сценарии до `10000`. Пока свежий снимок не передан, исходный предпросмотр остаётся образцом от `0`.
2. Полностью закройте Desktop, затем из Studio снова нажмите **«Создать dashboard»** на том же узле. **Нативно** откройте Desktop в том же профиле, попросите «Собери сохранённый черновик без правок и дай ссылку» и откройте новый предпросмотр. Сохраняется «Проверка сохранения», метка снимка обновляется, образец соответствует **453 / 97**.
3. На отдельной опубликованной копии в исходном профиле через **«Изменить в чате»** измените заголовок на «Только в первом профиле» и оставьте правку в черновике. Подготовьте чистый профиль и снова нажмите **«Изменить в чате»** в Studio. **Нативно** попросите «Собери черновик из загруженных исходников без правок и дай ссылку». Оформление и заголовок соответствуют опубликованной версии. Заголовок «Только в первом профиле» отсутствует.
4. **Нативно, Desktop.** Из редактора нажмите **«+»** в панели вкладок. Должен открыться обычный пустой чат проекта с прежним подключением к Loginom. На подключении с поддержкой агентских инструментов Studio попросите «Открой тестовую копию пакета и прочитай первую строку выхода узла “По убыванию ROI”». Ответ сверяется со штатными данными узла. Исходная вкладка редактора и её содержимое сохраняются.

**Свидетельство.** Два времени снимка, один заголовок локального черновика и два результата, отметка о перезапуске, экран редактирования из чистого профиля и новый обычный чат.

#### Д05. Переключение на соседний узел и другой пакет

**P0.** Риск — запись по текущему выделению Studio вместо привязки чата. **Подготовка.** В тестовом пакете нужен целевой узел без публикации и сосед с готовой версией. Откройте второй тестовый пакет с узлом того же имени и собственной опубликованной версией. Запишите для обоих соседей метки, заголовки и числа.

1. Получите снимок целевого узла и откройте чат, как в Д01. Убедитесь, что в предпросмотре показан путь целевого пакета. Затем в Studio вернитесь к сценарию, выберите соседний узел и переключитесь на второй пакет.
2. **Нативно, Desktop.** В изначальном чате попросите заголовок «Только для целевого узла» и публикацию. В подтверждении проверьте исходные пакет и узел, затем разрешите один раз. При расхождении цели отмените и зафиксируйте шаг 2 как сбой.
3. После готовности в Studio откройте отдельно исходную цель, соседний узел и одноимённый узел второго пакета. Новый заголовок и новая метка есть только у цели. Соседи показывают прежние метки и контрольные значения. Сравните хеши обоих `.lgp`.

**Свидетельство.** Путь и узел в запросе Desktop и три результата Studio с метками, включая прежние значения соседей.

#### Д06. Отмена первой и повторной публикации

**P0.** Риск — запись без согласия или потеря черновика. **Подготовка.** Одна копия без публикации и одна с готовой A, в обеих есть отличимый черновик.

1. На каждой копии запросите публикацию и **нативно** нажмите **«Запретить»** в обычном диалоге. Черновик остаётся доступным с правкой. Desktop сообщает об отмене или отказе.
2. Studio без публикации оставляет ссылку на чат и после повторного выбора предлагает создать дашборд. Открытая A сохраняет заголовок, метку и работающий пересчёт. В перечне публикаций обеих копий нет новой записи.
3. На копии без публикации запросите её снова с явным согласием. Пока первая версия ещё не готова, нажмите **Esc** из экрана со ссылкой. Дождитесь готовности и снова выберите узел в Studio. Кнопка **Dashboard** открывает новую версию с живыми данными. Закрытое окно не открывается само.

**Свидетельство.** Отмены в Desktop, прежнее состояние обеих копий в Studio и перечень версий до/после отмены. Для шага 3 — схема после Esc и готовая версия после повторного входа.

#### Д07. Читатель, отказ записи и повторный вход в Studio

**P0.** Риск — потеря доступа к чтению или запись без прав. **Подготовка.** Публикация B на тестовой копии. Право читателя на пакет подтверждено, права записи в каталог нет. Для проверки публикации Desktop подключён с той же ролью.

1. Читатель открывает пакет в отдельной сессии Studio и нажимает **Dashboard**. Видны B, её метка и живые строки для текущего параметра. Откройте «Данные узла», затем схему. Проверьте, что обычный просмотр сценария доступен.
2. **Нативно, Desktop.** Из доступного читателю чата этого узла запросите публикацию отчётливо изменённого черновика. Если показано подтверждение — проверьте цель и разрешите один раз. Ожидается понятный отказ прав при открытии редактора или при записи, согласно фактической границе доступа. Для зачёта **отказа записи** нужен запрос, дошедший до проверки прав на публикацию. Если редактор закрыт для роли, фиксируйте отказ на входе и отдельно подготовьте профиль с доступом к редактору и без права записи. Версия B и число её публикаций сохраняются.
3. Закройте пакет без сохранения параметров и завершите сеанс Studio. Войдите снова и откройте B. Сравните с сохранённым параметром самого пакета, у чистой ROI-копии это `0`. Откройте результат узла штатным способом. Сравните хеш исходной копии `.lgp` после проверки.

**Свидетельство.** Роль и права, B у читателя, видимый отказ на конкретном шаге, перечень версий, экран после повторного входа и хеш копии.

### Два профиля автора на одной тестовой копии

#### Д08. Конфликт до подтверждения и между подтверждением и записью

**P0.** Риск — устаревшее согласие перезаписывает чужой результат. **Подготовка.** У узла нет публикаций. Два автора через **«Создать dashboard»** подготавливают разные локальные черновики в своих профилях. Первый сохраняет свой черновик без публикации. Откройте Studio для наблюдения за готовой версией. Маркеры авторов — «Черновик первого», «Версия второго B» и «Версия второго C».

1. Второй автор публикует B. Первый из ранее начатого черновика просит публикацию. **Нативно** проверьте, что запрос показывает пакет, узел и версию B с вариантами **«Опубликовать мою версию»** и **«Отмена»**. Отмените. В Studio остаётся B, в Desktop остаётся черновик первого.
2. Первый запрашивает публикацию заново и оставляет подтверждение B открытым. Второй публикует C. Дождитесь C в Studio. Первый нажимает **«Опубликовать мою версию»** в старом окне. Desktop сообщает о смене версии и требует нового согласия. В Studio видна C, файла публикации первого автора ещё нет.
3. Если запрос не появился сам, первый снова вводит «Опубликуй этот дашборд». Убедитесь, что теперь показывается C. Подтвердите. После готовности Studio показывает «Черновик первого» с новой меткой, данные соответствуют текущему параметру.

**Свидетельство.** Запрос для B, отмена, C в Studio, отказ по старому запросу и новое согласие для C. Сопоставьте версии и время с перечнем записей тестового узла.

### Выделенный стенд для отказов и специальных данных

#### Д09. Серверная сборка завершается ошибкой

**P0.** Риск — публикация объявлена готовой при неудачной сборке, рабочая версия пропала. **Подготовка.** Две копии как в Д06. Выберите установку без чужих задач. Оператор временно задаёт только контейнеру сборщика `DASHBOARD_TEMPLATE` с путём к отсутствующему каталогу и перезапускает его на том же образе с теми же томами. Издатель, Studio и готовые сборки доступны. Подойдёт и другая подтверждённая оператором точка отказа серверной сборки после записи.

1. На каждой копии проверьте рабочий предпросмотр, затем **нативно** подтвердите публикацию. Пока сборка идёт, Studio показывает ссылку на чат для первой публикации и A с её меткой для повторной.
2. Дождитесь серверного статуса ошибки. В Desktop ожидается сообщение **«Сборка на стенде не удалась»**, черновик доступен. Если до результата истекло окно ожидания Desktop, возможен ответ о неподтверждённой готовности, а ошибку отдельно подтвердите по Studio. В Studio **«Новая публикация … не собрана»** появляется рядом со ссылкой на чат при первой публикации, при повторной A остаётся рабочей с сообщением о сбое. Новая метка не заменяет A.
3. Оператор возвращает штатное значение `DASHBOARD_TEMPLATE` и перезапускает сборщик. **Нативно** снова запросите и подтвердите публикацию. Studio открывает новую готовую версию без обновления страницы, сообщение об ошибке исчезает. Для отдельной проверки локального отказа нужен черновик с невалидными исходниками. Запись на стенде не начинается и Studio не сообщает о серверной ошибке этой попытки.

**Свидетельство.** Для обеих копий запишите подтверждение, ошибку Desktop/Studio и серверный статус своей версии, затем экран восстановленной версии. Локальная ошибка сборки не заменяет шаги 1–3.

#### Д10. Новая версия готова, но Studio временно не может её загрузить

**P0.** Риск — при сбое загрузки теряются A, параметры или автоматическое восстановление. **Подготовка.** В Studio открыта A при `MinBudget=0`. Оператор готовит временный HTTP 503 на документ новой версии B по маршруту `/apps/<ключ>/<хеш-сборки>/`, с доступными Studio, опросом версий и уже загруженной A. Для ручной разновидности допустима блокировка маршрута приложения в DevTools отдельной вкладки после загрузки A, до готовности B. Запишите, был ли это 503 или блокировка браузером.

1. Включите отказ, **нативно** подтвердите публикацию B. Дождитесь подтверждения серверной готовности и зафиксируйте неуспешную загрузку B со стороны браузера. Studio продолжает показывать A с её меткой. Сообщение об ошибке поверх A для этого отказа не обязательно.
2. Пока отказ действует, примените `10000` в A и откройте «Данные узла». После пересчёта должны отобразиться **453 / 97** в таблице и на A.
3. Снимите отказ. Не закрывая дашборд и не обновляя страницу, дождитесь повторной загрузки. Studio переключает приложение и метку на B, оставляя **10 000** и **453 / 97**. Нажмите Esc и снова откройте B.

**Свидетельство.** Ответ браузера на новую версию, одновременно готовая B в Desktop и A в Studio, пересчёт на A, затем B с тем же значением без перезагрузки.

#### Д11. Ошибка первоначальной загрузки и ошибка расчёта

**P1.** Риск — пустые, старые или недоступные данные выглядят одинаково. **Подготовка.** Выделенная копия с опубликованной версией. Оператор может временно заблокировать документ приложения и отдельно вызвать обратимый сбой выполнения узла, например временно сделать недоступным CSV отдельной копии.

1. При заблокированном документе откройте готовый дашборд из схемы. Studio переходит от **«Открываем dashboard…»** к **«Dashboard не ответил»**, когда приложение не сигнализирует о готовности. Восстановите доступ, нажмите Esc и заново откройте его. Появляются метка и живые данные. Для первой загрузки этой уже опубликованной версии допускается повторный вход.
2. Со снятой блокировкой приложения откройте «Данные узла», вызовите сбой узла и примените другой параметр. Studio показывает **«Идёт расчёт»**, затем ошибку без подстановки прежних строк или сообщения **«Нет строк»**. Нажатие **«Изменить в чате»** при ошибке расчёта объясняет, что нужно исправить сценарий и повторить действие. Нового пригодного снимка с прежними строками не появляется.
3. Восстановите источник и примените другое значение либо заново выполните узел. Сверьте строки с эталоном. Повторите **«Изменить в чате»** и **нативно** проверьте, что Desktop получает актуальный снимок.
4. На отдельной копии опубликуйте приложение, использующее `campaigns`. В Studio переименуйте это поле на выходе тестового узла в `campaign_count`, оставив числа прежними. Выполните узел и откройте дашборд. Он сообщает о пропавшем поле и убирает зависимые показатели, а «Данные узла» показывают новое поле. В **«Изменить в чате»** попросите «Обнови дашборд для поля `campaign_count` вместо `campaigns`, сохрани разрез по каналам и общий итог». **Нативно** проверьте черновик и подтвердите публикацию. Новая версия в Studio показывает правильные числа.

**Свидетельство.** Сообщение о недоступном приложении, ошибка узла при конкретном параметре, сообщение о пропавшем поле и рабочие результаты после каждого восстановления.

#### Д12. Образец, ограничение строк и длинных значений

**P1.** Риск — частичный результат выглядит как полный или пустой. **Подготовка.** На отдельном пакете нужны два табличных выхода с известным результатом. В одном 10 001 короткая строка с последовательными ID, в другом несколько строк с одной текстовой ячейкой длиной 10 001 знак. Для первого задайте дашборд, который показывает число полученных строк и подписывает итог по полученной части при усечении.

1. Из узла с ID откройте черновик. **Нативно** проверьте, что в Desktop по снимку доступно до **100 строк** и что итог помечен как образец. Этот образец дополнительно ограничен **512 КиБ**. Опубликуйте с разовым согласием.
2. В Studio откройте опубликованную версию. При коротких строках ожидается **«Строк получено 10000 из 10001»**. В «Данных узла» проверьте **«Далее»**, **«Назад»** и крайние страницы. После **«К dashboard»** итог по показанной части явно обозначен. Полное число строк доказывает штатный выход узла.
3. На узле с длинной ячейкой откройте дашборд. Ожидается **«Некоторые значения укорочены»** при сохранении числа строк. Сравните длинное значение со штатным выходом. Состояние отличается от пустого результата Д02.

**Свидетельство.** Размер образца, полное число из штатного выхода, обе подписи Studio и страницы таблицы. Короткие ID изолируют лимит по строкам от суммарного лимита размера.

### Тестовая копия для удаления

#### Д13. Отмена и полное удаление выбранного дашборда

**P0.** Риск — удаление без согласия, потеря чужих данных или действующая старая ссылка. **Подготовка.** У цели две публикации, изменённый локальный черновик с открытым предпросмотром и известная версия у соседа. Оператор записал перечень версий и хеш `.lgp`.

1. **Нативно, Desktop.** В чате цели напишите «Удали дашборд этого узла вместе с его опубликованными версиями и локальным черновиком». В запросе видны пакет, узел, число версий **2** и предупреждение о локальном черновике и неопубликованных правках. Нажмите **«Отмена»**. Оба файла публикаций и черновик сохраняются, Studio открывает прежнюю версию цели и соседа.
2. Повторите запрос и нажмите **«Удалить»** после сверки той же цели. Desktop подтверждает завершение, старый предпросмотр перестаёт открываться, история чата с результатом остаётся. После штатного обхода издателя заново выберите цель в Studio. Появляется **«Создать dashboard»**. Проверьте, что у цели больше нет публикаций.
3. Откройте дашборд соседа и сравните версию и строки. Сравните хеш `.lgp`. Новый переход из Studio на цель открывает чистый черновик, старый чат не позволяет дописать в новый черновик. На этом чистом черновике можно повторить запрос удаления с числом **0** и отменить, проверив необходимость нового согласия.

**Свидетельство.** Диалог отмены и подтверждения, прежний и новый предпросмотры без раскрытия URL, состояние Studio для цели и соседа, перечень версий и хеш `.lgp`.

#### Д14. Частичное удаление и повтор с проверкой остатка

**P0.** Риск — ложный успех, исчезновение черновика или удаление непредъявленных версий. **Подготовка.** Отдельная копия как в Д13, обе версии были успешно собраны. Оператор может подтвердить удаление первой версии и остановить вторую операцию на FileStorage, оставляя повторное чтение каталога доступным.

1. **Нативно** подтвердите удаление двух версий. В контрольной точке оператор вызывает отказ второй операции. Desktop сообщает о частичном результате и подтверждённом числе удалённых версий. Локальный черновик и его предпросмотр сохраняются. После обхода издателя заново откройте цель и проверьте метку оставшейся готовой версии и состояние соседа. По перечню файлов проверьте, что одна версия удалена, другая осталась.
2. Снимите отказ. Запросите удаление снова. Подтверждение показывает оставшийся набор, в этой постановке одну версию. Нажмите **«Отмена»** и проверьте сохранность. Запросите вновь и подтвердите. У цели всё удалено, прежний предпросмотр остановлен, Studio предлагает создать дашборд. Сосед и `.lgp` сохранены.

**Свидетельство.** Записи версии до отказа, после отказа, после отмены и после завершения. Приложите текст Desktop об исходе и результаты просмотра соседа. Полный отказ прав до первого удаления покрывает другой случай. Без управляемой точки остановки отметьте Д14 заблокированным.

## Ограничения и решение о выпуске

- **Блокировка связки** — нет артефакта или подтверждения его состава, права или лицензия стенда мешают открыть тестовую копию, недоступна модель, браузер не может открыть нужный Desktop, отсутствует совместимая фикстура. Запишите точный шаг и условие возобновления. Если при подтверждённых предусловиях ломается штатный запуск или открытие, это дефект кандидата. Передача ссылки аргументом пригодна для диагностики, системный переход остаётся отдельной проверкой.
- **Блокировка отдельного сценария** — невозможно подключить вторую сессию к той же копии, подтвердить роль с чтением без записи, воспроизвести очередь или изолировать сбой сборки, загрузки либо частичного удаления. Отметку **«Не применимо»** используйте только для поставки, из состава которой документированно исключили функцию. Для выбранного SHA удаление и автообновление входят в объём.
- **Пробелы** — этот план проверяет работу установленного Dashboard через Desktop и Studio. В Д12 не воспроизводится крайний случай, когда из непустого результата не передано ни одной строки из-за суммарного размера. Для него требуется отдельная широкая фикстура, ожидаемое состояние — «Итоги недоступны». Полная приёмка установщика, обновления и отката пакетов, общий аудит изоляции, standalone CLI и матрица ОС/браузеров идут по своим runbook. Для выпуска со строгим HTTPS выполните Д01, Д07 и Д10 в этом режиме на заявленной связке. Остальные режимы учитывайте по факту прогона. [M5](dashboard-m5.md) · [M6](dashboard-m6.md) · [Изоляция](../../security/dashboard-isolation.md)
- **Предлагаемый критерий выпуска** — Д01 и все применимые P0 подтверждены на точном установленном кандидате в заявленном режиме. Управляемый отказ можно воспроизводить на выделенной установке того же кандидата. Для остальных случаев есть результат либо принятое ограничение с указанием риска. PASS от исходников, другого SHA или стенда с прежней оболочкой не закрывает установленный прогон. Для заблокированного P0 нужна повторная проверка после снятия блокировки.
- **Остановить выпуск** при неверной привязке, потере рабочей версии или черновика, изменении `.lgp`, публикации либо удалении без актуального согласия или прав, ложном сообщении об успехе, неверных/устаревших данных, потере принятого параметра при A → B, срыве автоматического открытия или восстановления на целевой связке, невозможности читать дашборд с положенными правами или вернуться к сценарию. Запишите первый нарушенный шаг и соберите свидетельство до повторной операции.
