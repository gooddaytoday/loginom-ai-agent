## Реестр причин и исправлений

### D-F01 и D-F03 — бюджеты настройки и чтения

D45 baseline: configure_ms=120000 истёк 2026-09-21 17:18:32.249 UTC. `execute_wizard` начался 17:18:30.867 и вернулся SUCCEEDED 17:18:32.438, но следующий read-back не стартовал. D65 baseline: исполнение завершилось 18:42:12.415 UTC; общий deadline наступил 18:43:35.763, MCP timeout — 18:43:35.765. Точное чтение и восстановление форматов двадцати полей не уложились в оставшиеся 83 секунды. Сетевой сбой не подтверждён. Операция `abc-key-items-001` осталась неопределённой в read после completed execution.

Исправление: defaults настройки/исполнения/всей операции — 300000/120000/600000 ms, с учётом точного чтения и cleanup. Целевой D45 на `.11` показал, что модель продолжала задавать configure_ms=120000. Поэтому compact user-v1 больше не принимает технические budgets: их задаёт приложение. Полный диагностический контракт с явными неизменяемыми сроками сохранён. Существующие pending/deadlines не продлеваются. Предел отдельного `node_wait` 60000 ms явно указан в описании; прежние ошибки запросов wait модель исправляла сама.

Изменения: `658b8ab953232164c9f28534e39b2990c0c85547`, затем `c643db47657f6644b167d27dbaa0dec269e769c4`. ### D-F08 — короткий заданный моделью срок дополнительного чтения

D65-final15 построил и выполнил семь узлов. Ошибку формулы модель исправила на том же retained Calculator через подтверждённое восстановление настроек (FAILED с cleanup=true), без помощи человека.
