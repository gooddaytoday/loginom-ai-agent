Parent root-origin boundary (CODE/OFFLINE)

The fixed standalone run producer mints one frozen origin alongside its original
control, before profile/startup awaits. The original signal and absolute deadline
remain in the parent private WeakMap; no wire field or serialized copy grants
membership. Sorting forwards the same control through its fixed launcher.

The Node launcher checks live admission before fork, binds the actual child PID
and port before startup dispatch, and refuses a second child for that control.
After fork, identity binding itself permits expired/aborted originals so the
actual host handle can reach existing cleanup. SDK admission checks the original
abort reason first, then deadline, retained child/port descriptors and identity.
No new controller, budget or timer is created.

ChildProcess.connected is an own data slot on Node and an inherited native
accessor on Bun. The private producer retains its descriptor and owner/prototype
chain without calling the accessor. Data-slot false and descriptor/chain drift
refuse; transport remains responsible for liveness. This is custody of the
actual producer-created child, not generic getter permission or native authority.

SDK owner/lease guards now include this binding. Ports from older ordinary paths
keep existing behavior without acquiring origin qualification. Release/capture,
finally, startup policy and terminal component authority remain unchanged.

This cut does not transfer origin through IPC, bind managed message/handle task/
per-call controller, register H0 invocation, or qualify loaded native closures.
Those remain next predicates. Fixtures use real Node fork/FS/AbortController;
child protocol responses and Page/native/session are doubles. All terminal
native/content/persistence/cleanup authorities remain false.
