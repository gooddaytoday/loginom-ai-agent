## Scoped mkdel calls

Before creation the capsule retains the original `ss.mkdel` function object and its descriptor/prototype guards. During each of the four retained storage methods only, an owned temporary overlay observes that method's actual `ss.mkdel(this, delegate)` invocation. It requires the same `ss` namespace, exact precreation FileStorage, current storage invocation and one call. It invokes the retained original once with unchanged arguments and returns its exact function result. The call and successful completion receipts are frozen; delegate and returned-function prototypes remain guarded through the pending continuation.

The dispatch receipt requires that exact mkdel call/completion and carries their original refs only inside the capsule. The call has `mkdelIdentityQualified: true` scoped to `FileStorage.<method>:mkdel`. This observes the selected dynamic lookup/call and receiver, not the delegate's hidden lexical environment. Both delegate receipts and the overall result retain `closureIdentityQualified: false` and broad `nativeReceiversQualified: false`. Existing task/source/reader guards and raw-first-error behavior remain in force; own overlays restore exactly and foreign descriptors are never overwritten.

Targeted `storage mkdel` controls cover four original-method calls on the packet/control route; same-VM pinned mscorlib/Task; pre-call method/accessor/prototype refusal; explicitly labelled reentrant negative calls with foreign receiver/namespace or a repeat; pending delegate/returned-function/mkdel drift; and six raw-first-rejection cases. Native Loginom, session, Page, SDK and dispatch task remain doubles. Stock H0 and `NATIVE_LEXICAL_QUALIFICATION_MISSING` are unchanged. Closed suites are not rerun.
