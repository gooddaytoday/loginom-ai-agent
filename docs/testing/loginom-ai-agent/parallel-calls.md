# Параллельные команды Loginom: исправление от 2026-09-21

Последующее применение: локально собрана и установлена macOS-версия
`0.1.7-local.20260921.1`; [отчёт установки](reports/2026-09-21-local-macos/report.md).
Ниже сохранены результаты исходной проверки до сборки.

## Причина

В установленном Desktop 0.1.6 запрос описания узлов поступил через 108 мс после начала
загрузки CSV, пока загрузка ещё выполнялась. Managed runtime отклонил второй вызов
с `LOGINOM_REQUEST_INVALID`, поскольку допускает один активный вызов. HostPort уже
создал запись журнала и преобразовал отказ в `LOGINOM_CALL_UNCERTAIN`, переведя
активные записи в восстановление. Последующие команды получили
`LOGINOM_RECOVERY_REQUIRED`, хотя сама загрузка завершилась успешно.

## Изменение

- Общий адаптер Desktop/CLI выполняет вызовы одного run последовательно. Ожидание
  очереди не расходует таймаут транспорта и не создаёт записи восстановления.
- Отменённый ожидающий вызов не прерывает активный. Освобождение run запрещает
  запуск ожидающих вызовов. Разные чаты сохраняют независимое выполнение.
- HostPort дополнительно отклоняет конкурентный вызов до создания записи журнала:
  `LOGINOM_CALL_BUSY`. Он не меняет журнал и владение активной операции.
- Настоящая неопределённость сохраняет прежнюю блокировку восстановления. Прерывание
  активной команды проходит вне очереди. Автоматического повтора операций нет.

## Проверено

Использованы Bun 1.3.14 и установленный bundled Node 24.19.0 на macOS arm64.

До исправления новый регрессионный тест `complete` воспроизвёл
`LOGINOM_CALL_UNCERTAIN` при удерживаемой загрузке и конкурентных запросах.

После исправления:

- 18 тестов Host: `parallel-calls`, `host-port`, `recovery`, `transport`.
- 35 тестов Desktop: `src/main/loginom`.
- `bun typecheck` из `packages/loginom-host` и `packages/desktop`.
- Реальный managed runtime и Loginom: одновременно отправлены загрузка тестового
  CSV и `dock_action_describe`; обе команды успешны, SHA-256 загруженного файла
  совпал, журнал восстановления пуст. Затем выполнен импорт, сохранён пакет;
  receipt подтвердил закрытие пакета, logout и отсутствие отброшенных изменений.

Live-проверка использовала **изменённые исходники адаптера и HostPort** и ресурсы
установленного 0.1.6. Это проверка общей связки Host/runtime, а не приёмка нового
собранного Desktop или исполнения команды через модель.

Успешный локальный протокол:
`/var/folders/d0/pcsq9b9j1pvgy1vd9mp9l61w0000gn/T/loginom-parallel-live-QWUvKF/summary.json`.
Диагностические receipts и конфигурация остаются вне Git.

Первый live-прогон подтвердил исправление очереди, но тест попытался сохранить
пустой пакет прямо из вкладки хранилища и получил no-effect отказ
`Active workflow has no verified cached package identity`. Cleanup receipt:
`BLOCKED / CONFIRMED_SAVE_REQUIRED`. Во втором прогоне добавлен штатный импорт,
который возвращает рабочий сценарий перед сохранением. Первый протокол сохранён
отдельно в `loginom-parallel-live-96fzqp`; он не считается полной приёмкой.

## Повторение live-проверки

Из `packages/loginom-host`, закреплённым Bun:

```sh
LOGINOM_AI_AGENT_TEST_CONFIG=/absolute/private/acceptance-config.json \
LOGINOM_AI_AGENT_TEST_RESOURCES=/absolute/bundled/loginom \
bun script/parallel-calls-live.ts
```

Конфигурация совместима с существующим `runtime-acceptance.ts`: `api_key`,
`loginom_url`, `workflow_profile.loginom_user`, `workflow_profile.passwordless_login=true`.
Нужен разрешённый тестовый аккаунт. Скрипт создаёт приватный временный профиль,
тестовый CSV и уникальный пакет в папке аккаунта; закрывает пакет и выходит через
существующий acceptance cleanup runtime. Сохранённые тестовые файлы не удаляет.

## Ограничения применения

С 2026-09-23 мягкий режим по умолчанию снимает замок `LOGINOM_RECOVERY_REQUIRED`
после неопределённой операции. Очередь параллельных вызовов и `LOGINOM_CALL_BUSY`
не изменились. Строгий журнал включается только `LOGINOM_AI_AGENT_STRICT_RECOVERY=1`
у CLI. Эта запись не отменяет результаты проверки 2026-09-21.

Установленное приложение 0.1.6 не заменено. Для применения исправления в GUI нужна
новая сборка и установка. Исходная пользовательская задача и её записи
восстановления не изменены; исправление не является разрешением на автоматический
повтор старых неопределённых операций. Полный ABC-анализ этим прогоном не проверялся.
