## Эталоны p1–p8

Каждый `expected-demo.json` получается из собственного независимого oracle.
Формат: `export_input` и обязательный `export_destination`; проверка — вызов
`parseExpectedOutputs` из `scripts/node-acceptance/expected-outputs.mjs`.
Образец структуры — [n1 expected](../../../n1/expected-demo.json),
но его строгие требования не переносить в короткие просьбы автоматически.

Фиксировать только требования просьбы и данных. Для свободных меток применять
`label_any: true`, для свободного порядка колонок — `column_order: any`,
строк — `ordered: false`. Поле `name` остаётся обязательным в текущем формате;
`label_any` не позволяет произвольные имена. Не заявлять проверку свободы,
которую текущий matcher не выражает, и не менять оснастку ради этой поставки.

В README задачи перечислить обязательный результат, допустимые варианты,
числовые допуски и пределы статического сравнения. Путь экспорта описать
как часть просьбы или операторского окружения, без скрытых бизнес-условий.
Полный контракт — [раздел 3 подплана](../../../short-plan.md#3-oracle-и-свободные-варианты-ответа).

## Дополнение p9–p16 / D7f

Восемь новых expected с `export_input`, `export_destination`, свободными метками,
порядком колонок и строк. Новые имена прямо заданы короткими просьбами;
номер кластера и отдельная схема коэффициентов не навязываются.
`TotalPollen` в p15 — real, тип суммы Группировки; count — integer.
Real: допуск `max(1e-8, 1e-10 × |expected|)`. HTTP: только Code, Route,
Method, HttpStatusCode; все подписи свободны через `label_any`.
Excel: первый лист, явные Id integer / Gallery string / Weight real.
Смена числового типа по-прежнему требует операторского разбора.
