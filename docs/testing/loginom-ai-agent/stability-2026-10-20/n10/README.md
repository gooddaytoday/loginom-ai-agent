## Энергопотребление макета цеха

Модели: [prompt.md](prompt.md), [energy.csv](data/energy.csv).
Оператору: [generate.py](generate.py), [oracle.py](oracle.py), [expected-demo.json](expected-demo.json).
Ожидаемое сочетание: импорт → Линейная регрессия → экспорт `energy-forecast.csv`.
Генератор `generate.py`, seed **101022**; перемешанный порядок входа не задаёт порядок вывода.

20 строк — полная сетка X = 1…5, Z = 1…4; Y — энергия с погрешностью ±0.5 кВт·ч.
X и Z независимы, остаток ортогонален константе и обоим признакам.
Коэффициенты: константа 12, X = 2, Z = −0.75. Итог: 20 прогнозов, 3 коэффициента.
X, Z, Y — real; RowID — integer.

Oracle решает нормальные уравнения МНК методом Гаусса–Жордана в точной арифметике
`Fraction`; каждый ненулевой pivot проверяет полный ранг, также проверяется
ортогональность остатков всем столбцам матрицы. Все строки после отбора — обучение,
со свободным членом, без регуляризации, стандартизации и тестовой выборки.
Эталон содержит полную таблицу прогнозов перед экспортом и таблицу коэффициентов
на выходе 1 `datamining.lin_regression`. Порядок прогнозов — RowID по возрастанию;
колонки и их подписи точно заданы просьбой. Forecast и исходные числовые поля — real.
Порядок коэффициентов и их колонок свободный: `Name` (string),
`Y_coefficients` (real); Name содержит `<Константа>` и имена признаков.
Автоматические подписи коэффициентов просьбой не заданы: `label_any: true`.
Для всех real, включая коэффициенты и прогнозы, абсолютный допуск 1e-8,
относительный 1e-10; сравнение по `max(abs, rel × |expected|)`.

CSV: UTF-8 без BOM, LF, заголовок, запятая, точка в числах; пропусков нет.
Данные полностью синтетические, без персональных данных. Модели передавать только
просьбу и входной CSV; oracle, expected и README остаются у оператора.

Воспроизведение из корня репозитория (Python 3, стандартная библиотека):

```sh
D7_CASE=docs/testing/loginom-ai-agent/stability-2026-10-20/n10
python3 -B "$D7_CASE/generate.py"
python3 -B "$D7_CASE/oracle.py" > ./d7-rebuilt.json
cmp "$D7_CASE/expected-demo.json" ./d7-rebuilt.json
D7_ABS=$(realpath "$D7_CASE")
(cd / && python3 -B "$D7_ABS/oracle.py") > ./d7-other-cwd.json
cmp "$D7_CASE/expected-demo.json" ./d7-other-cwd.json
python3 -B "$D7_CASE/oracle.py" '/<username>/d7-n10-<run-id>.lgp' > ./d7-run-expected.json
```

Один позиционный аргумент меняет только `package_path`; по умолчанию используется
пример `/stability-2026-10-20/n10.lgp`. Oracle читает только CSV относительно
`__file__`, не генератор, expected, результаты Loginom или сеть. Проверка формата
через `parseExpectedOutputs` и правила будущего прогона — в [общем README](../README.md).
Временные JSON не коммитить. `nodes` проверяет наличие основных типов, не топологию.
`export_input` проверяет таблицу перед экспортом, а не байты файла или факт сохранения.
Статический расчёт не подтверждает выполнение, экспорт, сохранение или cold-check.
