## p18: короткий вариант s2-customers

Модели: только [просьба](prompt.md) и [customers.csv](data/customers.csv). Это самостоятельная просьба вместо исходного prompt s2.

Просьба содержит **19 слов** (разделение по пробельным символам), одну
неточность — опечатку **clent_code → client_code**. В customers.csv есть только один код клиента, client_code; пропущена буква i. Образец C-NNN однозначно задаёт обрезку пробелов, верхний регистр C и дефис перед тремя цифрами.
Других намеренных неточностей нет; формат CSV явно задан расширением файла.

Верный бизнес-результат: 8 строк status=active в исходном порядке; Code/Name/CreditLimit/Status, CreditLimit числовой. Нулевой лимит сохраняется; преобразование кодов совпадает со всеми девятью заменами s2.

Данные и [oracle](oracle.py) побайтно совпадают с [исходным s2-customers](../../demo-2026-10-22/s2-customers/README.md)
на SHA `9f2d305e32e841d206bf8d04d25ebd039156cd29`.
Входы: [customers.csv](data/customers.csv). Новые данные и генератор не создаются.
Oracle побайтно воспроизводит [expected.json](expected.json). Демо-эталон имеет другой набор обязательных узлов и селектор выхода; stdout oracle не подменяет его. [Демо-эталон](expected-demo.json) также скопирован без изменений.

Короткая просьба проверяет сохранение бизнес-смысла, а техническая схема
исходного эталона (имена/подписи, integer/real, обязательные типы узлов) сохранена
по заданию LAB-119. Эти ограничения не объявляются свободными и не доказываются
одной краткой фразой; альтернативная схема требует операторской оценки.
Порядок строк проверяется только там, где он задан сценарием.

Воспроизведение: `python3 -B oracle.py` из этого каталога; необязательный аргумент
меняет только `package_path`. Значение по умолчанию остаётся путём исходного s-сценария.
[Общая проверка p17–p24](../README.md#lab-119-короткие-варианты-p17-p24) описывает
сравнение с эталонами. Это статический PASS расчёта, не модельный/native/cold PASS.
Модели oracle, expected и README не передавать.
