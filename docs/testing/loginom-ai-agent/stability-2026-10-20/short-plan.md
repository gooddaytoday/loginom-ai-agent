## 1. Состав и просьбы

Создать p1–p8. В каждом: `prompt.md`, `data/*.csv`, генератор с seed,
независимый `oracle.py`, `expected-demo.json` с `export_destination`, README.
Просьба — 1–2 фразы живой речью, без названий узлов, типов полей, инструментов
и инструкций о способе построения. Не превращать её в полное ТЗ ради эталона.
README объясняет, что считается верным результатом и какие варианты допустимы.

Разрешены только уже поддержанные в `demo-022` узлы: импорт CSV, фильтр,
калькулятор, группировка, сортировка, слияние, замена, кросс-таблица,
кластеризация, линейная регрессия, экспорт. Наличие других узлов в D7
не расширяет этот список. В 2–3 задачах нужны 2+ последовательных узла
обработки; импорт и экспорт сами по себе это требование не закрывают.

Предметные области должны различаться и не повторять s1–s6 и n1–n12.
Для сверки: s1–s6 — выручка, очистка клиентов, долги заказов, филиалы,
затраты по категориям, товарный ABC; n1–n6 — дефицит запасов, выплаты курьерам,
тарифы доставки, коммунальные расходы, простои, обучение.
В D7b n7–n12 — пункты выдачи, режимы стенда, упаковка, энергия,
HTTP-отражение, чистый расход партий. D7b находится в
[PR #138](https://github.com/gooddaytoday/loginom-ai-agent/pull/138);
в исходный SHA этой карточки ещё не входит. Его не копировать и не ждать
для начала документальной работы.

## 2. Данные

Каждая задача получает синтетические CSV по 10–40 строк данных и генератор
с фиксированным seed. Генератор должен воспроизводить записанные CSV побайтно.
Формат: UTF-8 без BOM, заголовок, запятая, точка в числах, без персональных
данных. В README описать схему, единицы и команду генерации.
Данные должны делать бизнес-смысл понятным из короткой просьбы: скрытые
правила из README не становятся обязательными требованиями к модели.
Подробнее: [данные](acceptance/short/data/README.md).

## 3. Oracle и свободные варианты ответа

Сначала просьба и данные, затем независимый расчёт и expected. Oracle читает
только свои CSV, использует стандартную библиотеку Python, пути относительно
`__file__`; не читает expected, пакет, модельный результат или сеть.
Без аргумента stdout побайтно совпадает с `expected-demo.json`; аргумент пути
пакета меняет только `package_path`. Числовые приближения имеют явный допуск.

Фиксировать только то, что однозначно следует из просьбы и данных. Не заданные
просьбой имена и порядок колонок, метки и порядок строк не превращать
в обязательные условия. Применять существующие `label_any: true`,
`column_order: any` и `ordered: false`, где соответствующее свойство свободно.
`label_any` освобождает метку, но не имя поля: не выдавать его за wildcard
для имён. Не копировать из подробных n-задач строгие схемы без обоснования.
Выбирать задачи и форму ожидаемого результата, позволяющие выразить эту свободу
существующим форматом. Невыразимое условие не считать проверенным и не заменять
жёстким именем; продукт и matcher в этой карточке не расширять.

Все expected содержат `export_destination`, используют `export_input`
и принимаются существующим `parseExpectedOutputs`. README объясняет назначение
пути экспорта и какие его части заданы просьбой или окружением будущего запуска;
служебный путь не должен маскировать дополнительное бизнес-требование.
Правила: [expected](acceptance/short/expected/README.md),
[oracle](acceptance/short/oracle/README.md).

## 4. Статическая приёмка

1. Восемь полных каталогов; просьбы по 1–2 фразы без технических подсказок;
   разные новые области; в 2–3 задачах последовательность 2+ узлов обработки.
2. CSV имеют 10–40 строк данных, генераторы с seed воспроизводят их побайтно.
3. Все восемь oracle воспроизводят expected побайтно из своего и другого
   текущего каталога. Аргумент пути пакета меняет только `package_path`.
4. Все восемь expected приняты реальным вызовом `parseExpectedOutputs`
   из `scripts/node-acceptance/expected-outputs.mjs`, а не запуском модуля.
5. Для каждой задачи сопоставлены просьба, данные и ограничения expected:
   нет скрытых условий из README, свободные имена/метки/порядок не зажаты.
6. Корневой README дополнен покрытием p1–p8 и командами воспроизведения;
   ссылки работают, diff ограничен документами и данными этого каталога.
7. Независимая статическая приёмка — Ловец Галюцинаций, как D7b, на точном
   опубликованном SHA. Успешный разбор expected не означает PASS исполнения.
