## p7: Археология: материалы находок

[Просьба](prompt.md) — единственный текст для будущей модели; к нему передаются
только CSV из [data](data/). Этот README, [oracle](oracle.py),
[expected](expected-demo.json) и [подплан](../short-plan.md) — для оператора.

`finds.csv`: 18 строк; FindID — код находки, Trench — раскоп, MaterialCode — код материала. `materials.csv`: 12 строк; уникальный MaterialCode и его название Material. Все поля текстовые; у каждой находки ровно одно соответствие.
Синтетика без персональных данных. CSV: UTF-8 без BOM, заголовок, запятая,
точка в числах, перевод строки LF; [генератор](generate.py), seed `2207`.

Верный результат: 18 исходных находок с названием материала из справочника, все исходные поля находок плюс Material. Все коды известны и уникальны в справочнике: выбор inner/left не влияет на результат, размножения строк нет.
Предполагаемая обработка: Слияние (помимо импорта/экспорта).
Это объяснение покрытия, не подсказка модели и не требование к топологии графа.

Имена исходных колонок сохраняются по просьбе; имена новых итоговых полей,
если они есть, также взяты из просьбы. Порядок колонок свободный
(`column_order: any`), подписи свободные (`label_any: true` у всех полей).
`label_any` не разрешает переименование полей. Порядок строк свободный
(`ordered: false`); порядок строк JSON лишь способ записи эталона.
Имена узлов, их подписи, число вспомогательных шагов и выбор эквивалентного
способа расчёта не ограничиваются. `nodes` требует только импорт и экспорт;
результат читается на входе экспорта через `export_input`.

Числа-счётчики представлены как `integer`, дробные измерения — как `real`;
текстовые коды остаются `string`. Это схема статического эталона, взятая из
содержимого CSV и единиц измерения. Все дроби кратны 0.25 и точно представимы
в binary64; приближений и допусков нет. Oracle читает только свои CSV,
не импортирует генератор и не читает expected/пакет/ответ модели/сеть.

Имя `finds-materials.csv` задано просьбой. Каталог `/stability-2026-10-20/` —
окружение будущего запуска: оператор задаёт его как папку экспорта до запуска,
а не как дополнительное бизнес-правило. `export_destination` фиксирует этот
каталог и имя, чтобы однозначно выбрать экспорт. Личный путь пакета задаёт
оператор; `/stability-2026-10-20/p7.lgp` — пример. Аргумент oracle
меняет только `package_path`, экспорт остаётся в согласованном каталоге.

Из этого каталога:

```sh
python3 -B generate.py
python3 -B oracle.py > rebuilt.json
cmp expected-demo.json rebuilt.json
python3 -B oracle.py '/operator/d7-p7-run.lgp' > run-expected.json
```

Не добавлять временные JSON в Git. Полная проверка из разных текущих
каталогов и вызов `parseExpectedOutputs` — в [общем README](../README.md#d7d-короткие-просьбы-p1-p8).
Статическая приёмка не доказывает построение, исполнение, выгрузку или сохранение
в Loginom. Типы `integer`/`real` matcher различает строго: эквивалентный результат
с другим числовым типом требует операторского разбора и не объявляется здесь
проверенной свободой. Байты экспортированного CSV matcher не сравнивает.
