## p15: Летние режимы ульев

Модели: только [просьба](prompt.md) и [hives.csv](data/hives.csv).
Оператору: [генератор](generate.py), [oracle](oracle.py), [expected](expected-demo.json),
[подплан D7f](../short-plan.md#d7f-p9-p16-lab-115).

HiveID и Season — string; Flight — среднее число вылетов за минуту, Pollen — масса собранной пыльцы в граммах за день, оба real; 14 летних и 4 зимних наблюдения.
Синтетика без персональных данных, seed **2215**. CSV: UTF-8 без BOM,
заголовок, запятая, точка в числах, LF, 10–40 строк; генерация воспроизводит
все входы побайтно. Id и текстовые коды служат идентификаторами, не признаками.

Верный результат: После отбора summer — две строки с 6 и 8 ульями, средним Flight и суммой Pollen (real).
Покрытие: Фильтр → Кластеризация → Группировка (между импортом и экспортом).
`nodes` требует основные типы, но не фиксирует топологию, имена и число
вспомогательных узлов; равноценные способы подготовки/итога допустимы.

Oracle выделяет облака по крупнейшим разрывам первой координаты и независимо
проверяет, что межгрупповые расстояния более чем в 100 раз превышают внутригрупповые
в квадрате, а каждая точка ближе к своему центру. Проверяются исходный масштаб,
нормирование диапазоном и z-score. Эти варианты дают тот же состав групп;
масштаб и алгоритм просьбой не зафиксированы, произвольный иной состав групп
не считается автоматически эквивалентным. Номера/метки кластеров не сравниваются.
Зимние выбросы делают пропуск отбора заметным. TotalPollen — real, стандартный тип суммы Группировки; Hives — integer (число строк).

Имена сохраняемых и новых полей прямо заданы просьбой/входными заголовками.
У всех полей `label_any: true` (свобода подписи, не имени), `column_order: any`,
`ordered: false`: порядок колонок и строк свободный, дубликаты строк учитываются.
Промежуточные поля и метки не ограничиваются; состав итоговых полей — по просьбе.
Числовые типы — схема данных: счётчики integer, измерения и прогнозы real;
для real допуск `max(1e-8, 1e-10 × |expected|)`, для остальных значений — точно.
Matcher строго различает integer/real: численно равный иной тип требует
операторского разбора, такая свобода не объявляется проверенной.

Имя `summer-hives.csv` задано просьбой; `/stability-2026-10-20/` —
папка окружения будущего прогона, которую оператор объявляет модели заранее.
При другой папке оператор адаптирует `export_destination` в копии expected,
сохраняя имя файла. Путь пакета тоже операторский; аргумент oracle меняет
только `package_path`, не папку экспорта и не бизнес-результат.

Из этого каталога (Python 3, стандартная библиотека):

```sh
python3 -B generate.py
python3 -B oracle.py
python3 -B oracle.py '/operator/d7f-p15.lgp'
```

Полные побайтные проверки из двух cwd и реальный вызов `parseExpectedOutputs` —
в [общем README](../README.md#d7f-короткие-просьбы-p9-p16).
Oracle читает только свой доставленный вход относительно `__file__`,
не импортирует генератор, не читает expected/пакет/ответ модели/сеть.
`export_input` сравнивает таблицу перед экспортом, не байты CSV.
Статическая поставка не подтверждает выполнение модели, сохранение пакета,
доставку входов, доступность HTTP, выгрузку или cold-check.
