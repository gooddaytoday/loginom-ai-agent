## Task 1 — первый установленный dashboard по HTTPS

Task 1 принят независимым ревью: **Spec Approved / Quality Approved**, mandatory 0, optional 1 учтён ниже. Создан отдельный Docker installer `packages/dashboard/deploy/containers.sh install --engine docker --public-host <host> [--app-host-port <port>]`. Он обнаруживает одну работающую штатную установку по Compose services/mounts/network, оставляет vendor compose и файлы клиента неизменными и добавляет только `dashboard.site.conf`. Неверная конфигурация возвращает прежний site-файл до graceful reload.

Современный Compose ожидаемо предупреждает об устаревших `version: "2.4"` и `external.name`. Этот формат сохранён ради согласованного нижнего Compose; предупреждения не означают отказ установки. `version` не удаляется, синтаксис сети не меняется без доказанной совместимости, stderr не подавляется.

Вручную подготовленный каталог содержит `containers.sh`, `compose-release.yaml`, `image.tar`, `image.ref`, `SHA256SUMS`. Образ собран общим Dockerfile с текущими M5 server/shell, закреплённым Node и шаблоном. Это проверка потребителя будущей поставки; автоматический packaging и полный lifecycle остаются последующим задачам. Собственное состояние — `/var/opt/loginom-dashboard`; publisher получает только UserStorage RO, web/builder non-root, все роли имеют RO rootfs, dropped capabilities, no-new-privileges, конечные limits/tmpfs; publisher/builder без сети.

Web отдаёт точные GET `/dashboard/health` и `/dashboard/shell.js` после Host-check. Entry читает соседний установленный shell только для роли web. При HTTPS app-origin требуется private `DASHBOARD_TLS_UPSTREAM` до открытия listeners: порт app пересылает TLS в Apache 8444, а внутренний HTTP app listener 8102 и API 8100 наружу не опубликованы. Только Studio наследует узкий API rewrite через `InheritDownBefore`; app-vhost использует `IgnoreInherit` и общий app proxy. LookupResponse и MessagePort v1 не изменены. Доверенный script-tag несёт SRI и фактический HTTPS-порт Studio; при silent handshake оболочка предлагает ссылку на текущий hostname `/app/` с этим портом.

TLS tests используют настоящий HTTPS server, временный OpenSSL CA и доверяющий TLS client; проверены bytes, отказ upstream, закрытие клиента и конечный 30-секундный idle timeout.
