## Подготовка

- Нужны зелёные локальные проверки и CI окончательного коммита: `unit`, `dashboard-browser`, `dashboard-template` на доступных системах. Desktop DEB/AppImage, CLI, служба, оболочка и установщик должны происходить из одного чистого закоммиченного дерева. Используйте закреплённые Bun, Node и Chromium из Product/lockfile; [подготовка входов CI](../../../.github/actions/setup-loginom-inputs/action.yml). Старые кандидаты сохраняйте, новый output не должен их заменять.
- Desktop собирается и проверяется по [Linux runbook](linux.md#сборка): из `packages/desktop` — `bun run build`, `bun run package:linux --x64 --publish never`, затем `write-manifest.ts` и `verify-artifact.ts` для DEB и AppImage с реальной версией кандидата. CLI из корня: `bun packages/loginom-host/script/build-cli.ts <новый-абсолютный-каталог>`; подготовка, manifest/archive verification и установка — [standalone runbook](standalone-cli.md). Зафиксируйте SHA256 артефактов вне Git, безопасные итоги — ниже. Не используйте старый `dist` или dirty-кандидат как выпуск.
- **Перед заменяющей DEB-установкой запросите согласие владельца:** `sudo dpkg -i <новый.deb>` заменяет пакет в `/opt`; работающее приложение владелец закрывает сам. Только затем устанавливайте. Для прогона задайте отдельный `LOGINOM_AI_AGENT_TEST_ROOT` и запустите установленный Desktop. Backend V1: `LOGINOM_AI_AGENT_SIDECAR_V2` не задавать. Подключение — локальный dev-стенд `http://127.0.0.1:32768/app/`, модель — через обычные настройки. CLI использует собственный отдельный `LOGINOM_AI_AGENT_CLI_PROFILE`, настройте то же подключение его командой `loginom setup`.
- Проверяется только локальная тройка `dashboard-master-20261109-{server,studio,web}`. Рабочий компьютер — read-only эталон M2, менять его нельзя. Частные конфигурации, inspect, образы, credentials и сырые журналы храните вне Git с доступом только владельцу.

До любых изменений локального стенда проверьте Docker context, точные контейнеры, сеть и порты:

```sh
docker context show
docker inspect dashboard-master-20261109-server dashboard-master-20261109-studio
docker network inspect dashboard-master-20261109-net
ss -ltn '( sport = :32768 or sport = :32769 )'
```

По Task 18, шаги 4a–4b: остановите Server, сохраните `docker inspect` в приватный файл и `docker commit` в приватный локальный образ. Скопируйте ROI-файлы для контрольных хешей до изменений. Проверьте образ через временный **остановленный** контейнер (`docker create` и `docker cp`): должны сохраниться `/workdir/UserStorage`, `/workdir/dashboard-app` и хеши `campaign.lgp`/`dataset.csv`. Удалите только временный контейнер. Mounts, если появились, сохраняйте отдельно: `docker commit` их не включает. Запустите прежний Server.

Исходную остановленную Studio всегда сохраните под резервным именем. Сделайте её приватный образ и создайте замену под штатным именем в прежней сети с `-p 127.0.0.1:32768:80`; не подключайте к замене единственную исходную копию writable mounts. Проверьте Server по журналу, вход в `/app/` и `/app-debug/` и WebSocket 101 на соответствующем `/ws/`, выполнение ROI. Оба клиента должны проксировать WebSocket в этот Server. При ошибке сначала выясните её причину по журналу. Новый стенд создаётся по [рецепту](../../../dashboard/stand/README.md), существующий не пересоздавайте этим рецептом.

Если прежний web существует, приватно сохраните его inspect, остановите и оставьте под резервным именем. Перед установщиком отдельно сохраните `$HOME/loginom-dashboard` и данные mounts. Не удаляйте резерв до успешной приёмки. Для возврата остановите новые компоненты, восстановите Server из проверенного образа с прежними параметрами, верните сохранённые Studio, сеть, каталог и прежний web; проверьте вход и ROI. Если web прежде отсутствовал, удаляется только новый. `uninstall` M3 сам по себе M1 не восстанавливает.

## Десять шагов

Выполняйте по порядку на минифицированной Studio `/app/`; приватные результаты сохраняйте локально, в итог заносите только обезличенные факты. Все строки «Итог» пока не заполнены.

1. **S6: размер и запуск.** После согласованной установки определите путь установленного `resources/loginom/dashboard` и выполните:

   ```sh
   dashboard_resources=/opt/loginom-ai-agent/resources/loginom/dashboard
   du -sb "$dashboard_resources"
   tar -cf - -C "$dashboard_resources" . | gzip -6 | wc -c
   ```

   Сравните размер DEB с прежним кандидатом. Сделайте по три замера `loginom-ai-agent-cli --version` и времени чата от отправки до первого запроса модели на текущей и предыдущей сборках. Укажите измерения и сравнение; прирост запуска Linux больше 2 с — остановка и вопрос владельцу. Проверьте результаты `dashboard-template` на Windows/macOS. Ожидается трактовка строки как данных, файловые действия только в `work/src/`, попытка обращения к `control/` отклоняется без вопроса; привязка не изменена.
