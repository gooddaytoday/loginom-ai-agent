# Аудит пути создания сценария

Дата: 2026-09-21. Финальный source baseline: `4270f2c93` (кандидат `.10`).
[План](../../superpowers/plans/2026-09-21-loginom-scenario-debugging.md),
[реестр живых прогонов](scenario-debugging-results.md).
Это аудит текущего пути и его границ, не сертификация всех режимов Loginom.

## Границы и доказательства

| Граница | Проверенное поведение | Ограничение |
| --- | --- | --- |
| GUI → сообщение → вложение | Задания и CSV отправлены через установленный Desktop; сохранены тексты и SHA-256 фактических вложений из чатов. `prompt-input/files`, `build-request-parts`, `submit` отделены от исполнения Loginom. | Неподдерживаемые форматы и все предельные размеры файлов не входят в матрицу. |
| Desktop → подключение → Host | Изолированные профили, сохранение через GUI, наблюдаемые ready/generation; рабочий профиль пользователя сохранён. Keychain требовал участия пользователя, доступ получен без обхода. | Новый бинарный кандидат может снова потребовать системный доступ. |
| Session → acquire/catalog/admit | `session/tools.ts` передаёт безопасный код и этап недоступности; admission не продолжается после ошибки каталога. F09 проверен source-тестами и живым HOST_NOT_READY после незавершённой операции. | HOST_NOT_READY не означает успешное восстановление повреждённой операции. |
| Host → managed runtime → private IPC | Очередь, lease, журнал и исходный operation ID сохраняют связь результата с запросом. Короткое ожидание возвращает running, не объявляет действие неуспешным. | Потерянный ответ не разрешает повтор мутации; inspect может сам столкнуться с ошибкой UI. |
| executor → node apply/runner | Фазы target/configure/execute/read и возможный эффект различаются. Отвергнутый resume теперь сохраняет исходный outcome (F08). | Общее продолжение произвольного pending configure не реализовано. |
| Driver → Loginom | Схемы и валидаторы 14 типов сопоставлены с обработчиками; просмотрены импорт/экспорт, общая логика calculator-node и wrappers остальных типов. Реальное покрытие считается только по завершённым случаям реестра. | Наличие обработчика и passing tests сами по себе не доказывают исполнимость всех режимов. |
| Observe → действие | Новое наблюдение разрешено после доказанного отказа до жеста при сохранённой идентичности. F11 связывает Enter метаданных с владельцем, колонкой и неизменённым черновиком. | Неизвестный эффект, другой редактор или изменённое значение не разрешают replay. |
| Execute → read → граф | Успешные случаи имеют execution completed, доступные outputs и cleanup. Чтение чисел временно меняет формат и восстанавливает его. | F03: исключение чтения может оставить pending и представление таблицы; живой повтор этой ветки не получен. |
| Экспорт → файл | Требуются подтверждённое исполнение, назначение и разрешённая политика overwrite; файл читается через наблюдаемое хранилище и связывается с execution. | Экспорт подтверждён в V65 `.10`: выполнен узел, получен файл с bytes/SHA-256. |
| Public result → backend → история | F04/F05 сохраняют причину и рекомендуют исправление известного отказа; F10 сохраняет управляющую сводку при backend truncation, полный ответ остаётся локально. Проверены реальные UTF-8 лимиты. | Очень большой диагностический объект и live oversized exact-table отдельно не сертифицированы. |
| История → compaction | Прочитаны serialize/prune: completed output ограничивается 2000 символами при суммаризации; ошибки не обрезаются этим путём. Старые completed outputs могут быть очищены после сохранения недавнего контекста. | В исследованных чатах не найдено потери node execution/error control за этим пределом; общий риск compaction остаётся гипотезой, исправление не заявлено. |
| Save → приёмка | Успех требует save_completed и cleanup, графа и исполненных выходов; слова модели недостаточны. | Числа, cold reopen и повторное выполнение на новых данных исключены из текущего критерия. |

## Решения по препятствиям

- F01/F02: однозначная исходная метка разрешается по наблюдаемой схеме.
  Известная ошибка binding закрывает собственный черновик; после подтверждения
  позволяет исправленный запрос к тому же узлу. Неоднозначность не угадывается.
  Диагностическое восстановление и автономный русский ABC подтверждены.
- F04/F05/F08/F09/F10: исправлены передача причин, следующий шаг для известного
  отказа, сохранение исхода при rejected resume, диагностика недоступности
  и управляющая сводка при усечении. Проверки перечислены в реестре.
- F06: native Loginom нормализовал Unicode technical name. Вместо обещания
  сохранить такое имя введён ранний отказ до графа; Unicode source_name/label
  остаются разрешёнными. Установленная узкая регрессия прошла.
- F11: прежний Enter метаданных обходил общий механизм обновления ссылки.
  Исправление допускает только ограниченный повтор после NOT_APPLIED без эффекта;
  проверяет прежнюю идентичность редактора. Повтор B18 на `.8` прошёл импорт,
  весь сценарий завершён и сохранён.
- F12: B27 `.5` потерял наблюдаемый порт при создании следующего узла; inspect
  затем истекал по timeout. В `.8` добавлена предметная диагностика портов.
  `.9` устраняет бесконечное ожидание двух кадров в фоне: таймер ограничивает
  только read-only ожидание, общий deadline и проверка графа сохранены.
  Красный тест на прежнем коде и зелёный на новом подтверждают дефект ожидания,
  но не доказывают первопричину исчезновения порта. Повтор B27 завершён и сохранён, отказ порта не повторился.

F03 и F07 (истёкший deadline/лимит resume) остаются source-backed гипотезами:
не ослаблять guards или сроки без живого воспроизведения. Проблема CLI
`run-outcome.ts` с исправлением через новый ID относится к отдельной CLI-приёмке.

## Сохранность прежней приёмки

`.9` включает изменения предыдущих кандидатов. После `.6` успешный обычный
путь прежних случаев не менялся: F10 затрагивает только фактическое усечение,
F11 — доказанный отказ до Enter, диагностика порта — текст исключения,
а ограничение кадров — повторное чтение после временной ошибки графа.
Поэтому ранее сохранённые успешные сценарии остаются доказательствами своего
пути. Ветки воспроизведённых B18/B27 требуют отдельных повторов; эта аргументация
не заменяет их. Полный runtime: 2276 PASS / 2 SKIP, source transforms: 5045 PASS;
установленная `.9`: static DMG/ZIP и offline smoke PASS.

F13 воспроизведён в V65 `.9`: выбор опции data_kind после no-effect
UI_EPOCH_CHANGED не обновлял ссылку. Исправлен через общий ограниченный
perform с привязкой к колонке, редактору и владельцу меню. Не расширяет
возможности resume неизвестной операции. V65 `.10` прошёл импорт, выполнил остальные узлы, экспорт и сохранение.

На остановке матрица 10/10 завершена, покрытие 13/14.
transform.reform_columns прочитан по коду, но не выполнен моделью в зачётном
сценарии. Он остаётся единственным непокрытым типом. F03/F07, live oversized
compaction и первопричина прежнего F12 не объявлены доказанно устранёнными.

## Окончательное подтверждение

После возобновления выполнен дополнительный REFORM на установленном `.10`:
импорт и transform.reform_columns завершены, схема и выход прочитаны,
пакет сохранён. Матрица 10/10, фактическое покрытие 14/14.

Сохранность более ранних успешных путей в `.10`: изменение относительно `.9`
затрагивает только выбор import type/data_kind — тот же выбор проходит через
perform с привязкой к неизменному редактору; повтор возможен только после
строгого отказа до жеста. Схемы, вычисления, исполнения и сохранение прежних
узлов не менялись. Русский импорт выполнен в V65 и REFORM на `.10`, экспорт
и сохранение — в V65, reform — в дополнительном случае. B18/B27 прошли `.8`;
диагностический B27 с прежними запросами/координатами прошёл `.9`.

Итоговые source-проверки: runtime 2281 PASS / 2 SKIP, source transforms 5045 PASS.
На возобновлении менялись только документация и описание дополнительного
случая; повтор полного runtime без изменения кода не выполнялся.

Неподтверждённые гипотезы и ограничения предыдущих разделов сохраняются.
В частности, общий pending configure, ошибка read после execute и неизвестный
эффект не объявлены универсально восстанавливаемыми по успеху этих сценариев.
