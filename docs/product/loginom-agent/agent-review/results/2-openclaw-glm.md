- **Начало:** 2026-11-18 20:57 UTC. **Длительность:** ~55 минут (включая ~15 минут на приведение окружения в рабочее состояние).
- **Отступления от правил и почему:**
  - контейнер оценщика не имел системных библиотек и шрифтов, нужных Chromium; они установлены **локально в пользовательский каталог** (apt-get download + dpkg -x, без root и без изменений системы), из-за этого Chrome перезапускался несколько раз, а состояние демо восстанавливалось заново (`localStorage.clear()` из задания выполнялся повторно);
  - консоль браузера использовалась **только** для строк подготовки из задания (`localStorage.clear()`, переключатель политики администратора);
  - исходный код страницы, `.js` и `.css` не читал; DOM и дерево доступности — только для поиска видимых на экране элементов;
  - страницу «Прототип 2 · что решить» не открывал; на серверы Loginom, упомянутые в демо, не заходил;
  - модель сеанса не принимает изображения напрямую, поэтому каждый снимок дополнительно описан отдельной визионной моделью (`view_image`); все цитаты в отчёте продублированы текстом страницы.

#### 2. Вывод

Прототип ближе всего к лучшему агентскому harness для аналитика Loginom там, где решается доверие: разрешения с предпросмотром «Доступ», копия-вместо-оригинала с автобэкапом при замене, «Проверено приложением» против слов модели, трёхуровневый каталог дополнений и продуманный закрытый контур с политикой администратора — это сильнее всех сравниваемых продуктов (Claude Code, ChatGPT agent, KNIME K-AI, Alteryx Copilot). Дальше всего — глубина самой Loginom: изменения пакета показаны на уровне имён и типов узлов, но не их параметров, а связь с планировщиком, файловым хранилищем и подключениями к данным существует только в виде честных текстовых предупреждений.

#### 6. Чего не хватает лучшему harness для аналитика Loginom

1. **Параметры узлов в дифе.** Изменение «Фильтр по дате — перенесён» показано именем и типом, но не содержимым (какое условие фильтра, какие поля). Аналитик принимает правку, только видя параметры. Ускоряет: правка сценариев без открытия Studio. — https://help.loginom.ru/userguide/processors/
2. **Планировщик задач.** При замене пакета — текстовое «если пакет запускается по расписанию…», но не видно, **какие** задачи планировщика его запускают. Ускоряет: оценка последствий изменений для регламентных процессов. — https://help.loginom.ru/userguide/scheduler/scheduler.html
3. **Файловое хранилище Loginom.** Агент пишет в «Документы → Loginom AI Agent», но не работает с файловым хранилищем Studio/сервера, где лежат данные аналитика. Ускоряет: нахождение и переиспользование файлов сценариев. — https://help.loginom.ru/userguide/location_user_files.html
4. **Подключения к источникам данных.** Нет работы с подключениями Loginom к БД/API (создать, проверить, подставить в узел). Ускоряет: сборка сценариев «из SQL» на реальных источниках. — https://help.loginom.ru/userguide/integration/
5. **Переменные и параметры пакета.** Не показаны и не задаются переменные сценариев, входные порты и параметры узлов. Ускоряет: параметризация сценариев для повторного запуска. — https://help.loginom.ru/userguide/workflow/
6. **Создание задачи расписания из разговора.** «Запусти каждый день в 8:00» — естественная просьба аналитика; сейчас агент только запускает и предупреждает. Ускоряет: перевод разовой проверки в регламент. — https://help.loginom.ru/userguide/scheduler/scheduler.html
7. **Визуализация.** Ни один путь не затрагивает узлы визуализации и дашборды. Ускоряет: правка отчётов и панелей без Studio. — https://help.loginom.ru/userguide/visualization/
8. **Моделирование.** Обучение/применение моделей (узлы моделирования Loginom) агентом не демонстрируется. Ускоряет: подбор и проверку моделей. — https://help.loginom.ru/userguide/processors/
9. **Совместная работа на сервере.** Замена пакета в /user не показывает, у кого открыт пакет и какие права у коллег. Ускоряет: безопасные правки в команде. — https://help.loginom.ru/userguide/admin/
10. **Редакции и лицензии.** Подсказка, какая редакция нужна для возможности (планировщик — только Studio; см. таблицу компонентов). Ускоряет: объяснимые ограничения для покупателя/администратора. — https://help.loginom.ru/userguide/compare-editions.html

#### 7. Лишнее (пришло из агентов для программистов)

- **«Ответвить»** в меню сообщения — терминология чат-агентов; аналитику Loginom слово ничего не говорит (находка №4).
- **Раздел «Терминал» в «Разрешениях»** — для аналитика Loginom команды на компьютере почти не нужны. Сделано осторожно (выключен, с предупреждением «Включите, только если понимаете, зачем»), так что не мешает, но это след универсального harness.
- **«Скачивать отчёты»** (CSV) без выбора места и формата — стилистика «скачал файл» из веб-чатов; аналитику важнее положить отчёт в папку проекта или на сервер Loginom рядом с пакетом (сам мастер действий, кстати, это уже делает — «Документы → Loginom AI Agent → …», стоит распространить на разговоры).

#### 8. Что работает и что не трогать

1. Диф пакета с «Изменения / Как было», статусами «+ новый / ~ изменён / − удалён» и пояснением по клику на узел (4-03–4-05).
2. Шаг мастера «Доступ»: «сможет / не сможет» + «что увидит модель … данные уйдут в интернет» (5-02).
3. Блоки «Проверено приложением» и три исхода действий: Готово / Не подтверждено / Не удалось (5-05, 5-08, 5-09).
4. Каталог: три уровня доверия, «Проверено на примерах: N из N · Loginom 7.4», «Что будет разрешено» до установки, обновления с версией «1.2.0 → 1.3.0» (7-01, 7-02, 7-05).
5. Режим администратора: замки «Задано администратором», каталог из файла со сроком действия, диагностика с путём policy.json (10-06 – 10-11).

#### 9. Три самых важных изменения

1. **Показывать в дифе параметры узлов, а не только их имена и типы.** Сейчас «Фильтр по дате — перенесён» не отвечает на вопрос «что именно изменится в фильтре»; без этого аналитик принимает правку вслепую и всё равно открывает Studio — harness не экономит его время.
2. **Связать «Контекст» (План и Журнал) с реальными шагами агента.** Панель — главный экран доверия, а сейчас «План» показывает чужой сценарий, «Журнал» — две строки. Достаточно показывать те же шаги, что уже есть в ответе и в «Подробно».
3. **Перед заменой исходного пакета показывать конкретных потребителей: задачи планировщика и коллег с открытым пакетом.** Предупреждение «они сразу получат изменённую версию» — честное, но общее; список из планировщика превращает его в проверяемый факт и решает главный страх регламентных изменений.

#### 10. Что не проверено и какой риск остаётся

Не проверено поведение с настоящим Loginom (все ответы — заготовки): фактическая правка/запуск пакетов на сервере, эффект установленного навыка на ответ агента (в пробе разговора черновик лишь «включён», но не видно его влияния), реальное скачивание файлов (CSV/отчёт.html), кнопки «Изменить»/«Ответвить» у сообщений и длительные разговоры. Риск: заявленная глубина интеграции (параметры узлов, реальная сверка данных) может оказаться тоньше, чем изображает макет.
