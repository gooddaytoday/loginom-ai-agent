## Must fix

1. **Большое целое в параметре округляется** (`packages/dashboard/src/shell/loginom/parameters.ts:L29-38`)
   - **What this is:** Оболочка читает числовые переменные узла и отдаёт их в шапку, в состояние приложения и в снимок для чата.
   - **Problem:** Целое приводится через `Number(String(value))`. Значение `9007199254740993` становится `9007199254740992`. Таблица в том же адаптере такое целое оставляет текстом. В параметре точность теряется, и dashboard считает уже с другим числом.
   - **Fix:** Для целого, которое не помещается в безопасное целое JavaScript, не вызывать `Number`. Не класть его в список параметров с типом `number`. Таблица по-прежнему показывает исходный текст. Точная передача Int64 в состояние приложения — это уже смена контракта.
   - **If we skip it:** Переменная больше 2^53−1 отображается и уходит в расчёт неверной. Теста на эту границу нет.

## Should fix

2. **Ожидание публикации обрывается на первой сетевой ошибке** (`packages/dashboard/src/agent/publish.ts:L68-94`)
   - **What this is:** После записи файла `finishPublish` до двух минут спрашивает lookup, готова ли сборка.
   - **Problem:** Ответ HTTP без готовой сборки цикл продолжает. Обрыв соединения или не-JSON тело попадают в `catch` и делают `break`. Один сбой на первой секунде сразу возвращает `pending`, хотя стенд может ответить через несколько секунд.
   - **Fix:** В `catch` выходить только по отмене. Сетевую ошибку и плохой JSON пропустить и дождаться срока, как при ещё неготовой сборке.
   - **If we skip it:** Чат сообщает, что готовность не подтверждена, локальный образец остаётся, хотя сборка на стенде ещё идёт. Повторная публикация создаёт вторую версию.

3. **Принятая сборка не сверяется с хешем** (`packages/dashboard/src/publisher/index.ts:L51`, `packages/dashboard/src/web/apps.ts:L200-205`)
   - **What this is:** Publisher запоминает `buildHash` в `state.json`. Пока хеш исходников тот же и статус не `pending`, запись не перечитывается. Web отдаёт файл, если путь совпал с хешем в URL и это не символьная ссылка.
   - **Problem:** Подмена файлов внутри `builds/<ключ>/<хеш>/` или чужой `buildHash` в `state.json` переживает следующий обход. Очистка сохраняет каталог, на который ссылается состояние. Web эти байты отдаёт дальше. Права Loginom на пакет при этом не спрашиваются.
   - **Fix:** Для статуса `ready` на каждом обходе заново считать хеш каталога. Несовпадение снимает `ready`. При отдаче отказывать, если хеш дерева не равен хешу в URL.
   - **If we skip it:** Кто может писать в том `builds`, подменяет JavaScript уже открытого dashboard. В обычном режиме эти данные узла уходят тем же принятым каналом, что и у вредоносного приложения.

4. **Тома стенда создаются как `0777`** (`packages/dashboard/deploy/containers.sh:L551-561`, `packages/dashboard/src/publisher/index.ts:L137-138`)
   - **What this is:** Каталог состояния ставится в `0700`. `builds`, `jobs-in` и `jobs-out` создаются как `0777`. Каталог одной задачи publisher тоже делает `0777`, чтобы UID Loginom и UID 65534 могли удалять файлы друг друга.
   - **Problem:** Чужая учётка хоста внутрь не входит, пока родитель остаётся `0700` и принадлежит запускающему install. Уже существующий том install не сужает: каталог на месте, цикл его пропускает. Защита держится на одном режиме родителя. Внутри контейнера `0777` на задаче открыт любому UID, который видит этот том.
   - **Fix:** Общая группа только для UID publisher и 65534. Каталоги `2770`, и для новых, и для уже созданных. Sticky-бит не ставить: эти два UID должны удалять файлы друг друга. `0777` на каталоге задачи сузить до той же группы.
   - **If we skip it:** Смена режима родителя снова пускает любую локальную учётку к `state.json`, готовой сборке и чужому `jobs-out/<id>`.

5. **Снимок принимается без Origin и без предела частоты** (`packages/dashboard/src/web/server.ts:L104-116`)
   - **What this is:** `POST /dashboard/snapshots` кладёт до 100 снимков на 15 минут. Чужой `Origin` отклоняется. Запроса без `Origin` это не касается.
   - **Problem:** Браузер с другого сайта такой JSON не отправит: нет ответа на preflight. Прямой клиент до порта Studio отправит. После сотого снимка удаляется самый старый, в том числе ещё не прочитанный снимок пользователя. Угадать чужой UUID так нельзя.
   - **Fix:** С публичного виртуального хоста Studio не принимать `POST` без `Origin` из списка клиентов. Ограничить частоту создания снимков с одного адреса.
   - **If we skip it:** Кто достучался до API, может сорвать открытие dashboard, вытеснив снимок до того, как Desktop или CLI его прочитает.

6. **Самопроверка отдаёт консоль приложения агенту** (`packages/dashboard/src/draft/selfcheck.mjs:L25-26`, `packages/dashboard/src/agent/draft.ts:L35`)
   - **What this is:** Черновик сам открывает страницу в headless Chromium. Ошибки консоли и страницы, включая фрейм песочницы, попадают в ответ `dashboard_draft`.
   - **Problem:** Текст не обрезается по длине и не очищается от управляющих символов. Недоверенное приложение пишет в вывод агента и дальше в терминал, даже если модель ещё не читала `src/`.
   - **Fix:** Оставить не больше 20 сообщений, каждое ограничить по длине и убрать управляющие символы до записи в ответ инструмента.
   - **If we skip it:** Код чужой публикации может подсунуть агенту длинный текст или управляющие последовательности терминала в момент самопроверки.

7. **Успешный ответ dashboard теряется при ошибке закрытия браузера** (`packages/loginom-host/src/host.ts:L248-260`)
   - **What this is:** `performDashboard` читает или записывает публикацию в отдельном браузере и затем закрывает этот браузер.
   - **Problem:** `child.close()` стоит в `finally` и при ошибке выбрасывает исключение. Уже полученный ответ `child.request` до вызывающего кода не доходит. Удаление chat из `children` и `lost` тоже пропускается. Для записи файл в UserStorage уже может лежать на месте, а `finishPublish` не обновляет локальную основу. Для чтения первое открытие существующей публикации падает, хотя файл прочитан.
   - **Fix:** Если `child.request` уже вернул ответ, сохранить его. Ошибку закрытия записать в `shutdown.failed` и не подменять ею этот ответ. Chat убрать из `children` и `lost` в любом случае. `host.close()` по-прежнему завершается ошибкой, если очистка не подтверждена.
   - **If we skip it:** Пользователь видит сбой публикации или открытия. Повтор выглядит как конфликт версий либо как отсутствие уже существующей публикации.

8. **Временный `.part` остаётся в UserStorage** (`packages/loginom-runtime/src/dashboard-storage.mjs:L119-130`)
   - **What this is:** Запись кладёт JSON во временное имя `YYYYMMDDTHHMMSSZ.json.<uuid>.part` и затем переносит его на итоговое имя.
   - **Problem:** При `DASHBOARD_VERSION_EXISTS` и `DASHBOARD_ACCESS_DENIED` функция выходит сразу, part не удаляется. При неизвестном исходе part тоже остаётся, если чтение итогового имени не подтвердило тот же хеш. Publisher такие имена не берёт в сборку.
   - **Fix:** Удалять только этот part, когда итоговое имя не подтверждено тем же хешем. Итоговый файл публикации не трогать. В модуле сейчас нет удаления: нужен такой же узкий вызов FileStorage, как у upload и finish.
   - **If we skip it:** Каждая столкнувшаяся или оборванная публикация оставляет файл в каталоге пакета. Каталог UserStorage растёт без сборки и без отображения в Studio.

9. **Статус в документе изоляции описывает M3–M6 как незавершённые** (`docs/security/dashboard-isolation.md:L3`)
   - **What this is:** Первый абзац фиксирует, какая редакция требований действует и что уже принято.
   - **Problem:** Абзац говорит, что установленная приёмка M3 ещё не выполнена, а builder и publisher остаются целевыми этапами M4–M6. Runbook и `packages/dashboard/AGENTS.md` описывают M3–M6 как принятые.
   - **Fix:** Переписать статус на текущее поведение и указать действующие runbook. Исторический SHA оставить отдельной фразой.
   - **If we skip it:** Проверка по этому документу ищет незакрытую приёмку и несуществующие целевые этапы там, где код уже другой.

10. **Сбой проверки снимка выглядит как пропавший снимок** (`packages/app/src/components/prompt-input/submit.ts:L264`)
   - **What this is:** Перед отправкой и перед выпуском очереди `useDashboardTargetCheck` спрашивает Desktop, жива ли локальная папка снимка. `checkDashboardTarget` отвечает `false`, только если папки с этим id нет.
   - **Problem:** Любой отказ промиса — сбой IPC, ошибка чтения каталога, незарегистрированный обработчик — `.catch(() => false)` превращает в тот же `false`. Пользователь видит `dashboard.target.snapshotGone`: снимок уже использован, истёк или относится к другому стенду.
   - **Fix:** `false` оставить сообщением о пропавшем снимке. Отказ промиса не глотать и не подменять этим текстом. Показать отдельную ошибку связи с Desktop, чтобы повтор не требовал нового снимка из Studio.
   - **If we skip it:** Краткий сбой main-процесса останавливает отправку и очередь с советом открыть dashboard заново, хотя локальная папка на месте.

11. **Очередь сначала показывает сообщение, потом проверяет снимок** (`packages/app/src/components/prompt-input/submit.ts:L180`, `packages/app/src/pages/session.tsx:L1732`)
   - **What this is:** Пока сессия занята, текст с dashboard встаёт в очередь. При постановке из композера снимок уже проверяется. Когда очередь доходит до отправки, `sendFollowupDraft` проверяет его ещё раз.
   - **Problem:** Для обычного текста оптимистичное сообщение добавляется до `wait()` и `checkDashboard`. Путь slash-команды в той же функции проверяет цель раньше. Если к моменту отправки снимок пропал, сообщение мелькает в ленте и удаляется, пункт остаётся в очереди с `failed`. На сервер текст не уходит.
   - **Fix:** Для текста с dashboard вызывать проверку до `add()`, как у команды. При отказе не показывать сообщение в ленте.
   - **If we skip it:** Пользователь видит отправленный текст, затем ошибку и тот же пункт снова в очереди.
