# Настройка, выполнение и сохранение

Перед незнакомой настройкой прочти продуктовую справку и соответствующий helper.
Следующие suffix — указатели для поиска, полные селекторы сверяются с активной
вкладкой и DOM. Не переносись на другую форму из-за первого совпадения suffix.

## Мастер и выполнение

Выдели узел, открой его `Setting`, дождись `WizrdMCF`. После каждого `btnNext`
проверь новую страницу и снятие маски. `btnError` открывает подробности ошибки.
Для настроек полей/выражений прочти helper конкретного компонента: общий wizard
не определяет требования к входной таблице или формуле.

На обычной форме вводи значение в input, затем проверь value и применённое состояние.
Для combobox выбери пункт фактического boundlist, для checkbox проверь новое
состояние класса/значения. В ExtJS изменение текста не всегда равно commit:
переход фокуса или кнопка подтверждения могут быть частью helper.

При импорте локального CSV сначала подтверди файл в хранилище Loginom. Если для
загрузки открылась отдельная вкладка «Файлы», явно вернись на вкладку настройки
узла перед работой с input мастера: скрытый input другой вкладки не станет доступен
от повторного клика. Сверь полный серверный путь, введи его в обычный input,
заверши ввод переходом фокуса по актуальному helper и дождись результата чтения.
Если путь был введён до загрузки файла, повторно выбери уже загруженный файл через
обычный диалог. Различай успешный setFiles, наличие файла в хранилище и загрузку
preview мастера — это три разные проверки.

Кнопки мастера: `btnExecute`, `btnDone`, `btnView`, `btnClose`. Учитывай доступность
и точное назначение на текущей странице. На канве запуск узла доступен через
его `Launch` или `ModelForm;btnToggleActivateCurrent`; запуск всего графа —
`ModelForm;btnActivateAll`.

Дождись завершения процесса, проверь статус узла и выходного порта. В изученных
исходниках active рамка `#39b54a`, error `#ff0000`, warning `#f7931e`, inactive
`#9a9faf`, selection `#71b1e4`; выделение может скрывать полезный цвет. Проверяй
также иконку порта (`_active`/`_error`), подробности статуса и данные. Не объявляй
вычисление успешным только потому, что мастер закрылся.

Preview: активный выход → «Быстрый просмотр»/F3 по актуальному helper → ожидание
`PreviewWindow;PreviewForm;DataSetForm` и строк. Сверь колонки, типы, число строк и
несколько ожидаемых значений для задачи. Пустая таблица может быть корректна только
если это следует из данных и преобразования. При ошибке прочти сообщение узла.

## Пакеты и Save As

Для нового сценария создай черновик или пакет через UI. Для редактирования readonly
источника создай отдельную редактируемую копию, если это соответствует запросу.
Выбранные имя и папка относятся к серверному хранилищу Loginom, а не к файловой
системе машины агента или Dock.

1. Прочти `bg/helpers/packages.ts` и `bg/helpers/filedialog.ts`. Вызови Save As
   из меню пакета, проверь активный `SaveDialogForm`.
2. Выбери доступную папку и свободное имя `.lgp` либо указанное пользователем.
   Заполни input `SaveDialogForm;edtFileName`, затем нажми `btnOpen`. Существующий
   файл перезаписывай только в пределах разрешённого пользователем изменения.
3. Дождись закрытия диалога, отсутствия ошибки и обновления имени/состояния пакета.
4. Подтверди сохранение одним из способов: закрой сохранённый пакет, открой тот же
   `.lgp` через Open и сверь узлы/связи/настройки; либо скачай его штатным средством
   Loginom, проверь наличие непустого файла и возможность открытия. Для проверки
   закрытия не отбрасывай несохранённые изменения автоматически.
5. Оставь повторно открытый итоговый пакет в браузере. Сообщи фактическое имя/папку
   и результат проверки. Если скачан файл — дай ссылку на локальный артефакт.

Не выводи серверный путь из имени пользователя и не ожидай локальный `integration`.
Иконка Save или отсутствие ошибки сами по себе не доказывают сохранённый `.lgp`.
