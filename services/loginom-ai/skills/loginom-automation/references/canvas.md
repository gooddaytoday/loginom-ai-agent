# Узлы, связи и общий clipboard

Перед координатным действием получи актуальные bounds целевого элемента и графа.
На активной вкладке `MF;TF-N;ModelForm;cmpDiagram` должна быть видна канва.
Палитра открывается через `ModelForm;btnShowVendors`; компонент ищется в
`colVendors_...` с деревом категорий через `>`. Название и путь бери из DOM.

Не выбирай первую строку `table tr`, содержащую название: она может относиться
к скрытой вкладке или включать всё дерево. Найди точный `data-tid` компонента,
проверь его видимость и bounds. Точку назначения считай от bounds активного
`cmpDiagram`, а не как фиксированное смещение от палитры. Не определяй канву
по первому широкому SVG. Появление узлов проверяй по их актуальным `data-tid`
из helpers/DOM; число SVG `foreignObject` не является такой проверкой.

`Format` в исходниках нормализует метки, но это не повод конструировать устаревший
ID. Например, после повторного открытия одинаковые «Калькулятор» получили новые
суффиксы `@N`. Сравни список меток до и после добавления/вставки и получи полный ID.

## Настоящий drag

В проверенной версии прямой быстрый drag tool не создавал узел из палитры.
Помогла последовательность настоящих `page.mouse` событий с промежуточными шагами:

```javascript
async (page) => {
  // sourceSelector и target — свежие значения из DOM текущей вкладки.
  const source = await page.locator(sourceSelector).boundingBox();
  if (!source) throw new Error('Source is not on screen');
  const x = source.x + source.width / 2, y = source.y + source.height / 2;
  await page.mouse.move(x, y);
  await page.mouse.down();
  try {
    await page.waitForTimeout(80);
    await page.mouse.move((x + target.x) / 2, (y + target.y) / 2, { steps: 8 });
    await page.mouse.move(target.x, target.y, { steps: 8 });
    await page.waitForTimeout(150);
  } finally { await page.mouse.up(); }
  // Далее — ожидание конкретного нового узла или связи в DOM.
}
```

Короткие задержки здесь дают приложению обработать жест; они не заменяют ожидание
результата. Проверь, что координата назначения находится в свободной области графа.

Для связи найди выходной и входной порты нужных узлов в активной вкладке. Перенеси
центр выхода к центру входа той же последовательностью. Жди появления link с ID,
содержащим оба узла и порта (`...|Output_Data-0|...|Input_Data-0`), и при необходимости
осмотри изображение канвы. Мгновенное чтение после mouse.up может опередить DOM.
Наличие двух узлов рядом не означает связь. При неудаче проверь тип/активацию порта,
маску и координаты; небольшую коррекцию точки делай после этой проверки.

## Copy/paste

`dock_clipboard_transfer` принимает три функции: `copy`, `paste`, `confirm`.
Каждая получает `page`. Общая блокировка машины удерживается от начала copy до
подтверждения результата. `confirm` должна дождаться нужного DOM и вернуть `true`.
Узнай точную схему инструмента из его каталога.

- `copy`: явно активируй исходную workspace-вкладку, выдели нужные узлы и нажми
  scoped `MF;TF-N;ModelForm;btnCopy` (либо проверенную горячую клавишу).
- `paste`: явно активируй целевую вкладку и нажми её scoped `btnPaste`.
- `confirm`: сравни целевые метки/количество с исходным состоянием, проверь появление
  ожидаемых узлов/связей и отсутствие сообщения об ошибке. Проверка «кнопка нажата»
  недостаточна.

В DOM одновременно присутствуют кнопки нескольких вкладок; `:visible` не решает
эту неоднозначность. Source и target префиксы получают отдельно. После вставки
обнови ID, проверь входные зависимости и настройку узлов.

Если инструмент сообщил неопределённое завершение clipboard, не выполняй следующие
браузерные операции в этой среде. Сначала сохрани доступную диагностику и заверши
клиент: блокировка сохраняется до остановки его браузера, чтобы поздняя вставка
не перемешалась с другой сессией.
