## Дальнейшая поддержка Linux

- Проверять закреплённые версии из клиентского runtime и актуальные требования
  Playwright при обновлении зависимостей. Матрица ниже относится к указанным версиям.
- Для X11 сохранять `DISPLAY` и при необходимости `XAUTHORITY`; для нативного
  Wayland — `WAYLAND_DISPLAY`, `XDG_RUNTIME_DIR`, `XDG_SESSION_TYPE=wayland`.
  Сохранять также `XDG_CURRENT_DESKTOP`. Не копировать всё окружение в MCP.
- Проверять X11, XWayland и нативный Wayland отдельно. Headless-проверка подтверждает
  запуск и зависимости, но не clipboard, drag, Loginom или сохранение пакетов.
- Использовать Node и browser cache из одного закреплённого комплекта;
  source checkout должен иметь соответствующие `client/node_modules`.
  Ниже `DOCK_NODE`, `DOCK_BROWSERS`, `HERMES_PYTHON` — явно выбранные абсолютные пути.

```sh
"$DOCK_NODE" tools/loginom-acceptance/linux-browser-smoke.mjs --browsers "$DOCK_BROWSERS"
"$DOCK_NODE" tools/loginom-acceptance/linux-browser-smoke.mjs --browsers "$DOCK_BROWSERS" --headless
env -u NODE_TEST_CONTEXT "$DOCK_NODE" --test client/test/bridge.test.mjs
DOCK_TEST_NODE="$DOCK_NODE" "$HERMES_PYTHON" -m unittest discover -s tools/loginom-acceptance -p 'test_*.py'
```

Python-набор требует Python 3.11+ и полноценного Git checkout. Настройка,
preflight, выбор явной учётной записи/хранилища и запуск Hermes описаны в
[README обвязки](../../tools/loginom-acceptance/README.md).
Сохранять существующий proxy/NO_PROXY и подключение ChatGPT; обязательный
профиль — `openai-codex / gpt-5.6-sol / low` с проверкой фактических параметров.
При прикладной приёмке проверять сохранённый пакет независимым reader;
успешный выход Hermes сам по себе не является результатом аудита.

## Подтверждённая необходимость изменений

1. SDK 1.30.0 передаёт на POSIX только HOME, LOGNAME, PATH, SHELL, TERM, USER.
   Поэтому Linux-браузеру явно передаются DISPLAY, XAUTHORITY, XDG_RUNTIME_DIR,
   WAYLAND_DISPLAY, XDG_SESSION_TYPE, XDG_CURRENT_DESKTOP. Chromium 153 выбирает
   Wayland по XDG_SESSION_TYPE; определение рабочего стола участвует в выборе
   нативных proxy settings. Другие переменные и настройки моделей не меняются.
2. `imports.text` единственный из 14 обработчиков не отдавал `parameter_schema`
   в карточке типа узла. Добавлена схема из действующего публичного node API;
   новый импорт и patch существующего по-прежнему проверяет обработчик.
   Это контракт discovery Dock, а не отдельное требование MCP к карточкам Dock.
3. Редактор даты Loginom использует локаль браузера. Жёсткий русский порядок
   дня/месяца заменён наблюдаемой конфигурацией конкретного ComboBox. Неизвестный
   формат отклоняется; секунды и миллисекунды сохраняются без часового сдвига.
4. Для единственного агрегата Loginom допускает имя выходного поля без суффикса
   при привязке к источнику с суффиксом агрегата. Добавлена проверка через
   существующий resolver группировки; идентичность источников, порядок, типы,
   метки и сохранённые поля продолжают проверяться строгим общим verifier.

Перенесены только соответствующие изменения из `5e24a1d1`, `0155143e`,
`fb7493e6`, с адаптацией к текущему main. Полный перенос прежней ветки не нужен.

## Даты: границы подтверждённого поведения

Loginom 7.4.2 использует Ext JS 5.1.2.748. При en-US живое UI показало:

- Дискретный datetime: скаляр и обе границы диапазона используют ComboBox.
  Формат берётся из GetParserConfigForLocale; секунды и миллисекунды допустимы.
- Непрерывный datetime: скаляр и диапазон используют Ext.ux.DateTimeField.
  ISO local принимается через altFormats `c`, но штатный commit теряет дробные
  секунды. Ненулевые миллисекунды отклоняются до удаления прежних условий;
  для точного скаляра/диапазона требуется наблюдаемый дискретный вид поля.
- Список, в том числе у дискретного поля, использует отдельный DateTimeField;
  Enter сохраняет миллисекунды. Формат связан с конкретным input и владельцем
  диалога; неизвестный parser не допускает ввода.

Это общее поведение Loginom, не Linux-ограничение. Первоначальная гипотеза о
запрете миллисекунд для всех диапазонов **отброшена** после наблюдения дискретного
ComboBox. В v5 такого общего запрета нет. Условия без запроса изменения не
перезаписываются. Смена часового пояса не производится.

[Справка Loginom](https://help.loginom.ru/userguide/processors/transformation/row-filter/filtering-criteria.html)
подтверждает различие редакторов дискретного и непрерывного datetime; точность
миллисекунд установлена живыми проверками, а не обещанием документации.
Соответствующие API:
[Ext 5.1.2 Date](https://docs.sencha.com/extjs/5.1.2/api/Ext.form.field.Date.html),
[CellEditing](https://docs.sencha.com/extjs/5.1.2/api/Ext.grid.plugin.CellEditing.html).

### Диагностика полного Python-набора

Первый полный запуск системным Python 3.10.12: 705 тестов, 2 FAIL и 11 ERROR.
Ограниченный read-only test-signal-collector повторил каждый класс отказов 3/3;

выбран уже подготовленный Hermes Python 3.11.15. Поддержка Z документирована в
[Python 3.11 datetime](https://docs.python.org/3.11/library/datetime.html#datetime.datetime.fromisoformat).
Обратная адаптация этих helpers к системному Python 3.10 не добавлялась.

Отдельный дефект теста introduced в `18b3ac38d`: абсолютный macOS-путь Node в
`test_text_export_observer_evidence.py`. Заменён существующим в соседних тестах
порядком DOCK_TEST_NODE → установленный bundled Node → PATH; при отсутствии
Node тест явно отказывает. Все 10 observer-проверок выполнены успешно, включая
отрицательные варианты доказательств. Полный набор на Python 3.11.15: **715 PASS, 0 FAIL**, 212.290 секунд.
Таким образом, все выявленные причины проверены в предназначенном окружении.
