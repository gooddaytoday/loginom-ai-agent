# Node17: отдельная переоценка контракта импортов и origin

По поручению координатора исправлены две ошибки проверочного контракта. Продуктовый runtime `908c9b7d` не изменялся, новый Hermes не запускался, оригинальный frozen FAIL не заменён.

Повторный импорт обязан передать ровно `source,settings`, прежние подтверждённые artifact/upload ID, пустые `settings`, `inputs` и `mappings`. Явные bytes/hash сверяются с исходным файлом и подтверждённой доставкой. Существующий независимый `_verify_existing_import_output` после этого проверяет сохранённые source/format/columns/output и новое выполнение. Все три импорта run8 прошли обе проверки. Будущий текст задания исправлен отдельно; исходный `scenario.txt` сохранён.

Origin теперь использует последнюю подготовку данного сеанса перед началом конкретной операции, а не требует одну подготовку за всю историю. Не выбирается более старый удобный контекст. Подготовка внутри незавершённой операции, дублирование действующего контекста, чужие runtime/catalog/target/document/workflow и неподтверждённый owner отклоняются. Нативные origin/epoch/node/tab/prefix наблюдения по-прежнему обязательны. Позднее переоткрытие не влияет на завершённые операции предыдущего этапа.

Версии переоценки восстанавливают все **283** исходных harness blobs из Git `908c9b7d` и сверяют их с неизменённым `request.json`. Остальные исполняемые зависимости обязаны совпадать с исходными. Старый аудитор исполняется с явно записанной заменой import assertion; v3 дополнительно использует точный опубликованный diff origin. Исходные request/scenario/evidence/full-audit проверяются на неизменность до/после. Новые отчёты создаются только под отдельными именами и не перезаписываются. Это versioned re-evaluation, а не новый frozen PASS.

**34 Python-теста PASS**: подмены source/bytes/hash/settings/inputs/mappings/native node; 20 отрицательных случаев временной привязки origin; проверки происхождения переоценки отвергают несовпадающий исходный blob и неподтверждённую замену зависимости. На реальном run8 прошли три сохранённых импорта, семь выполненных экспортов до reopen и контрольная загрузка reject baseline. Оригинальные FAIL сохранены.

Оставшаяся остановка v3: `prepare-reopened-package` сообщает `ownership_verified=false`, поэтому сохранённый owner gate отклоняет первый экспорт после reopen. Source `client/lib/workspace.mjs:108` выставляет этот флаг только при `intent=new_draft`; для `open_package` он false по реализации. Это не доказательство чужого пакета или причины read-only, но без отдельного доказательства цепочки владения нельзя объявить проверку владельца успешной. Флаг не переписан и проверка не удалена.

Свежая независимая persistence оригинала также остаётся незакрытой. Координатор проверил отсутствие доступного Диспетчера и взял на себя обращение к владельцу для штатной проверки точного пакета. Разработчик повторно пакет не открывал, копий не создавал, учётные записи не менял.

Актуальный результат: **полная цель не принята**.
