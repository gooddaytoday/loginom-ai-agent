## Результат и границы

Один `node.apply` заполняет Null в явно выбранных полях средствами Loginom.
Первый scope: среднее для непрерывных целых/вещественных полей и заданная
строковая константа для дискретных строковых полей; неупорядоченный набор.
Неперечисленные поля не обрабатываются. Пустая строка, ноль и текст `null`
не становятся пропусками без отдельной подготовки, выбранной агентом.
Допустимый процент пропусков задаётся явно; его фактическая семантика проверяется.
Любая числовая константа, медиана, мода, предыдущая строка, интерполяция,
случайное заполнение, удаление строк и управление переменными остаются в roadmap.
Смена вида/типа поля выполняется отдельным узлом и не скрывается в этом handler.

## Вход и выход операции

Вход: новый/существующий узел, один табличный источник, актуальные типы и виды,
явный список обрабатываемых полей с методом и, для строки, значением замены;
порог 0–100% и неупорядоченный режим. Среднее не вычислять на стороне Dock.
На входной схеме проверить всю матрицу применимости до жестов. Числовой дискретный
столбец не переводить в непрерывный автоматически; вернуть точное ограничение.
Запрос задаёт полный набор обработок узла: неуказанные поля отключить явно,
чтобы случайный метод по умолчанию либо прежняя настройка не изменили данные.
Неподдержанный сохранённый метод при изменении существующего узла требует
явной замены в запросе; не сохранять его как будто handler проверил этот режим.

Выход общий: фазы, refs, execution identity, схема, строки, полнота и evidence.
Дополнительно отражать эффективный метод/тип/вид, порог и фактически оставшиеся Null.
Порог может оставить поле незаполненным: успех выполнения не равен отсутствию пропусков.
Полный счёт пропусков допустим только при полном чтении или проверенном агрегате.
Configure-only возвращает `execution=not_requested`, `output=not_refreshed`.
Если режим хранит обученное состояние, квитанция должна различать обучение и применение;
старое состояние не представлять результатом расчёта по изменившемуся источнику.

## Этапы реализации

1. Codex первым исследует реальный мастер в отдельной видимой сессии: метод,
   вид данных, checkbox поля, порог, строковый редактор и полную таблицу настроек.
   Проверить штатное выполнение, наличие обучения и сохранение его состояния.
2. Сверить UI с Help/E2E, закрепить матрицу методов и именованные ожидания;
   отдельно уточнить порог, полностью пустое поле и округление среднего для Integer.
3. Зарегистрировать тип; внутри `node.apply` добавить/найти, подключить, настроить
   весь набор обработок, прочитать итоговые параметры и завершить мастер.
4. Включить нужный lifecycle обучения в общую операцию только если он подтверждён.
   Не переобучать посторонние узлы или весь workflow; применение/переобучение
   существующего состояния должно иметь явную семантику, связанную с версией входа.
5. Выполнить и прочитать свежий выход общими средствами; не открывать мастер снова
   в обычном пути. После потерянного ответа сначала сверить фазу/метод/состояние.
6. Провести focused tests и независимые Codex live QA, затем обычный Hermes;
   допуск и сохранение evidence определены в [next-wave](next-wave.md).

## Проверки и приёмка

До запуска подготовить CSV и отдельный expected, не вычисляемый через handler.

- Непрерывное Float: `2.5, Null, 7.5` даёт `2.5, 5, 7.5`; отрицательные значения
  и точность более двух знаков проверяются без экранного округления.
- Непрерывное Integer с дробным средним: выходной тип и округление закрепить
  в первом live QA, а затем проверять независимым expected при повторении.
- Заданная строка меняется у существующего узла: Null заполняется новым значением,
  пустая строка и текст `null` сохраняются; число и порядок строк прежние.
- Порог ниже/на границе/выше фактической доли, 0% с 1/120 и полностью пустой
  столбец при 100%: проверить оставшиеся Null, а не только успешный запуск.
- Неперечисленные поля отключены; дискретное число со средним, переменный тип,
  чужое поле и недопустимый метод отклонены до жестов; пустой вход различим.
- Смена источника с другой средней, configure-only, отмена, повтор operation ID
  и потеря ответа: свежесть результата и, при наличии, обученного состояния проверены.
- Финальное сохранение и отдельный Codex reopen/reexecute воспроизводят параметры,
  полную таблицу и подтверждённую семантику сохранения/обновления обученного состояния.

Обычный Hermes получает только задачу и данные, использует существующую подписку
`openai-codex / gpt-5.6-sol / low`, завершает `package.save_checkpoint`.
Независимый auditor проверяет полный выход и сохранённые настройки отдельно;
отклоняет подмены метода, порога, активного поля, среднего и старого запуска.
Наличие оставшихся Null отражается в результате; не обещать полную очистку по summary.
