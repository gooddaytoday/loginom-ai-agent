# Node17: ожидание Save As и виртуальный список файлов

Кандидат основан на `5226aab7`. Полная цель пока **не принята**. Координатор разрешил адресную диагностику и исправления, без повторного полного ревью; новый Hermes требует отдельного назначения слота.

## Сохранение и повторное открытие

В full6 `20260913-215018-6e242f0e` все 22 смысловых node cases были выполнены, но первая попытка размещения Empty была отклонена до эффекта и добавила 23-й запрос. Исходный аудит сохранил FAIL `user_node_error`. В этом же прогоне `package.save_as` вернул AMBIGUOUS: `Selector packages.close cardinality 0, expected one`. Последующие операции модели не доказывают реальное повторное открытие.

Проверка исходника выявила асимметрию: ожидание окончания native Save As было только в ветке сохранения без открытия. Теперь оба режима ждут завершения Save As, затем режим открытия отдельно ждёт появления команды «Закрыть». Детерминированный тест задержанного меню падал до изменения и прошёл после; добавлен также случай задержанного появления Close. Это согласуется с ранее подтверждённым исправлением node12 `0e11a3fb24ca40a9f855008d2b0d1856d6f771ad`. Точную длительность исторической гонки full6 установить нельзя.

Живой диагностический Save As на `/test-2/node17-save-reopen-fixed-full6.lgp` прошёл: сохранение → закрытие → открытие, совпали путь, 8 узлов и 5 связей. Это копия для проверки исправления, а не независимый аудит исходного model package.

Исходный пакет full6 при свежем открытии был только для чтения. Локальные процессы завершены, но это не доказывает снятие серверной блокировки. Администрирование скрыто для test-2; обхода прав и удаления сессий не было. По указанию координатора дальнейшие попытки разблокировки прекращены, original fresh audit остаётся incomplete.
