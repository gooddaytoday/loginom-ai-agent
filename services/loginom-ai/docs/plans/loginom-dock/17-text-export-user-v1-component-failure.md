# Node17: единственный user-v1 прогон — FAIL на границе скачивания

Задание `node17:user-v1-component:1:e14c8211` выполнено одним новым stdio
прогоном `20260913-154255-92bfd3b3`, сессия
`3b238204-8e1e-42c3-91f6-45e28900ff02`. Компонент не принят; полный допуск
остался закрытым. Hermes не запускался, повторной попытки не было.

Использован неизменённый harness `e14c8211`: runtime155/harness275 и manifest
`47e8a6e14a9b43a98e8399cdba2f1ebc013b775475c10fecab368adcaddda00b`.
Исторический CLI tag `node17:user-v1-account-preflight:1:0f37df75` сохранён
ради байтовых pins. Отдельная запись
`.dock/node17/user-v1-component-current/authorization.json` связывает его
с текущим заданием и новой сессией; старые результаты не переиспользованы.

В реальном Loginom 7.4.2, на test-2, независимый аудит подтвердил профиль
user-v1, подготовленный документ/сценарий/сессию, видимую строку аккаунта
и закрытие меню единственным нажатием Avatar. Проверка заняла 115 мс,
незавершённых UI-действий не осталось. Этот результат впервые подтверждает
новый жест закрытия из e14c8211. Затем источник и исходный экспорт прошли:
все 124 байта совпали с эталоном, прочитаны 5 строк × 3 столбца. Отказ
перезаписи reject завершился FAILED с cleanup=true, без исполнения узла.

Observer выполнил 15 шагов, сохранил исходный граф, перешёл в `/test-2` и
увидел точный CSV размером 124 байта с доступной точкой взаимодействия.
Последняя запись — prepared шага 16 `download`. Через 1287.69 мс от начала
observer завершился `incomplete`, timed_out=false,
`OBSERVER_INCOMPLETE_REPLACE_NOT_DISPATCHED`. Нет сохранённого ответа download,
свежего файла observer, возврата в граф или actual-dispatch. В исходном
журнале отсутствуют любые события `smoke-replace`: replace не был отправлен.

Точнее локализовать внутреннюю ошибку по этому прогону нельзя. В
`text-export-observer-native.mjs` результат вызова сначала разбирается и
проверяется на SUCCEEDED, и только затем сохраняется completed. Поэтому
ошибка транспорта/разбора либо отрицательный native результат остаются без
исходного ответа. Конкретный код отказа, изменение DOM и факт жеста скачивания
не установлены. Отсутствие сохранённого файла не доказывает нулевое число жестов.
Следующая ограниченная диагностика должна сначала сохранять безопасный
отрицательный ответ до проверок успеха; новый прогон требует задания координатора.

Независимый полный component auditor сохранил FAIL `user_public_pairing`:
публичный запрос replace не имеет нормального результата. Это следствие
остановки observer, а не доказанная ошибка проекции успешного user-v1 ответа.
Аудит baseline и аккаунта выполнен отдельно; частичный успех не повышен до
component/full-goal PASS. Матрицы успешного native/replace аудита неприменимы.

Перед запуском прошли 6 целевых Node и 20 Python проверок. После остановки
повторно сверены все 155 runtime и 275 harness hashes, цепочка observer,
отсутствие dispatch/replace, исходные байты и журналы. Полный admission gate
проверен и отказал: `Native user-v1 component evidence pending`.
Manifest, продукт, runtime и цель 22 операции / 3 доставки / все save-reopen
не менялись. В этой фазе добавлены только отчёты.

Транспорт и собственный браузер закрылись; проверка процессов не нашла PID
этой сессии. Глобальная конфигурация не изменилась. Серверный logout не заявлен.
Координатор владеет следующим действием: ограниченная диагностика сохранения
native отказа, затем отдельное решение о следующей попытке. Слот Hermes пока
не требуется. Исторические неуспешные и диагностические прогоны сохранены.
