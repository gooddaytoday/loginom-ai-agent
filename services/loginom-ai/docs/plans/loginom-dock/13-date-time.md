## Результат и границы

Получать календарные разрезы для отчётов из типизированных полей Дата/Время
одним `node.apply`, сохраняя исходные строки. Начальный набор:

- числовые год, квартал, месяц, день месяца, час;
- начало и конец календарного года, квартала и месяца в типе Дата/Время;
- дата без времени и несколько преобразований одного или нескольких полей;
- явные имена, метки, порядок и включение исходных полей на выходе.

Точные пары «преобразование → тип» подтверждены live и перечислены ниже.
Недели/ISO-периоды, пользовательские строковые форматы и управление переменными
остаются дальнейшими режимами. Разбор строк в даты относится к импорту или
Калькулятору; этот обработчик не угадывает формат входной строки. Не добавлять
неявное преобразование часового пояса и не заменять узел формулами Калькулятора
для заявления о готовности данного handler.

## Исходная точка и источники

В coverage есть `component.transform.DateTimeReform`; полного обработчика нет.
Нужны карточка типа, схема параметров, чтение матрицы преобразований и её
применение поверх общих драйверов. Результат — один табличный выход.

[Официальный Help](https://help.loginom.ru/userguide/processors/transformation/trans-datatime/)
описывает выделение частей даты и варианты начала/конца периода.
Help source: `data/processors/transformation/trans-datatime/README.md`.
Прочитан E2E `tests/acceptance/wizards/transform/date_time_reform/datetimereform.ts`:
различает колонки начала, конца, числа и строки; селекторы определены в этом файле.
Числа позиций из тестов не становятся постоянными идентификаторами handler.
Отображение даты в примере Help не доказывает точное время конца периода.

## Контракт и локальная процедура

Вход: один актуальный источник и список преобразований, каждое связано с точным
именем входного поля, календарной частью/периодом, типом и границей периода.
Список задаётся целиком для выбранного поля; незапрошенные поля существующего
узла сохраняются. Пустой список для поля — только явное снятие его преобразований;
пустые параметры существующего узла означают выполнение сохранённой настройки.

1. Codex сначала исследует мастер на живом UI: несколько дат, доступность ячеек,
   выделение поля, видимые/скрытые строки и отдельный выходной порт.
2. Проверить входные типы, совместимость преобразований и уникальность выходных
   назначений до мутации. Отсутствующее поле не выбирать по похожей метке.
3. Добавить/найти и связать узел общим циклом, открыть его мастер; для каждого
   входного поля сверить и выставить ровно запрошенные флаги.
4. Прочитать всю заданную матрицу и число выбранных преобразований, включая
   прокручиваемую часть. Ждать применения конкретной ячейки нужного поля.
5. Для явного выходного порядка отключить автосинхронизацию сквозных полей:
   штатная синхронизация при повторной валидации перемещает их после вычисленных.
   Сочетание явного output layout и autosync=true отклоняется до изменений.
   Для сохранения точного входного порядка явно задать input autosync=false:
   при true после повторного открытия Loginom может переставить входные поля.
   Сопоставить сформированные поля с исходным полем, преобразованием и типом;
   настроить выходной mapping по этому соответствию, не по позиции в таблице.
6. Общий finish/execute/read возвращает наблюдённую конфигурацию и свежий выход.
   Для существующего узла снятие преобразования удаляет только соответствующее
   назначение; неопределённый эффект не разрешает повторный переключатель.

## Самостоятельные проверки

- Даты на границе года и квартала, февраль високосного/обычного года,
  последний день месяца, полночь и ненулевое время; точные значения периода
  вычислить независимо, после сверки native-семантики окончания периода.
- Несколько преобразований одного поля и два исходных поля с одинаковыми
  метками; проверить источник каждого выходного столбца, имена и порядок.
- Null, пустой вход, неправильный тип; ни Null, ни пустой набор не превращаются
  в текущую дату. Число строк для успешного преобразования равно входному.
- Добавление/снятие преобразования существующего узла, смена порядка входных
  полей; не должны остаться старые лишние столбцы или поменяться их источники.
- `done`, `close`, смена upstream и потеря ответа между выбором поля и флагом;
  повтор операции не инвертирует уже установленный флаг.

Обычная задача Hermes: построить суммы продаж по календарным месяцам и кварталам
из файла с датами и сохранить сценарий. Приёмка проверяет применение этого узла,
оба разреза и полный результат после отдельного открытия/выполнения Codex;
не передаёт Hermes селекторы и последовательность технических действий.

## Подтверждённая native-семантика (source-диагностика)

На Loginom 7.4.2 проверены `year`, `quarter`, `month`, `day_of_month`, `hour`
с целочисленным результатом; `year_start`, `year_end`, `quarter_start`,
`quarter_end`, `month_start`, `month_end`, `date` — с результатом Дата/Время.
Конец периода означает его последний календарный день **в 00:00:00.000**.
Это не последний момент суток. Значения читаются с точностью до миллисекунды,
без предположения о часовом поясе; Null сохраняется.

Отдельное сохранение, открытие и повторное выполнение полного примера 4×27
подтвердили все 12 преобразований на двух полях и явный выходной порядок
при autosync=false. Матрицы, имена, метки, типы и исключение исходного DateB
совпали. Independent persistence audit: fcccbde6 → a52fd065, PASS.
Также завершены source-проверки добавления/удаления, Close, неверного типа,
отказа замены занятой связи и потери ответа без повторного click. Повторное
сохранение/открытие/выполнение малого примера 0×7: f7cf52c5 → 6e3aa7ff,
strict persistence PASS при input/output autosync=false. При input autosync=true
строгий аудит обнаружил перестановку входов; это ограничение сохранено в отчёте.
Отдельные review, candidate admission и Hermes-приёмка остаются следующими этапами.

Критерий готовности: приняты все перечисленные преобразования и границы дат, сохранённые
настройки воспроизводятся; опубликованы точные режимы, pins и ограничения.
