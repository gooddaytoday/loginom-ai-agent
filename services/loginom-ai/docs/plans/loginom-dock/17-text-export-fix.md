# Node17 Text export: исправления R1/R2

13.09.2026 выполнен один correction round `node17:review-fix:1:110da29a:R1R2`
после [единственного review](17-text-export-review.md). Оба замечания исправлены.
Коммит исправлений: `2524921058b29db0e79e9a188ec7bb8fa9ef9d8c`; ветка `codex/node-17-text-export`,
компонент `component.exports.Text`. Это кандидат ветки, не состояние main,
сервера или установленного клиента. Повторное review и Hermes не запускались.

## Что изменено

R1: специализированный Next использует абсолютный срок операции. Проверки
отмены/срока выполняются после ожидания чтения, журнала и непосредственно перед
жестами; браузер повторяет их после проверок владельца, диалога и hit-test.
Host AbortSignal передаёт отмену уже запущенному браузерному действию. При
неопределённом результате транспорта маркер сохраняется: поздний скрипт не
получает разрешение продолжить. Неопределённое действие не повторяется.

R2: перед переходом с каждой страницы проверяется весь сохранённый набор её
параметров. Native decimal_separator="" («Не задано (,)») и text_qualifier=""
(«Нет») не нормализуются предположением. Они приводят к подтверждённому закрытию
черновика и отказу до Finish/Execute. Доказательство очистки обязательно для
возврата обычного FAILED; неполные подтверждения остаются AMBIGUOUS. Явная точка
или запятая и двойная кавычка переопределяют неподдержанное сохранённое значение.
Ранее допустимые пустые native defaults даты/времени сохраняются как наблюдаемые
значения; их формат не выдумывается и не объявляется разрешённым в конкретный вид.

## Воспроизведение и целевая проверка

Использован реальный Loginom 7.4.2 Linux, только test-2 и /test-2. Видимое окно
1508×949, viewport:null, внутренняя область 1508×862. Source harness изолирован
от Hermes и общего установленного клиента.

До исправления, source `110da29abe5d247c76ed71b09f7e6b7f6d0b588b`, runtime
`afc199953de8a6a7e0d1e3a04247a98e69d85d832e26d0168a06b2c0bb6b8cab`:

- R1: отмена после записи prepared-журнала не помешала реальному Next и Yes;
  мастер перешёл с параметров на формат. Execute не запрашивался, поэтому это
  доказательство позднего жеста, а не записи файла после отмены.
- R2: реальное «Не задано (,)» сохранило decimal_separator="". Public node.apply
  выполнил экспорт 109 байт, после чего SDK отверг результат по enum schema.
  Raw status сохранил SUCCEEDED. SHA файла:
  `6863f20a0d7fdae85fe3bb493658f0a3668187c6da81767ec7ce0b563a0b4957`.

После исправления, runtime `347615cbae29323d80b57488b794ecce607b5b9e0d2fbe86aa88b7460241311c`:

- Отмена после prepared-журнала оставила первую страницу и все настройки
  неизменными, без Next. При истечении срока после Next вопрос замены остался
  без ответа. Реальная host-отмена уже выполняемого действия также оставила
  вопрос без ответа. Для двух последних диагностик задержано только чтение
  владельца; это управляемая инъекция задержки в реальном UI, не измерение
  обычной скорости Loginom. Оператор отдельно отказал в замене и закрыл черновик.
- Сохранённый decimal default отклонён для нового и существующего destination;
  native qualifier «Нет» также отклонён. У всех FAILED/cleanup=true,
  в журналах нет Next и Execute. Без полного доказательства cleanup отрицательные
  source-тесты требуют AMBIGUOUS.
- Явные допустимые параметры успешно переопределили defaults: новый файл
  109 байт, SHA `e077d37b44116079268f49198cec415370dffa09cfdad3679258b3e781198361`.
  Default reject отказал в замене; прежние 109 байт/SHA сохранены независимым
  повторным скачиванием. Полные обновлённые native store 52/52 и 53/53 подтвердили
  отсутствие отклонённых новых файлов. Это проверки до последующей явной замены.
- Явный replace завершился 124 байтами с заголовком, SHA
  `9f9972ed174053d02745df8df0c3c2d44697b33f7fb6da2ce8463eb58cc5d13a`.
  Для обоих успешных экспортов независимый аудитор сравнил все байты, параметры,
  входную схему, источник, выполнение и цепочку событий; отклонил по 9 подмен.
- Пройдены 91/91 целевых тестов, 0 FAIL/0 SKIP. Проверены lifecycle cancellation,

Два отдельных подготовительных запроса получили NOT_APPLIED/cleanup=true из-за
временной workflow mask и блокировки узла после закрытия мастера. Они сохранены

Пакет `/test-2/node17-review-fix-20260913.lgp` сохранён публичным

раунде не проводился; persisted_content_verified=false не повышался до true.

## Доказательства и оставшиеся границы

[Машиночитаемый отчёт с hashes](17-text-export-fix-evidence.json).
Приватные исходные доказательства до исправления:
`.dock/text-export/live-1789301416218`; после:
`.dock/text-export/live-1789301890244`; диагностические скрипты/тестовый лог:
`.dock/node17/fix`. Они содержат наблюдения реального браузера и отдельные
исходные FAIL; в Git сохранены только отчёты и проверяемый код.

Историческая матрица разработки и её 1398 PASS/1 SKIP относятся к прежним
ревизиям. Она не перезапускалась и не переименовывалась в проверку исправленного
runtime. Широкие/пустые/typed/reopen случаи на старых runtime остаются историческими.
Текущий раунд подтвердил только R1/R2 и затронутые replace/reject/byte paths.
Нужна финальная автономная приёмка полного объявленного scope через выделенный
координатором Hermes openai-codex / gpt-5.6-sol / low и независимый аудит.
Слияние, push, deploy и обновление общего клиента не выполнялись.

Устойчивое знание именно для node17/component.exports.Text, ветки и source выше:
сохранённые native defaults требуется проверять до необратимого Execute;
ошибка schema после побочного эффекта не означает отсутствия результата.
Проверка бюджета специализированного действия должна охватывать ожидание журнала
и промежутки между native-жестами. Эти выводы не переносят готовность на node11–16
или main; проектная память пополняется штатным capture завершённой фазы.
