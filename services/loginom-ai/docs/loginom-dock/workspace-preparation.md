# Подготовка рабочей области — контракт 01

Реализация в исходниках от 7 сентября 2026 года. Production и установленный
клиент не обновлялись. Самостоятельная приёмка проверяет только подготовку,
а не node.apply, сохранение пакета или готовность всего выпуска.

## Запрос и передача в 02/03

Используется существующий `dock_prepare` в executor-preview/executor-replay,
тот же browser gate, session manifest, compatibility profile и skill pin.
Classic-режим сохраняет подготовку знаний без открытия workspace.

| Поле | Семантика |
| --- | --- |
| `operation_id` | Идентификатор подготовки в сессии; по умолчанию `prepare` |
| `intent: new_draft` | Значение по умолчанию; создаёт собственный несохранённый пакет, не присваивает активный чужой сценарий |
| `intent: open_package` | Требует точный абсолютный `package_path` с `.lgp`; путь сверяется с cached `PackageFileName`, узлы не запускаются |
| `intent: existing_workflow` | Требует `workflow_ref`, ранее выданный подготовкой в том же документе, дополненный `document_id` из результата |
| `timeout_ms` | Общий бюджет браузерной подготовки, 1–120000 мс; изменение бюджета не меняет идентичность операции |

`workflow_ref` содержит `workflow_id`, `tab_tid`, `prefix`, `navigation_path`.
Для возврата к нему передаются все эти поля и `document_id`.
`workflow_id` связан с конкретными объектами вкладки и cached package node:
совпадение номера вкладки или метки после закрытия и повторного открытия недостаточно.
Новая операция разрешена после подтверждённой предыдущей подготовки; смена ID
не снимает неопределённый исход. Повтор ID с другим намерением отклоняется.

Результат сообщает фазу, причину, session/profile/build/document, workflow,
`package_ref`, `created_draft`, `ownership_verified`, `target_verified`,
`effect_possible`, `replayed` и квитанции именованных ожиданий.
У несохранённого пакета `path: null`, `persisted: false`.
При открытии существующего объекта `ownership_verified: false`: точность цели
не означает, что агент создал этот пакет или получил право удалить его.

В 02/03 передаются эта идентичность и pins существующей executor-сессии.
Драйверы должны проверять свою цель перед жестом. Возвращаемое
`interaction_readiness: driver_verification_required` намеренно не доказывает
готовность drag, конфигурацию узла, его выполнение или сохранение пакета.
Отдельного интерпретатора сценария и второго браузерного механизма нет.

## Ожидания и квитанции

Проверяются `ui_build`, `login_or_workspace`, `login_result`,
`workspace_entry_ready`, `package_menu_ready`, `open_package_dialog` и
`exact_workflow_ready` — только применимые к выбранному пути.
Фиксированная пауза 500 мс удалена. Маски загрузки ожидаются внутри операции;
диалог несохранённых изменений возвращает `UNSAVED_CHANGES` без ответа на него.

Живой старт показал, что аватар появляется раньше готовой начальной страницы.
Обращение к меню в этот промежуток вызывало assert `GetNodeByRef` в Loginom.
`workspace_entry_ready` проверяет именно готовую начальную страницу или сценарий,
а также исчезновение масок. Это проверено через основной MCP-путь.

До браузерного вызова сохраняется признак попытки в session manifest.
В документе браузера перед возможным созданием хранится квитанция и набор
прежних вкладок. После потерянного ответа повтор ID сначала сверяет квитанцию,
новую вкладку и cached package identity; ещё один click создания не разрешается.
После потери документа локальный журнал не восстанавливает черновик.
Неизвестный исход сохраняет запрет на новую подготовку с другим ID.

Для прежних сценариев проверяется сохранность вкладок и содержимого DOM графов.
Это проверка отсутствия изменений от подготовки, а не полный аудит данных,
настроек всех узлов или файлов на сервере. Отмена не закрывает и не удаляет пакеты.
Сведения о возможном создании остаются в квитанции; READY после отмены не публикуется.

Ошибки включают требуемый/отклонённый вход, несовместимый UI build,
чужую страницу, блокирующий диалог, отказ открытия пакета, потерянный workflow,
изменённый workflow, потерянную квитанцию, deadline и прерванную подготовку.
`PACKAGE_OPEN_REJECTED` — общий отказ диалога открытия, включая отсутствие файла;
различение конкретных причин серверного отказа по тексту не заявляется.
