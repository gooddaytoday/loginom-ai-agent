## Разрешённый объём

Разрешён отдельный ограниченный диагностический прототип чтения tagged binary
response IBGDataSource.AsVariant(Row,Col), method321/interface116 до ReadVariant,
в собственной test-1 сессии Loginom7.4.2, максимум50строк×8столбцов.
Это новая внутренняя RPC capability, а не текущий cached-UI reader.
Исходный план разработчика:
`unavailable:artifact-727b98939539f8b3`.

До каждого чтения доказать datasource owner, document/workflow/node/port/index,
execution freshness, schema/row bounds и фиксированные build/source SHA; перепроверить
после чтения. Использовать только фиксированный read method, whitelist tags,
lossless integer/real/datetime/Null, отказ при неизвестном tag, потере owner/freshness
или неполном payload. Никаких произвольных RPC, записей через RPC, извлечения
credentials, shared hooks/plugin/transport или автоматического fallback.
Пакет/процесс/браузер диагностические, отдельные от других потоков.
Сначала проверить семантику ответа и ownership на собственном тестовом наборе;
невозможность доказать их останавливает эксперимент. Результат — evidence/report,
не автоматическое включение нового способа чтения в продукт.

ReadVariant статически теряет discriminator; прямой AsVariant proxy возвращает
уже primitive. Соответствие сырых tags исходному subtype и полный Preview caller-chain
ещё не подтверждены. Эксперимент может завершиться выводом о непригодности подхода.
Пассивный захват обычного UI-response пока не имеет доказанного owner/row binding.

Причина отдельного решения — изменение согласованной архитектурной границы:
[архитектура](architecture.md#уточнение-mvp-после-разбора-4-сентября) описывает
адаптеры cached UI state, «а не универсальный DOM API и не вызовы RPC».
Прежний запрет запуска до решения пользователя заменён этим точным разрешением;
общая архитектурная граница остальных операций сохраняется.
Это не новый отказ автоматической проверки и не разрешение менять общий плагин.
