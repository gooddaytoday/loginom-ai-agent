Причина первого отказа — полный аудитор использует verifier создания нового
импорта для existing request, где метка законно не повторяется. Сам graph node
связан точным ref с ранее выполненным импортом. Существующий специализированный
verifier уже проверяет эту связь и старые/новые байты, но при явно переданном
mapping одновременно подставляет сохранённый порядок; нижний verifier
отклоняет конфликт этих двух способов задания output columns.

Оба пробела направлены в адресную доработку проверочного кода. Ни события,
ни запрос модели, ни замороженный итог run8 не переписываются. Reopen guard
не обходится. После исправления нужны его положительные/отрицательные
проверки и новый зафиксированный комплект следующего полного прогона.
