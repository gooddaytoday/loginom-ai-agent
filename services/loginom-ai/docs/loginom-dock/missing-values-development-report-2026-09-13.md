## Реализация

Добавлен `preprocessing.data_recovery / impute`: создание или поиск узла,
соединение, проверка типов/видов, настройка полного списка полей, завершение,
выполнение и чтение выхода одним `node.apply`. Поддержаны среднее для непрерывных
Integer/Real и константа для дискретной строки, включая пустую строку; явный порог
0–100%, неупорядоченный набор. Неперечисленные поля отключаются. Существующий
узел допускает `{}` для сохранения поддерживаемых настроек. Среднее вычисляет Loginom.

Общий UI-слой дополнен только наблюдёнными необходимыми случаями: группа палитры
«Предобработка», точное открытие порта при hover-клоне, привязка контекста отмены,
ограниченное ожидание перехода поверхности, открытие частично скрытой карточки
визуализатора и прокрутка до неё. Неактивные нативно скрытые Table не расходуют
лимит обхода определений. Ячейки виртуализованной таблицы привязаны к cached record
и DOM-строке; суффикс cell data-tid не считается номером записи и может повторяться
в разных строках. Защиты владельца, кэша/DOM, свежести и границы обхода сохранены.

## Границы приёмки

Это source-разработка и Codex direct QA. Обзор, обычный Hermes и автономная приёмка
не запускались; публикация, merge, deploy и переустановка общего клиента не выполнялись.
Нужен отдельный диспетчерский запуск следующих этапов.

Native `package.save_checkpoint` для `/test-4` блокирует закреплённый каталог,
разрешающий только `/test-1..3`. Запрос нового изолированного immutable candidate
описан в [заявке](missing-values-candidate-request-2026-09-13.md); текущий каталог
не менялся. Ручной Save As не считается проверкой native checkpoint.

Реальное отсутствие CSV вызвало terminal failed в Loginom. Общая квитанция оставила
AMBIGUOUS/pending execute/cleanup:false и не выдала успешный выход. Отдельное чтение
подтвердило failed той же группы; файл восстановлен и панель закрыта вручную,
прежний pending runtime завершён. Автоматическое завершение такого общего отказа
как FAILED/cleanup:true остаётся ограничением, которое должен видеть ревьюер.

Существующий Text Import при смене CSV сохранил прежние определения колонок;
перестановка массива columns в запросе сама по себе их не переставляет. Этот
невалидный источник отклонён аудитом. Для проверки Node14 создан отдельный импорт,
его схема и данные подтверждены. Обработчик Text Import не изменялся.

После reopened QA и fault-проверки пакет закрыт с отказом от сохранения только
последующих диагностических изменений. Проверенная сохранённая копия сохранена.
Собственные runtime, MCP и браузер завершены; неразрешённая операция не переносилась
в новый runtime; повтор её ID не повторял жесты. Автоматическое восстановление после lost reply
не заявляется: проверен безопасный pending и идемпотентный повтор без жестов.
