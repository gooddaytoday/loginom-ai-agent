# Автосвязи при добавлении узла

Исследование 7 сентября 2026, подплан 02. Проверяется именно связь между
портами узлов, а не автоматическое сопоставление полей внутри порта.

## Подтверждённые правила

Help `data/workflow/ports/README.md`, раздел «Связывание портов»:

- При drag-and-drop компонента из палитры Loginom может показать предварительную
  связь и подсказку выходного порта соседа, затем создать связь при drop.
- Для нескольких входов используется верхний вход каждого типа. Это не означает,
  что все входы многовходового узла будут подключены.
- Удержание Alt во время drag отключает автосвязывание.
- Порты должны иметь совместимый тип. Для подключений проверка проводится при
  наведении, для остальных типов — при добавлении. Preview не доказывает успех.

E2E `tests/toreview/helpers/al/autobinding_helpers.ts`, `SearchNearestPort`:
модель кандидата использует координаты **портов**, положительное смещение X
до 191 включительно и модуль смещения Y до 63 включительно. Среди кандидатов
выбирается меньшая вертикальная дистанция. Это вспомогательный код в `toreview`,
с проверками через console, а не спецификация актуального продуктового алгоритма.
Не переносить эти числа и порядок разрешения равенств в драйвер как гарантию.
E2E `tests/acceptance/workflow/linking.ts` также применяет `modifiers: {alt: true}`.
Источники прочитаны через Dock из `viking://resources/loginom-dock/sources/`;
префиксы репозиториев — `loginom-help/` и `e2e-tests/` соответственно.

## Живые наблюдения

Loginom 7.4.2, `logi-test-plan.bg.local`, отдельные несохранённые черновики,
видимый Chromium: inner 1508×862, outer 1508×949. Источник «Текстовый файл»
сначала создан в (320,280), затем добавлен Калькулятор. Координаты ниже —
логические положения узлов, а не расстояние между портами.

| Смещение нового узла относительно источника | Автосвязь |
| --- | --- |
| (+64,0) | Нет |
| (+96,0), (+160,0), (+240,0) | Источник output 0 → новый input 0 |
| (0,+96), (+96,+96), (-96,0), (0,-96) | Нет |
| Новый источник слева от ранее созданного Калькулятора (-96,0) | Нет |
| (+96,0), Alt удерживается во время drop | Нет |
| Объединение (+96,0) | Только input 0; второй вход не подключён |

Эти результаты показывают, почему нельзя рассчитывать только на «достаточный
отступ»: важны сторона и геометрия портов, а не одна дистанция между узлами.
Отсутствие обратной автосвязи подтверждено одним случаем; не обобщать на все типы.

## Контракт драйвера

1. Снять полный малый граф до drop; после завершения прочитать его заново.
2. Проверить один новый узел нужного типа и сохранность прежнего графа.
3. Отделить новые связи текущего создания от существовавших до операции.
4. Сравнить точные GUID узлов, направления, типы и индексы портов с запросом.
   Подходящую автосвязь оставить: повторный connect или delete/reconnect не нужен.
5. Лишнюю связь текущего создания удалить через UI именно как связь. Проверить,
   что узлы, порты и прочие связи сохранились. Затем соединить требуемые порты.
6. Существующие незапрошенные связи не удалять. Не использовать пересоздание
   узла как исправление, не повторять drop после неизвестного результата.
7. Alt — доступный механизм для будущего явного режима подавления автосвязей.
   Сейчас поведение драйвера не меняется: сохранение полезных автосвязей остаётся
   штатным путём. Если такой режим вводится, нужен finally для отпускания Alt
   и мыши, проверка отмены и всё тот же контроль графа после drop.

Текущая фаза `node-target.mjs` уже сохраняет полезные входящие автосвязи и удаляет
только принадлежащие текущему созданию лишние входящие. Для иных типов портов,
исходящих автосвязей и новых версий платформы нельзя автоматически объявлять
поддержку на основании этих наблюдений. Посторонний diff остаётся неоднозначным.

## Воспроизведение и ограничения

`tools/loginom-acceptance/autolink-study.mjs` запускается закреплённым Node 24
с обязательными `--loginom-url` и `--loginom-user`; `--extended` включает Alt,
многовходовый узел, двух соседей, retain/remove/replay и перенос за доступную точку рамки.
Профиль изолирован, браузер закрывается после диагностики. Это source-runtime
исследование без модели, не Hermes-приёмка и не проверка сохранённого пакета.

Первая серия: `.dock/add-nodes-v2/mcp-1788809998616/autolink-study.json` —
девять завершённых наблюдений. Подготовительное добавление для следующего теста move получило строгий
NOT_APPLIED («Target is covered») до жеста. Перенос в этой попытке не выполнялся.
Неуспешный run сохранён целиком; возможные эффекты не повторялись. В диагностике
добавлено ограниченное обновление только после подтверждённого отказа до жеста,
с проверкой неизменности полного графа и отдельной квитанцией каждой попытки.


Расширенная серия: `.dock/add-nodes-v2/mcp-1788810075854/autolink-study.json`.
Alt, Объединение, два источника и retain/replay завершены. При двух источниках
в (320,280) и (360,240), новом Калькуляторе (480,280) выбран второй источник.
Не выводить универсальное правило «ближайший по центрам узлов» из этого случая.
Нужная автосвязь сохранена без connect/remove; повтор операции только прочитал граф.

Удаление выявило гонку доступности кнопки диалога: видимость подтверждения ещё
не означает достижимость точки клика. В `node-target-browser.mjs` добавлено
именованное ожидание `single_link_confirmation_reachable` с прежним deadline
и повторной проверкой точного текста перед подтверждением. Никаких повторных
удалений при неизвестном эффекте это не разрешает.
Живой исправленный путь: `.dock/add-nodes-v2/mcp-1788810176754/remove-operation.json`,
SUCCEEDED, ровно одна remove_link, без connect; replay не повторил жесты.
Узлы и порты сохранились. Последующая отдельная подготовка move в этой серии
остановилась до drop; всю серию не считать PASS.

После исправления: 439 клиентских тестов, 438 PASS, 1 SKIP, 0 FAIL;
`.dock/add-nodes-v2/autolink-client-tests.txt`. Сохранение/reopen и Hermes
в этом исследовании не запускались, production и установленный клиент не менялись.


Повтор `.dock/add-nodes-v2/mcp-1788810217723/remove-operation.json` показал
аналогичное перекрытие кнопки панели до открытия подтверждения. Добавлено
ожидание `single_link_delete_toolbar_reachable`; после него заново проверяются
единственная выбранная связь и неизменность полного графа, только затем click.
Первое предположение, что достаточно готовности одного диалога, не подтвердилось;
оба неуспешных runs сохранены, их результаты не переоценивались.


Финальная версия с двумя ожиданиями проверена живым удалением и replay:
`.dock/add-nodes-v2/mcp-1788810378012/remove-operation.json`, SUCCEEDED.
Полный набор клиента на этой версии: 438 PASS, 1 SKIP, 0 FAIL,
`.dock/add-nodes-v2/autolink-client-final.txt`. Проверены синтаксис диагностического
сценария и `git diff --check`.

Отдельные попытки диагностического переноса за метку/угол рамки
(`mcp-1788810294940`, `mcp-1788810324399`) не подтвердили изменения позиции.
Их нельзя использовать как свидетельство отсутствия автосвязи при переносе:
сам перенос не был выполнен. Для заключения требуется успешный move с readback.


Штатный move в финальной серии также отказался **до эффекта** из-за недоступной
точки: `.dock/add-nodes-v2/mcp-1788810378012/move-operation.json`, NOT_APPLIED,
partial_effect=false. Автосвязывание при переносе существующего узла остаётся
непроверенным. Следующий live-шаг подплана 02 — снять hit-test и SVG-геометрию
этого точного узла, исправить доступную точку move, затем проверить изменение
позиции и только после этого сравнивать связи. Общего PASS серии не заявлять.


## Уточнение при продолжении 02

Hit-test `.dock/add-nodes-v2/mcp-1788810702156/move-hit-test.json` показал:
центр выбранного узла перекрыт его собственной `NodesControls`. Эта панель
не служит ручкой drag. После снятия выделения через наблюдённую пустую точку
штатный move с точным GUID прошёл: `.dock/add-nodes-v2/mcp-1788810831031/`,
(720,480) → (416,280), новых связей нет. Прежнее ограничение переноса для этого
случая снято; это не утверждение обо всех типах и версиях Loginom.
