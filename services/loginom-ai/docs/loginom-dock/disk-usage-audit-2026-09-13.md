## Причина

Диагностические calculator-live.mjs, union-live.mjs и другие сохраняют каждый
полный browser response как browser-N.json; отдельно сохраняются execution-events
и public-api журналы. Многократные прогоны накапливают множество снимков состояния.
Пример calculator live-1789021537858:12238 JSON≈3.02GiB плюс JSONL≈333MiB;
профиль браузера только20MiB. Text import execute-1788836664324:
3822 JSON≈1.0GiB плюс журнал≈176MiB, профиль15MiB.

Сжатие в памяти по100 browser JSON из каждого примера:77.4% и77.9% экономии.
Это выборка, не измеренный итог сжатия всех каталогов. Основной источник роста —
подробные доказательства, а не браузерный кэш.

## Очерёдность

1. Архивировать закрытые исторические calculator-v3 и text-import-v3 прогоны.
   Сохранить paths/size/SHA256 каждого файла, проверить архив потоковым чтением
   и восстановление. Только после этого можно заменять распакованные копии архивом.
   Сначала маленькие партии из-за дефицита свободного места. Старые FAIL сохранять.
   Указать команду восстановления: существующие аудиторы ожидают исходные пути.
2. Затем аналогично union/join и завершённые задачи11/12. Не удалять worktrees
   целиком: ветки ещё не объединены и evidence нужны для приёмки.
3. Кэш только закрытых сессий — после проверки владельцев/процессов и отсутствия
   зависимости manifest. Ожидаемый выигрыш намного меньше архивирования JSON.
4. Проверить старые distributions/releases на воспроизводимость и ссылки текущих
   задач перед удалением. Совокупный объём этих двух каталогов≈3GiB.
5. Backup20260902T220114Z.tar≈4.8GiB не считать мусором: внутри Docker images,
   ollama_data, data и source. Уже содержит сжатые tar.gz. Нужна другая проверенная
   копия/решение о сроке хранения; повторное gzip не обещает большой экономии.

Нельзя удалять текущие raw evidence, DB/WAL, manifests, активные профили,
worktrees/.git и исходники для быстрого освобождения места. Нельзя считать
исторические PASS доказательствами текущего runtime.

## Предотвращение повторного роста

Нужны отдельные изменения instrumentation: потоковое сжатие журналов,
архивирование после завершения фазы, хранение повторных payload по hash с
ссылками при сохранённой причинной цепочке, лимит объёма с резервом и честной
остановкой. Изменения должны учитывать независимые аудиторы и существующие pins.
Эта проверка такие изменения не внедряла и не удаляла доказательства.
