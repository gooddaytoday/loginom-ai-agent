## Что реализовано

- `node-contracts.mjs` и `.d.ts`: восемь типов, запрос нового либо существующего
  узла, ссылки document/workflow/GUID, входные связи, общие интерфейсы 02/03.
  Схемы настроек реализуются типизированными обработчиками в 03–10.
- Совместимый batch `dock_action_describe` возвращает выбранные действия и типы.
  Пустой запрос и одиночный action_key сохраняют прежние ответы. Карточки
  различают внутренний графовый обработчик и ещё не готовую настройку;
  cache key включает runtime/catalog/skill/profile. Карточки не устанавливают код.
- `prepareNodeTarget`: создать/найти, переименовать, разместить, добавить нужные
  входы и соединить точные порты. Полезная автосвязь сохраняется без повторного
  connect, лишняя принадлежащая текущему созданию удаляется отдельно через UI.
- Приватный `createActionRuntime().runNodeTarget`: общий gate, operation ID,
  журнал эффектов, read-only inspect и явный resume исходной операции.
  Он является точкой подключения оболочки 03, не отдельным публичным MCP action.
  Legacy node.add/link.create остаются совместимыми; рекурсивных внешних вызовов нет.

```json
{"action_keys":["node.add","link.create"],"node_types":["imports.text","transform.union_data"]}
```

## Идентичность, порты и восстановление

Каждый read заново связывает GUID с отображённым SVG, проверяет подготовленные
объекты документа, вкладки/пакета, путь workflow и инкарнацию DOM-корня. Перед
жестами и внутри link.create сохраняются guards исходной подготовки и узлов.
Метки не служат идентификатором. Читаются локальные cached graph objects и DOM;
методы сервера и data proxy не вызываются.

DOM epoch здесь — инкарнация DOM-объекта, а не счётчик произвольных изменений
стилей. Штатная перерисовка SVG после собственного эффекта сверяется по GUID
и доменному графу; следующая операция получает свежую DOM-привязку.
Порядок ключей JSON не является частью идентичности. Значения полей и порядок
элементов массивов проверяются, а пути сравниваются по tid и label.

Индекс входа/выхода — **нулевой порядковый номер среди табличных портов**.
В Loginom 7.4.2 третий табличный вход Объединения имеет native индекс 3,
потому что индекс 2 занят служебным портом. Второй выход Фильтра проверен отдельно.
Незапрошенные связи существующего узла сохраняются; занятый чужой вход отклоняется.

Каждая мутация требует подтверждённой записи effect/before в fsync-журнал.
Браузерная квитанция и полный diff проверяются независимо. Inspect не продолжает
жесты. Resume разрешён только после подтверждения эффекта/cleanup и сверки
последнего полного графа; не более трёх возобновлений. Неизвестный drop не повторяется.
До двух локальных обновлений допускаются лишь после строгого отказа до жеста.

Отмена передаётся локальному Page registry текущего браузерного вызова. Цикл
мыши и ожидания проверяют её; gate удерживается до завершения/cleanup.
Отмена не означает rollback. Незавершённый результат остаётся частичным.
Итог target_ready всегда имеет configured/executed/package_saved=false.

## Исправления по живому интерфейсу

Перенос выбранного узла блокировался его собственной NodesControls. Драйвер
снимает выделение через наблюдённую пустую точку, проверяет неизменность графа
и переносит тот же узел. Проверено (720,480) → (416,280), без новых связей:
`.dock/add-nodes-v2/mcp-1788810831031/autolink-study.json`.

При удалении автосвязи видимость кнопки ещё не означала доступность точки клика.
Добавлены именованные ожидания панели удаления и подтверждения; перед click
заново проверяются выделенная связь, граф и точный текст подтверждения.
Условия автосвязывания, Alt и ограничения изложены в [autolinks.md](autolinks.md).

Первая Hermes-попытка `hermes-20260907-231040-5901300d` остановлена Codex после
выявления ошибочного сравнения порядка JSON-ключей. Её FAILED audit сохранён.
Проблема воспроизведена через настоящий UI (`reorder-reproduce.txt`), исправлена,
затем восемь типов и десять связей повторно проверены со всеми ключами в обратном
порядке (`reorder-fixed.txt`). Неизменный ошибочный прогон не перезапускался.
