## Контракт

`node.apply`: type `transform.filter_data`, mode `conditions`. Общая оболочка
открывает точный узел, проверяет входную схему, применяет условия, настраивает
оба выхода, выполняет узел и читает его выходы. Новых модельных UI-команд нет.

`parameters.groups` — непустой массив непустых групп И, соединённых ИЛИ.
Порядок сохраняется; новые группы полностью заменяют прежние условия.
Произвольные скобки и выражения не интерпретируются. Для существующего узла
`parameters: {}` проверяет и сохраняет поддержанные условия без переприсваивания.
Новый узел требует явных groups; `groups: []` не является пропуском всех строк.

Условие задаёт field, type, operator и соответствующие операнды.
Field — `{kind: "input_field", name: "Id"}` с точным именем входного поля
или `{kind: "row_number"}`. Номер строки имеет тип integer и относится
к фактическому порядку данных на входе фильтра.

| Операторы | Операнды | Типы |
| --- | --- | --- |
| `<`, `<=`, `>`, `>=`, `=`, `<>` | value | integer, real, datetime, string |
| between, not_between | lower, upper, границы включены | integer, real, datetime, string |
| in, not_in | непустой values | integer, real, datetime, string |
| is_null, not_null | нет | все пять scalar types |
| contains, not_contains, starts_with, not_starts_with, ends_with, not_ends_with | value | string |
| is_true, is_false | нет | boolean |

Для string-сравнений со значениями обязателен case_sensitive. Null-предикаты не принимают регистр: в Loginom этот редактор для них недоступен.
Null не передаётся как литерал; пустая строка остаётся отдельным значением.
Даты используют локальный ISO `2024-01-02T12:30:01` с необязательными тремя
знаками миллисекунд и без часового пояса. Числа должны быть конечными;
integer ограничен точным диапазоном JSON/JavaScript. Запрос ограничен
64 группами, 128 строками условий/ИЛИ и 128 значениями отдельного списка.
Переменные, variant, неподдержанные native операторы и неполная схема
приводят к отказу. Имена полей ограничены текущим идентификаторным контрактом
аналитических обработчиков: латинские буквы, цифры и подчёркивание, до 128 символов.

## Выходы и жизненный цикл

Входной mapping — port 0; выходные mappings — независимые port 0 и port 1.
Execute требует оба выхода: 0 — соответствуют условию, 1 — не соответствуют.
Каждый результат содержит port GUID в контексте конкретного узла, схему,
число строк, до десяти строк выборки и признак её полноты. Общий execution ID
связывает оба результата с одним выполнением. Ошибка чтения не превращается
в пустой порт. При require_exact_numbers=true чтение использует полноточный
формат «Таблица» и восстанавливает исходные настройки после чтения.

Done применяет настройки без выполнения; Close отбрасывает мастер без
переприсваивания условий. Оба режима возвращают not_requested/not_refreshed
и требуют пустой read.ports. Сохранение пакета — отдельный save_checkpoint;
локальная квитанция узла не доказывает сохранение на сервере.

После неопределённого эффекта сохраняется исходный operation ID. Потерянный
ответ не разрешает повторно добавить условие или выполнить узел. До жеста
разрешены только два обновления наблюдения при доказанном отсутствии эффекта,
той же цели, том же намерении и прежнем deadline.

## Доказательства

`filter-context.mjs` читает ограниченный native UI-cache и проверяет владельца
строки, редактора, списка/интервала. `filter-procedure.mjs` меняет условия
адресными жестами и сверяет значения после применения. `filter-output.mjs`
передаёт оба порта общему lifecycle и читателю таблиц.

Независимые Python-аудиторы сравнивают сырые наблюдения, условия, receipts,
execution и выходные таблицы с отдельным oracle. Golden CSV содержит десять
строк, полный дубликат, Null/empty, пять типов, дроби и секунды. Финальный
`filter-node-complete` дополнительно требует save/reopen/reexecute без
переприсваивания свойств; его успех не выводится из unit tests или отчёта модели.
