# Фиксированные read-only probes Loginom для MVP

Checkpoint: 4 сентября 2026 года. Профиль
`loginom-7.5.0-alpha-build49202-macos-chromium-ru` относится к **frontend/UI build**
`7.5.0-alpha+build.49202`, macOS, Chromium и русскому интерфейсу. Это не утверждение
о версии серверного бинарного файла. Значение прочитано из статического
`bg/app/Version.js`; перед работой runtime сверяет `globalThis.bg.app.Version`.

Эти probes — фиксированный код клиента для указанной сборки. Они не являются
универсальными DOM-селекторами или новым API Loginom. Action definition не может
передать путь к свойству или исполняемый callback. Другой build, отсутствующий
объект, неверный тип либо несовпадение активного ModelForm с DOM графа останавливают
операцию. Изменение probe требует нового runtime и новой приёмки.

## Почему одного заголовка недостаточно

E2E `bg/selectors.ts:75` (`s.tabs.ActiveTabName`) выбирает подпись текущей вкладки.
В `bg/app/TabForm.js:324` и `:1580` она устанавливается из `DisplayName` текущего
узла дерева: для workflow это «Сценарий», а не имя пакета. `document.title`
формируется из логического navigation path (`ChangeBrowserTitle`, строки 95–122).
Поле имени файлового диалога подтверждает введённый запрос, но само по себе не
доказывает, какой пакет открыт после сохранения. В рассмотренных E2E-селекторах и
статических источниках не подтверждён DOM-атрибут, одновременно содержащий полный
файловый путь пакета и его привязку к активному workflow. Наличие общего `qtip` в
дереве не считается таким подтверждением.

Поэтому `package.save_as` после закрытия и открытия проверяет **полное точное
равенство нормализованного `PackageFileName` запрошенному пути** и равенство
снимка узлов/связей сохранённому checkpoint. Совпадение подстроки или basename
недостаточно. Подпись вкладки остаётся только диагностикой.

Для drag координата указателя сначала переводится относительно `cntDiagram`,
затем учитываются прокрутка, отношение текущего масштаба к начальному и сетка 8.
Проверка SVG учитывает масштаб и translation, а допуск ограничен округлением
отрисовки; добавлять целую ячейку сетки для сокрытия ошибки преобразования нельзя.

Fingerprint сравнивает структуру графа: идентичности узлов, направление и тип
портов, их количество и порядок внутри типа, а также все связи между конкретными
ordinal-портами. Числовые индексы сортируются как числа. Он не сравнивает внутренние
настройки узлов или данные пакета. Удалять числовые суффиксы без сохранения порядка
и пересчёта endpoint нельзя: это скрывало бы подключение к другому входу.

В обоих итоговых снимках связь одна: `Источник / Output_Data-0` → третий вход
данных «Объединения». Два исходных входа сохранились, появился ровно один новый;
дополнительных итоговых портов или связей относительно checkpoint приёмника не
обнаружено. У «Источника» до сохранения и после открытия одинаковые три порта:
`Input_Connection-0`, `Input_Var-1`, `Output_Data-0`. Полного снимка его портов до
соединения этот journal не содержит.

Суффикс `3` не означает четыре входа данных: источник `TestIdentifier` получает
индекс из всей коллекции направления, включающей порты других типов. Независимое
сопоставление этих двух реальных снимков по типу и ordinal сохранило все количества
и единственную связь на `Input_Data[2]`.

Trace строки 7 содержит **две попытки перетаскивания**, но не снимки между ними.
По этому run нельзя независимо утверждать, что первая попытка была no-op, или
исключить промежуточные мутации. Он подтверждает конечное изменение **2 → 3 → 3**,
а не историю каждого drag. Для следующего replay добавлено сохранение состояний
до каждой попытки, после drag и после стабилизации; его live-приёмка отдельна.
Этот старый run завершил `package.save_as` со статусом `AMBIGUOUS` и не считается
положительной приёмкой сохранения.

## Граница read-only и приёмки

Чтение `PackageFileName` возвращает локальное поле `FPackageFileName`; его штатно
обновляет сам Loginom при открытии и сохранении. Probe не обращается к
`modelPackage.FileName`, `bg.selectAsync`, сессии сервера или RPC, не вызывает
создание классов, загрузку модулей, изменение графа, сохранение и навигацию. Вся
мутация остаётся обычным взаимодействием Playwright с UI. `NodeType` с возможным
ленивым кешированием заменён проверкой типа; обход родителей ограничен и защищён
от циклов.

Статический source evidence и локальные behavioral tests не заменяют replay в
реальном Loginom через Hermes/Xiaomi MiMo 2.5. Положительная приёмка относится
только к точным runtime/manifest SHA и UI build, сохранённым в replay attestation.
