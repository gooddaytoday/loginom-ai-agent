# Закрытие пакетов после изолированного прогона RC

Статус: механизм реализован в интеграционной ветке и проверен на живом Loginom 7.4.2; все три совместных RC-сценария также прошли полный аудит на новом runtime. Пользователь 2026-09-14 уточнил, что read-only уведомление после повторного открытия связано с оставшейся предыдущей Loginom-сессией. Приёмка RC продолжается с этого места; закрытие уведомления само по себе не освобождает пакет предыдущей сессии.

## Проверенные источники

- `/Users/kartamyshev/Git/e2e-tests/bg/utils/serverApiMethods.ts:166`: E2E `serverApi.CloseAllPackages()` возвращает результат `bg.app.Application.Instance.FMainForm.FMapTree.CloseAllPackages(true, false)` через `ClientFunction`.
- `/Users/kartamyshev/Git/e2e-tests/bg/helpers/main.ts:437`: `AfterTest` ожидает результат закрытия, затем наблюдает исчезновение вкладок перед очисткой временных каталогов. В Live Mode этот cleanup пропускается.
- `/Users/kartamyshev/Git/e2e-tests/bg/helpers/packages.ts:118`: UI helper `ClosePackage` закрывает текущий пакет, по умолчанию отвечает «Нет» на сохранение. Такое неявное отбрасывание изменений не подходит для общего клиентского завершения.
- `packages/loginom-runtime/client/lib/bridge.mjs`: до этой доработки `close()` закрывал только MCP/браузерные транспорты и освобождал leases. Теперь явно включаемый cleanup выполняется перед закрытием транспорта.
- `unavailable:artifact-d759ae4fffada7c4`: существующая диагностическая последовательность закрывает собственную открытую копию через меню, проверяет исчезновение её вкладки и выполняет logout с проверкой аккаунта. Это не освобождает пакет в другой оставшейся сессии.

## Принятый порядок

Для выделенного браузера прогона завершать работу в исходной Loginom-сессии, до остановки её браузерного транспорта:

1. Дождаться завершения текущей операции; не инициировать закрытие работающего узла.
2. Получить подтверждение итогового `package.save_checkpoint`, проверить точный путь/пакет и отсутствие новых несохранённых изменений.
3. Сверить подготовленный документ, аккаунт и единственный открытый пакет с точным путём прогона. При постороннем пакете отказаться от очистки. Вызвать `FMapTree.ClosePackage(node, false, true)` для проверенного пакета; штатный `BeforeClosePackageNode` остаётся включён.
4. Дождаться результата вызова и фактического отсутствия пакетов в клиентском дереве/вкладках. Не считать одно закрытие окна браузера подтверждением освобождения пакета.
5. В тестовом аккаунте явно выйти из Loginom, дождаться формы входа и затем закрыть браузер. Следующий независимый прогон открывает пакет только после этой последовательности.

При ошибке сохранения или неизвестных несохранённых изменениях автоматическое отбрасывание запрещено. Для независимого чтения заранее допустимо удалить только его временные изменения визуализаторов, сохранив исходный пакет неизменным. При уже потерянном исходном браузере требуется восстановление именно своей прежней сессии либо адресное завершение подтверждённой своей серверной сессии; вызов в новой сессии не считается освобождением старой блокировки.

Программный вызов является внутренним API. Семантика флагов проверена по функции живого Loginom 7.4.2: `suppressEvents=true` отключает `BeforeClosePackageNode`, в том числе проверку `Session.IsPackageModified` и закрытие вкладок. Поэтому вариант E2E `CloseAllPackages(true, false)` не перенесён в клиент. Выбран адресный `ClosePackage(node, false, true)` с предварительной серверной проверкой изменений и запретом работающих узлов. Подтверждение освобождения — новое открытие сохранённого пакета без read-only. Общие пользовательские браузеры и другие аккаунты cleanup не затрагивает.

## Реализация и проверка — 14 сентября, после согласования

- `packages/loginom-runtime/client/lib/package-cleanup.mjs`: проверка origin/build 7.4.2, подготовленного документа/сессии, фактического аккаунта, единственного пакета, точного пути, read-only, запущенных узлов и `Session.IsPackageModified`. Закрытие через штатный native guard → исчезновение вкладки → повторная проверка аккаунта/пустого перечня пакетов → Logout → LoginForm.
- `--acceptance-cleanup-package` — явный параметр изолированного replay-клиента. Обычный запуск его не включает. `bridge.close()` требует успешную квитанцию сохранения назначенного пути, отказывается закрывать неразрешённые/незавершённые операции и сохраняет `package-cleanup.json` до остановки транспорта. При отказе сохраняются браузер и clipboard leases; повторный сигнал не повторяет неизвестное действие.
- `run.py` включает параметр для трёх совместных RC-сценариев. Неподготовленный listTools precheck пропускается без UI. Отсутствующая квитанция подготовленной сессии не считается успехом. Аудитор проверяет её связь с сохранением, документом, аккаунтом и журналом.
- Независимый читатель закрывает собственные временные визуализаторы с явным `diagnosticDiscard:true`. Этот режим отсутствует в CLI-настройке основного прогона; он отвечает «Не сохранять» только на точный вопрос о проверенном пакете и не подтверждает остановку процессов. Его действия не записывают диагностические изменения в исходный файл.
