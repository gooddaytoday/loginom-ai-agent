## Что исправлено

Полный Missing Values аудитор теперь различает создание и обновление импорта.
Для existing используется существующая строгая проверка seed→update:
ранний успешный импорт с проверенными байтами, точный node ref, одинаковые
document/workflow/runtime, порядок checkpoints, новое выполнение, настройки
и выходные данные. Метка берётся из проверенного исходного узла, когда
existing request законно не повторяет её. Удалять проверку метки или доверять
только итоговой сводке не потребовалось.

Проверка доставки вызывает этот existing verifier и сохраняет полный прежний
контроль загрузки/скачивания, digest, destination и lifecycle. Для нового
импорта и исторического explicit replay путь не изменён.

В existing verifier явно заданное сопоставление полей проверяется своим
полным ordered mapping proof. Сохранённый порядок подставляется только при
отсутствии нового mapping. Раньше оба способа задавались одновременно,
и нижний verifier правильно отвергал такой конфликт.
