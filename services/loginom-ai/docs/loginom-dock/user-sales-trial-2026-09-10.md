## Сбой и предел диагностики

`group-product-001` создал новый GUID `70c38e5e-b2a1-45bf-9d0e-ce7cfa740b4f`
на позиции 760/80. Затем rename запросил «Выручка по товарам»; graph readback
вернул **«Выручка потоварам»**. Драйвер не подтвердил постусловие и вернул
AMBIGUOUS/NODE_APPLY_STOPPED, phase=target, cleanup_complete=false,
«Graph effect needs reconciliation». Входная связь отсутствовала.

Это подтверждено native graph receipts. Вероятный механизм — склеивание строк
перенесённой подписи: `client/lib/node-target-browser.mjs:49` использует
`labelElements[0].textContent` с заменой NBSP, без границы между текстовыми
фрагментами. Перенос и фактическое сохранённое native имя не проверены отдельным
live replay; это гипотеза причины, а не установленный факт. Прямое окно завершённой
сессии через отдельный UI-инструмент получить не удалось. Пустое запущенное окно
не использовалось как подтверждение состояния черновика.

Hermes пробовал inspect, wait, resume, UI repair, recover, cancel и prepare;
защита pending operation не позволила новые изменения. Он корректно сообщил
«Не завершено», не выдал расчёт по CSV за завершённый Loginom сценарий.
В конце модель указала черновик Package1; надёжного persisted package path нет.
Последующая доступность несохранённого черновика не подтверждена.

Следующая инженерная проверка: воспроизвести длинную переносимую подпись и
сопоставить rendered fragments/native model label/GUID, затем проверить rename
reconciliation и bounded stop для recovery. Исправления и повторный пользовательский
опыт должны идти отдельно с новыми pins/метриками; исходный FAIL не переписывать.
