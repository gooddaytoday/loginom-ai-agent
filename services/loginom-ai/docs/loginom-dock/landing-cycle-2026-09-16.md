первой загрузки `voids` и для прогрева, не пересоздавая сцену синхронно.

## Дополнение: смена по клику

По последующему запросу пользователя поток переключается на следующий и по
клику, без перезагрузки. Нативная прозрачная кнопка над рисунком поддерживает
Enter/Space, а пауза и replay остаются отдельными кнопками. Контроллер
пропускает повторные клики до завершения текущего перехода.

После загрузки выбранной сцены браузер в свободное время подготавливает только
следующую: импортирует модуль, создаёт сцену и прогревает её кэши вне экрана.
Переход длится 700 мс с плавным смешиванием прозрачных кадров. Старый кадр
сохраняется как снимок; на переходе анимируется только новая сцена, уже с полным
потоком. Это ограничивает нагрузку одним рендерером частиц на кадр. Пауза
не сбрасывается; при reduced motion сцена меняется сразу. При скрытии,
выходе за экран или resize переход завершается без оставленного фонового цикла.

После успешного фэйда обновляются выбранная сцена, постер и следующая позиция
LocalStorage. Клик всегда следует за текущим рисунком в этой вкладке;
перезагрузка использует последнюю сохранённую очередь. Без LocalStorage
клики продолжают работать в пределах документа. Ошибка импорта/подготовки
не меняет текущую сцену и сохранённую позицию. Dispose отменяет отложенный
прогрев, обработчики и переход, предотвращает позднее изменение хранилища.

В браузере проверены полный круг кликов, сохранение паузы, Enter и продолжение
после reload. На фактических 1280, 721 и 375 CSS px горизонтального переполнения
и ошибок страницы нет. Холст остаётся в DOM во время смены; начальный и
конечный кадры просмотрены. Это локальная проверка предпросмотра, без
серверной сборки, публикации и гарантии производительности на всех устройствах.

Все семь landing test-файлов прошли. В `landing-cycle.test.mjs` теперь 28
проверок, включая быстрые клики, повторное использование подготовленной сцены,
ошибки и отмену отложенной работы. Новый `landing-transition.test.mjs` содержит
13 проверок: смешивание кадров, пауза, reduced motion, resize/скрытие,
отмена и освобождение временных холстов. Синтаксис изменённых модулей
и `git diff --check` проверены.

## Исходная реализация при загрузке

Пользователь выбрал объединение четырёх альтернатив: при каждой загрузке
страницы показывать следующую сцену по кругу с сохранением в LocalStorage.
Порядок фиксирован: clouds → glyphs → ribbons → voids → clouds.
Предыдущий workflow с объёмными узлами в этот цикл не входит.

## Реализация

- `landing/hero-selection.mjs` читает имя следующей сцены из единственного
  ключа `loginom-dock.hero.next-variant.v1`, проверяет его по списку и сохраняет
  следующую позицию. Пустое или некорректное значение начинает цикл заново.
- `hero-cycle.mjs` выбирает сцену один раз на документ. WeakMap отдельно
  защищает выбор и запуск одного root от повторов. Пауза/replay остаются
  внутри общего engine и не расходуют позицию очереди.
- Там, где доступен Web Locks, короткое чтение/запись сериализовано между
  вкладками. Блокировка освобождается перед динамическим импортом сцены.
- Выбранный постер и `data-variant` устанавливаются до lazy import; сбой
  загрузки/запуска оставляет соответствующий резервный кадр.
- `index.html` подключает общий entry и CSS четырёх сцен. Номерные подписи
  сравнительных вариантов не добавлены в основной интерфейс.
- `build.mjs` включает модули, CSS и постеры в будущую серверную сборку.
- `preview-variants.mjs cycle` запускает общий лендинг на 4173; без аргумента
  также запускаются фиксированные 4174–4177. Их entry не обращается к очереди.

Очередь относится к origin и профилю браузера, не передаётся на сервер.
Если LocalStorage запрещён, страница продолжает работать, но сохранение
следующей позиции недоступно. Без JavaScript показывается постер clouds.
Восстановление существующего документа из back-forward cache не считается
новой загрузкой. Случайный выбор, интервальное переключение и влияние
replay на очередь не используются.
