## Исправления

**R16-1 подтверждён live.** В собственной копии пакета файл A был заменён файлом B
по тому же пути. Старые import и exact вернули SUCCEEDED и значение
`9007199254740995` из B при сохранённом доказательстве A (`9aac…`, вместо `76da…`).
Доказательство: `unavailable:artifact-3a202e4a01dc7609` и
привязанные browser/journal записи.

Теперь executor предоставляет внутреннюю полную упорядоченную историю загрузок,
включая незавершённые и неопределённые записи. Import проверяет актуальность
выбранного upload до настройки; exact дополнительно сопоставляет историю с
порядковым номером выполненного импорта. Подтверждённая замена теми же байтами
допускается. Изменённые или неизвестные байты после выполнения запрещают старое
доказательство, даже если позднее старые байты восстановлены. Обнаруженные
операции с доказанным отсутствием записи не считаются перезаписью.

Свежая live-проверка stale A после B дала NOT_APPLIED, effect_possible=false,
cleanup_complete=true. Current B и восстановленный A успешно импортировались.
На итоговом runtime повторная загрузка тех же байтов после выполнения импорта
сохранила успешное полное чтение 60 ячеек. Отдельная подтверждённая перезапись
после выполнения дала отказ внутреннего exact gate.

В отдельной `unavailable:artifact-8ca547184f7db605` native upload завершил submit,
после чего операторский harness потерял ответ. Inspect/recovery/replay этого
upload не выполнялись. Private history сохранила transport_uncertain; production
import source lineage отклонила proofA. Использованы настоящий private completed
import и uploads из executor. Первый диагностический completedStaticImports
через callback самого импорта исключал текущую операцию и отказал раньше lineage;
он сохранён, но не считается доказательством этого условия. Финальное
свидетельство — `fixed-unknown-lineage-gate.json`. На сервере собственный CSV
после этой диагностики может содержать изменённые байты; сохранная копия пакета
не объявляется готовым неизменным fixture. Проверка сохранения выполнена раньше.

**R16-2 подтверждён live.** Повторное скачивание frontend-файла не доказывало,
какая функция уже загружена в документ. Теперь проверяются SHA-256 исходного
представления 53 конкретных критических функций, восемь констант заголовка и
идентичность используемых session/manager/transport/socket/message объектов.
Проверка повторяется вокруг чтения, для выделенных request/response и перед
публикацией. Старые хеши frontend остаются дополнительной проверкой.

Контролируемая обёртка DispatchMessageAsync на собственной странице отклонена
без RPC: счётчик 2585 → 2585. Новая привязка изменённой функции также отвергнута
по хешу; после восстановления подтверждены все 53 функции. Сервер и общий
frontend не менялись. Финальный журнал сохраняет несекретные binding_id;
проверка реального redactor предотвращает повторную потерю этого поля.

**R16-3 исправлен.** Типы описывают sample/full coverage, discriminated native
cells, exact_table, coverage/consistency/binding и оба вида output port.
Полный режим разрешён только Collapse. Локальный TypeScript 5.2.2 проверил
строгий клиент без приведения типов и три отрицательных случая; новые зависимости
не устанавливались. Числовые границы и форматы строк продолжает проверять runtime.
