# Лендинг Loginom Dock

Публичный сайт: <https://loginom-dock.duckdns.org/>. Инструкция и интерфейс — на
русском языке. Endpoint клиента остаётся `https://loginom.duckdns.org/mcp`.
Текущие образы, точный Compose и откат — в
[руководстве эксплуатации](../docs/loginom-dock/operations.md).

Статический HTML/CSS/JS без внешних скриптов и зависимостей. `release.json` задаёт
опубликованный выпуск, платформы и контрольные суммы; `build.mjs` проверяет эти
данные и формирует `dist/`. `instructions.mjs` связывает выбранные агент и систему
с одним архивом, суммой и набором команд. Исходная страница без JavaScript
содержит установку Codex/macOS и ссылки на полную инструкцию и Linux.

## Сборка на сервере

Из корня checkout на VPS:

```sh
docker build -f deploy/loginom-dock/Dockerfile.landing \
  --build-arg LOGINOM_DOCK_REVISION=FULL_COMMIT_SHA \
  -t loginom-dock:landing-COMMIT .
```

Builder Node и финальный Caddy закреплены digest в Dockerfile. Статика входит
в образ по пути `/srv/loginom-dock-landing`; generated `dist/` не входит в Git
и Docker build context. Перед развёртыванием проверить новый `Caddyfile.server`
командой `caddy validate` из собранного образа. Затем указать образ в
`LOGINOM_DOCK_CADDY_IMAGE` собственного `deploy.env` и пересоздать Caddy через
серверный Compose. Существующие TLS-тома сохраняются. Для отката вернуть
предыдущий образ и Caddyfile. Обычная резервная копия уже сохраняет образ Caddy.

Ссылки `/studio/connect` перенаправляются на `/#install` нового домена: Caddy
обрабатывает прямой запрос, маршрут Studio — переход внутри приложения.
При изменении этого маршрута нужно также собрать и развернуть Studio.

Перед публикацией: проверки селекторов в `client/test/landing.test.mjs`, серверная
сборка, визуальный просмотр сайта на широком и узком экране, проверка всех
сочетаний агента/системы, копирования, ссылок выпуска, примеров, HTTPS и старого
адреса. Публичные инструкции сверять с `client/INSTALL.md` и реализацией мастера.

`landing/release.json` — источник публичных ссылок и SHA-256. Для нового выпуска
обновлять его только после проверки GitHub assets, затем пересобирать Caddy image.
`web-studio/src/lib/dock-release.ts` остался от прежней страницы и больше не управляет
загрузками: маршрут Studio теперь перенаправляет на лендинг.

## Фирменный стиль и лицензии

- Палитра: [официальный брендбук Loginom](https://brandbook.loginom.ru/color/),
  основной `#A23938`, тёмный `#7D2B29`, текст `#333333`.
- Шрифт: [Source Sans Pro из брендбука](https://brandbook.loginom.ru/typographics/),
  неизменённые WOFF2 Regular, Semibold и Bold; OFL включена в
  `assets/LICENSE-SourceSansPro.txt`. Шрифты загружаются с самого сайта.
- `dock-mark.svg` — отдельный знак интерфейса Dock; он не подменяет логотип Loginom.
- `sales.csv` — учебный набор продаж по товарам и регионам для расчёта,
  группировки и сортировки выручки.

Ключей, учётных записей и форм отправки данных на лендинге нет. Описание общей
базы и границ архивации соответствует архитектуре Dock.

## Первый экран: четыре сцены по кругу

Основной `index.html` загружает `hero-cycle.mjs`. При каждой новой загрузке
документа выбирается одна сцена в фиксированном порядке:
скопления (`clouds`) → знаки (`glyphs`) → ленты (`ribbons`) → пустоты (`voids`) →
снова скопления. Клик по потоку (или Enter/Space на нём) выбирает следующую
сцену в том же порядке без перезагрузки. После первого кадра следующая сцена
загружается и подготавливается в свободное время браузера.

`hero-selection.mjs` хранит имя следующей сцены в LocalStorage под ключом
`loginom-dock.hero.next-variant.v1`. Очередь общая для вкладок одного origin
в этом профиле браузера. Пауза, повтор, resize и переходы по якорям её не меняют.
Успешный переход по клику сохраняет следующую позицию; перезагрузка продолжает
после него. Клик следует за видимой сценой, даже если другая вкладка уже
сдвинула очередь. Повторные клики во время подготовки или фэйда объединяются.
Первое посещение или повреждённое значение начинают цикл со скоплений.
При недоступном хранилище лендинг работает с доступным значением либо первой
сценой, но продолжение очереди между загрузками сохранить нельзя.

Сцены находятся в `variants/`; `engine.mjs` управляет появлением, паузой,
повтором, reduced motion и видимостью. `flow-interaction.mjs` задаёт мягкое
локальное следование за курсором с возвратом в поток. Ракурс фиксирован.
Появление занимает 2,6 секунды, рендер ограничен 30 кадрами/с и DPR 1,5;
вне экрана и в скрытой вкладке цикл останавливается. На узком экране частиц
меньше. При reduced motion выбранная сцена неподвижна. При ошибке Canvas или
модуля остаётся соответствующий постер, без JavaScript — постер скоплений.
Смена занимает 700 мс: старый кадр растворяется, новая сцена проявляется сразу
с полным потоком. Одновременно анимируется только новая сцена. Предварительная
подготовка следующего рисунка прогревает его кэш; временные холсты перехода
освобождаются после завершения. Пауза сохраняется при смене, reduced motion
переключает сразу. Ошибка подготовки сохраняет текущий поток и очередь.
Тяжёлая сцена `voids` готовит геометрию и первый невидимый кадр порциями
с бюджетом 6 мс между передачами управления браузеру. Это мягкий бюджет,
не гарантия времени кадра: отдельная операция и сборка мусора могут занять
больше. При dispose подготовка отменяется через AbortSignal. Первый вход
в `voids` тоже использует асинхронное создание геометрии. Обычный видимый
кадр рисуется целиком, без показа промежуточных частей.
Внешних библиотек, видео и запросов к сторонним сервисам нет; CSP сохранена.

Проверки: `client/test/landing-cycle.test.mjs`, `landing-transition.test.mjs`, `landing-variants.test.mjs`,
`landing-pointer.test.mjs`, `landing-voids.test.mjs` и `landing.test.mjs`.
[Порядок, реализация и проверки](../docs/loginom-dock/landing-cycle-2026-09-16.md).

## Локальные предпросмотры

Общий лендинг: `node landing/preview-variants.mjs cycle` →
`http://127.0.0.1:4173/`. Без аргумента команда запускает его и четыре
фиксированных предпросмотра для сравнения:

- `http://127.0.0.1:4174/` — скопления, ключ `clouds`.
- `http://127.0.0.1:4175/` — знаки, ключ `glyphs`.
- `http://127.0.0.1:4176/` — ленты, ключ `ribbons`.
- `http://127.0.0.1:4177/` — пустоты, ключ `voids`.

Фиксированные предпросмотры не читают и не меняют очередь. Один из них можно
запустить отдельно: `node landing/preview-variants.mjs voids`.
На каждом порту `/?static` показывает резервный постер без запуска анимации
и изменения очереди; `/art-only` показывает только визуализацию.

`build.mjs` включает все четыре сцены, постеры, CSS и модули выбора в `dist/`.
Изменение подготовлено локально; публичный сайт требует отдельной серверной
сборки и публикации.
