# Особенности запуска задач по расписанию

В некоторых случаях точное время запуска задачи может не гарантироваться. При высокой загрузке процессора задачи могут запускаться немного позже запланированного времени. Если задан очень маленький период запуска, например, менее одной секунды, то некоторые плановые запуски могут быть пропущены.

Время запуска указывается в текущем часовом поясе для [Loginom Server](../components-platform.md). При этом учитывается переход на летнее время для стран/регионов, где это применяется. То есть, если период запуска будет равен «1 час», то задача может выполниться 23 или 25 раз за сутки из-за перевода часов. А период запуска равный «1 день» из-за перевода часов может составить 23 или 25 часов.

Отдельно учитываются случаи, когда время запуска по расписанию приходится непосредственно на время перевода часов:

- Если запуск запланирован на «пропущенный» час при переходе на летнее время, то запуск произойдет в момент перевода часов. Например, если запуск запланирован на 02:30:00, и происходит перевод часов с 02:00:00 на 03:00:00, то задача будет запущена в 03:00:00.
- Если запуск запланирован на «продублированный» час при переходе с летнего на обычное время, то запуск произойдет только один раз: до перевода часов.

Повторный запуск задачи может быть запланирован на день, которого в месяце нет, например, на 30 февраля. При этом могут возникать следующие ситуации:

- Если первый запуск запланирован на 30 января, а период запуска равен «1 месяц», то следующие запуски будут 28 февраля, 30 марта и т.д.
- Если период запуска равен «1 день», а в фильтре по дням месяца выбран только 30-й день, то запуска в феврале не будет.
