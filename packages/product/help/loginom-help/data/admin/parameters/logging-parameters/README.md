# Параметры логирования

В серверных и настольных редакциях платформы формируется лог-файл — журнал регистрации, в котором фиксируется выполнение каждого узла, что позволяет в случае возникновения ошибки выявить ее местоположение и возможную причину.

Параметры данной группы задают правила формирования лог-файла.

Изменения вступают в силу после нажатия кнопки Сохранить.

Параметр | Значение по умолчанию | Описание
Тип логирования | Файл | Параметр позволяет выбрать тип логирования: Файл или journald. Для Windows данный параметр не настраивается, лог записывается в файл. Для Linux доступны оба варианта. При использовании логирования в journald используется только один настраиваемый параметр Уровень логирования, остальные становятся недоступными для редактирования.
[Уровень логирования](logging-levels.md) | Информация | Здесь указывается способ и полнота заполнения лог-файла (Трассировка, Отладка, Информация, Событие, Предупреждение, Ошибка и Авария)
Трассировка исключений | false | Включает/отключает отладочный режим работы. При включенном отладочном режиме в лог-файл записывается расширенная информация для диагностики ошибок. Формирование расширенной информации при отладочном режиме работы приводит к потере производительности, поэтому в обычном режиме работы трассировка исключений должна быть отключена. По умолчанию отладочный режим работы выключен.
Логировать имя пакета у узла | false | Если параметр имеет значение `true`, то в сообщение лога вместе c GUID-ом активируемого узла будет добавлено имя пакета, в котором этот узел находится. Имя пакета выводится в сообщениях лога о запуске активации и об успешной активации узла. В сообщениях лога о деактивация узла имя пакета не выводится. Логирование имени пакета снижает производительность. В сообщениях об ошибках имя пакета выводится всегда, вне зависимости от значения данного параметра.
Логировать количество строк при активации узла | false | Если параметр имеет значение `true`, то при активации всех узлов, имеющих выходной порт с табличными данными, в сообщение лога будет добавлено количество строк на выходном порте. Если параметр имеет значение `false`, логирование будет производиться только для тех узлов, у которых включён аналогичный параметр в настройках узла.
Логировать удаление файлов | false | Если параметр имеет значение `true`, то в сообщение лога записывается результат удаления файлов и папок. Для непустых папок дополнительно записывается информация о попытке удаления. Для идентификации файла или папки в логе указывается путь относительно файлового хранилища. Параметр доступен только в серверных редакциях Loginom.
Разрешать доменные имена | false | Если параметр имеет значение `true`, то в сообщение лога об успешной/неуспешной авторизации и о закрытии сессии будет добавлен параметр `CLIENT_HOST` с доменным именем пользователя
Имя файла | app.log | Параметр содержит имя лог-файла. Задается путем относительно папки Logs. По умолчанию для серверной редакции на Windows файл расположен по адресу `C:\ProgramData\Loginom\Server\Logs`, на Linux в виде службы — `/var/opt/loginom/server/Logs`, а при запуске в контейнерах Linux — `/var/opt/loginom-docker/server/Logs`. Для настольной редакции на Windows журнал сохраняется по адресу `C:\Users\<User>\AppData\Roaming\Loginom\Personal\Logs`, а на Linux — `$HOME/.loginom/community/Logs`.
Перезапись файла | false | Флаг пересоздания файла логирования при запуске приложения, вместо его дополнения. При значении true при каждом запуске лог-файл будет перезаписывать старый.
Максимальный размер файла | 10484760 | Максимальный размер лог-файла, задается в байтах. При превышении данного размера, файл сохраняется с расширением .1 и создается новый. Например, старый файл app.log при превышении указанного размера сохранится как app.log.1, а взамен ему будет создан новый app.log, где и продолжится ведение журнала.
Количество резервных файлов | 10 | Количество резервных копий, создаваемых при превышении максимального размера лог-файла. При превышении размера файла и создании нового файла логирования, старый файл получает расширение .1, со сдвигом старых сохраненных файлов на `+1: .2, .3, ..., .<максимальный индекс>`, старый резервный файл app.log.1 станет app.log.2, а если на момент добавления резервного файла уже был достигнут лимит, то самый старый файл лога удаляется. При значении < 1 старые файлы логов не сохраняются.
