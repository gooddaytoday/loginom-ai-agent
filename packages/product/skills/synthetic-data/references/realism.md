# Правдоподобные грязные данные

Грязный набор нужен, чтобы проверять аналитику и модели. Ошибки допустимы лишь настолько, насколько они встречаются в реальных системах: пропуск, опечатка, редкий выброс, потерянная строка. Абсурдное значение, которое ломает физический предел или строгий инвариант, генератор не выпускает.

Блок `realism` включай для каждого грязного набора. Без блока поведение прежнее, в том числе у пресета `retail`.

```json
{ "oneDefectPerCell": true, "maxDefectsPerRow": 2, "respectLimits": true }
```

- `oneDefectPerCell` — ячейка портится не больше одного раза. По умолчанию `true`, если блок задан.
- `maxDefectsPerRow` — не больше этого числа повреждённых ячеек в строке, от 1 до 20. По умолчанию 2.
- `respectLimits` — выброс, шум и `out_of_range` не выходят за `limits` колонки. Если `limits` нет, множитель выброса ограничен разумным пределом. По умолчанию `true`.

`limits` у колонки — это физическая граница, например возраст `0..120` или цена больше нуля. Обычные `min` и `max` задают только диапазон розыгрыша чистого значения.

Строгие правила и `compare` защищены всегда, даже без блока `realism`. Если порча ломает инвариант строки, она не применяется. Такая попытка попадает в `constraints.rejected_defects`, а не в `defects.csv`.

Ключ и атрибуты общей сущности защищены всегда: пропуск, шум, выброс и нечёткий дубликат их не меняют. Исключение — `orphan` на ключе. При заданном `realism` так же защищены колонки `lookup`, чтобы справочное значение не разъехалось с родителем.

`rule_violation` указывает таблицу, имя правила и долю. Он действует только на правило `severity: "soft"` и пишет это имя в `defects.csv`.

`drop` удаляет строки: потерянные записи или пропуски в ряду. Доля ограничена `rate`, хотя бы одна строка остаётся. Удалённые строки тоже перечислены в `defects.csv`.

`duplicate` с `mode: "fuzzy"` меняет один символ или единицу числа. `orphan` подставляет правдоподобный ключ, которого нет у родителя.
