# Уже написанный сценарий

Новый набор должен совпасть с тем, что сценарий уже импортирует: имена колонок, порядок, типы, разделитель, кодировку, заголовок и десятичный знак. Не добавляй колонки, которых нет во входе, если пользователь явно не просит расширить схему.

## Откуда взять схему

1. Пользователь приложил локальный `.lgp`. Вызови `synthetic_data_run` с операцией `inspect` и путём пакета. Ответ содержит `draft-spec.json` и `imports.json`: узлы импорта, тип Engine и имя файла из пакета, например `data.lgd`. Колонок в пакете нет, черновик с пустым `columns` сам по себе не проходит `generate`.
2. Сценарий открыт в профиле `loginom-automation`. После `loginom_dock_prepare` прочитай выход нужного импорта через `loginom_dock_node_read` или схему узла через `loginom_dock_action_describe`. Имена и типы бери из прочитанного выхода, не из догадки по подписи узла.

Дальше допиши `columns` и `output` в спецификации, вызови `validate`, затем `generate` с новым `name`, чтобы не столкнуться с уже выпущенным набором.

## Как вложить результат

Сообщи абсолютные пути файлов данных и попроси приложить их следующим сообщением. Для CLI перечисли `--file`. `manifest.json` и `defects.csv` приложи только если задача — проверить очистку или найти ошибки.

Пока файлов нет в `input_artifacts`, не вызывай `loginom_dock_artifact_deliver` и не подставляй путь генератора как серверный путь. После подтверждённого вложения добавь или замени импорт в сценарии через `loginom-automation`: текстовый импорт получает настройки из `output`, XLSX и JSON — соответствующий узел импорта из каталога. Сверь прочитанный выход с `manifest.json`: число строк и имена колонок.
