# Пресет retail

`generate` с `preset: "retail"` разворачивает обычную спецификацию. Параметры передаются строкой JSON в `params`. Все поля необязательны.

| Параметр | По умолчанию | Предел |
| --- | --- | --- |
| `stores` | 3 | 1..12, имена Центр, Север, Юг, Запад, Восток, далее «Магазин N» |
| `year` | 2024 | 1990..2100 |
| `products` | 40 | 1..5000 |
| `salesPerStore` | 200 | 1..20000, произведение со `stores` не больше 100000 |
| `seed` | 1 | как в спецификации |
| `format` | `csv` | `csv`, `xlsx`, `json` |
| `defects` | `true` | `false` отключает порчу |

Набор:

- `products.<формат>` — `sku`, `name`, `category`, `price`.
- `sales-<магазин>.<формат>` — продажи за год, по файлу на магазин. Колонки `sale_id`, `date`, `store`, `sku`, `qty`, `price` из справочника, `amount = qty * price`.
- `warehouse.<формат>` — один остаток `stock` на каждый `sku`.
- `logistics.<формат>` — дата, товар, склад «Склад», магазин, количество.

При `defects: true` в продажах есть пропуски количества, выбросы и несогласованные суммы, опечатки в магазине, точные дубликаты строк и ссылки на отсутствующий `sku`. Доли маленькие: 0.03, 0.02 и 0.01. Точный перечень — в `defects.csv`.

`validate` принимает только файл спецификации, не пресет. Чтобы изменить розничный набор, запиши JSON по этому составу, поправь объёмы, колонки или дефекты и вызови `validate`, затем `generate`.
