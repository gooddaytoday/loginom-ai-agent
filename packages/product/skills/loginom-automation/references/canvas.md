# Граф, узлы и ссылки

Для каждого типа узла прочитай его схему через `loginom_dock_action_describe`.
Узлы создаёт и настраивает `loginom_dock_node_apply`; нужные входы описываются
через `inputs`. Положение можно оставить runtime. Не подбирай data-tid,
координаты, clipboard или внутренние GUID вручную.

`target.kind=new` создаёт новый узел. Для изменения уже завершённого узла
используй `target.kind=existing`, выданный `target.ref` и новый operation ID.
`inputs:[]` сохраняет существующие связи. Ссылки узлов сохранённого пакета
содержат постоянный GUID, а не отображаемое имя. Document/workflow identity
бери из актуальной подготовки. Не восстанавливай tab_tid и navigation_path.

Для продолжения передавай `loginom_dock_node_resume` только исходный operation
ID. Для свежего выполнения и чтения подтверждённого узла используй
`loginom_dock_node_read` с `source_operation_id` успешной локальной операции.
Этот инструмент не принимает формулы и не открывает мастер настройки.

Сверь readback настроек, связи и выходные схемы с заданием. Условие
`sample_complete=false` означает неполную таблицу. Точное чтение чисел,
согласование категорий CrossTable и ограничения полного чтения описаны в
[порядке работы](workflow.md). Число видимых элементов графа не доказывает
правильность связей или вычислений.
