# Переменные в таблицу — в столбцы и в строки

<!-- mode: columns rows -->
Для преобразования набора переменных в одну строку таблицы выбирай
`dock_node_apply`, `target.type:"variables.to_table"`, `mode:"columns"`,
`parameters:{}`. Каждая переменная становится отдельным типизированным полем
табличного выхода 0. Имена, метки, типы и порядок берутся из источника.

Сначала найди или открой заданный пользователем источник переменных в текущем
сценарии. Проверь выданный графом выход `variable_outputs` и используй его NodeRef в
`variable_inputs:[{source:NodeRef,output:наблюдённый_номер,input:0,kind:"variables"}]`,
при `inputs:[]`. Готовый Калькулятор переменных не перенастраивай: его тип в графе
может быть иконкой `bg-vendor-icon-calcvariables`, а не типом Калькулятора таблиц. Номер выхода копируй из наблюдения:
у «Переменных сценария» несколько разных выходов. Табличный или управляющий порт
не заменяет набор переменных. Готовый fixture можно открыть как заданный пакет;
если источник — «Переменные сценария», выбери пользовательский порт 4; его
снимок доступен через `dock_node_read` с `read.variable_ports:[4]`.

Значения и формулы принадлежат источнику. Не создавай вместо преобразования
Калькулятор таблиц или JavaScript с переписанными константами. Не передавай
`variables`, `expressions`, `local_variables`, `bindings` или `layout` в параметры
этого узла. Для сохранения исходного порядка оставь `mappings:[]`.

Используй `finish:"execute"`, `read.ports:[0]`, достаточный `sample_rows` и
`require_exact_numbers:true`, затем дождись завершения той же операции.
Проверь всю строку, имена, метки и типы; NULL, пустая строка, FALSE и 0 различны.
Дата — гражданское время до миллисекунд, без добавления часового пояса.
Не утверждай точность, если чтение её не подтвердило.

`finish:"done"` применяет настройки без доказательства вычисленного результата;
`finish:"close"` отменяет черновик. Для повторного чтения завершённого узла
используй `dock_node_read` с его успешным `source_operation_id`, а не новый узел.
Сохраняй пакет отдельным `package.save_checkpoint` и проверь квитанцию сохранения.

Для списка «имя, метка, значение» выбирай тот же `dock_node_apply`,
`target.type:"variables.to_table"`, `mode:"rows"`, `parameters:{}`, `inputs:[]`
и явный `variable_inputs` выше. Выход 0 содержит `Name string`,
`DisplayName string`, `Value variant`: одна строка на переменную в исходном
порядке. Оставь `mappings:[]`, чтобы сохранить эти три поля.
Укажи `sample_rows` не меньше числа переменных (до 100),
`require_exact_numbers:true`; проверь `cell_type` каждого Value, включая NULL,
и точную гражданскую дату с миллисекундами. Не своди Variant к тексту и
не подменяй этот режим Калькулятором или JavaScript.

Поддерживаются непустые исходные наборы integer, real, boolean, string,
datetime и типизированный NULL. Сохранённый узел выполняй в его текущем режиме.

Смена режима и правка источника делаются на том же узле, новый преобразователь
не создаётся. Для «в строки» или обратно «в столбцы» вызови `dock_node_apply`,
`target:{kind:"existing",ref:NodeRef}`, `type:"variables.to_table"`, нужный
`mode`, `parameters:{}`, `mappings:[]`, прежний `variable_inputs` и
`finish:"execute"`. Связь и её порты остаются; GUID узла не меняется. Если в
запросе есть `mappings` при смене режима, будет отказ до изменения: выход
пересоздаётся, настраивай соответствие отдельным вызовом. Изменение,
удаление или добавление переменной делай в самом источнике (его узел,
`target.kind:"existing"`), затем снова выполни тот же преобразователь и
прочитай выход 0 целиком: порядок, схема, значения, NULL ≠ пустая строка.
После добавления и удаления набор и порядок берутся из источника.
Variant на входе и пустые наборы требуют отдельного назначения.
