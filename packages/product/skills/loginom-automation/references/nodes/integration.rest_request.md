# REST-запрос (`integration.rest_request`)

## Режим request — методы и тело

Для POST/PUT/PATCH/DELETE выбирай `dock_node_apply` с
`target.type:"integration.rest_request"`, `mode:"request"`, `finish:"execute"`.
В `parameters.connection` укажи `name`, `base_url`, `method`;
для каждого метода создай отдельное подключение с уникальным именем.
Для POST/PUT/PATCH задай `request_content_type:"application/json"` (или
`"text/plain"`) в connection и `parameters.body_field:"Body"` — имя
наблюдённого строкового поля входа 0. Каждая строка отправляется отдельно.
Body передаётся как исходный текст UTF-8; привязка к query для него запрещена.
DELETE не принимает body_field и request_content_type. Передай исходную
таблицу в `inputs`, даже при `query_parameters:[]`, чтобы запросов было по
одному на строку. Query и Body сохраняются вместе, кодируется только query.
Для отправки HTTP используй REST-запрос. Если нужны исходные ответы, сохраняй
Response без разбора JSON, JS и Калькуляторов. Method бери из исходной метки
метода; RowID сопоставляй с нативным RequestID (индекс строки с нуля).
Статус читай с порта 1. Соединяй результаты по RequestID; восемь строк
четырёх методов можно собрать Объединением. Сохрани пакет после чтения.
На существующем узле `parameters:{}` сохраняет метод и тело без перенастройки.

При сборке нескольких методов сохраняй промежуточные технические поля:
для Join и Union передавай `mappings:[]`. Порты 0 и 1 каждого REST соединяй
по RequestID, затем объединяй ветви. Исходный RequestId присоединяй по
наблюдённому индексу строки; оставь Response и фактический HttpStatusCode.
Для выгрузки исходных ответов присоедини исходную таблицу по RowID/RequestID,
выбери её метку соответствующего метода как Method, сохрани RowID, Response
и HttpStatusCode. Имена и исключения настрой выходным mapping последнего Join;
одинаковые четыре поля ветвей объединяй Union без вычислений.
В `mappings[].changes` исключаемому полю задавай только `source` и
`excluded:true`: не переименовывай его одновременно через name или label.

Для нового Union достаточно `target:{kind:"new",type:"transform.union_data"}`:
метку и position опускай, если пользователь их не назначил. Если операция
вернула созданный узел и подтверждённый `cleanup_complete:true`, а настройка
не завершена, используй новый operation_id и `target.kind:"existing"` с тем
же type/ref и исходными inputs, без label. Не создавай второй такой узел
и не повторяй старый жест или operation_id. При неподтверждённой очистке
сначала выполни предложенный инструментом release/recovery.

## Режим request — ответы GET

Если нужны только HTTP-статусы и ошибки REST, выполняй с read.ports:[1]:
HttpStatusCode, ErrorCode и ErrorDesc находятся на порту 1. Порт 0 читай,
когда задаче нужны тело ответа или его разбор; код 200 не подтверждает тело.

GET по полному URL без query-параметров допустим: `query_parameters:[]`, `inputs:[]`,
`finish:"execute"`; входная таблица и URL-кодировщик не нужны.

Запрашивай небольшие ответы: только нужные поля (`select`), страницы
с `limit/skip` по контракту сервиса. Не запрашивай gzip. HTTP 200 сам по себе
не доказывает получение тела. При ErrorCode ≠ 0 и пустом Response сообщи
в итоговом ответе код REST_RESPONSE_BODY_MISSING и подсказку:
«тело ответа не получено: повтори запрос или уменьши ответ (select, limit/skip)».
Не повторяй запрос самостоятельно без просьбы пользователя.
