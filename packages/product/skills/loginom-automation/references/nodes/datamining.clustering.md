# Кластеризация (`datamining.clustering`)

## Кластеризация k-means

Используй `target.type:"datamining.clustering"`, `mode:"k_means"`, вход 0.
Для нового узла задай `features:[{kind:"input_field",name:"X"},...]` только для
непрерывных числовых признаков и `clusters` (2…1000). Идентификаторы оставь
вне features: они сохранятся в выходе. `seed` (0…2147483647) по умолчанию 42.
`normalization:"none"|"standardize"` применяется ко всем выбранным признакам;
standardize нужен для разных единиц или по просьбе пользователя. Это нативная
стандартизация по выборочному SD. Константный признак принимается Loginom.
Новый узел по умолчанию использует none; существующий сохраняет одинаковую
поддерживаемую нормировку при пропуске параметра. Для смешанной настройки
нужен явный выбор метода.

`finish:"execute"` обучает текущий вход, затем выполняет узел. Читай оба порта:
0 — исходные строки, Cluster и Distance; 1 — центры в исходных единицах.
Distance при standardize использует нормализованные единицы. При отказе
активации входа обработчик останавливается до обучения/Execute: исправь NULL
или некорректные значения, не подменяй их нулями. Для изменения параметров
обращайся к тому же existing узлу. Другие нормировки, g-means и применение
сохранённой модели к новым данным в этом срезе не поддерживаются.

## Кластеризация

Для k-means по признакам в разных единицах либо по просьбе пользователя задай
`normalization:"standardize"` в параметрах Кластеризации: штатная стандартизация
использует выборочное SD. По умолчанию нового узла — `none`; у существующего
пропуск параметра сохраняет одинаковую поддерживаемую нормировку полей.
Центры порта 1 возвращаются в исходных единицах, Distance порта 0 — в масштабе
нормализованных признаков. Читай оба порта. Seed фиксируй для повторяемости;
номера кластеров — метки, а не ранги. Другие нормализаторы не поддерживаются.
