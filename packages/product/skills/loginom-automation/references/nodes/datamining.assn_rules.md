# Ассоциативные правила

<!-- mode: fp_growth -->
Используй узел `datamining.assn_rules`,
режим `fp_growth`: один основной вход с дискретными строковыми полями
`transaction_field` и `item_field`, по одной позиции покупки на строку.
Параметры `min_support_pct` и `min_confidence_pct` задаются в процентах;
`max_items=2` или `3` ограничивает общее число элементов набора и правила,
включая условие и следствие. `max_consequents=1` или `2` ограничивает
следствие и должен быть меньше `max_items`; для нового узла по умолчанию 1.
`min_lift` — минимальный лифт как отношение, не процент;
по умолчанию 0. Для нового узла
нужны все пять параметров. У существующего пропущенные значения сохраняются.

`dock_node_apply` с `finish:execute` явно обучает текущий связанный вход, дожидается завершения и выполняет узел. Повторный Execute переобучает. Вспомогательный вход и фильтры выбранных элементов не поддерживаются.
Для сравнения порогов сначала выгрузи оба порта, затем передай
`target.kind:existing` и ref того же узла, `parameters:{min_lift:<новый порог>}`,
`inputs:[]`, `mappings:[]`, `finish:execute`. Это явно переобучает узел;
читай и выгружай оба свежих результата. RuleID после фильтра перенумеровывается.
Одиночные наборы включены.
Для исключения слишком частых товаров задай `exclude_support_above_pct`,
процент от 0 до 100. Исключаются товары с поддержкой строго выше порога,
затем из оставшихся строятся наборы и правила. `null` выключает исключение;
у существующего узла пропуск сохраняет порог и состояние. После изменения
выполни `fp_growth` того же узла и выгрузи оба результата.
После открытия сохранённого пакета переобучите узел (Teach): без переобучения
Loginom 7.4.2 пересчитывает наборы без исключения; правила и настройки сохраняются.
Не подменяй NULL пустой строкой или нулём. Поля покупок не содержат NULL/пустых ID и товаров.

Выбирай этот узел для частых наборов и правил. Выходы: 0 — наборы, 1 — правила, 2 — «Применение правил», рекомендации
недостающих товаров для текущего входа. Для правил и рекомендаций
укажи `read.ports:[1,2]`, `sample_rows:100`, `require_exact_numbers:true`.
Порт 2 сохраняет RuleID соответствующего правила порта 1, Support/Confidence/Lift,
поле `transaction_field` и товарные поля условия/следствия. Читай полные значения,
типы, NULL и native-порядок всех полей. Рекомендация относится к отсутствующему
в покупке следствию. Равноценные правила самостоятельно не ранжируй.
Для каждой таблицы создай Экспорт текста с нужного порта: `output:1` или
`output:2`, все поля в прочитанном порядке. Поддержку и достоверность не вычисляй по округлённому отображению.
Имена товарных полей производны от выбранного `item_field`: суффиксы `_0`, `_1`
и при длине 3 `_2` у наборов; `_0_A`, `_1_A`, `_0_C`, `_1_C` у правил
с двумя следствиями. У нового узла длины 3 поля сгруппированы A/A/C/C;
после изменения длины возможен порядок A/C/A/C. Сохраняй прочитанный native-порядок
конкретного узла; недостающие позиции — NULL.
Сохрани пакет отдельно после экспорта.
<!-- /mode -->

<!-- mode: apply -->
Для новых покупок используй тот же `datamining.assn_rules` с сохранённой
моделью. Замени файл того же Импорта на holdout и выполни Импорт.
Вызови `dock_node_apply`: `target.kind:existing`, ref обученного узла,
`mode:apply`, `parameters:{}`, `inputs:[]`, `mappings:[]`, `finish:execute`,
`read.ports:[1,2]`. Узел читает настройки, закрывает мастер без сохранения
и выполняет модель без обучения. Порт 1 сохраняет правила и метрики train;
порт 2 содержит рекомендации новым покупкам. Выгрузи оба порта, сохрани пакет.
После открытия пакета снова используй `apply`. Для переобучения — `fp_growth`.
<!-- /mode -->
