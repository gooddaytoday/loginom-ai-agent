# Сглаживание (`preprocessing.smoothing`)

<!-- mode: hodrick_prescott -->
## Сглаживание Ходрика–Прескотта

Для сглаживания ряда Ходрика–Прескотта используй `dock_node_apply` с
`target.type="preprocessing.smoothing"`, `mode="hodrick_prescott"` и
`parameters.smoothing:[{field:"X",lambda:1},{field:"R",lambda:1}]`.
Для каждого непрерывного integer/real поля укажи ровно одно из `lambda`
(0.0625…102659800000000) или связанного `period` (2…20000).
Входной порядок строк задаёт последовательность ряда; исходные значения и NULL
сохраняются, добавляются real-поля X_S/R_S. Для этой операции выбирай Сглаживание;
Калькулятор и JavaScript для вычисления тренда не нужны. Новый узел требует полный
список правил; на существующем пропуск `smoothing` сохраняет настройки,
`smoothing:[]` выключает обработку всех полей. Выполняй `finish:"execute"`,
`read.ports:[0]`, без обучения. После замены файла выполни прежний узел;
не пересоздавай его. All-null может дать нативную ошибку алгоритма, её нужно
сообщить пользователю. Для точного порядка полей используй существующий
`mappings:[{direction:"output",port:0,autosync:false,fields:[...]}]`, перечислив
все исходные и сглаженные поля через `source:{kind:"configured_field",name:...}`
в запрошенном порядке. Естественный autosync-порядок может измениться при новом
открытии. Вейвлеты в этом режиме не поддерживаются.

Для тренда Ходрика–Прескотта выбирай `preprocessing.smoothing` / `hodrick_prescott`; перед настройкой прочитай [детали параметров, NULL и выходов](preprocessing.smoothing.md). Не заменяй узел Калькулятором или JavaScript.
После замены файла выполняй прежний узел, не пересоздавай его.

## Вейвлет Хаара

Для вейвлет-сглаживания Хаара (Добеши порядка 1) выбирай `dock_node_apply`,
`target.type:"preprocessing.smoothing"`, `mode:"wavelet"`,
`parameters:{smoothing:[{field:"X",family:"daubechies",order:1,depth:1,boundary:"symmetric"}]}`.
Глубина `depth` — 1 или 2, границы — симметричные. Используй этот узел для
сглаживания, не вычисляй вейвлет через Калькулятор или JavaScript.
Обрабатываются только перечисленные непрерывные integer/real поля;
исходные значения и порядок строк сохраняются, добавляется вещественное X_S.
Используй вход без NULL; интерполяция пропусков не подтверждена.
Новый узел требует правила; на существующем пропуск `smoothing` сохраняет
настройки, `smoothing:[]` выключает обработку. Меняй глубину на том же узле,
не пересоздавай его. `finish:"execute"`, `read.ports:[0]`, обучение не нужно.
Для явного порядка полей обязательно задай
`mappings:[{direction:"output",port:0,autosync:false,fields:[...]}]`:
каждое поле с `source:{kind:"configured_field",name:"RowID"}` (аналогично
X, Tag и X_S) в нужном порядке. Autosync может менять порядок после reopen.
Прочитай полный выход, экспортируй CSV с исходными типами и сохрани пакет.
