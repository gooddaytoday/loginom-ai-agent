# Импорт из базы данных (SQLite)

<!-- mode: table sql -->
Получай parameter_schema через dock_action_describe(node_types:["imports.database"]).
Это узел «Импорт > База данных»: данные из файла SQLite `.db` в хранилище. Не заменяй
его Калькулятором, JavaScript или текстовым импортом и не выгружай базу в CSV.

- `parameters.database.database_path` — точный путь файла в хранилище (`/папка/people.db`).
  Обработчик сам создаёт или переиспользует подключение SQLite модуля по этому пути,
  тестирует его и связывает с портом «Подключение». Отдельный узел подключения не создавай.
- `mode:"table"` + `database.table` — таблица или представление целиком: все поля
  в исходном порядке. Порядок строк не гарантирован.
- `mode:"sql"` + `database.sql` — ровно один SELECT. Выбор, переименование и порядок
  полей задавай в SELECT, порядок строк — `ORDER BY`.
- Узел без табличных входов: `inputs:[]`, `finish:"execute"`, `read.ports:[0]`.
- Типы выхода следуют объявленным типам столбцов: INTEGER → целый, TEXT → строка,
  REAL → вещественный, BOOLEAN → логический, DATETIME → дата/время. NULL остаётся NULL,
  пустая строка — пустой строкой; не заменяй пропуски нулями.
- Существующий узел с `parameters:{}` сохраняет настройки; Execute читает базу заново.

Отклоняются до изменений: не-SELECT, второй оператор, комментарии, параметры `:имя`
и макросы `%имя%`, фильтры мастера, тайм-аут, «Игнорировать ошибки», подмножество полей
в режиме table (используй sql), другие СУБД. Ошибка теста подключения означает, что файла
нет по этому пути или это не база SQLite: проверь путь, не создавай пустую базу.
