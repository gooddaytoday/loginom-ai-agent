# Соединение таблиц по позиции

<!-- mode: positional -->
Используй `transform.col_union_data`, mode `positional`, для двух или трёх таблиц. Выбирай этот узел, когда пользователь соединяет записи по позиции.
Запроси карточку типа через `dock_action_describe`. Вход 0 — главная таблица,
вход 1 — первая присоединённая, необязательный вход 2 — вторая. Строки сопоставляются по позиции; порядок входов важен.
Прочитай все источники перед настройкой. Выход 0 сохраняет поля всех входов,
в том числе одноимённые. Читай реальные имена; для нужного порядка/переименования
задай полный выходной mapping с `autosync:false`. Не угадывай суффикс коллизии.

`parameters.col_union.row_count`: `minimum`, `maximum` или `input`.
Для `input` обязательно `determining_input:"main"`, `"attached"` или `"third"` (при входе 2).
`padding`: `null` — пропуски; `repeat` — циклически весь короткий набор;
`last` — последняя запись. Пустой набор нечем повторять: его поля дают NULL.
Существующие NULL сохраняются; пустая строка, 0 и false — отдельные значения.

Новый узел требует ровно 2 или 3 источника на входах 0,1 либо 0,1,2 и явные row_count/padding.
У существующего `parameters:{}` сохраняет поддерживаемые настройки.
Проверь компактный readback: режим, правило размера, дополнение, выбранный
вход, все фактические связи и выходной mapping. Execute пересчитывает текущие
входы без обучения. Прочитай все строки выхода 0, затем сохрани пакет.
Для промежуточного результата используй `dock_node_read`; `exports.text`
создавай для явно названного пользователем CSV.
Для трёх непустых входов доступны maximum/repeat и определитель third.
Повторное открытие: выполни тот же существующий узел с `parameters:{}`,
`inputs:[]`, сохраняя все связи и mapping. Несопоставленные и повторные входы
отвергаются до мутации. Переменные, пустые случаи трёх входов и apply не поддержаны.
