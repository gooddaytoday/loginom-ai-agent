# Таблица в дерево

<!-- mode: manual_structure -->
Прочитай карточку trees.from_table и полную схему параметров до настройки.
Сначала выполни и полностью прочитай табличный источник. Используй его точные
технические имена, типы и порт 0. Задай manual_structure: полный список nodes
в порядке родитель → дети, с точными JSON Pointer путями без индексов массива.
Корень Root — object; одна ветвь object array; допускается один вложенный object.
Для каждого скаляра укажи source_field, контейнерам его не задавай. Метка равна
имени. Порядок списка определяет порядок детей, а не порядок колонок источника.

Правило: одна входная строка — один элемент массива в исходном
порядке. Повторный OrderID не означает группировку. Нельзя молча выполнять агрегацию или удалять дубли.
NULL отличается от пустой строки, 0 и false. Int64 читай точно, десятичным текстом;
не преобразуй 9007199254740993 в Number. Выход 0 — дерево: прочитай его полную
схему и экземпляры с типами, а не только конечную JSON-строку.

Новый узел требует всю структуру. Для существующего parameters:{} сохраняет её;
явный nodes заменяет весь список. Done подтверждает настройки, Execute — новое
выполнение и чтение. Сохрани пакет отдельно после чтений. Не повторяй неизвестный
эффект. XSD, произвольные массивы, группировка, даты, Variant и переменные
отклоняются до изменения UI. Пустой вход пока не поддерживается.

По запросу построить дерево из строк выбирай `dock_node_apply` с `target.type:"trees.from_table"`, `mode:"manual_structure"`. Получи карточку `dock_action_describe` с `node_types:["trees.from_table"]`; её `parameter_schema` задаёт `nodes`. Дерево читает сам узел с `read.ports:[0]`.
