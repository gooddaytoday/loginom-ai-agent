# Группировка (`transform.group_data`)

<!-- mode: aggregate -->
## Группировка

Меняя `measures` existing Группировки, задай полный `group_by` и связь входа 0 в `inputs`.
Удаление полных дублей = Группировка по всем полям без мер (`measures: []`).

## Медиана

Медиана группы — `function: "median"` в `measures` этого же узла Группировки (не Калькулятор и не JS). Поле-источник — целое (integer); результат вещественный (real). NULL пропускаются, группа только из NULL даёт NULL. Выходное имя и метку задай в `name`/`label` меры. Для пары «исходное поле + медиана» используй две меры на одно поле с разными `name`.

## Мода, стандартное отклонение, пропуски

В `dock_node_apply` выбирай `type: "transform.group_data"`, `mode: "aggregate"` и `parameters.measures`:
- мода — `function: "mode"`, вход integer/string, выход того же типа; NULL не участвуют, полностью NULL даёт 0 для integer и пустую строку для string;
- стандартное отклонение — `function: "stddev"`, вход integer, выход real; выборочное, без NULL; одно непустое значение даёт 0, полностью NULL — NULL;
- число пропусков — `function: "null_count"`, вход integer/string, выход integer; пустая строка не считается пропуском.

Эти агрегаты выполняй Группировкой. Для каждой меры укажи `field: {kind: "input_field", name: "имя источника"}`, `function`, выходные `name` и `label`. Перед применением прочитай актуальную карточку через `dock_action_describe`. Для повторной настройки того же узла передай полный `group_by`, полный `measures` и связь входа 0 в `inputs`; `parameters: {}` сохраняет поддержанные настройки. Native-суффиксы нескольких функций — Mode, Std и Null.
## Первое, последнее, единственное, список

В том же `dock_node_apply` (`transform.group_data`, `aggregate`) выбери меру:
- `first` / `last` — первое / последнее значение в исходном порядке, включая крайний NULL;
- `only` — единственное различное значение группы; повторы допустимы, разные значения дают NULL;
- `concat` — список без NULL; пустой текст сохраняется, полностью NULL даёт пустую строку.

Вход этих четырёх функций — integer/string. Первые три сохраняют тип источника, список всегда string. Не подменяй их Калькулятором или JavaScript и не сортируй вход перед first/last. Имена и метки результата задавай в `name`/`label` каждой меры.

Только у `function: "concat"` обязательно задай `concat: {separator: "|", wrapper: "\"", unique: false, order: "none"}`. `wrapper` — пустая строка, двойная или одинарная кавычка; для чисел без ограничителя используй пустую строку. `order: "none"` сохраняет исходный порядок, `ASC`/`DESC` сортируют значения; `unique: true` удаляет повторы. Настройки относятся к одному исходному полю, не ко всем мерам узла. Для нескольких состояний перенастраивай тот же узел полными ключами, мерами и входом 0, после каждого Execute читай весь результат и выгружай отдельный CSV; Save сохраняет финальное состояние.
## Кэш и сортировка результата

В `dock_node_apply` этого же узла (`transform.group_data`, `aggregate`) задай `parameters.cache_groups: true/false` для кэширования значений групп и `parameters.sort_result: true/false` для сортировки по ключам `group_by` по возрастанию. Сортировка относится к ключам, не к агрегатам; при false порядок групп не задан. Используй Группировку.

На existing можно передать только нужный переключатель, сохранив ключи, меры и mapping; пропущенный переключатель сохраняется. Передай `inputs: []`, `mappings: []`, `finish: "execute"`, прочитай `configuration.readback.options.pedDimCache.value` / `pedSortResult.value` и полный результат.  Для сравнения выкл/вкл выполни оба состояния на том же узле и выгрузи CSV каждого состояния. При повторной полной настройке сохрани итоговый переключатель; Save сохраняет финальное состояние, после открытия Execute с `parameters: {}` выполняет сохранённую настройку.
