# Замена (`transform.replace_columns`)

<!-- mode: exact regex -->
## Тип результата Замены

Для точного словаря строковых/числовых ключей с типизированным результатом
выбирай `transform.replace_columns`, `mode:"exact"`. В каждом правиле `type`
остаётся типом входного поля; дополнительный `result_type` задаёт тип
`pairs[].to` и `other.value`: `string`, `integer`, `real`, `datetime`.
Без `result_type` тип результата равен входному, прежние правила сохраняются.
Например, `type:"string", result_type:"integer"`, пара
`from:{type:"string",value:"12"}, to:{type:"integer",value:12}`.
Ключи сравниваются по прежним правилам: строки требуют `case_sensitive`,
числа — `precision≥0` (2 знака): допуск включительно, ближайший, tie→больший; >0: real `_Delta=ключ−вход`. Даже при числовом результате строковый ключ не требует precision.
Это таблица соответствий, а не автоматический разбор произвольного текста:
незаданный ключ, включая числовую строку, подчиняется `other`.
При другом типе задавай `other:{mode:"null"}` или типизированное `value`;
`keep` создаёт в Loginom Variant и здесь отклоняется. `datetime` поддерживает
`other:null` и константы локального ISO `YYYY-MM-DDTHH:mm:ss`, без зоны и долей секунды.
Неподошедшее значение и исходный NULL при `other:null` дают NULL и флаг true.
`output_mode:"replace"` меняет тип исходного поля, `"add"` сохраняет исходное
и создаёт `<имя>_Replace` нового типа; `<имя>_Replaced` остаётся boolean.
Существующий узел с `parameters:{}` сохраняет все правила и типы; переданное
правило полностью заменяет настройки своего поля, незаданные поля сохраняются.
Для вычисления по строке или преобразования произвольного текста по формуле
выбирай Калькулятор. Boolean-результаты и смена типа в regex пока не поддержаны.

## Замена по регулярному выражению

Для замены по регулярному выражению используй `dock_node_apply` с
`target.type="transform.replace_columns"`, `mode="regex"`, а не Калькулятор
или JavaScript. В `parameters.rules` задай `field={kind:"input_field",name:…}`,
`type="string"`, упорядоченные `pairs` с `from={type:"string",value:<шаблон>}`
и `to={type:"string",value:<константа>}`, `other={mode:"keep"}` или `null`.
Первое совпадение подстроки заменяет всю ячейку константой; ссылки на группы (знак доллара с номером) не подставляются и попадают в значение буквально.
Для игнорирования регистра ставь `(?i)` в начале шаблона; `case_sensitive`
и `precision` полностью опускай. Поддержаны ASCII-литералы, группы, `[0-9]`,
положительный `{n}`, `^`/`$`. `output_mode="add"` сохраняет исходное поле,
`replace` заменяет его; обе настройки дают логический `<поле>_Replaced`.
Для изменения текста замены передай тот же existing ref и полное правило
этого поля; незаданные поля и `output_mode` сохраняются. Смешанные exact/regex
таблицы и другие конструкции требуют явного отказа, а не обхода через JS.

### Тип значений замены

Для словаря соответствий с другим типом результата выбирай Замену; для вычисляемой формулы или разбора произвольного текста — Калькулятор. См. `../node-settings.md`.

### Regex-замена

Первое совпадение заменяет всю ячейку константой; без подстановок групп. Смешанные exact/regex таблицы и неподдержанные конструкции — отказ.
