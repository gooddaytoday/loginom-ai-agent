# Факторный анализ (`research.factor_analysis`)

`research.factor_analysis`, mode `pca_fixed`: метод главных компонент,
заданное число факторов, `rotation:"none"`. По умолчанию native включает
Варимакс: у нового узла явно выбери «Без вращения». Автоматический отбор,
вращения, отдельное ограничение выходных факторов и сохранённый apply
в первом срезе не поддерживаются.

Прочитай карточку типа в `dock_action_describe`. Укажи полный набор
`parameters.factor_analysis.features` техническими именами непрерывных Integer/Real полей и число
`factors` и `rotation` в том же объекте; RowID и текстовые поля оставь без роли. Переданный набор заменяет
все роли; пропущенные параметры существующего узла сохраняются.
Первый срез принимает непустой полноранговый вход без NULL в признаках,
констант и нечисловых значений. Не заменяй NULL нулём и не удаляй строки
самостоятельно: сообщи пользователю о границе поддержки.

`finish:"execute"` должен обучить текущий вход, затем выполнить узел;
одна активация применяет прежнюю модель. После замены источника используй
тот же узел и явное переобучение. Не создавай новый узел для обновления.

Читай оба порта: 0 — scores перед исходными полями, 1 — нагрузки
(`ColumnName`, `ColumnDisplayName`, `Factor1`…`FactorP`). Native создаёт P
полей факторов по числу признаков даже при K<P: неиспользованные scores
содержат NULL, нагрузки — 0. Исходные строки и типы сохраняются.
При изменении числа факторов читай фактическую схему, не угадывай её по K.
Знак фактора произволен: scores и нагрузки одного фактора меняют знак
согласованно. Числа и oracle не включай в пользовательское задание.
Прочитай все строки, экспортируй требуемые таблицы и сохрани пакет.

Для факторного анализа вызывай `dock_node_apply` с `target.type:"research.factor_analysis"`, `mode:"pca_fixed"` и `read.ports:[0,1]`. Настройку и вычисление выполняет этот узел. Выходной порядок закрепляется обработчиком через autosync=false; mappings оставь пустым.
