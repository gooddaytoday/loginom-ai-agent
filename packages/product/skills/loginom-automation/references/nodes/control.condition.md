# control.condition

Условие переключает ветви: выполняется первая истинная ветвь, остальные
блокируются; если ложны все, работает встроенная ветвь «Иначе». Когда задача
просит выбрать ветвь или режим по значению переменной, используй
`control.condition`, а не Калькулятор, Фильтр строк или JavaScript: они не
блокируют ветви. Сначала `dock_action_describe({node_types:["control.condition"]})`.

У нового узла портов нет, поля условия появляются только после связей. Поэтому
настройка идёт двумя вызовами `dock_node_apply` одного узла, по ref/GUID.

<!-- mode: ports -->
Шаг 1. target `{kind:"new",type:"control.condition"}`, mode `ports`,
parameters `{}`, inputs `[]`, без variable_inputs, mappings `[]`,
finish `"done"`, read `{ports:[],sample_rows:0,require_exact_numbers:false}`.
Узел получает вход таблицы 0 и вход переменных 0; оба передаются на выход
каждой ветви. После Done у узла два табличных выхода: 0 — пользовательская
ветвь, 1 — «Иначе». Не добавляй второй узел для «Иначе».
<!-- /mode -->

<!-- mode: variable_branch -->
Шаг 2. target `{kind:"existing",type:"control.condition",ref}` того же узла,
mode `variable_branch`. В этом же вызове свяжи входы:
inputs `[{source:<ref таблицы>,output:0,input:0}]`,
variable_inputs `[{source:<ref variables.user>,output:4,input:0,kind:"variables"}]`
(выход 4 «Переменные сценария» — все переменные).
parameters `{branches:[{name:"Detailed",variable:"Mode",operator:"=",value:1}]}`:
ровно одна пользовательская ветвь, одно условие «переменная = значение».
variable — техническое имя входной переменной; value того же типа
(целое число JSON или строка). «Иначе» не задаётся: она встроена.
finish `"execute"`, read `{ports:[<выход выбранной ветви>],sample_rows:100,require_exact_numbers:true}`.

Результат чтения содержит `branch_activity`: для каждого выхода `executed`
true/false. Это и есть проверка, что другая ветвь не выполнялась. Читай только
выход с executed:true; выход заблокированной ветви отвергается как
не выполнявшийся — это ожидаемый результат, а не сбой.

Смена режима после изменения переменной: измени только значение в
`variables.user` (тот же ref, mode values). Затем выполни Условие без
перенастройки: тот же ref, mode `variable_branch`, parameters `{}`, inputs `[]`,
без variable_inputs, mappings `[]`, finish `"execute"`, read.ports — выход
ветви, которая теперь должна сработать (для «Иначе» — 1). Обработчик только
читает сохранённую ветвь: одно условие, его поле — входная переменная (по
списку полей узла, без изменений), отношение =, значение задано. Иначе отказ
до Execute: перенастрой Условие через branches. После Execute снова
возвращается `branch_activity`: прежняя ветвь `executed:false`.
Не вызывай `dock_node_read` для выхода заблокированной ветви.

Не поддерживаются: агрегации столбцов таблицы, «ИЛИ», регистр, несколько
ветвей, деревья, режим отладки. Такой запрос отвергается до изменения узла.
Если Loginom сохранил другое значение (неподходящий тип), обработчик
сообщает об отказе: исправь value под тип переменной.
<!-- /mode -->
