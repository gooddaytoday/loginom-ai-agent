# Конечные классы

<!-- mode: internal apply -->
Для одного дискретного строкового или непрерывного целого признака
и бинарной строковой цели выбери
`preprocessing.coarse_classes`, режим `internal`. Сначала прочитай карточку через
`dock_action_describe({node_types:["preprocessing.coarse_classes"]})`.
В `parameters.coarse_classes` задай точные технические имена `input_field`,
`target_field`, строку `event_value`, `partition:"automatic"`,
`min_class_percent`, `max_classes`, `uniformity_percent`.
Остальные поля получают роль unused и сохраняются без изменений.
Числа в процентах: 5 означает 5%, 0 — оптимизацию IV.

`internal` явно обучает текущий вход перед выполнением. Настроенный узел
и материализованные классы — разные состояния. Для нового входа без обучения
примени существующий узел с `mode:"apply"`, `parameters:{}`, `inputs:[]`,
`mappings:[]`, `finish:"execute"`. Требуются сохранённые классы. Apply читает
состояние, закрывает draft без коммита и выполняет; команда Train не вызывается.
Новая целевая колонка может содержать NULL. Предиктор должен содержать только
известные непустые категории обучения. Пустые строки и NULL в прочих полях
сохраняй раздельно. При обычном обучении каждая категория содержит события и не-события.
Для фиксации автоматического дискретного разбиения задай frozen:true в
parameters.coarse_classes, mode:"internal". После Save меняй файл того же
импорта и повторяй internal с frozen:true на том же узле: классы сохраняются,
частоты, WoE и IV пересчитываются, включая нулевые частоты. Не снимай фиксацию
и не создавай новый узел. Произвольное сглаживание не задаётся.

Явно запроси `read.ports:[0,1,2]`: порт 0 — строки с ClassNum/ClassMark/
ClassSignificant, порт 1 — параметры классов и WoE/IV, порт 2 — общий IV и
значимость признака. Новые поля следуют сразу за преобразуемым исходным полем.
Номер класса начинается с нуля и не означает порядок категорий исходного CSV.
ClassSignificant здесь содержит вклад класса в IV. Доли EventRate/NonEventRate
считаются внутри класса; WoE использует доли относительно общих событий/
не-событий. Не вычисляй WoE из округлённых UI-значений.

Сохрани пакет отдельно после проверки всех выходов. Для экспорта всех трёх
выходов сохраняй порядок: строки, классы, значимости. При чтении проверяй все значения, типы, NULL и порядок полей.
Для непрерывного integer-входа и двух ручных классов используй тот же узел
с mode:"internal", partition:"manual", max_classes:2 и целым cut.
Диапазоны значений из задачи (min..cut, cut..max) задаются одним cut;
внешние границы не задаются и не требуют уточнения.
Минимальная доля и равномерность сохраняют прежний смысл; предварительное
квантование выключается автоматически. Обработчик применяет и блокирует ручное
разбиение перед обучением, чтобы границы не пересчитывались. Сохраняй исходный
integer/continuous тип X; не вычисляй номера классов Калькулятором или JavaScript.
Границы порта 1 имеют Variant/real, внешние — NULL. Принадлежность самой границы
проверяй строкой с X=cut. Числа WoE/IV получай из полных выходов.
`apply` использует сохранённую дискретную модель.
Готовую внешнюю таблицу классов (признак, номер класса, категория)
Loginom 7.4.2 к дискретному признаку не применяет: `partition:"external"`
отклоняется кодом COARSE_EXTERNAL_UNSUPPORTED до любых действий. Обучи тот
же узел с `partition:"automatic"` только на входе 0 (frozen:true сохраняет
классы при переобучении) и сообщи пользователю об ограничении. Не имитируй
внешнее разбиение Калькулятором или JavaScript.
Внешние числовые диапазоны, переменные и неизвестные категории не поддерживаются.
