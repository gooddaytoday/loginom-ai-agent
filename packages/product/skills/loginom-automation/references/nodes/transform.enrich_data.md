# Дополнение данных

<!-- mode: left -->
Для добавления столбцов справочников к главной таблице выбирай
`dock_node_apply` с `target.type:"transform.enrich_data"`, `mode:"left"`. Вход 0 — главная таблица, входы 1…N —
от 1 до 14 справочников (три и больше — тот же один узел, не цепочка и не Калькулятор). Свяжи каждый справочник непосредственно с главной
таблицей: `parameters.enrichment.tables=[{port,keys:[{main,lookup}]}]`.
Имена ключей бери из фактических схем; типы каждой пары должны совпадать.
Составной ключ задавай всеми парами сразу.
Каждому справочнику — свой `port` подряд с 1 и свой источник в `inputs`. Поля ключей справочника исключаются
из результата; остальные присоединяются к исходным полям главной таблицы.

Для различимых названий задай полные `enrichment.prefixes` с `enabled`,
`name`, `label`. Подтверди фактические технические имена после применения:
нативный механизм формирует названия и разрешает совпадения.
Схема параметров типа находится в `dock_action_describe` для этого типа.

Новый узел требует все ключи и настройки префиксов, главную таблицу и каждый
объявленный справочник в `inputs`. Пропуск `enrichment` у существующего узла
сохраняет поддержанные настройки только при неизменных источниках.
Для замены данных справочника настрой тот же узел `imports.text`: доставь новый
CSV, задай `parameters.source` из подтверждённой доставки и
`settings.source.source_path`, сохрани совместимые колонки и выполни импорт.
Затем выполни прежнее Дополнение данных: `parameters:{}`, `inputs:[]`,
`mappings:[]`, `finish:"execute"`. Это сохраняет ключи, префиксы и выходной mapping.
Для изменения самих ключей передай полное `parameters.enrichment`.
Чтобы добавить ещё справочник к существующему узлу, передай тот же узел
(`target.kind:"existing"`), новый источник в `inputs` и полный `enrichment`
со всеми прежними таблицами и новой; прежние ключи и префиксы повтори.
После изменения прочитай выход 0: `read.coverage:"sample", sample_rows:100,
require_exact_numbers:true` для малой таблицы; проверь sample_complete.
Режим read.coverage=full для этого типа не зарегистрирован.

Для заданного точного порядка полей задай существующий выходной mapping:
direction=output, port=0, autosync=false и fields со всеми configured_field
в нужном порядке. Автосинхронизация может переставить ключевые поля после
сохранения/открытия. Явный layout должен сохранять имена и метки всех полей.

NULL в ключах совпадает с NULL; пустая строка — отдельное значение.
Каждое совпадение справочника сохраняется: дубликаты расширяют результат,
совпадения двух справочников перемножаются. Без совпадения главная строка
сохраняется с NULL в полях этого справочника. Другой справочник всё равно
связывается с исходной главной таблицей.

Для CSV с NULL и пустым текстом используй `exports.text` с
`parameters.null_marker:"?"`; пустой текст должен остаться пустым.

Не добавляй обучение и режим применения модели: это преобразование таблиц.
Другие виды соединения, вычисляемые ключи, преобразование
типов и привязки параметров к переменным в этот срез не входят.
При нативном отказе прочитай причину из кнопки ошибки мастера.
