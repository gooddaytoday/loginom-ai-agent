# Параметры полей (`transform.reform_columns`)

<!-- mode: scalar -->
После открытия сохранённого пакета перед новым Reform (`transform.reform_columns`)
подтверди выполнение его существующего табличного источника: сохранённые узлы
могут быть неактивны. Используй `loginom_dock_node_read` с успешным локальным
`source_operation_id`; если такой операции в текущей подготовке нет — выполни
тот же существующий источник через `target.kind=existing`, его точный ref,
`inputs:[]`, пустой patch по схеме этого типа и `finish=execute`. Дождись успеха
и прочитай нужный выход, затем создавай Reform. Не пересоздавай источник и не
меняй его параметры. Не запускай автоматически REST/JS/экспорт или цепочку с
такими побочными действиями: сначала проверь соответствие просьбе пользователя.

Отказ `reform preflight requires an active source output` с `NOT_APPLIED`,
`effect_possible=false`, `cleanup_complete=true` возникает до создания Reform;
после подтверждённого выполнения источника повтори просьбу с новым operation_id.
Для русских заголовков меняй `label`, сохраняя допустимые внутренние `name`;
при экспорте русских подписей выбери `header=labels`.

Повторное выполнение Параметров полей без перенастройки: parameters:{changes:[]},
inputs:[], mappings:[]; поля выбираются по входным именам, даже после переименования.

Переименование, обмен имён и смена типа поля делай этим узлом, а не Калькулятором
и не JavaScript. Один вызов — один полный список `changes`: каждое изменение
выбирает поле по входному имени (`field={kind:input_field,name}`) и задаёт
`name`, `label`, `type`, `data_kind`, `usage` или `excluded`; остальное
сохраняется. Конечные имена считаются на исходном наборе полей, поэтому цикл
вида A→B и B→A передавай одним вызовом: `{field:A,name:B,label:B}` и
`{field:B,name:A,label:A}`. Временное имя клиент подберёт и уберёт сам — не
добавляй его и не делай два вызова. Метку обмениваемых полей задавай явно, иначе
она останется прежней. Порядок полей на выходе задавай в `mappings`.

Вещественное в целое (`type=integer`) округляет к ближайшему целому и теряет дробь;
делай это только по просьбе пользователя, значения на половинах требуют отдельной
договорённости. Проверяй результат чтением выхода с `read.require_exact_numbers=true`.
