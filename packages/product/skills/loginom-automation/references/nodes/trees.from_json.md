## JSON в дерево и дерево в таблицу

Если нужен табличный результат REST, разбирай фактический `Response` выхода 0
через Калькулятор → Свёртка → Кросс-таблица. Сохраняй служебный `RequestID`
для соединения с выходом 1 REST: фактический `HttpStatusCode` берётся оттуда.
Значения извлекай из ответа сервера, не подставляй исходные поля запроса или
константы; формулы — по справке.
Не упаковывай несколько REST-ответов в один документ ради ограничения деревьев.

Выбирай `trees.from_json` → `trees.to_table` по просьбе о дереве или для ровных
записей без вложенных контейнеров. Внутри записей `trees.from_json`, `mode:"auto_structure"`
поддерживает объекты, одну ветвь их массивов и однородные массивы скаляров.
Для `[]` нужен непустой типизированный массив по тому же пути в другой записи;
результат содержит ноль экземпляров. `details:{}` сохраняет контейнер с NULL
в полях, определённых другими записями; фиктивные записи не создавай.
Читай дерево выхода 0: сохраняй границы массивов, порядок, точные Int64 и типизированный
NULL отдельно от пустой строки, false и нуля. `trees.to_table` требует одну повторяющуюся ветвь без
вложенных массивов; табличное разворачивание вложенных записей не поддержано.
Если разбор REST уже получил `Nested containers in repeated records` или иной
отказ области поддержки деревьев, не останавливай табличный сценарий:
при неизвестном эффекте сначала выполни выданный recovery через `operation.recover`,
затем продолжи табличным путём от выхода REST. Не повторяй неподдерживаемое дерево.

Сначала выполни и полностью прочитай источник: один JSON object в одной строке
строкового поля; несколько документов не поддержаны. Используй `trees.from_json`, `mode:"auto_structure"`,
`parameters:{json_field:"Document",root_mode:"auto"}`, `finish:"execute"` и
`read:{ports:[0],sample_rows:100,require_exact_numbers:true}`. Выход 0 — типизированное
дерево: `tree.schema` хранит порядок, имена, типы, контейнеры и массивы;
`tree.instances` — все экземпляры, их пути, порядок, значения и NULL. Большие
целые передаются десятичными строками. Не восстанавливай дерево из текста задачи.

`trees.from_json` поддерживает даты с исходным форматом `YYYY-MM-DDThh:mm:ss`:
лист `datetime`, типизированный NULL, civil `YYYY-MM-DDTHH:MM:SS.mmm`,
`precision:"millisecond"`, `representation:"local_datetime"`. Не сдвигай время
через UTC. `trees.to_table` даты пока не принимает.

Смешанные скалярные значения одного поля дают лист `variant`: `cell_type`
сохраняет подтип integer/real/string/boolean/datetime/null, `precision:"exact_native"`
подтверждает чтение native-кадра. `value` для integer и real — точная десятичная
строка, для boolean — логическое значение, NULL — `is_null:true,value:null`.
Различай целое и вещественное по `cell_type`; JS-тип числа этого не доказывает.
Читай фактический выход узла; смешанные массивы скаляров пока не поддержаны.

Подключай этот же порт к `trees.to_table`, `mode:"selected_nodes"`.
На новом узле обязательны `selected_paths` (пути листьев схемы в её порядке,
например `/id`, `/items/sku`, без индексов массива), `repeat_parents`,
`composite_names:false`, `composite_labels:false`, `label_separator:"."`.
`repeat_parents:true` повторяет выбранных родителей для каждой позиции;
`false` оставляет их только в первой строке, далее NULL. Выход 0 — таблица.
Полностью прочитай её, проверь типы и порядок, затем экспортируй и сохрани пакет.
Пустая строка, ноль и false сохраняются; missing scalar и JSON null дают NULL.
Для экспорта таблицы с NULL и пустыми строками явно выбери непустой маркер NULL.

Первый этап поддерживает одну непустую повторяющуюся ветвь объектов с уникальными
именами листьев, до 64 выбранных полей. Нет ручной схемы, XSD, forced root,
соседних массивов объектов, составных колонок и ручного формата дат.
Дерево ограничено 256 экземплярами, глубиной 16 и 1 MiB; превышение — отказ,
без обрезания. На существующем узле `parameters:{}` сохраняет настройки,
явный `selected_paths` заменяет весь выбор. Если пользователь просил именно дерево,
при отказе сообщи ограничение; не подменяй запрошенное дерево JavaScript или
вычислениями по вложению. Для табличного результата REST действует путь выше.
