## JSON в дерево и дерево в таблицу

Для таблицы REST разбирай фактический `Response` выхода 0
через Калькулятор → Свёртка → Кросс-таблица. Связывай с выходом 1 REST по
`RequestID`; фактический `HttpStatusCode` — там.
Значения — из ответа сервера, не полей запроса/констант; формулы — по справке.
Не объединяй REST-ответы в документ ради ограничения деревьев.

Выбирай `trees.from_json` → `trees.to_table` по просьбе о дереве или для записей
без вложенных контейнеров. `mode:"auto_structure"` поддерживает
один JSON-документ в одной строке: объект или корневой массив объектов;
также вложенные/соседние массивы объектов и однородные массивы скаляров.
Корневой массив `[{"Region":"A"},…]` импортируй одной строкой в строковый
столбец (без разбиения по запятым) → `json_field` этого столбца, `root_mode:"auto"`;
пути листьев (`/Region`, без индексов) выбирай в `trees.to_table`.
Файл не преобразуй; несколько строк JSON не поддержаны.
Для `[]` нужен непустой типизированный массив того же пути в другой записи;
экземпляров ноль. `details:{}` сохраняет контейнер с NULL
в полях из других записей; фиктивные записи не создавай.
Читай выход 0: границы массивов, порядок, точные Int64, типизированный
NULL отдельно от пустой строки, false и нуля. `trees.to_table` требует ветви
без вложенных массивов, соседние разворачивает подряд; вложенные записи в таблицу не разворачивай.
При `Nested containers in repeated records` или другом отказе деревьев в REST
не останавливай табличный сценарий: при неизвестном эффекте выполни
`operation.recover`, продолжай табличным путём от выхода REST; дерево не повторяй.

Сначала выполни и прочитай весь источник: `trees.from_json`, `mode:"auto_structure"`,
`parameters:{json_field:"Document",root_mode:"auto"}`, `finish:"execute"` и
`read:{ports:[0],sample_rows:100,require_exact_numbers:true}`. Выход 0 — типизированное
дерево: `tree.schema` (порядок, имена, типы, контейнеры) и `tree.instances`
(экземпляры, пути, значения, NULL). Большие целые — десятичные строки.
Не восстанавливай дерево из текста задачи.

Даты `trees.from_json` — `YYYY-MM-DDThh:mm:ss`:
лист `datetime`, типизированный NULL, civil `YYYY-MM-DDTHH:MM:SS.mmm`,
`precision:"millisecond"`, `representation:"local_datetime"`. Не сдвигай время
через UTC. `trees.to_table` даёт из них колонку DateTime.

Смешанные скаляры одного поля дают лист `variant`: `cell_type`
сохраняет подтип integer/real/string/boolean/datetime/null, `precision:"exact_native"`
подтверждает native-кадр. `value`: integer/real — точная десятичная строка,
boolean — логическое, NULL — `is_null:true,value:null`; целое и вещественное
различай по `cell_type`, не по JS-типу. Смешанные массивы скаляров не поддержаны.

Подключай этот порт к `trees.to_table`, `mode:"selected_nodes"`.
Новый узел требует `selected_paths` (пути листьев в порядке схемы,
например `/id`, `/items/sku`, без индексов массива), `repeat_parents`,
`composite_names`, `composite_labels`, `label_separator`: обычно `false`, `false`, `"."`;
составные — по [справке](trees.to_table.md).
`repeat_parents:true` повторяет выбранных родителей в каждой позиции,
`false` — только в первой строке, далее NULL. Выход 0 — таблица.
Проверь типы и порядок таблицы; полное чтение и экспорт — по просьбе.
Пустая строка/0/false сохраняются; missing scalar и JSON null дают NULL.
Для экспорта NULL и пустых строк явно выбери непустой маркер NULL.

Пределы: непустые ветви повторяемых объектов, уникальные имена листьев,
до 64 полей; без ручной схемы, XSD, forced root и ручного формата дат.
Лимиты: 256 экземпляров, глубина 16, 1 MiB; сверх — отказ без обрезки.
В существующем узле `parameters:{}` сохраняет настройки, `selected_paths`
заменяет весь выбор. Если просили именно дерево, при отказе сообщи ограничение;
не подменяй дерево JavaScript или расчётом по вложению. Для таблицы REST — путь выше.
