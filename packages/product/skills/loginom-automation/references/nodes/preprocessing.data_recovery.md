# Заполнение пропусков (`preprocessing.data_recovery`)

## Заполнение пропусков

Для замены числовых NULL нулём выбирай `preprocessing.data_recovery`, `mode:"impute"`,
`parameters:{fields:[{field:{kind:"input_field",name:"Amount"},method:"zero"}],max_nulls_percent:100,ordered:false}`.
`zero` — нативный метод для integer/real обоих видов данных; `value` не передавай.
`mean` требует непрерывное числовое поле, `constant` — дискретную строку и строковое
`value`. Переданный `fields` полностью заменяет обработку: неперечисленные поля
выключаются. Для сохранения настроек существующего узла передай `parameters:{}`.
Порог — явное целое 0–100; при `mean` выше порога NULL сохраняются. Нативный
`zero` заполняет NULL независимо от порога, включая полностью пустое числовое поле. Существующие нули и
необрабатываемые поля сохраняются. Используй
`finish:"execute"`, читай порт 0. Median/mode, ordered и интерполяция не поддержаны.

Перед заполнением пропусков сверяй метод с фактическим типом/видом поля и
контрактом: текущий `preprocessing.data_recovery` поддерживает `mean` только для
непрерывных integer/real, `zero` — для числовых integer/real, `constant` — только для дискретных string.
Числовую константу нельзя передать строкой `"0"` ради обхода этой границы.
Если по бизнес-правилу отсутствие оплаты или наблюдения означает ноль, используй
штатный `method:"zero"` этого узла без `value`; явно задай допустимый процент
пропусков и `ordered:false`. При `mean` порог может оставлять NULL; нативный `zero`
заполняет NULL независимо от порога, включая полностью пустое числовое поле.
Проверь фактический результат перед арифметикой и отбором.
Без такого правила NULL не подменяй. После отказа прочитай актуальный выход
выбранного существующего источника; не строй формулу по выходу неудавшегося узла.
При возможном эффекте сначала урегулируй исходную операцию по browser.md.
