# Текстовый файл (`exports.text`)

<!-- mode: delimited fixed_width -->
`dock_node_apply`, `type:"exports.text"`: CSV — `mode:"delimited"`; фиксированная ширина —
`mode:"fixed_width"` (ширины по содержимому и заголовкам, текст слева, числа справа,
между полями пробел; без Калькулятора/JS; ручных ширин, точности чисел и delimiter нет).
`destination` — .csv/.tsv/.txt; `mappings:[]`. Кодировка по умолчанию UTF-8; также
`encoding:"Windows-1252"`, `"UTF-16 LE"`, `"UTF-16 BE"`; `"Windows-1251"` — только
по явной просьбе пользователя. BOM — `bom:true/false` (для CP1251 Loginom 7.4.2 BOM
игнорирует: `bom:false`); CRLF — `line_ending:"CRLF"`.
Символы вне CP1251 заменяются байтом `0x1A` (SUB): предупреди пользователя об этой потере.
ISO: `date_format:"yyyy/mm/dd",date_separator:"-",time_format:"hh:mm:ss",time_separator:":"`.
On refusal fix only the rejected value; keep other requested settings. Check readback.

Если в выгружаемых данных есть NULL и пустые строки, а пользователь не задал маркер выгрузки,
явно передай в параметре `null_marker` непустой маркер,
не совпадающий с не-NULL значениями. По умолчанию выбери тот же непустой маркер, что при импорте,
если он был задан; иначе `NULL`. Назови выбранный маркер пользователю.

Новому экспорту нужен destination в назначенной папке. Обычный CSV: UTF-8, запятая,
header=names, bom=false, LF, десятичная точка, пустой NULL, двойная кавычка. Существующий
узел получает только заданные изменения. Конфликт пути проверяют и Done, и Execute; замена
файла — только `overwrite=replace` с явным destination и разрешением пользователя, иначе
сообщи конфликт. В продолжении не возвращай старый destination без требования задания.

`inputs[0].source` — тот `node_id` и выход, чей успешный результат дал запрошенный итог
(строки, схема, агрегаты проверены); совпадения поля или имени файла мало. Для количеств
и сумм по группам — сводка Группировки, не детализация Калькулятора.
До Execute прочитай входную таблицу и сверь имена и порядок колонок с заданием; расхождение
исправь Reform/Параметрами полей до первого подключения Экспорта (занятую связь apply
не меняет), перечитай и проверь `configuration.readback.input_mapping.fields`.
В продолжении переиспользуй Export, если итог даёт прежний источник: `target.kind=existing`,
точный `target.ref`, `inputs:[]`, новый `operation_id`; только смена файла не требует нового Export.
Если итогу нужен новый узел выше Export, а задание называет другой destination, создай
новый Export от этого узла в этот файл; прежний не трогай. Иначе исправь прежнюю upstream-цепочку на месте или сообщи ограничение; второй Export на тот же destination не создавай.
После отказа `mappings` исправь upstream и повтори тот же Export с `mappings:[]`. Порядок
колонок меняй лишь по требованию задания; если сохранённое входное соответствие не даёт
нужной раскладки, сообщи ограничение.

Имя файла из переменной: вместо `destination` передай
`file_name_variable:{kind:"variable",name:"ReportFile"}`. Источник — выполненный
Калькулятор переменных, где строка ReportFile — полный путь в папке экспорта, например
`"<папка>/report-" + ReportDate + ".csv"` (входную переменную пиши без `Var.`). Подключи `variable_inputs:[{source:<его ref>,output:0,input:0,kind:"variables"}]`.
Для новой даты измени и выполни тот же Калькулятор, затем тот же Export
(`target.kind=existing`, `parameters:{}`): привязка сохраняется, файл пишется по новому
пути, прежний остаётся. Не создавай второй Export и не подставляй литерал пути.
NULL, пустое значение, `%Name%` и путь вне папки отклоняются до записи; readback
`file_name_variable` и `destination` подтверждают привязку и путь.

Execute возвращает `output.file_artifacts` с размером и SHA-256 файла; портов данных нет:
`read:{ports:[]}`. Сверь назначение и формат с заданием; Done и Close файл не подтверждают.
Не скачивай итог повторно через server source cache; сохрани пакет и сообщи результат.
