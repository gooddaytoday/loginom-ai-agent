# Импорт LGD

Получай parameter_schema через dock_action_describe(node_types:["imports.lgd"]).
Используй source из завершённой доставки вложения. По умолчанию задавай lgd_import.checksum="verify".
Режим native. Новый узел без табличных входов, табличный выход 0.
Сохраняй имена, метки, типы, виды, порядок и NULL/пустую строку.
Никакого обучения. Execute читает выход 0; Done сохраняет настройки;
Close отменяет черновик. Сам пакет сохраняется отдельным Save.
Пустая таблица вместо ошибки checksum не означает успешного импорта.
LZ4-файлы могут содержать checksum «Нет», «Сжатых данных» или «Сжатых и несжатых данных».
Отсутствие checksum не доказывает целостность. lgd_import.checksum="ignore" допустим
только по явному запросу пользователя до ошибки checksum. После такой ошибки не
отключай проверку и не возвращай пустую успешную таблицу; повторный обход для того
же digest или узла запрещён. У существующего узла {} сохраняет checksum и источник.
32-bit LGD и DDF недоступны на нашем стенде: нет 32-битного Loginom и Deductor для
получения и проверки штатных файлов. Это ограничение платформы/источника; такие
файлы остаются запрещены. Variant и другие алгоритмы сжатия не поддерживаются.

Для пути из переменной создай и выполни «Калькулятор (переменные)» со строковой
переменной, содержащей точный путь завершённой доставки. Подключай его выход 0
через variable_inputs:[{source:ref,output:0,input:0,kind:"variables"}].
У LGD это обычный Input_Var-1, логический variables 0; скрытого control-порта нет.
Задавай lgd_import:{checksum:"verify",bindings:{source_path:{variable:"SourceFile"}}}
и source для того же проверенного файла. Имя — точное имя соответствия переменных;
значение должно быть непустым строковым абсолютным .lgd-путём из этого источника.
Readback.source.source_variable подтверждает выбранное имя, source_path — его путь.
После изменения переменной выполни её источник снова, затем тот же LGD-узел с source
нового проверенного файла. Привязка сохраняется; литерал поверх неё не записывается.
При привязке указывай source при каждом применении; после reopen получай ссылку
на сохранённый файл через dock_storage_source. Это проверка файла, а не смена привязки.

Выбирай этот нативный узел через `dock_node_apply`, `mode:"native"`. Калькулятор и JavaScript не нужны для чтения или записи LGD. Для обратного импорта собственного экспорта выбери файл через `dock_storage_source`, затем `parameters.source:{kind:"storage",server_source_ref:...}`. Не загружай и не конвертируй его повторно.

Для LGD сразу используй `loginom_file_admit` и завершённую доставку; текстовые profile/scan и выборка не нужны. Не задавай столбцы вручную — они сохранены в бинарном файле.

Для точной проверки выполни `dock_node_apply` с `finish:"execute"`, `read:{ports:[0],sample_rows:100,require_exact_numbers:true}`. Сверь `row_count`, схему и все доступные строки; при большем наборе не называй выборку полным результатом.
