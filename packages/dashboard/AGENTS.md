# Платформа dashboard

Снимок и папка чата, сборка и публикация — в `src/agent`, loopback-сервер и страница черновика — в `src/draft`, три примера — в `examples`. Службы API и хоста приложений — в `src/web`, схемы обмена — в `src/contract`, доверенная оболочка и адаптер Studio — в `src/shell`, SDK v1 — в `src/sdk/loginom.ts`. Bun собирает `dist/server.mjs` для Node и единый `dist/shell.js` для браузера. Dashboard — недоверенный код: он работает на отдельном origin в `sandbox="allow-scripts"`, получает данные через MessagePort и не меняет параметры. Пакет `.lgp` интеграция не записывает.

Для разработки приложений соблюдайте [инструкции приложений](../../dashboard/AGENTS.md). Desktop/CLI один раз получают снимок с настроенного стенда и создают `<данные бэкенда>/dashboards/*/{work,control}`. Модель читает `work/` и пишет только в `work/src/`; привязка, сборки и набор шаблона ей недоступны. `template/` содержит lockfile и файлы платформы (`index.html`, `tsconfig.json`, `vite.config.mjs`, `resolver.mjs`, `scan.mjs`): сборщик копирует только разрешённые исходники поверх платформы и напрямую запускает `tsc`/Vite встроенным Node, без `npm run` приложения. Исключение границ модулей: `draft` использует `web/apps.ts` и `shell/frame.ts`.

- Из `packages/dashboard`: `bun typecheck`, `bun run test` (сборка, покрытие web не ниже 90%, контракт и SDK), `bun run check:size`, `bun run test:browser` (браузерные проверки, страница, самопроверка, публикация и `test/build` — шаблон, три примера и ограничения сборки). Укажите `LOGINOM_AI_AGENT_TEST_NODE` и `PLAYWRIGHT_BROWSERS_PATH` для закреплённых Node и Chromium из `packages/product/loginom-release.json` и lockfile runtime. Зависимости шаблона: `npm ci --ignore-scripts` из `template`. Для временных файлов используйте подготовленный `$TMPDIR` вне Git.
- Стенд из корня: `./packages/dashboard/deploy/dev-master.sh install [--strict] [--cli-button] [--web NAME]`, `check [--web NAME]`, `uninstall [--web NAME]`. `install` без `--strict` включает обычный режим. Перед изменением стенда обязательны `bash -n` и ShellCheck для этого скрипта. Приватная конфигурация для `check` передаётся только через `DASHBOARD_STUDIO_CONFIG`; [рецепт стенда](../../dashboard/stand/README.md#проверка-и-удаление), [приёмка M3](../../docs/testing/loginom-ai-agent/dashboard-m3.md).
- Установщик создаёт `~/loginom-dashboard/`: `node`, `server.mjs`, `builds/`. Отдельный контейнер `dashboard-master-20261109-web` работает от UID/GID пользователя, читает эти каталоги без записи и не видит `UserStorage`. API `8100` доступен внутри Docker для Apache Studio; хост приложений `8101` опубликован только как `127.0.0.1:32769`, origin `http://dashboards.localhost:32769`. Node больше не запускается внутри Loginom Server.
- API хранит до 100 одноразовых снимков на 15 минут: `POST /dashboard/snapshots`, затем один `GET /dashboard/snapshots/<ID>`. `targets` и `current` удалены. Образец — до 100 строк и 512 КиБ; ключ привязки содержит путь пакета, GUID сценария и узла, без origin.
- Без решения владельца нельзя добавлять `allow-same-origin`, команды приложения или новые типы сообщений, ослаблять резолвер и проверку импортов до `tsc`, CSP и loopback-границы сервера черновика, одноразовость снимка, заголовки хоста приложений, расширять `frame-src` Studio, менять режимы и лимиты или заменять принудительный CSP на Report-Only. `style-src` остаётся без `unsafe-inline`: реальные React/Recharts проверки прошли без запасного варианта.
