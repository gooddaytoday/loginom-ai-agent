# Платформа dashboard

Службы API и хоста приложений — в `src/web`, схемы обмена — в `src/contract`, доверенная оболочка и адаптер Studio — в `src/shell`, SDK v1 — в `src/sdk/loginom.ts`. Bun собирает `dist/server.mjs` для Node и единый `dist/shell.js` для браузера. Dashboard — недоверенный код: он работает на отдельном origin в `sandbox="allow-scripts"`, получает данные через MessagePort и не меняет параметры. Пакет `.lgp` интеграция не записывает.

Для разработки приложений по снимку соблюдайте [инструкции приложений](../../dashboard/AGENTS.md). Исходники находятся в `dashboard/apps/<ключ>`, шаблон и npm lockfile — в `template`, публикация — `script/publish.mjs`. **До M4 publisher запускайте только для доверенных исходников:** `npm run typecheck` и `npm run build` выполняют код приложения на машине публикации. Песочница браузера сборку не защищает.

- Из `packages/dashboard`: `bun typecheck`, `bun run test` (сборка, покрытие web не ниже 90%, контракт и SDK), `bun run check:size`, `bun run test:browser` (браузерные проверки, все три примера и `test/publish`). Укажите `LOGINOM_AI_AGENT_TEST_NODE` и `PLAYWRIGHT_BROWSERS_PATH` для закреплённых Node и Chromium из `packages/product/loginom-release.json` и lockfile runtime. Зависимости шаблона: `npm ci --ignore-scripts` из `template`. Для временных файлов используйте подготовленный `$TMPDIR` вне Git.
- Стенд из корня: `./packages/dashboard/deploy/dev-master.sh install [--strict] [--web NAME]`, `check [--web NAME]`, `uninstall [--web NAME]`. `install` без `--strict` включает обычный режим. Перед изменением стенда обязательны `bash -n` и ShellCheck для этого скрипта. Приватная конфигурация для `check` передаётся только через `DASHBOARD_STUDIO_CONFIG`; [рецепт стенда](../../dashboard/stand/README.md#проверка-и-удаление), [приёмка M2](../../docs/testing/loginom-ai-agent/dashboard-m2.md).
- Установщик создаёт `~/loginom-dashboard/`: `node`, `server.mjs`, `builds/`. Отдельный контейнер `dashboard-master-20261109-web` работает от UID/GID пользователя, читает эти каталоги без записи и не видит `UserStorage`. API `8100` доступен внутри Docker для Apache Studio; хост приложений `8101` опубликован только как `127.0.0.1:32769`, origin `http://dashboards.localhost:32769`. Node больше не запускается внутри Loginom Server.
- API хранит последние 100 снимков в памяти. Для отдельной отладки из корня: `DASHBOARD_ALLOW_CURRENT=1 node packages/dashboard/dist/server.mjs`. `/dashboard/current` требует флага и loopback TCP-соседа. Установщик флаг выключает; DTO снимка и `targets` в M2 сохраняются, образец остаётся 12 строк.
- Без решения владельца нельзя добавлять `allow-same-origin`, команды приложения или новые типы сообщений, ослаблять заголовки хоста приложений, расширять `frame-src` Studio, менять режимы и лимиты или заменять принудительный CSP на Report-Only. `style-src` остаётся без `unsafe-inline`: реальные React/Recharts проверки прошли без запасного варианта.
