# Независимые данные узла 14

CSV используют `;`, UTF-8, Null-маркер `NULL`, qualifier `"`.
Id/Count/Untouched — Integer, Amount — Float, Note — String.
Amount/Count — непрерывные, остальные — дискретные.

Эти ожидания не вычисляются обработчиком:

- core, порог 100: Amount `[2.5,5,7.5,5]`; Count `[1,2,2,2]` (положительное
  дробное среднее предварительно наблюдалось); Note `[alpha,MISSING,"",null]`,
  последнее значение — текст. Untouched `[0,Null,10,20]` остаётся без обработки.
- boundary: 5/12 Null, оставшиеся значения Amount=10/Count=2/Note=text.
  При пороге 40 Null должны остаться, при 41 и 42 — заполняться согласно E2E;
  требуется live-подтверждение.
- one-in-120, порог 0: первый Null должен заполняться согласно Help;
  требуется live-подтверждение.
- precision: числовое среднее Amount `1.055555550555555`, проверка без экранного
  округления; Integer со средним -1.5 дал -2; отдельный повтор подтвердил этот expected.
- all-null, порог 100: поведение всех трёх обрабатываемых полей требуется установить
  в Loginom, затем закрепить отдельным expected до повторного прогона.
- empty: ноль строк, сохранённая схема. Нельзя подменять неизвестное число строк нулём.

Ни один fixture сам по себе не является свидетельством пройденной проверки.

`expected.json` содержит отдельные именованные ожидания. MISSING — placeholder
для явно запрошенной строковой константы; source digest и имена полей проверяются
независимо. `audit_missing_values_run.py` принимает сохранённые запросы, квитанции
импорта/загрузки и отдельно прочитанную полную таблицу. Он не заявляет persistence.

`reordered.csv` переставляет precision-поля в порядок Note, Untouched, Count,
Id, Amount. Для Amount и Note импорт задаёт одинаковую метку `Same`; выбор
обработки остаётся по имени. Независимый expected сохраняет этот порядок,
типы, виды и метки. Наличие fixture не означает, что live-проверка завершена.


Автономная приёмка 2026-09-13 использует отдельный `acceptance-pins.json`:
девять CSV (включая changed.csv),14 этапов и independent Decimal oracle.
Границы выше впоследствии проверены напрямую; точная матрица и актуальные
ограничения находятся в `../../node14/PREPARATION.md`. Исторические заметки
«требуется проверить» не означают автономный PASS. Все выбранные полностью
пустые поля сохранили Null; при5/12 границы40/41/42 подтверждены;1/120 при0
заполнился. В публичном node.apply образец ограничен10 строками, поэтому
полные12/120 для автономного goal читает отдельный проверяющий после сохранения.
