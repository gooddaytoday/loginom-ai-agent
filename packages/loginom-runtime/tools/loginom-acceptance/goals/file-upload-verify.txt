Через Loginom Dock выполни dock_prepare. Сохрани artifact_id и upload.grant_id единственного разрешённого CSV __UPLOAD_NAME__. Требуется отправить файл и проверить скачанные серверные байты в этой же сессии; заверши transfer после сверки и очистки. Это ещё не проверка запрета перезаписи.

Для входа в файловое хранилище найди главную панель MF;cntMain;tlbMainToolbar через scope=roots, прочитай её root_ref с observation_id (без scope) и возьми ref кнопки «Файлы» из подробного чтения. Discovery выдаёт области без разрешения на жест; действовать можно после подробного чтения.

Открой «Файлы» и перейди в __STORAGE_DIRECTORY__ только click кнопки файлового хранилища и double_click по сегментам __STORAGE_SEGMENTS__. Для больших списков используй scope=roots со storage_name очередного сегмента, прочитай root_ref/observation_id discovery и действуй по ref подробного чтения. При UI_EPOCH_CHANGED обнови наблюдение и повтори только явно не выполненную навигацию. Ничего не создавай, не удаляй, не переименовывай и не сохраняй.

В action.ref передавай element.ref из доставленного наблюдения — строку, начинающуюся с ui-. Поля tid и identity.anchor_tid не являются ref для действий. При продолжении страницы передавай только cursor, без scope/root_ref. REQUEST_REJECTED с request_rejected=true и effect_possible=false означает отказ ДО действия: исправь формат запроса, при необходимости прочитай свежие refs и продолжай. Такой отказ не завершает диагностический запуск.

Найди NavigationBar;NavigationPanel через scope=roots без storage_name, прочитай его через root_ref и проверь file_storage.status=observed, directory=__STORAGE_DIRECTORY__. Передай observation_id этого чтения, artifact_id, upload_grant_id и новый operation_id в dock_artifact_upload ОДИН раз. Используй только закреплённое launcher разрешение, не передавай пути или политику в tool. Ожидается AMBIGUOUS/UPLOAD_SERVER_VERIFICATION_REQUIRED. Вызови dock_operation_inspect для исходного upload ID: должен оставаться pending.

Теперь найди __UPLOAD_NAME__ через dock_workspace_observe(scope=roots, storage_name=точное имя файла). Прочитай найденную область через root_ref и observation_id discovery. Из подробного чтения возьми file_ref строки с точным именем CSV и observation_id этого чтения. Вызови dock_artifact_verify ОДИН раз, передав operation_id исходной загрузки, новый verification_id, observation_id и file_ref. Это единственный разрешённый способ скачивания в этой проверке. Не делай обычный click/double_click по файлу, не обходи pending через UI repair/abandon, не повторяй upload.

Проверь SUCCEEDED, bytes_verified=true, bytes=230 и SHA из admitted artifact. Затем ещё раз dock_operation_inspect исходного upload ID: server_copy_verification.bytes_verified=true, upload_completion_verified=true, original state=resolved и outcome.status=SUCCEEDED. Transfer должен завершаться только по подтверждённым байтам, browser completion и cleanup. При отказе сообщи реальный результат и закончи диагностический запуск без обходов. После verify не выполняй других изменений интерфейса.

Используй только Loginom Dock и его E2E/Help источники; без терминала, другого браузера, делегирования или смены модели. В конце кратко сообщи результат сверки байтов и оставшиеся ограничения.
