# Подключение Loginom Dock

Loginom Dock даёт агенту инструкции и общую базу знаний Loginom, а браузер запускает
на вашем компьютере. После успешной подготовки задачи её сообщения и результаты
инструментов сохраняются в общей базе Dock с очисткой секретов. Браузерные профили
и двоичные артефакты остаются локально.

## Что понадобится

- Установленный Codex версии 0.149.1 или новее либо Hermes версии 0.21.0 или новее
  в поддерживаемой основной ветке. Команда выбранного агента должна быть доступна
  в терминале.
- Windows 11 x64, macOS с Apple Silicon или Linux x64 с графическим окружением.
- Клиентский ключ Dock от администратора и адрес вашего Loginom с `?testable=true`.
- Существующая рабочая папка в файловом хранилище Loginom, доступная вашей учётной записи.
- Доступ к серверу Dock, GitHub и целевому Loginom. Для внутреннего стенда нужен VPN.

В проекте Loginom Dock сценарии через Hermes выполняются через уже подключённую
подписку ChatGPT. Установщик Dock не меняет модель или провайдера Hermes.

## Установка

Откройте [страницу установки Loginom Dock](https://loginom-dock.duckdns.org/#install)
и перейдите к указанному там релизу.
Скачайте архив для своей системы и файл `SHA256SUMS`. macOS соответствует
`darwin-arm64`, Linux — `linux-x64`, Windows — `win32-x64`. Сравните контрольную
сумму архива с записью в `SHA256SUMS`: на macOS используйте `shasum -a 256`,
на Linux — `sha256sum`, на Windows — `Get-FileHash -Algorithm SHA256` в PowerShell.

Распакуйте архив, откройте терминал в каталоге `loginom-dock` и запустите мастер
для своего агента:

```sh
./install.sh --agent codex
```

или:

```sh
./install.sh --agent hermes
```

Для отдельного профиля Hermes добавьте `--hermes-home /полный/путь/к/профилю`.
В мастере укажите адрес Dock (по умолчанию `https://loginom.duckdns.org/mcp`),
адрес Loginom, клиентский ключ и рабочую папку, например `/analyst/Мои сценарии`.
Это папка на сервере Loginom: в ней создаются сценарии, входные файлы и результаты.
Ввод ключа скрыт. Не вставляйте ключ в команду,
сообщение агенту или ссылку.

Мастер установит собственную среду Dock и Chromium, зарегистрирует native-плагин
и проверит подключение. Системные Node.js/Python и чужие настройки агента сохраняются.
На минимальном Linux мастер может сообщить об отсутствующих библиотеках Chromium;
их устанавливает администратор системы. Подробности — в `client/README.md`.

На Windows распакуйте ZIP и из каталога `loginom-dock` выполните в PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 --agent codex
```

Параметры `--agent hermes`, `--config-from`, `--storage-root`, `--rollback`, `--uninstall` и
`--hermes-home` совпадают с примерами выше. Среда устанавливается в
`%USERPROFILE%\.loginom-dock`; системные Node.js и Python не заменяются.

Для Codex проверьте разрешения обработчиков Dock в `/hooks`, если агент запрашивает
доверие. Для Hermes при работающем gateway перезапустите его после установки.
Откройте новую сессию и попросите: «Проверь подключение Loginom Dock». В диагностике
должны быть доступны сервер, источники, инструкции и браузер; при начале работы
в Loginom `dock_prepare` должен успешно завершиться и активировать архив.

## Датасет из сообщения

В Codex приложите CSV, TSV или текстовый файл к сообщению. В Hermes Desktop/TUI
выберите файл через вложения или укажите его через `@file`. Напишите, какой сценарий
нужно построить. Dock подготовит отдельную копию файла и загрузит её в выбранную
рабочую папку, когда агент настроит импорт. Существующие файлы не перезаписываются.
Для этого сообщения должно быть включено доверие обработчикам плагина.

Можно приложить до восьми файлов: до 16 МиБ каждый и до 64 МиБ суммарно.
Передача XLSX и JSON поддержана, но готовых обработчиков импорта этих форматов
в данном RC ещё нет. Автоматическая обработка в RC использует текстовые датасеты.
Вложения через Telegram и другие мессенджеры этой проверкой не охвачены.

При первом обращении откроется Loginom. Войдите в обычной форме и сообщите агенту,
что вход выполнен; пароль не нужно передавать в чат. Путь рабочей папки можно
изменить повторным запуском мастера с `--storage-root /путь/в/Loginom`.

## Обновление и откат

Скачайте новый комплект, проверьте сумму и повторите мастер с тем же агентом и
профилем. Мастер сохраняет текущие адреса, ключ и рабочую папку автоматически.
При необходимости явно выберите другой защищённый конфиг:

```sh
./install.sh --agent hermes --config-from "$HOME/.loginom-dock/config.json"
```

При необходимости замените `hermes` на `codex`. Обновление применяется к новым
сессиям; уже работающие сессии сохраняют закреплённые версии.

Чтобы вернуть предыдущую установку, из распакованного комплекта выполните:

```sh
./install.sh --agent hermes --rollback
```

Указывайте тот же профиль Hermes, если использовали `--hermes-home`. После прерванной
установки эта команда восстанавливает сохранённую регистрацию. Если предыдущей
установки не было, обычный откат к предыдущей версии недоступен.

## Удаление

```sh
./install.sh --agent hermes --uninstall
```

Для Codex замените имя агента. Удаляются плагин и подключение выбранного агента.
Локальные профили, артефакты, очередь и общая серверная история сохраняются.

## Если подключение не работает

Повторите диагностику Dock в новой сессии. Проверьте VPN, адрес Loginom,
`?testable=true`, клиентский ключ и доступность рабочего стола. Успешное открытие
страницы ещё не означает вход в Loginom: выполните вход в обычной форме браузера.
Если установка прервалась, используйте описанный откат и сохраните текст ошибки
без ключей. Не удаляйте вручную каталог Dock, пока не восстановлена регистрация.
