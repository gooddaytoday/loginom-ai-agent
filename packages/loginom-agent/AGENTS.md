# Loginom product plugin

- `@loginom-ai-agent/loginom-agent` is the built-in server plugin of the product. Core runs it last in `post` under a reserved ID (`packages/core/src/plugin/product.ts`). `src/index.ts` composes the plugin; `src/host.ts` starts the one private Loginom Host of the server process (`packages/cli/src/server-process.ts` calls it at boot) and each Location's plugin leases it for its sessions.
- Loginom tools are the Dock catalog (`src/dock.ts`), local files (`src/local-file.ts`, `src/file-profile.ts`), package documentation (`src/package-docs.ts`) and dashboards (`src/dashboard*.ts`). Names, inputs and results are those of 0.4; do not change them without the owner. Keep host credentials and context tokens out of model parameters, and preserve original-user attachment admission; see [host contracts](../loginom-host/AGENTS.md).
- Access follows the task profile: `src/access.ts` hides tools the task may not use and rejects calls anyway; `src/permissions.ts` holds the product permission defaults; `src/skills.ts` admits reserved product skill IDs only from the verified bundled catalog. A dashboard's work folder fixes its profile for the whole session (`src/dashboard.ts`).
- Loginom MCP `isError` becomes a tool error. `src/loginom-result.ts` keeps the control summary of an oversized receipt (status, error, node, execution, next step) and marks omitted table data; never present a cropped table as complete. `src/browser-recovery.ts` owns the end-of-turn browser recovery reminder.
- Tests: `bun test` and `bun typecheck` from `packages/loginom-agent`. Source tests do not establish installed or live acceptance. Runtime contracts: [loginom-runtime](../loginom-runtime/AGENTS.md); product pins and skills: [product](../product/AGENTS.md).
