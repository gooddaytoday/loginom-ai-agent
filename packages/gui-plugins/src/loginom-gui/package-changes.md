# Контракт карточки изменений пакета (C3.20)

Отрисовщик читает завершённый отдельный tool part `loginom_package_changes` в конце последнего ответа хода.
Серверный источник помещает данные в `state.metadata.loginom.packageChanges` (`v: 1`); `sessionID` — разговор,
`turnID` — ID этого финального сообщения ассистента. `packageName` — имя исходного пакета, `copyPath` — путь копии.
Нужен один такой результат на ход, только при подтверждённых изменениях копии. Это не инструмент модели.

`edits` — разница исходника и копии с операциями и GUID в форме S10-5, **не** `metadata.loginom.manualEdits`
(это правки человека между шагами). Изменение связи отмечает оба её узла; новый/удалённый узел учитывается один раз.
Необязательный `comparison` — пара `{ original, copy }` для одного и того же сравниваемого выхода на сопоставимых
данных. В каждой части нужны факты S10-9 `run` (`executed`) и `table` (`tableRead`) с одинаковым `executionId`,
а у исходника и копии ID запусков различаются. Без этой пары карточка не выводит сверку.

Необязательные `copyUrl`, `originalUrl`, `schemaUrl` открывают готовые HTTP(S)-адреса, полученные от Loginom или
схемы. По кнопке «Открыть» логический путь новой версии передаётся обработчику `loginom-package:<encoded path>`;
если обработчика нет, показывается точный путь в Loginom. Логический путь не считается локальным файлом.

Действия идут в `loginom.package-copy` (LAB-2218); подтверждённые ответы и ошибки меняют состояние карточки.
Перед изменением клиент проверяет актуальность хода; сервер остаётся ответственным за привязку операции к нужной
копии и её актуальность. Состояние ответов RPC хранится в текущем окне, не выдаётся за сохранённое состояние сервера.
