# Desktop connection to Loginom

- Electron main owns the Loginom connection of the Desktop profile only until the service takes it. The renderer uses the typed preload API and receives redacted status, never stored secret values.
- OpenCode 2 runs the Host in the Desktop service, not in the main process. `credential-migration.ts` moves the 0.4 connection (`<userData>/loginom/connection`, written with Electron `safeStorage`) into the service store (`<data>/loginom/connection`, envelope `cliCredentials` of `packages/loginom-host/src/connection`). `credentials.ts` runs it once, after `app.whenReady` and before the layer that starts the service. The 0.4 store is only read, never changed. A connection that cannot move leaves the service without one and never stops the app; the outcome is a code without secrets in the main log.
- Linux stores secrets as plaintext configuration with files `0600`, directories `0700`; Windows uses DPAPI and macOS the Keychain. The production profile is `${XDG_CONFIG_HOME:-~/.config}/com.loginom.aiagent`; do not relocate it when changing the installation directory. Other channels have separate profiles.
- Generations, recovery and the lease of a connection live in `packages/loginom-host` (see [host boundary](../../../../loginom-host/AGENTS.md)). The Desktop connection service and recovery store of 0.4 are not part of this directory in OpenCode 2; their replacement belongs to the Desktop stage B4.
- Preserve explicit proxy environment and the loopback bypass for the Loginom runtime. System proxy for model and OAuth traffic is applied to the Desktop sidecar and CLI, not to runtime children. See `docs/superpowers/specs/2026-09-23-system-proxy-v2.md`.
- Run `bun test src/main/loginom` and `bun typecheck` from `packages/desktop`. Real GUI tests use isolated profiles; never restart or overwrite the user's running session for debugging.
- See [desktop release instructions](../../../AGENTS.md) and [acceptance runbooks](../../../../../docs/testing/loginom-ai-agent/README.md).
