# Desktop connection lifecycle

- Electron main owns connection credentials, durable generations, private host IPC and recovery. Renderer uses the typed preload API and receives redacted status, never stored secret values.
- `connection-store.ts`, `credentials.ts`, `connection-service.ts` and `recovery-store.ts` re-export the common implementations in `packages/loginom-host/src/connection`. `desktop-service.ts` supplies Electron paths and safeStorage to `createLoginomHost`; `host-port.ts` re-exports the common handler over the structural HostPort contract. Existing connection tests here exercise those common implementations through the Desktop exports.
- Linux intentionally stores secrets as plaintext configuration with files `0600`, directories `0700`. Production profile is `${XDG_CONFIG_HOME:-~/.config}/com.loginom.aiagent`; do not relocate it when changing the installation directory. Other channels have separate profiles.
- Lease a connection generation for the whole active drain. Save pending changes durably and activate only at a safe boundary. Attempts use isolated UUIDs; retain receipts across recovery.
- Persist/fsync recovery intent before tool dispatch. По умолчанию неопределённая операция не требует подтверждения и не блокирует следующее поколение подключения: Desktop не включает `strictRecovery`. `acknowledgeRecovery` и журнал строгого режима остаются для приёмки. Операции не повторяются автоматически. Кнопка восстановления в настройках скрыта.
- Setup has separate Loginom AI and Loginom connection cards. Cloud is the default; custom mode stores an explicit endpoint/key. No shared key is packaged. Loginom URL/username/password can be saved before cloud login; browser verification stays separate. Login persists cloud credentials immediately, without applying the draft mode; mode switches preserve both credentials. Disconnect removes local cloud credentials even if site revoke fails, with a visible warning. Desktop and CLI profiles remain independent. Defaults come from Product; password is empty without placeholder. The files folder derives from username without an availability probe. Model/provider settings remain separate.
- Electron main receives the build-only validated cloud tuple as an import.meta literal. Runtime env/manifest cannot select endpoints. Cloud site/Help use only explicit proxy environment (after login-shell initialization) and system CA; no OS/PAC resolver. Chromium keeps `--no-proxy-server`; model/sidecar system proxy v2 is unchanged.
- Preserve explicit proxy environment and the loopback bypass for the Loginom runtime. System proxy for model and OAuth traffic is applied to the Desktop sidecar and CLI, not to runtime children. See `docs/superpowers/specs/2026-09-23-system-proxy-v2.md`.
- Run `bun test src/main/loginom` and `bun typecheck` from `packages/desktop`. Real GUI tests use isolated profiles; never restart or overwrite the user's running session for debugging.
