# Формат спецификации test_data

Файл — UTF-8 JSON. Неизвестное поле скрипт отвергает до записи CSV
(код выхода 2). Числа долей передавай как JSON-числа, не строками.

## Пример

Запрос: 1000 строк интернет-магазина, в 5% сумма отрицательная,
в 2% статус пустой.

```json
{
  "name": "orders",
  "rows": 1000,
  "seed": 42,
  "csv": { "delimiter": ";", "decimal_separator": ".", "null_marker": "" },
  "columns": [
    { "name": "order_id", "label": "ID заказа", "type": "integer", "generator": { "kind": "sequence", "start": 100001 } },
    { "name": "order_date", "label": "Дата", "type": "datetime", "generator": { "kind": "date_range", "from": "2026-01-01", "to": "2026-09-30" } },
    { "name": "amount", "label": "Сумма", "type": "real", "generator": { "kind": "number", "min": 100, "max": 50000, "distribution": "lognormal", "decimals": 2 } },
    { "name": "status", "label": "Статус", "type": "string", "generator": { "kind": "choice", "values": ["Новый", "Оплачен", "Отправлен", "Доставлен", "Отменён"], "weights": [10, 25, 20, 40, 5] } }
  ],
  "anomalies": [
    { "column": "amount", "kind": "negative", "share": 0.05 },
    { "column": "status", "kind": "null", "share": 0.02 }
  ],
  "overlap": "disjoint"
}
```

Скрипт запишет ровно 50 отрицательных сумм и 20 пустых статусов.
Одинаковый `seed` даёт побайтно тот же CSV.

## Корень

| Поле | Обязательность | Смысл |
| --- | --- | --- |
| `name` | да | Имя файла без расширения. ASCII: буква или `_`, затем буквы, цифры и `_`, до 120 символов. |
| `rows` | да | Целое от 1 до 1 000 000. |
| `seed` | нет | Целое. По умолчанию 42. |
| `csv` | нет | Формат файла, см. ниже. |
| `columns` | да | От 1 до 1000 колонок. |
| `anomalies` | нет | Список аномалий. Пустой список — чистый набор. |
| `overlap` | нет | `disjoint` (по умолчанию) или `independent`. |
| `key_column` | нет | Колонка, чьи значения попадают в ключ ответов. По умолчанию первая. |

## CSV

По умолчанию: разделитель `;`, десятичный разделитель `.`, пустой маркер
NULL, ограничитель текста `"`, кодировка UTF-8.

| Поле | Правило |
| --- | --- |
| `delimiter` | Один символ, не перевод строки. Не равен десятичному разделителю и ограничителю. |
| `decimal_separator` | `.` или `,`. |
| `null_marker` | Строка до 256 символов без перевода строки и без пробелов по краям. Пустая строка значит пустое поле. |
| `text_qualifier` | Один символ. |
| `encoding` | Только `UTF-8`. |

Заголовок — технические имена колонок. Дата без времени: `YYYY-MM-DD`.
Дата со временем: `YYYY-MM-DDTHH:MM:SS`. Логические значения генератора
`boolean`: `True` и `False`.

## Колонка

`name` — то же правило ASCII, что у имени набора, и оно же попадает
в заголовок. `label` — подпись для человека, до 120 символов, можно
по-русски. `type`: `integer`, `real`, `string`, `boolean`, `datetime`.

`data_kind` можно не указывать. Подстановка:

| Тип | Вид данных |
| --- | --- |
| `integer`, `string`, `boolean` | `Дискретный` |
| `real`, `datetime` | `Непрерывный` |

Явное значение — только `Неопределенное`, `Непрерывный` или `Дискретный`.

## Генераторы

Поле `generator.kind` и тип колонки должны подходить друг другу.

| `kind` | Тип | Поля |
| --- | --- | --- |
| `sequence` | `integer` | `start` (1), `step` (1, не 0). Значение строки `i` (с нуля): `start + step * i`. |
| `uuid` | `string` | Без полей. Строка UUID из `seed`, не системный случайный UUID. |
| `number` | `integer`, `real` | `min`, `max`, `distribution` (`uniform`, `normal`, `lognormal`), для `real` ещё `decimals` (0…8, по умолчанию 2). У целого `decimals` не задают. `lognormal` требует `min` > 0. |
| `date_range` | `datetime` | `from`, `to` в ISO. `with_time` необязателен: если в границе есть `T`, время включается. |
| `date_offset` | `datetime` | `base` — имя другой datetime-колонки. `min_days` (0), `max_days` (30). Сдвиг не раньше базы, пока `min_days` ≥ 0. Цикл баз отвергается. |
| `choice` | `string` | `values` — 1…200 непустых строк короче 200 символов, без пробелов по краям и без повторов. `weights` — необязательные положительные веса той же длины. |
| `pattern` | `string` | `template` до 80 символов. Каждый `#` становится цифрой, остальные символы копируются. Пример: `SKU-#####`. |
| `boolean` | `boolean` | `true_weight` от 0 до 1, по умолчанию 0.5. |

`normal` берёт середину диапазона и ширину `(max - min) / 6`, значения
вне диапазона отбрасывает. `date_offset` считается от чистой базы:
аномалия в базовой колонке уже посчитанный сдвиг не двигает.

## Аномалии

У каждой аномалии ровно одно из полей `share` и `count`.
`share` — число больше 0 и не больше 1. Число строк —
`rows * share` с обычным округлением половины вверх (0,5 и выше — вверх).
Если результат 0, спецификация отвергается: увеличь долю или число строк.
`count` — целое от 1 до `rows`.

`duplicate_row` задаётся без `column`. Остальные виды требуют `column`.
Одну пару «колонка + вид» дважды не повторяют.

`overlap: disjoint` — в строке не больше одной аномалии. Сумма всех
`count` не может превысить `rows`.
`overlap: independent` — в одной строке могут сойтись аномалии разных
колонок. Одна колонка по-прежнему не делится, а `duplicate_row` не
делит строку ни с чем.

| `kind` | Куда | Что попадает в ячейку |
| --- | --- | --- |
| `null` | любой тип | Маркер NULL. Пустой маркер — пустое поле. |
| `empty` | любой тип | Пустая строка, отличная от маркера. Нельзя, если маркер и так пустой. |
| `negative` | `integer`, `real` | Модуль чистого значения со знаком минус. Нельзя, если генератор сам может дать отрицательное, и нельзя на строке. |
| `zero` | `integer`, `real` | Ноль. Нельзя, если `sequence` проходит через 0 или диапазон состоит только из нуля. |
| `boundary` | `number`, `date_range`, `date_offset` | Ровно `min` или `max` (для даты — `from`/`to` или крайний сдвиг). Строки в ключе ответов идут по возрастанию: первая, третья и дальше получают минимум, вторая и четвёртая — максимум. Одна строка получает минимум. Края диапазона должны различаться. |
| `out_of_range` | `number`, `sequence`, `date_range`, `date_offset` | На 1 выше максимума: `max + 1`, следующий день или `max_days + 1`. |
| `outlier` | те же | На 1000 выше максимума: `max + 1000`, плюс 1000 дней или `max_days + 1000`. |
| `future_date` | `date_range`, `date_offset` | На 30 дней позже конца диапазона или `max_days + 30`. |
| `bad_format` | `integer`, `real`, `datetime` | Текст `BAD` или `not-a-date`, который не разбирается как число или дата. |
| `unknown_category` | `choice` | `UNKNOWN`, если такого значения нет в списке. |
| `whitespace` | `string` | Чистое значение с двумя пробелами по краям. |
| `case_variant` | `choice` | То же значение другим регистром, сначала верхним. |
| `long_text` | `string` | Строка длиной не меньше 200 символов. |
| `duplicate_key` | `sequence` или `uuid` | Ключ копируется из чистой строки. Другие ячейки остаются своими. |
| `duplicate_row` | вся строка | Копируется чистая строка целиком. |

Чистые строки не содержат значений этих аномалий, поэтому счётчик по
файлу совпадает с запрошенным числом. `zero` и `boundary` вместе
отвергаются, если граница диапазона равна нулю: иначе ноль нельзя
отличить от границы.

Для дублей нужна хотя бы одна чистая строка-источник. На таблице из
одной колонки `duplicate_key` уже создаёт полные дубли, поэтому вместе
с `duplicate_row` она отвергается.

## Манифест

Рядом с CSV пишется `<name>.manifest.json`, `schema_version`
`test_data.manifest.v1`.

- `spec` — спецификация с подставленными значениями по умолчанию и
  уже посчитанным `count`.
- `loginom_import` — настройки узла «Импорт из текстового файла»:
  `source.encoding`, `source.rows_to_skip` = 0, `source.first_line_as_title`
  = true, `format` (разделитель, десятичный разделитель, маркер NULL,
  ограничитель) и `columns` (`name`, `label`, `type`, `data_kind`,
  `used` = true). Пути в хранилище Loginom здесь нет.
- `anomalies` — ключ ответов: `requested`, `actual`, номера строк
  с 1 без заголовка, значения `key_column`. Для дублей ещё
  `source_rows` — откуда скопирована строка.
- `clean_rows` — строки без единой аномалии.
- `column_stats` — число NULL, для чисел и дат минимум и максимум
  разобранных значений, для строк число различных.

После записи скрипт читает CSV модулем `csv` и сверяет счётчики.
Расхождение — код выхода 1, CSV удаляется, манифест не пишется.

## Сводка в stdout

Только при коде 0:

```json
{
  "csv": "/absolute/test-data/orders.csv",
  "manifest": "/absolute/test-data/orders.manifest.json",
  "rows": 1000,
  "clean_rows": 930,
  "seed": 42,
  "anomalies": [
    { "column": "amount", "kind": "negative", "requested": 50, "actual": 50 },
    { "column": "status", "kind": "null", "requested": 20, "actual": 20 }
  ]
}
```
