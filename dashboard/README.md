# Dashboard в локальном Loginom

Для продолжения на другом компьютере начните с [инструкции переноса](HANDOFF.md).

На действующем стенде пока M1: до завершения приёмки M2 открывайте только собственные доверенные dashboard. Ниже описано поведение M2 после принятой установки; статус проверки — в [runbook M2](../docs/testing/loginom-ai-agent/dashboard-m2.md).

[Открыть маркетинговый сценарий](http://127.0.0.1:32768/app/#packages/user/dashboard-roi/campaign.lgp/Unit1/workflow).
Пользуйтесь адресом из ссылки: host и порт входят в привязку приложения.
Войдите тестовым пользователем стенда, выделите **«По убыванию ROI»** и нажмите
**Dashboard** в начале панели сценария. Неактивный узел выполнится автоматически;
у активного загрузится готовый результат без нового расчёта. Пока узел выполняется,
видно «Идёт расчёт». При ошибке закройте dashboard и откройте снова для новой попытки.
Измените порог бюджета в доверенной шапке над приложением и нажмите Enter
или выйдите из поля: Loginom выполнит узел, таблица и график обновятся.
«Вернуться к сценарию» закрывает приложение, сохраняя применённый порог в сессии.
Интеграция dashboard и публикация не записывают пакет `.lgp`; сохранение сценария остаётся штатным действием Loginom.

Для создания у узла с табличным первым выходом нажмите **«Создать dashboard»**.
Для правки готового dashboard откройте его и нажмите **«Изменить в чате»**.
В сборке Loginom AI Agent Desktop с поддержкой dashboard над полем ввода появятся
действие и имя узла. При закрытом Desktop или на главном экране откроется новый черновик.
Напишите просьбу и отправьте её. Метка относится к одной просьбе и снимается после
принятия сообщения. После публикации закройте dashboard и откройте его снова.
Для обычного клика из Linux браузеру нужен обработчик системных ссылок этой сборки.
Сборка и команды подключения указаны в [отчёте по Desktop](../docs/superpowers/plans/2026-11-10-dashboard-desktop.md).

Ссылки «Открыть чат в Desktop» и «Изменить в чате» используют отдельный контекст браузера: сценарий Loginom не закрывается. Обычное предупреждение о несохранённых изменениях остаётся включённым.

Desktop прикладывает к сообщению снимок конкретного клика. Исполнитель читает его по
`http://127.0.0.1:32768/dashboard/targets/<ID>` и до конца запроса использует этот ID.
Если ID нет, нажмите «Создать dashboard» или «Изменить в чате» в Studio и отправьте
просьбу через Desktop. Сервис хранит последние 100 снимков; перезапуск удаляет их все.
Опубликованные приложения хранятся на диске.

Для прямой локальной отладки запустите из корня отдельный процесс:
`DASHBOARD_ALLOW_CURRENT=1 node packages/dashboard/dist/server.mjs`. После создания снимка в этом
процессе можно читать `http://127.0.0.1:8100/dashboard/current`. Маршрут требует и флаг,
и loopback TCP-соседа (IPv4, IPv6 или отображённый IPv4); forwarded-заголовки его не
открывают. Штатный `dev-master.sh install` не включает флаг, а `/dashboard/current` через Apache
возвращает 404. После установки создайте новый снимок: чтение по его ID должно дать 200.

Dashboard считается недоверенным кодом. Он работает на отдельном origin в песочнице и получает данные через SDK v1 (`onState`, `close`), без доступа к Studio и хранилищам; CSP закрывает обычные сетевые запросы. Параметры меняет только шапка. До M4 исходники для `publish.mjs` должны быть доверенными: сборка выполняет их `npm run` на машине публикации. Остаточные риски обычного режима описаны в [плане изоляции](../docs/security/dashboard-isolation.md#принятые-риски).

## Воспроизведение и обслуживание

- Используется [изолированный стенд Loginom master](stand/README.md). При работающих `dashboard-master-20261109-server` и `dashboard-master-20261109-studio` соберите пакет: `(cd packages/dashboard && bun run build)`, затем из корня выполните `./packages/dashboard/deploy/dev-master.sh install`. Для строгого режима добавьте `--strict`; повторный `install` без флага возвращает обычный режим.
- Установщик подключает оболочку обоих клиентов, принудительный CSP и отдельный `dashboard-master-20261109-web`. API на порту `8100` доступен Apache по сети Docker; приложения на `8101` опубликованы только как `http://dashboards.localhost:32769`. На хосте `~/loginom-dashboard/` содержит Node, службу и `builds/`; контейнер читает их без записи, не получает `UserStorage` и перезапускается самостоятельно. Перезапуск Loginom Server не требует переустановки dashboard. Существующий пакет ROI не перезаписывается.
- Обновление M1 → M2: **install → свежий снимок и перепубликация ROI → check**. Старые приложения с `window.frameElement.dashboard` не совместимы с песочницей и автоматически не переносятся. Обновите Studio, нажмите «Создать dashboard» у нужного узла и используйте ID этого клика. Для сохранённых исходников выполните `commands.publish` из снимка; новое приложение сначала создаётся через `commands.init`. Перезапуск web удаляет ID из памяти, но сохраняет опубликованные сборки.
- Шаблон с lockfile — в `packages/dashboard/template`, исходники — в `dashboard/apps`. `publish.mjs` проверяет типы, собирает Vite, хеширует готовую закрытую копию и атомарно переключает `current`. Документ приложения имеет адрес `/apps/<ключ>/<хеш>/`. `binding.json`, `sample.json` и `current` браузеру не выдаются. Образец остаётся контекстом чата: `tableSource` различает `live`, `published-example`, `unavailable`; экран получает актуальную таблицу через SDK.
- Приложение показывает загрузку, расчёт, ошибку, пустой результат и данные; при усечении — число показанных и общее число строк. Пределы состояния: 10 000 строк, 10 000 символов в ячейке, 5 000 000 символов суммарного JSON строк. Образец снимка Desktop остаётся прежним (12 строк).
- После свежей публикации выполните `./packages/dashboard/deploy/dev-master.sh check` с [приватной конфигурацией](stand/README.md#проверка-и-удаление). Команда проверяет API, заголовки, контейнер и адаптер в обоих клиентах; полная UI-приёмка SDK описана отдельно в [runbook M2](../docs/testing/loginom-ai-agent/dashboard-m2.md).
- `uninstall` снимает интеграцию и свой web-контейнер, сохраняет `builds/`, исходники и пакеты. После повторного `install` и `check` прежний M2 dashboard должен открыться без новой публикации.

Проверки исходников и ограничения изменения защиты — в [инструкции пакета](../packages/dashboard/AGENTS.md). Это локальный dev-стенд; слияние, выпуск и перенос на другие машины выполняются отдельно.
