# Dashboard в локальном Loginom

Для продолжения на другом компьютере начните с [инструкции переноса](HANDOFF.md).

[Открыть маркетинговый сценарий](http://127.0.0.1:32768/app/#packages/user/dashboard-roi/campaign.lgp/Unit1/workflow).
Пользуйтесь адресом из ссылки: host и порт входят в привязку приложения.
Войдите тестовым пользователем стенда, выделите **«По убыванию ROI»** и нажмите
**Dashboard** в начале панели сценария. Неактивный узел выполнится автоматически;
у активного загрузится готовый результат без нового расчёта. Пока узел выполняется,
видно «Идёт расчёт». При ошибке закройте dashboard и откройте снова для новой попытки.
Измените порог бюджета и нажмите Enter
или выйдите из поля: Loginom выполнит узел, таблица и график обновятся.
«Вернуться к сценарию» закрывает приложение, сохраняя применённый порог в сессии.
Чтобы изменить сам пакет на диске, сохраните его средствами Loginom.

Для создания у узла с табличным первым выходом нажмите **«Создать dashboard»**.
Для правки готового dashboard откройте его и нажмите **«Изменить в чате»**.
В сборке Loginom AI Agent Desktop с поддержкой dashboard над полем ввода появятся
действие и имя узла. При закрытом Desktop или на главном экране откроется новый черновик.
Напишите просьбу и отправьте её. Метка относится к одной просьбе и снимается после
принятия сообщения. После публикации закройте dashboard и откройте его снова.
Для обычного клика из Linux браузеру нужен обработчик системных ссылок этой сборки.
Сборка и команды подключения указаны в [отчёте по Desktop](../docs/superpowers/plans/2026-11-10-dashboard-desktop.md).

Ссылки «Открыть чат в Desktop» и «Изменить в чате» используют отдельный контекст браузера: сценарий Loginom не закрывается. Обычное предупреждение о несохранённых изменениях остаётся включённым.

Для отладки в Codex откройте или создайте dashboard в Loginom и напишите просьбу в чате
из корня этого проекта. Codex берёт последнюю цель стенда при первом чтении.
Desktop прикладывает к сообщению снимок конкретного клика. Снимки доступны до перезапуска
сервиса Node.js, опубликованные приложения хранятся на диске.

## Воспроизведение и обслуживание

- Используется [изолированный стенд Loginom master](../docs/research/2026-11-09-dashboard-live-investigation.md).
  На работающих **dashboard-master-20261109-server** и **dashboard-master-20261109-studio**
  выполните из корня `./dashboard/install.sh`. Скрипт включает bootstrap обоих клиентов,
  запускает NodeJS за Apache, устанавливает зависимости шаблона и копирует отсутствующие
  файлы ROI. Существующий пакет не перезаписывается. Обновите уже открытую страницу
  Loginom после установки. После перезапуска server-контейнера выполните ту же команду.
- В проверенном стенде dashboard уже опубликован. Для публикации на пересозданном стенде
  нажмите «Создать dashboard» у целевого узла; если исходники уже есть, выполните
  `commands.publish` из снимка. Для нового приложения сначала выполните `commands.init`.
  Обе команды относятся к одному ID; публикация заработает и из чистой копии исходников.
- В `dashboard/template` хранятся шаблон, lockfile и установленные зависимости;
  в `dashboard/apps` — редактируемые приложения. `publish.mjs` проверяет типы,
  собирает Vite и только после успеха переключает опубликованный каталог.
  В браузере данные берутся через `window.frameElement.dashboard`: `state()`,
  `change(значение, имя?)` и `run()`. Bootstrap подготавливает результат до загрузки
  iframe, поэтому при открытии приложению достаточно `state()`; собственный
  автозапуск или начальная кнопка «Выполнить» не нужны. При публикации рядом с `binding.json`
  сохраняется `sample.json` из того же ID. Если в новой сессии нет собственного
  результата (также после ошибки), Node берёт пример этой привязки и указывает
  `tableSource: "published-example"`. Собственный результат помечен `live`,
  отсутствие обоих — `unavailable`. Выполненный пустой результат остаётся пустым.
  Пример служит контекстом чата; экран по-прежнему читает адаптер.
  При обновлении старой установки сначала опубликуйте по ещё доступному ID
  с живыми строками и проверьте `sample.json`, затем запускайте `install.sh`
  и обновляйте страницу: перезапуск Node удаляет старые ID.
- Проверки: из `dashboard` — `node --test server.test.mjs bootstrap.test.mjs`; из `dashboard/template`
  или каталога приложения — `bun typecheck`, `npm run build`.
  [Дизайн](../docs/superpowers/specs/2026-11-09-loginom-dashboard-design.md) и
  [план](../docs/superpowers/plans/2026-11-09-dashboard-app.md) описывают границы приёмки.

Этот способ рассчитан на доверенный код и небольшие таблицы локального стенда.
Числовые параметры берутся из переменных открытого сценария.
