# Dashboard в локальном Loginom

M3 добавляет черновик в Desktop и CLI, затем отдельную публикацию. Установленная приёмка M3 ещё не выполнена: порядок и места для результатов — в [runbook M3](../docs/testing/loginom-ai-agent/dashboard-m3.md). Результаты M2 сохраняются в [runbook M2](../docs/testing/loginom-ai-agent/dashboard-m2.md).

## Создание и правка

1. Подключите Desktop к тому же стенду, что открыт в Studio. На локальном dev-стенде это `http://127.0.0.1:32768/app/`.
2. Выберите узел с табличным первым выходом и нажмите «Создать dashboard». Для правки откройте Dashboard и нажмите «Изменить в чате». Каждый клик создаёт новый одноразовый снимок на 15 минут.
3. Desktop забирает снимок только с настроенного стенда и открывает новый чат в папке dashboard с меткой узла. Напишите просьбу обычными словами. Агент покажет ссылку на проверенный черновик.
4. Черновик показывает реальные строки образца и время снимка. Поля параметров недоступны: пересчёт появится после публикации. Попросите правку в том же чате — открытая страница обновится сама.
5. Попросите «Опубликовать». Разовое окно подтверждения называет узел и путь пакета; «Разрешать всегда» недоступно. После успешной публикации откройте узел в Studio и нажмите Dashboard.

Параметры меняет доверенная шапка Studio. Неактивный узел выполняется автоматически, активный отдаёт готовый результат. Для [ROI](http://127.0.0.1:32768/app/#packages/user/dashboard-roi/campaign.lgp/Unit1/workflow) у узла «По убыванию ROI» порог `MinBudget` 0 → 10 000 → 0 даёт 500 → 453 → 500 кампаний. Esc внутри приложения или кнопка шапки возвращает сценарий. Интеграция и публикация не записывают `.lgp`; сохранять сценарий можно штатным действием Loginom.

Повторная ссылка, истёкший снимок или другой настроенный стенд требуют нового клика в Studio. Не читайте снимок заранее: второе чтение даёт 404. Ссылки открывают Desktop отдельно, сессия Studio остаётся открытой. При отправке Desktop проверяет метку по локальной папке, без повторного чтения со стенда.

## Данные и границы

Папка — `<данные бэкенда>/dashboards/<имя пакета>-<ключ>/`: `work/snapshot.json`, `work/sample.json`, `work/src/` и соседняя служебная `control/`. Модель читает только `work/`, пишет только в `work/src/`. Новый снимок обновляет контекст и привязку, сохраняя исходники. Примеры лежат в `packages/dashboard/examples`; каталога `dashboard/apps` и `publish.mjs` больше нет.

Сборщик берёт только разрешённые исходники поверх файлов платформы из `packages/dashboard/template`, проверяет импорты до `tsc` и использует встроенные Node/набор шаблона. Команды приложения не запускаются. Отдельный headless Chromium проверяет черновик без сессии Loginom. Dashboard работает на отдельном origin в песочнице, получает данные через SDK v1 (`onState`, `close`); CSP закрывает обычные сетевые запросы. Приложение показывает загрузку, расчёт, ошибку, пустой результат и данные с отметкой усечения. Остаточные риски — в [плане изоляции](../docs/security/dashboard-isolation.md#принятые-риски).

Сервер черновика слушает loopback и живёт вместе с бэкендом. После перезапуска Desktop агент даёт новую ссылку. В CLI ссылка живёт до конца `run`. После подтверждённой публикации `sample.json` удаляется: для следующего черновика нужен свежий клик «Изменить в чате».

Публикация M3 временно доступна только на локальный dev-стенд через `$HOME/loginom-dashboard/builds`; `published` возвращается после совпадения хеша в `lookup`. Хост приложений читает каталог без записи. Для другого стенда инструмент сообщает, что публикация появится в следующей версии. Публикация через хранилище и отдельный сборщик относятся к M4.

## Воспроизведение и обслуживание

- [Перенос и входы сборки](HANDOFF.md), [новый стенд](stand/README.md), [обновление существующего стенда и приёмка](../docs/testing/loginom-ai-agent/dashboard-m3.md).
- Из корня: `(cd packages/dashboard && bun run build)`, затем `./packages/dashboard/deploy/dev-master.sh install`. `--strict` включает строгий режим; обычный `install` возвращает обычный. Для отладки из Codex добавьте `--cli-button`: кнопка Studio копирует `loginom-ai-agent-cli run --dashboard <ID> "<текст>"`. Подключение берётся из профиля CLI. Без `--auto` публикация отклоняется.
- Установщик создаёт отдельный ограниченный `dashboard-master-20261109-web`: API `8100` доступен Apache в Docker; приложения `8101` опубликованы только как `http://dashboards.localhost:32769`. `$HOME/loginom-dashboard/` содержит Node, службу и `builds/`. Node не работает внутри Loginom Server, существующие ROI-файлы не перезаписываются.
- После первой публикации M3 выполните `./packages/dashboard/deploy/dev-master.sh check` с [приватной конфигурацией](stand/README.md#проверка-и-удаление). `check` проверяет интеграцию обоих клиентов, но не заменяет полный runbook M3. Старые ID и ключи публикации M1/M2 не переиспользуются: получите свежий снимок и опубликуйте заново.
- `uninstall` снимает интеграцию и свой web-контейнер, сохраняя сборки и пакеты; прежний M1 этим не восстанавливается. Перед обновлением существующего стенда сохраните данные по runbook M3.

Проверки исходников и ограничения изменения защиты — в [инструкции пакета](../packages/dashboard/AGENTS.md). Слияние и выпуск выполняются отдельно.
