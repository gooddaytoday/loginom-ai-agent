# Dashboard в локальном Loginom

[Открыть маркетинговый сценарий](http://127.0.0.1:32768/app/#packages/user/dashboard-roi/campaign.lgp/Unit1/workflow).
Пользуйтесь адресом из ссылки: host и порт входят в привязку приложения.
Войдите тестовым пользователем стенда, выделите **«По убыванию ROI»** и нажмите
**Dashboard** в начале панели сценария. Измените порог бюджета и нажмите Enter
или выйдите из поля: Loginom выполнит узел, таблица и график обновятся.
«Вернуться к сценарию» закрывает приложение, сохраняя применённый порог в сессии.
Чтобы изменить сам пакет на диске, сохраните его средствами Loginom.

У другого узла с табличным первым выходом нажмите **«Создать dashboard»**,
затем опишите приложение в чате Codex из корня этого проекта. Для правки снова
откройте существующий Dashboard, напишите пожелание в чат и после публикации
закройте и откройте пульт. Выбор узла без открытия не меняет адресата запроса.
На стенде один пользователь; цель привязывается в момент первого чтения агентом.
Снимки живут до перезапуска NodeJS, созданные приложения — на диске.

## Воспроизведение и обслуживание

- Используется [изолированный стенд Loginom master](../docs/research/2026-11-09-dashboard-live-investigation.md).
  На работающих **dashboard-master-20261109-server** и **dashboard-master-20261109-studio**
  выполните из корня `./dashboard/install.sh`. Скрипт включает bootstrap обоих клиентов,
  запускает NodeJS за Apache, устанавливает зависимости шаблона и копирует отсутствующие
  файлы ROI. Существующий пакет не перезаписывается. Обновите уже открытую страницу
  Loginom после установки. После перезапуска server-контейнера выполните ту же команду.
- В проверенном стенде пульт уже опубликован. Для публикации на пересозданном стенде
  нажмите «Создать dashboard» у целевого узла; если исходники уже есть, выполните
  `commands.publish` из снимка. Для нового приложения сначала выполните `commands.init`.
  Обе команды относятся к одному ID; публикация заработает и из чистой копии исходников.
- В `dashboard/template` хранятся шаблон, lockfile и установленные зависимости;
  в `dashboard/apps` — редактируемые приложения. `publish.mjs` проверяет типы,
  собирает Vite и только после успеха переключает опубликованный каталог.
  В браузере данные берутся через `window.frameElement.dashboard`: `state()`,
  `change(значение, имя?)` и `run()`. В снимке только примеры строк.
- Проверки: из `dashboard` — `node --test server.test.mjs`; из `dashboard/template`
  или каталога приложения — `bun typecheck`, `npm run build`.
  [Дизайн](../docs/superpowers/specs/2026-11-09-loginom-dashboard-design.md) и
  [план](../docs/superpowers/plans/2026-11-09-dashboard-app.md) описывают границы приёмки.

Этот способ рассчитан на доверенный код и небольшие таблицы локального стенда.
Числовые параметры берутся из переменных открытого сценария. Desktop в этот этап не входит.
