# Продолжение dashboard + Desktop на другом компьютере

Текущий путь M3: [описание](README.md), [дизайн](../docs/superpowers/specs/2026-11-12-dashboard-m3-design.md), [runbook M3](../docs/testing/loginom-ai-agent/dashboard-m3.md). Установленная приёмка M3 ещё предстоит. [Runbook M2](../docs/testing/loginom-ai-agent/dashboard-m2.md) и [checkpoint M1](../docs/testing/loginom-ai-agent/dashboard-m1-handoff.md) сохраняют результаты прежних установок в их исходной области проверки.

Рабочая ветка — `dashboard-m3`. История ветки очищалась от унаследованных ключей; для новой машины используйте новый clone. Не сливайте старую историю обратно: переносите нужные изменения отдельными проверенными коммитами и проверяйте секреты перед отправкой.

## Входы и порядок

1. Получите checkout и workspace-зависимости закреплённым Bun из `packageManager`. Node/Chromium и прочие версии берите только из `packages/product/loginom-release.json` и lockfile runtime. Каноническая подготовка входов — [CI action](../.github/actions/setup-loginom-inputs/action.yml); рецепты сборки Desktop — [Linux runbook](../docs/testing/loginom-ai-agent/linux.md), CLI — [standalone runbook](../docs/testing/loginom-ai-agent/standalone-cli.md). Прежние кандидаты сохраняйте; приватные артефакты со встроенным ключом не добавляйте в Git.
2. Для нового Loginom следуйте [рецепту стенда](stand/README.md). Нужен разрешённый лицензированный дистрибутив, не входящий в Git. Для существующего стенда используйте подготовку и возврат из runbook M3; общий installer другого стенда не запускайте. Адреса клиента `127.0.0.1:32768` и приложений `127.0.0.1:32769` должны быть свободны.
3. Соберите Desktop DEB, CLI и платформу из одного чистого коммита; выполните статическую проверку артефактов. Перед заменяющей DEB-установкой требуется согласие владельца, который сам закрывает работающее приложение. Запустите Desktop с отдельным `LOGINOM_AI_AGENT_TEST_ROOT`, backend V1; `LOGINOM_AI_AGENT_SIDECAR_V2=1` не задавайте. Настройте модель и подключение к своему dev-стенду через обычные настройки; auth и credentials не переносите в Git.
4. Установите интеграцию `./packages/dashboard/deploy/dev-master.sh install --cli-button`. На новом стенде сначала подтвердите вход по WebSocket и исполнение ROI. Затем пройдите десять шагов runbook M3: создание → черновик → правка → разовое подтверждение публикации → Studio и живые параметры. Старые снимки не переносятся, новый клик всегда даёт новый ID.

Три примера SDK v1 находятся в `packages/dashboard/examples`, общий шаблон — в `packages/dashboard/template`. `dashboard/apps`, команды снимка и `publish.mjs` удалены: из Codex используйте `loginom-ai-agent-cli run --dashboard <ID> "<текст>"`. Штатный пользователь создаёт и правит dashboard через Desktop без технических команд. Исходники сохраняются в папке данных профиля; если при правке на новой машине их нет, Desktop сообщает, что доступна заготовка.

Снимки, `node_modules`, `dist`, серверные сессии и приватные логи не переносятся как исходники. После проверки штатно закройте свои пакеты и выполните «Выход» из Loginom до закрытия вкладки: иначе пакет может остаться заблокированным. Безопасные результаты и ограничения запишите в runbook, сырые журналы оставьте вне Git.
