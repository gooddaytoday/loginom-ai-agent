# Офлайн-поставка Loginom Enterprise 7.4.2 и Dashboard M7

Упаковщик принимает два проверенных локальных архива. Собранный комплект содержит их исходные байты и адаптер, который подключает Dashboard к конфигурации Apache поставки 7.4.2.

После загрузки оригинального образа M7 адаптер создаёт локальный производный образ с отдельным тегом. Единственный новый слой открывает чтение кода и шаблона непривилегированным процессам Dashboard. Оригинальный архив и тег образа сохраняются. Для создания слоя Docker использует только загруженный образ и отключённую сеть.

```sh
./pack-loginom-with-dashboard.sh <архив-Enterprise> <архив-Dashboard> <каталог-результата>
```

Рядом с tar формируется файл `.tar.sha256`. Упаковщику нужны GNU tar, GNU Coreutils и GNU patch. При появлении следующей пары архивов сначала сверить имена сервисов, конфигурацию Apache и тест Dashboard. Затем добавить проверенные суммы и совместимый адаптер.

## Установка

Нужны Docker Engine 29.1.3, Docker Compose 2.40.3 или более новые версии, действующая лицензия Enterprise и доступ с рабочих мест к HTTP Studio и порту приложений 8101. Адрес `studio.example.test` в примере заменяется фактическим именем Studio.

```sh
sha256sum -c loginom-release-7.4.2-6e72ef0f1824-dashboard-m7.tar.sha256
tar -xf loginom-release-7.4.2-6e72ef0f1824-dashboard-m7.tar
cd loginom-release-7.4.2-6e72ef0f1824-dashboard-m7
sha256sum -c SHA256SUMS
tar -xf loginom-release-7.4.2-6e72ef0f1824.tar
```

Установить Enterprise вложенным `install.sh` согласно инструкции базовой поставки. Сохранить действующий способ лицензирования. После успешного штатного `verify.sh` подключить Dashboard.

```sh
sudo ./dashboard-742.sh install --public-host studio.example.test
sudo ./dashboard-742.sh check
```

При повторном запуске базового `install.sh` подключить Dashboard той же командой. Адаптер применяет отдельный Compose-файл к сервису `http`, используя `.env` штатной установки. Команда `check` проверяет серверную публикацию, оболочку и штатную Studio.

Для проверки с рабочего места создать dashboard из обычной Studio, открыть черновик в Desktop M7 и подтвердить публикацию. Заново открыть пакет в Studio и сверить живые строки узла. Проверке `deploy/check-studio.mjs 7.4.2` из исходников Dashboard нужны приватная конфигурация входа и подготовленный тестовый пакет.

## Снятие Dashboard

```sh
sudo ./dashboard-742.sh uninstall
```

Адаптер снимает дополнение и пересоздаёт только штатный HTTP-контейнер. Исходники опубликованных dashboards остаются в UserStorage.
